Config and secrets配置与密钥

Keep settings and keys out of your code and feed them in from the environment · ~10 min · reading and practice把设置和密钥放在代码之外，从环境里传进去 · 约 10 分钟 · 阅读加练习

Step 1 · Same code, different settings第 1 步 · 同样的代码，不同的设置

Learn先学

Your app runs on your laptop, on a test server and for real users. The code is the same; the settings differ: which database, which model, how loud the logs. Putting them in the code means editing code for every place. Put them in the environment instead and the same package works anywhere.

你的应用在笔记本、测试服务器和真实用户那里运行。代码是同一份；设置不同：连哪个数据库、用哪个模型、日志多详细。把它们写进代码，每换个地方就要改代码。放进环境里，同一个包到哪里都能用。

Step 2 · Environment variables第 2 步 · 环境变量

Learn先学

An environment variable is a named value that sits outside the program, handed to it when it starts. In Python, os.environ.get("NAME", default) reads one and falls back to a default when it is missing. Values are always text, so convert numbers yourself. Assigning to os.environ["NAME"] sets one for the running program (a real deployment sets them outside, but this is handy for trying things).

环境变量是放在程序之外、启动时交给程序的带名字的值。在 Python 里，os.environ.get("NAME", default) 读取一个，缺失时使用默认值。值总是文本，数字要自己转换。给 os.environ["NAME"] 赋值，就是为运行中的程序设置一个（真实部署里是在程序之外设置，但这样方便试验）。

import os mode = os.environ.get("APP_MODE", "dev") limit = int(os.environ.get("MAX_ITEMS", "10")) print(mode, limit)

Step 3 · Secrets never go in git第 3 步 · 密钥绝不进 git

Learn先学

A secret is a key, password or token that proves who you are. Once it is in git history it is out for good, even if you delete the file, and bots scan public repositories within minutes. Keep secrets in the platform’s secret store or a local file that git ignores, commit an env.example with fake values to show what is needed, and the moment a key leaks, revoke it: switch it off at the provider, then issue a new one and update your settings. Decide where each belongs.

密钥是证明你身份的钥匙、密码或令牌。一旦进了 git 历史，就算删掉文件也收不回来，机器人几分钟内就会扫描公开仓库。把密钥放进平台的密钥存储，或 git 忽略的本地文件；提交一份带假值的 env.example 说明需要哪些；一旦泄漏，立刻作废它：在服务商那里关掉，再签发新的并更新设置。判断每一项该放哪里。

Sort each one.

给每一项分类。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Config differs by place; code stays the same.
• Read settings from environment variables, and remember they are text.
• Never commit a secret; revoke it if it leaks.

• 配置因地方而异，代码保持不变。
• 从环境变量读取设置，记住它们是文本。
• 绝不提交密钥；泄漏了就作废。
