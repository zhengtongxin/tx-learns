Containers容器

Step 1 · Works on my machine第 1 步 · 在我电脑上能跑

Learn先学

Code depends on more than itself: the language version, installed packages, system files. It runs on your laptop and breaks on the server because one of those differs. A container packages the app and everything it needs into one unit that behaves the same wherever it runs.

代码依赖的不止它自己：语言版本、安装的包、系统文件。它在你的笔记本上能跑，到服务器上就坏了，因为其中一样不同。容器把应用连同它需要的一切打包成一个整体，无论在哪里运行，行为都一样。

Step 2 · Image and container第 2 步 · 镜像与容器

Learn先学

An image is the sealed recipe-plus-ingredients: read-only and shareable. A container is one running copy started from an image. One image can start ten containers, each a fresh copy of the same sealed recipe. Stop a container and its inner changes vanish unless you saved them in a separate storage area (a volume) that outlives it.

镜像是封好的“菜谱加食材”：只读，可以共享。容器是从镜像启动的一个运行中的副本。一个镜像可以启动十个容器，每个都是同一份封好的配方的全新副本。容器停止后，里面的改动会消失，除非存到了独立于它的存储区域（卷）里。

Step 3 · A Dockerfile第 3 步 · Dockerfile

Learn先学

A Dockerfile is the recipe for an image, written as steps: start from a base, copy files in, install packages, say what to run. FROM python:3.12-slim picks the base to start from (a small image with Python 3.12 already installed), WORKDIR sets the folder inside, COPY brings files in, RUN executes a command while the image is being built (here, installing the packages listed in requirements.txt, the project’s list of needed packages), and CMD is the command that runs each time a container starts. Because it is text, it lives in git next to the code.

Dockerfile 是镜像的配方，按步骤写：从一个基础镜像开始、复制文件进去、安装依赖、说明要运行什么。FROM python:3.12-slim 选定起点用的基础镜像（一个已装好 Python 3.12 的精简镜像），WORKDIR 设定里面的工作文件夹，COPY 把文件带进去，RUN 在构建镜像时执行一条命令（这里是安装 requirements.txt 里列出的依赖，它是项目所需包的清单），CMD 是每次容器启动时运行的命令。因为它是文本，可以和代码一起放进 git。

FROM python:3.12-slim WORKDIR /app COPY requirements.txt . RUN pip install -r requirements.txt COPY . . CMD ["python", "app.py"]

Takeaways要点回顾

• A container bundles an app with what it needs, so it behaves the same everywhere.
• An image is the sealed recipe; a container is one running copy.
• A Dockerfile writes the recipe as text steps.

• 容器把应用和它需要的东西打包，所以处处行为一致。
• 镜像是封好的配方；容器是一个运行中的副本。
• Dockerfile 把配方写成文本步骤。
