Logs and monitoring日志与监控

See what a running app is doing, and be told when something is wrong · ~10 min · reading and practice看见运行中的应用在做什么，并在出问题时得到通知 · 约 10 分钟 · 阅读加练习

Step 1 · You cannot see a server第 1 步 · 你看不见服务器

Learn先学

On a laptop you watch the screen. On a server nobody does, so the app has to leave a trail. A log is that trail: one line per event, with a time, a level (INFO, WARNING, ERROR) and facts that help later: which request, which user id, how long it took. ms means milliseconds, and JSON is text that writes data as named values, which json.loads turns into Python dictionaries. Never log secrets or whole private messages.

在笔记本上你盯着屏幕。服务器上没人盯，所以应用得留下痕迹。日志就是这条痕迹：一个事件一行，有时间、级别（INFO、WARNING、ERROR），以及日后有用的事实：哪个请求、哪个用户编号、花了多久。ms 指毫秒；JSON 是用“名字加值”写数据的文本，json.loads 把它变成 Python 字典。绝不记录密钥或完整的私人消息。

Step 2 · Logs you can search第 2 步 · 能搜索的日志

Learn先学

A line of free text is hard to count. A line of structured JSON can be filtered and totalled by a program. Compare what you can ask of each.

一行自由文本很难统计。一行结构化的 JSON 可以被程序过滤和汇总。比较一下你能向它们问什么。

import json lines = [ '{"level": "INFO", "ms": 120}', '{"level": "ERROR", "ms": 900}', '{"level": "INFO", "ms": 80}', ] records = [json.loads(x) for x in lines] errors = [r for r in records if r["level"] == "ERROR"] print(len(errors))

Step 3 · Metrics and alerts第 3 步 · 指标与告警

Learn先学

Logs answer “what happened to this request”. Metrics are numbers over time that answer “is it healthy”: error rate, response time, queue length. An alert tells a person when a metric crosses a line. Alert on what users feel (errors up, pages slow), not on every twitch: an alert that fires daily and means nothing teaches everyone to ignore it. Decide which are worth waking someone.

日志回答“这个请求怎么了”。指标是随时间变化的数字，回答“是否健康”：错误率、响应时间、队列长度。告警在指标越线时通知人。针对用户感受到的问题告警（错误变多、页面变慢），而不是每次小波动：天天响又没意义的告警，会教大家忽略它。判断哪些值得叫醒一个人。

Takeaways要点回顾

• A server is invisible, so the app must leave logs.
• Structured logs can be searched and counted by a program.
• Alert on what users feel, and keep alerts rare enough to trust.

• 服务器看不见，所以应用必须留下日志。
• 结构化日志可以被程序搜索和统计。
• 针对用户感受到的问题告警，并让告警少到值得信任。
