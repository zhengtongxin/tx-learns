Events and configuration事态与配置

Tell warning from exception events, use configuration relationships before a change, and match a case to confidentiality, integrity or availability · ~9 min · reading and practice分清警告与异常事态，变更前利用配置关系，并把案例对应到保密性、完整性或可用性 · 约 9 分钟 · 阅读加练习

Step 1 · Events and monitoring第 1 步 · 事态与监控

Learn先学

An event is any change of state that matters for managing a service. Monitoring is watching for events so people hear about them early. Events come in three kinds: informational (nothing to do), warning (something is approaching a limit) and exception (a limit is passed or something has failed). An exception usually starts an incident. The team that runs the service sets the limits, so 70% is a choice, not a rule. In Chinese this site calls an incident 事件 and an event 事态.

事态是对管理服务有意义的任何状态变化。监控是留意事态，让人们尽早知道。事态分三类：信息类（无需处理）、警告类（正在接近极限）和异常类（超过极限或已经失败）。异常通常会触发一次事件（incident）。限值由运行该服务的团队设定，所以 70% 是一种选择而不是规则。本站中文把 incident 称为“事件”，把 event 称为“事态”。

Example: a file server at 70% full sends a warning; at 100% it is an exception and users cannot save, so an incident is logged.

例子：文件服务器用到 70% 时发出警告；到 100% 就成了异常，用户无法保存，于是记录一次事件。

Event kind Example Next step Informational backup finished none Warning disk 70% full look at it soon Exception disk 100% full, saves fail log an incident

Step 2 · Configuration records第 2 步 · 配置记录

Learn先学

A configuration item is any component that must be managed to deliver a service, such as a server, a database, a licence or a document. A configuration record holds its details and, above all, its relationships to other items and to the services that depend on it.

配置项是为交付服务而必须管理的任何组成部分，例如服务器、数据库、许可证或文档。配置记录保存它的详细信息，最重要的是它与其他配置项以及依赖它的服务之间的关系。

Use it before a change: if a database is linked to three services, a change to it can touch all three, so you plan for all three.

变更之前就用它：如果一个数据库连着三项服务，对它的变更可能影响这三项，所以要为这三项做计划。

Step 3 · Protecting information第 3 步 · 保护信息

Learn先学

Information security has three aims. Confidentiality: only the right people can see it. Integrity: it is correct and changes only in authorised ways. Availability: it can be used when needed. A single incident can break more than one aim: a stolen laptop with customer records breaks confidentiality, and if the thief also changes the records, integrity too.

信息安全有三个目标。保密性：只有合适的人能看到。完整性：信息正确，只会按授权的方式改变。可用性：需要时就能使用。一次事件可能同时破坏不止一个目标：存有客户记录的笔记本被盗破坏保密性，若窃贼还改动了记录，完整性也受损。

Sort each one by the aim it protects.

按它保护的目标给每一项分类。

Now make it yours现在把它变成你的

Takeaways要点回顾

• An event is a state change that matters; monitoring watches for them.
• Informational, warning, exception: only an exception usually starts an incident.
• A configuration record's relationships show what a change touches.
• Confidentiality, integrity, availability are the three aims of information security.
• One incident can break more than one aim.

• 事态是有意义的状态变化；监控就是留意它们。
• 信息类、警告类、异常类：通常只有异常会触发事件。
• 配置记录里的关系显示一次变更会牵涉到什么。
• 保密性、完整性、可用性是信息安全的三个目标。
• 一次事件可能同时破坏不止一个目标。
