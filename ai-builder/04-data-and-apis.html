Data and APIs数据与接口

Call a real web service with the HTTP Request node, shape what comes back and handle errors · ~15 min · hands-on用 HTTP Request 节点调用真实的网络服务，整理返回的数据并处理错误 · 约 15 分钟 · 动手做

Step 1 · Call a real API第 1 步 · 调用一个真实接口

Learn先学

Many apps have no n8n node. Almost all have an API, a web address that answers with JSON. The HTTP Request node calls it for you. Free public APIs need no key, so start with one.

很多应用没有现成的 n8n 节点，但几乎都有 API：一个会用 JSON 回答的网址。HTTP Request 节点就替你去调用它。免费的公开接口不需要密钥，先拿一个练手。

• Method: GET reads, POST sends.
• URL: the address, without the ?... part.
• Query parameters: the name=value pairs after the ?. Add them as a list in the node, not glued onto the URL.
• Authentication: a paid or private API wants a key in a header; save it as a credential, never in the URL.

• 方法：GET 是读取，POST 是发送。
• URL：地址，不含 ? 后面的部分。
• 查询参数：? 之后的 名称=值。在节点里按列表添加，不要拼进网址。
• 认证：收费或私有的接口要在请求头里带密钥；存成凭证，不要写进网址。

Method: GET URL: https://api.open-meteo.com/v1/forecast Query: latitude = 1.29 (central Singapore) longitude = 103.85 current = temperature_2m,wind_speed_10m Result: one item, shaped like this (your numbers will differ): { "current": { "time": "2026-11-27T14:00", "temperature_2m": 31.2, "wind_speed_10m": 9.4 }, ... }

Click Execute step and read the Output tab before you build anything: that shape is exactly what every later node sees.

点 Execute step，先看输出面板，再动手搭：那个结构就是后面每个节点看到的东西。

Step 2 · Shape the result第 2 步 · 整理结果

Learn先学

The raw answer is rarely what the next node wants. Dots walk into nested JSON: {{ $json.current.temperature_2m }} is 31.2. Edit Fields keeps only the fields you name, an IF node splits the path on a condition, and a Code node handles real logic.

原始返回很少正好是下一个节点要的样子。用点号进入嵌套的 JSON：{{ $json.current.temperature_2m }} 就是 31.2。Edit Fields 只留你点名的字段，IF 节点按条件分路，需要真正的逻辑时用 Code 节点。

In a Code node set Run Once for All Items. $input.first() is the first incoming item; you return a list of new items, each wrapped as { json: ... }.

在 Code 节点里选 Run Once for All Items。$input.first() 是第一个输入条目；你要返回一个新条目的列表，每个都包成 { json: ... }。

// Turn the weather answer into one decision for the outdoor class. const w = $input.first().json.current; // the nested object from step 1 const windy = w.wind_speed_10m > 20; // km/h return [{ json: { temp: w.temperature_2m, windy, note: windy ? "Windy: move the class indoors" : "Fine for the outdoor class" } }];

Step 3 · When the API says no第 3 步 · 接口拒绝时

Learn先学

Every reply carries a status code. Learn the common ones; they tell you what to fix.

每个回复都带一个状态码。认得常见的几个，就知道该修什么。

• 400: your request is malformed, often a typo in a parameter name.
• 401 / 403: the key is missing or not allowed.
• 404: wrong address or the thing does not exist.
• 429: too many requests; slow down or add a Wait node.
• 500: the service itself failed; retry later.

• 400：请求本身格式不对，常见是参数名拼错。
• 401 / 403：密钥缺失或没有权限。
• 404：地址错了，或者东西不存在。
• 429：请求太多；放慢，或加一个 Wait 节点。
• 500：服务本身出错；稍后重试。

In the node's Settings tab, turn on Retry On Fail for temporary errors. By default an error stops the whole run; set On Error to Continue (using error output) to send failures down their own path, for example to a message that tells you.

在节点的 Settings 标签里，为临时性错误打开 Retry On Fail（失败重试）。默认情况下一个错误会让整个运行停下；把 On Error 设成 Continue (using error output)，失败的条目就会走单独的一条路，比如发一条消息提醒你。

Sort each one.

给每一项分类。

Now make it yours现在把它变成你的

Takeaways要点回顾

• The HTTP Request node reaches any service that has an API; read its Output tab first.
• Query parameters go in the list; keys go in credentials, never in the URL.
• Dots reach nested fields: $json.current.temperature_2m.
• Edit Fields, IF and Code shape the data for the next step.
• Status codes tell you what to fix: 400 typo, 401 key, 429 rate, 500 retry.

• HTTP Request 节点能连任何有 API 的服务；先看它的输出面板。
• 查询参数放进列表；密钥放凭证里，不要写进网址。
• 用点号取嵌套字段：$json.current.temperature_2m。
• Edit Fields、IF 和 Code 把数据整理成下一步要的样子。
• 状态码告诉你该修什么：400 拼写、401 密钥、429 太快、500 重试。
