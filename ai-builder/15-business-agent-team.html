Many agents and MCP · Project多智能体与 MCP · 项目

Business agent team业务智能体团队

Plan and test a small team of agents for a real or made-up business, with people in charge of anything risky · ~45 min · project为一门真实或虚构的小生意规划并测试一个智能体小团队，风险大的事由人负责 · 约 45 分钟 · 项目

Step 1 · Pick one job and one front door第 1 步 · 选一个任务和一个入口

Learn先学

Do not automate a business. Pick one job with a clear start and end: answer parent enquiries for a small tuition centre, chase unpaid invoices, or sort a shared inbox. Choose one front door: phone, chat or email.

别想着把整门生意自动化。选一个任务，有清楚的起点和终点：回答小型补习中心的家长咨询、催收未付发票，或整理共用邮箱。再选一个入口：电话、聊天或邮件。

Write the job in one sentence and list what a mistake would cost. That list tells you where a person must stay in charge.

用一句话写下这个任务，并列出出错的代价。这份清单就告诉你，哪里必须由人负责。

Sort each one.

给每一项分类。

Step 2 · Give each helper one job第 2 步 · 每个助手只做一件事

Learn先学

Build a small team, not one giant agent. A front desk agent (voice or chat) talks to people and calls the others. A knowledge helper searches your documents. A booking and a billing helper act, with approval. Anything unclear goes to a person.

组一支小团队，而不是一个巨无霸智能体。前台智能体（语音或聊天）负责和人说话，并调用其他助手。知识助手搜索你的文档。预约和账务助手负责行动，要经过批准。任何不清楚的，交给真人。

A simple router decides who takes a request. Put the riskiest topics first and send unknowns to a person. Match whole words: "feels" contains "fee".

一个简单的路由决定由谁接手。把风险最高的话题放在最前面，认不出的交给真人。要匹配整个单词：“feels”里就含有“fee”。

// Pick which helper handles a request, and whether a person must approve first. // Riskier topics come first, so "refund the booking" goes to billing. const RULES = [ { agent: 'billing', words: ['refund', 'charged', 'invoice', 'receipt'], approval: true }, { agent: 'booking', words: ['book', 'reschedule', 'cancel', 'trial lesson'], approval: true }, { agent: 'knowledge', words: ['fee', 'fees', 'price', 'hours', 'open', 'where', 'subject'], approval: false }, ]; function route(text) { // Match whole words only: "feels" must not match "fee". const t = ' ' + text.toLowerCase().replace(/[^a-z0-9]+/g, ' ') + ' '; for (const rule of RULES) { if (rule.words.some(w => t.includes(' ' + w + ' '))) { return { agent: rule.agent, approval: rule.approval }; } } return { agent: 'human', approval: true }; // anything unknown goes to a person }

Step 3 · Test, limit and measure第 3 步 · 测试、设限、衡量

Learn先学

• Test: write 20 real requests and the helper that should take each. Run them after every change.
• Limit: cap spending, calls and what each helper may touch. Approval on anything that writes, sends or moves money.
• Measure: count calls handled, wrong answers, minutes saved and cost per call, for a week, before you trust it with more.

• 测试：写 20 个真实请求，以及应该由哪个助手接手。每次改动之后都跑一遍。
• 设限：限制花费、调用次数和每个助手能碰的东西。凡是写入、发送、动钱的，都要批准。
• 衡量：统计一周内处理的来电数、答错数、省下的分钟数和每通电话的成本，再决定要不要放手更多。

A team that is measured gets better. One that is not measured gets trusted too early.

被衡量的团队会越来越好，不被衡量的团队会被过早地信任。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Pick one job and one front door, not a whole business.
• Give each helper one job and only the tools it needs.
• Route risky topics first; unknown goes to a person.
• A person approves anything that writes, sends or moves money.
• Test, limit and measure before you let it do more.

• 选一个任务和一个入口，别碰整门生意。
• 每个助手一个任务，只给需要的工具。
• 高风险话题先路由，认不出的交给真人。
• 凡是写入、发送、动钱的事，都由人批准。
• 先测试、设限、衡量，再放手让它多做。
