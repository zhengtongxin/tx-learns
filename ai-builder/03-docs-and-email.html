Docs and email文档与邮件

Connect Gmail and Google Docs, and let AI draft while you approve · ~12 min · hands-on连上 Gmail 和 Google 文档，让 AI 起草、你来批准 · 约 12 分钟 · 动手做

Step 1 · Connect an account once第 1 步 · 账号只连一次

Learn先学

Gmail, Google Docs and Google Sheets all use OAuth: you sign in with Google and n8n stores a token, never your password. Add the credential once from any Google node, then reuse it.

Gmail、Google 文档和 Google 表格都用 OAuth：你用 Google 账号登录，n8n 保存的是一个令牌，而不是你的密码。在任何 Google 节点里添加一次凭证，之后到处复用。

Use a test account first. A workflow that can send mail can also send the wrong mail.

先用测试账号。能发邮件的工作流，也会发错邮件。

Step 2 · Let AI label and draft第 2 步 · 让 AI 分类并起草

Learn先学

Pass the email text to an AI node and ask for structured output: a small JSON with a label and a draft, so later nodes can read each field.

把邮件正文交给 AI 节点，要求结构化输出：一小块 JSON，里面有标签和草稿，后面的节点就能逐个字段读取。

The prompt below is the whole trick: say exactly which fields to return.

下面的提示词就是全部诀窍：明确说出要返回哪些字段。

Read the email below. Return JSON only, with two fields: "label": one of "booking", "question", "complaint", "other" "draft": a polite reply of at most 60 words, or "" if label is "other" Email: {{ $json.snippet }}

Step 3 · Put a person before send第 3 步 · 发送前放一个人

Learn先学

• Create a Gmail draft instead of sending, or use a Send and Wait for Response step that asks you to approve.
• Auto-send only for low-risk labels, and only after you have read many drafts.
• Log each decision to a Sheet row, so you can review what the agent did.

• 创建 Gmail 草稿而不是直接发送，或者用 Send and Wait for Response 步骤请你批准。
• 只有低风险的类别才自动发送，而且要等你读过很多草稿之后。
• 把每次决定记到一行表格里，方便回头检查。

The more costly a mistake, the more a person should stand in front of it.

错误代价越高，越该有人站在它前面。

Sort each one.

给每一项分类。

Step 4 · Wire the answer into a draft第 4 步 · 把答案接到草稿上

Do it动手

Order the nodes like this: Gmail Trigger (new email) → AI node with the prompt above → IF on the label → Gmail with Resource Draft and Operation Create. Open the AI node’s output panel and find where the answer sits (often a field named text, or output if you attach a Structured Output Parser). Use that exact field name in the next node, for example {{ $json.output.draft }}.

节点顺序：Gmail Trigger（新邮件）→ 带上面提示的 AI 节点 → 按标签判断的 IF → Gmail 节点，Resource 选 Draft，Operation 选 Create。打开 AI 节点的输出面板，看答案放在哪个字段（常见是 text，接了 Structured Output Parser 则是 output），下一个节点里就用这个确切的字段名，例如 {{ $json.output.draft }}。

If a later node says the field is missing, the model usually wrapped the JSON in a sentence. Fix the prompt (“Return JSON only”) or attach the parser. Do not make every later node cope with free text.

如果后面的节点说字段不存在，多半是模型在 JSON 外加了一句话。去改提示（“只返回 JSON”）或接上解析器，别让后面每个节点都去应付自由文本。

Now make it yours现在把它变成你的

Takeaways要点回顾

• OAuth lets n8n act for you without holding your password.
• Ask the model for structured output so later nodes can use each field.
• Draft first, send later: a person approves anything costly.
• Log what the agent did so you can review it.
• Test with a throwaway account before the real one.

• OAuth 让 n8n 代你操作，却不持有你的密码。
• 让模型输出结构化结果，后面的节点就能逐字段使用。
• 先起草后发送：花钱的事由人批准。
• 记录智能体做了什么，方便复查。
• 先用一次性账号测试，再换真账号。
