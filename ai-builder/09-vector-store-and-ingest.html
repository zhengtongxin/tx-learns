Step 1 · Make a store in Supabase第 1 步 · 在 Supabase 建一个库

Learn先学

Supabase is a hosted Postgres database. Its pgvector extension stores embeddings and finds the closest ones. Create a free project, open the SQL Editor and run the script below once.

Supabase 是托管的 Postgres 数据库。它的 pgvector 扩展能存嵌入并找出最近的几条。新建一个免费项目，打开 SQL Editor，把下面的脚本运行一次。

The number in vector(1536) is the length of each embedding. It must equal what your embedding model produces. Change the model later and you must re-embed everything.

vector(1536) 里的数字是每条嵌入的长度，必须和你的嵌入模型产出的长度一致。以后换了模型，所有内容都要重新嵌入。

create extension if not exists vector; create table documents ( id bigserial primary key, content text, -- the chunk of text metadata jsonb, -- where it came from, e.g. {"file":"products.txt"} embedding vector(1536) -- must match your embedding model ); create function match_documents ( query_embedding vector(1536), match_count int default 3, filter jsonb default '{}' ) returns table (id bigint, content text, metadata jsonb, similarity float) language plpgsql as $$ #variable_conflict use_column begin return query select id, content, metadata, 1 - (documents.embedding <=> query_embedding) as similarity from documents where metadata @> filter order by documents.embedding <=> query_embedding limit match_count; end; $$;

Step 2 · Ingest with an n8n workflow第 2 步 · 用 n8n 工作流入库

Learn先学

• Trigger: a new or changed file, or a button you press.
• Extract: get the plain text out of the file.
• Split: cut it into chunks, about 500 characters with a small overlap, so a sentence is not cut off from its context.
• Embed and store: the Supabase Vector Store node in Insert mode, with an Embeddings model attached.

• 触发：新文件、文件有改动，或你按一个按钮。
• 提取：从文件里取出纯文字。
• 切分：切成约 500 字符的块，留一点重叠，免得一句话和它的上下文被切断。
• 嵌入并存储：用 Supabase Vector Store 节点的 Insert 模式，并接上一个 Embeddings 模型。

Add each chunk's source file name as metadata. Later you can show where an answer came from.

把每块来自哪个文件写进元数据，以后就能说明答案出自哪里。

Step 3 · Search it back第 3 步 · 再把它搜出来

Learn先学

A second workflow does the reverse: embed the question, call match_documents, and take the top few chunks. The n8n Supabase node does this in Get many mode, or an agent can use the store as a tool.

第二个工作流做相反的事：嵌入问题，调用 match_documents，取最靠前的几块。n8n 的 Supabase 节点用 Get many 模式就能做到，也可以让智能体把这个库当成工具。

• Use the service role key only inside n8n credentials. Never put it in a web page or share it.
• Turn on row level security for tables a browser may reach.

• service role 密钥只放在 n8n 的凭证里，不要放进网页，也不要分享。
• 浏览器可能碰到的表，要打开行级安全。

Sort each one.

给每一项分类。

• Chunk about 500 characters with a little overlap and keep the source name.
• Keep the service role key inside n8n only.

• 带 pgvector 的 Supabase 存嵌入，并找出最近的。
• 列的长度必须和嵌入模型一致。
• 入库就是触发、提取、切分、嵌入、写入。
• 切成约 500 字符、略有重叠，并保留来源名。
