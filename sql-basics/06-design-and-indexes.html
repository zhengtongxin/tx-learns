Design and indexes设计与索引

Shape tables so data stays clean, and speed up lookups with an index · ~10 min · reading and practice把表设计得让数据保持干净，并用索引加快查找 · 约 10 分钟 · 阅读加练习

Step 1 · Shape the table第 1 步 · 设计表

Learn先学

Each table holds one kind of thing, and each column holds one value (not “tea, cake” in a cell). Give every table a primary key. Pick a sensible type for each column: numbers for amounts, text for names. For money prefer whole cents (an integer) to avoid rounding surprises.

每张表只装一类东西，每列只放一个值（不要在一个格子里写“tea, cake”）。每张表都要有主键。给每列选合适的类型：金额用数字，名字用文本。金额最好用整数“分”来存，避免舍入带来的意外。

Step 2 · Constraints第 2 步 · 约束

Learn先学

Constraints make the database refuse bad data: NOT NULL (a value is required), UNIQUE (no duplicates), CHECK (price >= 0) (a rule) and FOREIGN KEY (must point at a real row). Catching a mistake at the door is far cheaper than cleaning it up later.

约束让数据库拒绝坏数据：NOT NULL（必填）、UNIQUE（不许重复）、CHECK (price >= 0)（一条规则）、FOREIGN KEY（必须指向真实存在的行）。在门口拦住错误，比事后清理便宜得多。

CREATE TABLE menu ( id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE, price REAL CHECK (price >= 0) );

Step 3 · Indexes第 3 步 · 索引

Learn先学

Without help, finding one row in a big table means reading every row. An index is a sorted side structure on a column, like a book’s index: CREATE INDEX idx_menu_name ON menu(name). Lookups on that column get fast, but every insert and update must also maintain the index, and it uses space. Index the columns you search or join on, not everything.

没有帮助的话，在大表里找一行就得把每一行都读一遍。索引是建在某一列上的有序辅助结构，就像书后的索引：CREATE INDEX idx_menu_name ON menu(name)。这一列上的查找会变快，但每次插入和更新也要维护索引，并占用空间。给你常用来搜索或连接的列建索引，而不是给所有列都建。

Takeaways要点回顾

• One kind of thing per table, one value per cell, store each fact once.
• Constraints stop bad data at the door.
• An index speeds lookups but costs writes and space.

• 每张表一类东西，每格一个值，每个事实只存一次。
• 约束在门口拦住坏数据。
• 索引加快查找，但要付出写入和空间的代价。
