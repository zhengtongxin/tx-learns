Changing data修改数据

Add, change and remove rows with INSERT, UPDATE and DELETE, and why WHERE matters most · ~10 min · reading and practice用 INSERT、UPDATE、DELETE 增加、修改和删除行，以及为什么 WHERE 最要紧 · 约 10 分钟 · 阅读加练习

Step 1 · Three ways to change第 1 步 · 三种修改

Learn先学

INSERT INTO menu VALUES (...) adds a row. UPDATE menu SET price = 3.5 WHERE name = 'tea' changes values. DELETE FROM menu WHERE name = 'toast' removes rows. Always say which columns you are filling in an INSERT, so a later column change does not scramble it.

INSERT INTO menu VALUES (...) 新增一行。UPDATE menu SET price = 3.5 WHERE name = 'tea' 修改值。DELETE FROM menu WHERE name = 'toast' 删除行。写 INSERT 时要明确列出填的是哪些列，这样以后表结构变了也不会错位。

INSERT INTO menu (name, price, kind) VALUES ('soup', 4.0, 'food'); UPDATE menu SET price = 3.5 WHERE name = 'tea'; DELETE FROM menu WHERE name = 'toast';

Step 2 · The missing WHERE第 2 步 · 漏写的 WHERE

Learn先学

UPDATE and DELETE with no WHERE hit every row. This is the classic disaster. Habit: write the WHERE first, run the same condition as a SELECT to see what it will touch, and only then change the data.

UPDATE 和 DELETE 不写 WHERE 会作用于每一行。这是最经典的事故。好习惯：先写 WHERE，用同样的条件跑一次 SELECT 看它会碰到哪些行，然后才真正修改数据。

Step 3 · All or nothing第 3 步 · 要么全做要么不做

Learn先学

A transaction groups several changes so that they all succeed or none do. Moving money means subtracting from one account and adding to another; a crash between the two must not lose it. BEGIN, the changes, then COMMIT (or ROLLBACK to undo).

事务把几个修改打成一组，要么全部成功，要么全不生效。转账要从一个账户扣、再给另一个账户加，两步之间崩溃也不能把钱弄丢。BEGIN、修改，然后 COMMIT（或用 ROLLBACK 撤销）。
