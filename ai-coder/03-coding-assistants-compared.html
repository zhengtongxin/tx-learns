Coding assistants compared编程助手对比

Compare Cursor, Copilot, Codex and Antigravity by where they run and who steers · ~11 min · concepts按“在哪里运行、谁来掌舵”对比 Cursor、Copilot、Codex 和 Antigravity · 约 11 分钟 · 讲概念

Step 1 · Four questions, not a ranking第 1 步 · 四个问题，不排名

Learn先学

These tools change every month, so a ranking goes stale. Compare them with four questions instead: Where does it run (editor, terminal, cloud)? Who steers (you approve each step, or it runs on its own)? Which models can you pick? How is it priced (flat plan, usage, or both)?

这些工具每个月都在变，排名很快就过时。不如用四个问题来比：在哪里运行（编辑器、终端、云端）？谁来掌舵（每步由你批准，还是自己跑）？能选哪些模型？怎么收费（固定套餐、按用量，还是两者结合）？

Check each tool's own page for today's answers. Treat anything below as a snapshot.

答案以各工具官网当下的说明为准。下面的内容只是一张快照。

Step 2 · The four in one glance第 2 步 · 四个工具一览

Learn先学

• Cursor: an editor built around AI. Tab completion, an agent panel that edits many files, and a choice of models.
• GitHub Copilot: lives in your editor and on GitHub. Chat, agent mode, and an agent you can hand an issue to.
• Codex: OpenAI's coding agent. A terminal tool, an editor extension, and cloud tasks that run in a sandbox and come back as a diff.
• Antigravity: Google's agent-first editor, with a manager view that lets you run several agents and review what they did.

• Cursor：围绕 AI 打造的编辑器。有 Tab 补全、能改多个文件的智能体面板，还能选模型。
• GitHub Copilot：在你的编辑器和 GitHub 上都能用。有对话、智能体模式，还能把一个 issue 交给它去做。
• Codex：OpenAI 的编程智能体。有终端工具、编辑器扩展，还有在沙箱里运行、最后交回一份改动的云端任务。
• Antigravity：Google 的“智能体优先”编辑器，有个管理视图，可以同时跑多个智能体并审阅它们做了什么。

They overlap more each month. The real difference is the surface you work on.

它们每个月都更像彼此。真正的区别在你工作的界面。

Step 3 · Pick the surface for the job第 3 步 · 按活儿选界面

Learn先学

Editor when you want to watch and steer: quick edits, reading unfamiliar code. Terminal when the task is scriptable or you live in the shell. Cloud when the task is long and well described: you hand it over and review the finished diff later.

想边看边掌舵，选编辑器：小改动、读不熟悉的代码。任务可以脚本化、或你本来就在命令行里，选终端。任务又长又描述得很清楚，选云端：交出去，稍后审阅完成的改动。

Whatever you pick, the habit is the same: a clear brief, a test to run, and you read the diff before it lands.

不管选哪个，习惯都一样：简报写清楚、有测试可跑、合并前自己读一遍改动。

A fair comparison uses the same small task and four things you can count, not a feeling:

公平的比较要用同一个小任务，再数四件看得见的事，而不是凭感觉：

Task (same for both): "Reject an empty name in createUser(), add a test for it, run the tests." Tool A Tool B Asked before editing? yes / no yes / no Ran the tests itself? yes / no yes / no Follow-up messages to get a passing result ___ ___ Diff I had to undo ___ lines ___ lines

Sort each one.

给每一项分类。

Step 4 · Read a filled-in sheet第 4 步 · 读一张填好的对比表

Learn先学

Here is a sheet someone filled in after giving two tools the same task. Numbers beat impressions, but only if you read what they leave out.

这是有人给两个工具同一个任务后填好的表。数字胜过印象，前提是你也看清它没写的部分。

Tool A Tool B Asked before editing? yes no Ran the tests itself? yes yes Follow-up messages to get a passing result 3 1 Diff I had to undo 0 lines 14 lines
Learn先学

Tool B was faster to a passing result, but it edited without asking and left 14 lines to undo. Neither is “better”: which one fits depends on whether you want to steer (A) or hand over and review the diff (B). One task is also a small sample, so repeat it on a second task before you decide.

工具 B 更快得到通过的结果，但它没问就改，还留下 14 行要撤销。没有谁绝对更好：看你想自己掌舵（A），还是交出去再审阅改动（B）。一个任务也只是很小的样本，决定之前再换一个任务重复一次。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Compare tools by where they run, who steers, which models, and the price.
• Editor to watch, terminal to script, cloud to hand over.
• Features converge; your workflow habits do not change.
• Always: a clear brief, a test to run, and read the diff.

• 按“在哪运行、谁掌舵、哪些模型、怎么收费”来比较工具。
• 编辑器用来盯着，终端用来脚本化，云端用来交出去。
• 功能会趋同，你的工作习惯不用变。
• 永远是：简报清楚、有测试可跑、读完改动再合并。
