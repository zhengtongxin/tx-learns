Step 1 · From autocomplete to agents第 1 步 · 从补全到智能体

Learn先学

AI coding tools come in three levels. Autocomplete finishes the line you are typing. Chat answers questions and writes a snippet you paste in. An agent does the work itself: it reads your files, edits them, runs commands and checks the result.

AI 编程工具分三个层次。补全帮你写完正在敲的那一行。对话回答问题、给你一段代码让你自己粘贴。智能体自己动手：读你的文件、改文件、运行命令、检查结果。

The jump is the last one. An agent has tools (read a file, edit a file, run a command) and keeps going until the task is done or it gets stuck.

真正的跳跃在最后一步。智能体手里有工具（读文件、改文件、运行命令），会一直做到任务完成或卡住为止。

The same small job at each level: add a /health route to a Node app, and a test for it.

同一件小事，在三个层次上分别怎么做：给一个 Node 应用加一个 /health 路由，再写一个测试。

Autocomplete You type: app.get('/hea It offers: lth', (req, res) => res.json({ ok: true })); You write the test, run it and fix it yourself. Chat You paste server.js and ask for a /health route. It replies with a snippet. You paste it in, run the tests yourself, and paste the error back if it fails. Agent You say: "Add GET /health returning {ok:true}, add a test, and run npm test until it passes." It opens the files, edits them, runs the tests, reads the failure, fixes it, and reports what it changed.

Step 2 · The loop an agent runs第 2 步 · 智能体的循环

Learn先学

Every agent runs the same loop: read the relevant files, plan a change, edit, run something (tests, the app), then check the output and go round again.

每个智能体都在跑同一个循环：读相关文件、计划一处改动、编辑、运行点什么（测试、应用），再检查输出，然后再来一轮。

Your job moves from typing code to setting the goal, giving a way to check, and judging the result. A goal with a check ("make npm test pass") works far better than a goal without one ("make it better").

你的工作从敲代码，变成定目标、给出检查办法、评判结果。带检查的目标（“让 npm test 通过”）远比不带检查的目标（“做得更好”）有效。

Weak: "Make the login page better." (better how? how will anyone know it worked?) Strong: "On the login page, show an error under the password box when the password is under 8 characters. Add a test in login.test.js. Done when npm test passes." (what to change, where, and how to check it)

Step 3 · Steer by feel, or by design第 3 步 · 凭感觉，还是靠设计

Learn先学

Vibe coding means describing what you want and judging the result by running it, without reading every line. It is great for throwaway tools, prototypes and learning.

Vibe coding（凭感觉编程）是说出你想要什么，靠运行结果来判断，不逐行阅读代码。适合一次性小工具、原型和学习。

Vibe engineering keeps you as the owner: you set the design, read the diff (the list of lines it added and removed) and insist on tests. Agentic engineering goes one step further and designs systems of agents with limits, checks and a person approving risky steps.

Vibe engineering（专业级氛围工程）里你仍然是负责人：你定设计、读改动（它增删了哪些行）、坚持要有测试。智能体工程再进一步：设计一群智能体，带限制、带检查，高风险的步骤由人批准。

The more a mistake costs, the more you move from feel towards design. This track walks that road in three stages.

出错的代价越大，就越要从“凭感觉”走向“靠设计”。这条路线分三个阶段，带你走完这段路。

Step 4 · Read a run like a transcript第 4 步 · 像读记录一样读一次运行

Learn先学

You rarely watch an agent type. You read what it did afterwards, so learn to spot the loop in a log. Here is a short run for the goal “make npm test pass”:

你很少盯着智能体打字，多数时候是事后读它做了什么，所以要学会在日志里认出那个循环。下面是目标“让 npm test 通过”的一次简短运行：

1 read src/price.js, test/price.test.js 2 plan "total() ignores the discount; apply it before tax" 3 edit src/price.js (+2 -1: 2 lines added, 1 removed) 4 run npm test 5 check 1 failing: expected 94.5, got 95.04 6 plan "tax should apply to the discounted amount only" 7 edit src/price.js (+1 -1) 8 run npm test 9 check all 12 passing
Learn先学

Read it for two things: did a check actually happen (lines 5 and 9), and did the second round learn from the first (line 6 uses the failure on line 5). A run with edits but no run-and-check line is a guess, however confident the summary sounds.

读它看两件事：有没有真的检查过（第 5、9 行），以及第二轮有没有从第一轮学到东西（第 6 行用了第 5 行的失败）。只有编辑、没有运行和检查的记录就是猜测，不管总结听起来多自信。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Autocomplete finishes lines, chat answers, an agent acts with tools.
• An agent loops: read, plan, edit, run, check.
• Vibe coding suits throwaway work; engineering suits work that must last.
• The costlier a mistake, the more you design instead of feel.

• 补全写完一行，对话给出回答，智能体用工具动手做。
• 智能体循环：读、计划、改、运行、检查。
• 凭感觉编程适合用完即弃的活；要长久的活要靠工程。
• 出错越贵，就越要设计而不是凭感觉。
