Agentic engineering · Lesson 3智能体工程 · 第 3 课

Large codebases大型代码库

Work in code too big to read: map it, leave notes, test first, change in small steps · ~13 min · concepts在大到读不完的代码里工作：先画地图、留笔记、先测试、小步改动 · 约 13 分钟 · 讲概念

Step 1 · Map before you change第 1 步 · 先画地图，再动手

Learn先学

A real codebase will not fit in any context window, and it does not need to. The agent searches instead of reading everything: it finds the entry points, follows the calls, and opens only what matters.

真实的代码库放不进任何上下文窗口，也不需要放进去。智能体靠搜索而不是通读：找到入口、顺着调用走、只打开重要的部分。

Begin with a read-only task: "map the main folders, the entry points and how a request flows through. Write it to ARCHITECTURE.md." You review the map and fix what it got wrong before anyone changes anything.

从一个只读任务开始：“画出主要文件夹、入口，以及一次请求是怎么流转的，写到 ARCHITECTURE.md。”你先审阅这张地图、改正错的地方，然后才让任何人动代码。

Step 2 · Notes the agent leaves for itself第 2 步 · 智能体留给自己的笔记

Learn先学

The agent forgets between sessions, so give it memory in files. Keep the root AGENTS.md short, and add small AGENTS.md files in subfolders with the rules for that part. Tools that support it load a subfolder's file when the agent works there.

智能体在会话之间会忘记，所以给它放在文件里的记忆。根目录的 AGENTS.md 保持简短，再在子文件夹里放小的 AGENTS.md，写那一块的规矩。支持这个功能的工具，会在智能体在那个文件夹里工作时加载它。

When an agent learns something the hard way (a command that needs a flag, a folder that looks unused but is not), add one line to the right file, so the next session starts smarter.

智能体吃过苦头才学到的东西（某条命令必须加某个参数、某个看着没用其实有用的文件夹），就在对应文件里加一行，让下一个会话起点更高。

# payments/ - All amounts are integer cents. Never use floats here. - Run only this folder's tests while working: npm test -- payments - legacy/ looks unused but the nightly job imports it. Do not delete. - Any change to refund rules needs a person to review.

Step 3 · Change safely, in small steps第 3 步 · 安全地、小步地改

Learn先学

Before touching old code, add tests that pin down what it does today (characterisation tests), even if the behaviour looks odd. Then change one concern at a time: a rename, a move or a behaviour change, never all together.

动老代码之前，先加固定住它今天行为的测试（特征测试），即使行为看着奇怪也先固定下来。然后一次只改一个关注点：改名、搬家、改行为，绝不混在一起。

Plan first, make one slice, run the tests, commit, repeat. Use a sub-agent to explore so the main session stays small, and keep each pull request something a person can review in ten minutes.

先计划、做一小块、跑测试、提交，再重复。用子智能体去探索，让主会话保持小；每个拉取请求都要小到一个人十分钟能审完。

Sort each one.

给每一项分类。

Step 4 · Pin it, then change one thing第 4 步 · 先固定，再改一件事

Learn先学

Here is a characterisation test on a small legacy function. The function charges a flat fee below 1000 cents and 2% above. Look at the third check: the fee drops from 30 to 20 at exactly 1000. That looks like a bug, but nobody knows who depends on it, so the test pins it as it is today and you flag it to a person instead of fixing it in the middle of a refactor.

这是一个给小型遗留函数写的特征测试。这个函数在 1000 分以下收固定费用，以上收 2%。看第三条检查：金额刚到 1000 时，费用反而从 30 降到 20。这看着像 bug，但没人知道谁依赖它，所以测试先按今天的样子固定下来，并把它报给人去决定，而不是在重构中途顺手改掉。

// legacy/fee.js: nobody remembers why function fee(cents) { if (cents < 1000) return 30; return Math.floor(cents * 0.02); } // fee.char.test.js: pin what it does TODAY const assert = require('node:assert'); // assert stops with an error if a check is false assert.strictEqual(fee(500), 30); // small amounts pay a flat 30 assert.strictEqual(fee(999), 30); assert.strictEqual(fee(1000), 20); // odd: the fee drops here, but we pin it assert.strictEqual(fee(5035), 100); console.log('all pinned');

Now make it yours现在把它变成你的

Takeaways要点回顾

• Agents search; they do not read everything.
• Start read-only: map, notes, a baseline of tests.
• Keep memory in files, near the code it describes.
• Pin behaviour with tests, then change one concern at a time.

• 智能体靠搜索，不是通读。
• 从只读开始：地图、笔记、测试基线。
• 把记忆放在文件里，放在它所描述的代码旁边。
• 先用测试固定行为，再一次只改一个关注点。
