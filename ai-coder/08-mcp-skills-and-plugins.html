MCP, skills and pluginsMCP、技能与插件

Extend an agent three ways: MCP for access, skills for know-how, plugins to share both · ~11 min · concepts用三种方式扩展智能体：MCP 给“通路”，技能给“门道”，插件把它们打包分享 · 约 11 分钟 · 讲概念

Step 1 · MCP: access to things第 1 步 · MCP：接通外部世界

Learn先学

You met MCP as a standard plug between AI apps and tools. For coding it is how an agent reaches your issue tracker, database, docs or browser. A server is added by a few lines of config.

你已经认识了 MCP：AI 应用和工具之间的标准插头。放到编程里，它让智能体够得着你的任务系统、数据库、文档或浏览器。接入一个服务器只需要几行配置。

Every connected server adds tool descriptions to the context. Add only what the task needs, and give each the least access it requires.

每接一个服务器，工具描述就会占用一些上下文。只接任务需要的，并且只给最小权限。

{ "mcpServers": { "docs": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "./docs"] } } }

Step 2 · Skills: know-how on demand第 2 步 · 技能：按需取用的门道

Learn先学

A skill is a folder with a SKILL.md file: a name, a one-line description of when to use it, and the steps. The agent reads only the descriptions at first and loads the full skill when the task matches, so skills cost little context until needed.

技能是一个带 SKILL.md 文件的文件夹：名字、一句“何时使用”的描述，以及步骤。智能体起初只读描述，任务匹配时才加载整个技能，所以在用到之前几乎不占上下文。

Use a skill for a procedure your team repeats: how you write a release note, how you review a migration.

把团队反复要做的流程做成技能：比如怎么写发布说明、怎么审一次数据库迁移。

--- name: release-note description: Write a release note from merged changes. Use when asked for a changelog or release note. --- 1. List the merged changes since the last tag. 2. Group them: new, fixed, changed. 3. One plain sentence each, no internal jargon. 4. End with anything users must do (migrations, new settings).

Step 3 · Plugins, and which to reach for第 3 步 · 插件，以及该选哪个

Learn先学

A plugin bundles commands, skills, sub-agents, hooks and MCP servers into one installable package, so a team shares a setup in one step.

插件把命令、技能、子智能体、钩子和 MCP 服务器打包成一个可安装的整体，团队一步就能共享同一套配置。

A rule of thumb: need to reach something? MCP. Need the agent to know how? A skill. Need to share a whole setup? A plugin. Install third-party ones as carefully as any code: read what they do first.

经验法则：要够到某个东西？用 MCP。要智能体懂得怎么做？用技能。要分享整套配置？用插件。第三方的插件要像任何代码一样谨慎安装：先看它做什么。

Sort each one.

给每一项分类。

Now make it yours现在把它变成你的

Takeaways要点回顾

• MCP reaches systems; skills carry know-how; plugins bundle and share.
• Every MCP server costs context: add only what the task needs.
• Skills load on demand, so they are cheap until used.
• Treat third-party plugins like any code you would run.

• MCP 够到系统；技能承载门道；插件打包分享。
• 每个 MCP 服务器都占上下文：只接任务需要的。
• 技能按需加载，没用到时很省。
• 第三方插件和任何你要运行的代码一样要谨慎。
