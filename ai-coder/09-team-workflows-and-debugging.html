Team workflows and debugging团队流程与调试

Use agents inside a team workflow, and give them what they need to debug · ~11 min · concepts把智能体放进团队流程，并给它调试所需要的东西 · 约 11 分钟 · 讲概念

Step 1 · One loop for the team第 1 步 · 团队共用一个循环

Learn先学

A steady loop works for people and agents alike: explore the code, plan, build in small steps, test, commit, open a pull request. Ask for the plan before the code.

有一个稳定的循环，人和智能体都适用：探索代码、计划、分小步构建、测试、提交、发起拉取请求。先要计划，再要代码。

For a team, share what the agent reads: commit AGENTS.md, custom commands and skills. Everyone gets the same test command, the same rules, the same checks in continuous integration (CI).

对团队来说，要共享智能体读的东西：提交 AGENTS.md、自定义命令和技能。每个人都有同一条测试命令、同一套规矩、持续集成（CI）里同样的检查。

Step 2 · You still own the review第 2 步 · 审阅仍归你

Learn先学

Agent-written code is code you are responsible for. Read the diff like a colleague's: does it match the plan, are there tests, any new dependency, any secret, any change you did not ask for?

智能体写的代码，你要负责。像读同事的代码那样读它的改动：和计划一致吗？有测试吗？有没有新依赖、有没有密钥、有没有你没要求的改动？

Keep pull requests small and single-purpose. A 2,000-line agent diff is a review nobody can do, and the checks are only as good as the review behind them.

拉取请求要小而专一。2,000 行的智能体改动没人审得了，而检查的可靠程度，取决于背后那次审阅。

Step 3 · Debugging with an agent第 3 步 · 和智能体一起调试

Learn先学

Give it the evidence: the exact error, how to reproduce it, what you expected. Ask for causes first, then a fix. Best of all, ask it to write a failing test that captures the bug, then make it pass.

把证据给它：准确的报错、复现的办法、你期望的结果。先让它找原因，再给修复。最好的做法是让它先写一个能复现这个 bug 的失败测试，再让测试通过。

Change one thing at a time. If it loops on the same wrong idea after two tries, stop, start a fresh session and give it what you learned.

一次只改一件事。如果它在同一个错误想法上试了两次还在打转，就停下来，开一个新会话，把你学到的告诉它。

Bug: checkout total is 1 cent too high when 3 people share a dish. Reproduce: node scripts/try-split.js (prints 1679, expected 1678) Do not change code yet. First list three likely causes, with the file for each. Then write a failing test that shows the bug. Only then fix it.

Sort each one.

给每一项分类。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Explore, plan, build small, test, commit, pull request.
• Share AGENTS.md, commands and skills so the team agrees.
• You own the review; keep diffs small.
• Debug with evidence: error, steps, expectation. Causes first, then a failing test.

• 探索、计划、小步构建、测试、提交、拉取请求。
• 共享 AGENTS.md、命令和技能，让团队保持一致。
• 审阅归你；改动要小。
• 用证据调试：报错、步骤、期望。先找原因，再写失败测试。
