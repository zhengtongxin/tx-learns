Agent-built service智能体合力做的服务

Plan a small service as tasks, run workers in waves under guardrails, and review the result · ~60 min · project把一项小服务规划成任务，在护栏之下分波运行执行者，并审阅结果 · 约 60 分钟 · 项目

Step 1 · Specify and split第 1 步 · 写规格，再拆分

Learn先学

Pick a small service you could describe in a page: for example a receipt tracker with an endpoint to add a receipt, one to list them by month, and a short README. Write the spec, then split it into tasks in tasks.json with each task's files and dependencies.

选一项你一页纸就能说清的小服务，比如收据记录器：一个添加收据的接口、一个按月列出收据的接口，加一份简短的 README。写好规格，再拆成 tasks.json 里的任务，标明每个任务的文件和依赖。

A good split has several tasks that can run at once, and no two of them touch the same file.

好的拆分里，有好几个任务可以同时跑，而且任何两个都不碰同一个文件。

[ { "id": "store", "deps": [], "files": ["src/store.js"] }, { "id": "add", "deps": ["store"], "files": ["src/add.js"] }, { "id": "list", "deps": ["store"], "files": ["src/list.js"] }, { "id": "readme", "deps": [], "files": ["README.md"] }, { "id": "tests", "deps": ["add", "list"], "files": ["test/service.test.js"] } ]

Step 2 · Plan the waves, run the workers第 2 步 · 规划波次，运行执行者

Learn先学

Run your planner over tasks.json. It returns the waves: wave 1 can run together, wave 2 starts when wave 1 is merged, and so on. It refuses a circular or unknown dependency before any agent starts.

对 tasks.json 运行你的规划器。它返回各个波次：第 1 波可以一起跑，第 1 波合并之后才开始第 2 波，依此类推。在任何智能体开工之前，它就会拒绝循环依赖或未知依赖。

Now run each wave: one worker per task, each in its own worktree, with your sandbox and hooks on. Give every worker a brief that stands alone: its task, its files, the test to pass.

然后逐波运行：每个任务一个执行者，各在自己的 worktree 里，沙箱和钩子都开着。给每个执行者一份自成一体的简报：它的任务、它的文件、要通过的测试。

Step 3 · Verify, merge, and look back第 3 步 · 验证、合并、回顾

Learn先学

After each wave, run the tests, let a reviewer sub-agent read the combined diff, then you merge. Do not start the next wave on an unreviewed result.

每一波之后，运行测试，让一个审阅子智能体读合并后的整体改动，然后由你合并。不要在没审阅的结果上开始下一波。

Finish with a short look back: how many agents, what it cost, which task failed and why, and what you would change in the split or the briefs. That note is how you get better at this.

最后写一段简短的回顾：用了多少个智能体、花了多少钱、哪个任务失败了为什么、拆分或简报下次要怎么改。这段笔记就是你在这件事上越做越好的办法。

Sort each one.

给每一项分类。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Plan as data: tasks, files, dependencies.
• A planner script rejects cycles and unknown dependencies before agents run.
• One worker per task, own worktree, sandbox and hooks on.
• Test, review, then a person merges before the next wave.
• Look back: agents, cost, failures, changes.

• 把计划写成数据：任务、文件、依赖。
• 规划器脚本在智能体开工前就拒绝循环依赖和未知依赖。
• 一任务一执行者，各有 worktree，沙箱和钩子开着。
• 测试、审阅，再由人合并，然后才开始下一波。
• 回顾：智能体数量、花费、失败、改进。
