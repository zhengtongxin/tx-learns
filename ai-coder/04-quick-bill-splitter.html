Quick bill splitter快速分账小工具

Vibe-code a small bill splitter from a brief and a test, then decide whether to keep it · ~30 min · project用一份简报和一个测试，凭感觉做出分账小工具，再决定留不留 · 约 30 分钟 · 项目

Step 1 · Write the brief as a test第 1 步 · 把简报写成测试

Learn先学

Fast does not mean vague. Give the agent a brief (who it is for, what it does, what done looks like) and, best of all, a test it can run. A test is a brief the computer can check.

快不等于含糊。给智能体一份简报（给谁用、做什么、怎样算完成），最好再加一个它能运行的测试。测试就是电脑能检查的简报。

Our tool splits a Singapore hawker-centre bill: each dish is shared by some people, a 10% service charge is added, then 9% GST. Money is kept in cents, and the shares must add up to the exact total.

我们的小工具要拆一张新加坡小贩中心的账单：每道菜由几个人分，加 10% 服务费，再加 9% 消费税（GST）。金额用分来存，每个人的份额加起来必须正好等于总额。

Build splitBill(items, options) in split.js (plain Node.js, no packages). items: [{ name, cents, who: ['Mei', 'Raj'] }] - the people sharing that dish. options: { service: 0.10, gst: 0.09 } Return { total, shares } where shares is { person: cents }. Rules: service charge first, then GST on both. Shares must add up to total exactly. Throw an Error if a dish has nobody sharing it. Done when: node test_split.js prints an ok line.

Step 2 · Let the agent build; you run and read第 2 步 · 让智能体去做；你来运行、来读

Learn先学

Open the starter/ folder in your agent of choice, give it the brief and tell it to run the test until it passes. Then do what vibe coding usually skips: run it yourself, and skim the diff for anything odd, such as a new dependency or a rounding shortcut.

在你选的智能体里打开 starter/ 文件夹，把简报给它，让它一直跑测试到通过。然后做凭感觉编程常跳过的一步：自己运行一遍，并扫一眼改动，看有没有怪东西，比如多出的依赖或偷懒的取整。

Rounding is the trap. Cents cannot be split evenly, so a fair tool hands the leftover cent to someone, and still adds up.

取整是陷阱。分不能平均切开，所以公平的工具要把剩下的那一分交给某个人，而且总数仍然对得上。

Step 3 · Keep it or throw it away第 3 步 · 留下，还是扔掉

Learn先学

Set a time box (say 30 minutes) before you start. When time is up, decide: if you will use it again, add the test to a repository and a one-line README. If not, delete it without guilt. Throwaway code is the point of vibe coding.

开始之前先定一个时间盒（比如 30 分钟）。时间到了就决定：还会再用，就把测试放进仓库，再写一行 README；不会再用，就毫不心疼地删掉。一次性的代码正是凭感觉编程的意义。

One rule never bends: do not hand a throwaway tool real secrets or real customers' data.

有一条规矩永远不松：不要把真实密钥或真实客户的数据交给一个一次性小工具。

Sort each one.

给每一项分类。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Fast is not vague: a brief plus a test.
• A test is a brief the computer can check.
• Skim the diff even when you vibe.
• Set a time box, then keep or delete.
• Money in integer cents, shares that add up.

• 快不等于含糊：简报加测试。
• 测试就是电脑能检查的简报。
• 凭感觉做也要扫一眼改动。
• 先定时间盒，再决定留还是删。
• 金额用整数分，份额要加得起来。
