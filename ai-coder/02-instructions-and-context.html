Instructions and context指令与上下文

Give an agent a short instruction file and keep its context clean · ~11 min · concepts给智能体一份简短的说明文件，并保持它的上下文干净 · 约 11 分钟 · 讲概念

Step 1 · Context is the whole job第 1 步 · 上下文就是全部

Learn先学

A model only knows what is in its context: your instructions, the files it has read, the conversation so far. The window is limited, and a crowded one makes answers worse, not better.

模型只知道它上下文里的东西：你的指令、它读过的文件、到目前为止的对话。窗口是有限的，塞得太满，回答反而更差。

So most of coding with agents is deciding what the agent sees. A clear request plus the right three files beats a vague request plus the whole repository.

所以用智能体写代码，大半功夫在于决定它能看到什么。清楚的请求加上恰当的三个文件，胜过含糊的请求加整个代码库。

Step 2 · AGENTS.md: the project briefing第 2 步 · AGENTS.md：项目简报

Learn先学

AGENTS.md is a plain Markdown file in your repository root that coding agents read at the start. Many tools read it, including Codex, Cursor, Copilot and OpenCode. Claude Code reads CLAUDE.md; a one-line file that says to read AGENTS.md keeps both in step.

AGENTS.md 是放在仓库根目录的普通 Markdown 文件，编程智能体一开始就会读它。很多工具都读它，包括 Codex、Cursor、Copilot 和 OpenCode。Claude Code 读的是 CLAUDE.md；让它写一行“请读 AGENTS.md”，两边就能保持一致。

Put in what an agent cannot guess: how to run, test and format; the rules of the codebase; what never to touch. Keep it short. Every line is read on every task.

只写智能体猜不到的东西：怎么运行、测试、格式化；这个代码库的规矩；什么绝对不能碰。要短，因为每个任务都会把每一行读一遍。

# Shop booking app ## Commands - Install: npm install - Test: npm test (run before you say you are done) - Dev server: npm run dev ## Rules - Plain JavaScript, no new dependencies without asking. - Money is stored as integer cents, never as decimals. - Never edit files in generated/ or .env. ## Layout - src/ app code, test/ tests, docs/api.md the API we promise

Step 3 · Keeping context clean第 3 步 · 保持上下文干净

Learn先学

Start a fresh session for each new task, so old talk does not leak in. When a long session gets muddy, summarise what matters and restart rather than push on.

每个新任务都开一个新会话，免得旧的闲聊混进来。长会话变得混乱时，先总结要点再重新开始，不要硬撑。

Point to files by name instead of pasting them. Give the agent a way to check itself, such as the test command. An agent that can run the tests needs far less hand-holding.

用文件名指给它看，不要整段粘贴。给它一个自检的办法，比如测试命令。能自己跑测试的智能体，需要的指点少得多。

Never put secrets in AGENTS.md or in a prompt. Keys live in environment variables the agent is not told.

不要把密钥写进 AGENTS.md 或提示词。密钥放在环境变量里，别告诉智能体。

Should it go in AGENTS.md?

该不该写进 AGENTS.md？

Now make it yours现在把它变成你的

Takeaways要点回顾

• The agent knows only what is in its context.
• AGENTS.md holds commands, rules and boundaries, in few lines.
• Fresh session per task; point to files instead of pasting.
• Give the agent a way to check itself.
• No secrets in prompts or instruction files.

• 智能体只知道它上下文里有的东西。
• AGENTS.md 只放命令、规矩和边界，越短越好。
• 每个任务一个新会话；指向文件，不要整段粘贴。
• 给智能体一个自检的办法。
• 提示词和说明文件里不放密钥。
