Terminal agents终端智能体

Work with a coding agent in the terminal, and keep control with permission modes · ~11 min · concepts在终端里和编程智能体一起工作，并用权限模式保持掌控 · 约 11 分钟 · 讲概念

Step 1 · Why the terminal第 1 步 · 为什么用终端

Learn先学

A terminal agent runs in the command line, next to your code. It works with any editor, runs over SSH on a server, and can be scripted: one command in, one result out, which makes it easy to use in checks and automations.

终端智能体在命令行里运行，就在你的代码旁边。它能配任何编辑器，能在服务器上通过 SSH 运行，还能被脚本化：一条命令进去、一个结果出来，很适合放进检查和自动化流程。

Claude Code (from Anthropic) is the best-known. OpenCode is open source and works with models from many providers. Codex and Gemini each have a command-line tool too. Their habits are alike: start in your project folder, describe the task, approve or refuse each step.

最有名的是 Claude Code（Anthropic 出品）。OpenCode 是开源的，能配很多服务商的模型。Codex 和 Gemini 也各有命令行工具。它们的习惯很像：在项目文件夹里启动、描述任务、逐步批准或拒绝。

cd my-project claude # start an interactive session in this folder claude -p "list the TODO comments in src/" # one answer, then exit (scriptable)

Step 2 · Permissions: you hold the brake第 2 步 · 权限：刹车在你手里

Learn先学

By default the agent asks before it edits a file or runs a command. You can loosen this in steps: allow edits without asking, allow specific safe commands such as the test command, or switch on a plan mode where it may only read and propose.

默认情况下，智能体改文件或运行命令之前会先问你。你可以分级放宽：允许不经询问地编辑、允许某些安全的命令（比如测试命令），或者打开计划模式，让它只读和提方案。

Plan first, then execute: ask for a plan, read it, fix it, then let it edit. Most wasted work comes from an agent that charged ahead on a wrong idea.

先计划、再执行：先要一份计划，读完、改好，再让它动手。多数白费的功夫，来自智能体在错误想法上一路冲到底。

In Claude Code the loosening lives in a small settings file you can commit, so the whole team shares it. Other tools have an equivalent file; the idea is the same.

在 Claude Code 里，放宽权限写在一个可以提交的小设置文件里，整个团队共用。别的工具也有类似的文件，思路一样。

{ "permissions": { "allow": ["Bash(npm test)", "Bash(git diff:*)"], "deny": ["Read(./.env)"] } }

Allowed: the test command and reading diffs, with no prompt. Denied: the agent can never read your .env file of keys. Everything else still asks.

允许：运行测试和查看 diff，不再提示。拒绝：智能体永远不能读你放密钥的 .env 文件。其余一切仍然会先询问。

Step 3 · Choosing and staying safe第 3 步 · 选择与安全

Learn先学

Pick by fit: a closed tool with the vendor's best model, or an open one where you choose the model and the bill. Try the same small task in two and keep the one you trust.

按适合度选：用厂商自家最强模型的闭源工具，或你自己选模型、自己管账单的开源工具。拿同一个小任务在两个里各试一遍，留下你信得过的那个。

Flags that skip every permission prompt exist. Use them only inside a throwaway sandbox (see Sandboxing), never on your real laptop with your real keys.

确实有“跳过所有权限提示”的开关。只能在用完即弃的沙箱里用（见“沙盒”一课），绝不要在装着真实密钥的真实电脑上用。

Sort each one.

给每一项分类。

Step 4 · Read a permission file like a gate第 4 步 · 像看一道门那样读权限文件

Learn先学

A rule matches a pattern, and anything the rules do not name still asks. Take the settings file from Step 2 and ask what each command would do. (Exact matching rules differ between tools and versions, so confirm them in your tool’s own page; the thinking is what carries over.)

规则匹配的是某种写法，规则没提到的一概还是要询问。拿第 2 步的设置文件，问问每条命令会怎样。（各工具、各版本的精确匹配规则不同，请到你所用工具自己的页面确认；能带走的是这种思路。）

npm test runs, no prompt (listed exactly) npm test -- --watch asks: it is not the exact text that was listed git diff HEAD~1 runs, no prompt (a git diff command, any arguments) git push origin main asks: nothing allows it Read ./.env (file tool) refused: denied cat .env (shell command) asks, but it is NOT covered by the Read rule

The last two lines are the lesson. A deny on the file-reading tool does not automatically cover a shell command that reads the same file. A rule file is a convenience for you, not a security boundary. To keep the keys really out of reach, keep them out of the folder, or run the agent in a sandbox where the file is not there.

最后两行才是重点。对文件读取工具的禁止，并不会自动覆盖一条读同一个文件的 shell 命令。规则文件是给你方便用的，不是安全边界。要让密钥真正碰不到，就别把它放在项目文件夹里，或者让智能体在没有这个文件的沙盒里运行。

Now make it yours现在把它变成你的

Takeaways要点回顾

• A terminal agent sits beside your code and can be scripted.
• Claude Code and OpenCode are two examples; habits carry across.
• Approve by default, allow safe commands, plan before editing.
• Skip-all-permissions only in a disposable sandbox.

• 终端智能体就在你的代码旁边，还能被脚本化。
• Claude Code 和 OpenCode 是两个例子；习惯可以通用。
• 默认逐步批准，放行安全命令，改动前先计划。
• “跳过所有权限”只能用在用完即弃的沙箱里。
