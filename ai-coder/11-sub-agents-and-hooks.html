Sub-agents and hooks子智能体与钩子

Split work across sub-agents with their own context, and enforce rules with hooks · ~11 min · concepts把工作分给各有上下文的子智能体，并用钩子强制执行规则 · 约 11 分钟 · 讲概念

Step 1 · Sub-agents: a fresh desk for one job第 1 步 · 子智能体：为一件事准备的干净桌面

Learn先学

A sub-agent is a helper the main agent hands one narrow job to. It works in its own context and sends back a short result, so the main conversation stays clean. It does not see the main chat, so the brief must stand alone.

子智能体是主智能体把一件窄任务交出去的助手。它在自己的上下文里工作，只送回一个简短的结果，所以主对话保持干净。它看不到主对话，所以交代的简报必须自成一体。

Good uses: searching a big codebase, reviewing a diff with fresh eyes, running a slow check. You define one in a Markdown file with a name, a description of when to use it, and the tools it may use.

适合的用途：搜索大型代码库、用“新鲜的眼睛”审阅改动、运行耗时的检查。你用一个 Markdown 文件来定义：名字、何时使用的描述，以及它能用的工具。

--- name: reviewer description: Reviews a diff for bugs, missing tests and secrets. Use after a change is written. tools: Read, Grep, Glob, Bash --- You are a strict code reviewer. You may read and run tests but never edit files. Report: must fix, should fix, fine. Quote the file and line for each point.

Step 2 · Hooks: rules that always run第 2 步 · 钩子：永远会执行的规则

Learn先学

A line in AGENTS.md is a request; the agent can forget it. A hook is a command your tool runs automatically at a set moment, such as before a tool call or after a file edit. It runs every time, whatever the agent decides.

AGENTS.md 里的一行字只是请求，智能体可能忘记。钩子是你的工具在固定时刻自动运行的命令，比如调用工具之前、编辑文件之后。不管智能体怎么决定，它每次都会执行。

Use hooks for what must always happen: format after each edit, run the tests when the agent says it is done, block a dangerous command.

用钩子做“必须永远发生”的事：每次编辑后格式化、智能体说做完时运行测试、拦截危险命令。

{ "hooks": { "PreToolUse": [ { "matcher": "Bash", "hooks": [{ "type": "command", "command": ".claude/hooks/guard.sh" }] } ] } }

Step 3 · A guard that blocks第 3 步 · 一道会拦截的守卫

Learn先学

The hook receives the pending tool call as JSON. If it exits with code 2, the call is blocked and its message goes back to the agent, which then picks another way.

钩子会以 JSON 的形式收到即将执行的工具调用。如果它以退出码 2 结束，这次调用就被拦下，它的提示会回给智能体，让它另想办法。

Keep guards narrow and fast. A guard that blocks too much teaches people to switch it off.

守卫要窄、要快。拦得太多，人们就会学会把它关掉。

#!/usr/bin/env bash # Reads the pending tool call as JSON on stdin. Exit 2 = block it. cmd=$(jq -r '.tool_input.command // empty') case "$cmd" in *"rm -rf"*|*"git push --force"*) echo "Blocked: a person must run this one." >&2 exit 2 ;; esac

Sort each one.

给每一项分类。

Step 4 · Test the guard, then see what slips past第 4 步 · 测试守卫，再看什么能溜过去

Learn先学

A hook is code, so test it like code: feed it a pending call and check the exit code. Save the guard from Step 3 as guard.sh (run it with bash guard.sh, so it needs no extra setup), then send it a fake tool call as JSON. (jq is a small command-line tool that reads JSON; echo $? prints the exit code of the last command.)

钩子是代码，就要像测代码一样测它：喂给它一个待执行的调用，看退出码。把第 3 步的守卫存成 guard.sh（用 bash guard.sh 运行，不用额外设置），再用 JSON 给它发一个假的工具调用。（jq 是读取 JSON 的命令行小工具；echo $? 会打印上一条命令的退出码。）

echo '{"tool_input":{"command":"rm -rf build"}}' | bash guard.sh echo $? # 2: blocked, the message went to stderr echo '{"tool_input":{"command":"rm -rf build"}}' | bash guard.sh echo $? # 0: two spaces, and it slipped past echo '{"tool_input":{"command":"git push -f origin main"}}' | bash guard.sh echo $? # 0: the short flag slipped past too

Exact-text matching is fragile. A pattern is better, for instance grep -Eq 'rm +-[a-z]*(rf|fr)|git +push .*(--force|-f)( |$)', which catches the extra space, rm -fr and -f. It still misses a disguised command such as sh -c "r""m -rf x", and it blocks a harmless echo "rm -rf".

按原文匹配很脆弱。用模式更好，比如 grep -Eq 'rm +-[a-z]*(rf|fr)|git +push .*(--force|-f)( |$)'，它能抓住多出来的空格、rm -fr 和 -f。但它仍然漏掉伪装过的命令，比如 sh -c "r""m -rf x"，还会误拦无害的 echo "rm -rf"。

So a guard is a safety net for honest mistakes, not a wall against a determined trick. Pair it with a sandbox so that what slips through cannot reach anything valuable.

所以守卫是防范无心之失的安全网，挡不住处心积虑的花招。要和沙盒搭配，让漏过去的东西也碰不到有价值的东西。

Now make it yours现在把它变成你的

Takeaways要点回顾

• A sub-agent works in its own context and returns a short result.
• Its brief must stand alone: it cannot see your chat.
• AGENTS.md asks; a hook enforces.
• Exit code 2 blocks a call and tells the agent why.
• Keep guards narrow, or people switch them off.

• 子智能体在自己的上下文里工作，只返回简短结果。
• 它的简报必须自成一体：它看不到你的对话。
• AGENTS.md 是请求；钩子是强制。
• 退出码 2 会拦下调用，并告诉智能体原因。
• 守卫要窄，否则人们会把它关掉。
