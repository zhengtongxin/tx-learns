Agentic engineering · Lesson 4智能体工程 · 第 4 课

Swarms and orchestrators智能体群与调度器

Run many agents at once with one lead, split by files, and kept on a leash · ~14 min · concepts让多个智能体同时工作：一个负责人、按文件切分，并且受到约束 · 约 14 分钟 · 讲概念

Step 1 · Orchestrator and workers第 1 步 · 调度者与执行者

Learn先学

In a swarm, one orchestrator agent breaks a goal into tasks and hands each to a worker agent. Workers run at the same time, each in its own worktree (a second checkout of the same repo, in its own folder), and report back. The orchestrator checks the results and puts them together.

在智能体群里，一个调度者智能体把目标拆成任务，每个任务交给一个执行者智能体。执行者同时开工，各在自己的 worktree（同一个仓库的另一份检出，放在自己的文件夹里）里，做完回报。调度者检查结果并把它们合起来。

It pays off when the tasks are independent: many files to convert, many modules to test, many pages to build. It does not pay off for one tangled problem, where agents just wait for each other.

任务彼此独立时才划算：很多文件要转换、很多模块要测试、很多页面要搭建。一个纠缠在一起的问题就不划算，因为智能体只是在互相等。

Step 2 · Split so workers never collide第 2 步 · 切分到工人互不冲突

Learn先学

Two agents editing the same file is how swarms fail. Give every task a list of the files it may touch and the tasks it depends on. Tasks with no shared files and no open dependencies can run together; the rest wait for a later wave.

两个智能体改同一个文件，是智能体群失败的典型方式。给每个任务写明它可以碰的文件和它依赖的任务。没有共享文件、依赖也都完成的任务可以一起跑；其余的等到后面的一波。

Writing the plan as data, not prose, lets a script check it: no unknown dependencies, no circular ones, no two tasks in the same wave sharing a file. You build exactly that planner in the project.

把计划写成数据而不是散文，脚本就能检查：没有未知依赖、没有循环依赖、同一波里没有两个任务共享一个文件。你会在项目里做出的就是这样一个规划器。

[ { "id": "api", "deps": [], "files": ["src/api.js"] }, { "id": "ui", "deps": ["api"], "files": ["src/ui.js"] }, { "id": "tests", "deps": ["api"], "files": ["test/api.test.js"] }, { "id": "docs", "deps": [], "files": ["README.md"] } ]

Step 3 · Keep the swarm on a leash第 3 步 · 给群体套上缰绳

Learn先学

Cost multiplies with every agent. Set a cap on how many run at once, a budget in money or tokens, and a stop rule for tasks that keep failing.

每多一个智能体，花费就成倍增加。要设置并发上限、以金钱或 token 计的预算，以及对反复失败的任务的停止规则。

Always add a check: tests per task, then a separate reviewer agent over the whole result. Let a person merge. More agents make more output, not more correctness.

一定要加检查：每个任务有测试，再由一个独立的审阅智能体看整体结果。让人来合并。智能体多了，只是产出多了，不是正确性多了。

Sort each one.

给每一项分类。

Step 4 · From plan to waves第 4 步 · 从计划到几波

Learn先学

A wave is a set of tasks that can run together. Start with the plan above. api and docs have no dependencies and share no file, so they form wave 1. ui and tests both wait for api, so they could form wave 2.

一波就是可以同时运行的一组任务。从上面的计划开始：api 和 docs 没有依赖，也不共享文件，所以是第 1 波。ui 和 tests 都要等 api，本来可以是第 2 波。

Now suppose both also need to edit src/index.js. The planner must not put them in the same wave. This small script does the grouping and gives three waves, not two.

现在假设它们都要改 src/index.js。规划器不能把它们放进同一波。下面这个小脚本负责分组，结果是三波，不是两波。

const tasks = [ { id: "api", deps: [], files: ["src/api.js"] }, { id: "ui", deps: ["api"], files: ["src/ui.js", "src/index.js"] }, { id: "tests", deps: ["api"], files: ["test/api.test.js", "src/index.js"] }, { id: "docs", deps: [], files: ["README.md"] }, ]; const done = new Set(), waves = []; // a Set is a list with no repeats while (done.size < tasks.length) { const wave = [], used = new Set(); for (const t of tasks) { if (done.has(t.id) || !t.deps.every(d => done.has(d))) continue; // not ready yet if (t.files.some(f => used.has(f))) continue; // a file is already taken in this wave wave.push(t.id); t.files.forEach(f => used.add(f)); } if (wave.length === 0) throw new Error('stuck: a dependency is missing or circular'); wave.forEach(id => done.add(id)); waves.push(wave); } console.log(waves); // [ [ 'api', 'docs' ], [ 'ui' ], [ 'tests' ] ]

Now make it yours现在把它变成你的

Takeaways要点回顾

• One orchestrator splits the goal; workers run in parallel in their own worktrees.
• Swarms suit independent tasks, not one tangled problem.
• Give each task its files and dependencies; no shared files in one wave.
• Cap the agents, the budget and the retries; a person merges.

• 一个调度者拆目标；执行者在各自的 worktree 里并行。
• 智能体群适合独立任务，不适合一个纠缠的问题。
• 给每个任务写明文件和依赖；同一波里不共享文件。
• 限制智能体数量、预算和重试次数；由人合并。
