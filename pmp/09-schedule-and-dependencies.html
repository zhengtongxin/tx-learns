Schedule and dependencies进度与依赖

Step 1 · Four dependencies第 1 步 · 四种依赖

Learn先学

A dependency says how one activity relates to another. Read it as predecessor first, successor second, then pair the words: the first is about the predecessor, the second about the successor.

依赖关系说明一个活动与另一个活动的关系。读法是先前置、后后续，再配对两个词：第一个词说前置活动，第二个词说后续活动。

Finish-to-start (FS) is the most common and is the default: you must finish painting before you start hanging pictures. The other three are less common but appear in exam questions.

完成到开始（FS）最常见，也是默认的：刷完墙才能挂画。另外三种较少用，但会出现在考题里。

FS finish -> start paint walls, then hang pictures SS start -> start start digging, then start laying pipe FF finish -> finish finish writing, then finish proofreading SF start -> finish new guard starts, then old guard may finish SF is the rarest. Read it the same way: A starts, then B finishes.

Sort each one.

给每一项分类。

Step 2 · Critical path and float第 2 步 · 关键路径与浮动

Learn先学

The critical path is the longest chain of dependent activities from start to finish. It decides the shortest time the project can take. A delay on it delays the whole project by the same amount.

关键路径是从头到尾最长的一串相互依赖的活动，它决定项目最短能多快完成。关键路径上的延误会等量推迟整个项目。

Float (or slack) is how long an activity can slip without delaying anything important. On the critical path, float is zero. Off it, float is positive, and you can use it to move resources.

浮动时间是一个活动能拖延多久而不影响关键事项。关键路径上的浮动是零；不在关键路径上的浮动为正，可以用来调配资源。

Path 1: A (3) -> B (4) -> D (2) = 9 Path 2: A (3) -> C (2) -> D (2) = 7 Critical path: A-B-D, 9 units. Float on C = 9 - 7 = 2 units.

Step 3 · Lead, lag and compression第 3 步 · 提前量、滞后量与压缩

Learn先学

A lead lets a successor start earlier, overlapping the predecessor: start laying carpet two days before painting ends. A lag forces a wait: let concrete cure for three days before building on it.

提前量让后续活动更早开始，与前置活动重叠：刷漆结束前两天就开始铺地毯。滞后量强制等待：混凝土养护三天后才能在上面施工。

To shorten the schedule, compress the critical path. Crashing adds resources, such as overtime or extra people, so it raises cost. Fast tracking runs activities in parallel that were planned in sequence, so it raises risk of rework. Compression only helps on the critical path.

要缩短工期，就压缩关键路径。赶工是增加资源，比如加班或加人，所以会增加成本。快速跟进是把原计划顺序做的活动改成并行，所以会增加返工风险。压缩只有用在关键路径上才有效。

Now make it yours现在把它变成你的

Takeaways要点回顾

• FS is the default; read dependencies as predecessor then successor.
• The critical path is the longest path and has zero float.
• Float is how far an activity can slip without hurting the end date.
• A lead overlaps activities; a lag forces a wait.
• Crashing adds cost; fast tracking adds risk; both work only on the critical path.

• FS 是默认关系；读依赖时先前置、后后续。
• 关键路径是最长路径，浮动为零。
• 浮动时间是活动在不影响完工日期下可拖延的长度。
• 提前量让活动重叠，滞后量强制等待。
• 赶工增加成本，快速跟进增加风险，两者只对关键路径有效。
