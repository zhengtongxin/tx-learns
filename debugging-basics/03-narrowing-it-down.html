Finding the bug · Lesson 3找到问题 · 第 3 课

Narrowing it down缩小范围

Cut the search in half again and again until only the cause is left · ~10 min · reading and practice一次次把搜索范围砍掉一半，直到只剩下原因 · 约 10 分钟 · 阅读加练习

Step 1 · Guess, then test第 1 步 · 先猜，再验证

Learn先学

Staring at code hoping the bug shows itself is slow. Instead, state a guess: “the value is already wrong when it reaches this function”. Then run something that can prove it wrong: print the value there, or call the function alone. A guess that is proven wrong still helps, because it removes a part of the code from the search.

盯着代码等问题自己现形很慢。换个办法：说出一个猜测——“值在到达这个函数时就已经不对了”。然后运行一个能推翻它的东西：在那里打印这个值，或单独调用这个函数。被推翻的猜测同样有用，因为它把一部分代码从搜索范围里去掉了。

Step 2 · Halve the search第 2 步 · 对半查找

Learn先学

If the data is right at the start and wrong at the end, check the middle. If it is right in the middle, the problem is in the second half; if wrong, in the first. Each check halves what is left. Sixteen steps need only four checks, and a thousand need about ten. This works on code, on data files and on a list of changes.

如果数据在开头是对的、结尾是错的，就检查中间。中间是对的，问题就在后半段；是错的，就在前半段。每检查一次，剩下的范围就少一半。十六步只需四次检查，一千步大约十次。这个办法适用于代码、数据文件和一串改动。

lo, hi = 1, 16 steps = 0 while lo < hi: mid = (lo + hi) // 2 steps += 1 if mid >= 11: # version 11 is the first bad one hi = mid else: lo = mid + 1 print(lo, steps)

Step 3 · Ask when it broke第 3 步 · 问问什么时候坏的

Learn先学

If it worked last week, the cause is among the changes since then. Version control (a tool that records every change to your files, such as git) can halve that list for you: mark a version that worked and one that does not, check the version in the middle, and repeat. Finding the single change that broke things is often faster than understanding the whole system. Then read that one change.

如果上周还是好的，原因就在这之后的改动里。版本控制（记录你文件每一次改动的工具，比如 git）可以替你把这个清单对半砍：标出一个好的版本和一个坏的版本，检查中间的版本，如此重复。找出那一个导致问题的改动，往往比理解整个系统更快。然后只读这一个改动。

Takeaways要点回顾

• State a guess you can test.
• Halve the search: check the middle.
• When it broke tells you what broke it.

• 说出一个可以验证的猜测。
• 对半查找：检查中间。
• 什么时候坏的，就能告诉你是什么搞坏的。
