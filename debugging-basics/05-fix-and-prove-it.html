Fixing it for good · Lesson 2彻底修好 · 第 2 课

Fix and prove it修复并证明

Fix the cause, add a test that would have caught it and check you broke nothing else · ~10 min · reading and practice修掉原因，加一个本来能抓住它的测试，并确认没有弄坏别的东西 · 约 10 分钟 · 阅读加练习

Step 1 · Cause, not symptom第 1 步 · 修原因，不修症状

Learn先学

A symptom is what you see: the crash, the wrong number. The cause is why it happens. Wrapping a crash in a try block that ignores it hides the symptom and leaves the cause, and the bad value flows on to break something else later. Ask “why was this value ever wrong?” until you reach the place it was made, and fix it there.

症状是你看到的：崩溃、错的数字。原因是它为什么会发生。把崩溃包进一个忽略它的 try 里，只是藏起了症状、留下了原因，坏值会继续流动，之后弄坏别的东西。一直问“这个值当初为什么会错？”，直到找到它产生的地方，在那里修。

Step 2 · Turn the bug into a test第 2 步 · 把问题变成测试

Learn先学

Take the minimal example from before and turn it into a test that fails now. Then fix the code until it passes. The test proves the fix worked, and it stays in the project to catch the same bug if someone brings it back. A bug fixed without a test tends to return.

拿前面得到的最小示例，把它变成一个现在会失败的测试。然后改代码，直到测试通过。这个测试证明了修复有效，并留在项目里，万一有人把同样的问题带回来，它就能抓住。没有测试的修复，问题往往会回来。

def last_word(s): return s.split()[-1] # the fix: split() with no argument skips extra spaces # the test, written first: assert means "this must be true, or stop with an error" # before the fix (split(" ")) it failed; with the fix below it passes assert last_word("hi there ") == "there" print(last_word("hi there ")) print(len(" ".split())) # an edge case, explained in the next step

Step 3 · Check the neighbours第 3 步 · 检查相邻的东西

Learn先学

A fix can break something nearby. Run the whole test suite, not only the new test. Look at the edge cases next to your bug: if a trailing space was the problem, what about an empty string, or only spaces? Notice that the fixed function above would still fail on " ", because there is no last word to return. Decide what it should do, and write that down as another test.

修复可能弄坏附近的东西。要运行整个测试集，而不是只跑新测试。看看你那个问题旁边的边界情况：如果问题是末尾空格，那空字符串或全是空格呢？注意，上面修好的函数遇到 " " 仍然会出错，因为根本没有最后一个词可返回。决定它应该怎么办，并把这个决定写成另一个测试。

Takeaways要点回顾

• Fix where the bad value is made, not where it crashes.
• Turn the bug into a test before you fix it.
• Run everything, and test the edges next door.

• 在坏值产生的地方修，而不是在它崩溃的地方。
• 修之前，先把问题变成测试。
• 运行全部测试，并测试相邻的边界。
