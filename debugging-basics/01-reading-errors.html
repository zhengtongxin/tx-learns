Reading errors读懂报错

Read an error message from the bottom up and learn what it is telling you · ~10 min · reading and practice从下往上读报错信息，弄懂它在告诉你什么 · 约 10 分钟 · 阅读加练习

Step 1 · The message is a clue第 1 步 · 报错是一条线索

Learn先学

An error message is the program telling you what it was doing and why it stopped. Beginners often skim it, feel panic and start changing code at random. Slow down: the message is the most precise information you will get all day.

报错信息是程序在告诉你它在做什么、为什么停下来。新手常常扫一眼、心里一慌就开始乱改代码。慢下来：这条信息是你一整天里能拿到的最精确的信息。

Read it from the bottom up. The last line names the kind of error and says what went wrong. The lines above it are the traceback, the chain of calls that led there, with the most recent call last. Start with the last line, then find the closest line of your own code in the list above.

要从下往上读。最后一行说出错误的种类和出了什么问题。它上面是回溯，即一路调用下来的链条，最近的调用排在最后。先看最后一行，再在上面的列表里找离它最近的、你自己写的那行代码。

Traceback (most recent call last): File "app.py", line 7, in <module> print(average([])) File "app.py", line 3, in average return total / len(items) ZeroDivisionError: division by zero

Step 2 · Name the kind of error第 2 步 · 说出错误的种类

Learn先学

The name before the colon tells you the family of the problem. ValueError: the right kind of value, but not an acceptable one. TypeError: the wrong kind of value for the operation. KeyError: a dictionary has no such key. IndexError: a list is not that long. ZeroDivisionError: you divided by zero. Once you can name the family, you know where to look.

冒号前面的名字告诉你问题属于哪一类。ValueError：值的种类对，但不被接受。TypeError：值的种类不适合这个操作。KeyError：字典里没有这个键。IndexError：列表没有那么长。ZeroDivisionError：除以了零。能说出类别，就知道该去哪里找。

def f(x): return 10 / x try: f(0) except ZeroDivisionError as e: # "as e" names the error object print(type(e).__name__, e) # its kind, then its message

Step 3 · Say it in plain words第 3 步 · 用大白话说出来

Learn先学

Before touching the code, put the message in one plain sentence: “line 7 divided by something that was zero”. Then ask the next question: where did that zero come from? The error shows where the program stopped, and the real cause is often earlier, at the place the bad value was made.

动代码之前，先用一句大白话复述这条信息：“第 7 行除以了一个为零的东西”。然后问下一个问题：这个零是从哪来的？报错显示的是程序在哪里停下，真正的原因往往更早，在坏值产生的地方。

Takeaways要点回顾

• Read the traceback from the bottom up.
• The error’s name tells you which family of problem it is.
• Where it stopped is not always where it began.

• 从下往上读回溯。
• 错误的名字告诉你它属于哪一类问题。
• 停下的地方不一定是出问题的地方。
