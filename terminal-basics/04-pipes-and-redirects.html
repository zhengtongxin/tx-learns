Pipes and redirects管道与重定向

Send output to a file, chain small commands together and see why this beats one big tool · ~10 min · reading and practice把输出写进文件，把小命令串起来，并明白为什么这比一个大工具更强 · 约 10 分钟 · 阅读加练习

Step 1 · Output to a file第 1 步 · 输出到文件

Learn先学

Commands print to the screen, but > sends that output into a file instead: ls > files.txt. It replaces the file if it exists. >> appends to the end instead. Nothing is printed on screen, so open the file to see the result.

命令默认打印到屏幕，而 > 把输出改送进文件：ls > files.txt。文件已存在时会被替换。>> 则追加到末尾。屏幕上不会打印什么，要打开文件看结果。

echo "tea" > menu.txt echo "coffee" >> menu.txt cat menu.txt

Step 2 · The pipe第 2 步 · 管道

Learn先学

A pipe | feeds the output of one command into the next as its input. Each tool does one small job and you combine them: cat log.txt | grep ERROR | wc -l reads the log, keeps the error lines and counts them. This is the idea behind most shell work.

管道 | 把一条命令的输出送进下一条命令当输入。每个工具只做一件小事，再把它们组合起来：cat log.txt | grep ERROR | wc -l 读日志、留下错误行、再数出行数。大多数 shell 工作都基于这个想法。

Step 3 · Build a pipeline第 3 步 · 拼一条流水线

Learn先学

Build pipelines one step at a time: run the first command, check the output, then add the next stage. sort orders lines, uniq -c counts neighbours that repeat (so sort first), and head keeps the top few. A stage that goes wrong is easy to spot when you grew the line gradually.

一步一步拼流水线：先运行第一条命令，检查输出，再加下一级。sort 给行排序，uniq -c 统计相邻重复的行（所以要先排序），head 只留前几行。逐步加长，哪一级出错就很容易发现。
