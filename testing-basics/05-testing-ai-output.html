Testing AI output测试 AI 的输出

Check answers that are different every time, by testing properties and a small set of examples · ~10 min · reading and practice检查每次都不一样的回答：测试性质，并用一小组样例 · 约 10 分钟 · 阅读加练习

Step 1 · Properties, not exact text第 1 步 · 测性质，不测原文

Learn先学

A model rarely gives the same words twice, so assert reply == "Sure!" is brittle. Test properties that must always hold: the reply is not empty, it is valid JSON, it contains one of the allowed labels, it is under 200 words, it does not leak the system prompt.

模型很少两次给出同样的措辞，所以 assert reply == "Sure!" 很脆弱。要测的是必须始终成立的性质：回答不为空、是合法的 JSON、包含允许的标签之一、少于 200 词、没有泄露系统提示。

Step 2 · Validate the shape第 2 步 · 校验形状

Learn先学

When your program depends on a structure, parse it and check it before use. Ask the model for JSON, load it, and reject anything missing a required key or using a value outside the allowed set. A validator turns a surprise in production into a clear error you can test.

当你的程序依赖某种结构时，使用之前先解析并检查。让模型输出 JSON，加载它，拒绝缺少必需键或值超出允许范围的结果。校验器把线上的意外变成可以测试的清楚错误。

import json ALLOWED = {"positive", "negative", "neutral"} def parse_label(raw): data = json.loads(raw) if data.get("label") not in ALLOWED: raise ValueError("bad label") return data["label"]

Step 3 · A small evaluation set第 3 步 · 一小组评估样例

Learn先学

Keep 20 to 50 real examples with the answer you want, and run them after every change to the prompt. Count how many pass, and treat a drop as a failed test. This is an eval: the unit test of AI work. Add every real failure you meet to the set so it can never come back unnoticed.

准备 20 到 50 个真实样例及你想要的答案，每次改提示词后都跑一遍。数一数通过多少个，把下降当作测试失败。这就是评估：AI 工作的单元测试。每遇到一个真实的失败，就加进样例集，让它再也不能悄悄回来。

Takeaways要点回顾

• Test properties that must always hold, not exact wording.
• Parse and validate structured output before using it.
• Keep a small eval set and treat a drop as a failing test.

• 测必须始终成立的性质，而不是精确措辞。
• 使用结构化输出之前先解析并校验。
• 保留一小组评估样例，把下降当作失败的测试。
