Edge cases边界情况

Test the empty, zero, negative and huge inputs where bugs actually hide · ~10 min · reading and practice测试空、零、负数和极大的输入，bug 真正藏身的地方 · 约 10 分钟 · 阅读加练习

Step 1 · Where bugs hide第 1 步 · bug 藏在哪

Learn先学

The typical input rarely breaks. Bugs live at the edges: empty lists, zero, negative numbers, one item, the largest allowed value, text with spaces or accents, missing fields. For every function ask “what is the weirdest input a real user could send?” and write a test for each.

典型的输入很少出问题。bug 住在边界上：空列表、零、负数、只有一项、允许的最大值、带空格或重音的文本、缺失的字段。对每个函数问一句“真实用户能给出的最怪的输入是什么”，并为每一种写一个测试。

Step 2 · Expecting an error第 2 步 · 期望出错

Learn先学

Good code refuses bad input loudly. A test can check that: call the code inside try and assert that the expected exception happened (with pytest: with pytest.raises(ValueError):). Silence on bad input is a bug.

好的代码会大声拒绝坏输入。测试也能检查这一点：把调用放进 try，断言发生了预期的异常（pytest 里是 with pytest.raises(ValueError):）。对坏输入保持沉默，本身就是 bug。

def average(nums): if not nums: raise ValueError("no numbers") return sum(nums) / len(nums) try: average([]) print("no error: bug") except ValueError: print("refused empty list")

Step 3 · Boundary values第 3 步 · 边界值

Learn先学

Bugs love the exact boundary. If a discount starts at 100, test 99, 100 and 101: an off-by-one mistake (> instead of >=) only shows at 100.

bug 最爱刚好卡在边界上。如果折扣从 100 开始，就测 99、100 和 101：差一错误（把 >= 写成 >）只在 100 这一点才会暴露。

Takeaways要点回顾

• Bugs hide at the edges: empty, zero, negative, one, exact limits.
• Test that bad input is refused loudly.
• Test the exact boundary, plus one on each side.

• bug 藏在边界：空、零、负数、一项、刚好的上限。
• 测试坏输入会被大声拒绝。
• 测试刚好的边界，以及两边各一个值。
