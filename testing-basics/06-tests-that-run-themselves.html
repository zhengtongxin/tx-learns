Tests that run themselves自动运行的测试

Run tests on every change automatically and keep them fast, trusted and worth the effort · ~10 min · reading and practice让测试在每次改动时自动运行，并保持快速、可信、值得投入 · 约 10 分钟 · 阅读加练习

Step 1 · Run on every change第 1 步 · 每次改动都运行

Learn先学

Tests you must remember to run get skipped. Continuous integration (CI) runs them automatically on a server every time you push code or open a pull request, and shows a green tick or a red cross next to the change. Many teams make a green tick a rule before merging, so a break is caught in minutes, not in production.

需要你记得去跑的测试，迟早会被跳过。持续集成（CI）在每次你推送代码或发起拉取请求时，自动在服务器上运行它们，并在改动旁边显示绿勾或红叉。许多团队规定绿勾才能合并，这样问题几分钟内就被发现，而不是等到线上。

name: tests on: [push, pull_request] jobs: test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - run: pip install pytest - run: pytest

Step 2 · Fast and repeatable第 2 步 · 快速且可重复

Learn先学

A test suite people trust is fast (seconds), repeatable (same result every run) and independent (any order, alone or together). A test that fails one run in twenty is worse than none: people learn to ignore red. Common causes are the clock, random numbers, shared files and the network. Fix the clock, seed the randomness, use temporary folders and fakes.

值得信任的测试集是快的（几秒）、可重复的（每次结果相同）、相互独立的（顺序任意，单独或一起跑都行）。每二十次才失败一次的测试比没有还糟：大家会学会无视红灯。常见原因是时钟、随机数、共享文件和网络。固定时钟、给随机数设种子、用临时文件夹和替身。

Step 3 · What is worth testing第 3 步 · 什么值得测

Learn先学

You cannot test everything, so spend effort where a bug would cost most: money, user data, rules that change often, and anything that broke before. A test for a bug you already fixed (a regression test) is the best value of all. Do not test the language or a library, only your own logic.

你不可能什么都测，所以把力气花在出了 bug 代价最大的地方：钱、用户数据、经常变化的规则，以及以前坏过的东西。给已经修好的 bug 写的测试（回归测试）性价比最高。不要去测语言或第三方库，只测你自己的逻辑。

Takeaways要点回顾

• CI runs tests on every change so nobody has to remember.
• Trusted tests are fast, repeatable and independent.
• Spend effort on costly risks, and add a test for every bug you fix.

• CI 在每次改动时运行测试，没人需要记得。
• 可信的测试快速、可重复、相互独立。
• 把力气花在代价高的风险上，每修一个 bug 就补一个测试。
