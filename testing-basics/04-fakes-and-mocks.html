Fakes and mocks替身与模拟

Test code that calls the network or a model by swapping the slow, costly part for a stand-in · ~10 min · reading and practice测试会调用网络或模型的代码：把又慢又贵的部分换成替身 · 约 10 分钟 · 阅读加练习

Step 1 · Keep tests offline第 1 步 · 让测试离线

Learn先学

A test that calls a real web API or an AI model is slow, costs money, needs a key and fails when the wifi does, for reasons that have nothing to do with your code. Pass the risky part in as a parameter, and in tests hand over a fake: a tiny stand-in that returns a fixed answer.

一个会调用真实 Web API 或 AI 模型的测试，又慢、又花钱、还要密钥，而且 wifi 一断就失败，这些都和你的代码无关。把有风险的部分作为参数传进来，测试时递给它一个替身：一个返回固定答案的小东西。

def greeting(get_name): return "Hello, " + get_name() # real use: greeting(lambda: ask_user()) # in a test: assert greeting(lambda: "Mei") == "Hello, Mei"

Step 2 · Record what happened第 2 步 · 记录发生了什么

Learn先学

A mock is a fake that also remembers how it was used, so the test can check what the code asked for: that the model was called once, with the right prompt. In Python unittest.mock.Mock does this for you: m.assert_called_once_with("hi").

模拟对象是会记住自己如何被使用的替身，这样测试就能检查代码向它要了什么：模型被调用了一次，并且用了正确的提示词。在 Python 里 unittest.mock.Mock 替你做到这一点：m.assert_called_once_with("hi")。

Takeaways要点回顾

• Tests should not call paid, slow or flaky services.
• Pass the risky part in, and hand a fake to the test.
• A mock also records how it was called.

• 测试不该调用付费、缓慢或不稳定的服务。
• 把有风险的部分传进来，测试时递一个替身。
• 模拟对象还会记录自己如何被调用。
