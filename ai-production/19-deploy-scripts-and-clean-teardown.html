Deploy scripts and teardown部署脚本与拆除

Wrap the steps in two scripts so deploying and destroying are one command each, and leave nothing running behind you · ~30 min · hands-on把步骤包进两个脚本，让部署和销毁各是一条命令，并且不在身后留下任何还在运行的东西 · 约 30 分钟 · 动手实践

Step 1 · A deploy script第 1 步 · 一个部署脚本

Learn先学

A deploy has an order: build the backend zip first (the function resource reads it), build the front end, select and print the workspace, apply, upload the site, tell the CDN to forget old copies, print the addresses. Put it in one script that takes the environment name. set -euo pipefail stops at the first error, and -auto-approve skips Terraform's yes/no question. The addresses come from outputs.tf, short blocks that expose resources from the last lesson. This script is for macOS and Linux.

部署有顺序：先构建后端 zip（函数资源要读它），构建前端，选中并打印工作区，apply，上传网站，让 CDN 忘掉旧副本，打印地址。把它放进一个接收环境名的脚本。set -euo pipefail 遇到第一个错误就停，-auto-approve 跳过 Terraform 的 yes/no 确认。地址来自 outputs.tf，那是几个暴露上一课资源的小块。这个脚本适用于 macOS 和 Linux。

#!/usr/bin/env bash set -euo pipefail ENV="${1:?usage: ./deploy.sh dev|test|prod}" ( cd backend && rm -rf package twin.zip \ && pip install --platform manylinux2014_x86_64 --target package --only-binary=:all: -r requirements.txt \ && cp *.py package/ && ( cd package && zip -qr ../twin.zip . ) ) ( cd frontend && npm ci && npm run build ) cd infra terraform workspace select -or-create "$ENV" echo "workspace: $(terraform workspace show)" terraform apply -auto-approve -var="environment=$ENV" aws s3 sync ../frontend/dist "s3://$(terraform output -raw site_bucket)" --delete aws cloudfront create-invalidation --distribution-id "$(terraform output -raw cdn_id)" --paths "/*" > /dev/null echo "site: $(terraform output -raw site_url)"

Step 2 · A destroy script that empties first第 2 步 · 先清空的销毁脚本

Learn先学

Terraform will not delete a bucket that still holds files, so destroy fails at the buckets. The destroy script empties them first, then lets Terraform remove the rest. (force_destroy = true on the bucket resource in dev and test lets Terraform do it itself.)

Terraform 不会删除还装着文件的存储桶，所以 destroy 会在存储桶那里失败。销毁脚本先把它们清空，再让 Terraform 移除其余部分。（在 dev 和 test 的存储桶资源上设 force_destroy = true，Terraform 就会自己清空。）

#!/usr/bin/env bash set -euo pipefail ENV="${1:?usage: ./destroy.sh dev|test|prod}" cd infra terraform workspace select "$ENV" echo "workspace: $(terraform workspace show)" for name in site_bucket memory_bucket; do aws s3 rm "s3://$(terraform output -raw "$name")" --recursive # a bucket with files will not delete done terraform destroy -auto-approve -var="environment=$ENV"

Step 3 · Prove the teardown第 3 步 · 证明拆除干净

Learn先学

"Destroy complete" is not proof. Check that Terraform's own list is empty, that the cloud's command line finds nothing with that environment's name, and that the console agrees. Because both directions are one command, delete test environments every time you stop work. The budget alarm is the last line of defence; your own habit is the first.

“Destroy complete”不算证据。检查 Terraform 自己的清单是空的，云的命令行找不到带那个环境名的东西，控制台也一致。因为两个方向都只要一条命令，每次收工就删掉测试环境。预算警报是最后一道防线；你自己的习惯才是第一道。

./destroy.sh test cd infra && terraform workspace select test terraform state list # should print nothing aws s3 ls | grep wharf-twin-test # should print nothing aws lambda list-functions \ --query "Functions[?starts_with(FunctionName, 'wharf-twin-test')].FunctionName" # should be []

Now make it yours现在把它变成你的

Common errors常见错误

• Permission denied Fix: Run chmod +x deploy.sh destroy.sh.
• usage: ./deploy.sh dev|test|prod You gave no environment. Fix: Run ./deploy.sh dev.
• BucketNotEmpty Fix: Keep the aws s3 rm --recursive step before terraform destroy.

• Permission denied 解决：运行 chmod +x deploy.sh destroy.sh。
• usage: ./deploy.sh dev|test|prod 没给环境名。 解决：运行 ./deploy.sh dev。
• BucketNotEmpty 解决：保留 terraform destroy 之前的 aws s3 rm --recursive 步骤。

Takeaways要点回顾

• One script deploys and one destroys, both taking the environment name.
• Print the current workspace before anything changes.
• Empty buckets first: a bucket with files will not delete.
• Prove a teardown with the state list, the command line and the console.
• Delete test environments between sessions; the budget alarm is the last line of defence.

• 一个脚本部署、一个脚本销毁，都接收环境名。
• 任何改动之前先打印当前工作区。
• 先清空存储桶：有文件的桶删不掉。
• 用状态清单、命令行和控制台证明拆除干净。
• 测试环境每次用完就删；预算警报是最后一道防线。
