The twin works on Mei Ling's laptop: it has a voice, facts and a memory folder. Now she wants it on the wharf's cloud account, with no laptop involved. She moves the code to a serverless function, and Auntie Siti chats with it twice. The second time, the twin has forgotten her. The handover book has vanished between shifts.

分身在 Mei Ling 的笔记本上运行得很好：有声音、有事实，还有一个记忆文件夹。现在她想把它放到码头的云账号上，不再依赖笔记本。她把代码搬到无服务器函数上，Siti 阿姨跟它聊了两次。第二次，分身把她忘了。交接簿在两个班次之间不见了。

Step 1 · The request path, piece by piece第 1 步 · 请求的路径，一块一块看

Learn先学

A bucket is a cloud folder for files (objects) with no server attached. A CDN (content delivery network) is a fast front door that caches your pages near the visitor and gives them HTTPS. An API gateway is the public door for your backend. Here is the whole path: the browser asks the CDN; the CDN fetches the front end from a bucket; the page calls the gateway; the gateway runs the function; the function calls the model service and reads or writes the memory bucket.

存储桶（bucket）是云上存放文件（对象）的文件夹，不挂任何服务器。CDN（内容分发网络）是一扇很快的前门，它把页面缓存在离访客近的地方，并提供 HTTPS。API 网关是后端对外的公开入口。整条路径是这样：浏览器问 CDN；CDN 从一个存储桶取前端页面；页面调用网关；网关运行函数；函数调用模型服务，并读写记忆存储桶。

browser → CDN → site bucket (the front end files) browser → API gateway → function → model service └→ memory bucket (one object per session)

Step 2 · Memory becomes objects in a bucket第 2 步 · 记忆变成存储桶里的对象

Learn先学

A serverless function has no durable disk. Anything it writes to a file can vanish between calls, and two copies of the function never share files. So the memory moves to a bucket, one object per session, named after the session id. The code below uses boto3, the Python library for the cloud (pip install boto3). The bucket name comes from an environment variable.

无服务器函数没有持久的磁盘。它写进文件的任何东西，都可能在两次调用之间消失，而且函数的两个副本之间不共享文件。所以记忆搬到存储桶里，每个会话一个对象，名字用会话 id。下面的代码用 boto3，也就是操作云的 Python 库（pip install boto3）。存储桶的名字来自环境变量。

import json import os import boto3 from botocore.exceptions import ClientError s3 = boto3.client("s3") BUCKET = os.environ["MEMORY_BUCKET"] def load_from_bucket(session_id: str) -> list: try: obj = s3.get_object(Bucket=BUCKET, Key=f"{session_id}.json") return json.loads(obj["Body"].read()) except ClientError as err: if err.response["Error"]["Code"] == "NoSuchKey": return [] # a new visitor raise # anything else is a real problem def save_to_bucket(session_id: str, history: list) -> None: s3.put_object(Bucket=BUCKET, Key=f"{session_id}.json", Body=json.dumps(history).encode("utf-8"), ContentType="application/json")

Step 3 · One codebase, local or cloud第 3 步 · 一份代码，本地或云上都能跑

Learn先学

You still want to run everything on your laptop while building. So let one environment variable choose where memory goes: local files or the bucket. The rest of the server calls the same two function names either way. Keep the session id check from the first lesson of this topic: only safe characters, so nobody can aim at other files or objects. (The boto3 functions from step 2 are renamed load_from_bucket and save_to_bucket here.)

开发时你仍然想在笔记本上运行所有东西。所以让一个环境变量来选记忆放哪里：本地文件还是存储桶。服务器的其余部分无论哪种都调用同样的两个函数名。别忘了本主题第一课里的会话 id 检查：只允许安全字符，这样没人能指向别的文件或对象。（第 2 步里的 boto3 函数在这里改名叫 load_from_bucket 和 save_to_bucket。）

import json import os import re from pathlib import Path USE_BUCKET = os.environ.get("USE_BUCKET", "false") == "true" def check_id(session_id: str) -> str: if not re.fullmatch(r"[A-Za-z0-9-]{1,64}", session_id): raise ValueError("bad session id") return session_id def load_history(session_id: str) -> list: sid = check_id(session_id) if USE_BUCKET: return load_from_bucket(sid) # the boto3 version from step 2 path = Path("memory") / f"{sid}.json" return json.loads(path.read_text(encoding="utf-8")) if path.exists() else [] def save_history(session_id: str, history: list) -> None: sid = check_id(session_id) if USE_BUCKET: return save_to_bucket(sid, history) Path("memory").mkdir(exist_ok=True) (Path("memory") / f"{sid}.json").write_text(json.dumps(history), encoding="utf-8")

Step 4 · Package the function and give it permission第 4 步 · 打包函数，并给它权限

Learn先学

For a zip-based function, install the libraries into a folder, add your code and zip it. Install for the chip type the cloud uses, not your laptop's. A small adapter library (mangum) lets the FastAPI app answer function calls. Then set the environment variables and give the function a role that allows only what it needs: read and write objects in the memory bucket, plus list it (without the list permission, a missing object is answered "access denied" instead of "not found", and a new visitor would crash the code in step 2). Nothing else. This is least privilege.

对基于 zip 的函数，要把库安装到一个文件夹里，加上你的代码再打成 zip。安装时要按云使用的芯片类型，而不是你笔记本的。一个小的适配库（mangum）让 FastAPI 应用能回应函数调用。然后设置环境变量，再给函数一个只允许它需要的事的角色：只能读写记忆存储桶里的对象，外加能列出它的内容（没有列出权限的话，对象不存在时返回的是“拒绝访问”而不是“找不到”，新访客会让第 2 步的代码崩溃）。别的都不行。这就是最小权限。

# in server.py, after app = FastAPI() and your routes: from mangum import Mangum handler = Mangum(app) # the function's entry point: server.handler
# build the zip pip install --platform manylinux2014_x86_64 --target package --only-binary=:all: -r requirements.txt cp *.py package/ && cp -r data package/ cd package && zip -r ../twin.zip . && cd ..
# the function's role: this and nothing more {"Version": "2012-10-17", "Statement": [{"Effect": "Allow", "Action": ["s3:GetObject", "s3:PutObject"], "Resource": "arn:aws:s3:::wharf-twin-memory/*"}, {"Effect": "Allow", "Action": "s3:ListBucket", "Resource": "arn:aws:s3:::wharf-twin-memory"}]}

Step 5 · The static front end, the CDN and CORS第 5 步 · 静态前端、CDN 和 CORS

Learn先学

The static front end goes into its own bucket, and the CDN sits in front of it. But now the page comes from one address and the API from another. The browser blocks that unless the gateway answers with CORS headers naming the page's address as allowed. Set that on the gateway, or you will see the calls fail in the browser console while the function itself is fine.

静态前端放进它自己的存储桶，CDN 放在它前面。但现在页面来自一个地址，API 来自另一个地址。除非网关用 CORS 头回应、并把页面的地址列为允许，否则浏览器会拦下。要在网关上设置，不然你会看到调用在浏览器控制台里失败，而函数本身其实没事。

API gateway → CORS Allowed origins: https://twin.example.com (the CDN address of the page) Allowed methods: POST, OPTIONS Allowed headers: content-type

Step 6 · The cost levers第 6 步 · 控制成本的杠杆

Learn先学

A small twin costs very little, but each piece has a lever. Give the function only the memory it needs. Keep logs short, with a retention period. Delete what you no longer use: test buckets, old versions, forgotten functions. The budget alarm from the safe-account lesson tells you if you got it wrong.

一个小分身花不了多少钱，但每一块都有一个杠杆。给函数它需要的内存就够。日志保持精简，并设置保留期。把不再用的东西删掉：测试存储桶、旧版本、被遗忘的函数。账号安全那课设的预算警报，会告诉你有没有弄错。

What I got wrong我犯过的错Three slips. A serverless function has no durable disk, so my file memory silently vanished between calls. The gateway had no CORS settings, so the browser blocked my calls. And at first I gave the function far too many permissions.三个失误。无服务器函数没有持久磁盘，所以我的文件记忆在两次调用之间悄悄消失了。网关没有 CORS 设置，浏览器拦了我的调用。而且一开始我给了函数多得多的权限。

Common errors常见错误

• botocore.exceptions.ClientError: AccessDenied The function role may not read or write the memory bucket. Fix: Check the role policy lists the bucket name exactly, with /* for objects.
• KeyError: 'MEMORY_BUCKET' The function has no such environment variable. Fix: Add MEMORY_BUCKET and USE_BUCKET=true in the function settings.
• Runtime.ImportModuleError: Unable to import module 'server' The zip holds the wrong files or libraries built for another system. Fix: Rebuild with the --platform manylinux2014_x86_64 line and zip from inside package/.
• CORS error in the browser console The gateway does not allow the page address. Fix: Add the CDN address under allowed origins, with POST, OPTIONS.

• botocore.exceptions.ClientError: AccessDenied 函数的角色没有读写记忆桶的权限。 解决：检查角色策略里的桶名是否完全一致，对象部分要带 /*。
• KeyError: 'MEMORY_BUCKET' 函数里没有这个环境变量。 解决：在函数设置里添加 MEMORY_BUCKET 和 USE_BUCKET=true。
• Runtime.ImportModuleError: Unable to import module 'server' 压缩包里的文件不对，或库是为别的系统构建的。 解决：用带 --platform manylinux2014_x86_64 的命令重新构建，并在 package/ 里面打包。
• CORS error in the browser console 网关没有允许页面所在的地址。 解决：在允许的来源里加入 CDN 地址，方法包括 POST, OPTIONS。

Takeaways要点回顾

• The path: browser, CDN, site bucket, API gateway, function, model service and memory bucket.
• A serverless function has no durable disk, so storage is a service.
• Memory becomes one object per session in a bucket.
• An environment variable can switch the same code between local files and the bucket.
• Package the function for the cloud's chip type, and give it only the permissions it needs.
• The gateway needs CORS, or the browser blocks the calls.
• Know the cost levers: small memory, short logs, delete what is unused.

• 路径：浏览器、CDN、网站存储桶、API 网关、函数、模型服务和记忆存储桶。
• 无服务器函数没有持久磁盘，所以存储就是一项服务。
• 记忆变成存储桶里每个会话一个对象。
• 用一个环境变量，就能让同一份代码在本地文件和存储桶之间切换。
• 按云的芯片类型打包函数，只给它需要的权限。
• 网关需要 CORS，否则浏览器会拦下调用。
• 了解成本杠杆：小内存、短日志、删掉不用的东西。
