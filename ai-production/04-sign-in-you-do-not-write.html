Ready-made sign-in现成登录

Let only signed-in people use your product, without writing a login system · ~30 min · hands-on让只有登录的人才能使用你的产品，而且不用自己写登录系统 · 约 30 分钟 · 动手实践

Step 1 · Let a service do sign-in第 1 步 · 让服务来做登录

Learn先学
  • A hosted sign-in service (Clerk here) stores passwords, sends reset emails and shows the sign-in screens. Your product only asks: who is this request from?
  • It gives you two keys. The public key identifies your app and may go to the browser. The secret key acts as your server and stays there, out of git (add .env.local to .gitignore first).
  • In Next.js only names starting NEXT_PUBLIC_ reach the browser.
  • 托管登录服务（这里用 Clerk）保存密码、发重置邮件、展示登录界面。你的产品只问一件事：这个请求是谁发的？
  • 它给你两把密钥。公开密钥标识你的应用，可以给浏览器；秘密密钥代表你的服务器，只留在服务器上，也不进 git（先把 .env.local 加进 .gitignore）。
  • 在 Next.js 里，只有以 NEXT_PUBLIC_ 开头的名字才会到浏览器。
# .env.local (listed in .gitignore) NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_... CLERK_SECRET_KEY=sk_test_... CLERK_JWKS_URL=https://... # shown in the dashboard

Step 2 · Show the right thing, send the token第 2 步 · 显示对的内容，并送出令牌

Learn先学
  • Wrap the app in the service's provider so every page knows who is signed in. Signed-out visitors get a sign-in button; signed-in ones get the product.
  • Signed in, the browser holds a session token (a signed text called a JWT). Send it in an Authorization header on every API call.
  • Tokens live about a minute, so ask for a fresh one right before each request.
  • 用服务的提供者（provider）包住整个应用，每个页面就知道谁已登录。没登录的访客看到登录按钮，已登录的看到产品。
  • 登录后，浏览器持有一个会话令牌（带签名的文本，叫 JWT）。每次调用 API 都用 Authorization 头带上它。
  • 令牌大约一分钟就过期，所以每次请求前都取一个新的。
// pages/_app.tsx (npm install @clerk/nextjs) import type { AppProps } from "next/app"; import { ClerkProvider } from "@clerk/nextjs"; export default function App({ Component, pageProps }: AppProps) { return ( <ClerkProvider {...pageProps}> <Component {...pageProps} /> </ClerkProvider> ); }
// pages/index.tsx import { useAuth, SignedIn, SignedOut, SignInButton, UserButton } from "@clerk/nextjs"; // inside the page: what each visitor sees <SignedOut><SignInButton mode="modal" /></SignedOut> <SignedIn><UserButton /> ...the product...</SignedIn> // inside the page component const { getToken } = useAuth(); async function ask() { const token = await getToken(); // fresh, every time const res = await fetch("/api", { headers: { Authorization: "Bearer " + token }, }); return res.json(); }

Step 3 · Check the token on the server第 3 步 · 在服务器上验令牌

Learn先学
  • Anyone can send an Authorization header, so the API must verify it. Checks in the browser are only for looks.
  • The token carries a signature only the service can make. Its public keys (at a web address called JWKS) let your server verify it without phoning the service.
  • If valid, the user id is in sub. A bad token gets 401 ("unauthorized"). Depends(guard) runs the check before your function.
  • For the live site, add the same variables with vercel env add and redeploy.
  • 谁都能发 Authorization 头，所以 API 必须验证。浏览器里的检查只是为了好看。
  • 令牌带着只有服务才能做出的签名。它的公钥（放在叫 JWKS 的网址）让你的服务器不用打电话问服务就能验证。
  • 验过了，用户 id 就在 sub 里。令牌不合格得到 401（“未授权”）。Depends(guard) 在你的函数之前运行检查。
  • 线上要用 vercel env add 加上同样的变量，再重新部署。
import os from fastapi import Depends, FastAPI from fastapi_clerk_auth import ClerkConfig, ClerkHTTPBearer, HTTPAuthorizationCredentials app = FastAPI() guard = ClerkHTTPBearer(ClerkConfig(jwks_url=os.environ["CLERK_JWKS_URL"])) @app.get("/api") def hello(creds: HTTPAuthorizationCredentials = Depends(guard)): user_id = creds.decoded["sub"] return {"message": "Welcome aboard, " + user_id} # add fastapi-clerk-auth to api/requirements.txt

Common errors常见错误

• Missing publishable key: the variable is missing locally or on the host. Fix: add it in both places and redeploy.
• 403 Forbidden: the token is missing or expired. Fix: call getToken() right before each request.
• KeyError: 'CLERK_JWKS_URL': not set on the host. Fix: vercel env add CLERK_JWKS_URL, then vercel --prod.

• Missing publishable key：本地或平台上缺少该变量。 解决：两处都加上并重新部署。
• 403 Forbidden：令牌缺失或已过期。 解决：每次请求前调用 getToken()。
• KeyError: 'CLERK_JWKS_URL'：平台上没设置。 解决：vercel env add CLERK_JWKS_URL，再 vercel --prod。

Takeaways要点回顾

• Do not write password handling; use a hosted sign-in service.
• Public key to the browser; secret key stays on the server and out of git.
• The browser sends a short-lived signed token (JWT) with each request.
• The server verifies it with the service's public keys. Browser checks are only for looks.
• The host needs the same environment variables, then a redeploy.

• 不要自己处理密码，用托管登录服务。
• 公开密钥给浏览器；秘密密钥留在服务器，也不进 git。
• 浏览器每次请求都带上短寿命的签名令牌（JWT）。
• 服务器用服务的公钥验证它。浏览器里的检查只是为了好看。
• 平台需要同样的环境变量，然后重新部署。
