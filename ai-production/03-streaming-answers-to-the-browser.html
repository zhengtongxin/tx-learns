Step 1 · Waiting versus seeing第 1 步 · 干等与看着它写

Learn先学

A model writes an answer a few words at a time. Normally the server waits for all of it, then sends one big reply. With streaming, the server forwards each small piece the moment it exists. Same answer, same total time. But the first word shows up almost at once, and a screen that is changing feels alive.

模型是一次写几个词来生成答案的。通常服务器会等它全部写完，再一次性发出一大段回复。用流式输出（streaming）时，每一小段一生成，服务器就立刻转发。答案相同，总时间也相同，但第一个词几乎马上出现，而不断变化的屏幕让人觉得它活着。

no streaming: [ blank ............................ ][ whole answer ] streaming: [ blank ][ Th ][ e can ][ teen is ][ open ] ...

Step 2 · Ask the model for a stream第 2 步 · 向模型要一个流

Learn先学

Add stream=True to the model call. Instead of one finished reply, you get something you can loop over, and each loop gives you a small chunk. The text is inside the chunk. Some chunks carry no text at all (the last one is often empty), so check before you use it.

在模型调用里加上 stream=True。你拿到的不再是一份写完的回复，而是一个可以循环的东西，每次循环给你一小块数据块（chunk）。文字就在块里。有些块里没有文字（最后一块常常是空的），所以用之前要先检查。

from openai import OpenAI client = OpenAI() stream = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": "Describe today's canteen menu in three lines."}], stream=True, ) for chunk in stream: piece = chunk.choices[0].delta.content if piece: print(piece, end="", flush=True)

Step 3 · Send it on: server-sent events第 3 步 · 转发出去：服务器推送事件

Learn先学

Now pass each piece on to the browser. The simplest format is server-sent events: plain text lines. Each line starts with data: and a blank line ends one message. In FastAPI, write a generator (a function that yields pieces one at a time) and wrap it in a streaming response marked text/event-stream. One catch: if a piece holds a newline, every line inside it needs its own data: prefix.

现在把每一块转发给浏览器。最简单的格式是服务器推送事件（server-sent events）：纯文本行。每行以 data: 开头，空行表示一条消息结束。在 FastAPI 里，写一个生成器（用 yield 一块一块吐出内容的函数），再包进一个标记为 text/event-stream 的流式响应。有个陷阱：如果某一块里含换行，里面每一行都要有自己的 data: 前缀。

from fastapi import FastAPI from fastapi.responses import StreamingResponse from openai import OpenAI app = FastAPI() client = OpenAI() def as_event(text): lines = text.split("\n") return "".join(f"data: {line}\n" for line in lines) + "\n" def generate(): stream = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": "Describe today's canteen menu in three lines."}], stream=True, ) for chunk in stream: piece = chunk.choices[0].delta.content if piece: yield as_event(piece) yield "data: [DONE]\n\n" # our own "finished" signal @app.get("/api") def stream_answer(): return StreamingResponse(generate(), media_type="text/event-stream")

Step 4 · Listen in the browser, and know when to stop第 4 步 · 在浏览器里接收，并知道何时停

Learn先学

The browser has a built-in listener called EventSource. Give it the address and it calls your function for every message. Append each piece to the screen. Then the important part: close it when the stream ends. If the connection drops, EventSource quietly reconnects and asks again, so without a close the page can spin forever. (EventSource can only make simple GET requests. A later project reads the stream another way.) In the page, keep the text in state (const [answer, setAnswer] = useState(""), as in lesson 2), and call ask(setAnswer) when the button is pressed.

浏览器内置了一个接收器，叫 EventSource。给它一个地址，每来一条消息它就调用你的函数。把每一块追加到屏幕上。然后是关键：流结束时要关掉它。连接一断，EventSource 会悄悄重连、再问一遍，所以不关的话页面可能一直转圈。（EventSource 只能发简单的 GET 请求，之后的项目会换一种方式读这个流。）在页面里用状态保存文字（const [answer, setAnswer] = useState("")，和第 2 课一样），并在按下按钮时调用 ask(setAnswer)。

function ask(setAnswer) { const source = new EventSource("/api"); let text = ""; source.onmessage = (event) => { if (event.data === "[DONE]") { source.close(); return; } text += event.data; setAnswer(text); }; source.onerror = () => source.close(); }

Step 5 · Make it pretty, and let it through第 5 步 · 让它好看，并让它畅通无阻

Learn先学

Models write markdown: **bold**, lists, headings. Show it raw and it looks messy. A small library (react-markdown) turns it into real headings and lists, and Tailwind's prose class (from the typography plugin) spaces them nicely. Open package.json first: a tailwindcss version starting with 3 means follow the first comment below, 4 means the second. One last trap: streaming can work locally, then arrive in one lump once live. That means something in the middle is buffering: holding the pieces until the end. The host and any proxy must pass them straight through. The two headers in the code ask for exactly that: no-cache asks for no stored copies, and X-Accel-Buffering: no asks some proxy servers not to hold the pieces back.

模型写出来的是 markdown：**粗体**、列表、标题。原样显示会很乱。一个小库（react-markdown）能把它变成真正的标题和列表，Tailwind 的 prose 类（来自排版插件）让间距好看。先打开 package.json：tailwindcss 版本以 3 开头就按下面第一条注释做，以 4 开头就按第二条。最后一个陷阱：流式输出在本地正常，上线后却一下子全到了。这说明中间有东西在缓冲（buffering）：把块攒到最后才放出来。托管平台和中间的任何代理都必须让它们直接通过。代码里的两个 headers 就是为此而设：no-cache 要求不保存副本，X-Accel-Buffering: no 要求一些代理服务器不要扣住这些块。

# terminal npm install react-markdown @tailwindcss/typography // Tailwind 3: in tailwind.config.js add plugins: [require("@tailwindcss/typography")] // Tailwind 4 (newer projects): in styles/globals.css add @plugin "@tailwindcss/typography"; // in the page import ReactMarkdown from "react-markdown"; <div className="prose"> <ReactMarkdown>{answer}</ReactMarkdown> </div> # api: ask the layers in between not to hold the pieces return StreamingResponse(generate(), media_type="text/event-stream", headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"})
What I got wrong我犯过的错Three mistakes. A newline inside a chunk broke the format, because every line needs its own data: prefix. I only tested streaming locally, but the host and any proxy in between must not buffer the response. And I never closed the stream on errors, so the page spun forever.三个错误。块里的换行把格式弄坏了，因为每一行都要有自己的 data: 前缀。我只在本地测了流式输出，但托管平台和中间的代理都不能缓冲响应。我还没在出错时关掉流，结果页面一直转圈。

Takeaways要点回顾

• Streaming does not make the model faster. It makes waiting feel shorter.
• stream=True gives you chunks to loop over. Some chunks have no text.
• Server-sent events are plain text: each line starts with data: , and a blank line ends a message.
• A newline inside a piece needs its own data: prefix on every line.
• Close the EventSource when the stream ends or fails, or it reconnects forever.
• Every layer between the API and the browser must pass pieces straight through. Test it live.

• 流式输出不会让模型变快，只是让等待显得更短。
• stream=True 给你可循环的数据块，有些块没有文字。
• 服务器推送事件是纯文本：每行以 data: 开头，空行结束一条消息。
• 块里的换行，每一行都要有自己的 data: 前缀。
• 流结束或出错时要关掉 EventSource，否则它会一直重连。
• API 到浏览器之间的每一层都必须让块直接通过，要在线上测试。
