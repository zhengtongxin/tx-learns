Streaming to the browser流式输出到浏览器

Show the model's answer word by word, so waiting feels short · ~25 min · hands-on把模型的回答一个词一个词地显示出来，让等待变短 · 约 25 分钟 · 动手实践

Step 1 · Stream from the server第 1 步 · 服务器端流式输出

Learn先学
  • A model writes a few words at a time. Streaming forwards each piece the moment it exists, instead of waiting for the whole answer.
  • Total time is the same, but the first word shows up almost at once.
  • Add stream=True and loop over the chunks. Some have no text, so check first.
  • Send each piece as server-sent events: lines starting data: , a blank line ends a message. A newline inside a piece needs its own data: on every line.
  • 模型一次写几个词。流式输出是每一段一生成就转发，而不是等整段答案写完。
  • 总时间不变，但第一个词几乎马上出现。
  • 加上 stream=True，循环处理数据块。有些块没有文字，要先检查。
  • 用服务器推送事件发送：每行以 data: 开头，空行结束一条消息。块里的换行，每一行都要有自己的 data: 。
from fastapi import FastAPI from fastapi.responses import StreamingResponse from openai import OpenAI app = FastAPI() client = OpenAI() def as_event(text): lines = text.split("\n") return "".join(f"data: {line}\n" for line in lines) + "\n" def generate(): stream = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": "Describe today's hawker menu in three lines."}], stream=True, ) for chunk in stream: piece = chunk.choices[0].delta.content if piece: yield as_event(piece) yield "data: [DONE]\n\n" # our own "finished" signal @app.get("/api") def stream_answer(): return StreamingResponse(generate(), media_type="text/event-stream")

Step 2 · Listen in the browser, and stop第 2 步 · 在浏览器里接收，并停下

Learn先学

The built-in EventSource calls your function for every message. Append each piece to the screen, and close it when the stream ends. If the connection drops, EventSource quietly reconnects and asks again, so without a close the page can spin forever.

浏览器内置的 EventSource 每来一条消息就调用你的函数。把每一段追加到屏幕上，并在流结束时关掉它。连接一断，EventSource 会悄悄重连、再问一遍，所以不关的话页面可能一直转圈。

function ask(setAnswer) { const source = new EventSource("/api"); let text = ""; source.onmessage = (event) => { if (event.data === "[DONE]") { source.close(); return; } text += event.data; setAnswer(text); }; source.onerror = () => source.close(); }

Step 3 · Let it through live第 3 步 · 上线后让它畅通

Learn先学

Streaming can work locally, then arrive in one lump once live. Something in the middle is buffering: holding pieces until the end. These two headers ask the layers in between not to. Always test streaming on the live address.

流式输出可能在本地正常，上线后却一下子全到了。中间有东西在缓冲：把块攒到最后才放出来。这两个响应头要求中间各层不要这样做。流式输出一定要在线上地址测试。

# ask the layers in between not to hold the pieces return StreamingResponse(generate(), media_type="text/event-stream", headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"})

Common errors常见错误

• IndexError: list index out of range: a chunk had an empty choices. Fix: check if chunk.choices: first.
• The answer arrives all at once: something is buffering. Fix: add the two headers and test live.

• IndexError: list index out of range：某个块的 choices 是空的。 解决：先检查 if chunk.choices:。
• 答案一下子全到：有东西在缓冲。 解决：加上那两个响应头，并在线上测试。

Takeaways要点回顾

• Streaming does not speed up the model; it makes waiting feel shorter.
• stream=True gives chunks; some have no text.
• Server-sent events: each line starts data: , a blank line ends a message.
• Close the EventSource on finish or error.
• Every layer in between must pass pieces straight through. Test live.

• 流式输出不会加快模型，只是让等待显得更短。
• stream=True 给出数据块，有些块没有文字。
• 服务器推送事件：每行以 data: 开头，空行结束一条消息。
• 结束或出错时要关掉 EventSource。
• 中间每一层都必须让块直接通过，要在线上测试。
