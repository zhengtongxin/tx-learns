Front end and API前端与 API

See how a page and a Python API deploy together under one web address · ~25 min · hands-on看懂一个页面和一个 Python API 如何在同一个网址下一起上线 · 约 25 分钟 · 动手实践

Step 1 · Two halves, one address第 1 步 · 两半，一个地址

Learn先学
  • The front end is files the browser downloads, so it can never keep a secret.
  • The API runs on the host, the company whose servers run your site (Vercel in this lesson). It holds the model key and does the real work.
  • Put both behind one address, like a shop front and its kitchen.
  • 前端是浏览器下载的文件，永远保不住秘密。
  • API 运行在托管平台（用自己的服务器替你运行网站的公司，本课用 Vercel）上，持有模型密钥，做真正的工作。
  • 两者放在同一个地址后面，就像店面和后厨。

Step 2 · Build both halves and join them第 2 步 · 搭好两半并连起来

Learn先学
  • Make the page with one command: create-next-app (Next.js is a toolkit for React pages).
  • Put the Python route in an api/ folder, with its own api/requirements.txt. Skip it and the page looks fine while the API fails.
  • A rewrites rule in vercel.json sends /api/... to Python and the rest to Next.js. If the folder already has a vercel.json or a root requirements.txt from an earlier Python-only deploy, this file replaces the first and api/requirements.txt replaces the second. One site also means no CORS trouble: browsers block a page from calling an API on a different address unless that API allows it, and here both share one address.
  • The page calls the relative path /api, so it works on your laptop (vercel dev) and live.
  • 用一条命令建页面：create-next-app（Next.js 是做 React 页面的工具包）。
  • 把 Python 路由放进 api/ 文件夹，并配自己的 api/requirements.txt。漏了它，页面看着正常，API 却会失败。
  • vercel.json 里的 rewrites 规则把 /api/... 交给 Python，其余交给 Next.js，如果文件夹里已经有以前只部署 Python 时留下的 vercel.json 或根目录的 requirements.txt，这个文件取代前者，api/requirements.txt 取代后者。同一个网站也就没有 CORS 麻烦：浏览器会拦住页面去调用另一个地址上的 API，除非那个 API 明确允许；这里两者共用一个地址。
  • 页面调用相对路径 /api，所以在笔记本（vercel dev）和线上都能用。
npx create-next-app@latest helper --typescript --tailwind --no-app
# api/index.py from fastapi import FastAPI from openai import OpenAI app = FastAPI() client = OpenAI() # reads the key from the OPENAI_API_KEY environment variable @app.get("/api") def hello(): reply = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": "Write a one-line welcome for a hawker centre."}], ) return {"message": reply.choices[0].message.content}
# api/requirements.txt fastapi uvicorn openai
// vercel.json { "rewrites": [{ "source": "/api/:path*", "destination": "/api/index.py" }] }
// pages/index.tsx import { useEffect, useState } from "react"; export default function Home() { const [message, setMessage] = useState("Loading..."); useEffect(() => { fetch("/api") .then((r) => r.json()) .then((data) => setMessage(data.message)); }, []); return <main className="p-8 text-xl">{message}</main>; }

useState holds a value the page shows; changing it redraws the page. useEffect runs in the browser after the page appears, which is where the API call belongs; the [] at its end means “run once, not on every redraw”. fetch is the browser's built-in way to call an address, and .then says what to do when the answer arrives. The HTML-like tags inside the function are JSX: React turns them into the page.

useState 保存页面显示的值，改了它页面就重画。useEffect 在页面出现之后、在浏览器里运行，调用 API 就该放这里；末尾的 [] 表示“只运行一次，不是每次重画都运行”。fetch 是浏览器自带的访问某个地址的方法，.then 说明答案回来后做什么。函数里那些像 HTML 的标签是 JSX：React 会把它们变成页面。

Step 3 · Deploy: preview, then production第 3 步 · 部署：先预览，再上线

Learn先学

Link the folder to a host project once, set the key as an environment variable, and deploy. A plain deploy is a preview; --prod is production. They are separate deployments with separate addresses: test the first, then go live.

先把文件夹关联到平台上的一个项目，把密钥设为环境变量，再部署。普通部署是预览，--prod 才是生产。它们是两个独立的部署、两个地址：先测前者，再上线。

vercel link vercel env add OPENAI_API_KEY vercel # preview: open the address and test vercel --prod # production

Now make it yours现在把它变成你的

Common errors常见错误

• Failed to fetch: the rewrite is missing or the API did not deploy. Fix: check vercel.json is at the root and open /api directly.
• Command "npm run build" exited with 1: an error in pages/index.tsx. Fix: run npm run build locally and fix the first error.

• Failed to fetch：重写规则缺失，或 API 没部署成功。 解决：确认 vercel.json 在根目录，并直接打开 /api。
• Command "npm run build" exited with 1：pages/index.tsx 里有错误。 解决：在本地运行 npm run build，修好第一个错误。

Takeaways要点回顾

• Two halves: a front end in the browser, an API on the host.
• The front end cannot keep secrets; the API holds them.
• One rewrite rule gives one address and no CORS trouble.
• Call /api, not a full address.
• Preview and production are two deployments: test, then promote.

• 两半：浏览器里的前端，托管平台上的 API。
• 前端保不住秘密，API 保管秘密。
• 一条重写规则就是一个地址，没有 CORS 麻烦。
• 调用 /api，不要用完整地址。
• 预览和生产是两个部署：先测，再升级。
