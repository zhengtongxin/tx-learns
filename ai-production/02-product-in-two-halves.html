A product in two halves: front end and API产品的两半：前端和 API

上回产品已经能对 /api 的访问回一小段 JSON。今天它让 Siti 阿姨失望了：她想要一个印着食堂名字的真正页面。我们的办法是加一个 React 页面，并让它和 Python 接口共用一个地址。

The story故事

Last time Mei Ling shipped a service that answers with JSON. Nobody wants to read raw JSON. Auntie Siti wants a real page with her canteen's name on it. So Mei Ling adds a face: a React page in the browser, backed by the same Python API. Two halves, one address.

上次 Mei Ling 上线了一个返回 JSON 的服务。没人想看原始 JSON。Siti 阿姨想要一个写着食堂名字的真正页面。于是 Mei Ling 给它加了一张“脸”：浏览器里的 React 页面，背后还是那个 Python API。两半，一个地址。

Step 1 · Two halves, one address第 1 步 · 两半，一个地址

Learn先学

The front end is the part people see. It is just files that your browser downloads and runs, so it can never keep a secret. The API is the part that runs on the host. It holds the model key and does the real work. Picture a restaurant: the dining room is the front end, the kitchen is the API, and the doorway between them is one address.

前端是人们看到的部分。它只是浏览器下载并运行的文件，所以永远保不住秘密。API 则运行在托管平台上，持有模型密钥，做真正的工作。想象一家餐厅：餐厅大堂是前端，厨房是 API，两者之间的传菜口就是同一个地址。

browser ──► yourproduct.app/ ──► Next.js page (front end) browser ──► yourproduct.app/api ──► Python API (holds the key) │ ▼ the model

Step 2 · Start the front end第 2 步 · 搭起前端

Learn先学

React is a way to write a page as small reusable pieces. Next.js is a toolkit for React pages. One command (npx runs a tool without installing it first) makes a project. Its flags answer the setup questions for you: TypeScript, Tailwind, and the older "pages" layout (--no-app). Then empty the sample page. Tailwind is just short class names for styling: p-8 means "padding", text-xl means "big text". Its typography plugin later makes rendered markdown look decent.

React 是把页面写成一块块可以反复使用的小部件的方式。Next.js 是做 React 页面的工具包。一条命令（npx 不用先安装就能直接运行一个工具）就能建好项目。参数替你回答了设置问题：TypeScript、Tailwind，以及较旧的 “pages” 目录结构（--no-app）。然后清空示例页面。Tailwind 就是一堆简短的样式类名：p-8 表示“内边距”，text-xl 表示“大字”。它的排版插件（typography plugin）之后能让渲染出的 markdown 好看一些。

npx create-next-app@latest wharf-helper --typescript --tailwind --no-app cd wharf-helper # delete the sample content in pages/index.tsx
✔ Creating a new Next.js app in ./wharf-helper Success! Created wharf-helper

Step 3 · Add the Python half第 3 步 · 加上 Python 那一半

Learn先学

Put a Python file in a folder named api, next to your Next.js files. It is the same FastAPI route as before. It needs its own requirements file, placed beside it in the api folder as the code below shows, because the Python half installs its own packages. Skip it and the page will look fine while the API quietly fails.

在 Next.js 文件旁边建一个叫 api 的文件夹，里面放一个 Python 文件，和之前一样是 FastAPI 路由。它需要自己的 requirements 文件，和它一起放在 api 文件夹里（如下面的代码所示），因为 Python 这一半要安装自己的包。漏了它，页面看起来一切正常，API 却悄悄失败。

# api/index.py from fastapi import FastAPI from openai import OpenAI app = FastAPI() client = OpenAI() @app.get("/api") def hello(): reply = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": "Write a one-line welcome for the wharf canteen."}], ) return {"message": reply.choices[0].message.content}
# api/requirements.txt (beside index.py) fastapi uvicorn openai

Step 4 · Join them with one address第 4 步 · 用同一个地址把它们连起来

Learn先学

Two things connect the halves. First, a host config that sends /api/... to Python and everything else to Next.js. Its rewrites rule means "send this address to that file", and this file replaces the builds and routes config from lesson 1 (the api folder is still built automatically, and destination is the path of a file in it). The root requirements.txt from lesson 1 is no longer used: the one in api/ replaces it. The browser sees one site, so the browser's cross-site safety rules (CORS) never get in the way. Second, the page calls a relative path, /api, not a full address. A relative path means "same site as this page", so it works on your laptop (run it with vercel dev, which runs both halves locally) and in production.

有两样东西把两半连起来。第一，一个托管平台配置：把 /api/... 交给 Python，其余交给 Next.js。它的 rewrites 规则意思是“把这个地址交给那个文件”，这个文件取代第 1 课里的 builds 和 routes 配置（api 文件夹仍会自动构建，destination 是其中一个文件的路径）。第 1 课根目录的 requirements.txt 不再使用，由 api/ 里的取代。浏览器看到的是同一个网站，所以浏览器的跨站安全规则（CORS）不会来捣乱。第二，页面调用的是相对路径 /api，而不是完整地址。相对路径的意思是“和当前页面同一个网站”，所以在你的笔记本（用 vercel dev 运行，它会在本地同时跑两半）和线上都能用。

// vercel.json { "rewrites": [{ "source": "/api/:path*", "destination": "/api/index.py" }] }
// pages/index.tsx import { useEffect, useState } from "react"; export default function Home() { const [message, setMessage] = useState("Loading..."); useEffect(() => { fetch("/api") .then((r) => r.json()) .then((data) => setMessage(data.message)); }, []); return <main className="p-8 text-xl">{message}</main>; }

useState keeps a value the page shows: message is the value and setMessage changes it, which redraws the page. useEffect runs only in the browser, after the page appears. That is where a call to the API belongs.

useState 保存页面要显示的一个值：message 是这个值，setMessage 用来改它，改了页面就会重画。useEffect 只在浏览器里、页面出现之后运行，调用 API 就该放在这里。

Step 5 · Deploy: preview, then production第 5 步 · 部署：先预览，再上线

Learn先学

Link the folder to a host project once (vercel link asks which project to attach this folder to), then set the model key as an environment variable, exactly as before. A plain deploy makes a preview. --prod promotes it to production. These are two separate deployments with two addresses, so check the preview first and only then go live.

先把文件夹关联到托管平台的一个项目（vercel link 会问你把这个文件夹接到哪个项目），再像之前一样把模型密钥设为环境变量。普通的部署会得到一个预览版；加上 --prod 才升级为生产版。它们是两个独立的部署、两个地址，所以先在预览里检查，再正式上线。

vercel link vercel env add OPENAI_API_KEY vercel # preview: open the printed address and test vercel --prod # production
? Set up and deploy? yes Linked to wharf-helper (created .vercel) Added Environment Variable OPENAI_API_KEY to Project wharf-helper Production: https://wharf-helper.vercel.app [38s]
What I got wrong我犯过的错I called the API with a full address locally, and it broke in production. A relative /api path works in both places. I also forgot the Python requirements file, so the API half failed while the page looked perfectly fine. The page is only the shell: when something is missing, look at the API's build log.我在本地用完整地址调用 API，上线后就坏了。相对路径 /api 在两个地方都能用。我还忘了 Python 的 requirements 文件，结果页面看起来完全正常，API 那一半却失败了。页面只是外壳：缺了什么，就去看 API 的构建日志。

Now make it yours现在把它变成你的

What changed这一课之后Now the product shows Auntie Siti a real page at one address, with the Python half tucked behind it like the back office behind the public gate. The next problem is that a model answer takes eight seconds, and she sees a blank screen the whole time.现在产品在同一个地址上给 Siti 阿姨展示一个真正的页面，Python 那半藏在后面，就像公开闸口后面的办公室。下一个问题是模型要花八秒才答完，这段时间她看到的是一片空白。

Common errors常见错误

• Failed to fetch The page called /api but the rewrite is missing or the API did not deploy. Fix: Check vercel.json is at the project root and that api/index.py exists; open /api in the browser.
• Error: Command "npm run build" exited with 1 A TypeScript or import error in pages/index.tsx. Fix: Run npm run build on your laptop first and fix the first error it prints.

• Failed to fetch 页面请求了 /api，但重写规则缺失，或 API 没有部署成功。 解决：确认 vercel.json 在项目根目录、api/index.py 存在，并在浏览器里直接打开 /api。
• Error: Command "npm run build" exited with 1 pages/index.tsx 里有 TypeScript 或导入错误。 解决：先在自己电脑上运行 npm run build，修好打印出的第一个错误。

Takeaways要点回顾

• A product has two halves: a front end in the browser and an API on the host.
• The front end is just files the visitor downloads, so it cannot keep secrets. The API holds them.
• A host rule sends /api/... to Python and the rest to Next.js. One address, no CORS trouble.
• Call /api, not a full address, so it works locally and live.
• The Python half needs its own requirements file.
• Preview and production are two deployments. Test the first, then promote.

• 一个产品有两半：浏览器里的前端，和托管平台上的 API。
• 前端只是访问者下载的文件，保不住秘密；秘密由 API 保管。
• 平台规则把 /api/... 交给 Python，其余交给 Next.js。一个地址，没有 CORS 麻烦。
• 调用 /api 而不是完整地址，本地和线上才都能用。
• Python 那一半需要自己的 requirements 文件。
• 预览和生产是两个部署：先测前者，再升级。
