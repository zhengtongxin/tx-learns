Where we left off上回讲到

Last time the product ran on the wharf's own cloud account, answering every visitor from scratch. Today Auntie Siti says "I'm Siti" and, one message later, the twin has no idea. We fix it by sending the earlier messages each time and saving each session to a file.

上回产品跑在码头自己的云账号上，对每位访客都从零开始回答。今天 Siti 阿姨说了“我是 Siti”，下一条消息时，分身却什么都不知道。我们的办法是每次都带上之前的消息，并把每个会话存成一个文件。

The story故事

At every shift change the wharf uses a handover book, so the night crew knows what the day crew did. Mei Ling wants a digital twin: a chat page that answers visitors the way she would, even when she is off shift. She builds it, and Auntie Siti tests it first. She says "I'm Siti" in one message, asks "what's my name?" in the next, and the twin has no idea.

码头每次换班都有一本交接簿，让夜班知道日班做了什么。Mei Ling 想做一个数字分身：一个聊天页面，即使她下班了，也能像她一样回答访客。她做好之后，Siti 阿姨第一个来试。她在一条消息里说“我是 Siti”，下一条问“我叫什么名字？”，分身一点头绪都没有。

Step 1 · The first version has no memory第 1 步 · 第一个版本没有记忆

Learn先学

Start with the two halves you know: a FastAPI backend that calls the model, and a page that talks to it. The backend takes one message, sends it to the model and returns the reply. That is all it does, and each call is a brand new conversation. The session_id field is sent, but nothing uses it yet. Step 3 starts using it.

从你已经熟悉的两半开始：一个调用模型的 FastAPI 后端，和一个跟它说话的页面。后端收到一条消息，发给模型，再把回复返回。它只做这些，而且每次调用都是一场全新的对话。session_id 字段已经发过来了，但现在还没有用到，第 3 步才开始用它。

from fastapi import FastAPI from pydantic import BaseModel from openai import OpenAI app = FastAPI() client = OpenAI() class Chat(BaseModel): session_id: str message: str @app.post("/api/chat") def chat(body: Chat): result = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": body.message}], # only this one message ) return {"reply": result.choices[0].message.content}

Step 2 · A chat page with the Next.js app router第 2 步 · 用 Next.js 应用路由写聊天页面

Learn先学

Next.js has two ways to organise pages. The newer app router uses folders: a file called page.tsx inside app/twin/ becomes the address /twin. Components run on the server unless the file starts with "use client", and a chat box needs that, because it reacts to clicks and typing. The older pages router used a pages/ folder instead. useState is React's way to keep a value, like the reply, between clicks. The tags in the code, like <main>, are JSX: JavaScript that writes the page. Each page load makes up a session id that is sent along with every message, so a refresh starts a new session. The page sends messages to /api/chat, the route from step 1, so the page and the API must share one address. The container lesson shows how.

Next.js 有两种组织页面的方式。较新的应用路由（app router）靠文件夹：app/twin/ 里的 page.tsx 就成了地址 /twin。组件默认在服务器上运行，除非文件开头写了 "use client"，而聊天框需要它，因为要响应点击和输入。较老的页面路由（pages router）用的是 pages/ 文件夹。useState 是 React 用来在两次点击之间保存一个值（比如回复）的办法。代码里像 <main> 这样的标签叫 JSX，是用来写页面的 JavaScript。每次打开页面（刷新也算）会生成一个会话 id，随每条消息一起发送。页面把消息发到 /api/chat，也就是第 1 步写的那条路由，所以页面和 API 要共用一个地址（容器那一课讲了怎么做）。

"use client"; import { useState } from "react"; export default function Twin() { const [sessionId] = useState(() => crypto.randomUUID()); const [text, setText] = useState(""); const [reply, setReply] = useState(""); async function send() { const res = await fetch("/api/chat", { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ session_id: sessionId, message: text }), }); const data = await res.json(); setReply(data.reply); } return ( <main> <input value={text} onChange={(e) => setText(e.target.value)} /> <button onClick={send}>Send</button> <p>{reply}</p> </main> ); }

Step 3 · Send the earlier messages every time第 3 步 · 每次都把之前的消息一起发

Learn先学

The model is stateless: it keeps nothing between calls. The chat looks continuous only because the app sends the whole conversation each time. So keep a list of messages per session id. Add the new user message, send the list, then add the model's reply to it. This version holds the lists in a Python dictionary.

模型是无状态（stateless）的：两次调用之间它什么也不记。聊天看起来连贯，只是因为应用每次都把整段对话发过去。所以要为每个会话 id 保存一份消息列表：加入新的用户消息，把列表发出去，再把模型的回复也加进列表。这个版本把列表放在一个 Python 字典里。

from fastapi import FastAPI from pydantic import BaseModel from openai import OpenAI app = FastAPI() client = OpenAI() histories = {} # session id → list of messages class Chat(BaseModel): session_id: str message: str @app.post("/api/chat") def chat(body: Chat): history = histories.setdefault(body.session_id, []) history.append({"role": "user", "content": body.message}) result = client.chat.completions.create(model="gpt-5.4-mini", messages=history) reply = result.choices[0].message.content history.append({"role": "assistant", "content": reply}) return {"reply": reply}

Step 4 · Save each session as a file第 4 步 · 把每个会话存成文件

Learn先学

A dictionary lives in the program's memory, so a restart wipes it. Write each session to its own JSON file on disk instead, named after the session id. Because the id comes from the browser, check that it holds only safe characters before it goes into a file name, or a visitor could aim at other files. The file is easy to open and read like a log.

字典活在程序的内存里，重启一次就清空了。改成把每个会话写进磁盘上各自的 JSON 文件，文件名用会话 id。因为 id 来自浏览器，放进文件名之前要检查它只含安全的字符，否则访客可能指向别的文件。这个文件很容易打开，像日志一样读。

import json import re from pathlib import Path MEMORY_DIR = Path("memory") MEMORY_DIR.mkdir(exist_ok=True) def session_file(session_id: str) -> Path: if not re.fullmatch(r"[A-Za-z0-9-]{1,64}", session_id): raise ValueError("bad session id") return MEMORY_DIR / f"{session_id}.json" def load_history(session_id: str) -> list: path = session_file(session_id) return json.loads(path.read_text(encoding="utf-8")) if path.exists() else [] def save_history(session_id: str, history: list) -> None: session_file(session_id).write_text(json.dumps(history, ensure_ascii=False), encoding="utf-8")

Step 5 · Do not let it grow forever第 5 步 · 别让它无限增长

Learn先学

Every call sends the whole history, so a long chat costs more with every message, and one day it will not fit at all. Decide what to keep. The simplest rule is to send only the last 20 messages. Also decide how long files live and who may read them: a conversation is personal data.

每次调用都发送整段历史，所以聊得越长，每条消息越贵，总有一天会装不下。要决定保留什么。最简单的规则是只发最近 20 条消息。还要决定文件保留多久、谁能读：对话是个人数据。

# uses client (step 1) and load_history / save_history (step 4) def reply_to(session_id: str, message: str) -> str: history = load_history(session_id) history.append({"role": "user", "content": message}) result = client.chat.completions.create( model="gpt-5.4-mini", messages=history[-20:], # only the latest 20 go to the model ) reply = result.choices[0].message.content history.append({"role": "assistant", "content": reply}) save_history(session_id, history) # the file keeps everything return reply
What I got wrong我犯过的错I thought the model remembered. The chat looked continuous, so I assumed it did. In truth, only the messages my code sent made it seem so. I also let the history grow forever, which costs more with every message. And a new version of Tailwind (a styling helper) broke my styles until I read its migration note.我以为模型会记得。聊天看起来很连贯，所以我就这么以为了。其实只是我的代码发出去的那些消息让它看起来连贯。我还让历史无限增长，每条消息都更贵。另外，写样式的工具 Tailwind 出了新版本，把我的样式搞坏了，直到我读了迁移说明才好。

Now make it yours现在把它变成你的

What changed这一课之后Now the twin remembers a chat, like the night crew reading the handover book, and Auntie Siti's name comes back. The next problem is that it still sounds like a polite stranger and gives vague answers about what Mei Ling actually works on.现在分身记得住一段对话，就像夜班同事读交接本，Siti 阿姨的名字也记起来了。下一个问题是它听起来仍像个客气的陌生人，被问到 Mei Ling 到底做什么时，回答含糊。

Takeaways要点回顾

• A chat model is stateless: every call starts blank.
• Memory is your stored messages plus a session id.
• Send the earlier messages with each new call.
• Save sessions to files so a restart does not wipe them, and check the session id first.
• Cap the history, because long chats cost more with every message.
• In the Next.js app router, folders define routes, and a component needs "use client" to react to typing.
• Decide what to keep, for how long, and who can read it.

• 聊天模型是无状态的：每次调用都从空白开始。
• 记忆就是你存下的消息加上一个会话 id。
• 每次新调用都带上之前的消息。
• 把会话存成文件，重启才不会清空，并且先检查会话 id。
• 限制历史长度，因为聊得越长每条消息越贵。
• 在 Next.js 应用路由里，文件夹决定路由，组件要写 "use client" 才能响应输入。
• 要决定保留什么、保留多久、谁能读。
