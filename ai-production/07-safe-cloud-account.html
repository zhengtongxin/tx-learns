A safe cloud account: roots, users and budget alarms安全的云账号：根用户、普通用户与预算警报

上回产品有了一份真正的工作，但它跑在托管平台上。今天 Mei Ling 还没碰云，Ong 主管就问“出了事谁来付钱？”。我们的办法是先把账号设置好：锁起根登录、建一个权限有限的日常用户，再设预算警报。

The story故事

The canteen helper works, and Mei Ling wants it on a real cloud, not just on her laptop. Mr Ong has one question before she touches anything: "Who pays if this goes wrong?" So she sets up the account properly first: a locked-away master login, a limited daily login, and an alarm that rings when money starts to leak. (The examples use AWS names, but every big cloud has the same pieces.)

食堂助手已经能用了，Mei Ling 想把它放到真正的云上，而不只是留在笔记本里。在她动手之前，Ong 主管先问了一句：“出了岔子，谁来付钱？”所以她先把账号设置妥当：一个锁起来的总登录、一个权限有限的日常登录，再加一个钱开始漏出去时会响的警报。（例子用的是 AWS 的名字，但每家大云厂商都有同样的零件。）

Step 1 · Lock the root login away第 1 步 · 把根用户锁起来

Learn先学

When you sign up, you get a root user: the login that can do everything, including closing the account and changing the bill. Protect it at once with multi-factor authentication (MFA): a password plus a one-time code from an app on your phone. Then stop using it. Root is for rare emergencies only, like the master key kept in Mr Ong's safe.

注册时你会得到一个根用户（root）：它什么都能做，包括关闭账号和修改账单。马上用多因素认证（MFA）保护它：密码加上手机应用里的一次性验证码。然后就不要再用它了。根用户只用于罕见的紧急情况，就像锁在 Ong 主管保险柜里的那把总钥匙。

1. Sign up with an email you control 2. Turn on MFA for the root user (authenticator app) 3. Log out of root 4. Keep the root password and recovery codes somewhere offline

Step 2 · Set budget alarms before any resource第 2 步 · 先设预算警报，再建任何资源

Learn先学

A budget alert sends you an email when your spending reaches a number you chose. Set it before you create anything, because the alarm is the whole point: it tells you the day a nearly free project stops being free. An alert only sends email. It does not stop the spending, so you still have to turn things off yourself. Use several levels, so the first is a nudge and the last is a shout.

预算警报会在花费达到你设定的数字时给你发邮件。要在创建任何东西之前设好，因为警报才是重点：它会告诉你，一个几乎免费的项目是哪一天不再免费的。警报只会发邮件，不会停止花费，所以你还得自己把东西关掉。多设几档，第一档是提醒，最后一档是大喊。

Budget name Amount (USD) Email when spend reaches wharf-nudge 1 50% of the amount wharf-warn 5 80% of the amount wharf-shout 10 100% of the amount (pick numbers you could not ignore)

Step 3 · A limited user, and a group that holds the permissions第 3 步 · 权限有限的用户，和存放权限的用户组

Learn先学

Now create a daily user for yourself. Do not attach permissions to the person. Make a user group, give the group the permissions, and let people join the group. When a new teammate arrives, you add one name to the group instead of ticking twenty boxes. Think of a gate pass: Sergeant Lee issues the pass type "builder", not a custom pass for each person.

现在给自己建一个日常用户。不要把权限直接挂在人身上，而是建一个用户组，把权限给用户组，让人加入用户组。新同事来了，你只需往组里加一个名字，而不用再勾二十个选项。就像通行证：Lee 警官发的是“建设者”这一类通行证，而不是给每个人单做一张。

Group: wharf-builders permissions: container registry (store images) serverless functions (run code) storage buckets (keep files) CDN (serve pages fast) API gateway (public front door) logs (read what happened) User: mei-ling → member of wharf-builders

Step 4 · Sign in as the daily user and pick a region第 4 步 · 用日常用户登录，并选好区域

Learn先学

Sign in as your new user from now on. The console is the cloud's web page where you click through everything. Choose a default region: the part of the world where your resources physically live. Pick one close to your users and keep it the same. Many services exist per region, so something you created in one region is invisible in another. If you cannot find something you made, check the region first.

从现在起用新用户登录。控制台（console）是云的网页，所有操作都在那里点选。再选一个默认区域（region）：你的资源实际所在的地理位置。选离用户近的，并保持不变。很多服务是按区域分开的，在一个区域里创建的东西，在另一个区域里是看不见的。找不到自己建的东西时，先看区域。

Console sign-in: account id + user "mei-ling" + password + MFA code Default region: Asia Pacific (Singapore) (top-right corner of the console) The region must match in the console, in your commands and in your config.

Step 5 · Four words you will see everywhere第 5 步 · 随处可见的四个词

Learn先学

Serverless compute runs your code only when someone calls it. A container registry is like GitHub, but for packaged apps called images. The identity service decides who can do what. The logging service is a diary for your servers: everything they print is written there, so you can read it later. (In AWS they are Lambda, ECR, IAM and CloudWatch.)

无服务器计算只在有人调用时才运行你的代码。容器镜像仓库（registry）就像 GitHub，只不过存的是打包好的应用，叫镜像。身份服务决定谁能做什么。日志服务是服务器的“日记本”：服务器打印的内容都会记在那里，之后可以翻看。（在 AWS 里它们分别是 Lambda、ECR、IAM 和 CloudWatch。）

What I got wrong我犯过的错Three slips. I skipped the budget step "for later", but the alarm is the whole point. I also did everything as root because it was easier. And my default region did not offer the service I wanted, so it simply was not there. Pick the region on purpose.三个失误。我把预算这一步“留到以后”，但警报才是重点。我还图省事，什么都用根用户来做。而且默认区域没有我想用的服务，于是它就是不出现。区域要有意识地选。

Now make it yours现在把它变成你的

What changed这一课之后Now the wharf has a cloud account ready for the product: the master login stays in the safe, the daily user has limited passes, and Mr Ong's budget alarm rings before the bill leaks. The next problem is that the product runs on Mei Ling's laptop but crashes on Kumar's office PC: it needs a standard box.现在码头有了一个能放产品的云账号：主钥匙锁在保险柜里，日常用户的通行证有限，账单漏水之前 Ong 主管的预算警报就会响。下一个问题是产品在 Mei Ling 的笔记本上能跑，在 Kumar 的办公室电脑上却崩溃：它需要一个标准的箱子。

Takeaways要点回顾

• Protect the root login with MFA, then leave it alone.
• Set budget alerts before creating any resource.
• Give permissions to a group, and put people in the group.
• Do daily work as the limited user.
• Choose a region on purpose: resources are invisible across regions.
• A typical learning project stays almost free, and the alarm tells you the day it does not.

• 用 MFA 保护根用户，然后别去动它。
• 在创建任何资源之前先设预算警报。
• 把权限给用户组，再把人放进用户组。
• 日常工作用权限有限的用户。
• 有意识地选区域：资源跨区域是看不见的。
• 一个典型的学习项目几乎免费，而警报会告诉你它不再免费的那一天。
