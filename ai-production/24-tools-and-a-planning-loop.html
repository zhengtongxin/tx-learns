The story故事

The wharf agent from the last lesson answers questions, but it cannot do sums reliably and it never says what it is about to do. Mei Ling wants two upgrades. First, a tool for the sums. Second, a visible to-do list, so that Mr Ong can see the plan before the agent acts, the way he reads a work order before a shift starts.

上一课的码头智能体能回答问题，但算数不可靠，也从不说自己接下来要做什么。Mei Ling 想做两个升级。第一，加一个算数的工具。第二，加一份看得见的待办清单，让 Ong 先生能在智能体动手之前看到计划，就像他在换班前先读工单一样。

Step 1 · A tool is a function with a good description第 1 步 · 工具就是带好说明的函数

Learn先学

A tool is a plain function the model may ask to run. You mark it with a decorator (a line like @tool above the function). The model never sees your code. It sees the function name and the docstring, the text in triple quotes. So the docstring is the instruction manual. If it is vague, the model will ignore the tool.

工具就是模型可以请求运行的普通函数。你用装饰器（函数上面的 @tool 这一行）来标记它。模型看不到你的代码，它只看到函数名和文档字符串，也就是三引号里的那段文字。所以文档字符串就是使用说明书。写得含糊，模型就会无视这个工具。

import math from strands import tool @tool def square_root(number: float) -> float: """Return the square root of a non-negative number. Use this whenever the user needs a square root.""" return math.sqrt(number)

Step 2 · Hand the tool to the agent and relaunch第 2 步 · 把工具交给智能体，再启动

Learn先学

Pass the tools in a list when you build the agent. The deployed copy does not change by itself, so launch again, then invoke it with a prompt that really needs the tool. Check the logs: you should see the tool being called, not the model guessing.

构建智能体时，把工具放进一个列表传进去。已经部署的那份不会自己变，所以要再启动一次，然后用一个确实需要这个工具的提示词去调用它。看一下日志：你应该看到工具被调用，而不是模型在瞎猜。

helper = Agent( system_prompt="You are a short, friendly helper for the wharf IT desk.", tools=[square_root], ) # in agent.py, define square_root above this agent. handle() still calls helper
# in your terminal, not in agent.py agentcore launch agentcore invoke '{"prompt": "A square yard is about 0.836 square metres. How long is one side, in metres?"}'

Step 3 · Build a to-do list the agent can use第 3 步 · 做一份智能体能用的待办清单

Learn先学

A plan is just a list the agent writes and updates. You need three things: a typed item (a small record with a description and a done flag; BaseModel from pydantic checks the type of each field), a list kept in memory, and tools to add an item, mark one done and print the list. Tell the model that positions start at 1, in the tool text itself. People count from 1, and a model will follow what you wrote there. Python lists count from 0, so the first item is plan[0]: the code subtracts 1 from the position to find it.

计划其实就是智能体自己写、自己更新的一份清单。你需要三样东西：一个有类型的条目（一条小记录，有描述和完成标记；pydantic 的 BaseModel 会检查每个字段的类型）、一份放在内存里的清单，以及工具：新增条目、把某条标为完成、打印清单。在工具说明里直接写明位置从 1 开始。人是从 1 数起的，而模型会照你写在那里的说法去做。Python 的列表是从 0 数起的，所以第 1 项在代码里是 plan[0]：代码要把位置减 1 才能找到它。

from pydantic import BaseModel class Todo(BaseModel): description: str done: bool = False plan: list[Todo] = [] # lives in memory (see "what I got wrong") @tool def show_plan() -> str: """Return the current plan, one line per step.""" return "\n".join( f"{i}. [{'x' if t.done else ' '}] {t.description}" for i, t in enumerate(plan, start=1) ) @tool def add_todo(description: str) -> str: """Add one step to the plan. Call once per step, in order.""" plan.append(Todo(description=description)) return show_plan() @tool def mark_done(position: int) -> str: """Mark a step as done. Positions start at 1, not 0.""" plan[position - 1].done = True return show_plan()

Step 4 · Tell the agent to plan first第 4 步 · 让智能体先做计划

Learn先学

The tools exist, but the agent will not use them unless the system prompt says so. Spell out the loop: make a plan with the to-do tools, do each step, mark it done, then answer. Because every tool returns the list, you see the plan change after each move.

工具有了，但系统提示词不说，智能体就不会用。把循环写清楚：先用待办工具做计划，一步一步做，每做完一步就标记完成，最后回答。因为每个工具都会返回清单，你每动一步都能看到计划在变。

planner = Agent( system_prompt=( "First, write a plan with add_todo, one call per step. " "Then do the steps in order. After each one, call mark_done. " "When every step is done, give the final answer." ), tools=[add_todo, mark_done, show_plan, square_root], ) # in handle(), call planner instead of helper: reply = planner(...) # then launch again, and invoke with a task that has four steps

Step 5 · Read the plan as it moves第 5 步 · 看计划怎么动

Learn先学

Read the printed list top to bottom. An agent you can see is easier to trust and easier to fix: if the answer is wrong, you can find the step where it went off. A good plan line is one clear action, such as Take its square root. A vague line like figure it out hides the real action, so you cannot check it.

从上到下读打印出来的清单。看得见的智能体更容易信任，也更容易修：答案不对，你能找到它从哪一步偏掉的。好的计划条目是一个清楚的动作，比如“取它的平方根”。“想办法搞定”这样含糊的条目会把真正的动作藏起来，你就没法检查。

1. [x] Find the area of the square yard 2. [x] Take its square root 3. [ ] Convert the length to feet 4. [ ] Write the answer
What I got wrong我犯过的错Three slips. My first docstring just said "math tool", so the model ignored it; once it said exactly when to use it, it worked. I was off by one: the model said "step 1" and my code treated that as the second item, so I now ask for positions starting at 1 and subtract 1 in code. And my list is a global, so it resets when the container restarts. That is fine for a demo, not for real work.三个失误。我第一版的文档字符串只写了“数学工具”，模型就无视它；写清楚什么时候该用之后，它就好了。我还差了一位：模型说“第 1 步”，我的代码却把它当成第二项，所以现在我要求位置从 1 开始，并在代码里减 1。我的清单是个全局变量，容器一重启就清空。做演示没关系，真用就不行。

Now make it yours现在把它变成你的

What changed这一课之后Now the agent writes its plan first and then uses the calculator, so Mr Ong reads the job sheet and sees which line it is on. The next problem is that it still sounds sure whether or not it is right, and Mr Ong asks how he can know.现在智能体先写计划，再用计算器，Ong 先生读工作单就能看到它做到了哪一行。下一个问题是不管对不对它听起来都很有把握，Ong 先生问他怎么才能知道。

Takeaways要点回顾

• A tool is a plain function with a decorator and a docstring.
• The model reads the docstring, not your code. Make it specific.
• After you change the agent, launch again.
• A plan is a typed to-do list plus tools to add, tick and print.
• Say in the tool text that positions start at 1.
• The system prompt must tell the agent to plan first.
• A visible plan makes an agent easier to trust and to debug.

• 工具就是带装饰器和文档字符串的普通函数。
• 模型读的是文档字符串，不是你的代码，所以要写具体。
• 改了智能体之后，要再启动一次。
• 计划就是一份有类型的待办清单，加上新增、打钩、打印的工具。
• 在工具说明里写明位置从 1 开始。
• 系统提示词必须要求智能体先做计划。
• 看得见的计划，让智能体更容易信任，也更容易调试。
