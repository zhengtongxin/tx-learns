Tools and a planning loop工具与规划循环

Give the deployed agent a tool, then a to-do list so it plans and ticks off its own steps · ~35 min · hands-on给已部署的智能体一个工具，再给它一份待办清单，让它自己做计划、自己打钩 · 约 35 分钟 · 动手

Step 1 · A tool is a function with a good description第 1 步 · 工具就是带好说明的函数

Learn先学

A tool is a plain function the model may ask to run, marked with a @tool decorator. The model never sees your code, only the name and the docstring, so the docstring is the manual: if it is vague, the tool is ignored. Pass tools in a list when you build the agent, launch again (the deployed copy does not change by itself) and check the logs for a real tool call.

工具是模型可以请求运行的普通函数，用 @tool 装饰器标记。模型看不到你的代码，只看到名字和文档字符串，所以文档字符串就是说明书：写得含糊，工具就会被无视。构建智能体时把工具放进列表传入，再启动一次（已部署的那份不会自己变），并在日志里确认真的有工具调用。

import math from strands import Agent, tool @tool def square_root(number: float) -> float: """Return the square root of a non-negative number. Use this whenever the user needs a square root.""" return math.sqrt(number) helper = Agent( system_prompt="You are a short, friendly helper for the wharf IT desk.", tools=[square_root], )

Step 2 · A to-do list the agent can use第 2 步 · 智能体能用的待办清单

Learn先学

A plan is a list the agent writes and updates: a typed item (description plus done flag, checked by pydantic's BaseModel), a list in memory, and tools to add an item, tick one and print the list. Say in the tool text that positions start at 1; Python counts from 0, so the code subtracts 1.

计划是智能体自己写、自己更新的清单：一个有类型的条目（描述加完成标记，由 pydantic 的 BaseModel 检查）、一份内存里的清单，以及新增、打钩、打印的工具。在工具说明里写明位置从 1 开始；Python 从 0 数起，所以代码要减 1。

from pydantic import BaseModel class Todo(BaseModel): description: str done: bool = False plan: list[Todo] = [] # in memory: resets when the container restarts @tool def show_plan() -> str: """Return the current plan, one line per step.""" return "\n".join(f"{i}. [{'x' if t.done else ' '}] {t.description}" for i, t in enumerate(plan, start=1)) @tool def add_todo(description: str) -> str: """Add one step to the plan. Call once per step, in order.""" plan.append(Todo(description=description)) return show_plan() @tool def mark_done(position: int) -> str: """Mark a step as done. Positions start at 1, not 0.""" plan[position - 1].done = True return show_plan()

Step 3 · Tell the agent to plan first第 3 步 · 让智能体先做计划

Learn先学

Tools alone are not enough: the system prompt must spell out the loop. Because every tool returns the whole list, you see the plan change after each move, and if the answer is wrong you can find the step where it went off. A good plan line is one clear action; "figure it out" hides it.

光有工具不够：系统提示词必须把循环写清楚。因为每个工具都返回整份清单，你每动一步都能看到计划在变，答案不对时也能找到偏掉的那一步。好的计划条目是一个清楚的动作；“想办法搞定”会把它藏起来。

planner = Agent( system_prompt=( "First, write a plan with add_todo, one call per step. " "Then do the steps in order. After each one, call mark_done. " "When every step is done, give the final answer." ), tools=[add_todo, mark_done, show_plan, square_root], ) # in handle(), call planner instead of helper, then launch again
1. [x] Find the area of the square yard 2. [x] Take its square root 3. [x] Convert the length to feet One side is about 0.91 m, or 3.0 feet.

Now make it yours现在把它变成你的

Common errors常见错误

• NameError: name 'square_root' is not defined Fix: Define the tool above the Agent(...) line.
• IndexError: list index out of range The position is not in the plan. Fix: Call show_plan first, and count from 1.
• The plan is empty on the next request It lives in memory. Fix: Keep the plan per request, or save it somewhere that lasts.

• NameError: name 'square_root' is not defined 解决：把工具定义在 Agent(...) 那一行上面。
• IndexError: list index out of range 位置不在计划里。 解决：先调用 show_plan，并从 1 开始数。
• The plan is empty on the next request 它存在内存里。 解决：让计划只属于每次请求，或存到能持久保存的地方。

Takeaways要点回顾

• A tool is a function with a decorator and a docstring; the model reads the docstring, not the code.
• Launch again after changing the agent.
• A plan is a typed to-do list plus tools to add, tick and print.
• The system prompt must tell the agent to plan first.
• A visible plan is easier to trust and to debug.

• 工具是带装饰器和文档字符串的函数；模型读的是文档字符串，不是代码。
• 改了智能体之后要再启动一次。
• 计划是有类型的待办清单，加上新增、打钩、打印的工具。
• 系统提示词必须要求智能体先做计划。
• 看得见的计划更容易信任，也更容易调试。
