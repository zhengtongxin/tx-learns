The story故事

Mei Ling is a junior IT officer at Pasir Panjang Wharf 7. Her AI helper works beautifully, but only on her laptop. Auntie Siti, who runs the wharf canteen, wants to try it on her phone. Mei Ling could read ten articles about "going to production". Instead she ships the smallest thing that can possibly work: one route that says hello. Then she makes it smarter.

Mei Ling 是 Pasir Panjang 码头 7 号的初级 IT 专员。她的 AI 助手在自己的笔记本上运行得很好，但也只能在她的笔记本上。码头食堂的 Siti 阿姨想用手机试试。Mei Ling 本可以先读十篇“如何上线”的文章，她却选了最小的做法：先上线一个只会打招呼的接口，再让它变聪明。

Step 1 · What "production" really means第 1 步 · “生产环境”到底是什么

Learn先学

Production sounds big and scary. It is not about size. It means three plain things: other people can reach it, it keeps running when your laptop is shut, and your secrets are not sitting in the files. Think of the difference between cooking at home and opening a stall: same food, but now strangers can walk up at any hour.

“生产环境”听起来又大又吓人，其实跟规模无关。它只有三件很朴素的事：别人能访问到它、你合上笔记本它也照样运行、密钥不会躺在文件里。就像在家做饭和开摊位的区别：食物一样，但现在陌生人随时都能走过来。

Step 2 · The smallest service: one file第 2 步 · 最小的服务：一个文件

Learn先学

Start with no AI at all. A route is an address your service answers, such as /api. FastAPI is a Python tool that turns a function into a route. This file answers any visit to /api with a short piece of JSON (a tidy way to write data as text).

先不要 AI。路由（route）就是你的服务能回应的一个地址，比如 /api。FastAPI 是一个 Python 工具，能把一个函数变成路由。这个文件会对每次访问 /api 的请求，回一小段 JSON（把数据写成文字的整洁格式）。

# api/index.py from fastapi import FastAPI app = FastAPI() @app.get("/api") def hello(): return {"message": "Ahoy from Wharf 7"}

Step 3 · Tell the host what to build第 3 步 · 告诉托管平台要构建什么

Learn先学

A host is a company's computer that runs your code for you. It cannot guess what you wrote, so you leave two notes. A requirements file lists the Python packages to install. A small config file says "build this Python file, and send every URL to it" (in the file below, src is what to match, dest is where to send it, and (.*) means "any address at all"). Think of a delivery slip taped to a container: contents, and where it must go.

托管平台是别人的电脑，替你运行代码。它猜不到你写了什么，所以你要留两张纸条。requirements 文件列出要安装的 Python 包；一个小小的配置文件写明“构建这个 Python 文件，并把所有网址都交给它”（下面的文件里，src 是要匹配的地址，dest 是送去哪里，(.*) 表示“任何地址”）。就像贴在集装箱上的送货单：里面装什么、要送到哪。

# requirements.txt fastapi uvicorn
# vercel.json { "builds": [{ "src": "api/index.py", "use": "@vercel/python" }], "routes": [{ "src": "/(.*)", "dest": "api/index.py" }] }

Step 4 · Deploy with one command第 4 步 · 一条命令上线

Learn先学

The host has a command-line tool. It needs Node (a program that runs JavaScript tools) to install. Install it and log in once (the first box below), then run one command for each deploy. It uploads your folder, builds it and prints an address. That first deploy is a preview: a safe test copy with its own address. Adding --prod makes the real production one.

托管平台有命令行工具，需要先装 Node（运行 JavaScript 工具的程序）才能安装它。装好并登录一次（下面第一个框），之后每次部署只运行一条命令，它就会上传你的文件夹、构建并打印出一个地址。第一次部署是预览（preview）：一个带独立地址的安全测试副本。加上 --prod 才是真正的生产（production）版本。

# once (Node must already be installed: nodejs.org) npm install -g vercel vercel login # every deploy vercel # preview address vercel --prod # production address
(example output) Vercel CLI 39.0.0 Preview: https://wharf-helper-git-abc123.vercel.app [3s] Production: https://wharf-helper.vercel.app [41s]

Step 5 · Now add the model, and keep the key out第 5 步 · 再加上模型，并把密钥放在外面

Learn先学

Only now does Mei Ling add the AI. The model is the AI itself, and the OpenAI client is the Python helper that talks to it. Each call costs money, so the model needs a key: a secret code that tells the AI company whose account to bill. The client reads the key from an environment variable: a named setting kept outside your files. You set it in the host (vercel env add), so the code never contains the key. Add openai to requirements.txt too, then run vercel --prod again.

到这时 Mei Ling 才加上 AI。模型（model）就是 AI 本身，OpenAI 客户端（client）是替你和它说话的 Python 工具。每次调用都要花钱，所以模型需要一把密钥（key）：一串告诉 AI 公司该向谁收费的秘密代码。客户端从环境变量里读取密钥：这是放在文件之外的一个命名设置。你在托管平台里设置它（vercel env add），代码里就不会出现密钥。别忘了把 openai 也加进 requirements.txt，然后再运行一次 vercel --prod。

# api/index.py from fastapi import FastAPI from openai import OpenAI app = FastAPI() client = OpenAI() # reads OPENAI_API_KEY from the environment @app.get("/api") def hello(): reply = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": "Write a one-line welcome for the wharf canteen."}], ) return {"message": reply.choices[0].message.content}
# terminal vercel env add OPENAI_API_KEY vercel --prod
$ curl https://wharf-helper.vercel.app/api {"message":"Welcome to the Wharf 7 canteen, where lunch is always on time!"}
What I got wrong我犯过的错I typed the key straight into the code first. It worked, and that is exactly the danger: it felt fine. I moved it to an environment variable before the first deploy. I also hit command not found because Node was not installed, and a Python version mismatch because the host picks a version for you unless you say which one to use. The host's project settings (or its docs) show where to pick the Python version.我一开始把密钥直接写进了代码。它能用，而这正是危险所在：感觉没问题。我在第一次部署之前就把它挪到了环境变量里。另外我还遇到过 command not found，因为没装 Node；还遇到 Python 版本不匹配，因为平台会自己挑一个版本，除非你指定用哪个。在平台的项目设置（或文档）里可以找到选择 Python 版本的地方。

Now make it yours现在把它变成你的

What changed这一课之后Now the product can say hello at a real public address, and Auntie Siti can open it on her phone, like a trial container sent through the gate. The key stays in the host's settings, never in the box. The next problem is that it answers in raw JSON, which nobody wants to read: it needs a face.现在产品能在真实的公开地址上打招呼，Siti 阿姨用手机就能打开，就像一个试运行的集装箱已经过了闸口。密钥留在平台的设置里，不在箱子里。下一个问题是它回的是原始 JSON，没人想读：它需要一张脸。

Common errors常见错误

• ModuleNotFoundError: No module named 'openai' The package is missing from the file Vercel installs from. Fix: Add openai to requirements.txt and run vercel --prod again.
• openai.AuthenticationError: Incorrect API key provided The key was not set on Vercel, or has a stray space. Fix: Run vercel env add OPENAI_API_KEY again, paste the key alone, then redeploy.
• 404: NOT_FOUND The routes in vercel.json do not point at api/index.py. Fix: Check the file path in "src" and "dest", then deploy again.

• ModuleNotFoundError: No module named 'openai' Vercel 只安装依赖文件里列出的包，而 openai 没写进去。 解决：把 openai 加进 requirements.txt，再运行 vercel --prod。
• openai.AuthenticationError: Incorrect API key provided Vercel 上没有设置密钥，或密钥里多了空格。 解决：重新运行 vercel env add OPENAI_API_KEY，只粘贴密钥本身，然后重新部署。
• 404: NOT_FOUND vercel.json 里的路由没有指向 api/index.py。 解决：检查 "src" 和 "dest" 里的文件路径，然后重新部署。

Takeaways要点回顾

• "Production" is not big. It is: others can reach it, it runs when your laptop is shut, secrets are outside the files.
• Ship a tiny thing first, then add the model.
• A requirements file says what to install. A config file says what to build and where traffic goes.
• A preview address is a test copy. --prod makes the real one.
• Secrets live in the host's environment settings, never in the repo.
• When a deploy fails, read the build log first.

• “生产环境”不是“大”，而是：别人能访问、笔记本合上也运行、密钥在文件之外。
• 先上线一个小东西，再加模型。
• requirements 文件说明装什么；配置文件说明构建什么、流量送到哪。
• 预览地址是测试副本，--prod 才是正式版本。
• 密钥放在平台的环境设置里，绝不放进仓库。
• 部署失败，先看构建日志。
