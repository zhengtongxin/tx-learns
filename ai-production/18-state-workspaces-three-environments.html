State and three environments状态与三套环境

Run development, test and production as three copies of the same stack from one set of files, without copy-pasting configs · ~35 min · hands-on用同一套文件把开发、测试和生产跑成同一个架构的三份副本，不用复制粘贴配置 · 约 35 分钟 · 动手实践

Step 1 · One config, an environment variable, unique names第 1 步 · 一份配置、一个环境变量、唯一的名字

Learn先学

Keep one folder of config and add a variable called environment (dev, test or prod). Feed it into every name, so the three environments are the same files with a different word in the names. Bucket names must also be unique across everyone's accounts, so build them from project, environment and your account id. A local is a named shortcut; a data block asks the cloud for a fact instead of creating something.

只留一个配置文件夹，加一个叫 environment 的变量（dev、test 或 prod）。把它放进每一个名字里，这样三个环境就是同样的文件、名字里只差一个词。存储桶名字还必须在所有人的账号里唯一，所以由项目、环境和你的账号 id 拼成。local 是起了名的快捷方式；data 块是向云查询一个事实，而不是创建东西。

variable "environment" { type = string validation { condition = contains(["dev", "test", "prod"], var.environment) error_message = "environment must be dev, test or prod." } } data "aws_caller_identity" "me" {} locals { prefix = "wharf-twin-${var.environment}" suffix = data.aws_caller_identity.me.account_id } resource "aws_s3_bucket" "memory" { bucket = "${local.prefix}-memory-${local.suffix}" }

Step 2 · State and one workspace per environment第 2 步 · 状态，以及每个环境一个工作区

Learn先学

The state records which real resources match which lines of config. A workspace is a named copy of the state, so make one per environment. To deploy, select the workspace and pass the same name as the variable. If they disagree, the plan tries to replace prod's things with dev's, so print the workspace and read the plan before every apply. And never hand-edit what the config owns: the next plan will try to undo it.

状态记录哪些真实资源对应配置的哪几行。工作区是状态的一份有名字的副本，所以每个环境建一个。部署时要选中工作区，并且把同样的名字作为变量传入。两者不一致，plan 会想把 prod 的东西换成 dev 的，所以每次 apply 前先打印工作区、读 plan。配置管着的东西别手工改：下一次 plan 会想把它改回去。

terraform workspace new dev # once per environment terraform workspace select -or-create dev terraform workspace show # always print it before you apply terraform plan -var="environment=dev" terraform apply -var="environment=dev"

Step 3 · Per-environment settings第 3 步 · 每个环境自己的设置

Learn先学

Environments share a shape, not every setting. Put the choice in a map (a lookup table) keyed by environment name and pick from it with one line: a small, cheap model in dev, a bigger one in prod.

各环境结构一样，但不必每项设置都一样。把选择放进以环境名为键的映射表（查找表），用一行去取：dev 用小而便宜的模型，prod 用更大的。

variable "model_ids" { type = map(string) default = { dev = "apac.amazon.nova-micro-v1:0" test = "apac.amazon.nova-lite-v1:0" prod = "apac.amazon.nova-pro-v1:0" } } locals { model_id = var.model_ids[var.environment] # then: MODEL_ID = local.model_id }

Now make it yours现在把它变成你的

Common errors常见错误

• Invalid value for variable Fix: Pass -var="environment=dev" exactly.
• Workspace "test" doesn't exist Fix: Run terraform workspace new test, or use select -or-create.
• reading ZIP file twin.zip is not built yet. Fix: Build the zip, then plan again.

• Invalid value for variable 解决：准确传入 -var="environment=dev"。
• Workspace "test" doesn't exist 解决：运行 terraform workspace new test，或用 select -or-create。
• reading ZIP file twin.zip 还没构建。 解决：先构建压缩包，再 plan。

Takeaways要点回顾

• One folder of config drives every environment: same code, one state per workspace.
• An environment variable in every name stops collisions; add the account id for global bucket names.
• Select the workspace, pass the same name, and print the workspace before you apply.
• Use a map for per-environment settings.
• Never hand-edit what the config owns.

• 一个配置文件夹驱动所有环境：同样的代码，每个工作区一份状态。
• 每个名字里放 environment 变量防止撞车；全局的桶名再加账号 id。
• 选好工作区，传同样的名字，apply 前先打印工作区。
• 每个环境不同的设置用映射表。
• 配置管着的东西别手工改。
