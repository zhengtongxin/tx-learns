Step 1 · Start from the planner第 1 步 · 从规划智能体出发

Learn先学

Begin with the planner from the last lesson: the to-do item, the list, and the tools to add, tick and show. Do not rebuild anything. Everything new is added on top, so you can tell what broke if something does. Before you add anything, launch it once and confirm it still plans.

从上一课的规划智能体开始：待办条目、清单，以及新增、打钩、显示的工具。什么都不要重建，所有新东西都加在上面，这样出了问题你知道是哪里坏的。加东西之前，先启动一次，确认它还能做计划。

Project so far (one entry-point file, agent.py): Todo model description + done flag plan list in memory tools add_todo, mark_done, show_plan launched and invoked still plans? yes → continue

Step 2 · Add a sandbox tool for running code第 2 步 · 加一个跑代码的沙盒工具

Learn先学

A code interpreter is a managed sandbox: a sealed box in the cloud that runs Python and hands back the output. Your tool sends code to it and reads the result. Streamed means the answer arrives in pieces, so the loop joins the pieces into one string. with opens the sandbox and closes it when the block ends. clearContext: False tells it not to wipe its earlier state first. The code never touches your own machines. A model wrote that code, so it could do anything; the sandbox keeps any damage inside the box. Create the sandbox in the same region as your agent, or the call fails.

代码解释器是一个托管沙盒：云上一个封闭的盒子，运行 Python 并把输出交回来。你的工具把代码发给它，再读取返回的结果。“流式”的意思是结果分成小块陆续到达，所以循环要把这些小块拼成一个字符串。with 负责打开沙盒，块结束时自动关掉。clearContext: False 表示先不要清掉它之前的状态。代码绝不会碰到你自己的机器。模型写的代码可能做任何事，沙盒把损害关在盒子里。沙盒要建在和智能体相同的区域，否则调用会失败。

from bedrock_agentcore.tools.code_interpreter_client import code_session @tool def run_python(code: str) -> str: """Run Python code in a safe sandbox and return what it prints. Use it to check an answer. Always print the result.""" with code_session("ap-southeast-1") as sandbox: response = sandbox.invoke( "executeCode", {"code": code, "language": "python", "clearContext": False}, ) output = "" for event in response["stream"]: output += str(event["result"]) return output

Step 3 · Make the check a required to-do第 3 步 · 把验证写成必做的待办

Learn先学

Giving the agent the sandbox is not enough: it may just skip it. So change the system prompt in two ways. Solve in your head first, without code. Then add a to-do that starts with "Write Python code to..." and run it to check. Because it is a line in the plan, it is no longer optional.

光给智能体一个沙盒不够：它可能直接跳过。所以从两方面改系统提示词。先不用代码，靠自己推理解出来。然后加一条以“Write Python code to...”开头的待办，并运行它来验证。因为它是计划里的一行，就不再是可选的了。

checker = Agent( system_prompt=( "Make a plan with add_todo. Solve the task yourself first, without code. " "Then add one more to-do that starts with 'Write Python code to' " "and use run_python to check your answer. " "If the check disagrees, fix the answer. Mark each step done, then reply." ), tools=[add_todo, mark_done, show_plan, run_python], ) # in handle(), call checker instead of the earlier agent

Step 4 · Colour the coding steps, relaunch and try a puzzle第 4 步 · 给写代码的步骤上色，重新启动并出一道谜题

Learn先学

Make the check easy to spot. In show_plan, wrap any line that starts with "Write Python code" in a colour code (terminals read \033[96m as "cyan" and \033[0m as "reset"). Then launch again and invoke with a puzzle. The right answer is 9 (the number of ways to reshuffle 4 people so that nobody keeps their own), so you can check the agent. Read three things: the plan, the answer, and the check.

让验证步骤一眼就能看到。在 show_plan 里，把以“Write Python code”开头的行包上颜色代码（终端把 \033[96m 读作“青色”，\033[0m 读作“恢复”）。然后再启动，用一道谜题调用它。这道题的正确答案是 9（4 个人互换班次、谁都不留回自己班次的方法数），你可以拿它来核对。读三样东西：计划、答案和验证。

@tool def show_plan() -> str: """Return the current plan, one line per step.""" lines = [] for i, t in enumerate(plan, start=1): line = f"{i}. [{'x' if t.done else ' '}] {t.description}" if t.description.startswith("Write Python code"): line = "\033[96m" + line + "\033[0m" lines.append(line) return "\n".join(lines)
# agentcore launch # agentcore invoke '{"prompt": "How many ways can 4 crane operators swap shifts so nobody keeps their own?"}'
1. [x] Work out the answer by reasoning: 9 2. [x] Write Python code to check the count of derangements of 4 output: 9 3. [x] Compare the two There are 9 ways.

Step 5 · Turn on observability and read the trace第 5 步 · 打开可观测性，读调用轨迹

Learn先学

A trace is a recording of one run: each tool call, how long it took and how many tokens it used (a token is a small piece of text, about a word or part of one, that the model reads and writes; you pay per token). It stays empty until you switch observability on in the console first. After that, run the puzzle again and open the trace. Look for the slowest step and the longest wait.

轨迹是一次运行的录像：每次工具调用、用了多久、花了多少 token（一小段文字，大约一个词或一个词的一部分，模型读和写的都是它，按 token 计费）。必须先在控制台里打开可观测性，否则它一直是空的。打开后，再跑一次谜题，然后打开轨迹。找出最慢的一步和等得最久的地方。

Trace of one run: add_todo x4 0.4 s (model: solve first) 3.1 s 1,900 tokens run_python 6.8 s ← slowest mark_done x4 0.3 s final answer 1.2 s

Step 6 · Delete the agent and its resources第 6 步 · 删掉智能体和它的资源

Learn先学

When you are done, remove what you made: the deployed agent, its container image (the packed copy of your code) in the registry, and its roles. A forgotten agent is a small bill that nobody remembers approving. Write the list of what to remove before you start deleting, and check the console afterwards to be sure it is empty.

做完之后，把你建的东西清掉：已部署的智能体、仓库里的容器镜像（打包好的代码副本）和它的角色。被遗忘的智能体就是一笔没人记得批准过的小账单。动手删之前，先把要删的东西列成清单，删完再去控制台确认已经清空。

Clean-up list [ ] the deployed agent [ ] its image in the registry [ ] the roles made for it [ ] the log groups (the saved logs of each run; or set a short retention, meaning how long they are kept) [ ] open the console and check that nothing is left
What I got wrong我犯过的错Three slips. The sandbox was created in a different region from the agent, so the first check failed. The agent skipped the check when the prompt only said "you may use code"; making it a required to-do fixed that. And the trace stayed empty until I turned on observability in the console, which I had to do before the run, not after.三个失误。沙盒建在了和智能体不同的区域，所以第一次验证失败了。提示词只写“你可以用代码”时，智能体跳过了验证；把它写成必做的待办之后就好了。轨迹一直是空的，直到我在控制台里打开可观测性，而且必须在运行之前打开，不是之后。

Common errors常见错误

• AccessDeniedException on code interpreter The agent role may not use the code-interpreter service. Fix: Add that permission to the role (or relaunch so the toolkit adds it).
• The checker never calls run_python The prompt does not say to write a "Write Python code to" step. Fix: Keep that sentence exactly in the system prompt.
• The sandbox prints nothing The code computed a value but never printed it. Fix: The tool says "always print the result"; keep that line.

• AccessDeniedException on code interpreter 智能体的角色无权使用代码解释器服务。 解决：给角色加上这项权限（或重新启动让工具包补上）。
• The checker never calls run_python 提示词没有要求添加以 “Write Python code to” 开头的步骤。 解决：把那句话原样保留在系统提示词里。
• The sandbox prints nothing 代码算出了结果，却没有打印。 解决：工具说明里写着 “always print the result”，请保留这一句。

Recap小结A second opinion from code catches answers the model got wrong.
The sandbox keeps untrusted code away from your account.
Read the trace to find the slow step, and clean up everything you launched.让代码给出第二意见，能抓出模型答错的地方。
沙箱让不可信的代码远离你的账号。
读追踪记录找出慢的那一步，并清理所有你启动过的东西。
Plain words白话词汇Sandbox: a locked room where code can run without touching your account. Trace: a timed list of every step one run took.沙箱（sandbox）：代码可以在其中运行、却碰不到你账号的隔离房间。追踪记录（trace）：一次运行每一步的耗时清单。

Takeaways要点回顾

• Start from the working planner and add one thing at a time.
• A managed code interpreter runs code in a sealed sandbox, not on your machines.
• Keep the sandbox in the same region as the agent.
• Make the check a required to-do in the plan, not a suggestion.
• Turn on observability before the run, then read the trace.
• Delete the agent and its resources when you finish.
• Verification beats confidence: plan, act, check, and keep a trace.

• 从能跑的规划智能体出发，一次只加一样东西。
• 托管的代码解释器在封闭沙盒里跑代码，不在你的机器上。
• 沙盒和智能体放在同一个区域。
• 把验证写成计划里的必做待办，而不是建议。
• 运行之前先打开可观测性，然后读轨迹。
• 做完之后，把智能体和它的资源删掉。
• 验证胜过自信：计划、行动、验证，并留下轨迹。
