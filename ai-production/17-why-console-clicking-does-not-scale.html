Step 1 · Code instead of clicks第 1 步 · 用代码代替点击

Learn先学

A setup built by clicking lives only in your memory. Delete a throwaway copy by hand and you see the pain: six parts, around thirty clicks, and an order to respect (the CDN before the bucket it points at, buckets emptied before deleting). Infrastructure as code puts the setup in text files, so it can be:

点出来的搭建只存在于你的记忆里。手工删一份一次性副本你就懂了：六个部件、约三十次点击，还有顺序要守（先删 CDN，再删它指向的存储桶；存储桶先清空再删）。基础设施即代码把搭建写成文本文件，于是它可以被：

• reviewed before it changes
• versioned in git (a tool that records every change to files)
• repeated for a second copy
• shared with a teammate

• 改动前被审阅
• 在 git（记录文件每次改动的工具）里版本管理
• 为第二份副本而重复
• 和队友共享

Step 2 · Five Terraform ideas第 2 步 · Terraform 的五个概念

Learn先学

Terraform is a popular infrastructure-as-code tool. It has five ideas:

Terraform 是常用的基础设施即代码工具，有五个概念：

resource what to make aws_s3_bucket "memory" provider which cloud's plugin aws variable a knob you set per run var.environment state what exists right now terraform.tfstate workspace a separate copy of the state dev, test, prod

Step 3 · Your first config第 3 步 · 你的第一份配置

Learn先学

Install Terraform (brew install terraform, choco install terraform or the official download) and check terraform -version. It reuses your AWS command-line login. Before the first commit, ignore the plugin folder and the state file, which can hold secrets in plain text. Then start with one bucket (names are shared worldwide, so change it). init downloads plugins, plan previews without changing anything, apply does it, destroy removes it.

安装 Terraform（brew install terraform、choco install terraform 或官方下载），用 terraform -version 检查。它沿用你的 AWS 命令行登录。第一次提交前，先忽略插件文件夹和状态文件，后者可能以明文存着秘密。然后从一个存储桶开始（桶名全球共用，请改成你自己的）。init 下载插件，plan 只预览不改动，apply 执行，destroy 移除。

.terraform/ *.tfstate *.tfstate.* *.tfvars
terraform { required_providers { aws = { source = "hashicorp/aws", version = "~> 5.0" } # any 5.x, never 6.0 } } provider "aws" { region = "ap-southeast-1" } resource "aws_s3_bucket" "memory" { bucket = "wharf-twin-practice-ml-2026" tags = { Project = "twin" } }
terraform init terraform plan terraform apply terraform destroy

Now make it yours现在把它变成你的

Common errors常见错误

• Failed to install provider Fix: Check your network, then run terraform init -upgrade.
• BucketAlreadyExists The name is taken. Fix: Add your initials or account id.
• No valid credential sources found Fix: Configure your command-line sign-in again, then repeat terraform plan.

• Failed to install provider 解决：检查网络，再运行 terraform init -upgrade。
• BucketAlreadyExists 名字已被占用。 解决：加上你的缩写或账号 id。
• No valid credential sources found 解决：重新配置命令行登录，再运行 terraform plan。

Takeaways要点回顾

• Clicked setups are hard to remember, repeat or share.
• Infrastructure as code means text you can review, version, repeat and share.
• Terraform's five ideas: resource, provider, variable, state, workspace.
• Keep state and .terraform/ out of git.
• plan shows what will change before anything does.

• 点出来的搭建难记、难重复、难共享。
• 基础设施即代码，就是可审阅、可版本管理、可重复、可共享的文本。
• Terraform 的五个概念：资源、提供者、变量、状态、工作区。
• 状态和 .terraform/ 不要进 git。
• plan 在任何改动发生前显示将会改什么。
