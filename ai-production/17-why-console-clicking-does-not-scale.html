Where we left off上回讲到

Last time the product was live, built in one afternoon of console clicking. Today it fails when Mr Ong wants three copies and Mei Ling cannot remember every click. We fix it by describing the product in a file, so it can be read, planned and rebuilt.

上回，产品已经上线，是花了一个下午在控制台里点出来的。今天 Ong 先生想要三份副本，Mei Ling 却记不住每一次点击。我们的办法是把产品写成一份文件，让它可以被阅读、预演和重建。

The story故事

Mr Ong likes the twin so much that he wants three copies: one to play with, one to test, one for the public. Mei Ling built the first copy by clicking through the console for an afternoon, and she cannot remember every click. Kumar peers at her screen and says what he always says: "If you do it twice, it should be a script. And before that, a plan on paper."

Ong 先生太喜欢这个分身了，想要三份：一份玩，一份测试，一份给公众。Mei Ling 是花了一个下午在控制台里一点一点点出第一份的，她已经记不清每一下点击。Kumar 凑过来看她的屏幕，说了他的口头禅：“做两遍的事，就该写成脚本。在那之前，先在纸上画个方案。”

Step 1 · Take the hand-made twin apart第 1 步 · 先把手工搭的分身拆掉

Learn先学

Before the fix, feel the problem. Delete a throwaway hand-made copy of the twin on purpose (never the live one that people use), in the console (the cloud company's web page where you click). You will see how many parts there were, and that they depend on each other: a thing that points at another thing must go first, or you hit "still in use" errors. Buckets must also be emptied before they can be deleted.

解法之前，先感受问题。有意把一个手工搭的一次性分身副本删掉（绝对不要删正在被人使用的那个），在控制台里，也就是云服务商那个你用来点击的网页。你会看到原来有这么多部件，而且它们互相依赖：指向别的东西的部件要先删，否则会撞上“仍在使用中”的错误。存储桶也要先清空才能删。

1. CDN disable it, wait a few minutes, then delete (it points at the site bucket) 2. API gateway it points at the function 3. function it uses the role 4. function's role detach its policies, then delete 5. memory bucket empty it, then delete 6. site bucket empty it, then delete six parts, around thirty clicks

Step 2 · Infrastructure as code第 2 步 · 基础设施即代码

Learn先学

Infrastructure as code means the setup is text in files, not a memory of clicks. Text can be reviewed (someone reads it before it changes), versioned (every change is in git history; git is the tool that records every change to a folder of files, and a diff is the list of lines that changed), repeated (run it again for a second copy) and shared (a teammate gets the same setup). Think of the berth plan pinned to the wall: anyone can read what goes where, and a change must be written on the plan first.

基础设施即代码的意思是：搭建本身就是文件里的文字，而不是一堆点击的记忆。文字可以被审阅（改动前有人先读）、被版本管理（每次改动都在 git 历史里；git 是一个记录文件夹里每次改动的工具，diff 是改动的行列表）、被重复（再跑一遍就得到第二份）、被共享（队友拿到的搭建是一样的）。就像贴在墙上的泊位图：谁都能读出什么放哪儿，要改也得先改在图上。

clicking: remember → click → hope → forget what you did as code: write it → plan (read the diff) → apply → it is in git

Step 3 · Five Terraform ideas第 3 步 · Terraform 的五个概念

Learn先学

Terraform is a popular tool for infrastructure as code. It has five ideas. A resource is a thing to create, like a bucket. A provider is the plugin that knows how to talk to one cloud. A variable is a knob you set per run. The state is Terraform's record of what really exists. A workspace is a separate copy of the state, so one set of files can drive several environments.

Terraform 是一个常用的基础设施即代码工具。它有五个概念。资源（resource）是要创建的东西，比如一个存储桶。提供者（provider）是懂得和某个云打交道的插件。变量（variable）是每次运行时设置的旋钮。状态（state）是 Terraform 对“实际存在什么”的记录。工作区（workspace）是状态的一份独立副本，所以同一套文件可以驱动多个环境。

resource what to make aws_s3_bucket "memory" provider which cloud's plugin aws variable a knob var.environment state what exists right now terraform.tfstate workspace a separate copy of the state dev, test, prod

Step 4 · Install it, and keep its local files out of git第 4 步 · 安装它，并让它的本地文件远离 git

Learn先学

Install Terraform from its official download page or your system's package manager (for example brew install terraform on a Mac, or choco install terraform on Windows; on Linux use the vendor's package repository), then check it with terraform -version. It uses the same AWS login as the AWS command line, so if aws already works on your laptop, Terraform will too. Before the first commit, write a .gitignore. Terraform downloads provider plugins into a folder, and it writes the state to a file that can hold passwords and keys in plain text. Neither belongs in git. (The small .terraform.lock.hcl file, which pins plugin versions, should be committed.)

从官方下载页或你系统的包管理器安装 Terraform（例如 Mac 上 brew install terraform，Windows 上 choco install terraform，Linux 用官方软件源），然后用 terraform -version 检查。它使用和 AWS 命令行相同的 AWS 登录，所以你笔记本上的 aws 能用，它也能用。第一次提交之前，先写好 .gitignore。Terraform 会把提供者插件下载到一个文件夹里，还会把状态写进一个文件，这个文件里可能以明文存着密码和密钥。这两样都不该进 git。（记录插件版本的小文件 .terraform.lock.hcl 则应该提交。）

$ terraform -version
# .gitignore .terraform/ *.tfstate *.tfstate.* *.tfvars crash.log
(example output) $ terraform -version Terraform v1.9.8 on linux_amd64

Step 5 · Read one small config, line by line第 5 步 · 一行一行读一份小配置

Learn先学

Start with one bucket, and understand every line before you make more. The first block says which provider to download (the ~> 5.0 means any 5.x version, but never 6.0, so a new major release cannot surprise you). The second sets its region. The third is the resource: its type, a local name (memory), and its settings. Then run the four commands: init downloads plugins, plan shows what would change without changing anything, apply does it, destroy removes it.

先从一个存储桶开始，每一行都弄懂了再去建更多。第一块说明要下载哪个提供者（~> 5.0 表示任何 5.x 版本，但不会升到 6.0，这样新的大版本不会给你惊喜）。第二块设置它的区域。第三块是资源：它的类型、一个本地名字（memory）和它的设置。然后运行四条命令：init 下载插件，plan 显示将会改什么、但不真的改，apply 去执行，destroy 把它移除。

Bucket names are shared by everyone in the cloud, so change the name below to one of your own.

存储桶的名字是全云共用的，所以请把下面的名字换成你自己的。

# main.tf terraform { required_providers { aws = { source = "hashicorp/aws", version = "~> 5.0" } } } provider "aws" { region = "ap-southeast-1" } resource "aws_s3_bucket" "memory" { bucket = "wharf-twin-practice-ml-2026" tags = { Project = "twin" } }
# then, in the same folder: terraform init terraform plan terraform apply terraform destroy
Plan: 1 to add, 0 to change, 0 to destroy. aws_s3_bucket.memory: Creation complete after 2s Apply complete! Resources: 1 added, 0 changed, 0 destroyed.
What I got wrong我犯过的错Three slips. I thought code for infrastructure would be harder than clicking. The first time it is; by the tenth time it is far easier. I deleted things in the wrong order and hit dependency errors. And I almost committed the state file, which can hold secrets.三个失误。我以为用代码管基础设施比点鼠标难。第一次确实难；到第十次就容易多了。我删东西的顺序不对，撞上了依赖错误。我还差点把状态文件提交上去，而它里面可能有秘密。

Now make it yours现在把它变成你的

What changed这一课之后Now the product exists as a small Terraform file Mei Ling can read, preview with a plan and rebuild: the berth plan pinned on the wall. The next problem is that one file must make three copies (dev, test, prod) without them drifting apart, and Kumar's logbook, the state, has to keep them straight.现在产品有了一份 Mei Ling 能读、能用 plan 预演、能重建的小型 Terraform 文件：就像钉在墙上的泊位图。下一个问题是同一份文件要造出三份副本（开发、测试、生产）而不互相走样，Kumar 的工作日志，也就是状态，要负责把它们理清楚。

Common errors常见错误

• Error: Failed to install provider No internet from the terminal, or the version rule matches nothing. Fix: Check your network, then run terraform init -upgrade.
• BucketAlreadyExists S3 bucket names are shared by everyone, and yours is taken. Fix: Add your initials or account id to the name.
• Error: No valid credential sources found Terraform cannot find your cloud sign-in. Fix: Configure your command line sign-in again, then repeat terraform plan.

• Error: Failed to install provider 终端没有联网，或版本规则没有匹配的版本。 解决：检查网络，再运行 terraform init -upgrade。
• BucketAlreadyExists S3 桶名全球唯一，你的名字已被占用。 解决：在名字里加上你的缩写或账号 id。
• Error: No valid credential sources found Terraform 找不到你的云登录信息。 解决：重新配置命令行登录，再重复 terraform plan。

Recap小结Code beats clicking: it is repeatable, reviewable and kept in git.
Four moves: init, plan, apply, destroy; always read the plan.
Never commit the state file or secrets.代码胜过点击：可重复、可审查、存在 git 里。
四个动作：init、plan、apply、destroy；一定要读计划。
不要提交状态文件和密钥。
Plain words白话词汇Terraform: a tool that reads files describing your cloud and makes the cloud match them. State: its notebook of what it has already made. Plan: a preview of changes before they happen.Terraform：读取描述云环境的文件，并让云与之一致的工具。状态（state）：它记录已创建内容的笔记本。计划（plan）：改动发生前的预览。

Takeaways要点回顾

• Hand-built infrastructure is hard to remember, repeat or share; deleting it shows how many parts there were.
• Delete in dependency order: whatever points at something goes first, and buckets are emptied before they go.
• Infrastructure as code means the setup is text that can be reviewed, versioned, repeated and shared.
• Terraform's five ideas: resources, providers, variables, state and workspaces.
• Keep .terraform/ and state files out of git, because state can hold secrets.
• plan shows what will change before anything changes.
• Anything I can click, I should be able to rebuild from a file.

• 手工搭的基础设施难记、难重复、难共享；把它删掉就能看出原来有多少部件。
• 按依赖顺序删除：指向别的东西的先删，存储桶先清空再删。
• 基础设施即代码，就是让搭建成为可审阅、可版本管理、可重复、可共享的文字。
• Terraform 的五个概念：资源、提供者、变量、状态和工作区。
• 把 .terraform/ 和状态文件挡在 git 之外，因为状态里可能有秘密。
• plan 在任何东西改变之前，先显示将会改什么。
• 凡是我能点出来的，我都应该能从一份文件里重建出来。
