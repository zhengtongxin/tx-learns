Containers in plain words容器的大白话

See what a container really is, and why packing the app into one makes deploying calmer · ~25 min · hands-on看懂容器到底是什么，以及为什么把应用装进容器能让部署更省心 · 约 25 分钟 · 动手实践

Step 1 · A container is a sealed box第 1 步 · 容器是一个封好的箱子

Learn先学
  • A container holds your app plus everything it needs: language, libraries, settings. It runs the same on your laptop, a colleague's PC and the cloud.
  • A Dockerfile is the recipe: start from a base image (a ready-made box with Python), copy files, install libraries, say how to start.
  • 容器里装着应用和它需要的一切：语言环境、库、配置。在你的笔记本、同事的电脑和云上，它跑起来都一样。
  • Dockerfile 是配方：从基础镜像（已带 Python 的现成箱子）开始，复制文件，安装库，写明怎么启动。
FROM python:3.12-slim WORKDIR /app COPY requirements.txt . RUN pip install --no-cache-dir -r requirements.txt COPY . . CMD ["uvicorn", "server:app", "--host", "0.0.0.0", "--port", "8000"]

Step 2 · Build, run, registry第 2 步 · 构建、运行、镜像仓库

Learn先学
  • Build turns the recipe into an image: the sealed box on a shelf.
  • Run starts a container from the image: the box open and working. One image can run many containers.
  • A registry is the cloud shelf where images are stored.
  • -t names the image; -p 8000:8000 connects port 8000 on your machine to port 8000 in the box.
  • 构建把配方变成镜像：货架上封好的箱子。
  • 运行从镜像启动容器：打开并开始工作的箱子。一个镜像可以跑很多个容器。
  • 镜像仓库是云上存放镜像的货架。
  • -t 给镜像起名；-p 8000:8000 把本机 8000 端口接到箱子里的 8000 端口。
docker run hello-world # is the tool working? docker build -t canteen-helper . # recipe → image docker run -p 8000:8000 canteen-helper # image → running container # now open http://localhost:8000 in the browser

Step 3 · Keep the box small and correct第 3 步 · 让箱子又小又对

Learn先学
  • An ignore file keeps junk out (COPY . . copies everything it sees).
  • Build for the platform you deploy to: an Apple-chip Mac builds for a different chip than most cloud servers.
  • A container never sees your .env unless you pass the values in.
  • 忽略文件把杂物挡在外面（COPY . . 会复制它看到的一切）。
  • 按你要部署的平台构建：苹果芯片的 Mac 构建出的镜像，和多数云服务器的芯片不同。
  • 容器看不到你的 .env，除非你把值传进去。
# .dockerignore (one name per line) node_modules .git .env __pycache__
docker build --platform linux/amd64 -t canteen-helper . docker run --env-file .env -p 8000:8000 canteen-helper

Step 4 · Serve the front end from the box第 4 步 · 让箱子自己提供前端

Learn先学

Export the Next.js page as static files (output: "export" in next.config.js, build, copy out to static) and let the Python API serve them. One box, one address, so the page can call /api/health by relative path. CORS stays as the backup if a front end lives elsewhere.

把 Next.js 页面导出为静态文件（next.config.js 里设 output: "export"，构建，把 out 复制成 static），让 Python API 来提供。一个箱子、一个地址，页面就能用相对路径调用 /api/health。前端放在别处时，CORS 是后备方案。

from fastapi import FastAPI from fastapi.middleware.cors import CORSMiddleware from fastapi.staticfiles import StaticFiles app = FastAPI() app.add_middleware(CORSMiddleware, allow_origins=["https://helper.example.com"], allow_methods=["*"], allow_headers=["*"]) @app.get("/api/health") def health(): return {"ok": True} # last, so the API routes above win app.mount("/", StaticFiles(directory="static", html=True), name="site")

Now make it yours现在把它变成你的

Common errors常见错误

• Cannot connect to the Docker daemon: Docker is not running. Fix: start it and retry.
• No module named 'fastapi': requirements.txt is not copied or lacks it. Fix: check the COPY line and rebuild.
• port is already allocated: something uses port 8000. Fix: stop it or use -p 8001:8000.

• Cannot connect to the Docker daemon：Docker 没运行。 解决：启动后重试。
• No module named 'fastapi'：requirements.txt 没复制，或没列出它。 解决：检查 COPY 行并重新构建。
• port is already allocated：8000 端口被占用。 解决：停掉它，或用 -p 8001:8000。

Takeaways要点回顾

• A container is the app plus everything it needs, sealed to run the same everywhere.
• A Dockerfile is the recipe; build makes an image, run starts a container, a registry stores images.
• Use an ignore file and build for your deploy platform.
• Pass env values in; the container does not see your .env.
• Serve a static front end from the API: one box, one address.

• 容器是应用加上它需要的一切，封好后到哪儿运行都一样。
• Dockerfile 是配方；构建得到镜像，运行启动容器，镜像仓库存放镜像。
• 用忽略文件，并按部署平台构建。
• 要把环境变量传进去；容器看不到你的 .env。
• 让 API 提供静态前端：一个箱子，一个地址。
