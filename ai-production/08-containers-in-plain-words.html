Step 1 · A container is a sealed box第 1 步 · 容器就是一个封好的箱子

Learn先学

A container holds your app plus everything it needs to run: the language, the libraries, the settings. Because all of that travels inside the box, it runs the same on your laptop, on Kumar's PC and on the cloud. The cloud only has to know how to run boxes, not how your app wants its Python.

容器里装着你的应用，加上它运行所需的一切：语言环境、库、配置。因为这些都装在箱子里一起走，所以它在你的笔记本、Kumar 的电脑和云上跑起来都是一样的。云只需要知道怎么运行箱子，不用管你的应用想要什么样的 Python。

without a container: your code + (hope the machine has the right Python and libraries) with a container: [ your code + Python + libraries + start command ] ← one sealed box

Step 2 · The Dockerfile is the recipe第 2 步 · Dockerfile 就是配方

Learn先学

You describe the box in a plain text file called a Dockerfile. It is a recipe: start from a base image (someone else's ready-made box that already has Python), copy in your files, install the libraries, and say how to start the app. Because it is a text file, it can be reviewed and rebuilt like any other code. This one assumes a requirements.txt and a server.py that defines app.

你用一个叫 Dockerfile 的纯文本文件来描述这个箱子。它就是配方：从一个基础镜像（base image）开始（别人做好的、已经带 Python 的箱子），复制你的文件，安装库，再写明怎么启动应用。因为它是文本文件，所以可以像其他代码一样被审查、重新构建。这个例子假设你有 requirements.txt，以及一个定义了 app 的 server.py。

FROM python:3.12-slim WORKDIR /app COPY requirements.txt . RUN pip install --no-cache-dir -r requirements.txt COPY . . CMD ["uvicorn", "server:app", "--host", "0.0.0.0", "--port", "8000"]

Step 3 · Build, run, and the registry第 3 步 · 构建、运行与镜像仓库

Learn先学

Install Docker Desktop (the desktop app that gives you the docker command), then check it works with the tiny hello-world image. Build turns your recipe into an image: the finished, sealed box sitting on a shelf. Run starts a container from that image: the box opened and working. One image can run as many containers as you like. A registry is the shelf in the cloud where images are stored, so the cloud can pull them. In the commands below, -t canteen-helper gives the image a name, the last . means "this folder", and -p 8000:8000 connects port 8000 on your laptop to port 8000 inside the box. (A port is a numbered door for network traffic.)

先安装 Docker Desktop（一个提供 docker 命令的桌面应用），再用很小的 hello-world 镜像检查它能不能用。构建（build）把配方变成镜像（image）：做好封好、放在货架上的箱子。运行（run）则从镜像启动一个容器（container）：打开并开始工作的箱子。一个镜像可以同时跑任意多个容器。镜像仓库（registry）就是云上存放镜像的货架，云可以从那里取走镜像。下面的命令里，-t canteen-helper 给镜像起个名字，结尾的 . 表示“当前这个文件夹”，-p 8000:8000 把你笔记本的 8000 端口接到箱子里的 8000 端口上。（端口就是网络流量的一扇编号门。）

docker run hello-world # is the tool working? docker build -t canteen-helper . # recipe → image docker run -p 8000:8000 canteen-helper # image → running container # now open http://localhost:8000 in the browser
$ docker build -t canteen-helper . [+] Building 24.6s (9/9) FINISHED => naming to docker.io/library/canteen-helper $ docker run -p 8000:8000 canteen-helper INFO: Uvicorn running on http://0.0.0.0:8000

Step 4 · Keep the box small and correct第 4 步 · 让箱子又小又对

Learn先学

Three habits save pain. First, an ignore file keeps junk out of the box (COPY . . copies everything it can see). Second, build for the platform you deploy to: a Mac with an Apple chip builds for a different chip type than most cloud servers. Third, a container does not see your .env file unless you hand its values in when you run it.

三个习惯能省很多麻烦。第一，用忽略文件把杂物挡在箱子外面（COPY . . 会复制它看得到的所有东西）。第二，按你要部署的平台来构建：用苹果芯片的 Mac 构建出的镜像，和大多数云服务器的芯片类型不同。第三，容器看不到你的 .env 文件，除非运行时把里面的值传给它。

# .dockerignore (one name per line) node_modules .git .env __pycache__
# build for the chip type of the cloud server, then run with your settings docker build --platform linux/amd64 -t canteen-helper . docker run --env-file .env -p 8000:8000 canteen-helper docker images # check the size, then shrink it once
$ docker images REPOSITORY TAG IMAGE ID SIZE canteen-helper latest 9f2c1d7a3b10 214MB

Step 5 · Make the front end plain files第 5 步 · 把前端变成普通文件

Learn先学

Next.js is a popular tool for building web pages in JavaScript. Until now its front end ran its own server. For one small box we want less: turn it into static files (a static export: ready-made HTML, CSS and JavaScript) and let the Python API serve them. Then the page and the API share one address, so the page can call the API with a relative path like /api/health, no host name. Add CORS too (the browser's rule about which sites may call your API) so a front end hosted elsewhere keeps working. In next.config.js, set output: "export", build, and copy the out folder to static. The sign-in service also needs to know the new address; the project lesson at the end of this topic covers that.

Next.js 是一个用 JavaScript 做网页的流行工具。到现在为止，它的前端一直在跑自己的服务器。对一个小箱子来说，我们想要更简单：把它变成静态文件（静态导出：现成的 HTML、CSS 和 JavaScript），让 Python API 来提供它们。这样页面和 API 共用一个地址，页面就能用像 /api/health 这样的相对路径调用 API，不用写主机名。再加上 CORS（浏览器关于“哪些网站可以调用你的 API”的规则），这样放在别处的前端也能继续用。在 next.config.js 里设置 output: "export"，构建，再把 out 文件夹复制成 static。登录服务也要知道新地址，本主题最后的项目课会讲。

# next.config.js: module.exports = { output: "export" }; # then: npm run build and copy the "out" folder to "static"
from fastapi import FastAPI from fastapi.middleware.cors import CORSMiddleware from fastapi.staticfiles import StaticFiles app = FastAPI() app.add_middleware(CORSMiddleware, allow_origins=["https://helper.example.com"], allow_methods=["*"], allow_headers=["*"]) @app.get("/api/health") def health(): return {"ok": True} # last, so the API routes above win app.mount("/", StaticFiles(directory="static", html=True), name="site")
What I got wrong我犯过的错Three slips. My first image was huge because I copied everything, so now I use an ignore file and a small base image. I built on a Mac and ran the image on a different chip type, so build for the platform you deploy to. And I forgot that the container cannot see my env file unless I pass it in.三个失误。我的第一个镜像特别大，因为我把所有东西都复制进去了，现在我会用忽略文件和小的基础镜像。我在 Mac 上构建，却在另一种芯片类型上运行，所以要按部署的平台来构建。我还忘了容器看不到我的 env 文件，除非我把值传进去。

Common errors常见错误

• Cannot connect to the Docker daemon Docker Desktop (or the Docker service) is not running. Fix: Start Docker, wait for it to say running, then repeat the command.
• ModuleNotFoundError: No module named 'fastapi' requirements.txt was not copied or does not list it. Fix: Check the COPY requirements.txt . line and the file contents, then rebuild.
• port is already allocated Another program already uses port 8000. Fix: Stop it, or map another port: -p 8001:8000.

• Cannot connect to the Docker daemon Docker Desktop（或 Docker 服务）没有运行。 解决：启动 Docker，等它显示运行中，再重复命令。
• ModuleNotFoundError: No module named 'fastapi' requirements.txt 没复制进去，或没列出它。 解决：检查 COPY requirements.txt . 这一行和文件内容，然后重新构建。
• port is already allocated 别的程序已经占用了 8000 端口。 解决：停掉它，或换端口：-p 8001:8000。

Takeaways要点回顾

• A container is the app plus everything it needs, sealed in one box that runs the same everywhere.
• A Dockerfile is the recipe: base image, copy files, install, start command.
• Build makes an image; run starts a container; a registry stores images.
• Use an ignore file, a small base image, and build for your deploy platform.
• A container does not see your env file unless you pass the values in.
• Serve a static front end from the API so both share one address.
• The recipe is code too, so it can be reviewed and rebuilt.

• 容器就是应用加上它所需的一切，封在一个箱子里，到哪儿运行都一样。
• Dockerfile 是配方：基础镜像、复制文件、安装、启动命令。
• 构建得到镜像，运行启动容器，镜像仓库存放镜像。
• 用忽略文件、小的基础镜像，并按部署平台来构建。
• 容器看不到你的 env 文件，除非你把值传进去。
• 让 API 提供静态前端，两者共用一个地址。
• 配方本身也是代码，所以可以被审查、重新构建。
