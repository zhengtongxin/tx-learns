Managed service vs vendor API托管服务与厂商 API

Swap the twin's brain from a vendor's API to the cloud account's own model service, and know what changes · ~30 min · hands-on把分身的“大脑”从厂商的 API 换成云账号自带的模型服务，并看清哪些东西会变 · 约 30 分钟 · 动手实践

Step 1 · Managed service vs vendor API第 1 步 · 托管服务与厂商 API

Learn先学

A vendor API is a model company's website, called with its secret key. A managed model service (here Amazon Bedrock on AWS) offers many companies' models inside your own cloud account:

厂商 API是模型公司自己的网站，用它给的密钥调用。托管模型服务（这里是 AWS 的 Amazon Bedrock）则在你自己的云账号里提供许多公司的模型：

• no servers to run, pay per request
• requests stay in the region you pick
• your function calls it with its role (its own identity and permissions), so no vendor key to store

• 不用运行服务器，按请求付费
• 请求留在你选的区域
• 函数用它自己的角色（独立的身份和权限）调用，不用存厂商密钥

vendor API: function ──(vendor key)──► vendor's servers own invoice, own key managed: function ──(its role)────► model service in YOUR account same invoice, same rules

Step 2 · Change the code第 2 步 · 改代码

Learn先学

Three things change: a runtime client for one region, a model id that exists in that region, and a new message shape. The system prompt gets its own field, each message holds content blocks, and the answer sits under output → message → content. Messages must alternate between user and assistant. Install with pip install boto3.

要改三处：一个区域的运行时客户端、一个在该区域存在的模型 id，以及新的消息格式。系统提示有自己的字段，每条消息装内容块，答案在 output → message → content 下。消息必须在用户和助手之间交替。用 pip install boto3 安装。

import os import boto3 client = boto3.client("bedrock-runtime", region_name=os.environ.get("AWS_REGION", "ap-southeast-1")) MODEL_ID = os.environ.get("MODEL_ID", "apac.amazon.nova-lite-v1:0") def ask_managed(system_prompt: str, history: list, user_text: str) -> str: messages = history + [{"role": "user", "content": [{"text": user_text}]}] resp = client.converse( modelId=MODEL_ID, system=[{"text": system_prompt}], messages=messages, inferenceConfig={"maxTokens": 300}, ) return resp["output"]["message"]["content"][0]["text"]

Step 3 · Permissions: two doors, and the function's role第 3 步 · 权限：两扇门和函数的角色

Learn先学

Calling a model needs a permission (a JSON policy: Effect, Action, Resource) and a one-time access request per model in the console. The deployed function runs as its own role, so attach the policy to that role, not only to your user. Keep it narrow. A model id with a regional prefix such as apac. is an inference profile, so allow both addresses.

调用模型需要一份权限（JSON 策略：Effect、Action、Resource），以及在控制台里对每个模型做一次访问申请。部署后的函数以自己的角色运行，所以策略要加在这个角色上，而不只是你的用户。范围要窄。带 apac. 这类区域前缀的模型 id 是推理配置文件，两个地址都要允许。

{"Effect": "Allow", "Action": "bedrock:InvokeModel", "Resource": [ "arn:aws:bedrock:*::foundation-model/amazon.nova-*", "arn:aws:bedrock:*:*:inference-profile/*.amazon.nova-*"]}

Now make it yours现在把它变成你的

What I got wrong我犯过的错I gave my user permission but forgot the function's role needs it too, and the model id did not match the region.我给了自己的用户权限，却忘了函数的角色也需要，而且模型 id 和区域对不上。

Common errors常见错误

• AccessDeniedException Model access was not requested in this region, or the role lacks bedrock:InvokeModel. Fix: Request the model for that region and add the action to the role.
• Invalid model identifier Wrong id or missing regional prefix. Fix: Copy the id from the console list into MODEL_ID.
• A conversation must start with a user message The history starts with the assistant, repeats a role or holds a system line. Fix: Keep only alternating user and assistant messages, starting with the user.

• AccessDeniedException 没有在这个区域申请模型，或角色缺少 bedrock:InvokeModel。 解决：在该区域申请模型，并给角色加上这个操作。
• Invalid model identifier id 写错或缺区域前缀。 解决：从控制台列表复制 id 到 MODEL_ID。
• A conversation must start with a user message 历史以助手开头、角色重复或含 system 行。 解决：只保留以用户开头、交替出现的 user 和 assistant 消息。

Takeaways要点回顾

• A managed model service puts many vendors' models behind one API in your own account.
• The function calls it with its role: no vendor key, one invoice.
• Permission to call and access to each model are two separate switches.
• Model id and region must match; messages alternate, with the system prompt in its own field.
• Attach the policy to the function's role, not just your user.

• 托管模型服务在你自己的账号里，用一个 API 提供许多厂商的模型。
• 函数用角色调用：没有厂商密钥，只有一张发票。
• 调用权限和每个模型的访问权是两个独立的开关。
• 模型 id 和区域要对得上；消息交替出现，系统提示放在自己的字段里。
• 策略要加在函数的角色上，而不只是你的用户。
