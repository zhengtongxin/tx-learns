Subscriptions and gating a feature订阅与功能开关

Let only paying users into the main feature, using the billing you already have · ~25 min · hands-on用现成的计费功能，只让付费用户使用主要功能 · 约 25 分钟 · 动手实践

Where we left off上回讲到

Last time the product let signed-in visitors reach the model. Today Mr Ong points out that a free sign-in is still a free ride on the model bill. We fix it with a small monthly plan from the same sign-in service, checked on the server.

上回产品让已登录的访客用上了模型。今天 Ong 先生指出，免费登录仍然是在白用模型额度。我们的办法是用同一个登录服务提供一个小额月度套餐，并在服务器上检查。

The story故事

Sign-in is working, but Mr Ong still has a point: a free tour of the canteen helper is fine, a free ride on the model bill is not. He wants the main feature behind a small monthly plan. Mei Ling does not want to build a payment system either, and the sign-in service she already uses has billing built in.

登录已经能用了，但 Ong 主管还是有道理：免费参观食堂助手没问题，白嫖模型账单就不行。他想把主要功能放在一个小额月度套餐后面。Mei Ling 也不想自己做支付系统，好在她用的登录服务自带计费。

Step 1 · A plan is a gate with a slug第 1 步 · 套餐就是带 slug 的一道门

Learn先学

Turn on billing in the service's dashboard and create one plan: a name, a monthly price and a short feature list. The dashboard gives the plan a slug (a short name for the plan). Copy it exactly (the long internal id is a different value). Your code never says "this user paid". It asks "is this user on plan that slug?". Think of a gate that opens for one particular pass colour.

在服务后台打开计费，创建一个套餐（plan）：名字、月价和一小段功能列表。后台会给这个套餐一个 slug（套餐的简短名字），要原样复制。你的代码从不说“这个用户付了钱”，而是问“这个用户在不在那个 slug 的套餐上？”。就像一道只对某种颜色通行证开放的门。

Step 2 · Show the price第 2 步 · 展示价格

Learn先学

The service gives you a ready-made pricing table component. Drop it on the landing page and it lists your plan. When someone clicks to subscribe, the service shows its own payment form, so card numbers never touch your code. That is the point of hiring it.

服务提供一个现成的定价表组件。放到落地页上，它就会列出你的套餐。有人点击订阅时，由服务展示它自己的支付表单，所以银行卡号根本不会经过你的代码。这正是用它的意义。

import { PricingTable } from "@clerk/nextjs"; // on the landing page <PricingTable />

Step 3 · Gate the product page第 3 步 · 给产品页加一道门

Learn先学

A protect component wraps the product. It shows its content only to people on the plan. Everyone else sees the fallback you give it, here the pricing table. So signed-in free users land on a page that politely asks them to subscribe. In the code, wharf_pro is a placeholder: use the plan slug you copied in step 1.

保护（protect）组件把产品包起来，只对在这个套餐上的人显示内容，其他人看到你给它的后备内容（fallback），这里就是定价表。于是已登录的免费用户会看到一个礼貌地请他们订阅的页面。代码里的 wharf_pro 只是占位，要换成你在第 1 步复制的套餐 slug。

import { Protect, PricingTable } from "@clerk/nextjs"; <Protect plan="wharf_pro" fallback={<PricingTable />}> ...the canteen helper goes here... </Protect>

Step 4 · Try the whole flow with fake money第 4 步 · 用假钱试一遍完整流程

Learn先学

Services have a test mode: payments are pretend, and the service's docs list a test card number that always works. Walk the path as a customer: sign in, see the pricing table, pay with the test card, watch the gate open. Then find where a subscription can be managed or cancelled, because customers will look for it.

服务都有测试模式：付款是假的，文档里会给出一个总能成功的测试卡号码。以顾客的身份走一遍：登录、看到定价表、用测试卡付款、看着门打开。然后找到可以管理或取消订阅的地方，因为顾客一定会去找。

1. sign in → pricing table (gate closed) 2. pay, test card → gate opens, product shows 3. manage / cancel → find the button, try it

Step 5 · The gate only hides the screen第 5 步 · 这道门只是藏起了屏幕

Learn先学

Here is the trap. The Protect component hides content in the browser. A free user can still call your API directly with their own valid sign-in token. If the feature must be paid-only, the server needs its own check. The verified token carries the user's plan in a field named pla. If your token uses another name, check the service's token settings. So read it there, and refuse the call with status 402 (the web code for "payment needed") when the plan is missing. Hiding a button is not security.

这里有个陷阱。Protect 组件只在浏览器里把内容藏起来。免费用户仍然可以带着自己有效的登录令牌，直接调用你的 API。如果功能必须只对付费用户开放，服务器就得有自己的检查。已验证的令牌里带着用户的套餐，字段名叫 pla。如果你的令牌用的是别的名字，就去服务的令牌设置里查。所以要在服务器上读出它，没有套餐时用状态码 402（网页里“需要付款”的代码）拒绝调用。藏起一个按钮不是安全措施。

import os from fastapi import Depends, FastAPI, HTTPException from fastapi_clerk_auth import ClerkConfig, ClerkHTTPBearer, HTTPAuthorizationCredentials app = FastAPI() guard = ClerkHTTPBearer(ClerkConfig(jwks_url=os.environ["CLERK_JWKS_URL"])) @app.get("/api") def hello(creds: HTTPAuthorizationCredentials = Depends(guard)): plan = creds.decoded.get("pla", "") # the user's plan, inside the verified token if "wharf_pro" not in plan: raise HTTPException(status_code=402, detail="Subscription needed") return {"message": "Welcome, subscriber"}
What I got wrong我犯过的错"Plan not found". I used the wrong plan slug. Then I always saw the pricing table, even after subscribing, because the slug in the gate did not match the one I bought. And I forgot that the gate only hides the screen: if the feature must be paid-only, the API needs its own check.“Plan not found”。我用错了套餐 slug。后来订阅之后我依然只看到定价表，因为门里的 slug 和我买的不一致。我还忘了这道门只是藏起了屏幕：如果功能必须只对付费用户开放，API 就得有自己的检查。

Now make it yours现在把它变成你的

What changed这一课之后Now the main feature sits behind a small plan: the pricing table is the sign, and the API check is Sergeant Lee reading the berth booking at the gate. The next problem is that the product only chats, so the plan has nothing real to sell: it needs a job, like the clinic nurse's evening notes.现在主要功能放在一个小套餐后面：价格表是牌子，接口里的检查则是 Lee 警官在闸口核对泊位预订。下一个问题是产品只会聊天，套餐没有什么真正的东西可卖：它需要一份工作，比如诊所护士每晚要写的记录。

Takeaways要点回顾

• Billing is a gate with a plan slug. The code checks the slug, not the name.
• The service hosts the pricing table and the payment form, so you never touch card numbers.
• A protect component shows content only to the plan, and a fallback to everyone else.
• Use test mode and a test card to walk the whole flow, including cancelling.
• A wrong plan slug gives "plan not found", or a gate that never opens.
• Hiding a button is not security. Check the plan on the server too.

• 计费就是一道带套餐 slug 的门，代码检查的是 slug，不是名字。
• 定价表和支付表单由服务托管，你不用接触银行卡号。
• 保护组件只对该套餐显示内容，其他人看到后备内容。
• 用测试模式和测试卡走完整个流程，包括取消。
• 套餐 slug 错了，会出现 “plan not found”，或者门永远不开。
• 藏起按钮不是安全措施，服务器上也要检查套餐。
