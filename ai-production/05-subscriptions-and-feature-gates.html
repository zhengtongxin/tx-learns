Users, sign-in and money · Lesson 2用户、登录与收费 · 第 2 课

Subscriptions and feature gates订阅与功能开关

Let only paying users into the main feature, using the billing you already have · ~25 min · hands-on用现成的计费功能，只让付费用户使用主要功能 · 约 25 分钟 · 动手实践

Step 1 · A plan is a slug第 1 步 · 套餐就是一个 slug

Learn先学
  • Sign-in is not payment. Turn on billing in the same service and create a plan: name, monthly price, feature list.
  • The dashboard gives it a slug. Copy it exactly. Your code never asks "did this user pay?", only "is this user on plan that slug?".
  • The service hosts the pricing table and payment form, so card numbers never touch your code. Use its test mode and test card to try the flow.
  • 登录不等于付费。在同一个服务里开启计费，创建一个套餐：名字、月价、功能列表。
  • 后台会给它一个 slug，要原样复制。你的代码从不问“这个用户付钱了吗”，只问“这个用户在不在那个 slug 的套餐上”。
  • 定价表和支付表单由服务托管，银行卡号不会经过你的代码。用它的测试模式和测试卡试一遍流程。

Step 2 · Gate the page第 2 步 · 给页面加门

Learn先学

Protect shows its content only to people on the plan; everyone else sees the fallback, here the ready-made pricing table. Replace pro_plan with the slug you copied.

Protect 只对该套餐上的人显示内容，其他人看到后备内容，这里是现成的定价表。把 pro_plan 换成你复制的 slug。

import { Protect, PricingTable } from "@clerk/nextjs"; <Protect plan="pro_plan" fallback={<PricingTable />}> ...the product goes here... </Protect>

Step 3 · Check the plan on the server第 3 步 · 在服务器上查套餐

Learn先学
  • Protect only hides content in the browser. A free user can still call your API with their own valid token.
  • The verified token lists the user's plans in a field named pla (check the service's token settings if yours differs), such as "u:pro_plan".
  • Read it on the server and refuse with 402 ("payment needed") when the plan is missing. Hiding a button is not security.
  • Protect 只在浏览器里藏内容。免费用户仍可带着自己有效的令牌直接调用 API。
  • 已验证的令牌里，用户的套餐列在名为 pla 的字段中（若不同，查服务的令牌设置），例如 "u:pro_plan"。
  • 在服务器上读它，没有套餐就用 402（“需要付款”）拒绝。藏起按钮不是安全措施。
import os from fastapi import Depends, FastAPI, HTTPException from fastapi_clerk_auth import ClerkConfig, ClerkHTTPBearer, HTTPAuthorizationCredentials app = FastAPI() guard = ClerkHTTPBearer(ClerkConfig(jwks_url=os.environ["CLERK_JWKS_URL"])) @app.get("/api") def hello(creds: HTTPAuthorizationCredentials = Depends(guard)): plan = creds.decoded.get("pla", "") # the user's plan, inside the verified token if "pro_plan" not in plan: raise HTTPException(status_code=402, detail="Subscription needed") return {"message": "Welcome, subscriber"}

Now make it yours现在把它变成你的

Common errors常见错误

• 402 Payment Required: the user has no such plan. Fix: subscribe with the test card, then sign out and in so a fresh token carries the plan.
• Empty pricing table, or "plan not found": billing is off, or the slug is wrong. Fix: turn billing on and copy the slug again.

• 402 Payment Required：用户没有该套餐。 解决：用测试卡订阅，然后退出再登录，让新令牌带上套餐。
• 定价表为空，或 “plan not found”：没开计费，或 slug 写错。 解决：开启计费并重新复制 slug。

Takeaways要点回顾

• Billing is a gate with a plan slug; code checks the slug, not the name.
• The service hosts the pricing table and payment form.
• Protect shows content to the plan and a fallback to everyone else.
• Hiding a button is not security: check the plan on the server before the model call.

• 计费就是一道带套餐 slug 的门，代码检查 slug，不是名字。
• 定价表和支付表单由服务托管。
• Protect 对该套餐显示内容，其他人看到后备内容。
• 藏起按钮不是安全措施：调用模型前要在服务器上查套餐。
