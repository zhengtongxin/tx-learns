Step 1 · A form with three fields第 1 步 · 一张三个字段的表单

Learn先学

Structured input gives you predictable output. The form has a patient name, a visit date and free-text notes. For the date, use a real date picker (type="date"). It always produces the format 2026-11-23, called ISO format (year, month, day), which every system understands. Each value and onChange pair keeps the box and its variable in step: the variable always holds what the box shows. Mark all three fields required.

结构化的输入才有可预测的输出。表单有病人姓名、就诊日期和自由文本的笔记。日期要用真正的日期选择器（type="date"），它总是给出 2026-11-23 这样的格式，叫 ISO 格式（年-月-日），所有系统都认识。每一对 value 和 onChange 让输入框和变量保持一致：变量里总是输入框当前显示的内容。三个字段都标上 required。

const [patientName, setPatientName] = useState(""); const [visitDate, setVisitDate] = useState(""); const [notes, setNotes] = useState(""); const [output, setOutput] = useState(""); <input required value={patientName} onChange={(e) => setPatientName(e.target.value)} /> <input required type="date" value={visitDate} onChange={(e) => setVisitDate(e.target.value)} /> <textarea required value={notes} onChange={(e) => setNotes(e.target.value)} />

Step 2 · A checked request: Pydantic and POST第 2 步 · 带检查的请求：Pydantic 与 POST

Learn先学

A Pydantic model describes the data you expect, and FastAPI rejects anything that does not fit before your code runs. Declare visit_date as a date and a bad one gets refused automatically. Use POST, not GET. A GET carries its data in the address. A POST carries it in the request body, the part of the message the address bar never shows. Notes in the address would end up in logs and histories. A route only answers the method it was written for.

Pydantic 模型描述你期望的数据，FastAPI 会在你的代码运行之前就拒绝不合格的数据。把 visit_date 声明成 date，格式不对就会被自动拒绝。要用 POST 而不是 GET。GET 把数据放在地址里；POST 把数据放在请求体（request body）里，那是地址栏从不显示的部分。笔记如果放在地址里，就会留在日志和浏览历史里。一个路由只回应它被写成的那种请求方法。

Step 3 · One prompt, three outputs第 3 步 · 一个提示词，三份输出

Learn先学

A model gives dependable output when you tell it the exact shape. A system prompt is the standing instruction the model reads before every request (its role is system; the nurse's notes arrive separately, as the user message). This one asks for the same three sections every time, written for three different readers. Using headings means the page can show them neatly later, and the nurse always knows where to look.

你把确切的格式告诉模型，它的输出才可靠。系统提示词（system prompt）是模型在每次请求前都会先读的固定指令（角色是 system；护士的笔记则作为 user 消息单独送来）。这份提示词每次都要求同样的三个部分，分别写给三类不同的读者。用标题来分隔，页面之后就能整齐地显示，护士也总知道该看哪里。

SYSTEM_PROMPT = """You help a clinic nurse write up a visit. Use only facts that are in the notes. If something is missing, say so. Answer in markdown with exactly these three sections: ## Summary for the records Short, factual, for the file. ## Next steps for the nurse A checklist of follow-ups. ## Email to the patient Friendly, plain language, no jargon."""

Step 4 · Stream it, gate it, keep the sign-in第 4 步 · 流式输出，加上门，保留登录

Learn先学

Now join everything from before. The API verifies the sign-in token, checks the plan, then streams the model's reply. This route is a POST, and the browser's EventSource only does GET and cannot send headers. So the page uses fetch and reads the body piece by piece, and the server sends plain text, with no data: lines. getReader() hands over the bytes as they arrive, and TextDecoder turns the bytes back into text. Show the result with the markdown renderer from the streaming lesson.

现在把之前学的全部接起来。API 先验证登录令牌，再检查套餐，然后流式输出模型的回复。这个路由是 POST，而浏览器的 EventSource 只能发 GET、也不能带请求头。所以页面改用 fetch，一块一块地读响应体，服务器发的就是纯文本，不需要 data: 行。getReader() 按到达顺序交出字节，TextDecoder 再把字节转回文字。结果用流式输出那一课里的 markdown 渲染器来显示。

# api/index.py import os from datetime import date from fastapi import Depends, FastAPI, HTTPException from fastapi.responses import StreamingResponse from fastapi_clerk_auth import ClerkConfig, ClerkHTTPBearer, HTTPAuthorizationCredentials from openai import OpenAI from pydantic import BaseModel, Field app = FastAPI() client = OpenAI() guard = ClerkHTTPBearer(ClerkConfig(jwks_url=os.environ["CLERK_JWKS_URL"])) # SYSTEM_PROMPT and class Visit from the last two steps go here @app.post("/api/consultation") def consultation(visit: Visit, creds: HTTPAuthorizationCredentials = Depends(guard)): if "wharf_pro" not in creds.decoded.get("pla", ""): raise HTTPException(status_code=402, detail="Subscription needed") user_note = f"Patient: {visit.patient_name}\nDate: {visit.visit_date}\nNotes: {visit.notes}" def generate(): stream = client.chat.completions.create( model="gpt-5.4-mini", stream=True, messages=[{"role": "system", "content": SYSTEM_PROMPT}, {"role": "user", "content": user_note}]) for chunk in stream: piece = chunk.choices[0].delta.content if piece: yield piece return StreamingResponse(generate(), media_type="text/plain")
// page: send, then read the stream (inside an async submit function) const { getToken } = useAuth(); // from @clerk/nextjs, as before async function submit() { const token = await getToken(); const res = await fetch("/api/consultation", { method: "POST", headers: { "Content-Type": "application/json", Authorization: "Bearer " + token }, body: JSON.stringify({ patient_name: patientName, visit_date: visitDate, notes }), }); if (!res.ok) { setOutput("Error " + res.status); return; } // 401: sign in, 402: plan needed const reader = res.body.getReader(); const decoder = new TextDecoder(); let text = ""; while (true) { const { done, value } = await reader.read(); if (done) break; text += decoder.decode(value, { stream: true }); // stream: true keeps half a Chinese character until the next chunk setOutput(text); } }

Step 6 · What a demo must not hold第 6 步 · 演示不能装什么

Learn先学

This works, and it is tempting to call it safe. It is not. It was built to learn, so real patient data must not go into it. Real use needs privacy-law compliance (following the data-protection rules of the country where the patients live, as checked by its regulator), encryption, audit logs (a record of who looked at what), access roles (who may see which records) and consent. Saying clearly what a demo is not allowed to hold is part of the job.

它能跑，所以很容易觉得它安全。其实不然：它是为了学习而做的，所以绝不能放真实的病人数据。真实使用需要符合隐私法规（遵守病人所在国家的数据保护规则，由该国监管机构检查）、加密、审计日志（记录谁看过什么）、访问角色（谁能看哪些记录）和知情同意。把“演示不能装什么”说清楚，本身就是工作的一部分。

What I got wrong我犯过的错Three mistakes. "Method not allowed": the route was still GET. I typed the date by hand into a plain text box and it went in the wrong format, so now I use the date picker and send ISO dates. And I treated the demo as safe for real patient data. It is not: real use needs privacy-law compliance, encryption, audit logs, access roles and consent.三个错误。“Method not allowed”：路由还是 GET。我曾在普通文本框里手敲日期，格式发错了，所以现在用日期选择器并发 ISO 日期。还有，我曾把这个演示当成可以放真实病人数据的东西。其实不行：真实使用需要隐私法规合规、加密、审计日志、访问角色和知情同意。

Common errors常见错误

• 422 Unprocessable Entity The form data does not match the Visit model (a missing field or a bad date). Fix: Send visit_date as YYYY-MM-DD and check the three field names.
• NameError: name 'SYSTEM_PROMPT' is not defined The comment line was left in place of the real prompt. Fix: Paste SYSTEM_PROMPT and class Visit above the route.
• TypeError: Cannot read properties of null (reading 'getReader') The request failed, so res.body is empty. Fix: Check res.ok first and show the status (401, 402, 422).

• 422 Unprocessable Entity 表单数据和 Visit 模型对不上（缺字段或日期格式不对）。 解决：把 visit_date 写成 YYYY-MM-DD，并核对三个字段名。
• NameError: name 'SYSTEM_PROMPT' is not defined 把真正的提示词换成了注释行，没有粘贴进来。 解决：把 SYSTEM_PROMPT 和 class Visit 粘贴到路由上方。
• TypeError: Cannot read properties of null (reading 'getReader') 请求失败了，所以 res.body 是空的。 解决：先检查 res.ok，并显示状态码（401、402、422）。

Takeaways要点回顾

• Structured input plus a structured prompt gives dependable output.
• A Pydantic model rejects bad requests before your code runs. Send ISO dates.
• Data in the body means POST, not GET.
• For a POST stream with a token, use fetch and read the body, not EventSource.
• The server keeps the sign-in check and the plan check, whatever the page hides.
• Walk the full path in a preview: sign in, subscribe, submit, read.
• Say clearly what a demo is not allowed to hold. Real patient data needs real safeguards.

• 结构化的输入加结构化的提示词，输出才可靠。
• Pydantic 模型在你的代码运行前就拒绝坏请求。日期要发 ISO 格式。
• 数据在请求体里，就用 POST，不用 GET。
• 要带令牌的 POST 流，用 fetch 读响应体，而不是 EventSource。
• 不管页面藏了什么，服务器都要保留登录检查和套餐检查。
• 在预览环境里把整条路走一遍：登录、订阅、提交、阅读。
• 说清楚演示不能装什么。真实病人数据需要真正的保障措施。
