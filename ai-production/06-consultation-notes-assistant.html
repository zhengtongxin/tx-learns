Turn the product into something a professional would use: one form, three tidy outputs · ~40 min · project把产品变成专业人士会用的东西：一张表单，三份整齐的输出 · 约 40 分钟 · 项目

Step 1 · A checked request第 1 步 · 带检查的请求

Learn先学
  • Structured input gives predictable output. The form has a name, a visit date and free-text notes, all required.
  • Use a real date picker (type="date"): it sends ISO format, 2026-11-23.
  • A Pydantic model describes the data you expect. A route asks for it by taking it as a parameter (def consultation(visit: Visit) in Step 3), and FastAPI then rejects anything else before your code runs.
  • Use POST: the data travels in the request body, not the address, so notes stay out of logs and histories.
  • 结构化的输入才有可预测的输出。表单有姓名、就诊日期和自由文本笔记，全部 required。
  • 用真正的日期选择器（type="date"）：它发出 ISO 格式，如 2026-11-23。
  • Pydantic 模型描述你期望的数据。路由把它当作参数接收（第 3 步里的 def consultation(visit: Visit)），FastAPI 就会在你的代码运行前拒绝其他数据。
  • 用 POST：数据放在请求体而不是地址里，笔记不会留在日志和浏览历史中。
const [patientName, setPatientName] = useState(""); const [visitDate, setVisitDate] = useState(""); const [notes, setNotes] = useState(""); <input required value={patientName} onChange={(e) => setPatientName(e.target.value)} /> <input required type="date" value={visitDate} onChange={(e) => setVisitDate(e.target.value)} /> <textarea required value={notes} onChange={(e) => setNotes(e.target.value)} />

Step 2 · One prompt, three outputs第 2 步 · 一个提示词，三份输出

Learn先学

Tell the model the exact shape. A system prompt is the standing instruction it reads before every request; the notes arrive separately as the user message. Three headed sections, one per reader, mean the page can show them neatly.

把确切的格式告诉模型。系统提示词是它在每次请求前读的固定指令；笔记则作为 user 消息单独送来。三个带标题的部分，每个对应一类读者，页面就能整齐地显示。

SYSTEM_PROMPT = """You help a clinic nurse write up a visit. Use only facts that are in the notes. If something is missing, say so. Answer in markdown with exactly these three sections: ## Summary for the records Short, factual, for the file. ## Next steps for the nurse A checklist of follow-ups. ## Email to the patient Friendly, plain language, no jargon."""

Step 3 · Stream it behind the gate第 3 步 · 在门后流式输出

Learn先学
  • The route verifies the token, checks the plan, then streams the reply.
  • A POST with a token cannot use EventSource, the browser's simplest tool for reading a stream (GET only, no headers). The page uses fetch and reads the body piece by piece; the server sends plain text. The comments in the second box explain each line of that reading loop.
  • The server keeps the plan check whatever the page hides.
  • 路由先验证令牌、检查套餐，再流式输出回复。
  • 带令牌的 POST 不能用 EventSource（浏览器里读取流最简单的工具，但只能 GET、不能带头）。页面改用 fetch，一块一块读响应体；服务器发纯文本。第二个代码框里的注释逐行解释了这个读取循环。
  • 不管页面藏了什么，服务器都保留套餐检查。
# api/index.py (SYSTEM_PROMPT and Visit from above go here) import os from fastapi import Depends, FastAPI, HTTPException from fastapi.responses import StreamingResponse from fastapi_clerk_auth import ClerkConfig, ClerkHTTPBearer, HTTPAuthorizationCredentials from openai import OpenAI app = FastAPI() client = OpenAI() guard = ClerkHTTPBearer(ClerkConfig(jwks_url=os.environ["CLERK_JWKS_URL"])) @app.post("/api/consultation") def consultation(visit: Visit, creds: HTTPAuthorizationCredentials = Depends(guard)): if "pro_plan" not in creds.decoded.get("pla", ""): # the sign-in token lists the user's plan under "pla"; pro_plan is the paid plan's name raise HTTPException(status_code=402, detail="Subscription needed") user_note = f"Patient: {visit.patient_name}\nDate: {visit.visit_date}\nNotes: {visit.notes}" def generate(): stream = client.chat.completions.create( model="gpt-5.4-mini", stream=True, messages=[{"role": "system", "content": SYSTEM_PROMPT}, {"role": "user", "content": user_note}]) for chunk in stream: piece = chunk.choices[0].delta.content if piece: yield piece return StreamingResponse(generate(), media_type="text/plain")
const [output, setOutput] = useState(""); // the text shown under the form const { getToken } = useAuth(); // from the sign-in library: the signed-in user's token async function submit(e) { // the form calls it: <form onSubmit={submit}> e.preventDefault(); // stop the browser reloading the page const token = await getToken(); const res = await fetch("/api/consultation", { method: "POST", headers: { "Content-Type": "application/json", Authorization: "Bearer " + token }, body: JSON.stringify({ patient_name: patientName, visit_date: visitDate, notes }), }); if (!res.ok) { setOutput("Error " + res.status); return; } // 401: sign in, 402: plan needed const reader = res.body.getReader(); // the reply arrives in pieces: a reader hands them over one by one const decoder = new TextDecoder(); // pieces are raw bytes: this turns them into text let text = ""; while (true) { // keep reading until the server says it is finished const { done, value } = await reader.read(); if (done) break; text += decoder.decode(value, { stream: true }); // stream: a character may be split across two pieces setOutput(text); // redraw with everything received so far } }

Step 4 · What a demo must not hold第 4 步 · 演示不能装什么

Learn先学

This was built to learn, so no real patient data goes in. Real use needs privacy-law compliance, encryption, audit logs, access roles and consent. Say clearly what a demo may not hold.

它是为学习而做的，所以不能放真实病人数据。真实使用需要隐私法规合规、加密、审计日志、访问角色和知情同意。要说清楚演示不能装什么。

Common errors常见错误

• 422 Unprocessable Entity: the data does not match Visit. Fix: send visit_date as YYYY-MM-DD and check field names.
• 405 Method Not Allowed: the route is still @app.get. Fix: use @app.post.
• Cannot read properties of null (reading 'getReader'): the request failed. Fix: check res.ok first.

• 422 Unprocessable Entity：数据和 Visit 对不上。 解决：把 visit_date 写成 YYYY-MM-DD，并核对字段名。
• 405 Method Not Allowed：路由还是 @app.get。 解决：改用 @app.post。
• Cannot read properties of null (reading 'getReader')：请求失败了。 解决：先检查 res.ok。

Takeaways要点回顾

• Structured input plus a structured prompt gives dependable output.
• A Pydantic model rejects bad requests early; send ISO dates.
• Data in the body means POST.
• A POST stream with a token uses fetch, not EventSource.
• A demo must not hold real private data.

• 结构化的输入加结构化的提示词，输出才可靠。
• Pydantic 模型尽早拒绝坏请求；日期发 ISO 格式。
• 数据在请求体里就用 POST。
• 带令牌的 POST 流用 fetch，不用 EventSource。
• 演示不能装真实的私密数据。
