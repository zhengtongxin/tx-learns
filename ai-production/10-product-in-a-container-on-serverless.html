Step 1 · Start from the working product第 1 步 · 从能用的产品开始

Learn先学

Do not change what the product does. Change how it is packed. Turn the front end into a static export (output: "export", then copy the out folder to static), and make the API an ordinary web server that serves those files and listens on all addresses. The sign-in check and the plan check stay exactly as they were.

不要改产品做什么，只改它怎么打包。把前端变成静态导出（output: "export"，再把 out 文件夹复制成 static），让 API 成为一个普通的网页服务器：它提供这些文件，并监听所有地址。登录检查和套餐检查原样保留。

npm run build # static export → "out" folder rm -rf static && cp -r out static # API entry point: server.py with app = FastAPI() and, last: app.mount("/", StaticFiles(directory="static", html=True), name="site") # start command: uvicorn server:app --host 0.0.0.0 --port 8000

Step 2 · Write the Dockerfile, run it locally first第 2 步 · 写 Dockerfile，先在本地跑

Learn先学

Use the recipe from the last two lessons: a slim Python base, your files, the adapter that lets a serverless function run a web app, and the streaming setting. Build it for the platform you will deploy to, then run it on your laptop. A bug is ten times cheaper to find here than in the cloud.

用前两课的配方：精简的 Python 基础镜像、你的文件、让无服务器函数能运行网页应用的适配器，以及流式设置。按要部署的平台构建，然后先在笔记本上运行。在这里找 bug，比在云上便宜十倍。

FROM python:3.12-slim COPY --from=public.ecr.aws/awsguru/aws-lambda-adapter:0.9.1 /lambda-adapter /opt/extensions/lambda-adapter ENV PORT=8000 ENV AWS_LWA_INVOKE_MODE=response_stream WORKDIR /app COPY requirements.txt . RUN pip install --no-cache-dir -r requirements.txt COPY . . CMD ["uvicorn", "server:app", "--host", "0.0.0.0", "--port", "8000"]
# then, in the terminal: docker build --platform linux/amd64 -t canteen-helper . docker run --env-file .env -p 8000:8000 canteen-helper

Step 3 · Create a repository and push the image第 3 步 · 创建仓库并推送镜像

Learn先学

Make a repository in the registry, one per app. Then log your container tool in using a temporary token that the cloud tool prints for your user (it expires, which is the point). Tag the image with the repository's full address, and push. This assumes the cloud command-line tool is installed and signed in as your daily user, with your default region set. In the commands, $(...) runs a command and keeps its answer. aws sts get-caller-identity asks the cloud who you are, and its answer is your account ID. --password-stdin passes the token in without typing it into the command.

在镜像仓库里建一个仓库，一个应用一个。然后用云的命令行工具为你的用户生成的临时令牌让容器工具登录（它会过期，这正是用意）。给镜像打上仓库完整地址的标签（tag），再推送。这里假设云的命令行工具已安装，并用你的日常用户登录，默认区域也设好了。命令里，$(...) 会运行一条命令并保存它的结果。aws sts get-caller-identity 问云你是谁，返回的就是你的账号 ID。--password-stdin 让令牌直接传进去，而不用写在命令里。

REGION=ap-southeast-1 ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text) REGISTRY=$ACCOUNT_ID.dkr.ecr.$REGION.amazonaws.com aws ecr create-repository --repository-name canteen-helper --region $REGION aws ecr get-login-password --region $REGION | docker login --username AWS --password-stdin $REGISTRY docker tag canteen-helper:latest $REGISTRY/canteen-helper:latest docker push $REGISTRY/canteen-helper:latest

Step 4 · Create the function and turn on its URL第 4 步 · 创建函数并打开它的地址

Learn先学

In the console, create a function from the container image you pushed. Set the memory and a generous timeout. Add the environment variables: the model key and the sign-in keys (the sign-in service, Clerk in this code, checks who people are), the same names as in your local .env. Then turn on the function URL with the streaming setting. Copy the address it gives you.

在控制台里，用你推送的容器镜像创建一个函数。设置内存和一个宽裕的超时时间。添加环境变量：模型密钥和登录密钥（登录服务，这段代码里用的是 Clerk，负责检查人是谁），名字和你本地 .env 里的一样。然后用流式设置打开函数地址，把它给出的地址复制下来。

Function: canteen-helper (from image canteen-helper:latest) Memory 512 MB · Timeout 60 s Environment variables: OPENAI_API_KEY, CLERK_SECRET_KEY, CLERK_JWKS_URL, ... (same names as .env) Function URL: auth NONE · invoke mode RESPONSE_STREAM → https://abc123.lambda-url.ap-southeast-1.on.aws/

Step 5 · Tell the sign-in service about the new address第 5 步 · 把新地址告诉登录服务

Learn先学

The sign-in service only lets people come back to addresses it knows. It still lists the old host, so sign-in fails on the new one. Add the function URL to its allowed addresses in its dashboard (and, in the API's CORS settings, if the front end is hosted elsewhere). Then test in order: sign in, subscribe with a test card (a fake card number the payment service accepts only in test mode), ask a question and watch it stream.

登录服务只允许人们回到它认识的地址。它的列表里还是旧主机，所以在新地址上登录会失败。到它的后台把函数地址加进允许的地址里（如果前端放在别处，也要加进 API 的 CORS 设置）。然后按顺序测试：登录、用测试卡（支付服务只在测试模式下接受的假卡号）订阅、提一个问题并看着它流式输出。

Sign-in dashboard → allowed addresses https://old-host.example.com (old) https://abc123.lambda-url.ap-southeast-1.on.aws (new) Test in order: 1 sign in 2 subscribe (test card) 3 ask a question → streams?

Step 6 · Read the logs, then know how to tear it all down第 6 步 · 读日志，并知道怎么全部拆掉

Learn先学

Something will fail, so find the function's log group first (the folder where its logs are kept). Read the newest lines from the bottom: the error is usually in the last few. When you are done experimenting, delete what you made so nothing quietly keeps billing. Confirm the console is clean in each region you used.

总会有东西失败，所以先找到函数的日志组（保存它日志的文件夹）。从最底下读最新的几行：错误通常就在最后几行里。实验结束后，把你建的东西删掉，免得有什么在悄悄计费。确认你用过的每个区域在控制台里都是干净的。

# read the newest log lines aws logs tail /aws/lambda/canteen-helper --since 10m --region $REGION # tear down (this deletes things for good) aws lambda delete-function --function-name canteen-helper --region $REGION aws ecr delete-repository --repository-name canteen-helper --force --region $REGION aws logs delete-log-group --log-group-name /aws/lambda/canteen-helper --region $REGION

Common errors常见错误

• no basic auth credentials The registry login expired or was skipped. Fix: Run the get-login-password line again, then push.
• exec format error The image was built for the wrong chip type. Fix: Build with --platform linux/amd64 and push again.
• Sign-in works locally but fails live The new function address is not in the sign-in allowed addresses. Fix: Add the new address in the sign-in dashboard.

• no basic auth credentials 注册表登录已过期或被跳过。 解决：重新运行 get-login-password 那一行，再推送。
• exec format error 镜像是为错误的芯片类型构建的。 解决：用 --platform linux/amd64 重新构建并推送。
• Sign-in works locally but fails live 新的函数地址没有加入登录服务的允许地址。 解决：在登录服务控制台加入新地址。

Takeaways要点回顾

• Same product, new home: change how it is packed, not what it does.
• Build and run the container locally first, for the platform you deploy to.
• Create a repository, log in with the temporary token, tag, push.
• The function needs the same environment variables as your local file, plus a longer timeout and the streaming URL.
• Add the new address to the sign-in service, or sign-in fails.
• Read the logs from the bottom when it fails.
• Most of the pain is config and addresses. Always have a way to tear it all down.

• 同一个产品，新的家：改的是怎么打包，不是它做什么。
• 先在本地构建并运行容器，并且按部署的平台来构建。
• 创建仓库，用临时令牌登录，打标签，推送。
• 函数需要和本地文件一样的环境变量，外加更长的超时时间和流式地址。
• 把新地址加进登录服务，否则登录会失败。
• 出错时从日志的最底下读起。
• 大部分麻烦出在配置和地址上。永远要有办法把一切拆掉。
