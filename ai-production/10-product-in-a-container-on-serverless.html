Containers on serverless无服务器上的容器

Move the signed-in, paid, streaming product onto your own cloud account: container, registry, serverless function, public address · ~50 min · project把带登录、收费和流式输出的产品整个搬到你自己的云账号上：容器、镜像仓库、无服务器函数、公开地址 · 约 50 分钟 · 项目

Step 1 · Pack it and run it locally第 1 步 · 打包并在本地运行

Learn先学
  • Do not change what the product does, only how it is packed. Export the front end as static files into static and let the API serve them: mounting a folder means “answer any other address with a file from here”, so it goes after the API routes, or it would swallow them.
  • The Dockerfile is the recipe for the container: a slim Python base, your files, the adapter (a small add-on that lets an ordinary web server run as a serverless function) and the streaming setting.
  • In the terminal box, npm run build uses npm, the tool that comes with Node.js, to write the finished pages into out. rm -rf static deletes only the previous copy inside this project folder, and the next command puts the fresh one back.
  • Build for the platform you deploy to and run it on your laptop first. A bug is far cheaper to find here.
  • 不要改产品做什么，只改怎么打包。把前端导出成静态文件放进 static，让 API 来提供：挂载一个文件夹的意思是“其他地址都用这里的文件来回答”，所以要放在 API 路由之后，否则会把它们吞掉。
  • Dockerfile 是容器的配方：精简的 Python 基础镜像、你的文件、适配器（让普通网页服务器能当无服务器函数运行的小插件）和流式设置。
  • 终端代码框里，npm run build 用 npm（随 Node.js 一起安装的工具）把做好的页面写进 out。rm -rf static 只删除这个项目文件夹里的旧副本，下一条命令再把新的放回去。
  • 按要部署的平台构建，并先在笔记本上运行。在这里找 bug 便宜得多。
FROM python:3.12-slim COPY --from=public.ecr.aws/awsguru/aws-lambda-adapter:0.9.1 /lambda-adapter /opt/extensions/lambda-adapter ENV PORT=8000 ENV AWS_LWA_INVOKE_MODE=response_stream WORKDIR /app COPY requirements.txt . RUN pip install --no-cache-dir -r requirements.txt COPY . . CMD ["uvicorn", "server:app", "--host", "0.0.0.0", "--port", "8000"]
npm run build # static export → "out" rm -rf static && cp -r out static docker build --platform linux/amd64 -t canteen-helper . docker run --env-file .env -p 8000:8000 canteen-helper # .env: the same keys the app uses locally (model key, sign-in keys)

Step 2 · Push, create the function, update sign-in第 2 步 · 推送、创建函数、更新登录

Learn先学
  • Make a registry repository, log in with a temporary token, tag the image with the repository address and push. (Assumes the cloud CLI is signed in as your daily user.)
  • Reading the script: $( ) runs a command and drops its output in place, and | feeds one command's output into the next. So the login line asks the cloud for a password that works for 12 hours and hands it straight to docker login; it never shows on screen.
  • Create the function from that image in the cloud console (Lambda, Create function, Container image; the settings are under Configuration): memory, a 60 s timeout, and the same environment variables as your .env. Turn on the function URL with streaming.
  • The sign-in service only lets people return to addresses it knows. Add the new function URL to its allowed addresses, or sign-in fails.
  • 在镜像仓库建一个仓库，用临时令牌登录，给镜像打上仓库地址的标签再推送。（假设云命令行工具已用你的日常用户登录。）
  • 读懂脚本：$( ) 运行一条命令并把输出放在原处，| 把前一条命令的输出交给后一条。所以登录那一行向云端要一个 12 小时有效的密码，直接交给 docker login，不会显示在屏幕上。
  • 在云控制台里用该镜像创建函数（Lambda → Create function → Container image；设置在 Configuration 下）：内存、60 秒超时，以及和 .env 一样的环境变量。开启带流式的函数地址。
  • 登录服务只允许人们回到它认识的地址。把新的函数地址加进它的允许地址，否则登录会失败。
REGION=ap-southeast-1 ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text) REGISTRY=$ACCOUNT_ID.dkr.ecr.$REGION.amazonaws.com aws ecr create-repository --repository-name canteen-helper --region $REGION aws ecr get-login-password --region $REGION | docker login --username AWS --password-stdin $REGISTRY docker tag canteen-helper:latest $REGISTRY/canteen-helper:latest docker push $REGISTRY/canteen-helper:latest

Step 3 · Read the logs, tear it down第 3 步 · 读日志，再拆掉

Learn先学

Read the newest log lines from the bottom: the error is usually in the last few. When done experimenting, delete what you made so nothing quietly keeps billing, and check each region you used.

从最底下读最新的日志行：错误通常就在最后几行。实验结束后，删掉你建的东西，免得有什么悄悄计费，并检查你用过的每个区域。

# read the newest log lines aws logs tail /aws/lambda/canteen-helper --since 10m --region $REGION # tear down (this deletes things for good) aws lambda delete-function --function-name canteen-helper --region $REGION aws ecr delete-repository --repository-name canteen-helper --force --region $REGION aws logs delete-log-group --log-group-name /aws/lambda/canteen-helper --region $REGION # last, the role the console made with the function (its name starts with canteen-helper-role): # in the console open IAM, then Roles, search for canteen-helper and delete it

Now make it yours现在把它变成你的

Common errors常见错误

• no basic auth credentials: registry login expired. Fix: rerun the get-login-password line, then push.
• exec format error: wrong chip type. Fix: build with --platform linux/amd64.
• Sign-in works locally but fails live: the new address is not allowed. Fix: add it in the sign-in dashboard.

• no basic auth credentials：仓库登录已过期。 解决：重新运行 get-login-password 那一行，再推送。
• exec format error：芯片类型不对。 解决：用 --platform linux/amd64 构建。
• 本地能登录、线上不行：新地址没被允许。 解决：在登录服务后台加上它。

Takeaways要点回顾

• Same product, new home: change how it is packed, not what it does.
• Run the container locally first, built for the deploy platform.
• Repository, temporary login, tag, push.
• The function needs the same environment variables, a longer timeout and the streaming URL.
• Tell the sign-in service the new address; always know how to tear it down.

• 同一个产品，新的家：改的是怎么打包，不是它做什么。
• 先在本地运行容器，并按部署平台构建。
• 仓库、临时登录、打标签、推送。
• 函数需要相同的环境变量、更长的超时和流式地址。
• 把新地址告诉登录服务；永远要知道怎么拆掉。
