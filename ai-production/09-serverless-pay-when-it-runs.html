Serverless pay-per-use按用量付费的无服务器

Run the containerised product without owning a server, and pay only for the milliseconds it works · ~25 min · hands-on不用自己养服务器就能运行容器化的产品，只为它干活的那几毫秒付钱 · 约 25 分钟 · 动手实践

Step 1 · Code that runs only on demand第 1 步 · 只在需要时运行的代码

Learn先学
  • Serverless means you do not own or watch a server. A function sits switched off until a request arrives, runs, then sleeps. You pay for the milliseconds it ran.
  • The catch is the cold start: the first call after a quiet spell wakes the box first, a few seconds. Calls right after are quick.
  • 无服务器指你不用拥有或盯着服务器。函数平时是关着的，请求一来就运行，然后休眠。你只为它运行的毫秒付钱。
  • 代价是冷启动：安静一阵后的第一次调用要先唤醒箱子，要几秒。紧接着的调用就很快。

Step 2 · Address, streaming and adapter第 2 步 · 地址、流式与适配器

Learn先学
  • A function URL gives the function its own HTTPS address, no gateway needed.
  • Its default invoke mode is "buffered": the whole answer is sent at the end. For word-by-word streaming, choose RESPONSE_STREAM.
  • A function receives an invocation, not a web request. A small adapter in your container turns each one into a normal request on a local port, so your FastAPI code does not change. It needs the same streaming setting.
  • 函数地址让函数拥有自己的 HTTPS 地址，不需要网关。
  • 默认调用模式是“缓冲”：最后才一次发出整个回答。要逐词流式，选 RESPONSE_STREAM。
  • 函数收到的是调用，不是网页请求。容器里的一个小适配器把每次调用变成本地端口上的普通请求，所以 FastAPI 代码不用改。它也需要同样的流式设置。
Function URL settings Auth type: NONE (the app does its own sign-in check) Invoke mode: RESPONSE_STREAM
FROM python:3.12-slim COPY --from=public.ecr.aws/awsguru/aws-lambda-adapter:0.9.1 /lambda-adapter /opt/extensions/lambda-adapter ENV PORT=8000 ENV AWS_LWA_INVOKE_MODE=response_stream WORKDIR /app COPY requirements.txt . RUN pip install --no-cache-dir -r requirements.txt COPY . . CMD ["uvicorn", "server:app", "--host", "0.0.0.0", "--port", "8000"]

Step 3 · Create it and read the logs第 3 步 · 创建函数并读日志

Learn先学
  • With the image in your registry, create the function from "container image". The console makes a basic role (permissions to run and write logs).
  • Set memory, a longer timeout (the default is a few seconds; model calls take longer) and your secrets as environment variables.
  • In the logs, the REPORT line shows Duration, Billed Duration and, only on a cold start, Init Duration.
  • 镜像进了仓库后，用“容器镜像”创建函数。控制台会建一个基本角色（运行和写日志的权限）。
  • 设置内存、更长的超时（默认只有几秒，模型调用更久），并把密钥放进环境变量。
  • 日志里的 REPORT 行显示运行时长、计费时长，而只有冷启动才有初始化时长。

Common errors常见错误

• Task timed out after 3.00 seconds: the default timeout is too short. Fix: set 60 seconds.
• 403 Forbidden on the function address: auth type is not NONE. Fix: set NONE and save.
• Answer arrives all at once: invoke mode is BUFFERED. Fix: set RESPONSE_STREAM and keep AWS_LWA_INVOKE_MODE=response_stream.

• Task timed out after 3.00 seconds：默认超时太短。 解决：设为 60 秒。
• 函数地址 403 Forbidden：认证方式不是 NONE。 解决：设为 NONE 并保存。
• 回答一下子全出来：调用模式是 BUFFERED。 解决：设为 RESPONSE_STREAM，并保留 AWS_LWA_INVOKE_MODE=response_stream。

Takeaways要点回顾

• Serverless runs only on demand; you pay for milliseconds.
• The first call after idle is a cold start; later calls are quick.
• Streaming needs the streaming invoke mode in two places: function URL and adapter.
• Set the timeout and environment variables on purpose.
• The REPORT log line shows what you were billed.

• 无服务器只在需要时运行，按毫秒付费。
• 闲置后的第一次调用是冷启动，之后的调用很快。
• 流式需要在函数地址和适配器两处都用流式调用模式。
• 超时和环境变量要有意识地设置。
• REPORT 日志行显示你被计了多少费。
