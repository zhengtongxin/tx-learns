Last time the product became a container that runs the same everywhere. Today Mr Ong frowns at paying for a server that idles all night, when most people only ask at lunch. We fix it by running the container as a serverless function that wakes on demand.

Step 1 · Code that runs only on demand第 1 步 · 只在需要时才运行的代码

Learn先学

Serverless does not mean there is no server. It means you do not own or watch one. A serverless function sits switched off until a request arrives, runs your code, then goes back to sleep, and you pay for the milliseconds it ran. The catch is the cold start: the first call after a quiet spell has to wake the box up first, which takes a few seconds. Calls right after that are quick.

无服务器（serverless）不是说没有服务器，而是说你不用拥有或盯着服务器。无服务器函数平时是关着的，请求一来就运行你的代码，然后回去睡觉，你只为它运行的那几毫秒付钱。代价是冷启动（cold start）：安静一阵之后的第一次调用要先把箱子唤醒，要花几秒钟。紧接着的调用就很快了。

request 1 (after a long quiet spell): wake the box → run → answer slow: a few seconds request 2 (right after): run → answer quick (long quiet spell: the box is put away again, and the bill stops)

Step 2 · Its own address, and streaming第 2 步 · 自己的地址，以及流式输出

Learn先学

A function URL gives the function its own HTTPS address, with no extra API gateway in front. It can also stream the answer word by word, like the helper does in the browser. But streaming only works if you choose the streaming-capable setting. The default is "buffered": the function collects the whole answer and sends it at the end. The invoke mode is a console switch. Step 3 adds a matching switch inside the container, and both must say streaming.

函数地址（function URL）让函数拥有自己的 HTTPS 地址，前面不需要再加 API 网关。它还能像助手在浏览器里那样，把回答一个词一个词地流式发出来。但只有选了支持流式的设置才行，默认是“缓冲”：函数先把整个回答攒齐，最后一次发出。调用模式是控制台里的一个开关，第 3 步会在容器里再加一个对应的开关。两个都要设成流式。

Function URL settings Auth type: NONE (the app does its own sign-in check) Invoke mode: RESPONSE_STREAM (BUFFERED, the default, waits for the whole answer)

Step 3 · A small adapter so your web app runs unchanged第 3 步 · 一个小适配器，让你的网页应用原样运行

Learn先学

A function does not speak "web server" by itself. It gets an invocation: a packet of data saying a request came in. A small adapter, dropped into your container, turns each invocation into a normal web request on a local port, and your FastAPI app answers it as always. So your Python code does not change. Only the Dockerfile gains a few lines. (Check the adapter's page for its latest version number.)

函数本身并不会“说网页服务器的话”。它收到的是一次调用（invocation）：一包说明有请求进来的数据。放进容器里的一个小适配器会把每次调用变成本地端口上的普通网页请求，你的 FastAPI 应用照常回答。所以你的 Python 代码不用改，只是 Dockerfile 多了几行。（它的最新版本号请去适配器的页面查。）

FROM python:3.12-slim COPY --from=public.ecr.aws/awsguru/aws-lambda-adapter:0.9.1 /lambda-adapter /opt/extensions/lambda-adapter ENV PORT=8000 ENV AWS_LWA_INVOKE_MODE=response_stream WORKDIR /app COPY requirements.txt . RUN pip install --no-cache-dir -r requirements.txt COPY . . CMD ["uvicorn", "server:app", "--host", "0.0.0.0", "--port", "8000"]

Step 4 · Create the function from the image第 4 步 · 用镜像创建函数

Learn先学

With the image in your registry (the project lesson after this one shows the push line by line), create the function in the console: choose "container image", pick yours, and the console makes a basic role for it (a set of permissions that lets the function run and write its logs). Then set the memory, the timeout and the environment variables (your secrets, kept out of the image). Raise the timeout: the default is a few seconds, and a model call can take longer.

镜像进了你的仓库之后（这节之后的项目课会逐行演示怎么推送），就可以在控制台创建函数：选“容器镜像”，选你的镜像，控制台会替它建一个基本角色（一组权限，让函数能运行并写日志）。然后设置内存、超时时间和环境变量（你的密钥，放在镜像外面）。把超时调大：默认只有几秒，而一次模型调用可能更久。

Function settings Source: container image canteen-helper:latest Memory: 512 MB Timeout: 60 seconds (not the small default) Environment: OPENAI_API_KEY = (your key)

Step 5 · Read the first request in the logs第 5 步 · 在日志里读第一个请求

Learn先学

Open the function's logs and find the line that starts with REPORT. It shows the Duration (how long your code ran), the Billed Duration (what you pay for) and, only on a cold start, the Init Duration (the time spent waking the box). Lower the memory and watch time and cost change: it is a trade, not a free win.

打开函数的日志，找到以 REPORT 开头的那一行。它显示运行时长（Duration）（你的代码跑了多久）、计费时长（Billed Duration）（你付钱的部分），而且只有冷启动时才有初始化时长（Init Duration）（唤醒箱子花的时间）。把内存调小，看看时间和成本怎么变：这是权衡，不是白捡的便宜。

REPORT RequestId: 3f1c... Duration: 812.45 ms Billed Duration: 813 ms Memory Size: 512 MB Max Memory Used: 140 MB Init Duration: 2301.55 ms
Cold start: Init Duration ~2.3 s, Duration ~0.8 s Warm start: no Init Duration, Duration ~0.4 s
What I got wrong我犯过的错Three slips. I thought it would feel instant every time, but the first request after a quiet spell is slow and users notice. Streaming did not stream until I picked the streaming-capable setting. And I left the timeout at its small default.三个失误。我以为每次都会像瞬间响应一样，其实安静一阵之后的第一个请求很慢，用户是看得出来的。直到我选了支持流式的设置，流式输出才真正流起来。我还把超时时间留在了很小的默认值。

Now make it yours现在把它变成你的

What changed这一课之后Now the product runs as a function that costs nothing while idle and wakes for the lunch crowd, with a slow first lift like Kumar's crane. The next problem is that this was a practice run: the real product, with its sign-in, plan and streaming, still lives on the hosting service.现在产品作为函数运行：闲置时不花钱，午饭人多时才醒来，只是第一下起吊较慢，像 Kumar 的吊机。下一个问题是这只是一次练习：真正的产品，带着登录、套餐和流式回答，还住在托管平台上。

Common errors常见错误

• Task timed out after 3.00 seconds The default timeout is too short for a model call. Fix: Set the timeout to 60 seconds in the function settings.
• 403 Forbidden on the function address The Function URL auth type is not NONE. Fix: Set the auth type to NONE (the app does its own check) and save.
• The answer arrives all at once The invoke mode is still BUFFERED. Fix: Set RESPONSE_STREAM and keep AWS_LWA_INVOKE_MODE=response_stream in the image.

• Task timed out after 3.00 seconds 默认超时对模型调用来说太短。 解决：在函数设置里把超时改成 60 秒。
• 403 Forbidden on the function address 函数地址的认证方式不是 NONE。 解决：把认证方式设为 NONE（应用自己做检查）并保存。
• The answer arrives all at once 调用模式仍是 BUFFERED。 解决：改成 RESPONSE_STREAM，并在镜像里保留 AWS_LWA_INVOKE_MODE=response_stream。

Takeaways要点回顾

• Serverless functions run only on demand, and you pay for the milliseconds.
• The first call after idle is a cold start, a few seconds slow. Later calls are quick.
• A function URL gives an HTTPS address with no gateway, and needs the streaming setting to stream.
• A small adapter lets an ordinary web framework run unchanged inside the container.
• Set the timeout and the environment variables on purpose.
• Read the REPORT log line for Duration, Billed Duration and Init Duration.
• It trades idle cost for cold starts: great for small, spiky apps.

• 无服务器函数只在需要时运行，按毫秒付费。
• 闲置之后的第一次调用是冷启动，要慢几秒；之后的调用就很快。
• 函数地址不需要网关就能提供 HTTPS 地址，要流式就得选流式设置。
• 一个小适配器就能让普通的网页框架在容器里原样运行。
• 超时时间和环境变量要有意识地设置。
• 读 REPORT 日志行，了解运行时长、计费时长和初始化时长。
• 它用冷启动换来了闲置零成本：很适合小而不均匀的应用。
