Quick agent runtime快速智能体运行时

See how much of the earlier plumbing a managed agent runtime does for you, from one command · ~30 min · hands-on看看托管的智能体运行时能替你做掉多少之前的管道活，一条命令就够 · 约 30 分钟 · 动手

Step 1 · Permissions, region, install第 1 步 · 权限、区域、安装

Learn先学

A managed agent runtime hosts your agent and does the container, registry and role plumbing for you. It still needs a pass first: a group allowed to use the model service, the build service and the runtime, plus model access requested in one region that you also launch in. Turn on observability once, so each call leaves a trace you can read later. Then install four packages in a fresh virtual environment.

托管的智能体运行时托管你的智能体，替你做容器、镜像仓库和角色这些管道活。它仍要先有通行证：一个能用模型服务、构建服务和运行时的用户组，并在某一个区域申请模型权限，之后也在同一区域启动。打开一次可观测性，每次调用就会留下可以之后读的轨迹。然后在新的虚拟环境里装四个包。

mkdir wharf-agent && cd wharf-agent python -m venv .venv && source .venv/bin/activate pip install bedrock-agentcore strands-agents bedrock-agentcore-starter-toolkit pydantic

Step 2 · Write the agent file第 2 步 · 写智能体文件

Learn先学

Three parts: an app object the runtime hosts, an agent with a system prompt, and one entry point, a function that takes the request and returns text. The @app.entrypoint decorator tells the runtime which function to call. Only one entry-point file is allowed per project.

三部分：运行时托管的应用对象、带系统提示词的智能体，以及唯一的入口，即接收请求并返回文字的函数。@app.entrypoint 装饰器告诉运行时调用哪个函数。每个项目只允许一个入口文件。

from bedrock_agentcore.runtime import BedrockAgentCoreApp from strands import Agent app = BedrockAgentCoreApp() helper = Agent( system_prompt="You are a short, friendly helper for the wharf IT desk.", ) @app.entrypoint def handle(payload): reply = helper(payload.get("prompt", "Hello")) return str(reply) if __name__ == "__main__": app.run()

Step 3 · Configure, launch, invoke第 3 步 · 配置、启动、调用

Learn先学

Configure names the entry file and the region. Launch builds the container, pushes it, creates the roles and starts the service. Invoke sends a JSON prompt and prints the reply. Delete the deployed agent when you are done.

配置指明入口文件和区域。启动构建容器、推送、创建角色并启动服务。调用发送 JSON 提示词并打印回复。用完后删掉部署的智能体。

agentcore configure -e agent.py --region ap-southeast-1 agentcore launch # container + registry + roles + running service agentcore invoke '{"prompt": "Which berth do I ask about a late pass?"}'

Now make it yours现在把它变成你的

Common errors常见错误

• AccessDeniedException Fix: Give the group the three services and request model access in the same region.
• Cannot connect to the Docker daemon Fix: Start Docker, or use the cloud build option.
• No module named 'strands' Fix: Run source .venv/bin/activate and install again.

• AccessDeniedException 解决：给用户组这三项服务，并在同一区域申请模型权限。
• Cannot connect to the Docker daemon 解决：启动 Docker，或使用云端构建选项。
• No module named 'strands' 解决：运行 source .venv/bin/activate 并重新安装。

Takeaways要点回顾

• A managed agent runtime hosts your agent and does the plumbing.
• Permissions first; model access and launch share one region.
• An agent file needs an app object, an agent and one entry point.
• Configure, launch and invoke replace the container, registry and role work.
• Delete what you deployed when you are done.

• 托管的智能体运行时托管你的智能体，并代办管道活。
• 权限先行；模型权限和启动用同一个区域。
• 智能体文件需要应用对象、智能体和唯一的入口。
• 配置、启动、调用取代了容器、镜像仓库和角色的手工活。
• 用完之后，把部署的东西删掉。
