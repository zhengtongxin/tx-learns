Step 1 · Permissions and region first第 1 步 · 先弄权限和区域

Learn先学

A managed service still needs a pass at the gate. Put your user in a group that may use three things: the model service (the models), the build service (it makes the container) and the agent runtime itself. Then ask for access to the model you want, in one specific region (a geographic location of the provider's data centres). Last, switch on observability in the runtime's console. The service then keeps a record of each call, called a trace, that you can read later.

托管服务也要在闸口出示通行证。把你的用户放进一个用户组，让它能用三样东西：模型服务（提供模型）、构建服务（负责做出容器）和智能体运行时本身。然后在某一个区域（服务商数据中心所在的地理位置）里申请你要用的模型的访问权。最后，在运行时的控制台里打开可观测性。服务会记下每次调用的过程，这份记录叫轨迹，之后可以读。

Group "wharf-agents" may use: [ ] model service (call models) [ ] build service (build the container) [ ] agent runtime (host the agent) Model access: request it in ap-southeast-1 (the region you will also launch in) Console: turn on observability once

Step 2 · Install the small project第 2 步 · 装好小项目

Learn先学

Read the runtime's docs and its starter kit first, so you know what it expects. Then make a tiny project with four packages: the runtime's SDK (the code that lets your file be hosted), an agent library, the runtime's toolkit (the launch command) and a data-models library (pydantic, which checks that your data has the right shape). Keep it in its own folder with its own virtual environment (a private set of packages for this one project, so projects do not mix).

先读运行时的文档和它的入门套件，知道它期待什么。然后建一个只有四个包的小项目：运行时的 SDK（让你的文件能被托管的代码）、一个智能体库、运行时的工具包（启动命令）和一个数据模型库（pydantic，检查你的数据形状对不对）。放在自己的文件夹里，用独立的虚拟环境（一套只属于这个项目的包，项目之间不会混在一起）。

mkdir wharf-agent && cd wharf-agent python -m venv .venv && source .venv/bin/activate pip install bedrock-agentcore strands-agents bedrock-agentcore-starter-toolkit pydantic
(example output) Successfully installed bedrock-agentcore-0.1.x strands-agents-1.x ...

Step 3 · Write the first agent file第 3 步 · 写第一个智能体文件

Learn先学

The file has three parts. An app object that the runtime hosts. An agent with a system prompt (the standing instructions that tell it who it is and how to answer). And one entry point: a function that takes the request, runs the agent on the prompt and returns text. The @app.entrypoint line above that function is a decorator: a label that tells the runtime which function to call. Only one entry-point file is allowed per project, so keep everything the runtime must start in that file.

这个文件有三部分。一个运行时来托管的应用对象；一个带系统提示词（先给它的一段固定指示，告诉它是谁、该怎么回答）的智能体；还有唯一一个入口：接收请求、让智能体处理提示词、返回文字的函数。代码里函数上面的 @app.entrypoint 是一个装饰器，就是一行标签，告诉运行时该调用哪个函数。每个项目只允许一个入口文件，所以运行时要启动的东西都放在这个文件里。

# agent.py from bedrock_agentcore.runtime import BedrockAgentCoreApp from strands import Agent app = BedrockAgentCoreApp() helper = Agent( system_prompt="You are a short, friendly helper for the wharf IT desk.", ) @app.entrypoint def handle(payload): reply = helper(payload.get("prompt", "Hello")) return str(reply) if __name__ == "__main__": app.run()

Step 4 · Configure, launch, invoke第 4 步 · 配置、启动、调用

Learn先学

Three commands. Configure tells the toolkit which file is the entry point and which region to use. Launch builds the container, pushes it to a registry, creates the roles and starts the service. Invoke sends it a JSON prompt and prints the reply. Compare that with the many hand steps you did before.

三条命令。配置告诉工具包哪个文件是入口、用哪个区域。启动会构建容器、推到镜像仓库、创建角色并启动服务。调用发一个 JSON 提示词给它，并打印回复。拿它和你之前手工做的那么多步骤比一比。

agentcore configure -e agent.py --region ap-southeast-1 agentcore launch # container + registry + roles + running service agentcore invoke '{"prompt": "Which berth do I ask about a late pass?"}'
Launch complete: wharf_agent (status: READY) Ask the desk about late passes at the Gate 2 office.
What I got wrong我犯过的错Three slips. My default region was not the region where I had model access, so every call errored; I now pass the region when I configure. I put helper code in a second entry-point file, and the runtime allows only one. And I forgot to delete the deployed agent afterwards, which is a small bill for nothing.三个失误。我的默认区域和申请到模型权限的区域不一样，所以每次调用都报错；现在配置时我会明确传入区域。我把辅助代码放进了第二个入口文件，而运行时只允许一个。我还忘了事后删掉已部署的智能体，白白花了一点钱。

Common errors常见错误

• AccessDeniedException Your group lacks a permission, or model access was not requested. Fix: Tick the three services for the group and request model access in the same region.
• Cannot connect to the Docker daemon The launch builds a container and Docker is not running (if your setup uses a local build). Fix: Start Docker, or use the cloud build option, then launch again.
• ModuleNotFoundError: No module named 'strands' The virtual environment is not active. Fix: Run source .venv/bin/activate and install again.

• AccessDeniedException 你的用户组缺少权限，或没有申请模型权限。 解决：给用户组勾选这三项服务，并在同一区域申请模型权限。
• Cannot connect to the Docker daemon 启动时要构建容器，而 Docker 没有运行（如果你的设置用本地构建）。 解决：启动 Docker，或使用云端构建选项，然后重新启动。
• ModuleNotFoundError: No module named 'strands' 虚拟环境没有激活。 解决：运行 source .venv/bin/activate 并重新安装。

Recap小结An agent is a model with a prompt, wrapped in one entry-point function.
agentcore launch builds, stores, permits and runs it for you.
Invoke it with JSON and read the reply, then clean up.智能体就是带提示词的模型，外面包着一个入口函数。
agentcore launch 替你完成构建、存放、授权和运行。
用 JSON 调用它、读回复，最后清理。
Plain words白话词汇Agent runtime: a service that hosts your agent and runs it when called. Entry point: the one function the runtime calls with each request.智能体运行时（agent runtime）：托管你的智能体、并在被调用时运行它的服务。入口（entry point）：运行时对每个请求都会调用的那一个函数。

Takeaways要点回顾

• A managed agent runtime hosts your agent and does the plumbing for you.
• Permissions come first: model service, build service and the runtime.
• Ask for model access in one region, and use that same region everywhere.
• An agent file needs an app object, an agent and one entry point.
• Configure, launch and invoke replace the container, registry and role work.
• Delete what you deployed when you are done.
• Managed runtimes remove the plumbing, not the thinking.

• 托管的智能体运行时替你托管智能体，并代办管道活。
• 权限先行：模型服务、构建服务和运行时。
• 在一个区域申请模型权限，并且处处使用同一个区域。
• 智能体文件需要应用对象、智能体和唯一的入口。
• 配置、启动、调用，取代了容器、镜像仓库和角色的手工活。
• 用完之后，把部署的东西删掉。
• 托管运行时去掉的是管道，不是思考。
