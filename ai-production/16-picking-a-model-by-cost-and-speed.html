Picking a model按成本速度选模型

Choose a model size on purpose by testing it, work out what a month costs, then watch real usage once the twin is live · ~30 min · hands-on用测试有意识地选定模型大小，算出一个月要花多少钱，上线后再盯着真实的使用情况 · 约 30 分钟 · 动手实践

Step 1 · Three sizes, and the model id as a knob第 1 步 · 三种大小，把模型 id 做成旋钮

Learn先学

A model family comes in three sizes: micro (fastest, cheapest), lite (balanced) and pro (best reasoning, slowest, dearest). Keep the model id in an environment variable so switching size needs no code change. The update command replaces the function's whole set of variables, so list every one you still need.

模型家族有三种大小：micro（最快最便宜）、lite（均衡）和 pro（推理最强，最慢最贵）。把模型 id 放进环境变量，换大小就不用改代码。更新命令会替换函数的整套变量，所以还需要的变量都要列出来。

# in server.py: MODEL_ID = os.environ["MODEL_ID"] aws lambda update-function-configuration --function-name wharf-twin \ --environment "Variables={MODEL_ID=apac.amazon.nova-micro-v1:0,MEMORY_BUCKET=wharf-twin-memory}"

Step 2 · What a month costs第 2 步 · 一个月要花多少钱

Learn先学

Models are priced per thousand tokens (small pieces of text, about three-quarters of a word), with a higher price for output than input. A chat costs input tokens × input price + output tokens × output price. The prices below are made-up round numbers; read the provider's current page.

模型按每千个 token（文字的小片段，约四分之三个英文单词）计价，输出比输入贵。一次聊天的费用 = 输入 token × 输入单价 + 输出 token × 输出单价。下面的价格是编的整数；请读服务商当前的价格页。

# example dollars per 1,000 tokens: (input, output) -- not real PRICES = {"micro": (0.00004, 0.00016), "lite": (0.00006, 0.00024), "pro": (0.0008, 0.0032)} def cost_per_chat(size, tokens_in=800, tokens_out=200): p_in, p_out = PRICES[size] return tokens_in / 1000 * p_in + tokens_out / 1000 * p_out # micro 6.4e-05 per chat, lite 9.6e-05, pro 0.00128

Step 3 · Same questions, three sizes第 3 步 · 同样的问题，三种大小

Learn先学

Never judge a model on one prompt. Write about ten questions, each with a word a good answer must contain, and run them on every size. Record passes, time and tokens (each reply has a usage block, which is what you are billed on). Then pick the smallest model that passes. Shorter system prompts and a capped history (say the last ten messages) cut tokens further.

别拿一个提示评判模型。写大约十道题，每题写一个好答案必须出现的词，在每种大小上都跑一遍。记下通过数、耗时和 token（每个回应都带 usage 块，计费就看它）。然后选能通过的最小模型。更短的系统提示和限制历史长度（比如只发最近十条）能进一步省 token。

import os import time import boto3 client = boto3.client("bedrock-runtime", region_name=os.environ.get("AWS_REGION", "ap-southeast-1")) SYSTEM = "You are a twin. Facts: she works in the wharf IT office and studies on weekends." SIZES = {"micro": "apac.amazon.nova-micro-v1:0", "lite": "apac.amazon.nova-lite-v1:0", "pro": "apac.amazon.nova-pro-v1:0"} QUESTIONS = [("Where does she work?", "wharf"), # grow this list to ten ("When does she study?", "weekend")] def run(size): passed, secs, tin, tout = 0, 0.0, 0, 0 for question, must_have in QUESTIONS: t0 = time.time() r = client.converse(modelId=SIZES[size], system=[{"text": SYSTEM}], messages=[{"role": "user", "content": [{"text": question}]}], inferenceConfig={"maxTokens": 200}) secs += time.time() - t0 passed += must_have in r["output"]["message"]["content"][0]["text"].lower() tin += r["usage"]["inputTokens"] tout += r["usage"]["outputTokens"] return passed, round(secs, 1), tin, tout for size in SIZES: print(size, run(size)) # (passed, seconds, input tokens, output tokens)

Step 4 · Watch it once it is live第 4 步 · 上线后盯着它

Learn先学

The test says what should happen; logs say what does. Add one log line per model call with the model, time and token counts, so slow or costly calls are searchable. Then set an alarm on the function's error count so you hear before a user complains.

测试告诉你应该发生什么，日志告诉你实际发生了什么。每次模型调用记一行日志，写上模型、耗时和 token 数，慢的或贵的调用就能搜到。再对函数的错误数设一个警报，让你比用户先知道。

import json MODEL_ID = SIZES["lite"] # the size you picked; client and time come from the step above def ask_logged(system_prompt: str, messages: list) -> str: t0 = time.time() resp = client.converse(modelId=MODEL_ID, system=[{"text": system_prompt}], messages=messages, inferenceConfig={"maxTokens": 300}) print(json.dumps({"event": "model_call", "model": MODEL_ID, "ms": round((time.time() - t0) * 1000), "in": resp["usage"]["inputTokens"], "out": resp["usage"]["outputTokens"]})) return resp["output"]["message"]["content"][0]["text"]

Now make it yours现在把它变成你的

Common errors常见错误

• KeyError: 'MODEL_ID' Fix: update-function-configuration replaces the whole set, so list every variable again.
• ThrottlingException Your test loop is too fast. Fix: Add time.sleep(1) between calls.

• KeyError: 'MODEL_ID' 解决：update-function-configuration 会替换整组变量，每个变量都要再列一遍。
• ThrottlingException 测试循环太快。 解决：在调用之间加 time.sleep(1)。

Takeaways要点回顾

• Micro, lite and pro trade speed and price against reasoning.
• Keep the model id in an environment variable.
• A chat costs input tokens × input price + output tokens × output price.
• Run the same questions on every size and pick the smallest that passes.
• Log one line per call and set an alarm.

• micro、lite 和 pro 在速度、价格与推理能力之间取舍。
• 把模型 id 放进环境变量。
• 一次聊天费用 = 输入 token × 输入单价 + 输出 token × 输出单价。
• 每种大小跑同样的问题，选能通过的最小那个。
• 每次调用记一行日志，并设置警报。
