Status codes and headers状态码与头信息

Read the number that says how a request went and the headers that travel with it · ~10 min · reading and practice读懂说明请求结果的数字，以及随请求一起走的头信息 · 约 10 分钟 · 阅读加练习

Step 1 · The number first第 1 步 · 先看数字

Learn先学

Every response starts with a status code, grouped by its first digit. 2xx means success (200 OK, 201 created). 3xx means look elsewhere (a redirect). 4xx means you got something wrong: 400 bad request, 401 not signed in, 403 not allowed, 404 not found, 429 too many requests. 5xx means the server failed: 500, 503.

每个响应都以状态码开头，按第一位数字分组。2xx 表示成功（200 正常，201 已创建）。3xx 表示去别处看（重定向）。4xx 表示你这边有问题：400 请求有误，401 未登录，403 不允许，404 找不到，429 请求太多。5xx 表示服务器出了故障：500、503。

The first digit tells you whose problem it is, which decides what you do next.

第一位数字告诉你是谁的问题，这决定了你接下来怎么做。

Put each code in its family.

把每个状态码放进它所属的一类。

Sort each one.

给每一项分类。

Step 2 · Headers第 2 步 · 头信息

Learn先学

Headers are name: value lines sent with a request or response, carrying information about the message rather than the data itself. Common ones: Content-Type (what format the body is, such as application/json), Authorization (who is asking) and Accept (what formats the client can read).

头信息是随请求或响应一起发送的“名字: 值”行，携带的是关于这条消息的信息，而不是数据本身。常见的有：Content-Type（正文是什么格式，例如 application/json）、Authorization（谁在请求）、Accept（客户端能读什么格式）。

HTTP/1.1 200 OK Content-Type: application/json {"item": "tea", "price": 3}

Step 3 · Reading a failure第 3 步 · 读懂失败

Learn先学

When a call fails, read the code before anything else. A 401 means fix your key. A 404 means fix the address. A 429 means slow down and retry later. A 500 is not your fault, so retry a little later rather than changing your request.

调用失败时，先看状态码。401 要去查你的密钥；404 要去查地址；429 要放慢并稍后重试；500 不是你的错，隔一会儿重试，而不是改你的请求。

Takeaways要点回顾

• The first digit of a status code says whose problem it is.
• Headers describe the message, not the data.
• Retry on 5xx and 429; fix your request on 4xx.

• 状态码第一位说明是谁的问题。
• 头信息描述消息本身，而不是数据。
• 遇到 5xx 和 429 重试；遇到其他 4xx 修正你的请求。
