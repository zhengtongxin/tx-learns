Keys and authentication密钥与身份验证

Prove who you are to an API with a key, and keep that key out of places where it can leak · ~10 min · reading and practice用密钥向 API 证明你是谁，并让密钥远离可能泄露的地方 · 约 10 分钟 · 阅读加练习

Step 1 · Who is asking第 1 步 · 是谁在请求

Learn先学

A server needs to know who is calling, to bill the right account and to stop strangers. An API key is a long secret string that stands for your account. Whoever holds the key can act as you and spend your money, so treat it like a password.

服务器需要知道是谁在调用，好向正确的账户计费，也好挡住陌生人。API 密钥是一长串代表你账户的机密字符。谁拿到密钥，谁就能冒充你、花你的钱，所以要像对待密码一样对待它。

Keys usually travel in a header, most often Authorization: Bearer <key>. A missing or wrong key gets a 401.

密钥通常放在头信息里发送，最常见的是 Authorization: Bearer <密钥>。缺失或错误的密钥会得到 401。

Step 2 · Keep it secret第 2 步 · 守住机密

Learn先学

Never write a key into code you share, a screenshot or a chat. Put it in an environment variable (or a .env file that your version control ignores) and read it from there. If a key leaks, revoke it and make a new one at once: deleting the file does not help, because copies already exist.

别把密钥写进要分享的代码、截图或聊天里。把它放进环境变量（或被版本管理忽略的 .env 文件），再从那里读取。密钥一旦泄露，立刻吊销并重新生成：把文件删掉没用，因为副本已经存在了。

import os key = os.environ.get("SHOP_API_KEY") if not key: raise SystemExit("Set SHOP_API_KEY first") headers = {"Authorization": "Bearer " + key} print(sorted(headers))

Takeaways要点回顾

• An API key stands for your account; treat it like a password.
• Send it in a header and read it from an environment variable.
• If it leaks, revoke it and make a new one.

• API 密钥代表你的账户，要像对待密码一样对待它。
• 在头信息里发送，从环境变量里读取。
• 一旦泄露，吊销并重新生成。
