Requests and responses请求与响应

See what happens between typing an address and seeing a page, and read a URL part by part · ~10 min · reading and practice看清从输入网址到看见页面之间发生了什么，并逐段读懂一个网址 · 约 10 分钟 · 阅读加练习

Step 1 · Ask, then answer第 1 步 · 一问一答

Learn先学

Almost everything on the web is the same two-step: a client (your browser or a program) sends a request, and a server sends back a response. The server does not remember you between requests unless something in the request says who you are. That is the whole model, and an API call is just this exchange done by code.

网络上几乎一切都是同样的两步：客户端（浏览器或程序）发出请求，服务器返回响应。除非请求里带着说明你是谁的东西，否则服务器在两次请求之间并不记得你。这就是全部模型，而 API 调用不过是由代码来做这一问一答。

A request names a method (what to do) and a URL (where). GET reads, POST sends new data, PUT or PATCH changes, DELETE removes.

请求包含方法（做什么）和网址（在哪）。GET 读取，POST 发送新数据，PUT 或 PATCH 修改，DELETE 删除。

Step 2 · Read a URL第 2 步 · 读懂网址

Learn先学

A URL has parts: the scheme (https), the host (shop.example.com), the path (/menu/tea) and the query after a ? (size=large&sugar=0), written as name=value pairs joined by &.

网址由几部分组成：协议（https）、主机（shop.example.com）、路径（/menu/tea），以及 ? 后面的查询参数（size=large&sugar=0），写成用 & 连接的 名字=值。

from urllib.parse import urlparse, parse_qs u = urlparse("https://shop.example.com/menu/tea?size=large&sugar=0") print(u.netloc) print(u.path) print(parse_qs(u.query))

Step 3 · Which method第 3 步 · 用哪个方法

Learn先学

Pick the method by what you want. Reading must never change anything, which is why a link you click is a GET.

按你想做的事选方法。读取绝不应该改变任何东西，所以你点的链接是 GET。

Takeaways要点回顾

• A client sends a request and a server sends a response.
• A URL is scheme, host, path and query.
• GET reads, POST creates, DELETE removes.

• 客户端发请求，服务器回响应。
• 网址由协议、主机、路径和查询参数组成。
• GET 读取，POST 新建，DELETE 删除。
