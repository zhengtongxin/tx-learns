Agents as graphs把智能体画成图

Turn your agent loop into a map of stations and arrows · ~25 min · hands-on把智能体循环画成档口和箭头组成的地图 · 约 25 分钟 · 动手实践

Key point要点

A graph is plain functions (nodes) reading and writing one shared state, joined by arrows (edges). Think of a kopitiam order pad that every station can read. LangGraph runs it for you, so you stop hand-writing the if chains between steps.

图就是一组普通函数（节点）读写同一份状态，再用箭头（边）连起来。可以想成咖啡店里每个档口都看得到的订单板。LangGraph 替你运行它，你不用再手写步骤之间的 if。

Step 1 · State, nodes and edges第 1 步 · 状态、节点和边

Learn先学
  • State is the pad everyone reads. A reducer says how old and new combine: add_messages appends; a plain field is overwritten by the last write.
  • A node is a function that returns only the keys it changes. An edge says who goes next; START and END are the doors.
  • Always five steps: define state, create builder, add nodes, add edges, compile.
  • 状态就是大家都读的订单板。reducer 决定新旧内容怎么合并：add_messages 追加；普通字段被最后一次写入覆盖。
  • 节点是只返回自己所改键的函数。边说明下一个轮到谁；START 和 END 是进门和出门。
  • 步骤永远是五步：定义状态、创建构建器、加节点、加边、编译。
import random from typing import Annotated from typing_extensions import TypedDict from langgraph.graph import StateGraph, START, END from langgraph.graph.message import add_messages class Pad(TypedDict): messages: Annotated[list, add_messages] # reducer: append, never overwrite malay: str # no reducer: last write wins def auntie(state: Pad) -> dict: shout = random.choice(["Kopi siap!", "Roti dah habis!", "Tunggu sekejap!"]) return {"messages": [{"role": "assistant", "content": shout}]} g = StateGraph(Pad) # builder g.add_node("auntie", auntie) # node g.add_edge(START, "auntie") # edges g.add_edge("auntie", END) app = g.compile() # compile out = app.invoke({"messages": [{"role": "user", "content": "order"}]}) print(out["messages"][-1].content)

Step 2 · A fork and a loop第 2 步 · 分叉与回环

Learn先学
  • A conditional edge chooses the next node. tools_condition answers "tools" or END; ToolNode runs the tools the model asked for.
  • An edge from the tools node back to the model is a loop.
  • 条件边选择下一个节点。tools_condition 回答 "tools" 或 END；ToolNode 运行模型请求的工具。
  • 从工具节点指回模型的边就是回环。

from langchain_openai import ChatOpenAI from langchain_core.tools import tool from langgraph.prebuilt import ToolNode, tools_condition llm = ChatOpenAI(model="gpt-5.4-mini") # reads OPENAI_API_KEY @tool def menu_price(item: str) -> float: """Price in S$ of a drink or dish on today's menu.""" return {"kopi o": 1.6, "roti canai": 1.5, "nasi lemak": 4.0}.get(item.lower(), 0.0) tools = [menu_price] llm_t = llm.bind_tools(tools) def counter(state: Pad) -> dict: return {"messages": [llm_t.invoke(state["messages"])]} def translate(state: Pad) -> dict: text = state["messages"][-1].content prompt = f"Translate to Bahasa Melayu, reply with only the translation:\n{text}" return {"malay": llm.invoke(prompt).content} g = StateGraph(Pad) g.add_node("counter", counter) g.add_node("tools", ToolNode(tools)) g.add_node("translate", translate) g.add_edge(START, "counter") g.add_conditional_edges("counter", tools_condition, {"tools": "tools", END: "translate"}) g.add_edge("tools", "counter") # the loop: back to the counter g.add_edge("translate", END) app = g.compile()

Step 3 · Memory across runs第 3 步 · 跨次运行的记忆

Learn先学
  • A reducer works only inside one run. For memory across calls, compile with a checkpointer and pass a thread_id: one pad per table.
  • MemorySaver vanishes on restart; SqliteSaver keeps a file. Every step is saved, so you can resume from an earlier one.
  • reducer 只在一次运行内部有效。想跨调用记住东西，编译时加上检查点并传入 thread_id：每张桌子一块板。
  • MemorySaver 重启就没了；SqliteSaver 存成文件。每一步都被保存，所以能从更早的一步继续。
from langgraph.checkpoint.memory import MemorySaver from langgraph.checkpoint.sqlite import SqliteSaver app = g.compile(checkpointer=MemorySaver()) table5 = {"configurable": {"thread_id": "table-5"}} app.invoke({"messages": [{"role": "user", "content": "I am Mei Ling, I always take kopi kosong"}]}, table5) print(app.invoke({"messages": [{"role": "user", "content": "My usual, please?"}]}, table5)["messages"][-1].content) # survives restarts: a file instead of memory, used inside its with-block with SqliteSaver.from_conn_string("pads.db") as saver: durable = g.compile(checkpointer=saver)

Takeaways要点回顾

• A graph is functions on a shared pad, joined by arrows.
• A reducer decides how old and new state combine: add_messages appends, a plain field is replaced.
• A node returns only the keys it changes; a conditional edge picks the next node; an edge back makes a loop.
• A checkpointer plus thread_id remembers across runs; SqliteSaver survives restarts.

• 图就是读写共享板子的函数，用箭头连起来。
• reducer 决定新旧状态怎么合并：add_messages 追加，普通字段被替换。
• 节点只返回它改动的键；条件边选下一个节点；指回前面的边形成回环。
• 检查点加 thread_id 才能跨次记住；SqliteSaver 重启后仍在。
