Outreach email helper外联邮件助手

You build the same agent team twice, once with your code as the boss and once with an LLM as the boss · ~30 min · hands-on同一支智能体团队你会搭两次：一次由你的代码当老板，一次由大模型当老板 · 约 30 分钟 · 动手实践

Step 1 · Sending, the boring part first第 1 步 · 先把发送搞定

Learn先学

Example: Lina runs a weekend tutoring centre and wants to email parents about a new Saturday coding club. Build a small team that writes and sends. Sending comes first, behind one send_message function so the agents never know how. The simplest free way is SMTP (the standard way a program hands email to a mail server) with an app password (a separate password just for scripts) kept in .env. Without one, push just prints the message, so you can still test. The sending is not the lesson: get it working once, then forget it.

示例：Lina 开了一家周末辅导班，想给家长发邮件介绍新的周六编程俱乐部。我们搭一支会写也会发的小团队。先搞定发送，并把它藏在一个 send_message 函数后面，智能体不必知道怎么发。最简单的免费办法是 SMTP（程序把邮件交给邮件服务器的标准方式）加应用专用密码（专门给脚本用的独立密码），放在 .env 里。没有的话，push 只把内容打印出来，照样能测试。发送不是重点：调通一次，然后就别管它。

import os, smtplib from dotenv import load_dotenv load_dotenv() # reads .env: MAIL_FROM, MAIL_TO, SMTP_HOST (your mail provider's server) and SMTP_APP_PASSWORD from email.message import EmailMessage def send_by_email(subject: str, body: str) -> None: msg = EmailMessage() msg["Subject"], msg["From"], msg["To"] = subject, os.environ["MAIL_FROM"], os.environ["MAIL_TO"] msg.set_content(body) with smtplib.SMTP(os.environ["SMTP_HOST"], 587) as server: server.starttls() # encrypt first server.login(os.environ["MAIL_FROM"], os.environ["SMTP_APP_PASSWORD"]) server.send_message(msg) def push(text: str) -> None: print(text) # no mail set up: print it (swap in a phone alert if you have one) def send_message(subject: str, body: str) -> None: if os.getenv("SMTP_APP_PASSWORD"): send_by_email(subject, body) else: push(f"{subject}\n\n{body}")

Step 2 · By code: three writers, then a picker第 2 步 · 由代码编排：三个写手，再来一个挑选者

Learn先学

Same base instructions, three tones: formal, playful, short. asyncio.gather runs all three at once, so the wait is the slowest one, not the sum. A picker agent reads every draft and replies with the best one only. result.final_output is an agent's last reply as text. await only works inside an async function, so the steps sit in async def main() and asyncio.run(main()) starts it.

基础指令相同，三种语气：正式、活泼、简短。asyncio.gather 让三个同时运行，等待时间是最慢的那个，而不是总和。挑选者智能体读完所有草稿，只回复最好的一份。result.final_output 是智能体最后一句回复的文字。在 .py 脚本里，要把 await 那几行放进 async def main():，再用 asyncio.run(main()) 启动。

import asyncio from agents import Agent, Runner, trace # trace groups a run's steps so you can replay them on the provider's Traces page base = ("You write emails for a weekend tutoring centre. " "Invite parents to the new Saturday coding club for kids aged 9 to 12.") writers = [ Agent(name="Formal writer", instructions=base + " Tone: polite and professional.", model="gpt-5.4-mini"), Agent(name="Playful writer", instructions=base + " Tone: warm and a little playful.", model="gpt-5.4-mini"), Agent(name="Brief writer", instructions=base + " Tone: short and clear for busy parents. Under 80 words.", model="gpt-5.4-mini")] picker = Agent(name="Picker", model="gpt-5.4-mini", instructions="You get several email drafts. Pick the one a busy parent is most likely to answer. Reply with that draft only.") async def main(): with trace("Coding club outreach"): drafts = await asyncio.gather(*(Runner.run(w, "Write the invitation email") for w in writers)) joined = "Drafts:\n\n" + "\n\n---\n\n".join(d.final_output for d in drafts) best = await Runner.run(picker, joined) send_message("A new Saturday coding club", best.final_output) asyncio.run(main())

Step 3 · By the LLM: a manager with tools第 3 步 · 由大模型编排：带工具的主管

Learn先学

Now hand the order to a Coordinator agent. @function_tool builds the tool's schema (its JSON description) from type hints and the docstring. A small model may just say “Email sent!” without calling anything; tool_choice="required" forces a real call. Each writer becomes a tool with .as_tool(), and control returns to the Coordinator after every call (A → B → A). Tool names cannot contain spaces, hence .replace.

现在把顺序交给一个 Coordinator（协调者）智能体。@function_tool 根据类型标注和文档字符串生成工具的 schema（JSON 描述）。小模型可能只是嘴上说“邮件已发送！”却什么都没调用；tool_choice="required" 强制它真正调用。每个写手用 .as_tool() 变成工具，每次调用后控制权都回到 Coordinator（A → B → A）。工具名不能有空格，所以要 .replace。

from agents import function_tool, ModelSettings @function_tool def send_email(subject: str, body: str) -> str: """Send one email to the parents' mailing list.""" send_message(subject, body) return "Sent" writer_tools = [w.as_tool(tool_name=w.name.lower().replace(" ", "_"), tool_description="Write a draft invitation email in this tone") for w in writers] coordinator = Agent(name="Coordinator", model="gpt-5.4-mini", tools=writer_tools + [send_email], model_settings=ModelSettings(tool_choice="required"), instructions="""You send one invitation email. 1. Get one draft from each of the three writer tools. Do not go on until you have all three. 2. Choose the single best draft yourself. 3. Send exactly one email with send_email.""") async def main(): # replaces Step 2's main() result = await Runner.run(coordinator, "Send the coding club invitation to parents") print(result.final_output)

Step 4 · Handoff, and code or LLM?第 4 步 · 交接，以及代码还是大模型？

Learn先学

Variant: the Coordinator only collects and picks, then hands off to a second agent, the Mailroom, which owns send_email. Control moves A → B and does not come back, so result.last_agent is the Mailroom. A handoff_description tells the Coordinator when to hand off.

By code is predictable and easy to debug. By the LLM is flexible but may skip your plan. Fixed steps: use code. A path that depends on the input: use the LLM.

变体：Coordinator 只负责收集和挑选，再交接给第二个智能体 Mailroom（收发室），由它掌管 send_email。控制权 A → B 之后不再回来，所以 result.last_agent 是 Mailroom。handoff_description 告诉 Coordinator 何时交接。

由代码编排可预测、好调试。由大模型编排灵活，但可能不照计划走。步骤固定用代码；路径取决于输入用大模型。

mailroom = Agent(name="Mailroom", model="gpt-5.4-mini", tools=[send_email], model_settings=ModelSettings(tool_choice="required"), handoff_description="Sends the chosen draft to the parents", instructions="You get one finished email. Send it once with send_email.") picker_boss = Agent(name="Coordinator", model="gpt-5.4-mini", tools=writer_tools, handoffs=[mailroom], instructions="Get a draft from each writer tool, choose the best, then hand off to the Mailroom with that draft.") async def main(): result = await Runner.run(picker_boss, "Send the coding club invitation to parents") print("Last agent:", result.last_agent.name) # Last agent: Mailroom
Flaky manager?主管不稳定？Small models sometimes ask two writers, or send two emails. Fixes: numbered steps (“send exactly one email”), forced tool use, or a bigger model. Test with your own address first: bulk mail from a new sender often lands in spam.小模型有时只问两个写手，或发两封邮件。办法：写清编号步骤（“只发一封邮件”）、强制调用工具，或换更大的模型。先发给自己的邮箱测试：新发件人群发的邮件常进垃圾箱。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Hide sending behind one send_message, then focus on the agents.
• asyncio.gather runs agents at the same time.
• By code: your Python decides the order. By the LLM: a manager uses agents as tools (A → B → A) or handoffs (A → B).
• @function_tool builds the schema; tool_choice="required" stops “pretend” sends.
• Flaky manager? Numbered steps, forced tools or a bigger model.

• 把发送藏在一个 send_message 后面，然后专心做智能体。
• asyncio.gather 让智能体同时运行。
• 由代码编排：你的 Python 决定顺序。由大模型编排：主管用“智能体当工具”（A → B → A）或交接（A → B）。
• @function_tool 生成 schema；tool_choice="required" 防止“假装发送”。
• 主管不稳？写编号步骤、强制调用工具或换更大模型。
