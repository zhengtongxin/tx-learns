Side case支线案例

Lina runs Little Lanterns, a small weekend tutoring centre. She is starting a Saturday coding club for kids aged 9 to 12 and wants to email parents about it. She has no time to write the email herself. So you build her a little team: three writers with different tones, someone to pick the best draft, and someone to send it. Each step today moves that one email closer to the parents' inboxes. At Kopi Corner the three writers draft Uncle Lim's monthly note and Aina is the one who presses send.

Lina 开了一家周末小辅导班 Little Lanterns。她要开一个面向 9 到 12 岁孩子的周六编程俱乐部，想发邮件告诉家长们。可她没空自己写。于是你给她搭一支小团队：三个语气不同的写手，一个挑出最佳草稿的人，再加一个负责发送的人。今天每一步，都让这封邮件离家长的收件箱更近一点。放到 Kopi Corner，三个写手起草 Lim 叔叔的月度通知，按下发送的是 Aina。

Step 1 · Sending, the boring part first第 1 步 · 先把发送这件无聊事搞定

Learn先学

The team needs a way to actually send. Proper email services want a domain you own plus DNS records, which is a lot of setup for a demo. The easiest free way is SMTP, the standard way a program hands an email to a mail server, using your own mailbox. You log in with an app password (a separate password just for scripts) kept in .env. If even that is not set up yet, the phone push helper from earlier lessons is a fine stand-in.

团队得有办法真正把邮件发出去。正规的邮件服务需要你拥有一个域名，还要配 DNS 记录，做个演示太折腾了。最简单的免费办法是用你自己邮箱的 SMTP，也就是程序把邮件交给邮件服务器的标准方式。登录用的是应用专用密码（专门给脚本用的独立密码），放在 .env 里。如果连这个都还没配好，用前几课的手机推送函数 push 代替也完全可以。

import os, smtplib from email.message import EmailMessage def send_by_email(subject: str, body: str) -> None: msg = EmailMessage() msg["Subject"], msg["From"], msg["To"] = subject, os.environ["MAIL_FROM"], os.environ["MAIL_TO"] msg.set_content(body) with smtplib.SMTP(os.environ["SMTP_HOST"], 587) as server: server.starttls() # encrypt first server.login(os.environ["MAIL_FROM"], os.environ["SMTP_APP_PASSWORD"]) server.send_message(msg) def push(text: str) -> None: ... # your own small helper from earlier lessons: posts text to a phone push service def send_message(subject: str, body: str) -> None: """One door for sending. The agents never know which way it went.""" if os.getenv("SMTP_APP_PASSWORD"): send_by_email(subject, body) else: push(f"{subject}\n\n{body}") # phone push fallback
Note to self提醒自己The sending is not the lesson. The agent work is. Get send_message working once, then forget about it.发送不是这一课的重点，智能体才是。把 send_message 调通一次，然后就别管它了。

Step 2 · By code: three writers at once, then a picker第 2 步 · 由代码编排：三个写手同时开工，再来一个挑选者

Learn先学

Lina does not know which tone parents like, so try three. Same base instructions, three tones: formal, playful, and short for busy parents. asyncio.gather runs all three at the same time, like asking three friends for a draft at once instead of one after another. A fourth agent, the picker, reads all drafts and replies with the best one only.

Agent, Runner and trace come from the Agents SDK you met in the last two lessons. Runner.run is async, so each call needs await, which means “wait here until this answer comes back”.

Lina 不知道家长喜欢哪种语气，那就三种都试试。基础指令相同，语气不同：正式、活泼、给忙碌家长的简短版。asyncio.gather 让三个同时运行，就像同时请三个朋友各写一稿，而不是一个接一个地等。第四个智能体是挑选者，读完所有草稿后只回复最好的那一份。

Agent、Runner 和 trace 都来自前两课用过的 Agents SDK。Runner.run 是异步的，所以每次调用前都要加 await，意思是“在这儿等结果回来再往下走”。

import asyncio from agents import Agent, Runner, trace base = ("You write emails for Little Lanterns, a weekend tutoring centre. " "Invite parents to the new Saturday coding club for kids aged 9 to 12.") writers = [ Agent(name="Formal writer", instructions=base + " Tone: polite and professional.", model="gpt-5.4-mini"), Agent(name="Playful writer", instructions=base + " Tone: warm and a little playful.", model="gpt-5.4-mini"), Agent(name="Brief writer", instructions=base + " Tone: short and clear for busy parents. Under 80 words.", model="gpt-5.4-mini")] picker = Agent(name="Picker", model="gpt-5.4-mini", instructions="You get several email drafts. Pick the one a busy parent is most likely to answer. Reply with that draft only.") with trace("Coding club outreach"): drafts = await asyncio.gather(*(Runner.run(w, "Write the invitation email") for w in writers)) joined = "Drafts:\n\n" + "\n\n---\n\n".join(d.final_output for d in drafts) best = await Runner.run(picker, joined) send_message("A new Saturday coding club", best.final_output)

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

(your inbox, a few seconds later) Subject: A new Saturday coding club Hi parents, our free coding club starts this Saturday at 10am ...

Each run returns a result, and result.final_output is the agent's last reply as text.

每次运行都会返回一个结果，result.final_output 就是智能体最后一句回复的文字。

Wrapping it all in trace makes the whole run show up as one entry on the Traces page of your OpenAI dashboard. When something goes odd, that trace is your best debugger.

把整个过程包在 trace 里，这次运行就会在 OpenAI 控制台的 Traces 页面里显示成一条记录。出了怪问题时，trace 就是你最好的调试工具。

One catch: a bare await at the top level only works in a notebook. In a .py script, put the code inside async def main(): and start it with asyncio.run(main()).

注意：直接在最外层写 await 只在 notebook 里行得通。如果是 .py 脚本，要把代码放进 async def main():，再用 asyncio.run(main()) 启动。

Step 3 · Make sending a real tool, and make the agent use it第 3 步 · 把发送做成真正的工具，并逼智能体用它

Learn先学

In Step 2 your code sent the email. Next, an agent will decide to send, so it needs send_message as a tool. Remember the JSON description of each tool you wrote by hand in earlier lessons? That is called a schema. @function_tool now builds it for you from your type hints (subject: str) and the docstring (the text in triple quotes). One surprise: a small model may just say “Email sent!” without calling anything. ModelSettings(tool_choice="required") forces a real tool call.

Three names, one chain: send_email is the tool the agent sees. It calls your Step 1 wrapper send_message, which then calls send_by_email or push.

第 2 步里是你的代码发的邮件。接下来要让智能体自己决定发送，所以它需要把 send_message 当成工具。还记得前几课里给每个工具手写的那段 JSON 描述吗？它叫 schema。现在 @function_tool 会根据类型标注（subject: str）和文档字符串（三引号里的那段说明）替你生成。有个意外：小模型可能只是嘴上说“邮件已发送！”，其实什么都没调用。ModelSettings(tool_choice="required") 强制它真正调用工具。

三个名字，一条链：send_email 是智能体看得到的工具，它调用第 1 步的包装函数 send_message，再由它调用 send_by_email 或 push。

from agents import function_tool, ModelSettings @function_tool def send_email(subject: str, body: str) -> str: """Send one email to the parents' mailing list. Args: subject: The subject line parents will see. body: The plain-text body of the email. """ send_message(subject, body) return "Sent" print(send_email.params_json_schema) # look: the SDK wrote the schema mailroom = Agent(name="Mailroom", model="gpt-5.4-mini", instructions="Turn the draft you get into a clear subject and body, then send it with send_email.", tools=[send_email], model_settings=ModelSettings(tool_choice="required"))

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

{'properties': {'subject': {'title': 'Subject', 'type': 'string'}, 'body': {'title': 'Body', 'type': 'string'}}, 'required': ['subject', 'body'], 'title': 'send_email_args', 'type': 'object', 'additionalProperties': False}

Step 4 · By the LLM: a manager with agents as tools第 4 步 · 由大模型编排：用“智能体当工具”的主管

Learn先学

So far your Python decided the order. Now you hand that job to a Coordinator agent. Each writer becomes a tool with .as_tool(), and the Coordinator also gets send_email. Its instructions are the plan, in numbered steps. Control comes back to the Coordinator after every call. Call the Coordinator A and a writer B: A asks B, B answers, A is in charge again (A → B → A), like a manager who keeps asking the team and decides alone. Tool names cannot have spaces, hence the .replace(" ", "_"). The Coordinator sends each writer tool a short text request and gets the draft back as text.

到目前为止，顺序都是你的 Python 定的。现在把这件事交给一个 Coordinator（协调者）智能体。每个写手用 .as_tool() 变成一个工具，Coordinator 还拿到 send_email。它的指令就是计划，按步骤编号写清楚。每次调用后控制权都回到 Coordinator。把 Coordinator 记作 A，某个写手记作 B：A 找 B 要稿，B 交回，A 重新掌控（A → B → A），像一位主管不断向团队要东西，最后自己拍板。工具名不能有空格，所以要 .replace(" ", "_")。Coordinator 给每个写手工具发一句简短的文字请求，拿回的是一份文字草稿。

writer_tools = [w.as_tool(tool_name=w.name.lower().replace(" ", "_"), tool_description="Write a draft invitation email in this tone") for w in writers] coordinator = Agent(name="Coordinator", model="gpt-5.4-mini", tools=writer_tools + [send_email], instructions="""You send one invitation email for Little Lanterns. 1. Get one draft from each of the three writer tools. Do not go on until you have all three. 2. Choose the single best draft yourself. 3. Send exactly one email with send_email. Never send more than one.""") with trace("Coding club, manager version"): result = await Runner.run(coordinator, "Send the coding club invitation to parents")

Step through one run. Watch who gets control back.

一步步看一次运行，注意控制权每次回到谁手里。

Step 5 · By the LLM: a handoff to the sender第 5 步 · 由大模型编排：交接给发送者

Learn先学

Another way: the Coordinator only collects drafts and picks one, then hands the job to Mailroom, which formats and sends. A handoff moves control across, A → B, and it does not come back. Mailroom gets the draft because it sees the whole conversation so far, drafts and choice included. The highlighted handoff_description works like a tool description: the Coordinator reads it to decide when to hand off. So Mailroom finishes the run, and result.last_agent tells you which agent that was. Fun fact: under the hood the SDK implements a handoff as a tool call too, named like transfer_to_mailroom.

另一种做法：Coordinator 只负责收集草稿、挑一份，然后把活交接给 Mailroom，由它排版并发送。交接是把控制权交过去，A → B，不会再回来。Mailroom 能拿到草稿，是因为它看得到之前的整段对话，包括所有草稿和选择。高亮的 handoff_description 就像工具说明：Coordinator 读它来判断什么时候该交接。所以最后收尾的是 Mailroom，result.last_agent 会告诉你收尾的是哪个智能体。有个冷知识：在底层，SDK 也是用一次工具调用来实现交接的，名字类似 transfer_to_mailroom。

mailroom = Agent(name="Mailroom", ..., tools=[send_email], handoff_description="Formats the chosen draft and sends it to parents", model_settings=ModelSettings(tool_choice="required")) coordinator = Agent(name="Coordinator", model="gpt-5.4-mini", tools=writer_tools, handoffs=[mailroom], instructions="""1. Get one draft from each of the three writer tools. 2. Choose the single best draft. 3. Hand off to Mailroom with that draft. Do not write the email yourself.""") result = await Runner.run(coordinator, "Send the coding club invitation")

Step 6 · Code or LLM: who should be the manager?第 6 步 · 代码还是大模型：谁来当主管？

Learn先学

You now have the same team run two ways. By code is predictable, repeatable and easy to debug, because the steps are written in Python. By the LLM is flexible: the path can change with the content, but the model may not follow your plan every time. Rule of thumb: fixed steps, use code; a path that depends on what comes in, use the LLM.

现在同一支团队你有了两种跑法。由代码编排可预测、可重复、好调试，因为步骤就写在 Python 里。由大模型编排更灵活：路径可以随内容变化，但模型不一定每次都照你的计划走。经验法则：步骤固定，用代码；路径取决于输入内容，用大模型。

The moment it clicked恍然大悟的那一刻“By code” is me being the manager. “By the LLM” is hiring a manager and hoping they follow the plan.“由代码编排”就是我自己当主管；“由大模型编排”就是雇一个主管，然后祈祷对方照着计划办事。

Sort each of Lina's jobs.

给 Lina 的每件事分类。

What I got wrong我踩过的坑With the small model, the manager versions were flaky. Sometimes the Coordinator asked only two writers. Sometimes it sent two emails. With the handoff, Mailroom sometimes never sent at all. My first instructions were one loose sentence. Three fixes helped: clear numbered steps (“do not go on until you have all three drafts”, “send exactly one email”), forcing tool use with tool_choice="required", and, when all else fails, a bigger model. And yes, my test email landed in spam. No surprise there: a new sender mailing many people at once often looks like spam. Test with your own address first.用小模型时，主管版本很不稳定。有时 Coordinator 只问了两个写手；有时它发了两封邮件；用交接时，Mailroom 有时干脆没发。我最初的指令只是一句笼统的话。三个办法有用：写清楚编号步骤（“三份草稿都拿到之前不要继续”“只发一封邮件”）、用 tool_choice="required" 强制调用工具，实在不行就换更大的模型。还有，我的测试邮件进了垃圾箱。这也不奇怪：一个新发件人一次给很多人发信，看起来就像垃圾邮件。先发给自己的邮箱试试。

Common errors常见错误

• smtplib.SMTPAuthenticationError: (535, b'5.7.8 Username and Password not accepted'): You used your normal mailbox password. Fix: create an app password in your mail account's security settings and put it in SMTP_APP_PASSWORD.
• socket.gaierror: [Errno -2] Name or service not known: The mail server name is wrong or empty. Fix: check SMTP_HOST in .env (for example smtp.gmail.com).
• RuntimeWarning: coroutine 'Runner.run' was never awaited: You forgot await, so the agent never ran. Fix: write await Runner.run(...).

• smtplib.SMTPAuthenticationError: (535, b'5.7.8 Username and Password not accepted')：你用了邮箱的登录密码。解决：到邮箱账号的安全设置里生成一个应用专用密码，填进 SMTP_APP_PASSWORD。
• socket.gaierror: [Errno -2] Name or service not known：邮件服务器名字错了或为空。解决：检查 .env 里的 SMTP_HOST（例如 smtp.gmail.com）。
• RuntimeWarning: coroutine 'Runner.run' was never awaited：你忘了写 await，所以智能体根本没运行。解决：写成 await Runner.run(...)。

Takeaways要点回顾

• Get sending working once behind one send_message wrapper, then focus on the agents.
• asyncio.gather runs several agents at the same time. The wait is the slowest one, not the sum.
• By code: your Python decides the order. Predictable and easy to debug.
• By the LLM: a manager agent decides, using agents as tools (A → B → A) or handoffs (A → B).
• @function_tool builds the schema from type hints and the docstring. tool_choice="required" stops “pretend” sends.
• Flaky manager? Numbered steps, forced tool use, or a bigger model.
• Wrap runs in trace(...). The trace is your best debugger.

• 先用一个 send_message 包装函数把发送调通，然后专心做智能体。
• asyncio.gather 让多个智能体同时运行，等待时间是最慢的那个，而不是总和。
• 由代码编排：你的 Python 决定顺序，可预测、好调试。
• 由大模型编排：主管智能体来决定，用“智能体当工具”（A → B → A）或交接（A → B）。
• @function_tool 根据类型标注和文档字符串生成 schema；tool_choice="required" 防止“假装发送”。
• 主管不靠谱？写编号步骤、强制调用工具，或换更大的模型。
• 把运行包在 trace(...) 里，trace 是你最好的调试工具。
