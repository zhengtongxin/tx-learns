Where we left off上回讲到

Last time the Kopi Corner assistant learned to ask the stall next door's own agent for help over A2A. Today Aina has to choose which framework to keep building on, and every one looks different. We fix it by building the same worker five times and comparing them.

上次 Kopi Corner 助手学会了通过 A2A 向隔壁摊位自己的智能体求助。今天 Aina 要选一个框架继续做下去，而每个看起来都不一样。我们把同一个工人做五遍来比较。

Side case支线案例

Five cafés in Penang all brew the same filter coffee. One has a lever machine, one a drip tower, one a cloth sock, one a moka pot, one a French press. The machines differ, but the steps are identical: grind, wet, brew, pour, serve. Once you know the steps you can work in any café. Agent frameworks are the same. You will build one identical worker five times. Its job: take a goal from a shared SQLite board (“read tonight's takings.txt, total each stall, write summary.txt”), plan its own steps, do them with file tools and tick each off. The Penang cafés are a side case: Kopi Corner is the sixth café, free to pick any machine.

槟城有五家咖啡店，都冲同样的滤泡咖啡。一家用杠杆机，一家用滴滤塔，一家用布袋，一家用摩卡壶，一家用法压壶。机器不同，但步骤完全一样：磨、润、冲、倒、上桌。会了步骤，去哪家店都能上手。智能体框架也是这样。你要把同一个工人用五个框架各做一遍。它的任务：从共享的 SQLite 任务板领一个目标（“读 takings.txt，按摊位合计，写进 summary.txt”），自己规划步骤，用文件工具完成，并逐项打勾。槟城的咖啡店是个支线案例：Kopi Corner 就是第六家店，可以随便挑机器。

Step 1 · The same five steps everywhere第 1 步 · 到哪里都是同样的五步

Learn先学

Every framework asks you for the same five things, in the same order: 1 create the agent (a model plus a system prompt: the instruction text that says what the agent is for), 2 run it, 3 add tools (typed functions), 4 add MCP (the standard plug for ready-made tools, here a file server limited to one folder), 5 put it in a loop with a goal. Only the names change.

每个框架都按同样的顺序要你做同样的五件事：1 创建智能体（模型加系统提示词，也就是告诉智能体它的职责的那段指令文字），2 运行，3 加工具（带类型的函数），4 接 MCP（给智能体接上现成工具的标准插头，这里是限定在一个文件夹的文件服务），5 带着目标放进循环。变的只是名字。

Step 2 · Strands and Pydantic AI第 2 步 · Strands 与 Pydantic AI

Learn先学

From here the worker uses OpenAI's gpt-4o-mini model, so set an OPENAI_API_KEY in your .env file the way you set the Google key in the first lesson of this tour. board is the shared task board from the story, a small SQLite database that lists the goals.

Strands marks tools with @tool and builds Agent(model, system_prompt, tools). Its headline feature is portability: swap the model class for another provider and nothing else changes.

从这里开始，工人改用 OpenAI 的 gpt-4o-mini 模型，所以要像这组巡礼的第一课那样，在 .env 文件里设置 OPENAI_API_KEY。board 是故事里的共享任务板，就是一个列出目标的小型 SQLite 数据库。

Strands 用 @tool 标记工具，构造 Agent(model, system_prompt, tools)。它的招牌是可移植：把模型类换成别的供应商，其余代码不用动。

pip install "strands-agents[openai]" "pydantic-ai-slim[mcp,openai]" mcp fastmcp python-dotenv
import os, subprocess from strands import Agent, tool from strands.models.openai import OpenAIModel from strands.tools.mcp import MCPClient from mcp import stdio_client, StdioServerParameters model = OpenAIModel(client_args={"api_key": os.environ["OPENAI_API_KEY"]}, model_id="gpt-4o-mini") @tool def show_board() -> list[dict]: """List every todo on the task board.""" return board.list_todos() files = MCPClient(lambda: stdio_client( StdioServerParameters(command="npx", args=["-y", "@modelcontextprotocol/server-filesystem", CAFE], cwd=CAFE), errlog=subprocess.DEVNULL)) worker = Agent(model=model, system_prompt="Work the pending goal on the board.", tools=[show_board, files]) await worker.invoke_async("Please work the pending goal.")
Learn先学

Pydantic AI takes a model string like "openai-chat:gpt-4o-mini", instructions=, plain functions as tools and MCP servers as toolsets=. Its special strength is typed, validated output: pass output_type= a Pydantic model and you get a checked object back, not loose text.

Pydantic AI 用 "openai-chat:gpt-4o-mini" 这样的模型字符串、instructions=、普通函数当工具，MCP 服务放进 toolsets=。它的特长是带类型、经过校验的输出：给 output_type= 传一个 Pydantic 模型，拿回的就是校验过的对象，而不是随意的文字。

import os from pathlib import Path from pydantic_ai import Agent from pydantic_ai.mcp import MCPToolset from fastmcp.client.transports import StdioTransport files = MCPToolset(StdioTransport(command="npx", args=["-y", "@modelcontextprotocol/server-filesystem", CAFE], cwd=CAFE, log_file=Path(os.devnull)), init_timeout=60) worker = Agent("openai-chat:gpt-4o-mini", instructions="Work the pending goal.", tools=[show_board], toolsets=[files]) async with worker: # this opens the MCP connection res = await worker.run("Please work the pending goal.") print(res.output)

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

I worked the pending goal: the page is written and ticked off on the board.

Step 3 · Microsoft Agent Framework and Agno第 3 步 · Microsoft Agent Framework 与 Agno

Learn先学

Microsoft Agent Framework merges two older Microsoft agent projects. You give it a chat client plus instructions, and it is async-first. Its real selling point is underneath: a graph workflow engine with checkpoints and human approval, and the same API in .NET.

Microsoft Agent Framework 合并了微软两个较早的智能体项目。你给它一个聊天客户端加 instructions，它以异步为先。真正的卖点在底层：带检查点和人工审批的图工作流引擎，而且 .NET 上有同样的 API。

Agno is very light. Making an agent takes microseconds, which matters when a server creates a fresh agent for every request.

Agno 非常轻。创建一个智能体只要微秒级，当服务器每个请求都新建一个智能体时，这一点就很重要。

# Microsoft Agent Framework from agent_framework import Agent, MCPStdioTool from agent_framework.openai import OpenAIChatClient files = MCPStdioTool(name="files", command="npx", args=["-y", "@modelcontextprotocol/server-filesystem", CAFE]) worker = Agent(client=OpenAIChatClient(model="gpt-4o-mini"), instructions="Work the pending goal.", tools=[show_board, files]) async with files: # the tool, not the agent res = await worker.run("Please work the pending goal.") print(res.text) # Agno from agno.agent import Agent from agno.models.openai import OpenAIChat from agno.tools.mcp import MCPTools async with MCPTools(server_params=srv, timeout_seconds=60) as files: worker = Agent(model=OpenAIChat(id="gpt-4o-mini"), instructions="Work the pending goal.", tools=[show_board, files]) res = await worker.arun(input="Please work the pending goal.") print(res.content)

Step 4 · Mastra, the TypeScript one第 4 步 · Mastra，TypeScript 的那个

Learn先学

Same five steps, different language. Mastra sits on the Vercel AI SDK, so a model is a "provider/model" string and a tool's inputs are described with a zod schema (zod is TypeScript's way of saying “this object must look like this”). Choose it when the rest of your app is already TypeScript.

同样五步，换了语言。Mastra 建在 Vercel AI SDK 之上，所以模型是 "provider/model" 字符串，工具的输入用 zod 模式描述（zod 是 TypeScript 里表达“这个对象必须长这样”的办法）。如果你的应用其余部分已经是 TypeScript，就选它。

import { Agent } from "@mastra/core/agent"; import { createTool } from "@mastra/core/tools"; import { MCPClient } from "@mastra/mcp"; import { z } from "zod"; const showBoard = createTool({ id: "show_board", description: "List every todo on the task board.", inputSchema: z.object({}), execute: async () => ({ todos: listTodos() }), }); const mcp = new MCPClient({ servers: { files: { command: "npx", args: ["-y", "@modelcontextprotocol/server-filesystem", CAFE] } } }); const worker = new Agent({ id: "takings-worker", name: "Takings Worker", instructions: "Work the pending goal on the board.", model: "openai/gpt-4o-mini", tools: { showBoard, ...(await mcp.listTools()) } }); const reply = await worker.generate("Please work the pending goal.", { maxSteps: 30 }); console.log(reply.text); process.exit(0); // otherwise the script hangs
What I got wrong我踩过的坑Three things cost me an evening. 1) The file server prints a banner on stderr (the program's error channel, where warnings go), and inside a Jupyter notebook on Windows there is no real stderr, so the launch fails. Each framework hides it differently: Strands errlog=, Pydantic AI log_file=, Agno needs its stdio_client patched, Microsoft Agent Framework needs a small subclass. Setting cwd= to the workspace is what makes takings.txt resolve. 2) The async with dance: Pydantic AI wants it on the agent, Agno and Microsoft Agent Framework on the tool. Forget it and the tools are simply not connected, with an error that does not say so. 3) Mastra keeps its connection pool open and never exits, so I end every script with process.exit(0). It also moves fast, so pin @mastra/core and do not trust old blog posts.有三件事让我耗了一个晚上。1) 文件服务会在 stderr（程序的错误输出通道，警告就打在这里）打印横幅，而在 Windows 的 Jupyter 笔记本里没有真正的 stderr，启动就失败。每个框架的藏法都不同：Strands 用 errlog=，Pydantic AI 用 log_file=，Agno 要给它的 stdio_client 打补丁，Microsoft Agent Framework 要写一个小子类。把 cwd= 设为工作目录，takings.txt 这样的相对路径才找得到。2) async with 的位置：Pydantic AI 写在智能体上，Agno 和 Microsoft Agent Framework 写在工具上。忘了写，工具就是没连上，而报错并不会告诉你这一点。3) Mastra 一直占着连接池不退出，所以我每个脚本都以 process.exit(0) 结尾。它更新也很快，要锁定 @mastra/core 的版本，别太信旧博客。

What changed这一课之后Now the Kopi Corner assistant can be built in Python or JS/TS, and Aina knows to choose by each framework's extra, like picking a machine for Uncle Lim's morning rush. The next problem is that frameworks hide what the loop actually does.现在 Kopi Corner 助手用 Python 或 JS/TS 框架都能做，Aina 也知道该看各框架的“额外的本事”来选，就像为林叔的早市挑机器。下一个问题是：框架把循环里到底做了什么藏起来了。

Common errors常见错误

• ModuleNotFoundError: No module named 'strands': The package name differs from the import. Fix: pip install "strands-agents[openai]" inside the same environment you run from.
• KeyError: 'OPENAI_API_KEY': Several of these frameworks read os.environ directly. Fix: call load_dotenv() first.
• Cannot find module '@mastra/core': The JS packages are not installed. Fix: run npm install @mastra/core in the project folder.

• ModuleNotFoundError: No module named 'strands'：包名和导入名不同。解决：在运行代码的同一个环境里 pip install "strands-agents[openai]"。
• KeyError: 'OPENAI_API_KEY'：这些框架里有几个直接读 os.environ。解决：先调用 load_dotenv()。
• Cannot find module '@mastra/core'：没装 JS 依赖。解决：在项目文件夹里运行 npm install @mastra/core。

Takeaways要点回顾

• Every framework asks for the same five steps: agent, run, tools, MCP, loop.
• Switching frameworks is mostly renaming. Pick by the extra each one offers.
• Strands: swap model providers freely. Pydantic AI: typed, validated output.
• Microsoft Agent Framework: durable graph workflows and .NET. Agno: very fast to create.
• Mastra: the TypeScript choice, with zod schemas for tools. Pin its version.
• MCP is where the pain is: stderr noise, cwd, and where async with goes.
• If tools seem missing and no error explains why, check the connection first.

• 每个框架都要同样的五步：智能体、运行、工具、MCP、循环。
• 换框架多半只是改名。要按各自额外的本事来选。
• Strands：自由切换模型供应商。Pydantic AI：带类型、经过校验的输出。
• Microsoft Agent Framework：可持久的图工作流和 .NET。Agno：创建速度极快。
• Mastra：TypeScript 的选择，工具用 zod 模式，记得锁定版本。
• 麻烦主要在 MCP：stderr 噪音、cwd，以及 async with 写在哪里。
• 工具好像没了又没有报错说明时，先检查连接。

Recap三句回顾

• Frameworks differ in spelling, not in shape: a model, instructions, tools and a loop.
• Pick Python or JS/TS by where the rest of your app lives.
• Compare frameworks by running the same small task in each.

• 框架的差别在写法，不在结构：模型、指令、工具和循环。
• 选 Python 还是 JS/TS，看你的其他应用在哪边。
• 比较框架最好的办法：在每个里面跑同一个小任务。
