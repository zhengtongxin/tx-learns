Key point要点

Every agent framework asks for the same five steps, so switching is mostly renaming. Choose by the extra each one adds, not by the core. We build one worker that reads a goal from a task board, totals takings.txt per stall and writes summary.txt.

每个智能体框架都要你做同样的五步，所以换框架多半只是改名字。按各自多出来的特色来选，别按核心来选。我们做一个执行者：从任务板读目标，按摊位汇总 takings.txt，写出 summary.txt。

  2. Run it with a first message.
  3. Add tools: typed functions.

  5. Put it in a loop with a goal.

  4. 加 MCP：现成的工具，这里是限定在一个文件夹的文件服务。
  5. 放进带目标的循环。

Step 2 · Two Python frameworks第 2 步 · 两个 Python 框架

Learn先学
  • Both use OpenAI's gpt-4o-mini, so put OPENAI_API_KEY in .env.
  • Strands marks tools with @tool. Its extra: swap the model class for another provider and nothing else changes.
  • Pydantic AI takes plain functions and MCP as toolsets=. Its extra: output_type= gives a validated object, not loose text.
  • MCP connections must be opened: async with worker in Pydantic AI. Forget it and the tools are silently not connected.
  • 两者都用 OpenAI 的 gpt-4o-mini，所以在 .env 里放 OPENAI_API_KEY。
  • Strands 用 @tool 标记工具。特色：把模型类换成别的供应商，其余都不用改。
  • Pydantic AI 用普通函数，MCP 通过 toolsets= 传入。特色：output_type= 给出校验过的对象，而不是随意的文字。
  • MCP 连接必须先打开：Pydantic AI 里是 async with worker。忘了的话，工具就悄悄没连上。

import os, subprocess from strands import Agent, tool from strands.models.openai import OpenAIModel from strands.tools.mcp import MCPClient from mcp import stdio_client, StdioServerParameters CAFE = "/abs/path/to/workspace" # folder holding takings.txt TODOS = ["Read takings.txt, total each stall, write summary.txt"] model = OpenAIModel(client_args={"api_key": os.environ["OPENAI_API_KEY"]}, model_id="gpt-4o-mini") @tool def show_board() -> list[str]: """List every todo on the task board.""" return TODOS files = MCPClient(lambda: stdio_client( StdioServerParameters(command="npx", args=["-y", "@modelcontextprotocol/server-filesystem", CAFE], cwd=CAFE), errlog=subprocess.DEVNULL)) worker = Agent(model=model, system_prompt="Work the pending goal on the board.", tools=[show_board, files]) await worker.invoke_async("Please work the pending goal.")
import os from pathlib import Path from pydantic_ai import Agent from pydantic_ai.mcp import MCPToolset from fastmcp.client.transports import StdioTransport def show_board() -> list[str]: """List every todo on the task board.""" return TODOS files = MCPToolset(StdioTransport(command="npx", args=["-y", "@modelcontextprotocol/server-filesystem", CAFE], cwd=CAFE, log_file=Path(os.devnull)), init_timeout=60) worker = Agent("openai-chat:gpt-4o-mini", instructions="Work the pending goal.", tools=[show_board], toolsets=[files]) async with worker: # this opens the MCP connection res = await worker.run("Please work the pending goal.") print(res.output)

Takeaways要点回顾

• Every framework asks for the same five steps: agent, run, tools, MCP, loop.
• Pick by the extra: Strands swaps providers, Pydantic AI validates output, Microsoft Agent Framework has graph workflows, Agno is fast, Mastra is TypeScript.
• MCP is where the pain is: stderr noise, cwd, and where async with goes.
• If tools seem missing with no error, check the connection first.

• 每个框架都要同样的五步：智能体、运行、工具、MCP、循环。
• 按特色选：Strands 能换供应商，Pydantic AI 校验输出，Microsoft Agent Framework 有图工作流，Agno 很快，Mastra 是 TypeScript。
• 麻烦都在 MCP：stderr 噪音、cwd、async with 写在哪里。
• 工具莫名缺失又没有报错，先检查连接。
