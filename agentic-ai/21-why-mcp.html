MCP · Lesson 1MCP · 第 1 课

Why MCP exists为什么需要 MCP

Plug in tools other people wrote, the same way every time · ~25 min · hands-on每次都用同样的方式接上别人写好的工具 · 约 25 分钟 · 动手实践

Key point要点

MCP (Model Context Protocol) is one shared plug for agent tools. A tool program (the server) lives outside your code; your agent framework's client plugs in the same way every time, so you stop writing glue code per tool. Like kopitiam stalls that all took the same QR payment: any app pays any stall.

MCP（模型上下文协议）是智能体工具共用的一种插头。工具程序（服务端）在你的代码之外；智能体框架里的客户端每次都用同样的方式接上，所以不用再为每个工具写胶水代码。就像咖啡店的摊位都改用同一种二维码支付：任何 App 都能付任何摊位。

Step 1 · What a server offers第 1 步 · 服务端提供什么

Learn先学
  • MCP is not magic. It is still just tools, but they live in someone else's program.
  • A server offers tools (actions), resources (read-only data) and prompts (ready-made instructions).
  • MCP 没有魔法，仍然只是工具，只不过它们在别人的程序里。
  • 服务端提供工具（动作）、资源（只读数据）和提示词（现成的指令）。

Step 2 · Local servers, listed then plugged in第 2 步 · 本地服务端：先列出，再接上

Learn先学
  • A local server starts as a subprocess on your machine and talks over stdio (a pipe between two programs).
  • List its tools before trusting it. The description and input schema are exactly what the model reads.
  • Put servers in mcp_servers=[...]; the agent decides when to use them. A file server is fenced to one folder.
  • The server lives only inside async with, so run the agent in there. First runs download the server, so raise the timeout.
  • 本地服务端在你的电脑上作为子进程启动，通过 stdio（两个程序之间的管道）通信。
  • 信任之前先列出它的工具。描述和输入模式正是模型读到的内容。
  • 把服务端放进 mcp_servers=[...]，由智能体决定何时使用。文件服务端被限定在一个文件夹。
  • 服务端只在 async with 里活着，所以要在里面运行智能体。第一次运行要下载服务端，所以把超时调大。
pip install openai-agents python-dotenv # plus Node + npx, or uv/uvx, to start servers
from agents.mcp import MCPServerStdio # run inside an async def main() or a notebook cell fetch = {"command": "uvx", "args": ["mcp-server-fetch"]} async with MCPServerStdio(params=fetch, client_session_timeout_seconds=60) as server: tools = await server.list_tools() for t in tools: print(t.name, "-", t.description[:80]) print(t.inputSchema) # the JSON schema the model sees
import os from agents import Agent, Runner, trace box = os.path.abspath("sandbox"); os.makedirs(box, exist_ok=True) browser = {"command": "npx", "args": ["@playwright/mcp@latest"]} files = {"command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", box]} RULES = "You browse the web to get things done. If one site is useless, try another. Only write files inside sandbox/." async with MCPServerStdio(params=browser, client_session_timeout_seconds=60) as b, \ MCPServerStdio(params=files, client_session_timeout_seconds=60) as f: agent = Agent(name="recipe_hunter", instructions=RULES, model="gpt-4o-mini", mcp_servers=[b, f]) with trace("recipe_hunter"): res = await Runner.run(agent, "Find a good Singapore asam laksa recipe and save a markdown summary to sandbox/laksa.md") print(res.final_output)

Step 3 · Remote servers, and when to use MCP第 3 步 · 远程服务端，以及何时用 MCP

Learn先学
  • A remote server is hosted by someone else: you install nothing, you give a URL, over streamable HTTP. It receives whatever the agent sends, so keep secrets out.
  • Use MCP for tools others maintain (browser, files, search, a product's official server) or to share tools across frameworks. Skip it for one small function: a plain @function_tool is simpler.
  • A server is code running with your permissions. Trust the source and fence the files.
  • 远程服务端由别人托管：你什么都不用装，只给一个 URL，走可流式 HTTP。智能体发出的内容它都会收到，所以别放机密。
  • 别人维护的工具（浏览器、文件、搜索、某个产品的官方服务端），或要在多个框架间共用工具时，用 MCP。只有一个小函数时不必用：普通的 @function_tool 更简单。
  • 服务端是以你的权限运行的代码。要信任来源，并把文件限制在一个文件夹里。
from agents.mcp import MCPServerStreamableHttp question = "In the latest version of the OpenAI Agents SDK, how do I filter which MCP tools an agent can see?" async with MCPServerStreamableHttp(name="docs", params={"url": "https://mcp.context7.com/mcp", "timeout": 60}) as docs: agent = Agent(name="docs_expert", instructions="Answer using the docs tools. Say so if unsure.", model="gpt-4o-mini", mcp_servers=[docs]) print((await Runner.run(agent, question)).final_output)

Takeaways要点回顾

• MCP is a shared plug: a server offers tools, a client in your framework uses them.
• Local servers are subprocesses over stdio; remote ones are a URL over streamable HTTP.
• List a server's tools first: the description and schema are what the model reads.
• The server lives only inside async with, so run the agent there.
• A server runs with your permissions: trust the source and fence the files.

• MCP 是共用的插头：服务端提供工具，框架里的客户端使用它们。
• 本地服务端是走 stdio 的子进程；远程服务端是走可流式 HTTP 的 URL。
• 先列出服务端的工具：描述和模式就是模型读到的内容。
• 服务端只在 async with 里活着，所以要在里面运行智能体。
• 服务端以你的权限运行：信任来源，并限制文件范围。
