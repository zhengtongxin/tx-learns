MCP · Lesson 1MCP · 第 1 课

Why MCP exists为什么需要 MCP

Plug in tools other people wrote, the same way every time · ~25 min · hands-on每次都用同样的方式接上别人写好的工具 · 约 25 分钟 · 动手实践

The story故事

You are helping Siew, who wants an agent that can search the web for a laksa recipe and save a summary on her computer. She has no wish to write a browser, and she does not want to learn a new plug for every tool she tries. At the kopitiam she noticed that every stall takes the same QR payment now. Today you build her agent the same way: ready-made tool programs, one plug.

你在帮 Siew，她想要一个能上网搜叻沙食谱、再把摘要存到电脑上的智能体。她不想自己写浏览器，也不想为试的每个工具都学一种新插头。她在咖啡店发现，现在每个摊位都收同一种二维码付款。今天你就用同样的办法来做她的智能体：现成的工具程序，一种插头。

Step 1 · Why a shared standard第 1 步 · 为什么要有共同的标准

Learn先学

Every kopitiam stall used to take payment its own way. One had a DuitNow QR, one wanted exact cash, one had a card machine from a bank nobody had heard of. Then most stalls switched to the same QR standard. Now any customer's banking app can pay any stall, and the owner does not care which bank you use.

以前每个咖啡店摊位收款的方式都不一样：有的用 DuitNow 二维码，有的只收零钱现金，有的用没人听过的银行刷卡机。后来大部分摊位改用同一个二维码标准。现在任何顾客的银行 App 都能付给任何摊位，摊主也不用管你用哪家银行。

MCP (Model Context Protocol) is that shared QR for agent tools. The stall is an MCP server: a separate program that offers tools. The customer's app is the MCP client, which lives inside your agent framework. Because the plug is the same everywhere, you stop writing glue code for each tool.

MCP（Model Context Protocol，模型上下文协议）就是智能体工具的这个共同二维码。摊位是 MCP 服务端：一个单独的程序，对外提供工具。顾客的 App 是 MCP 客户端，住在你的智能体框架里。插头到处都一样，你就不用为每个工具写一份胶水代码。

MCP is not magic. It is still just tools. The only new thing is that the tools live in someone else's program, and you plug them in the same way every time.

MCP 不是魔法，它还是工具。唯一新鲜的是：这些工具住在别人的程序里，而你每次都用同一种方式把它们接上。

your agent (inside a framework) | MCP client <-- same plug, every time --> MCP server |-- tools (actions the model can call) |-- resources (read-only data) '-- prompts (ready-made instructions)

Step 2 · Look inside a ready-made server第 2 步 · 先看看现成的服务端

Learn先学

Siew does not want to write a browser function. A local server is started as a subprocess on your own machine and talks to your code over stdio (standard input and output, like two programs passing notes through a pipe).

Siew 不想自己写浏览器函数。本地服务端会作为子进程在你自己的电脑上启动，并通过 stdio（标准输入输出，就像两个程序通过一根管子互传纸条）和你的代码对话。

Before giving a server to an agent, list its tools. The description and the input schema (the JSON that says what to pass in) are exactly what the model reads. Here we use the OpenAI Agents SDK as the client, as in the earlier SDK lessons.

把服务端交给智能体之前，先列出它的工具。工具的描述和输入格式（说明要传什么的 JSON）正是模型会读到的内容。这里用 OpenAI Agents SDK 作客户端，和之前的 SDK 课一样。

pip install openai-agents python-dotenv # plus Node + npx, or uv/uvx, to start servers from agents.mcp import MCPServerStdio fetch = {"command": "uvx", "args": ["mcp-server-fetch"]} async with MCPServerStdio(params=fetch, client_session_timeout_seconds=60) as server: tools = await server.list_tools() for t in tools: print(t.name, "-", t.description[:80]) print(t.inputSchema) # the JSON schema the model sees

Step 3 · Two servers, one agent第 3 步 · 两个服务端，一个智能体

Learn先学

Now Siew gets a real browser (the Playwright server) and a file server. The file server can read and write one folder only: you pass the folder as an argument, and nothing outside it is reachable.

现在 Siew 有了真正的浏览器（Playwright 服务端）和一个文件服务端。文件服务端只能读写一个文件夹：你把文件夹作为参数传进去，夹外的东西一概碰不到。

Both go into mcp_servers=[...]. The agent decides when to browse and when to write. You never wrote a browser or file function.

两个服务端一起放进 mcp_servers=[...]。什么时候上网、什么时候写文件由智能体决定，你一个浏览器函数或文件函数都没写。

import os from agents import Agent, Runner, trace box = os.path.abspath("sandbox"); os.makedirs(box, exist_ok=True) browser = {"command": "npx", "args": ["@playwright/mcp@latest"]} files = {"command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", box]} RULES = """You browse the web to get things done. Close cookie banners and pop-ups. If one site is useless, try another. Only write files inside sandbox/.""" async with MCPServerStdio(params=browser, client_session_timeout_seconds=60) as b, \ MCPServerStdio(params=files, client_session_timeout_seconds=60) as f: agent = Agent(name="recipe_hunter", instructions=RULES, model="gpt-4o-mini", mcp_servers=[b, f]) with trace("recipe_hunter"): res = await Runner.run(agent, "Find a good Penang asam laksa recipe and save a markdown summary to sandbox/laksa.md") print(res.final_output)
What I got wrong我踩过的坑I listed the tools inside the async with block, left the block, then tried to run the agent. It failed, because the server is a subprocess and it dies when the block ends. Create and run the agent inside the block. Two more traps: the first run is slow because npx and uvx download the server, so I set client_session_timeout_seconds=60 everywhere. And on Windows inside Jupyter, the launch can die with io.UnsupportedOperation: fileno. Wrapping the SDK's stdio_client with functools.partial(..., errlog=subprocess.DEVNULL) fixed it for me. An npx path with spaces can also break it.我在 async with 代码块里列出了工具，离开代码块后才去运行智能体，结果失败了：服务端是个子进程，代码块一结束它就没了。要在代码块里面创建并运行智能体。还有两个坑：第一次运行很慢，因为 npx 和 uvx 要先下载服务端，所以我到处都设了 client_session_timeout_seconds=60。另外在 Windows 的 Jupyter 里，启动可能报 io.UnsupportedOperation: fileno，用 functools.partial(..., errlog=subprocess.DEVNULL) 包住 SDK 的 stdio_client 就解决了。npx 路径带空格也可能出问题。

Step 4 · A remote server is just a URL第 4 步 · 远程服务端只是一个网址

Learn先学

Not every server has to run on your machine. A remote server is hosted by someone else, so you install nothing: you give a URL. It talks over streamable HTTP instead of stdio.

不是每个服务端都要跑在你的电脑上。远程服务端由别人托管，你什么都不用装，只要给一个网址。它走的是可流式 HTTP，而不是 stdio。

Try one that serves up-to-date library docs. A model alone often guesses at new features. With live docs it does not have to.

试试一个提供最新库文档的服务端。单靠模型，遇到新功能常常是瞎猜；有了实时文档，就不必猜了。

from agents.mcp import MCPServerStreamableHttp question = "In the latest version of the OpenAI Agents SDK, how do I filter which MCP tools an agent can see?" async with MCPServerStreamableHttp(name="docs", params={"url": "https://mcp.context7.com/mcp", "timeout": 60}) as docs: agent = Agent(name="docs_expert", instructions="Answer using the docs tools. Say so if unsure.", model="gpt-4o-mini", mcp_servers=[docs]) print((await Runner.run(agent, question)).final_output)

Step 5 · When to use MCP, and when not第 5 步 · 什么时候用 MCP，什么时候不用

Learn先学

Use it to plug in tools other people maintain (browser, files, search, a product's official server), or to share your own tools across several frameworks.

该用的时候：接入别人维护的工具（浏览器、文件、搜索、某个产品的官方服务端），或者想把自己的工具共享给好几个框架。

Skip it for one small function used by one agent: a plain @function_tool is simpler. And be careful. A server is code running on your machine with your permissions. Use servers from sources you trust, scope file servers to one folder, and read what a server's tools can do before handing them to an agent. Marketplaces list thousands of servers, which is exactly why caution matters.

不必用的时候：只有一个智能体用的一个小函数，直接用 @function_tool 更简单。还要小心：服务端是以你的权限在你电脑上运行的代码。只用你信任的来源，文件服务端限定在一个文件夹，把工具交给智能体之前先看清它们能做什么。市面上有列着成千上万个服务端的市场，所以更要谨慎。

Local stdio Remote HTTP Runs subprocess on my PC someone else's server Setup command + args url Good for files, browser, my code hosted services, docs, SaaS

Plain function tool or MCP server? Sort each case.

用普通函数工具，还是 MCP 服务端？逐个分类。

Now make it yours现在把它变成你的

Takeaways要点回顾

• MCP is a shared plug: a server offers tools, a client inside your framework uses them.
• It is still just tools. The new part is that they live in someone else's program.
• A server offers tools, resources (read-only data) and prompts.
• Local servers start as a subprocess over stdio. Remote ones are a URL over streamable HTTP.
• List a server's tools first: the description and schema are what the model reads.
• The server only lives inside async with, so run the agent in there. First runs are slow, so raise the timeout.
• A server runs with your permissions. Trust the source and fence the files.

• MCP 是共同的插头：服务端提供工具，框架里的客户端使用它们。
• 它依然只是工具，新鲜的只是工具住在别人的程序里。
• 服务端可以提供工具、资源（只读数据）和提示词。
• 本地服务端作为子进程，通过 stdio 通信；远程服务端是一个网址，走可流式 HTTP。
• 先列出服务端的工具：描述和输入格式就是模型读到的内容。
• 服务端只活在 async with 里，所以要在里面运行智能体；第一次很慢，把超时设长一点。
• 服务端以你的权限运行：信任来源，圈好文件范围。
