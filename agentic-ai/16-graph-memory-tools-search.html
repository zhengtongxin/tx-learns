Step 1 · create_agent: the tool loop in one line第 1 步 · create_agent：一行搞定工具循环

Learn先学

Last lesson you wired a model node, a tools node and a conditional edge yourself. create_agent hands you the same graph ready-made. You give it a model as a "provider:model" string, some tools and a system prompt. It is a real LangGraph graph underneath: a model node and a tools node going round in a loop.

上一课你亲手接了模型节点、工具节点和条件边。create_agent 直接给你一张现成的同样的图。你只要给它一个 "provider:model" 形式的模型字符串、几件工具和一段系统提示词。底下仍然是一张真正的 LangGraph 图：模型节点和工具节点绕着圈。

pip install langchain langchain-openai langgraph langchain-community langchain-mcp-adapters deepagents # env: OPENAI_API_KEY, SERPER_API_KEY
from langchain.agents import create_agent from langchain_core.tools import tool @tool def stall_price(item: str) -> str: """Typical price in S$ for a breakfast item near schools in Jurong East.""" return {"nasi lemak": "S$3.50", "kuih": "S$0.80 each", "milo ais": "S$2.80"}.get(item.lower(), "not sure") @tool def footfall(hour: int) -> str: """Rough number of parents passing the shop at a given hour (24h).""" return "about 120" if 7 <= hour <= 8 else "under 30" helper = create_agent( model="openai:gpt-5.4-mini", tools=[stall_price, footfall], system_prompt="You help a small shop owner plan a breakfast corner. Use your tools for numbers.", ) out = helper.invoke({"messages": [{"role": "user", "content": "Is 7:30am busy, and what does nasi lemak go for?"}]}) print(out["messages"][-1].content)

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

Yes, 7:30am is busy: about 120 parents pass the shop then. Nasi lemak goes for around S$3.50 nearby.

Step 2 · Memory and structured output第 2 步 · 记忆与结构化输出

Learn先学

Memory works the same way as in a graph: a checkpointer plus a thread_id. If you want the answer as data instead of prose, pass a response_format. The reply then carries a structured_response that is already filled in, ready for your code.

记忆的做法和图里一样：检查点加 thread_id。如果你想要的是数据而不是一段话，就传入 response_format。回复里会带一个已经填好的 structured_response，可以直接给代码用。

from langgraph.checkpoint.memory import MemorySaver from pydantic import BaseModel, Field chatty = create_agent(model="openai:gpt-5.4-mini", tools=[stall_price], checkpointer=MemorySaver()) cfg = {"configurable": {"thread_id": "cousin-hui"}} chatty.invoke({"messages": [{"role": "user", "content": "My budget is S$800 for equipment."}]}, cfg) class Plan(BaseModel): items: list[str] = Field(description="Breakfast items to sell") est_daily_sales: str = Field(description="Rough daily sales estimate in S$") planner = create_agent(model="openai:gpt-5.4-mini", tools=[stall_price, footfall], response_format=Plan) plan = planner.invoke({"messages": [{"role": "user", "content": "Plan the menu."}]})["structured_response"]

Step 3 · Middleware: code at fixed points in the loop第 3 步 · 中间件：在循环固定位置运行的代码

Learn先学

Sometimes you want to peek into the loop without rewriting it. Middleware is code that runs at fixed points: before the model call, or around each tool call. Think of a supervisor who watches every slip pass by. This one prints every tool call, which is my favourite debugging trick. Ready-made ones exist too: summarising long chats, hiding personal data, limiting calls and retrying.

有时你想看一眼循环里面，又不想重写它。中间件是在固定位置运行的代码：模型调用之前，或者每次工具调用的前后。就像一位盯着每张单子经过的主管。下面这个会把每次工具调用都打印出来，是我最爱的调试办法。也有现成的：总结过长的对话、隐藏个人信息、限制调用次数和重试。

from langchain.agents.middleware import wrap_tool_call @wrap_tool_call def spy(request, handler): print("tool ->", request.tool_call["name"], request.tool_call["args"]) return handler(request) watched = create_agent(model="openai:gpt-5.4-mini", tools=[stall_price], middleware=[spy])

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

tool -> stall_price {'item': 'nasi lemak'}

Step 4 · Tools someone else wrote: MCP and a real browser第 4 步 · 别人写好的工具：MCP 与真正的浏览器

Learn先学

Tools do not have to be your own Python functions. MCP is a standard plug that lets an agent use tools someone else wrote (it gets its own topic later). With langchain-mcp-adapters you load the tools an MCP server offers. The Playwright server gives your agent a real browser, and needs Node and npx. These tools are async, so the call changes from invoke to await ainvoke. In a notebook you can await at the top level; in a .py file wrap it in async def, as before.

工具不一定是你自己写的 Python 函数。MCP 是一种标准插头，让智能体使用别人写好的工具（后面有专门的主题）。用 langchain-mcp-adapters 就能载入某个 MCP 服务提供的工具。Playwright 服务给你的智能体一个真正的浏览器，需要 Node 和 npx。这些工具是异步的，所以调用要从 invoke 改成 await ainvoke。笔记本里可以在最外层直接 await；在 .py 文件里则要像之前那样包进 async def。

from langchain_mcp_adapters.client import MultiServerMCPClient client = MultiServerMCPClient({ "browser": {"transport": "stdio", "command": "npx", "args": ["-y", "@playwright/mcp@latest", "--isolated"]}, }) browser_tools = await client.get_tools() surfer = create_agent(model="openai:gpt-5.4-mini", tools=browser_tools, system_prompt="Browse to answer. Report briefly.") res = await surfer.ainvoke({"messages": [{"role": "user", "content": "Open a food delivery site and list three breakfast places in Jurong East."}]})

Step 5 · The big job: a deep agent第 5 步 · 大任务：深度智能体

Learn先学

Hui's full briefing needs planning, lots of searching, a file to write and helpers. A deep agent is create_agent with a harness added: a todo list for planning, file tools (write_file, read_file) and a task tool to delegate to sub-agents. Each sub-agent starts with a fresh context, so the lead's context stays small. virtual_mode=True keeps every file inside one folder.

惠的完整报告需要做计划、大量搜索、写文件，还要有帮手。深度智能体就是在 create_agent 外面加一层外壳：用来做计划的待办清单、文件工具（write_file、read_file），以及把工作交给子智能体的 task 工具。每个子智能体都从全新的上下文开始，所以主智能体的上下文不会变大。virtual_mode=True 让所有文件都留在同一个文件夹里。

import os from langchain_openai import ChatOpenAI from langchain_community.tools import GoogleSerperRun from langchain_community.utilities import GoogleSerperAPIWrapper from deepagents import create_deep_agent from deepagents.backends import FilesystemBackend box = os.path.abspath("workspace"); os.makedirs(box, exist_ok=True) search = GoogleSerperRun(api_wrapper=GoogleSerperAPIWrapper()) competitor_scout = { "name": "competitor-scout", "description": "Looks up one nearby breakfast competitor and returns three facts: menu, prices, hours.", "system_prompt": "Research the single shop you are given with the search tool. Return three short facts.", } lead = create_deep_agent( model=ChatOpenAI(model="gpt-5.4-mini"), tools=[search], subagents=[competitor_scout], system_prompt="Plan with your todos, delegate each competitor to competitor-scout, " "then write a one-page markdown briefing with a recommendation.", backend=FilesystemBackend(root_dir=box, virtual_mode=True), ) lead.invoke({"messages": [{"role": "user", "content": "Should a tuition centre in Jurong East sell breakfast to parents? Write breakfast.md."}]})
Learn先学

Sub-agents can have their own tools and skills. A skill is a folder with a SKILL.md: a name and description at the top, instructions below. Only the name and description sit in the prompt. The full file is read when it is needed, so skills cost almost nothing until used.

子智能体可以有自己的工具和技能（skill）。技能是一个带 SKILL.md 的文件夹：开头是名称和描述，下面是详细说明。提示词里只放名称和描述，需要时才读完整文件，所以技能在被用到之前几乎不占成本。

What I got wrong我搞错的地方Three things tripped me. First, MCP tools only work with ainvoke: calling invoke fails, and once one async tool is in, the whole call goes async. Second, deep agent paths are virtual: the agent writes /breakfast.md, which lands inside my workspace folder, not at my real root. I was confused until I looked in that folder. Third, a deep agent is overkill for a two-tool question, and create_agent is cheaper and faster. On Windows with Jupyter, starting a stdio MCP server can also fail because the notebook's error stream is not a real file. The fix is to send the adapter's errlog to subprocess.DEVNULL. Mac and Linux do not need it.我栽过三个跟头。第一，MCP 工具只能用 ainvoke：用 invoke 会失败，只要混进一个异步工具，整个调用就要改成异步。第二，深度智能体的路径是虚拟的：它写的是 /breakfast.md，实际落在我的工作文件夹里，而不是真正的根目录，我看了那个文件夹才弄明白。第三，两件工具的小问题用深度智能体是杀鸡用牛刀，create_agent 更便宜也更快。另外在 Windows 的 Jupyter 里启动 stdio 的 MCP 服务可能失败，因为笔记本的错误输出流不是真正的文件，解决办法是把适配器的 errlog 指向 subprocess.DEVNULL。Mac 和 Linux 不需要。

What changed这一课之后Now the Kopi Corner assistant keeps memory per thread, calls tools and searches the web inside the graph, so Auntie Suria's “kopi-C kurang manis” survives to the next morning. The next problem is that it needs one helper that truly remembers a person.现在 Kopi Corner 助手在图里按线程保存记忆、调用工具并联网搜索，Suria 阿姨记下的“少甜咖啡 C”第二天还在。下一个问题是：它需要一个真正记得住某个人的助手。

Common errors常见错误

• openai.AuthenticationError: Error code: 401: OPENAI_API_KEY is not set in this process. Fix: load .env before you create the agent.
• openai.NotFoundError: Error code: 404 - The model `gpt-5.4-mni` does not exist: A typo in the model name. Fix: copy the name exactly, and keep the explicit provider:model form, such as "openai:gpt-5.4-mini".
• RuntimeError: This event loop is already running / 'coroutine' was never awaited: MCP tools are async. Fix: use await agent.ainvoke(...) instead of invoke for them.

• openai.AuthenticationError: Error code: 401：这个进程里没有 OPENAI_API_KEY。解决：创建智能体之前先加载 .env。
• openai.NotFoundError: Error code: 404 - The model `gpt-5.4-mni` does not exist：模型名拼错了。解决：原样复制模型名，并保留明确的 服务商:模型 写法，例如 "openai:gpt-5.4-mini"。
• RuntimeError: This event loop is already running / 'coroutine' was never awaited：MCP 工具是异步的。解决：对它们用 await agent.ainvoke(...)，不要用 invoke。

Takeaways要点回顾

• create_agent is the model-and-tools loop in one line. Underneath it is still a graph.
• Memory is a checkpointer plus a thread_id. response_format gives you data back as structured_response.
• Middleware runs at fixed points in the loop: spy, summarise, hide personal data, limit, retry.
• MCP tools come from someone else's server. They are async, so use await ainvoke.
• A deep agent adds a todo list, files and sub-agents. It is for big jobs, not small questions.
• Sub-agents start with a fresh context. Skills load their full text only when needed.
• Deep agent file paths are virtual: they live inside the folder you chose.

• create_agent 一行就是“模型加工具”的循环，底下仍然是一张图。
• 记忆就是检查点加 thread_id。response_format 让你以 structured_response 拿回数据。
• 中间件在循环的固定位置运行：监视、总结、隐藏个人信息、限制、重试。
• MCP 工具来自别人的服务，是异步的，所以要用 await ainvoke。
• 深度智能体多了待办清单、文件和子智能体，适合大任务，不适合小问题。
• 子智能体从全新上下文开始。技能只有在需要时才载入完整内容。
• 深度智能体的文件路径是虚拟的：实际都在你选定的文件夹里。

Recap三句回顾

• create_agent gives you a tool-calling loop; the tools are plain functions with a docstring.
• Middleware watches or changes every model and tool call without touching the tools.
• Memory is a checkpointer per thread; MCP servers plug in more tools.

• create_agent 给你一个会调用工具的循环；工具就是带说明文字的普通函数。
• 中间件可以观察或修改每一次模型和工具调用，而不用改工具本身。
• 记忆是按会话保存的存档器；MCP 服务可以接入更多工具。
