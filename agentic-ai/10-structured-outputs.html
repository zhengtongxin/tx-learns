Structured outputs结构化输出

Turn an AI's opinion into data your code can check · ~25 min · hands-on把 AI 的“意见”变成代码能检查的数据 · 约 25 分钟 · 动手实践

Step 1 · A form, not a paragraph第 1 步 · 要一张表，不要一段话

Learn先学

Example: a coffee shop checks its monthly email to regulars before sending. A paragraph hides a leftover “[Customer Name]” or a wrong price, and code cannot read a paragraph. So describe the answer as a form: a class (a template with named boxes) written with Pydantic, which checks each box holds the right type. Pass it as output_type. The SDK turns it into a JSON schema (a description of the form that models read), asks the model to answer in that shape, and hands you a real object.

示例：咖啡店在发月度邮件给老顾客之前先检查。一段话会藏住没替换的“[Customer Name]”或错误的价格，代码又读不懂一段话。所以把答案描述成一张表：用 Pydantic 写一个类（带命名格子的模板），它会检查每个格子的类型。把它作为 output_type 传入，SDK 会把它变成 JSON schema（模型能读的表格描述），要求模型按这个形状回答，并交给你一个真正的对象。

from pydantic import BaseModel, Field from agents import Agent, Runner class EmailCheck(BaseModel): is_friendly: bool = Field(description="Warm and polite, the way a shop owner talks to regulars") has_placeholders: bool = Field(description="Contains leftover blanks like [Customer Name] or {name}") price_mentioned: str = Field(description="The price of the breakfast set as written, or '' if none") checker = Agent(name="Checker", instructions="You check shop emails before they are sent", model="gpt-5.4-mini", output_type=EmailCheck) result = await Runner.run(checker, draft) check = result.final_output # an EmailCheck object, not a string
Learn先学

The Field(description=...) text is what the model reads, so write it like an instruction. EmailCheck.model_json_schema() prints the schema it sees. Not every provider supports structured outputs, so keep the checker on one that does. price_mentioned asks the model to copy the price, not judge it: your code knows the right price.

Field(description=...) 的文字是模型读的，要像写指令一样写。EmailCheck.model_json_schema() 会打印它看到的 schema。并非每家提供商都支持结构化输出，检查员要放在支持的模型上。price_mentioned 让模型原样抄下价格而不是判断对错：知道正确价格的是你的代码。

Step 2 · The checker is just an if第 2 步 · 检查员其实就是一个 if

Learn先学

Once the answer is data, a safety check is ordinary Python: run the writer, run the checker, decide. It works in any framework.

答案一旦变成数据，安全检查就是普通的 Python：跑写手、跑检查员、做判断。在任何框架里都能用。

writer = Agent(name="Writer", instructions="You write friendly emails for a coffee shop.", model="gpt-5.4-mini") def send_message(subject, body): # stand-in: swap in your real email sender print("SENT:", subject) draft = (await Runner.run(writer, "Write this month's email")).final_output check = (await Runner.run(checker, draft)).final_output if check.has_placeholders or not check.is_friendly or check.price_mentioned != "S$8.50": print("Not sending, fix the draft first") else: send_message("This month's breakfast set", draft)

Step 3 · Optional: a guardrail第 3 步 · 可选：护栏

Learn先学

An output guardrail runs the same check for you around an agent. It returns tripwire_triggered=True when something is wrong, and the SDK stops the run with an error you catch. Keep the whole EmailCheck in output_info to see why it tripped. It only runs on the agent giving the final answer, not on a writer used as a tool.

输出护栏在智能体周围替你运行同样的检查。发现问题时返回 tripwire_triggered=True，SDK 随即叫停运行并抛出一个由你捕获的错误。把完整的 EmailCheck 放进 output_info，就能看到为什么被拦下。它只在给出最终答案的智能体上运行，不会在被当作工具的写手上运行。

from agents import output_guardrail, GuardrailFunctionOutput, OutputGuardrailTripwireTriggered @output_guardrail async def shop_email_check(ctx, agent, message): check = (await Runner.run(checker, message, context=ctx.context)).final_output bad = check.has_placeholders or not check.is_friendly or check.price_mentioned != "S$8.50" return GuardrailFunctionOutput(output_info={"check": check}, tripwire_triggered=bad) # the same writer as Step 2, now with the guardrail attached writer = Agent(name="Writer", instructions="You write friendly emails for a coffee shop.", model="gpt-5.4-mini", output_guardrails=[shop_email_check]) try: result = await Runner.run(writer, "Write this month's email") except OutputGuardrailTripwireTriggered: print("Checker said no, nothing was sent")

Now make it yours现在把它变成你的

Takeaways要点回顾

• Structured output is a typed object instead of a paragraph: a Pydantic class passed as output_type.
• Field(description=...) is what the model reads; check it with model_json_schema().
• Ask for facts to copy (the price as text), then compare in code.
• Not every model supports structured outputs; keep the checker on one that does.
• Once an opinion is data, a guardrail is just an if.

• 结构化输出是有类型的对象，而不是一段话：把 Pydantic 类作为 output_type 传入。
• 模型读的是 Field(description=...)，可用 model_json_schema() 查看。
• 让模型抄下事实（价格文字），再用代码比较。
• 并非所有模型都支持结构化输出，检查员要放在支持的模型上。
• “意见”一旦变成数据，护栏就只是一个 if。
