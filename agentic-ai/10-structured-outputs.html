Agent SDKs · Lesson 3智能体 SDK · 第 3 课

Structured outputs and a checker agent结构化输出与检查员智能体

Turn an AI's opinion into data your code can check · ~25 min · hands-on把 AI 的“意见”变成代码能检查的数据 · 约 25 分钟 · 动手实践

Where we left off上回讲到

Last time the assistant could draft the monthly note to regulars, but every reply came back as free text. Today it fails when Auntie Suria needs an order that code can check, and a paragraph gives it nothing to check. We fix it by asking for a fixed form and adding a checker agent.

上回助手学会了给老顾客写每月的通知，但每次回复都是自由文本。今天的问题是：Suria 阿姨需要一张代码能检查的订单，而一段文字没有什么可检查。我们的办法是要求固定格式的表格，再加一个检查员智能体。

The story故事

Uncle Lim runs a small kopitiam (a neighbourhood coffee shop) and emails his regulars every month. This month there is a new breakfast set: kaya toast, soft-boiled eggs and kopi for RM8.50. Three writer agents, each on a different model provider, draft the announcement. A manager picks the best one. Then a checker agent makes sure nothing embarrassing goes out: a leftover “[Customer Name]”, a rude tone, a wrong price.

Lim 叔叔开了一家小小的 kopitiam（街坊咖啡店），每个月给老顾客发邮件。这个月有新的早餐套餐：咖椰吐司、半熟蛋加咖啡，RM8.50。三个写手智能体分别跑在不同的模型提供商上，各写一版公告；主管挑出最好的一版；最后由检查员智能体确保不会发出尴尬的内容：忘了替换的“[Customer Name]”、无礼的语气、写错的价格。

Step 1 · One team, many model providers第 1 步 · 一个团队，多家模型提供商

Learn先学

Uncle Lim wants to compare drafts from different “brains”. In “Many models, one API” you saw that many providers speak the same language if you change the base_url. The SDK uses the same trick. Three steps per provider: find its OpenAI-compatible URL, make a client (the small object that carries your messages to that provider's server) with that URL and your key, then wrap the client as a model and give it to the Agent. As in the outreach helper, each writer becomes a tool for the manager with .as_tool(), and the manager also gets a send_email tool, a plain Python function marked @function_tool. This step is the warm-up. The main idea starts in Step 2.

Lim 叔叔想比较不同“大脑”写出的草稿。在《多个模型，同一套 API》里你见过：只要换掉 base_url，很多提供商都说同一种“语言”。SDK 用的是同一招。每家提供商三步：找到它兼容 OpenAI 的网址；用这个网址和你的密钥建一个客户端（把你的消息送到该提供商服务器的小对象）；把客户端包成模型，交给 Agent。和外联邮件助手一样，每个写手通过 .as_tool() 变成主管的工具，主管还多一个 send_email 工具：一个标了 @function_tool 的普通 Python 函数。这一步只是热身，重点从第 2 步开始。

# imports as in "Many models, one API": os, AsyncOpenAI, and Agent, OpenAIChatCompletionsModel from agents shop_voice = "You write friendly emails for Uncle Lim's kopitiam." # shared by all three writers other = AsyncOpenAI(base_url=OTHER_BASE_URL, api_key=os.getenv("OTHER_API_KEY")) writer_a = Agent(name="Writer A", instructions=shop_voice, model=OpenAIChatCompletionsModel(model="some-model-name", openai_client=other)) manager = Agent(name="Manager", model="gpt-5.4-mini", # plain string: an OpenAI model tools=[writer_a.as_tool(tool_name="writer_a", tool_description="Writes one draft"), writer_b.as_tool(...), writer_c.as_tool(...), # made the same way as writer_a send_email]) # send_email: a @function_tool that sends the chosen draft

Step 2 · Structured output: a form, not a paragraph第 2 步 · 结构化输出：要一张表，不要一段话

Learn先学

Normally a model gives you a paragraph, and your code would have to read it like a human. Instead, describe the shape of the answer as a form. Think of the card a waiter fills in: table number, dish, spicy or not. In Python you write that form as a class, a template with named boxes, using Pydantic, a library that checks each box holds the right type (true/false, text, number). Pass it as output_type and the SDK turns it into a JSON schema (a description of the form in the plain text format models read and write), asks the model to answer in that shape, and hands you a real object.

通常模型给你一段文字，代码得像人一样去“读”。换个办法：把答案的形状描述成一张表，就像服务员手里的点菜单：桌号、菜名、辣不辣。在 Python 里，这张表写成一个类，也就是带有命名格子的模板；我们用 Pydantic 来写，这个库会检查每个格子填的类型对不对（真/假、文字、数字）。把它作为 output_type 传入，SDK 会把它变成 JSON schema（用模型能读写的纯文本格式描述这张表），要求模型按这个形状回答，并交给你一个真正的对象。

from pydantic import BaseModel, Field from agents import Agent, Runner class EmailCheck(BaseModel): is_friendly: bool = Field(description="Warm and polite, the way a shop owner talks to regulars") has_placeholders: bool = Field(description="Contains leftover blanks like [Customer Name] or {name}") price_mentioned: str = Field(description="The price of the breakfast set as written, or '' if none") checker = Agent(name="Checker", instructions="You check shop emails before they are sent", model="gpt-5.4-mini", output_type=EmailCheck) result = await Runner.run(checker, draft) check = result.final_output # an EmailCheck object, not a string if check.has_placeholders: ...

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

EmailCheck(is_friendly=True, has_placeholders=True, price_mentioned='RM5.50') Not sending, fix the draft first
Learn先学

Two details matter. The Field(description=...) text is what the model reads to know what goes in each box, so write it like an instruction. And EmailCheck.model_json_schema() prints the exact schema the model sees; look at it once. Some providers go further and force the answer to match the form, so it can never come back broken. Not every provider supports structured outputs, so keep the checker on one that does.

有两个细节很重要。Field(description=...) 里的文字是模型用来理解每个格子该填什么的，所以要像写指令一样写。EmailCheck.model_json_schema() 会打印模型实际看到的 schema，值得看一次。有些提供商更进一步，强制答案必须符合这张表，所以永远不会返回坏掉的结果。但不是每家都支持结构化输出，所以检查员要放在支持的模型上。

Step 3 · The checker is just an if第 3 步 · 检查员其实就是一个 if

Learn先学

Now the payoff. Once the answer is data, a safety check is ordinary Python. Run the writer, run the checker, and decide. This works in any framework, is easy to read, and you can put the same check inside the send_email tool from Step 1 so a bad email can never leave. This plain if is all you need to start.

收获的时刻到了。答案一旦变成数据，安全检查就是普通的 Python：先跑写手，再跑检查员，然后做判断。这在任何框架里都能用，容易读，而且你还可以把同样的检查放进第 1 步的 send_email 工具里，让坏邮件根本发不出去。刚开始，有这个普通的 if 就够了。

draft = (await Runner.run(writer, "Write this month's email")).final_output check = (await Runner.run(checker, draft)).final_output if check.has_placeholders or not check.is_friendly or check.price_mentioned != "RM8.50": print("Not sending, fix the draft first") else: send_message("This month's breakfast set", draft) # a plain helper that sends the email (not the agent tool from Step 1); see the outreach helper lesson
Learn先学

Optional, once the if works: a guardrail is a check the SDK runs for you around an agent, and an output guardrail checks the agent's answer. It returns tripwire_triggered=True when something is wrong, like a trip wire across a doorway, and the SDK then stops the run with OutputGuardrailTripwireTriggered, an error you catch. Keep the whole EmailCheck in output_info so you can see why it tripped. The rule from the guardrails lesson still holds: an output guardrail only runs on the agent that gives the final answer. A writer used as a tool inside the manager never triggers its own.

可选内容，等 if 跑通后再看：护栏是 SDK 在智能体周围替你运行的检查，输出护栏检查的是智能体的回答。发现问题时它返回 tripwire_triggered=True，就像门口拉了一根绊线；SDK 随即用 OutputGuardrailTripwireTriggered 叫停运行，这是一个由你捕获的错误。把完整的 EmailCheck 放进 output_info，就能看到为什么被拦下。护栏那一课的规则依然成立：输出护栏只在给出最终答案的智能体上运行；被当作工具放在主管里的写手，不会触发它自己的护栏。

from agents import output_guardrail, GuardrailFunctionOutput, OutputGuardrailTripwireTriggered @output_guardrail async def shop_email_check(ctx, agent, message): # ctx: run details, you can ignore it for now check = (await Runner.run(checker, message, context=ctx.context)).final_output # message: the writer's answer; pass ctx.context along as is bad = check.has_placeholders or not check.is_friendly or check.price_mentioned != "RM8.50" return GuardrailFunctionOutput(output_info={"check": check}, tripwire_triggered=bad) writer = Agent(name="Writer", instructions=shop_voice, # shop_voice from Step 1 output_guardrails=[shop_email_check]) try: result = await Runner.run(writer, "Write this month's email") except OutputGuardrailTripwireTriggered: print("Checker said no, nothing was sent")

Sort each email by what the checker would report.

按检查员会给出的结果，给每封邮件分类。

What I got wrong我犯过的错First, I forgot output_type and got a paragraph back, then wrote result.final_output.is_friendly and hit an AttributeError on a string. Second, one provider ignored the schema completely, so the checker stays on a model that supports structured outputs. Third, I first asked for price_is_correct: bool, but then the model has to know the right price. Asking it to copy the price as text and comparing in code was far more reliable.第一，我忘了写 output_type，拿回一段文字，然后写 result.final_output.is_friendly，对字符串报了 AttributeError。第二，有一家提供商完全无视 schema，所以检查员要放在支持结构化输出的模型上。第三，我一开始让模型填 price_is_correct: bool，但这样模型得知道正确价格。改成让它原样抄下价格文字，再用代码比较，可靠得多。

Now make it yours现在把它变成你的

What changed这一课之后Now the assistant hands Auntie Suria a clean order (item, size, price in RM), like Uncle Lim's printed price list, and a checker agent holds back any note with a wrong price, such as the RM8.50 breakfast set. The next problem is that it knows nothing outside the shop.现在助手交给 Suria 阿姨的是一张干净的订单（品名、大小、价钱 RM），就像 Lim 叔叔印好的价目表；检查员智能体会拦下价钱错误的通知，比如 RM8.50 的早餐套餐。下一个问题是：它对店外的事一无所知。

Common errors常见错误

• pydantic_core._pydantic_core.ValidationError: 1 validation error for EmailCheck: The model's answer did not fit your schema (a field is missing or the wrong type). Fix: make each Field(description=...) clearer, or simplify the schema.
• agents.exceptions.OutputGuardrailTripwireTriggered: Guardrail tripped: The checker said no, which is the design. Fix: catch it, print what was wrong and let the writer try again.
• AttributeError: 'str' object has no attribute 'has_placeholders': The agent has no output_type, so final_output is plain text. Fix: pass output_type=EmailCheck when you build the checker.

• pydantic_core._pydantic_core.ValidationError: 1 validation error for EmailCheck：模型的回答不符合你的结构（缺字段或类型不对）。解决：把每个 Field(description=...) 写得更清楚，或简化结构。
• agents.exceptions.OutputGuardrailTripwireTriggered: Guardrail tripped：检查员说“不行”，这正是设计的用意。解决：接住异常，打印问题所在，让写手再试一次。
• AttributeError: 'str' object has no attribute 'has_placeholders'：智能体没设置 output_type，所以 final_output 只是普通文字。解决：创建检查员时传入 output_type=EmailCheck。

Takeaways要点回顾

• Change base_url, wrap the client in OpenAIChatCompletionsModel, and one team can use many providers.
• Structured output means a typed object instead of a paragraph.
• Describe the shape as a Pydantic class and pass it as output_type.
• Field(description=...) is what the model reads. Check it with model_json_schema().
• Not every model supports structured outputs. Keep the checker on one that does.
• Ask for facts to copy (the price as text), then compare in code.
• Structured output turns an opinion into data, so a guardrail is just an if.

• 换掉 base_url，用 OpenAIChatCompletionsModel 包住客户端，一个团队就能用多家提供商。
• 结构化输出就是拿回有类型的对象，而不是一段文字。
• 用 Pydantic 类描述形状，作为 output_type 传入。
• 模型读的是 Field(description=...)，可用 model_json_schema() 查看。
• 并非所有模型都支持结构化输出，检查员要放在支持的模型上。
• 让模型抄下事实（价格文字），再用代码比较。
• 结构化输出把“意见”变成数据，于是护栏就只是一个 if。
