Research assistant研究助手

Turn one big question into a report in your inbox, with four small agents and plain Python · ~30 min · hands-on用四个小智能体加普通 Python，把一个大问题变成收件箱里的一份报告 · 约 30 分钟 · 动手实践

Step 1 · The planner returns a plan第 1 步 · 规划员交出一份计划

Learn先学

Example: a small coffee shop asks, “What is the cheapest way to take cashless payments?” The answer lives on the web, so we build four small agents: plan, search, write, deliver. The planner thinks and does not search. Its answer must be a list your code can loop over, so it uses structured output. Put why before query: the model thinks of the reason first, and the search comes out better.

示例：一家小咖啡店问：“最便宜的无现金收款方式是什么？”答案在网上，所以我们做四个小智能体：规划、搜索、写作、送达。规划员负责思考，不搜索。它的答案必须是代码能逐项处理的列表，所以用结构化输出。把 why 放在 query 前面：模型先想理由，搜索会更准。

from pydantic import BaseModel, Field from agents import Agent class SearchIdea(BaseModel): why: str = Field(description="Why this search helps answer the question.") query: str = Field(description="The exact words to type into a web search.") class SearchPlan(BaseModel): searches: list[SearchIdea] = Field(description="The web searches to run.") planner = Agent(name="Planner", model="gpt-5.4-mini", output_type=SearchPlan, instructions="You plan research. Given a question, list 3 web searches that together answer it.")

Step 2 · Search at the same time第 2 步 · 同时搜索

Learn先学

A hosted tool runs on the provider's servers: add WebSearchTool() to the agent. Each search is charged, so keep tests to three. tool_choice="required" stops the searcher answering from memory. asyncio.gather sends all searches off together, so three take about as long as one.

托管工具跑在提供商的服务器上：把 WebSearchTool() 加进智能体即可。每次搜索都收费，测试时保持三个。tool_choice="required" 让搜索员不能凭记忆作答。asyncio.gather 把所有搜索一起派出去，所以三个的耗时和一个差不多。

import asyncio from agents import Agent, Runner, ModelSettings, WebSearchTool # one file, research.py: this box goes under Step 1, so SearchIdea, SearchPlan and planner are already defined searcher = Agent( name="Searcher", instructions="You get one search term. Search the web and summarise what you find in under 300 words.", model="gpt-5.4-mini", tools=[WebSearchTool()], model_settings=ModelSettings(tool_choice="required"), ) async def search_one(idea: SearchIdea) -> str: result = await Runner.run(searcher, f"Search term: {idea.query}\nWhy: {idea.why}") return result.final_output async def search_all(search_plan: SearchPlan) -> list[str]: jobs = [search_one(idea) for idea in search_plan.searches] return await asyncio.gather(*jobs) # * hands gather each job separately

Step 3 · Write and deliver第 3 步 · 写作与送达

Learn先学

The writer turns the question and every summary into a structured Report. The mailroom agent turns it into an HTML email and sends it with a @function_tool that wraps a plain send_message helper (built like the one in the outreach lesson, with SMTP settings in .env). While testing, SEND_EMAIL = False only prints.

写作员把问题和每份摘要写成结构化的 Report。收发室智能体把它排成 HTML 邮件，用一个包着普通 send_message 辅助函数的 @function_tool 发出去（做法同外联邮件那一课，SMTP 设置在 .env 里）。测试时用 SEND_EMAIL = False 只打印。

from agents import function_tool from pydantic import BaseModel, Field # same file, so Agent and Runner are already imported above class Report(BaseModel): summary: str = Field(description="The answer in 2-3 sentences.") report_md: str = Field(description="The full report in markdown, with headings.") writer = Agent(name="Writer", model="gpt-5.4-mini", output_type=Report, instructions="You write a clear research report for a small business owner from the search summaries.") async def write(question: str, findings: list[str]) -> Report: return (await Runner.run(writer, f"Question: {question}\nSearch summaries: {findings}")).final_output SEND_EMAIL = False # True = really send def send_message(subject, text_body, html_body): # plain helper: SMTP as in the outreach lesson if not SEND_EMAIL: print("Not sent:", subject); return ... @function_tool def send_report(subject: str, text_body: str, html_body: str) -> str: """Email the finished report to me.""" send_message(subject, text_body, html_body) return "Sent" mailroom = Agent(name="Mailroom", model="gpt-5.4-mini", tools=[send_report], instructions="You get a report in markdown. Make a clean HTML email and send it with send_report.")

Step 4 · Code is the boss第 4 步 · 由代码当老板

Learn先学

The recipe never changes (plan, search, write, deliver), so your own Python runs the steps in order. It is predictable and you know which step broke; a manager agent could skip a step or loop. Wrap the run in with trace(...) to see every agent and search in one record. Check the sources before trusting any number: fees change.

流程永远不变（规划、搜索、写作、送达），所以让你自己的 Python 按顺序执行。结果可预期，也知道哪一步出了问题；主管智能体可能漏掉一步或转圈。用 with trace(...) 包住运行，就能在一条记录里看到每个智能体和搜索。相信任何数字之前先核对来源：费用会变。

from agents import trace # last box of the same file: planner, search_all, write and mailroom are above QUESTION = "What is the cheapest way for a small coffee shop in Singapore to take cashless payments in 2026?" async def main(): with trace("Payments research"): search_plan = (await Runner.run(planner, f"Question: {QUESTION}")).final_output findings = await search_all(search_plan) report = await write(QUESTION, findings) await Runner.run(mailroom, report.report_md) print(report.summary) asyncio.run(main()) # in a notebook, write: await main()

Now make it yours现在把它变成你的

Takeaways要点回顾

• Deep research is one pattern: plan, search, write, deliver.
• A hosted tool like WebSearchTool() runs on the provider's side and is charged per call.
• Structured output lets the planner return a list your code can loop over.
• asyncio.gather runs searches together.
• For a fixed recipe, plain Python in charge beats a manager agent.

• 深度研究只有一个套路：规划、搜索、写作、送达。
• WebSearchTool() 这样的托管工具跑在提供商那边，按次收费。
• 结构化输出让规划员交出代码能逐项处理的列表。
• asyncio.gather 让搜索同时进行。
• 流程固定时，普通 Python 当老板胜过主管智能体。
