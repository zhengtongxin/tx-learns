Project: a research assistant项目：研究助手

Turn one big question into a report in your inbox, with four small agents and plain Python · ~30 min · hands-on用四个小智能体加普通 Python，把一个大问题变成收件箱里的一份报告 · 约 30 分钟 · 动手实践

Where we left off上回讲到

Last time the assistant returned clean, checked orders, but it knew nothing outside the shop. Today it fails when Uncle Lim asks what a PayNow QR code really costs, because that answer lives on the web. We fix it by adding agents that plan, search, write and email a report to Aina.

上回助手能交出干净、检查过的订单，但对店外的事一无所知。今天的问题是：Lim 叔叔问 PayNow 二维码到底要多少钱，答案在网上。我们的办法是加几个智能体，负责规划、搜索、写作，再把报告发给 Aina。

The story故事

Aina helps her Uncle Lim at his kopitiam in Singapore. Customers keep asking “can scan or not?” (can I scan to pay?). Uncle Lim wants the cheapest way to take cashless payments: a PayNow QR code, an e-wallet such as GrabPay or PayLah!, or a card terminal. What are the fees, and how does he set each one up? Aina could lose a whole evening to googling. Instead she builds a research helper: one agent plans the searches, another runs them, a third writes the report, and a fourth emails it to her.

Aina 在新加坡帮她的 Lim 叔叔打理 kopitiam（街坊咖啡店）。顾客总问“can scan or not?”（能扫码付款吗？）。Lim 叔叔想知道最便宜的无现金收款方式：PayNow 二维码、GrabPay 或 PayLah! 这样的电子钱包，还是刷卡机。各自的费用是多少，怎么开通？Aina 可能要花一整个晚上上网搜。她决定做一个研究助手：一个智能体规划搜索，一个去搜，第三个写报告，第四个把报告发到她的邮箱。

Step 1 · A hosted tool: web search第 1 步 · 托管工具：联网搜索

Learn先学

A model on its own only knows what it learnt in the past, and fees change. So the searcher needs the live web. Until now every tool was your own Python function. A hosted tool is different: it runs on the provider's servers, not on your computer. You just add it to the agent with WebSearchTool(). The catch: each search is charged, and you are tied to one provider. Keep the number of searches small while testing.

One more setting: ModelSettings(tool_choice="required") tells the model it must call a tool before it answers, so the searcher cannot skip the search.

模型自己只知道过去学到的东西，而费用经常变，所以搜索员需要实时的网络。到目前为止，每个工具都是你自己写的 Python 函数。托管工具不一样：它跑在提供商的服务器上，不在你的电脑上。你只要用 WebSearchTool() 把它加进智能体就行。代价是：每次搜索都要收费，而且你被绑定在一家提供商上。测试时要把搜索次数控制得小一点。

还有一个设置：ModelSettings(tool_choice="required") 告诉模型回答之前必须先调用工具，这样搜索员就不能跳过搜索。

from dotenv import load_dotenv from agents import Agent, ModelSettings, WebSearchTool load_dotenv(override=True) # reads OPENAI_API_KEY from your .env file searcher = Agent( name="Searcher", instructions="You get one search term. Search the web and summarise what you find in under 300 words.", model="gpt-5.4-mini", tools=[WebSearchTool()], model_settings=ModelSettings(tool_choice="required"), # must search, no answering from memory )

Step 2 · The planner returns a plan, not a paragraph第 2 步 · 规划员交出一份计划，而不是一段话

Learn先学

A big question is better split into a few small searches. The planner does that thinking and does not search. Its answer has to be a list your code can loop over, so it uses structured output, the form idea from “Structured outputs and a checker agent”. Each search gets a why and a query. Put why first: the model thinks about the reason before it picks the words, and the search comes out better. Quick reminder: a class built on BaseModel is a form with named blanks, and each Field(description=...) tells the model what to write in that blank.

大问题最好拆成几个小搜索。规划员负责这份思考，但它不搜索。它的答案必须是代码能逐项处理的列表，所以用结构化输出，也就是《结构化输出与检查员智能体》里的“表格”思路。每个搜索有一个 why 和一个 query。把 why 放在前面：模型先想理由再选关键词，搜索会更准。快速回顾：基于 BaseModel 的类就是一张有具名空格的表格，每个 Field(description=...) 告诉模型那个空格该填什么。

from pydantic import BaseModel, Field class SearchIdea(BaseModel): why: str = Field(description="Why this search helps answer the question.") query: str = Field(description="The exact words to type into a web search.") class SearchPlan(BaseModel): searches: list[SearchIdea] = Field(description="The web searches to run.") planner = Agent(name="Planner", model="gpt-5.4-mini", output_type=SearchPlan, instructions="You plan research. Given a question, list 3 web searches that together answer it.")

Step 3 · Run the searches at the same time第 3 步 · 让搜索同时进行

Learn先学

Each search takes a few seconds. Three in a row is slow, like three people queuing at one coffee counter. asyncio.gather sends them all off together and waits until every one is back, so three searches take about as long as one. The two words to know: async def marks a function that can pause, and await means “wait for this, but let other work run meanwhile”.

每个搜索要几秒钟。三个排队跑很慢，就像三个人挤在同一个咖啡柜台前。asyncio.gather 把它们一起派出去，等所有结果都回来，所以三个搜索的耗时和一个差不多。要记住两个词：async def 标记一个可以暂停的函数；await 的意思是“等这件事，但让别的事先跑着”。

import asyncio from agents import Runner async def search_one(idea: SearchIdea) -> str: result = await Runner.run(searcher, f"Search term: {idea.query}\nWhy: {idea.why}") return result.final_output async def search_all(search_plan: SearchPlan) -> list[str]: jobs = [search_one(idea) for idea in search_plan.searches] # one job per search, none started yet return await asyncio.gather(*jobs) # the * hands gather each job separately; it runs them together

Step 4 · The writer hands back a report第 4 步 · 写作员交回一份报告

Learn先学

The writer gets the question plus every search summary and turns them into one report. It uses structured output too: a Report form with three blanks, a short summary for a quick answer, the full report_md in markdown, and next_questions to research later. The small write function wraps one Runner.run() so the next step can just call it.

写作员拿到问题和每一份搜索摘要，把它们写成一份报告。它也用结构化输出：一张 Report 表格，有三个空格：用于快速回答的简短 summary、markdown 格式的完整 report_md，以及之后可以继续研究的 next_questions。小函数 write 只包一次 Runner.run()，下一步直接调用它就行。

class Report(BaseModel): summary: str = Field(description="The answer in 2-3 sentences.") report_md: str = Field(description="The full report in markdown, with headings.") next_questions: list[str] = Field(description="Good questions to research next.") writer = Agent(name="Writer", model="gpt-5.4-mini", output_type=Report, instructions="You write a clear research report for a small business owner from the search summaries.") async def write(question: str, findings: list[str]) -> Report: return (await Runner.run(writer, f"Question: {question}\nSearch summaries: {findings}")).final_output

Step 5 · The mailroom第 5 步 · 收发室

Learn先学

The last agent turns the report into a tidy HTML email and sends it with a tool. It is the same trick as the outreach helper: a plain helper send_message(...) does the sending, and a @function_tool called send_report wraps it for the agent. While testing, a SEND_EMAIL = False switch makes it print the email instead. Flip it on once your mail settings are in .env.

Three words in that code. .env is a small private file next to your script that holds keys and passwords, read by load_dotenv().

SMTP is the standard way a program hands an email to a mail server. An app password is a separate password your email provider gives you just for a script, so your real password stays private.

最后一个智能体把报告排成整洁的 HTML 邮件，并用工具发出去。做法和外联邮件助手一样：一个普通的辅助函数 send_message(...) 负责发送，再用 @function_tool 把它包成给智能体用的 send_report。测试时用 SEND_EMAIL = False 这个开关，让它只打印邮件而不真发。等邮箱设置写进 .env 后再打开。

代码里有三个词。.env 是放在脚本旁边、保存密钥和密码的小私密文件，由 load_dotenv() 读取。

SMTP 是程序把邮件交给邮件服务器的标准方式。应用专用密码是邮箱服务商专门给脚本用的另一个密码，这样你的真实密码不会外泄。

import os, smtplib from email.message import EmailMessage from agents import function_tool SEND_EMAIL = False # True = really send (needs MY_EMAIL, SMTP_SERVER, SMTP_APP_PASSWORD in .env) def send_message(subject, text_body, html_body): # plain helper, your code can call this if not SEND_EMAIL: print("Not sent:", subject); return msg = EmailMessage() msg["From"] = msg["To"] = os.getenv("MY_EMAIL") msg["Subject"] = subject msg.set_content(text_body) msg.add_alternative(html_body, subtype="html") with smtplib.SMTP(os.getenv("SMTP_SERVER"), 587) as server: server.starttls() server.login(os.getenv("MY_EMAIL"), os.getenv("SMTP_APP_PASSWORD")) server.send_message(msg) @function_tool def send_report(subject: str, text_body: str, html_body: str) -> str: """Email the finished report to me. Args: subject: A short, clear subject line. text_body: The report as plain text. html_body: The report as simple, clean HTML. """ send_message(subject, text_body, html_body) return "Sent" mailroom = Agent(name="Mailroom", model="gpt-5.4-mini", tools=[send_report], instructions="You get a report in markdown. Make a clean HTML email and send it with send_report.")

Step 6 · Code is the boss, not a manager agent第 6 步 · 由代码当老板，而不是主管智能体

Learn先学

In the outreach helper a manager agent, an agent whose tools are other agents, chose what to call next. Here the recipe never changes: plan, search, write, deliver. So your own Python runs the steps in order, one Runner.run() each. It is predictable, every step returns a typed object, and if something breaks you know which step. A manager agent is more flexible, but it can skip a step or loop. For a fixed recipe, code wins.

Wrap the run in with trace(...). A trace is the step-by-step record of a run: every agent, tool call and web search, with timings. Open it on the Traces page of your OpenAI dashboard, where all four agents show as one run.

在外联邮件助手里，是主管智能体（把其他智能体当工具用的智能体）决定下一步调谁。这里的流程永远不变：规划、搜索、写作、送达。所以让你自己的 Python 按顺序执行，每一步一个 Runner.run()。这样结果可预期，每一步都返回有类型的对象，出了问题也知道是哪一步。主管智能体更灵活，但它可能漏掉一步或者转圈。流程固定时，代码更胜一筹。

用 with trace(...) 把整个运行包起来。trace 是一次运行的逐步记录：每个智能体、每次工具调用和网络搜索，以及耗时。在 OpenAI 控制台的 Traces 页面打开它，四个智能体会显示为同一次运行。

from agents import trace QUESTION = "What is the cheapest way for a small kopitiam in Singapore to take cashless payments in 2026?" async def plan(question: str) -> SearchPlan: return (await Runner.run(planner, f"Question: {question}")).final_output async def deliver(report: Report) -> None: await Runner.run(mailroom, report.report_md) async def main(): with trace("Kopitiam payments research"): search_plan = await plan(QUESTION) findings = await search_all(search_plan) report = await write(QUESTION, findings) await deliver(report) print(report.summary) asyncio.run(main()) # all four agents exist now, so run it. In a notebook, just write: await main()

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

A small kopitiam can take QR payments for about 0.5% to 1.5% per sale. Most owners pick a bank terminal for steady volume and an e-wallet QR for low-cost starts. (a longer report is also in your inbox)

While SEND_EMAIL is False you should see Not sent: <the subject>, then the report summary. Open the trace to see each search.

当 SEND_EMAIL 为 False 时，你会看到 Not sent: <邮件主题>，然后是报告摘要。打开 trace，可以看到每一次搜索。

Which agent does each job? Sort them.

每项工作该由哪个智能体来做？请分类。

What I got wrong我犯过的错First, await Runner.run(...) worked in a notebook, then was a SyntaxError in a .py file. Outside a notebook, everything goes inside async def main() and you start it with asyncio.run(main()). Second, without tool_choice="required" the searcher sometimes answered from memory with old facts. The trace shows whether a real web search happened, so I check it there. Third, I ran five searches before I noticed they cost money. Three is plenty for learning. Fourth, the report ran on and on until I asked for “around 800-1200 words”.第一，await Runner.run(...) 在笔记本里能跑，放进 .py 文件就是 SyntaxError。在笔记本之外，所有内容都要放进 async def main()，再用 asyncio.run(main()) 启动。第二，没写 tool_choice="required" 时，搜索员有时直接凭记忆回答，用的是旧信息。trace 能看出有没有真的发起网络搜索，所以我去那里确认。第三，我跑了五个搜索才发现要收费，学习用三个就够了。第四，报告越写越长，直到我要求“大约 800-1200 字”才收住。
Check before you trust it相信之前先核对The report is only as good as its searches. Fees and promotions change. Before Uncle Lim signs anything, Aina opens the sources and checks the numbers herself.报告的质量取决于搜索。费用和优惠常常变动。在 Lim 叔叔签任何东西之前，Aina 要自己打开来源，核对那些数字。

Now make it yours现在把它变成你的

What changed这一课之后Now the assistant researches for Aina: she asks which cashless payment is cheapest and gets a sourced report in her inbox, so she keeps her evening. The next problem is that planning, searching and writing are still wired by hand in one script, so one agent does every role badly.现在助手能替 Aina 做调研：她问哪种无现金收款最便宜，就在收件箱里收到一份附出处的报告，晚上不用再熬夜上网搜。下一个问题是：规划、搜索、写作仍由一个脚本手工接线，一个智能体把每个角色都做得很差。

Common errors常见错误

• openai.BadRequestError: ... 'web_search' is not supported with this model: The hosted web search tool needs a model that supports it. Fix: use the model named in the lesson on the searcher agent.
• smtplib.SMTPAuthenticationError: (535, ...): The mail login was refused. Fix: use an app password in SMTP_APP_PASSWORD, and check MAIL_FROM.
• KeyError: 'MAIL_TO': A setting is missing from .env. Fix: add MAIL_FROM, MAIL_TO, SMTP_HOST and SMTP_APP_PASSWORD. Until then the helper prints "Not sent".
• The report is empty or very short: The planner returned too few searches. Fix: ask it for exactly 3 searches in the instructions, as the lesson does.

• openai.BadRequestError: ... 'web_search' is not supported with this model：托管的网页搜索工具需要支持它的模型。解决：给搜索员用课里指定的模型。
• smtplib.SMTPAuthenticationError: (535, ...)：邮箱登录被拒。解决：在 SMTP_APP_PASSWORD 里填应用专用密码，并检查 MAIL_FROM。
• KeyError: 'MAIL_TO'：.env 里少了一项设置。解决：补上 MAIL_FROM、MAIL_TO、SMTP_HOST 和 SMTP_APP_PASSWORD。补齐之前，辅助函数只会打印 “Not sent”。
• The report is empty or very short：规划员给的搜索太少。解决：像课里那样，在指令中要求它给出恰好 3 个搜索。

Takeaways要点回顾

• Deep research follows one pattern: plan, search, write, deliver.
• A hosted tool like WebSearchTool() runs on the provider's side. It is quick to use but charged per call.
• tool_choice="required" stops the searcher from answering from memory.
• Structured output lets the planner return a list your code can loop over.
• asyncio.gather runs the searches together, so three take about as long as one.
• For a fixed recipe, plain Python in charge beats a manager agent: predictable and easy to debug.
• A @function_tool is for the agent. To send from your own code, call the plain helper.
• Open the sources before you trust a number.

• 深度研究只有一个套路：规划、搜索、写作、送达。
• WebSearchTool() 这样的托管工具跑在提供商那边，用起来快，但按次收费。
• tool_choice="required" 让搜索员不能凭记忆作答。
• 结构化输出让规划员交出代码能逐项处理的列表。
• asyncio.gather 让搜索同时进行，三个的耗时和一个差不多。
• 流程固定时，让普通 Python 当老板胜过主管智能体：可预期，也好排错。
• @function_tool 是给智能体用的。想在自己的代码里发邮件，就调用那个普通辅助函数。
• 相信数字之前，先打开来源。
