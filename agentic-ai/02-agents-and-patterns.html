Agents and agentic patterns智能体与智能体模式

Learn by doing: play the agent, step through the patterns, make the call yourself · ~18 min · hands-on边做边学：亲自扮演智能体、逐步拆解模式、自己做判断 · 约 18 分钟 · 动手实践

By the end you can学完你能做到

• Play the agent loop: read a log and pick the next tool until a goal is met.
• Match five situations to the five workflow patterns without looking.
• Choose between a single call, a workflow and an agent by answering three questions.

• 玩一遍智能体循环：读日志、选下一个工具，直到目标完成。
• 不看资料，把五种情景对应到五种工作流模式。
• 回答三个问题，在单次调用、工作流和智能体之间做出选择。

Where we left off上回讲到

Last time the Kopi Corner assistant could follow a fixed workflow for an order. Today it fails when a request is not routine, like a catering order that needs a price check and a note to Uncle Lim. We fix it by learning when to use one call, a workflow or an agent, and the five patterns behind them.

上回 Kopi Corner 助手学会了按固定工作流处理订单。今天它遇到不是例行公事的请求就卡住了，比如要核价、还要给 Lim 叔叔留言的外烩订单。我们的办法是学会什么时候用单次调用、工作流或智能体，以及背后的五种模式。

Side case支线案例

Uncle Lim wants to treat Auntie Suria to a trip to Tokyo. He asks Aina's helper one thing: find a KL → Tokyo flight price, work out the total for 2 tickets in SGD, email him the total, then give the final answer. We follow that one request through seven steps. First you play the helper yourself, then we name what you did, and finally you decide how much machinery a job like this really needs. Kopi Corner's catering orders have the same shape: look something up, work it out, tell someone.

Lim 叔叔想带 Suria 阿姨去东京旅行。他只给 Aina 的助手一个任务：查出吉隆坡→东京的机票价格，算出 2 张票的新元总价，把总价发邮件给他，然后给出最终答案。我们跟着这一个请求走完七步。先由你亲自扮演助手，再给你刚做的事起名字，最后你来判断这样的工作到底需要多少“机关”。Kopi Corner 的外烩订单也是同一个形状：查一查、算一算、再通知人。

Step 1 · Be the agent第 1 步 · 亲自当智能体

Learn先学

Role-play before any definition: you are the brain of an AI agent (the LLM, short for large language model, the AI that reads and writes text). In a real agent, a model makes the choice below every turn. Today that model is you. You can only see the log of what has happened so far, and each turn you pick one tool. Repeat until the goal is done, in as few turns as you can.

先角色扮演，再看定义：你就是 AI 智能体的“大脑”（大模型，即 LLM，能读写文字的 AI）。在真实的智能体里，下面每一轮的选择都由模型来做，今天由你来做。你只能看到到目前为止发生了什么的日志，每一轮选一个工具。重复这个过程，直到目标完成，轮数越少越好。

Your five tools你的五个工具
🔎 Search flight price搜索机票价格💱 Look up exchange rate查询汇率🧮 Calculate total计算总价📧 Send email发送邮件✅ Give final answer给出最终答案

Step 2 · What you just did第 2 步 · 你刚才做了什么

Learn先学

Each turn you looked at what you knew, chose an action, got a result, and decided again. That cycle is the heart of an agent. Step through it once, then see the same idea as a few lines of code.

每一轮你都先看自己已知的信息，选一个动作，拿到结果，再做决定。这个循环就是智能体的核心。先逐步看一遍，再看同样的想法写成几行代码是什么样。

In code, the only difference between the two shapes is who picks the next step. Here a workflow first. Your code fixes the order, and the LLM only writes the words:

写成代码，两种形态的唯一区别就是谁来选下一步。先看工作流：顺序由你的代码定死，大模型只负责写文字：

Python · workflow.py
# sketch: search_price, get_rate, send_email are plain functions you wrote; ask_llm(text) sends one prompt to the model and returns its reply price = search_price("KL to Tokyo") rate = get_rate("USD", "SGD") total = 2 * price * rate body = ask_llm(f"Write one line telling Uncle Lim the total is SGD {total}") send_email(body)

And the agent. Nothing fixes the order: the LLM reads the log and picks the next tool, again and again, until it asks to stop.

再看智能体。顺序没有写死：大模型读日志、选下一个工具，一轮又一轮，直到它自己要求停下。

Python · agent.py
# sketch: ask_model and run_tool are stand-ins, not a real library goal = "KL to Tokyo: total for 2 tickets in SGD, email it, then answer" # what Uncle Lim asked for tools = ["search_price", "get_rate", "calculate", "send_email", "final_answer"] # the menu the model picks from history = [goal] # the log the LLM reads for turn in range(8): # range(8) is the step limit: a guardrail choice = ask_model(history, tools) # the LLM's choice: choice.name is the tool, choice.args its inputs if choice.name == "final_answer": break result = run_tool(choice.name, choice.args) # your code runs the chosen tool history.append(result) # the LLM sees this next turn

People define “agent” in three ways. They are not rivals: they are one idea at three zoom levels.

人们用三种方式定义“智能体”。它们不是互相竞争，而是同一个想法的三个放大层级。

1 · Does work for you1 · 替你干活Zoom level: outside. A goal goes in and a result comes out; the inside is a black box. Said by Sam Altman: an AI system that can do work for you independently.放大层级：从外面看。目标进去、结果出来，里面是个黑盒。Sam Altman 的说法：能独立替你完成工作的 AI 系统。
2 · LLM controls the flow2 · 大模型掌控流程Zoom in once: an LLM decides which steps run and in what order (in an agent, the LLM picks the next step; a fixed workflow is the cousin where your code does). A common view since late 2024 (Anthropic, Hugging Face).放大一层：由大模型决定运行哪些步骤、什么顺序（在智能体里由大模型选下一步；固定工作流则是由你的代码来选的“近亲”）。这是自 2024 年底以来的常见看法（Anthropic、Hugging Face）。
3 · Tools in a loop3 · 循环中的工具Zoom in again: the LLM calls tools, reads the result and repeats until the goal is met. Today's view: an LLM with tools, in a loop, to achieve a goal. This is what you played.再放大一层：大模型调用工具、读取结果，重复直到目标达成。当前主流：带着工具、在循环中为达成目标而运行的大模型。这就是你刚才玩的。
Remember this记住这句An agent is an LLM with tools, running in a loop, to achieve a goal.智能体 = 带着工具、在循环中运行、为达成目标而工作的大模型。

Step 3 · Workflow vs agent第 3 步 · 工作流 vs 智能体

Learn先学

Uncle Lim's task could also be built as a workflow: you write the route in code (search → rate → calculate → email → answer), and the LLM only fills in each step. Both are agentic systems: the umbrella term for any system where an LLM does part of the work, whether your code or the LLM picks the route. An agent is the kind where the LLM picks it. The difference is who decides.

Lim 叔叔的任务也可以做成工作流：路线由你用代码写死（搜索→汇率→计算→发邮件→回答），大模型只负责填每一步的内容。两者都叫智能体系统：凡是由大模型承担一部分工作的系统，统称智能体系统，不管路线由代码还是大模型选。智能体是其中由大模型选路线的那一种。区别在于由谁决定。

⚙️ Workflow工作流🧭 Agent智能体
Who picks the next step谁决定下一步Your code你的代码The LLM大模型
Path路径Same every run每次相同Can differ each run每次可能不同
Steps and cost步数与成本Predictable可预测Varies (you saw your own step count)会变化（你已看到自己的步数）
Best when适用于You know the steps步骤已知Open-ended; the steps depend on what turns up开放式；步骤取决于途中发现什么

Step 4 · The 5 workflow patterns第 4 步 · 5 种工作流模式

Learn先学

Most workflows are built from five shapes. Read the five cards, then watch two of them run: routing, where a router sends each message to a specialist, and evaluator-optimizer, where one LLM judges another.

大多数工作流由五种形状搭成。先读五张卡片，再看其中两种运行起来：路由（路由器把每条消息交给专家）和评估-优化（一个大模型评判另一个）。

1 · Prompt chaining
Input → Step 1 → Step 2 → Step 3 → Output
The idea: break a job into a fixed sequence of smaller calls. Each call is simpler and easier to get right.
Example: write an outline → write the article → translate it.
Use when: the steps are known in advance.

1 · 提示链
输入 → 步骤 1 → 步骤 2 → 步骤 3 → 输出
思路：把工作拆成一串固定顺序的小调用。每次调用更简单，也更容易做对。
例子：写大纲 → 写文章 → 翻译。
适用于：步骤事先已知。

2 · Routing
Input → Router → one of (Billing | Tech support | Sales) → Reply
The idea: classify the input, then send it to the specialised sub-task that suits it. This keeps concerns separate.
Example: billing questions vs technical problems vs sales enquiries.
Use when: different inputs need different handling.

2 · 路由
输入 → 路由器 → 其中之一（账单 | 技术支持 | 销售）→ 回复
思路：先对输入分类，再交给最合适的专门子任务，实现关注点分离。
例子：账单问题、技术故障、销售咨询各走各的通道。
适用于：不同输入需要不同处理。

3 · Parallelization
Input → (Security check | Style check | Speed check) at the same time → Combine → Output
The idea: split work into independent pieces, run them concurrently, then combine the results.
Example: review the same code for security, style and speed at once.
Use when: the sub-tasks don't depend on each other.

3 · 并行化
输入 → （安全检查 | 风格检查 | 性能检查）同时进行 → 汇总 → 输出
思路：把工作拆成相互独立的部分，并发运行，再汇总结果。
例子：同时从安全、风格、性能三方面审查同一段代码。
适用于：子任务之间互不依赖。

4 · Orchestrator-worker
Input → Orchestrator → (Worker A | Worker B | Worker C) → Combine → Result
The idea: a boss LLM breaks the task down dynamically at run time, delegates to workers, and merges their results.
Example: “Fix this bug” may touch 2 files today and 7 tomorrow.
Use when: you can't predict the sub-tasks in advance.

4 · 编排者-工作者
输入 → 编排者 → （工作者 A | 工作者 B | 工作者 C）→ 汇总 → 结果
思路：由“老板”大模型在运行时动态拆解任务，委派给工作者，再合并结果。
例子：“修这个 bug”今天可能涉及 2 个文件，明天可能是 7 个。
适用于：无法预先预测子任务。

5 · Evaluator-optimizer
Input → Generator ⇄ Evaluator → Output
The idea: one LLM produces, another judges. Loop until the output passes.
Example: draft an email → check tone and facts → revise.
Use when: there are clear quality criteria and revision helps.

5 · 评估-优化
输入 → 生成者 ⇄ 评估者 → 输出
思路：一个大模型负责产出，另一个负责评判。循环直到输出通过。
例子：起草邮件 → 检查语气和事实 → 修改。
适用于：有明确的质量标准，且修改能带来改进。

Step 5 · The price of freedom第 5 步 · 自由的代价

Learn先学

An agent's path, output and cost are unpredictable. Two tools keep that under control.

智能体的路径、输出和成本都难以预测。有两样工具可以把它管住。

Monitor监控Observability shows what happened: a trace is the step-by-step record of one run, like a flight's black box. Evals measure how good it is: a fixed set of test questions with known good answers, run again after every change, like a driving test.可观测性让你看清发生了什么：trace（追踪记录）是一次运行的逐步记录，就像飞机的黑匣子。评测衡量效果好坏：一组固定的测试问题和公认的好答案，每次改动后都重跑一遍，就像驾照考试。
Guardrails护栏Keep behaviour safe, consistent and inside intended boundaries. The range(8) in the agent.py sketch is one: it stops the loop after 8 turns.让行为安全、一致，并在设定的边界之内。agent.py 示例里的 range(8) 就是一种：循环最多跑 8 轮。

Step 6 · Two traps第 6 步 · 两个陷阱

Learn先学

Two mistakes catch almost every team that builds its first agent. Read both, then spot them.

几乎每个团队做第一个智能体时都会踩这两个坑。先读完，再来辨认。

🎯 Trap 1 · No business problem🎯 陷阱 1 · 没有业务问题LLMs generate content; that doesn't make it good. Name the business outcome you are improving and a metric for it. Without a metric you can't tell if the agent helps.大模型擅长生成，但不代表好。先明确要改善的业务结果和对应的指标。没有指标，就无法判断智能体是否有用。
🧑‍💼 Trap 2 · Anthropomorphizing🧑‍💼 陷阱 2 · 拟人化A “CEO agent” and an “intern agent” feel natural, but an LLM is not a person. It predicts plausible text. Role prompts are a useful technique (the multi-agent topic uses them), but design the system around the task, not an org chart.“CEO 智能体”“实习生智能体”听起来很自然，但大模型不是人，它只是预测合理的文字。给模型设定角色是有用的技巧（多智能体主题会用到），但系统要围绕任务来设计，而不是组织架构图。

Step 7 · Decide: workflow or agent?第 7 步 · 判断：工作流还是智能体？

Learn先学

The right approach: start simple, measure, and only climb when it pays off. Ask three questions, in this order:

正确做法：从简单开始、衡量，只有值得时才往上走。按这个顺序问三个问题：

1 · Is there a measurable metric?1 · 有可衡量的指标吗？No: stop and decide what “better” means first. Yes: go on.没有：先停下，想清楚“更好”是什么意思。有：继续。
2 · Does one plain LLM call hit it?2 · 单次普通大模型调用就能达标吗？Yes: use a single call, the simplest and cheapest. No or not tested: go on.能：用单次调用，最简单也最便宜。不能或没测过：继续。
3 · Can you write all the steps in advance?3 · 你能提前写出全部步骤吗？Yes: build a workflow and pick a pattern from Step 4. No: consider an agent, with monitoring and guardrails, and compare it against a simpler workflow first.能：搭建工作流，从第 4 步里选一种模式。不能：可以考虑智能体，加上监控和护栏，并先与更简单的工作流对比。

Choose the simplest design that works for each case.

为每个情景选一个够用的最简单方案。

Takeaways要点回顾

• The one idea: agents are powerful and unpredictable. Decide with a metric, not with hype. Skip this and you pay more, get more variation, and cannot prove it helped.
• An agent is an LLM with tools, running in a loop, to achieve a goal.
• In a workflow your code picks the next step; in an agent the LLM does.
• Five workflow patterns: prompt chaining, routing, parallelization, orchestrator-worker, evaluator-optimizer.
• Agents add cost, variation and risk. Climb from a single call to a workflow to an agent only when the metric improves.
• Plausible is not accurate: add traces, evals and guardrails, and a human check for high-stakes output.
• A great demo is not value. Value is a number that moved.

• 核心一句：智能体强大，但难以预测。用指标做决定，而不是靠热度。忽略这一点，你会花更多钱、得到更大的波动，还无法证明它有用。
• 智能体 = 带着工具、在循环中运行、为达成目标而工作的大模型。
• 工作流里由你的代码选下一步，智能体里由大模型来选。
• 五种工作流模式：提示链、路由、并行化、编排者-工作者、评估-优化。
• 智能体会增加成本、波动和风险。只有指标改善，才从单次调用升到工作流，再升到智能体。
• 合理不等于准确：加入追踪、评测和护栏，高风险输出再加人工复核。
• 漂亮的演示不等于价值，价值是某个数字真的变了。
