Agents as tools, handoffs and guardrails智能体当工具、交接与护栏

One agent becomes a small team, with checks at the door · ~25 min · hands-on一个智能体变成一支小团队，门口还有安检 · 约 25 分钟 · 动手实践

Where we left off上回讲到

Last time one agent on the SDK took every order, drinks and noodles alike. Today it fails when a regular orders mee goreng and asks for a refund in the same chat: one agent does all of it, badly. We fix it with specialist agents, handoffs and guardrails.

上回 SDK 上的一个智能体包办所有订单，饮料面食都是它。今天它的问题是：熟客点了炒面，又在同一段对话里要退款，一个智能体什么都做，结果都做不好。办法是专员智能体、交接和护栏。

Side case支线案例

Noor runs Pot & Petal, a small online plant shop. She wants a help desk agent called Fern. Fern should ask a plant expert when a customer's plant looks sick, pass refund requests to a returns specialist, and never let a pasted card number or a made-up discount slip through. Each step today adds one of those. At Kopi Corner Fern is the counter agent, and Plant Doctor and Returns Desk become Ah Seng's and Kak Ros's agents.

Noor 开了一家小网店 Pot & Petal，卖绿植。她想要一个叫 Fern 的客服智能体。顾客的植物生病时，Fern 要去问植物专家；有人要退款时，把对话转给退货专员；还绝不能让顾客贴进来的银行卡号或凭空许诺的折扣溜过去。今天每一步加上其中一样。放到 Kopi Corner，Fern 就是柜台智能体，Plant Doctor 和 Returns Desk 变成 Ah Seng 和 Kak Ros 的智能体。

Step 1 · An agent as a tool第 1 步 · 把智能体当工具

Learn先学

Fern is good at chatting, but not at diagnosing plants. You could stuff plant knowledge into Fern's prompt, but it gets long and messy. Instead, build a separate Plant Doctor agent and give it to Fern as a tool with .as_tool(). Think of asking a colleague across the desk: you get an answer, then you keep talking to the customer.

Fern 擅长聊天，但不擅长给植物看病。你可以把植物知识塞进 Fern 的提示词，但那会又长又乱。更好的做法是单独做一个 Plant Doctor 智能体，再用 .as_tool() 把它当工具交给 Fern。就像问隔壁工位的同事：拿到答案后，还是你继续和顾客说话。

plant_doctor = Agent( name="Plant Doctor", instructions="Diagnose a houseplant from its symptoms. Two sentences: the likely cause, then one fix.", model="gpt-5.4-mini") fern = Agent( name="Fern", instructions="You are the help desk of Pot & Petal. Be warm and brief. For sick plants, ask plant_doctor, then answer in your own words.", model="gpt-5.4-mini", tools=[plant_doctor.as_tool( tool_name="plant_doctor", tool_description="Diagnose a sick houseplant from a description of its symptoms")]) result = await Runner.run(fern, "My monstera has yellow leaves with brown tips")

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

Yellow leaves with brown tips usually mean overwatering or dry air. Check that the pot drains, let the top 3 cm of soil dry out, and keep the plant away from the aircon vent.

Step 2 · A handoff第 2 步 · 交接（handoff）

Learn先学

Refunds are different. Noor wants Returns Desk to own the whole chat, not have Fern relay messages. List it in handoffs, and when the model picks it, the SDK makes Returns Desk the active agent. This is transferring the phone call, not asking a colleague.

退款不一样。Noor 希望 Returns Desk 接管整段对话，而不是让 Fern 在中间传话。把它写进 handoffs，模型选中它时，SDK 就让 Returns Desk 成为当前智能体。这是把电话转过去，而不是问同事。

returns_desk = Agent( name="Returns Desk", handoff_description="Handles refunds and returns for damaged or wrong orders", instructions="You handle returns. Ask for the order number, then explain the next step.", model="gpt-5.4-mini") fern = Agent(name="Fern", ..., tools=[...], handoffs=[returns_desk]) result = await Runner.run(fern, "My pot arrived cracked. I want my money back.") print(result.last_agent.name) # who gave the final answer

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

Returns Desk

Step 3 · Tool or handoff?第 3 步 · 工具还是交接？

Learn先学

Both put a second agent to work, so they look alike. One question tells them apart: who talks to the customer next? If the first agent gets an answer back and keeps talking, it is a tool. If the second agent takes over and replies, it is a handoff.

两种方式都让第二个智能体干活，所以看起来很像。一个问题就能分清：接下来谁和顾客说话？如果第一个智能体拿回答案并继续说，那是工具；如果第二个智能体接手并回复，那就是交接。

The moment it clicked恍然大悟的那一刻At first I thought as_tool and handoffs were the same thing. Then it clicked: a tool is asking a colleague for an answer; a handoff is transferring the phone call. Another way to see it: as_tool is just a function call that happens to be an agent.一开始我以为 as_tool 和交接是一回事。后来突然想通了：工具是向同事要一个答案，交接是把电话转过去。换个角度看，as_tool 就是一次函数调用，只不过那个函数恰好是个智能体。

Step 4 · Input guardrail: check what comes in第 4 步 · 输入护栏：检查进来的内容

Learn先学

Some customers paste their full card number into the chat. Fern must never act on it. An input guardrail is a check on the customer's message that can stop the run before Fern replies. It returns GuardrailFunctionOutput, and if tripwire_triggered is true, the SDK stops the run by raising InputGuardrailTripwireTriggered. Like a smoke alarm: it does not cook, it only stops things when it sees trouble.

有些顾客会把完整的银行卡号贴进聊天框。Fern 绝不能据此行事。输入护栏是检查顾客消息的一道关卡，能在 Fern 回复之前叫停运行。它返回 GuardrailFunctionOutput；如果 tripwire_triggered 为真，SDK 就抛出 InputGuardrailTripwireTriggered 叫停运行。就像烟雾报警器：它不做饭，只在发现问题时喊停。

import re from agents import input_guardrail, GuardrailFunctionOutput, InputGuardrailTripwireTriggered @input_guardrail async def no_card_numbers(ctx, agent, message): found = bool(re.search(r"\d(?:[ -]?\d){12,15}", str(message))) return GuardrailFunctionOutput(output_info={"card_number": found}, tripwire_triggered=found) fern = Agent(name="Fern", ..., input_guardrails=[no_card_numbers]) try: result = await Runner.run(fern, "Charge 4111 1111 1111 1111 for two ferns") except InputGuardrailTripwireTriggered: print("Please never share card numbers in chat. Use the checkout page.")

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

Please never share card numbers in chat. Use the checkout page.

Step 5 · Output guardrail, and where guardrails run第 5 步 · 输出护栏，以及护栏在哪里运行

Learn先学

Noor also fears Fern inventing a discount. An output guardrail checks the final answer before the customer sees it (this one is deliberately simple; a real check would be smarter). The catch is where guardrails run: input guardrails only on the first agent, output guardrails only on the agent that gives the final answer.

Noor 还担心 Fern 自己编出一个折扣。输出护栏在顾客看到最终回答之前检查它（这个例子故意写得很简单，真实的检查会更聪明）。关键在于护栏在哪里运行：输入护栏只在第一个智能体上运行，输出护栏只在给出最终回答的智能体上运行。

from agents import output_guardrail, OutputGuardrailTripwireTriggered @output_guardrail async def no_discount_promises(ctx, agent, output): promised = "discount" in str(output).lower() return GuardrailFunctionOutput(output_info={"discount": promised}, tripwire_triggered=promised) fern = Agent(name="Fern", ..., input_guardrails=[no_card_numbers], output_guardrails=[no_discount_promises])

Will the guardrail run? Decide for each setup.

护栏会运行吗？逐个判断。

What I got wrong我踩过的坑I put the input guardrail on Plant Doctor, the agent Fern uses as a tool, and expected it to check the customer's message. It never did. Input guardrails only check the input of the first agent in the run, and output guardrails only check the agent that gives the final output. Plant Doctor is neither, and it only ever sees what Fern chooses to send it. Fix: put the guardrails on the front-door agent (here, Fern), and give every handoff target its own output guardrail.我把输入护栏装在了 Plant Doctor 上，也就是 Fern 当工具用的那个智能体，还以为它会检查顾客的消息。结果它从来没检查过。输入护栏只检查运行中第一个智能体的输入，输出护栏只检查给出最终输出的那个智能体。Plant Doctor 两者都不是，而且它只能看到 Fern 决定发给它的内容。解决办法：把护栏装在“前台”智能体上（这里是 Fern），并给每个交接目标单独配上输出护栏。

Common errors常见错误

• agents.exceptions.InputGuardrailTripwireTriggered: Guardrail tripped: Not a bug: the guardrail worked and raised an InputGuardrailTripwireTriggered exception, but nothing caught it. Fix: wrap Runner.run in try / except and print a friendly line.
• agents.exceptions.MaxTurnsExceeded: Max turns (10) exceeded: Two agents keep calling each other or a tool. Fix: tighten the instructions so one agent clearly finishes, or pass a larger max_turns on purpose.
• No error, but result.last_agent.name is still Fern: The handoff never fired because the target's purpose is vague. Fix: give it a clear handoff_description such as "refunds and cracked pots".

• agents.exceptions.InputGuardrailTripwireTriggered: Guardrail tripped：不是故障：护栏起作用并抛出了 InputGuardrailTripwireTriggered 异常，只是没人接住它。解决：用 try / except 包住 Runner.run，再打印一句友好的话。
• agents.exceptions.MaxTurnsExceeded: Max turns (10) exceeded：两个智能体在互相调用，或反复调用工具。解决：把指令写清楚，让其中一个明确收尾；或有意识地调大 max_turns。
• 没有报错，但 result.last_agent.name 还是 Fern：交接没触发，因为目标的用途写得太含糊。解决：给它一个清楚的 handoff_description，比如“退款与破损花盆”。

Takeaways要点回顾

• agent.as_tool(tool_name, tool_description) turns an agent into a tool. The caller gets the answer and stays in charge.
• handoffs=[other] lets the model pass the whole conversation on. The other agent replies from then on.
• Tool or handoff? Ask who talks to the user next.
• handoff_description tells the model when a handoff fits. result.last_agent tells you who answered.
• Guardrails return GuardrailFunctionOutput. When tripwire_triggered is true, the SDK raises an exception you catch.
• Input guardrails run only on the first agent. Output guardrails run only on the agent with the final answer.
• Put guardrails on the front door, not on helpers.

• agent.as_tool(tool_name, tool_description) 把智能体变成工具，调用者拿到答案后继续掌控。
• handoffs=[other] 让模型把整段对话交出去，之后由另一个智能体回复。
• 工具还是交接？问一句：接下来谁和用户说话。
• handoff_description 告诉模型何时该交接，result.last_agent 告诉你最后是谁回答的。
• 护栏返回 GuardrailFunctionOutput；tripwire_triggered 为真时，SDK 抛出异常，由你捕获。
• 输入护栏只在第一个智能体上运行，输出护栏只在给出最终回答的智能体上运行。
• 护栏装在前台，别装在辅助智能体上。
