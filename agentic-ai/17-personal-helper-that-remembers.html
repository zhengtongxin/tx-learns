Personal memory helper个人记忆助手

You build a helper that does errands, asks before it acts and checks its own work · ~40 min · project你做一个会跑腿、行动前先问你、还会检查自己成果的助手 · 约 40 分钟 · 项目

Key point要点

A helper you can trust has three parts: a worker that runs the errand with tools, a pause that asks you before anything leaves the shop, and a checker that tests the result against a “done means” line. Our helper is Kaki (Singlish for “buddy”). Errand: find three kopitiams near Tiong Bahru that open before 7am, write them to kopi.md, ping my phone with the best one.

值得信任的助手有三部分：用工具跑腿的执行者、在任何东西离开店之前先问你的暂停，以及按“完成标准”检查结果的检查员。我们的助手叫 Kaki（新加坡口语里的“伙伴”）。任务：找出中峇鲁附近三家 7 点前营业的咖啡店，写进 kopi.md，并把最好的一家推送到我手机。

Step 1 · Tools first第 1 步 · 先备工具

Learn先学
  • A worker is only as good as its toolbox: a search tool, two functions you write (ping_phone, ask_human) and two MCP servers: a browser, and a file tool that can only touch one folder.
  • A browser must keep tabs and cookies between calls, so keep its MCP session open with client.session(name) and load_mcp_tools(session).
  • 执行者的能力取决于工具箱：一个搜索工具、两个你自己写的函数（ping_phone、ask_human），以及两个 MCP 服务：浏览器，和一个只能动一个文件夹的文件工具。
  • 浏览器要在多次调用之间保留标签页和 cookie，所以用 client.session(name) 和 load_mcp_tools(session) 让 MCP 会话保持开启。
import os, requests from contextlib import AsyncExitStack from langchain_core.tools import tool from langchain_community.tools import GoogleSerperRun from langchain_community.utilities import GoogleSerperAPIWrapper from langchain_mcp_adapters.client import MultiServerMCPClient from langchain_mcp_adapters.tools import load_mcp_tools search = GoogleSerperRun(api_wrapper=GoogleSerperAPIWrapper()) @tool def ping_phone(text: str) -> str: """Send a short push notification to my phone.""" requests.post("https://api.pushover.net/1/messages.json", data={"token": os.getenv("PUSHOVER_TOKEN"), "user": os.getenv("PUSHOVER_USER"), "message": text}) return "sent" @tool def ask_human(instructions: str) -> str: """Ask me to do something only a human can do (login, captcha), with exact steps.""" return "The human says it's done. Continue." # run inside an async function or a notebook cell os.makedirs("workspace", exist_ok=True) client = MultiServerMCPClient({ "browser": {"transport": "stdio", "command": "npx", "args": ["@playwright/mcp@latest", "--isolated"]}, "files": {"transport": "stdio", "command": "npx", # reads and writes inside workspace/ only "args": ["-y", "@modelcontextprotocol/server-filesystem", os.path.abspath("workspace")]}, }) stack = AsyncExitStack() # remembers everything opened through it, and closes it all in one aclose() all_tools = [search, ping_phone, ask_human] for name in ("browser", "files"): session = await stack.enter_async_context(client.session(name)) # stays open all_tools += await load_mcp_tools(session) # when the errand is finished, in this same function: await stack.aclose()

Step 2 · The worker, and asking first第 2 步 · 执行者与先问一声

Learn先学
  • The worker is one create_agent with all_tools and middleware (small add-ons that run around every model and tool call): a visible plan, hidden emails and card numbers (PII, personally identifiable information), a cap on model calls, and a pause before risky tools. A checkpointer saves the conversation after each step under a thread_id, the name of this errand; pass the same id on every call and it carries on where it stopped. It keeps the conversation between turns, but InMemorySaver is gone when the program stops. What lasts is the file: the prompt tells Kaki to read its notes in workspace/ first and to save results there, so the next errand starts from kopi.md.
  • With HumanInTheLoopMiddleware the run pauses before a listed tool and the result holds __interrupt__. Resume with one decision per paused call: approve, reject with a message, or edit.
  • 执行者就是一个带 all_tools 和中间件（在每次模型调用和工具调用前后运行的小插件）的 create_agent：可见的计划、隐藏邮箱和银行卡号（PII，即个人身份信息）、限制模型调用次数、危险工具前先暂停。检查点在每一步之后把对话存到一个 thread_id（这次跑腿的名字）下面；每次调用都传同一个 id，它就从停下的地方接着做。它在多轮之间保留对话，但 InMemorySaver 在程序停止后就没了。真正留下来的是文件：提示词让 Kaki 先读 workspace/ 里的笔记，并把结果存在那里，下一次跑腿就从 kopi.md 开始。
  • 用 HumanInTheLoopMiddleware，运行会在列出的工具前暂停，结果里带 __interrupt__。恢复时每个暂停的调用给一个决定：批准、附消息拒绝或修改。
from datetime import datetime from langchain.agents import create_agent from langchain.agents.middleware import ( HumanInTheLoopMiddleware, ModelCallLimitMiddleware, PIIMiddleware, TodoListMiddleware, ) from langgraph.checkpoint.memory import InMemorySaver from langgraph.types import Command RUNNER_PROMPT = """You are Kaki, a practical helper who runs errands for me. Read pages with the browser, search when useful. If a page needs a login or captcha, call ask_human with exact steps. Stop when the 'done means' line is satisfied. Before you start, read every .md file in the workspace: those are your notes from earlier errands. Save what you find as a .md file there, so you remember it next time.""" worker = create_agent( model="openai:gpt-5.4-mini", tools=all_tools, system_prompt=f"{RUNNER_PROMPT}\nToday is {datetime.now():%A %d %B %Y}.", middleware=[ TodoListMiddleware(), # keeps a visible plan PIIMiddleware("email"), # redact emails PIIMiddleware("credit_card", apply_to_tool_results=True), ModelCallLimitMiddleware(run_limit=30), # stop runaway cost HumanInTheLoopMiddleware(interrupt_on={"ping_phone": True, "ask_human": True}), ], checkpointer=InMemorySaver(), ) cfg = {"configurable": {"thread_id": "errand-1"}} res = await worker.ainvoke({"messages": [{"role": "user", "content": "Find three kopitiams near Tiong Bahru open before 7am. Ping me the best."}]}, cfg) if "__interrupt__" in res: # res["__interrupt__"] is a list with one pause. Its .value is a dict: # {"action_requests": [{"name": "ping_phone", "description": "...", ...}], ...} one per paused tool call asks = res["__interrupt__"][0].value["action_requests"] print("Kaki wants to:", asks[0]["description"]) res = await worker.ainvoke(Command(resume={"decisions": [{"type": "approve"}] * len(asks)}), cfg) # or {"type": "reject", "message": "Don't ping me after 10pm"}

Step 3 · The checker: does “done” mean done?第 3 步 · 检查员：“完成”真的完成了吗？

Learn先学
  • Workers say “done!” too early. The checker is a model that returns a structured Verdict; the retry loop is plain Python, capped by tries.
  • Give the checker the list of tools actually called, or the worker can say “notification sent” without calling the tool.
  • 执行者总爱过早喊“做完了！”。检查员是个返回结构化 Verdict 的模型；重试循环是普通 Python，用 tries 封顶。
  • 要把实际调用过的工具列表交给检查员，否则执行者可以只说“通知已发送”，却根本没调用工具。
from pydantic import BaseModel, Field from langchain_openai import ChatOpenAI class Verdict(BaseModel): feedback: str = Field(description="Short, concrete feedback") done: bool = Field(description="Has the 'done means' line been met?") need_human: bool = Field(description="Is the worker stuck or asking a question?") checker = ChatOpenAI(model="gpt-5.4-mini").with_structured_output(Verdict) async def run_errand(errand: str, done_means: str, cfg: dict, tries: int = 3): msg = {"messages": [{"role": "user", "content": f"{errand}\n\nDone means: {done_means}"}]} for _ in range(tries): res = await worker.ainvoke(msg, cfg) if "__interrupt__" in res: # paused: resume with worker.ainvoke(Command(resume=...), cfg), then call run_errand again return {"status": "paused", "res": res} # approve or reject as in Step 2 reply = res["messages"][-1].content used = [c["name"] for m in res["messages"] for c in (getattr(m, "tool_calls", None) or [])] v = await checker.ainvoke( f"Errand: {errand}\nDone means: {done_means}\nTools used: {used}\nReply: {reply}\n" "Judge using the tool calls as evidence.") if v.done or v.need_human: return {"status": "done" if v.done else "need_human", "reply": reply, "feedback": v.feedback} msg = {"messages": [{"role": "user", "content": f"Not done yet. Feedback: {v.feedback}. Keep going."}]} return {"status": "gave_up", "reply": reply, "feedback": "gave up after max tries"} out = await run_errand("Find three kopitiams near Tiong Bahru open before 7am and write them to kopi.md.", "kopi.md lists three places, each with its opening time", cfg) print("Kaki says:", out.get("reply"), "|", out.get("feedback", out["status"]))
What I got wrong我犯过的错I opened the MCP sessions in one function and closed them in another, which gave confusing errors on exit. Open and close them in the same function: that is the await stack.aclose() line in Step 1. And without tries and a call limit, a strict checker plus an eager worker can loop and cost real money.我在一个函数里打开 MCP 会话，却在另一个函数里关闭，退出时得到一堆莫名其妙的错误。要在同一个函数里打开和关闭：就是第 1 步里的 await stack.aclose() 那一行。另外，没有 tries 和调用上限，严格的检查员加上积极的执行者可能一直循环，花掉真金白银。

Takeaways要点回顾

• Give a helper an errand and a “done means” line: it makes finishing checkable.
• The worker is one create_agent with tools and middleware that sets the limits.
• Human-in-the-loop pauses before risky tools; resume with one approve, reject or edit per call.
• The checker sees the tools actually called, so “I sent it” needs proof.
• Always cap the loop: tries and a model-call limit.

• 给助手任务的同时给一条“完成标准”：这样完成与否才可检查。
• 执行者就是一个带工具和中间件（设定边界）的 create_agent。
• 人在回路在危险工具前暂停；恢复时每个调用给一个批准、拒绝或修改。
• 检查员能看到实际调用的工具，所以“我发了”需要证据。
• 永远给循环设上限：tries 和模型调用上限。
