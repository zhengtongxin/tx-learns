Project: a personal helper that remembers项目：会记事的个人助手

You build a helper that does errands, asks before it acts and checks its own work · ~40 min · project你做一个会跑腿、行动前先问你、还会检查自己成果的助手 · 约 40 分钟 · 项目

Where we left off上回讲到

Last time the Kopi Corner assistant gained memory, tools and web search inside its graph. Today it still forgets each person: Uncle Lim's regular who wants “the usual” is a stranger every visit. We fix it by building one helper that remembers, asks first and checks its own work.

上次 Kopi Corner 助手在图里有了记忆、工具和联网搜索。今天它还是记不住每个人：林叔那位要“老样子”的熟客，每次来都像陌生人。我们做一个会记事、先问再做、还会自查的助手来解决。

Side case支线案例

Meet Kaki (like “my kaki”, my buddy). You give Kaki an errand and a line saying what done means: “Find three kopitiams within 2 km of Tiong Bahru that open before 7am and sell half-boiled eggs. Write them to kopi.md and ping my phone with the best one.” Kaki is a small shop with two people. A worker goes out and does the errand. A checker reads the report against your “done means” line. And before anything leaves the shop, like a ping to your phone, the worker has to ask you first. Kaki is a side case: swap his errand for Auntie Suria's regulars and he becomes the Kopi Corner assistant.

认识 Kaki（就是“我的 kaki”，我的伙伴）。你给 Kaki 一件差事，再写一句怎样算完成：“在 Tiong Bahru 周围 2 公里内找三家早上 7 点前开门、有卖半熟蛋的咖啡店，写进 kopi.md，再把最好的一家推送到我的手机。”Kaki 像一家有两个人的小店：跑腿的出去办事，检查员对照你的“完成标准”读他的报告。而任何要离开店里的动作，比如推送到你手机，跑腿的必须先问你。Kaki 是个支线案例：把他的差事换成 Suria 阿姨的熟客，他就是 Kopi Corner 助手。

Step 1 · Tools first: your own, ready-made and MCP第 1 步 · 先备工具：自己写的、现成的和 MCP

Learn先学

A worker is only as good as its toolbox, so build that first. Kaki gets a search tool, a Wikipedia tool, two functions you write (ping_phone and ask_human), plus a browser and a file tool from MCP servers. The browser has to keep its state, like open tabs and cookies, between calls. So you keep the MCP sessions open with client.session(name) and load_mcp_tools(session), instead of the default open-per-call.

跑腿的本事取决于工具箱，所以先备工具。Kaki 有一个搜索工具、一个维基百科工具、你自己写的两个函数（ping_phone 和 ask_human），再加上来自 MCP 服务的浏览器和文件工具。浏览器在两次调用之间要保持状态，比如打开的标签页和 cookie。所以要用 client.session(name) 加 load_mcp_tools(session) 让 MCP 会话一直开着，而不是默认的每次调用才开一次。

pip install langchain langchain-openai langgraph langchain-community langchain-mcp-adapters wikipedia gradio python-dotenv # also Node + npx. env: OPENAI_API_KEY, SERPER_API_KEY, PUSHOVER_USER, PUSHOVER_TOKEN
import os, requests from contextlib import AsyncExitStack from langchain_core.tools import tool from langchain_community.tools import GoogleSerperRun, WikipediaQueryRun from langchain_community.utilities import GoogleSerperAPIWrapper, WikipediaAPIWrapper from langchain_mcp_adapters.client import MultiServerMCPClient from langchain_mcp_adapters.tools import load_mcp_tools search = GoogleSerperRun(api_wrapper=GoogleSerperAPIWrapper()) wiki = WikipediaQueryRun(api_wrapper=WikipediaAPIWrapper()) @tool def ping_phone(text: str) -> str: """Send a short push notification to my phone.""" requests.post("https://api.pushover.net/1/messages.json", data={"token": os.getenv("PUSHOVER_TOKEN"), "user": os.getenv("PUSHOVER_USER"), "message": text}) return "sent" @tool def ask_human(instructions: str) -> str: """Ask me to do something only a human can do (login, captcha), with exact steps.""" # runs only after the pause in Step 3: you did the step, then approved return "The human says it's done. Continue." mcp_servers = { "browser": {"transport": "stdio", "command": "npx", "args": ["@playwright/mcp@latest", "--isolated"]}, "files": {"transport": "stdio", "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/abs/path/to/workspace"]}, } # keep each session open so the browser remembers its tabs # (these await lines must sit inside an async function or a notebook cell; # the package wraps them in open_toolbox) client = MultiServerMCPClient(mcp_servers) stack = AsyncExitStack() mcp_tools = [] for name in mcp_servers: session = await stack.enter_async_context(client.session(name)) mcp_tools += await load_mcp_tools(session) all_tools = [search, wiki, ping_phone, ask_human] + mcp_tools

Step 2 · The worker: one agent, a stack of middleware第 2 步 · 跑腿的：一个智能体加一叠中间件

Learn先学

The worker is one create_agent with all_tools. Its safety comes from middleware you met last lesson: a visible todo plan, hiding emails and card numbers, a cap on model calls to stop runaway cost, and a pause before risky tools. A checkpointer lets it remember the errand across turns. The prompt says what to do when a page needs a login: call ask_human with exact steps.

跑腿的就是一个带着 all_tools 的 create_agent。它的安全靠上一课见过的中间件：看得见的待办计划、隐藏邮箱和银行卡号、限制模型调用次数以免费用失控，以及在危险工具前暂停。检查点让它能跨回合记住这件差事。提示词写明了遇到要登录的页面怎么办：用 ask_human 并写清具体步骤。

from datetime import datetime from langchain.agents import create_agent from langchain.agents.middleware import ( HumanInTheLoopMiddleware, ModelCallLimitMiddleware, PIIMiddleware, TodoListMiddleware, ) from langgraph.checkpoint.memory import InMemorySaver RUNNER_PROMPT = """You are Kaki, a practical helper who runs errands for me. Read pages with the browser (snapshot first, click only when needed), search when useful, and save anything you produce into the workspace. If a page needs a login or captcha, call ask_human with exact steps. Stop when the 'done means' line is satisfied.""" worker = create_agent( model="openai:gpt-5.4-mini", tools=all_tools, system_prompt=f"{RUNNER_PROMPT}\nToday is {datetime.now():%A %d %B %Y}.", middleware=[ TodoListMiddleware(), # keeps a visible plan PIIMiddleware("email"), # redact emails PIIMiddleware("credit_card", apply_to_tool_results=True), ModelCallLimitMiddleware(run_limit=30), # stop runaway cost HumanInTheLoopMiddleware(interrupt_on={"ping_phone": True, "ask_human": True}), ], checkpointer=InMemorySaver(), )

Step 3 · Ask first: human-in-the-loop第 3 步 · 先问再做：人在回路中

Learn先学

With HumanInTheLoopMiddleware the run pauses just before a listed tool. The result then contains __interrupt__. You look at what Kaki wants to do and resume with a Command holding one decision per paused call: approve, reject with a message, or edit the arguments first. A rejection does not end the run. Kaki reads your message and carries on, which feels very natural.

有了 HumanInTheLoopMiddleware，运行会在列出的工具之前暂停。结果里会出现 __interrupt__。你先看 Kaki 想做什么，再用 Command 恢复，里面给每个暂停的调用一个决定：批准、附上留言拒绝，或者先修改参数。拒绝不会让运行结束，Kaki 会读你的留言然后继续，用起来很自然。

from langgraph.types import Command errand = "Find three kopitiams within 2 km of Tiong Bahru that open before 7am and sell half-boiled eggs. Write them to kopi.md and ping my phone with the best one." cfg = {"configurable": {"thread_id": "errand-1"}} # run inside an async def (or a notebook cell), because of await res = await worker.ainvoke({"messages": [{"role": "user", "content": errand}]}, cfg) if "__interrupt__" in res: asks = res["__interrupt__"][0].value["action_requests"] print("Kaki wants to:", asks[0]["description"]) res = await worker.ainvoke(Command(resume={"decisions": [{"type": "approve"}] * len(asks)}), cfg) # or: {"type": "reject", "message": "Don't ping me after 10pm"} # or: {"type": "edit", ...} to change the arguments first

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

Kaki wants to: Tool execution requires approval Tool: ping_phone Args: {'text': 'Best pick: ...'}

Step 4 · The checker: does “done” mean done?第 4 步 · 检查员：“做完了”真的做完了吗？

Learn先学

Workers can say “done!” too early. The checker is just a model that returns a structured Verdict: feedback, whether it is done, and whether a human is needed. The loop around it is plain Python, not a graph. One detail matters a lot: give the checker the list of tools actually called. Otherwise the worker can simply say “notification sent” without ever calling the tool.

跑腿的可能太早说“做完了！”。检查员只是一个返回结构化 Verdict 的模型：反馈、是否完成、是否需要人介入。外面的循环是普通 Python，不是图。有个细节非常重要：要把实际调用过的工具列表交给检查员。否则跑腿的可以只是嘴上说“通知已发送”，却从没调用过工具。

from pydantic import BaseModel, Field from langchain_openai import ChatOpenAI class Verdict(BaseModel): feedback: str = Field(description="Short, concrete feedback") done: bool = Field(description="Has the 'done means' line been met?") need_human: bool = Field(description="Is the worker stuck or asking a question?") checker = ChatOpenAI(model="gpt-5.4-mini").with_structured_output(Verdict) async def run_errand(errand: str, done_means: str, cfg: dict, tries: int = 3): msg = {"messages": [{"role": "user", "content": f"{errand}\n\nDone means: {done_means}"}]} for _ in range(tries): res = await worker.ainvoke(msg, cfg) if "__interrupt__" in res: return res # paused: returns the raw result (a dict), not a tuple # (the package settles pauses inside, so it always returns (reply, feedback)) reply = res["messages"][-1].content used = [c["name"] for m in res["messages"] for c in (getattr(m, "tool_calls", None) or [])] v = await checker.ainvoke( f"Errand: {errand}\nDone means: {done_means}\nTools used: {used}\nReply: {reply}\n" "Judge using the tool calls as evidence.") if v.done or v.need_human: return reply, v.feedback msg = {"messages": [{"role": "user", "content": f"Not done yet. Feedback: {v.feedback}. Keep going."}]} return reply, "gave up after max tries"
What I got wrong我搞错的地方One session, one task. A stdio MCP session has to be opened and closed in the same asyncio task. I opened it in one place and closed it from another (a Gradio callback), and got confusing cancel-scope errors. The fix is one background task that owns the sessions: it opens them, waits on an Event, and unwinds when told to stop. (A task is one piece of async code the event loop runs; a cancel scope is the guard around a block that lets it be cancelled, and it must be entered and left in the same task.) The package does it with open_toolbox: async with open_toolbox("workspace") as all_tools: opens and closes the sessions in one place. Two pauses, two decisions. If the worker pauses on two tools at once, one “approve” is not enough: send one decision per call, as the * len(asks) does. Infinite polishing. Without tries and ModelCallLimitMiddleware, a strict checker plus an eager worker can loop for a long time and cost real money. Keep both limits on.一个会话，一个任务。stdio 的 MCP 会话必须在同一个 asyncio 任务里打开和关闭。我在一个地方打开，却在另一个地方（Gradio 的回调）关闭，结果得到莫名其妙的 cancel-scope 错误。解决办法是用一个后台任务专门负责会话：它打开会话，等待一个 Event，被通知停止时再收尾。（任务是事件循环运行的一段异步代码；cancel scope 是包住一段代码、让它能被取消的保护范围，必须在同一个任务里进入和离开。）示例包用 open_toolbox 做到这一点：async with open_toolbox("workspace") as all_tools: 在同一个地方打开并关闭会话。两个暂停，两个决定。如果跑腿的同时在两个工具前暂停，一个“批准”不够：每个调用都要一个决定，就像 * len(asks) 做的那样。无止境的打磨。没有 tries 和 ModelCallLimitMiddleware，严格的检查员加上积极的跑腿者可能循环很久，花掉真金白银。两个上限都要开着。

Common errors常见错误

• ValueError: ... thread_id ... checkpointer: Pausing for approval needs a checkpointer and the same thread_id on resume. Fix: reuse the same cfg in both calls.
• KeyError: '__interrupt__': You read the pause before checking it exists. Fix: test if "__interrupt__" in res first, as the lesson does.
• The phone never buzzes after approval: PUSHOVER_USER or PUSHOVER_TOKEN is missing. Fix: add both to .env.

• ValueError: ... thread_id ... checkpointer：暂停等待批准需要存档器，恢复时也要用同一个 thread_id。解决：两次调用用同一个 cfg。
• KeyError: '__interrupt__'：你没检查就去读暂停信息。解决：像课里那样，先判断 if "__interrupt__" in res。
• The phone never buzzes after approval：没有 PUSHOVER_USER 或 PUSHOVER_TOKEN。解决：把两个都加进 .env。

Takeaways要点回顾

• Give a helper an errand and a “done means” line. It makes finishing checkable.
• Build the toolbox first. Keep MCP sessions open when a browser must remember its state.
• The worker is one create_agent with middleware: plan, hide personal data, limit calls, pause before risky tools.
• Human-in-the-loop pauses before a listed tool. Resume with one decision per paused call: approve, reject or edit.
• The checker is a structured-output model. Show it the tools actually called, so “I sent it” needs proof.
• Always cap the loop: tries and a model-call limit.
• A stdio MCP session must be opened and closed in the same asyncio task.

• 给助手一件差事，再加一句“完成标准”，完成与否才能被检查。
• 先备好工具箱。浏览器需要记住状态时，让 MCP 会话一直开着。
• 跑腿的就是一个带中间件的 create_agent：计划、隐藏个人信息、限制调用、危险工具前暂停。
• 人在回路中会在列出的工具前暂停。恢复时每个暂停的调用一个决定：批准、拒绝或修改。
• 检查员是一个结构化输出的模型。把实际调用过的工具给它看，“我发了”才需要证据。
• 循环一定要设上限：tries 和模型调用次数限制。
• stdio 的 MCP 会话必须在同一个 asyncio 任务里打开和关闭。

Recap三句回顾

• A worker agent is a model, a toolbox and middleware that sets the limits.
• Human-in-the-loop pauses before risky tools and resumes with approve, reject or edit.
• A checker agent reads the result before you trust it.

• 跑腿的智能体 = 模型 + 工具箱 + 设定边界的中间件。
• 人在回路会在危险工具之前暂停，再以批准、拒绝或修改继续。
• 结果交给你之前，先让检查员智能体读一遍。
