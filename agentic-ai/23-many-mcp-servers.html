Where we left off上回讲到

Last time the Kopi Corner assistant's order pad became an MCP server. Today it fails when Uncle Lim walks in: it does not remember his kopi-C kurang manis (coffee with evaporated milk, less sugar), knows nothing about the marathon closing the road, and cannot see supplier prices. We fix it by plugging in several servers, local and remote, each giving one kind of context.

上回 Kopi Corner 助手的点单本变成了 MCP 服务端。今天的问题是：Lim 叔一进门，它不记得他的少糖 kopi-C（加淡奶、少糖的咖啡），不知道马拉松封路，也看不到供货价格。我们接上好几个本地和远程的服务端，每个提供一种背景信息。

The story故事

A good kopitiam auntie is great at her job because of context, not because she is clever. Auntie Suria remembers that Uncle Lim takes kopi-C kurang manis and sits by the fan. She hears this morning that the road outside is closed for a marathon. She keeps a little book of supplier prices, and she checks the e-wallet terminal to see if today's payments went through. Today you give an agent the same four kinds of context, each from its own MCP server.

一位好的咖啡店阿姨做得好，靠的是背景信息，而不是聪明。Suria 阿姨记得 Lim 叔喝少糖的 kopi-C、爱坐风扇旁。她今早听说门外的路因为马拉松封路了。她有一本记供货价格的小册子，还会去看电子钱包机，确认今天的付款有没有到账。今天你要给一个智能体同样的四种背景信息，每一种都来自它自己的 MCP 服务端。

Step 1 · Four kinds of context第 1 步 · 四种背景信息

Learn先学

Context engineering means choosing what the model gets to see. Auntie's four kinds: memory (facts about people), fresh news (the web), her own notes (a knowledge base she builds) and live systems (payments, stock, prices).

上下文工程（context engineering）就是决定让模型看到什么。阿姨的四种：记忆（关于人的事实）、最新消息（网络）、自己的笔记（她自己建的知识库）和实时系统（付款、库存、价格）。

Each kind can be its own MCP server, and one agent can use several at once. Steps 2 to 5 below take them one at a time.

每一种都可以是单独的 MCP 服务端，一个智能体也可以同时用好几个。下面的第 2 到 5 步会一个一个来。

Auntie Suria The agent remembers Uncle Lim -> memory server (a map of people and facts, in a JSON file) hears about the marathon -> search server (the live web) flips through her price book -> vector server (notes the agent writes itself) checks the e-wallet terminal -> live integration (a company's own MCP server)

Which kind of context is each case?

下面每个情景是哪一种背景信息？

Step 2 · Long-term memory第 2 步 · 长期记忆

Learn先学

Without memory, a new run knows nothing about Uncle Lim. The official memory server stores entities (people), observations about them and relations between them in a JSON file that survives between runs. Create the memory/ folder first.

没有记忆，新的一次运行对 Lim 叔一无所知。官方的记忆服务端把实体（人）、关于他们的观察和它们之间的关系存在一个 JSON 文件里，下次运行还在。请先建好 memory/ 文件夹。

Settings for a server go in its env, here the file path. The agent only needs a sentence telling it to use those tools as memory.

服务端的设置放在它的 env 里，这里是文件路径。智能体只需要一句话，告诉它把这些工具当记忆来用。

pip install openai-agents python-dotenv # plus Node (for npx) and uv (its uvx runs a Python tool without installing it) # keys in .env: OPENAI_API_KEY (and TAVILY_API_KEY in Step 3)
import os from agents import Agent, Runner, trace from agents.mcp import MCPServerStdio from dotenv import load_dotenv load_dotenv() # reads the keys in .env into os.environ memory = {"command": "npx", "args": ["-y", "@modelcontextprotocol/server-memory"], "env": {"MEMORY_FILE_PATH": os.path.abspath("memory/regulars.json")}} RULES = "Use your entity tools as long-term memory: store facts about people and recall them later." async with MCPServerStdio(params=memory, client_session_timeout_seconds=60) as mem: a = Agent(name="auntie", instructions=RULES, model="gpt-4o-mini", mcp_servers=[mem]) await Runner.run(a, "I'm Lim. Kopi-C kurang manis, and I like the table by the fan.") # ...later, a brand new run... async with MCPServerStdio(params=memory, client_session_timeout_seconds=60) as mem: a = Agent(name="auntie", instructions=RULES, model="gpt-4o-mini", mcp_servers=[mem]) print((await Runner.run(a, "I'm Lim. The usual?")).final_output)

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

Welcome back, Lim! Kopi-C kurang manis, and I'll save you the table by the fan.

Step 3 · Fresh news, with one tool allowed第 3 步 · 最新消息，只放行一个工具

Learn先学

A search server keeps the agent current. But many servers offer lots of tools (search, extract, crawl...), and more tools mean more confusion and more tokens (the small pieces of text a model reads and is billed for). The SDK lets you filter them down to the ones you want. This box continues the file from Step 2: put it below those imports, because it reuses os, MCPServerStdio, Agent and Runner. The later boxes do the same.

搜索服务端能让智能体与时俱进。但很多服务端提供一大堆工具（搜索、提取、爬取……），工具越多越容易混乱，也越费 token（模型读取并按量计费的文字小单位）。SDK 可以让你把工具过滤成你想要的那几个。这个代码框接在第 2 步的文件后面：放在那些 import 下面，因为它用到 os、MCPServerStdio、Agent 和 Runner。后面的代码框也一样。

Note that the API key goes to the server through its env, not to the agent.

注意 API 密钥是通过 env 交给服务端的，不是交给智能体。

from datetime import date from agents.mcp import create_static_tool_filter # "@latest" is fine for trying it out; once it works, pin a version number so it cannot change under you search = {"command": "npx", "args": ["-y", "tavily-mcp@latest"], "env": {"TAVILY_API_KEY": os.getenv("TAVILY_API_KEY")}} only_search = create_static_tool_filter(allowed_tool_names=["tavily_search"]) async with MCPServerStdio(params=search, client_session_timeout_seconds=60, tool_filter=only_search) as s: a = Agent(name="news", instructions="Search the web and summarise briefly.", model="gpt-4o-mini", mcp_servers=[s]) print((await Runner.run(a, f"Any road closures in Bukit Timah this weekend? Today is {date.today()}.")).final_output)

Step 4 · Agentic RAG: the agent builds its own notebook第 4 步 · 智能体式 RAG：智能体自己建笔记本

Learn先学

Normal RAG (retrieval-augmented generation: look things up, then answer) loads documents into a vector store up front. In agentic RAG the agent itself decides what to store and when to search. A vector store finds notes by meaning, not by exact words. It turns each note into an embedding: a list of numbers that stands for what the note means, so a question can find a note that uses different words.

普通的 RAG（检索增强生成：先查资料，再回答）会提前把文档装进向量库。在智能体式 RAG 里，存什么、什么时候搜都由智能体自己决定。向量库按意思找笔记，而不是按字面一模一样。它把每条笔记变成一个嵌入（embedding）：一串代表笔记意思的数字，所以问题即使用词不同，也能找到对应的笔记。

The qdrant server gives the agent two tools: qdrant-store (save a note) and qdrant-find (search the notes by meaning). Run 1 searches the web and stores what it finds. Run 2 has no internet, only the notebook. If it gives the prices run 1 found, they came from the notebook. A model with no tools can still guess, so check: look for files in memory/qdrant, or ask it which note it used.

qdrant 服务端给智能体两个工具：qdrant-store（存一条笔记）和 qdrant-find（按意思搜笔记）。第 1 次运行上网搜索，并把找到的存起来。第 2 次运行没有网络，只有笔记本。如果它说出第 1 次找到的价格，就来自笔记本。没有工具的模型也可能瞎猜，所以要核对：看 memory/qdrant 里有没有文件，或问它用了哪条笔记。

from pathlib import Path vectors = {"command": "uvx", "args": ["mcp-server-qdrant"], "env": {"QDRANT_LOCAL_PATH": str(Path("memory/qdrant")), "COLLECTION_NAME": "suppliers"}} NOTES = """You research suppliers on the web and keep a knowledge base. Store anything worth keeping. When asked what you know, search the knowledge base and answer from it.""" # Run 1: search + store async with MCPServerStdio(params=search, tool_filter=only_search, client_session_timeout_seconds=60) as s, \ MCPServerStdio(params=vectors, client_session_timeout_seconds=120) as v: a = Agent(name="buyer", instructions=NOTES, model="gpt-4o-mini", mcp_servers=[s, v]) await Runner.run(a, "Find current wholesale prices for condensed milk in Singapore and remember them.") # Run 2: no web, only the knowledge base async with MCPServerStdio(params=vectors, client_session_timeout_seconds=120) as v: a = Agent(name="buyer", instructions=NOTES, model="gpt-4o-mini", mcp_servers=[v]) print((await Runner.run(a, "From your notes: what does condensed milk cost wholesale?")).final_output)

Step 5 · Live systems: local or remote, and optional第 5 步 · 实时系统：本地或远程，而且可有可无

Learn先学

The fourth kind is a live system: payments, inventory, market data. Many companies now publish an official MCP server. You can run their package locally over stdio, with your API key in env, and you control the version. Or you can use a remote URL: nothing to install, and you trust their uptime and sign-in.

第四种是实时系统：付款、库存、行情数据。现在很多公司都发布了官方 MCP 服务端。你可以用 stdio 在本地运行他们的包，把 API 密钥放进 env，版本由你控制；也可以用远程网址：什么都不用装，但要信任对方的稳定性和登录方式。

Make the code degrade gracefully: if the key is not set, skip that server so the rest of the agent still works. AsyncExitStack lets you open servers one by one (so you can skip some) and closes them all at the end, even if a run fails.

让代码能优雅降级：没有设置密钥就跳过这个服务端，智能体的其他部分照常工作。AsyncExitStack 让你一个一个地打开服务端（所以可以跳过其中一些），结束时全部关掉，即使运行失败也一样。

from contextlib import AsyncExitStack from agents.mcp import MCPServerStreamableHttp # a made-up payments provider, reached by URL payments = MCPServerStreamableHttp(name="payments", params={ "url": "https://mcp.example-pay.test/mcp", "headers": {"Authorization": f"Bearer {os.getenv('PAYMENTS_API_KEY')}"}}) async with AsyncExitStack() as stack: servers = [await stack.enter_async_context(MCPServerStdio(params=memory, client_session_timeout_seconds=60)), await stack.enter_async_context(MCPServerStdio(params=search, tool_filter=only_search, client_session_timeout_seconds=60))] if os.getenv("PAYMENTS_API_KEY"): # no key, no payments server servers.append(await stack.enter_async_context(payments)) a = Agent(name="auntie", instructions=RULES, model="gpt-4o-mini", mcp_servers=servers) print((await Runner.run(a, "Did today's e-wallet payments go through?")).final_output)

Example output: the payments URL above is made up, so a real run there gives a connection error. This is what a real server could let it say.示例输出：上面的付款网址是编的，照抄运行会得到连接错误。这是真实服务端可能让它说出的话。

Yes: all 14 e-wallet payments today went through, none are pending.
What I got wrong我踩过的坑Connecting four servers gave the model 30+ tools, and it started picking odd ones (crawl instead of search). create_static_tool_filter plus a sentence in the instructions about when to use each source fixed most of it. Then a market-data server (a live-system kind like Step 5, and not part of this lesson's code) broke on a fresh uvx run: it used an API that the mcp 2.0 release removed and did not cap its dependency. Pinning with uvx --with "mcp<2" and a version tag (a fixed release label such as @v0.10.0 added to the server's address) made it repeatable. Last, the vector server downloads an embedding model on first start, so it got a 120-second timeout. Memory and vectors are plain files (memory/*.json, memory/qdrant), so deleting the folder is a full reset.连上四个服务端后，模型一下子有了 30 多个工具，开始选些奇怪的（用爬取代替搜索）。用 create_static_tool_filter，再在指令里写一句每个来源什么时候用，就解决了大半。后来有个行情数据服务端（和第 5 步一样属于实时系统，但不在本课的代码里）在新的 uvx 运行里崩了：它用的接口被 mcp 2.0 删掉了，又没有限制依赖版本。用 uvx --with "mcp<2" 再加上版本标签（固定版本的标记，比如加在服务端地址后面的 @v0.10.0）固定版本后，就能稳定复现。最后，向量服务端第一次启动要下载嵌入模型，所以给它设了 120 秒超时。记忆和向量都是普通文件（memory/*.json、memory/qdrant），删掉文件夹就是彻底重置。

Common errors常见错误

• RuntimeError: Attempted to exit cancel scope in a different task: Servers were opened and closed in different tasks (a task is one running piece of async code). Fix: keep one AsyncExitStack and close it in the same task.
• McpError: ... 401 Unauthorized: A remote server needs a key. Fix: put it in .env and pass it in the headers.
• openai.BadRequestError: ... tools: array too long: Too many tools at once. Fix: filter with create_static_tool_filter so each agent sees only what it needs.

• RuntimeError: Attempted to exit cancel scope in a different task：服务在不同的任务里（task，一段正在运行的异步代码）打开和关闭。解决：用同一个 AsyncExitStack，并在同一个任务里关闭。
• McpError: ... 401 Unauthorized：远程服务需要密钥。解决：写进 .env，并放进请求头里传递。
• openai.BadRequestError: ... tools: array too long：一次给了太多工具。解决：用 create_static_tool_filter 筛选，让每个智能体只看到需要的。

Takeaways要点回顾

• Context engineering is choosing what the model sees. Memory, fresh news, own notes and live systems can each be an MCP server.
• The memory server keeps entities, observations and relations in a file that survives between runs.
• Filter a server's tools down to the ones you need: fewer tools, fewer wrong picks, fewer tokens.
• API keys go to the server through env, not to the agent.
• In agentic RAG the agent decides what to store and when to search.
• Live systems: run the package locally (you control the version) or use a remote URL (nothing to install).
• Skip a server when its key is missing, pin versions (mcp<2 means any mcp release below 2; a git tag is a fixed release label such as @v0.10.0), and give slow starts a long timeout.

• 上下文工程就是选择模型能看到什么。记忆、最新消息、自己的笔记和实时系统都可以各自成为一个 MCP 服务端。
• 记忆服务端把实体、观察和关系存在文件里，下次运行还在。
• 把服务端的工具过滤到只剩你需要的：工具少，选错少，token 也少。
• API 密钥通过 env 交给服务端，不是交给智能体。
• 智能体式 RAG 里，存什么、什么时候搜都由智能体决定。
• 实时系统：在本地运行它的包（版本由你控制），或者用远程网址（什么都不用装）。
• 缺密钥就跳过那个服务端，固定版本（mcp<2 表示 2 以下的 mcp 版本；git 标签是固定的版本标记，如 @v0.10.0），启动慢的给足超时时间。

Recap三句回顾

• Each server brings its own tools: memory, search, files, vectors.
• Filter tools so the agent sees only what the task needs.
• Use one exit stack so every server closes cleanly.

• 每个服务带来自己的工具：记忆、搜索、文件、向量。
• 筛选工具，让智能体只看到任务需要的。
• 用同一个退出栈，让每个服务都能干净地关闭。
