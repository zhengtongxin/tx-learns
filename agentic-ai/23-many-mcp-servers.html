Many MCP servers多个 MCP 服务

Give one agent memory, fresh news, its own notes and live systems · ~35 min · hands-on让一个智能体同时拥有记忆、最新消息、自己的笔记和实时系统 · 约 35 分钟 · 动手实践

Key point要点

A good agent is good because of context, not cleverness. Like a kopitiam auntie who remembers a regular's order, hears about the road closure and checks the payment terminal, one agent can plug in several MCP servers, each giving one kind of context.

好智能体靠的是上下文，不是聪明。就像咖啡店阿姨记得熟客的点单、听说了封路消息、还会查付款终端，一个智能体可以接上多个 MCP 服务端，每个提供一种上下文。

Step 1 · Four kinds of context第 1 步 · 四种上下文

Learn先学

Context engineering means choosing what the model gets to see:

  • Memory: facts about people (a memory server).
  • Fresh news: the live web (a search server).
  • Own notes: a knowledge base the agent builds (a vector server).
  • Live systems: payments, stock, prices (a company's own server).

上下文工程就是选择模型能看到什么：

  • 记忆：关于人的事实（记忆服务端）。
  • 最新消息：实时网络（搜索服务端）。
  • 自己的笔记：智能体自己建的知识库（向量服务端）。
  • 实时系统：付款、库存、价格（公司自己的服务端）。

Step 2 · Memory and fresh news第 2 步 · 记忆与最新消息

Learn先学
  • The official memory server stores entities, observations and relations in a JSON file that survives between runs. Settings go in the server's env.
  • A search server keeps the agent current, but servers offer many tools, and more tools mean more wrong picks and more tokens. Filter down to the one you want.
  • The API key goes to the server through env, not to the agent.
  • 官方记忆服务端把实体、观察和关系存在 JSON 文件里，多次运行之间不会丢。设置写在服务端的 env 里。
  • 搜索服务端让智能体保持最新，但服务端往往提供很多工具，工具越多，选错和 token 消耗越多。要过滤到只留需要的那一个。
  • API 密钥通过 env 交给服务端，不是交给智能体。

Step 3 · Own notes and live systems第 3 步 · 自己的笔记与实时系统

Learn先学
  • In agentic RAG the agent itself decides what to store and when to search. The qdrant server gives it qdrant-store and qdrant-find; notes are found by meaning, via embeddings (numbers standing for what a note means).
  • Run 1 searches the web and stores; Run 2 has no internet, only the notes.
  • A live system is a company's own MCP server, local or remote (a URL). If its key is missing, skip it so the rest still works; AsyncExitStack opens servers one by one and closes them all.
  • 智能体式 RAG 里，由智能体自己决定存什么、何时搜。qdrant 服务端给它 qdrant-store 和 qdrant-find；笔记按含义被找到，靠的是嵌入（代表笔记含义的一串数字）。
  • 第 1 次运行上网搜索并存下；第 2 次没有网络，只有笔记。
  • 实时系统是公司自己的 MCP 服务端，本地或远程（一个 URL）。缺密钥就跳过它，其余照常工作；AsyncExitStack 逐个打开服务端，最后统一关闭。
# same file as Step 2: os, Agent, Runner, MCPServerStdio, search and only_search come from there from pathlib import Path from contextlib import AsyncExitStack from agents.mcp import MCPServerStreamableHttp vectors = {"command": "uvx", "args": ["mcp-server-qdrant"], "env": {"QDRANT_LOCAL_PATH": str(Path("memory/qdrant")), "COLLECTION_NAME": "suppliers"}} NOTES = "You research suppliers on the web and keep a knowledge base. Search it when asked what you know." # Run 1: search + store async with MCPServerStdio(params=search, tool_filter=only_search, client_session_timeout_seconds=60) as s, \ MCPServerStdio(params=vectors, client_session_timeout_seconds=120) as v: a = Agent(name="buyer", instructions=NOTES, model="gpt-4o-mini", mcp_servers=[s, v]) await Runner.run(a, "Find current wholesale prices for condensed milk in Singapore and remember them.") # Run 2: no web, only the notes. To check it is not guessing, also ask for a price you never stored: it should say it has none async with MCPServerStdio(params=vectors, client_session_timeout_seconds=120) as v: a = Agent(name="buyer", instructions=NOTES, model="gpt-4o-mini", mcp_servers=[v]) print((await Runner.run(a, "From your notes: what does condensed milk cost wholesale?")).final_output) # a made-up payments provider, reached by URL payments = MCPServerStreamableHttp(name="payments", params={ "url": "https://mcp.example-pay.test/mcp", "headers": {"Authorization": f"Bearer {os.getenv('PAYMENTS_API_KEY')}"}}) async with AsyncExitStack() as stack: servers = [await stack.enter_async_context(MCPServerStdio(params=memory, client_session_timeout_seconds=60))] if os.getenv("PAYMENTS_API_KEY"): # no key, no payments server servers.append(await stack.enter_async_context(payments)) a = Agent(name="auntie", instructions=RULES, model="gpt-4o-mini", mcp_servers=servers)
What I got wrong我犯过的错Four servers gave the model 30+ tools and it picked odd ones (crawl instead of search). A tool filter plus a sentence on when to use each source fixed most of it. Also, the vector server downloads an embedding model on first start, so give it a 120-second timeout.四个服务端给了模型 30 多个工具，它开始乱选（用爬取代替搜索）。工具过滤加一句“何时用哪个来源”解决了大半问题。另外，向量服务端第一次启动要下载嵌入模型，所以给它 120 秒超时。

Takeaways要点回顾

• Context engineering is choosing what the model sees; memory, news, own notes and live systems can each be an MCP server.
• Filter a server's tools: fewer tools, fewer wrong picks, fewer tokens.
• API keys go to the server through env, not to the agent.
• In agentic RAG the agent decides what to store and when to search.
• Skip a server when its key is missing, pin versions, and give slow starts a long timeout.

• 上下文工程就是选择模型看到什么；记忆、新闻、自己的笔记和实时系统都可以是一个 MCP 服务端。
• 过滤服务端的工具：工具少，选错少，token 少。
• API 密钥通过 env 交给服务端，不是智能体。
• 智能体式 RAG 里，由智能体决定存什么、何时搜。
• 缺密钥就跳过服务端，锁定版本，给启动慢的服务端长一点的超时。
