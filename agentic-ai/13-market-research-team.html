Multi-agent teams · Project多智能体团队 · 项目

Market research team市场调研团队

Build a crew with a manager that searches the web, studies each option and pings your phone with one pick · ~35 min · hands-on搭一个带主管的团队：联网搜索、逐一研究，最后把唯一的推荐推送到你的手机 · 约 35 分钟 · 动手实践

Key point要点

A manager over three specialists can answer an open question such as “which night market should a kuih stall try next?”: a scout searches the web, a researcher studies each option, a picker chooses one and pings your phone.

一位主管带三位专才，就能回答开放式问题，比如“kuih 摊位下一个该去哪个夜市？”：侦察员上网搜索，研究员逐个研究，挑选员选出一个并推送到你的手机。

Step 1 · Tools and typed hand-overs第 1 步 · 工具与有类型的交接

Learn先学

A model cannot know what is trending today. A tool lets an agent reach outside its head: SerperDevTool (from crewai_tools) searches the web and needs a SERPER_API_KEY. Each search uses quota.

Free text between agents is fragile, so give each task a form: a Pydantic BaseModel plus output_pydantic. context names which earlier results a task reads.

模型不知道今天什么正热门。工具让智能体能做“脑子”以外的事：SerperDevTool（来自 crewai_tools）可搜索网络，需要 SERPER_API_KEY。每次搜索都消耗配额。

智能体之间传自由文本很脆弱，所以给每个任务一张表格：Pydantic 的 BaseModel 加 output_pydantic。context 指明任务要读哪些前面的结果。

from pydantic import BaseModel, Field from crewai import Agent, Task from crewai_tools import SerperDevTool # Serper is a web-search service: free key at serper.dev, saved as SERPER_API_KEY in .env class Market(BaseModel): name: str why_now: str = Field(description="Why people are talking about it lately") class MarketList(BaseModel): markets: list[Market] # the methods below sit inside a @CrewBase class, PasarPicker, that reads config/agents.yaml and config/tasks.yaml @agent def scout(self) -> Agent: return Agent(config=self.agents_config["scout"], tools=[SerperDevTool()], verbose=True) @task def find_markets(self) -> Task: return Task(config=self.tasks_config["find_markets"], output_pydantic=MarketList)
# config/tasks.yaml study_markets: description: > For each market found, research crowd, rent and competition for a kuih stall in {state}. expected_output: > A study of each market. agent: researcher context: - find_markets

Step 2 · A custom tool that pings a phone第 2 步 · 能给手机发提醒的自定义工具

Learn先学

A custom tool is a plain function with @tool. The docstring is what the model reads, so write it like instructions to a new colleague.

This one sends a push through Pushover (PUSHOVER_USER and PUSHOVER_TOKEN in .env). Only the picker gets it.

自定义工具就是带 @tool 的普通函数。文档字符串就是模型读到的说明，要像给新同事写指示一样去写。

这个工具通过 Pushover 发推送（.env 里放 PUSHOVER_USER 和 PUSHOVER_TOKEN）。只有挑选员拿到它。

import os, requests from crewai.tools import tool @tool("Notify Owner") def notify(message: str) -> str: """Send a short push message to the stall owner's phone. Args: message: the text to send, under 200 characters. """ resp = requests.post( "https://api.pushover.net/1/messages.json", data={"user": os.getenv("PUSHOVER_USER"), "token": os.getenv("PUSHOVER_TOKEN"), "message": message}, ) return f"sent, status {resp.status_code}" @agent def picker(self) -> Agent: return Agent(config=self.agents_config["picker"], tools=[notify], verbose=True)

Step 3 · A manager and memory第 3 步 · 主管与记忆

Learn先学

Go hierarchical: build the manager inside crew() with allow_delegation=True and pass it as manager_agent=. Do not declare it with @agent, or it becomes one more worker.

Add memory=True so a prompt like “find markets you have not suggested before” works across runs, and pass today's date so “trending now” means something.

改成层级式：在 crew() 里创建主管，带 allow_delegation=True，用 manager_agent= 传入。不要用 @agent 声明它，否则它会变成又一个工人。

加上 memory=True，“找出你以前没推荐过的夜市”这类提示才能跨次运行生效；再传入今天的日期，“最近热门”才有意义。

from datetime import date @crew def crew(self) -> Crew: # config/agents.yaml has a "boss" entry (role, goal, backstory) like the other three boss = Agent(config=self.agents_config["boss"], allow_delegation=True) return Crew( agents=self.agents, # scout, researcher, picker (not the boss) tasks=self.tasks, process=Process.hierarchical, manager_agent=boss, memory=True, verbose=True, ) # each input fills the slot of the same name in the YAML files, e.g. in find_markets: # description: As of {today}, find night markets people are talking about in {state}. PasarPicker().crew().kickoff(inputs={"state": "Singapore", "today": str(date.today())})

Which team member does each job? Sort them.

每项工作该由哪位队员来做？请分类。

What I got wrong我犯过的错I listed the boss as a worker. A hierarchical crew is also chatty: say exactly what each expected_output is, and when the flow is fixed anyway, sequential with context is more reliable.我把主管列成了工人。层级式团队也很啰嗦：把每个 expected_output 写清楚；如果流程本来就固定，用带 context 的顺序式更可靠。

Takeaways要点回顾

• A tool like SerperDevTool reaches the live web; each call costs quota.
• output_pydantic plus context give the next agent a typed list.
• In a custom tool, the docstring is the description the model reads.
• The manager is passed as manager_agent=, not listed in agents.
• memory=True plus “not suggested before” gives a fresh shortlist each run.

• SerperDevTool 这样的工具能访问实时网络，每次调用都消耗配额。
• output_pydantic 加 context 让下一个智能体读到有类型的列表。
• 自定义工具里，文档字符串就是模型读到的说明。
• 主管用 manager_agent= 传入，不列在 agents 里。
• memory=True 加上“以前没推荐过”，每次都得到新名单。
