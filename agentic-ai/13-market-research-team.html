Project: a market research team项目：市场调研团队

Build a crew with a manager that searches the web, studies each option and pings your phone with one pick · ~35 min · hands-on搭一个带主管的团队：联网搜索、逐一研究，最后把唯一的推荐推送到你的手机 · 约 35 分钟 · 动手实践

Where we left off上回讲到

Last time the assistant ran as a small crew with roles and tasks, but it only argued about one menu idea. Today it fails when Uncle Lim asks where a second Kopi Corner should open, which needs the web and one clear pick. We fix it by putting a manager over a scout, a researcher and a picker.

上回助手组成了有角色和任务的小团队，但只会讨论一个菜单点子。今天的问题是：Lim 叔叔问第二间 Kopi Corner 该开在哪里，这需要上网查，还要给出一个明确的选择。我们的办法是在侦察员、研究员和挑选员上面放一位主管。

Side case支线案例

Mei's aunt sells kuih (bite-sized Malaysian cakes) and wants a second stall at a pasar malam (night market). She asks: “Which one should I go to?” Answering that well takes a small team. A scout searches online for night markets people are talking about right now. A researcher studies each one: crowd, rent, how many kuih sellers are already there. A picker chooses the single best market and messages the aunt's phone. A manager sits above them, hands out the work and checks it. Mei's aunt's question is the same one Uncle Lim asks about a second Kopi Corner.

Mei 的阿姨卖 kuih（马来西亚小糕点），想在 pasar malam（夜市）再开一个摊位。她问：“我该去哪一个？”要答好这个问题，需要一个小团队。侦察员上网搜索最近大家在谈论的夜市。研究员逐个研究：人流、租金、已有多少卖 kuih 的摊位。挑选员选出唯一最好的夜市，并发消息到阿姨的手机。上面还有一位主管，负责分配工作并检查。Mei 阿姨的问题，和 Lim 叔叔问第二间 Kopi Corner 的是同一个。

Step 1 · Give the scout a web search tool第 1 步 · 给侦察员一个联网搜索工具

Learn先学

A model only knows what it learnt in the past, and night markets open and close all the time. A tool lets an agent do something outside its own head. CrewAI ships ready-made tools in the crewai_tools package. SerperDevTool searches the web through the Serper service, and it needs a SERPER_API_KEY.

Each search counts against your quota, so keep test runs small. Putting today's date into the scout's task helps too: “trending now” means nothing to a model that does not know the date. We pass that date in at kickoff, later.

模型只知道过去学到的东西，而夜市随时在开张和关门。工具让智能体能做它“脑子”以外的事。CrewAI 在 crewai_tools 包里自带现成的工具。SerperDevTool 通过 Serper 服务搜索网络，需要一个 SERPER_API_KEY。

每次搜索都会消耗配额，所以测试时要少跑。在侦察员的任务里写上今天的日期也有帮助：不知道日期的模型，没法理解“最近热门”。这个日期我们稍后在启动时传入。

# inside the crew project # uv add crewai-tools # .env needs: OPENAI_API_KEY and SERPER_API_KEY from crewai import Agent from crewai_tools import SerperDevTool @agent def scout(self) -> Agent: return Agent( config=self.agents_config["scout"], tools=[SerperDevTool()], # can now search the web verbose=True, )

Step 2 · Pass typed lists between agents第 2 步 · 在智能体之间传有类型的列表

Learn先学

Free text between agents is fragile: the researcher can misread what the scout wrote. Instead, hand the scout a form to fill in. A class built on BaseModel (from the library Pydantic, the same idea as in the structured outputs lesson) is a form with named blanks, and output_pydantic tells the task to answer in that form.

Then link the tasks with context. It names which earlier tasks' results a task should read, so the researcher definitely gets the scout's list.

智能体之间传自由文本很脆弱：研究员可能读错侦察员写的内容。换个做法：给侦察员一张表格去填。基于 BaseModel（来自 Pydantic 库，和结构化输出那一课是同一个思路）的类就是一张有具名空格的表格，output_pydantic 让任务按这张表格作答。

然后用 context 把任务连起来。它指明某个任务要读哪些前面任务的结果，这样研究员一定能拿到侦察员的名单。

from pydantic import BaseModel, Field from crewai import Task class Market(BaseModel): name: str = Field(description="Name of the night market") town: str = Field(description="Town or area") why_now: str = Field(description="Why people are talking about it lately") class MarketList(BaseModel): markets: list[Market] = Field(description="Night markets worth a look") class MarketStudy(BaseModel): name: str crowd: str = Field(description="Typical crowd size and peak hours") rent: str = Field(description="Rough stall rent per night, in RM") competition: str = Field(description="How many kuih sellers are already there") verdict: str = Field(description="Is it worth a stall?") class MarketStudyList(BaseModel): studies: list[MarketStudy] @task def find_markets(self) -> Task: return Task(config=self.tasks_config["find_markets"], output_pydantic=MarketList) @task def study_markets(self) -> Task: return Task(config=self.tasks_config["study_markets"], output_pydantic=MarketStudyList)
# config/tasks.yaml study_markets: description: > For each market found, research crowd, rent and competition for a kuih stall in {state}. expected_output: > A study of each market. agent: researcher context: - find_markets output_file: output/studies.json

Step 3 · Build a tool that pings a phone第 3 步 · 做一个能给手机发提醒的工具

Learn先学

The ready-made tools do not cover everything, so you can write your own. It is a plain function with the @tool decorator. The one rule that matters: the docstring is the description the model reads. Write it like instructions to a new colleague, including what each argument means.

This one sends a push message through Pushover, a notification service. It needs PUSHOVER_USER and PUSHOVER_TOKEN in .env. Only the picker will get it.

现成的工具不能涵盖所有需求，所以你可以自己写。它就是一个带 @tool 装饰器的普通函数。最关键的一条规则：文档字符串（docstring）就是模型读到的说明。要像给新同事写指示一样去写，包括每个参数的含义。

这个工具通过通知服务 Pushover 发送推送消息，需要在 .env 里放 PUSHOVER_USER 和 PUSHOVER_TOKEN。只有挑选员会拿到它。

# tools/notify.py import os, requests from crewai.tools import tool @tool("Notify My Aunt") def notify(message: str) -> str: """Send a short push message to the stall owner's phone. Args: message: the text to send, under 200 characters. """ resp = requests.post( "https://api.pushover.net/1/messages.json", data={"user": os.getenv("PUSHOVER_USER"), "token": os.getenv("PUSHOVER_TOKEN"), "message": message}, ) return f"sent, status {resp.status_code}" # in crew.py: only the picker gets this tool @agent def picker(self) -> Agent: return Agent(config=self.agents_config["picker"], tools=[notify], verbose=True)

Step 4 · Put a manager on top第 4 步 · 在上面放一位主管

Learn先学

Now the crew goes hierarchical with your own manager agent, like the one in the roles lesson but with a full description. Two rules. The manager needs allow_delegation=True so it may hand work out. And it is passed as manager_agent=, not listed in agents. If you declared it with @agent, the crew would treat it as one more ordinary worker.

Start the crew with today's date, so the scout's “trending now” has something to measure against.

现在让团队变成层级式，并用你自己的主管智能体，就像角色那一课里讲的，不过这次有完整的设定。有两条规则。主管需要 allow_delegation=True，才能把活分出去。而且它要用 manager_agent= 传入，不能列在 agents 里。如果你用 @agent 声明了它，团队会把它当成又一个普通工人。

启动团队时带上今天的日期，这样侦察员的“最近热门”才有个参照。

from datetime import date @crew def crew(self) -> Crew: boss = Agent(config=self.agents_config["boss"], allow_delegation=True) return Crew( agents=self.agents, # scout, researcher, picker (not the boss) tasks=self.tasks, process=Process.hierarchical, manager_agent=boss, verbose=True, ) PasarPicker().crew().kickoff(inputs={"state": "Selangor", "today": str(date.today())})

Expected output (your wording will differ)预期输出（你的措辞会有所不同）

$ crewai run ... Task find_markets completed: 6 night markets found Task study_markets completed $ ls output markets.json studies.json report.md

Which team member does each job? Sort them.

每项工作该由哪位队员来做？请分类。

Step 5 · Add memory so the shortlist stays fresh第 5 步 · 加上记忆，让名单保持新鲜

Learn先学

Run the crew twice and you may get the same three markets twice. memory=True turns on CrewAI's built-in memory. Short-term memory holds what happened earlier in this run. Long-term memory keeps results and lessons from earlier runs on disk. Entity memory keeps facts about named things, such as one market or one town.

The neat trick is to pair memory with the prompt. If the scout's task says “find markets you have not suggested before”, long-term memory is what makes that sentence work across runs. Memory needs an embedder (it turns text into numbers so it can be searched), which by default uses the same OpenAI key, so each run costs a little extra.

团队跑两次，可能会两次都拿到同样的三个夜市。memory=True 会打开 CrewAI 内置的记忆。短期记忆保存这一次运行里早先发生的事。长期记忆把以前运行的结果和教训存在磁盘上。实体记忆保存有名字的事物的信息，比如某个夜市或某个城镇。

巧妙之处是把记忆和提示词配合起来。如果侦察员的任务写着“找出你以前没推荐过的夜市”，是长期记忆让这句话在多次运行之间真正生效。记忆需要一个嵌入模型（把文字变成数字以便检索），默认用同一个 OpenAI 密钥，所以每次运行会多花一点钱。

# config/tasks.yaml find_markets: description: > Today is {today}. Search for night markets in {state} that people are talking about right now. Find markets you have not suggested before. expected_output: > A list of night markets, each with a reason it is trending. agent: scout
# crew.py return Crew( agents=self.agents, tasks=self.tasks, process=Process.hierarchical, manager_agent=boss, memory=True, # short-term, long-term and entity memory verbose=True, )
What I got wrong我犯过的错I listed the boss as a worker. Declared with @agent, the manager became an ordinary member of the crew. With manager_agent= you build it inside crew() without the decorator. A hierarchical crew is chatty. The manager re-delegated the same task several times and once skipped the notification. Clear expected_output text and telling the picker to “always send exactly one notification” helped. When the flow is fixed anyway, sequential with context is more reliable. Stale and costly search. Every Serper call uses quota, and results looked old until I put {today} in the scout's task.我把主管列成了工人。用 @agent 声明后，主管变成了团队里的普通成员。用 manager_agent= 时，要在 crew() 里创建它，并且不加装饰器。层级式团队很啰嗦。主管把同一个任务重复分配好几次，有一次还漏掉了通知。写清楚 expected_output，并告诉挑选员“必须只发一条通知”，就好多了。如果流程本来就固定，用带 context 的顺序式更可靠。搜索结果过时又花钱。每次 Serper 调用都消耗配额，在侦察员的任务里加上 {today} 之前，结果看上去都很旧。
Check before you trust it相信之前先核对The team ranks what the web says. Before the aunt pays any rent, Mei visits the market once and counts the kuih sellers herself.团队只是把网上的说法排了个序。在阿姨交任何租金之前，Mei 要亲自去那个夜市一趟，自己数一数卖 kuih 的摊位。

Common errors常见错误

• pydantic.ValidationError: 1 validation error for MarketList: The task's answer did not match output_pydantic. Fix: make expected_output in the YAML describe the same list shape.
• KeyError: 'today': The YAML mentions {today} but you did not pass it. Fix: add "today": str(date.today()) to inputs.
• Search tool returns nothing / 403 from the search service: SERPER_API_KEY is missing in .env. Fix: add it and restart crewai run.

• pydantic.ValidationError: 1 validation error for MarketList：任务的回答和 output_pydantic 不匹配。解决：让 YAML 里的 expected_output 描述同样的列表结构。
• KeyError: 'today'：YAML 里用了 {today}，但你没传。解决：在 inputs 里加上 "today": str(date.today())。
• Search tool returns nothing / 403 from the search service：.env 里没有 SERPER_API_KEY。解决：补上它，再重新运行 crewai run。

Takeaways要点回顾

• A tool like SerperDevTool lets an agent reach the live web. Each call costs quota.
• Pass a Pydantic form with output_pydantic so the next agent reads a typed list, not loose text.
• context names which earlier results a task reads.
• In a custom tool, the docstring is the description the model reads.
• A manager is passed as manager_agent=, with allow_delegation=True, and is not in agents.
• Hierarchical is flexible but chatty. Clear expected outputs keep it in line.
• memory=True plus a prompt like “not suggested before” gives a fresh shortlist each run.
• Put today's date in the task so “trending now” means something.

• SerperDevTool 这样的工具让智能体能访问实时网络，每次调用都消耗配额。
• 用 output_pydantic 传一张 Pydantic 表格，下一个智能体读到的就是有类型的列表，而不是零散文字。
• context 指明任务要读哪些前面的结果。
• 自定义工具里，文档字符串就是模型读到的说明。
• 主管用 manager_agent= 传入，带 allow_delegation=True，不在 agents 里。
• 层级式灵活但啰嗦，写清预期输出能让它守规矩。
• memory=True 加上“以前没推荐过”这样的提示，每次运行都有新名单。
• 在任务里写上今天的日期，“最近热门”才有意义。
