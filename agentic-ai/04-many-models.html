Step 1 · Pick the right model第 1 步 · 选对模型

Learn先学

Providers sell models in sizes. Small ones are fast and cheap, big ones think harder. Three more options sit outside that ladder: DeepSeek (strong and cheap), Groq (open-source models on very fast hardware) and Ollama (open-source models on your own machine). Open-source means the model's files are public, so anyone can run them.

厂商按大小出售模型：小的又快又便宜，大的思考更深入。另外还有三种不在这个阶梯里的选择：DeepSeek（强而便宜）、Groq（在极快硬件上运行开源模型）和 Ollama（在你自己电脑上运行开源模型）。开源是指模型文件公开，谁都可以自己运行。

Step 2 · One code shape, three swaps第 2 步 · 同一种代码，只换三样

Learn先学

Almost every provider offers an endpoint (the web address your code sends its requests to) that speaks the same language as OpenAI. So you reuse the same OpenAI client and only change where it points. To switch provider you change only three values: the key (whose account pays), the address base_url (where the request is sent) and the model name (which brain answers). Everything else stays exactly the same. In the code, os.getenv("OPENAI_API_KEY") reads the key from an environment variable, a named setting kept outside your code (Lesson 3 loaded it from .env), so the key itself is never typed into the script.

几乎每家厂商都提供与 OpenAI 说同一种“语言”的接口（endpoint，也就是你的代码发送请求的网址）。所以你可以复用同一个 OpenAI 客户端，只改它指向的地址。换厂商只需要改三个值：密钥（用谁的账户付费）、地址 base_url（请求发往哪里）和模型名（由哪个模型回答）。其余全部保持不变。代码里的 os.getenv("OPENAI_API_KEY") 从环境变量（保存在代码之外、带名字的设置）里读取密钥（第 3 课已用 .env 加载），所以密钥本身不会写进脚本。

Python · compare.py (OpenAI)Python · compare.py（OpenAI）
import os from openai import OpenAI client = OpenAI(api_key=os.getenv("OPENAI_API_KEY")) response = client.chat.completions.create( model="gpt-5.4-nano", messages=messages) answer = response.choices[0].message.content

Step 3 · Run a model on your own machine第 3 步 · 在自己的电脑上运行模型

Learn先学

Ollama is the same trick with the server on your laptop: free, private and offline. A server is a program that waits for requests and answers them. localhost means “this computer”, and 11434 is the port (a numbered door on your computer) Ollama listens on, so http://localhost:11434 reaches Ollama on your own machine. The setup is a short checklist, then the call looks like any other provider.

Ollama 用的是同样的办法，只是服务器就在你的笔记本上：免费、私密、可离线。服务器是一个等着接收请求并作答的程序。localhost 的意思是“这台电脑”，11434 是 Ollama 监听的端口（电脑上带编号的“门”），所以 http://localhost:11434 指向你自己电脑上的 Ollama。安装只是一份简短清单，之后的调用和其他厂商一样。

Shell · terminalShell · 终端
ollama pull llama3.2
Python · compare.py (Ollama)Python · compare.py（Ollama）
# same compare.py: it reuses the OpenAI import and the messages list from above ollama = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama") ollama.chat.completions.create(model="llama3.2", messages=messages)
Mind the size注意大小Many Ollama models are far too big for a home computer. Start with ones around 3 GB (gigabytes of disk space) or less, such as llama3.2. Avoid names ending in :cloud, which are a hosted service, not local.很多 Ollama 模型对家用电脑来说太大。先从 3 GB（千兆字节的磁盘空间）左右或更小的开始，例如 llama3.2。避开以 :cloud 结尾的名称，那是托管服务，不是本地运行。

Step 4 · Build the competition第 4 步 · 搭建模型擂台

Learn先学

Aina's script does seven things in a fixed order. Each step needs something the step before it made, so the order cannot change. One script can hold more than one pattern: feeding one call's output into the next is prompt chaining, and sending the same question to many models independently is parallelization. The walk-through marks which is which. Go one step at a time.

Aina 的脚本按固定顺序做七件事。每一步都要用到前一步产生的东西，所以顺序不能换。一个脚本里可以同时有多种模式：把一次调用的输出喂给下一次是提示链，把同一个问题独立地发给多个模型是并行化。走读过程里会标出各是哪一种。一步一步走一遍。

Step 5 · Be the judge第 5 步 · 当一次裁判

Learn先学

The question was written by the model in step 1, because Aina asked it for a hard, open question to stress-test her customer helper. It came back as: “Which matters more to a society, truth or trust? Answer in two sentences.” Real customers will ask easier things, but the same ranking works for them. A judge model must reply in strict JSON (a plain-text format of labels and values, like {"best": 2}) so code can read it. Then the code maps numbers back to names.

这个问题是第 1 步里的模型写的，因为 Aina 让它出一道难的开放题，用来给顾客助手做压力测试。它给出的是：“对一个社会来说，真相和信任哪个更重要？用两句话回答。”真实顾客问的会简单些，但同样的排名办法照样适用。裁判模型必须返回严格的 JSON（一种由标签和值组成的纯文本格式，比如 {"best": 2}），代码才能读取。然后代码把编号映射回模型名称。

First, be the judge yourself, using clarity and strength of argument. Three answers came back:

先自己当裁判，标准是表达清晰度和论证力度。回来了三个回答：

#1 Both matter and it really depends on the situation and many factors.
#2 Trust. A truth nobody believes changes nothing, while trust lets a society keep finding and correcting its mistakes.
#3 Truth, because trust built on lies eventually collapses.

#1 两者都重要，这真的取决于具体情况和许多因素。
#2 信任。没人相信的真相改变不了什么，而信任能让社会不断发现并纠正自己的错误。
#3 真相，因为建立在谎言上的信任终将崩塌。

A judge using that rubric would reply {"results": ["2", "3", "1"]}. The judge only does that because the prompt tells it to. Here is the prompt, with the answers already glued in as “Response from competitor N”:

按这个标准，裁判会返回 {"results": ["2", "3", "1"]}。裁判之所以这样回复，是因为提示词要求它这样做。下面是提示词，各回答已经拼成“Response from competitor N”放在里面：

Python · compare.py (the judge prompt)Python · compare.py（裁判提示词）
# together = the numbered answers glued into one string (see Step 4) # competitors = the list of model names judge = f"""You are judging a competition between {len(competitors)} competitors. Rank them by clarity and strength of argument for this question: {question} {together} Reply only with JSON, best first, like {{"results": ["2", "3", "1"]}}. """

Now read a verdict in code.

现在来读代码里的裁判结论。

Python · compare.py (reading the verdict)Python · compare.py（读取结论）
import json competitors = ["model-A", "model-B", "model-C"] reply = '{"results": ["2", "3", "1"]}' # the judge's reply: text in JSON form, best first results = json.loads(reply)["results"] # JSON text -> a Python list: ["2", "3", "1"] competitor = competitors[int(results[0]) - 1]
One after another逐个运行A plain for loop calls the models one at a time, so total time is the sum. Truly parallel calls need async (code that starts many calls without waiting for each to finish). The pattern “parallelization” is about the idea, independent calls, not how this loop is written.普通的 for 循环一次只调用一个模型，总耗时是各次之和。真正并行需要 async（不必等一个调用结束就能发起许多调用的写法）。“并行”模式讲的是思路：彼此独立的调用，而不是这个循环的写法。
Know the limits了解局限A judge is one more model, so its ranking is an opinion. Use a strong model, hide who wrote what, and spot-check the result.裁判也是一个模型，所以它的排名只是一种意见。请用强模型，隐藏回答者身份，并抽查结果。

Takeaways要点回顾

• Pick the size to match the job: small for volume, large for hard thinking, local for privacy.
• Switching providers means changing base_url, the key and the model name.
• Ask a judge for JSON so your code can read the ranking.
• You do not need every provider. One key is enough to practise.

• 按任务选大小：量大用小模型，难题用大模型，隐私用本地模型。
• 换厂商只需改 base_url、密钥和模型名。
• 让裁判返回 JSON，代码才能读取排名。
• 不需要用遍所有厂商，一个密钥就足够练习。
