Your own agent loop自写智能体循环

You build a coordinator agent that runs five workers, checks their pages in a browser and finishes on its own · ~45 min · project你做一个总协调智能体：指挥五个工人、在浏览器里检查页面，并能自己收工 · 约 45 分钟 · 项目

Key point要点

Frameworks hide the loop, so write the outer one yourself: a coordinator agent with a few tools that starts workers, watches a shared board, inspects each result and stops. Example: five builders each make one booth page for a school fair site. The code uses Google's Agent Development Kit (pip install google-adk, a GOOGLE_API_KEY) with a Gemini model; any framework would do, because the loop is the same.

框架把循环藏起来了，所以自己写外层循环：一个带几件工具的总协调智能体，负责启动工人、盯着共享的任务板、检查每个成果，然后收工。示例：五位建造者各做校园义卖会网站的一个摊位页面。代码用的是 Google 的 Agent Development Kit（pip install google-adk，需要 GOOGLE_API_KEY）和一个 Gemini 模型；换任何框架都行，因为循环是一样的。

Step 1 · The agent decides, the tools do the mechanics第 1 步 · 智能体做决定，工具做机械活

Learn先学
  • Each worker already has an inner loop: its model picks a tool, reads the result and picks again until its page is built. Your new code is the outer loop, one level up: an agent doing the same thing with whole workers in place of tools.
  • Anything brittle and exact (starting processes, timeouts, checking files) goes into a tool. Anything that is a choice (what to build, whether a page is good enough, who to send back) is left to the model.
  • 每个工人已经有自己的内层循环：它的模型挑一个工具、读结果、再挑，直到页面做好。你新写的是高一层的外层循环：一个智能体做同样的事，只是把工具换成了整个工人。
  • 凡是脆弱又精确的事（启动进程、超时、检查文件）放进工具；凡是需要选择的事（做什么、页面够不够好、打回谁）交给模型。

Step 2 · A fresh inspector, then the coordinator第 2 步 · 全新的检查员，再是总协调

Learn先学
  • To check a page, start a new, short-lived agent with a real browser and one report tool. The browser comes from the Playwright MCP server: MCP is a standard way to plug ready-made tools into an agent, and this server starts with one npx command. A fresh agent per page keeps each session small. No report means “no verdict”, which counts as failing.
  • The coordinator's tools: start a builder (returns at once, so all five run in parallel), wait (its own tool, so the coordinator decides when), inspect, send back.
  • Cap the loop with max_llm_calls so it cannot run forever.
  • 检查页面时，启动一个全新、短命的智能体，配真实浏览器和一个 report 工具。浏览器来自 Playwright MCP 服务：MCP 是把现成工具接到智能体上的标准方式，这个服务用一条 npx 命令就能启动。每个页面一个新智能体，会话就不会膨胀。没有汇报就是“没有结论”，算作不通过。
  • 总协调的工具：启动建造者（立即返回，所以五个并行）、等待（单独一个工具，由总协调决定何时等）、检查、打回。
  • 用 max_llm_calls 给循环封顶，防止永远跑下去。
from google.adk.agents import LlmAgent from google.adk.agents.run_config import RunConfig from google.adk.runners import InMemoryRunner from google.adk.tools.mcp_tool import McpToolset, StdioConnectionParams from mcp import StdioServerParameters from google.genai import types async def run_once(agent, max_llm_calls): """Run one agent to the end, with a cap on model calls.""" runner = InMemoryRunner(agent=agent, app_name="inspect") session = await runner.session_service.create_session(app_name="inspect", user_id="coord") msg = types.Content(role="user", parts=[types.Part(text="Begin.")]) async for _ in runner.run_async(user_id="coord", session_id=session.id, new_message=msg, run_config=RunConfig(max_llm_calls=max_llm_calls)): pass async def judge(uri: str) -> dict: verdict = {} def report(works: bool, note: str) -> dict: """Record whether the page loads and the widget works, with one short note.""" verdict.update(works=works, note=note) return {"ok": True} browser = McpToolset(connection_params=StdioConnectionParams( server_params=StdioServerParameters(command="npx", args=["-y", "@playwright/mcp@latest", "--browser", "chrome", "--isolated"]), timeout=30.0)) # the first browser call starts slowly inspector = LlmAgent(name="inspector", model="gemini-2.5-flash", instruction=f"Open {uri}, try the widget, check the console, then call report.", tools=[browser, report]) try: await run_once(inspector, max_llm_calls=25) finally: await browser.close() return verdict or {"works": False, "note": "no verdict"}

Returns immediately.""" goal = board.add_goal(f"Build the {booth} page in site/{team.slug(framework)}/") team.start(framework, goal) return f"{framework} is building {booth}" async def wait_for_builders() -> str: """Block until every started worker exits or times out. Returns the status.""" await team.wait_all(timeout=300) return team.status() async def inspect_page(slug: str) -> str: """Open one finished page in a real browser and report whether it works.""" return str(await judge(f"http://localhost:8000/{slug}/")) # the site folder, served locally def send_back(framework: str, problem: str) -> str: """Give one worker a single fix task that describes the problem.""" return team.fix_once(framework, problem) # fix_once refuses a second fix for the same page return [start_builder, wait_for_builders, inspect_page, send_back] coordinator = LlmAgent(name="fair_coordinator", model="gemini-2.5-flash", instruction="Build the fair site with your team: start every builder, wait, inspect each page, " "send back at most one fix per page, then finish.", tools=make_tools(team))

Step 3 · The board and the guardrails第 3 步 · 任务板与护栏

Learn先学
  • The coordinator never talks to a builder directly. Each builder claims its goal on the shared board, writes its steps under it and ticks them off. The same board gives you a live view.
  • A team of agents can burn money and time forever. Limit everything, and decide in advance what happens on failure.
  • 总协调从不直接和建造者对话。每位建造者在共享任务板上认领目标，在下面写自己的步骤并逐项勾掉。同一块板子还能做实时显示。
  • 一群智能体可能永远烧钱烧时间。每样东西都设上限，并提前决定失败时怎么办。

Sort these safeguards by the problem they solve.

把这些保险措施按它们解决的问题分类。

What I got wrong我犯过的错Worker banners tore the live view apart until I sent their output to DEVNULL. And the default 5-second MCP timeout was too short for the first browser call, so I raised it to 30.工人打印的横幅把实时显示撕得七零八落，直到我把它们的输出送进 DEVNULL。默认 5 秒的 MCP 超时对第一次浏览器调用太短，我调成了 30 秒。

Now make it yours现在把它变成你的

Takeaways要点回顾

• The outer loop is an agent with a few tools: the agent chooses, the tools do the exact mechanics.
• Start workers without waiting so they run together; waiting is its own tool.
• The shared board is the only channel between coordinator and workers.
• Use a fresh, short-lived inspector with a real browser for each page.
• Bound everything: model calls, worker time, one fix per page, plus a plain fallback page.

• 外层循环是一个带几件工具的智能体：智能体做选择，工具做精确的机械活。
• 启动工人时不等待，让它们同时跑；等待是单独的工具。
• 共享任务板是总协调和工人之间唯一的通道。
• 每个页面用一个全新、短命、带真实浏览器的检查员。
• 一切都设上限：模型调用、工人时间、每页只修一次，再加一个朴素的兜底页面。
