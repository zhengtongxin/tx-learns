The big picture整体思路

An LLM API is a function you call over the internet: you send a list of messages, you get text back. An agent is built from many such calls, so this tiny skill is the foundation of everything that follows.

LLM API 就是一个通过网络调用的函数：你发送一组消息，它返回文本。智能体由许多次这样的调用组成，所以这个小技能是后面一切的基础。

Step 1 · Keep your key safe第 1 步 · 安全保管密钥

Your API key is like a password that also bills your credit card. Never paste it into code. Put it in a file named .env in your project folder, and let Python read it from there.

API 密钥就像一个会扣你信用卡的密码。不要把它写进代码里，而是放在项目文件夹的 .env 文件中，让 Python 从那里读取。

Digging out the reply取出回复 response.choices[0].message.content reads as: the response → its list of choices → the first one → its message → the content (your text). response.choices[0].message.content 的意思是：响应 → 其 choices 列表 → 第一项 → 它的 message → 其中的 content（你要的文字）。

Messages are a list消息是一个列表

Each message is a small dictionary with a role and some content. Today you only need the user role (that's you speaking).

每条消息都是一个带有角色和内容的小字典。今天只需要 user 角色（也就是你在说话）。

messages = [{"role": "user", "content": "Tell me a fun fact"}]
Each call starts fresh每次调用都从零开始The model remembers nothing between calls. Anything it should know must be inside the messages you send. That's why, in the chain below, we paste earlier results into the next prompt.模型在两次调用之间什么都不记得。它需要知道的内容，必须写在你发送的消息里。这就是为什么在下面的调用链里，要把上一步的结果粘贴进下一个提示词。

Step 3 · Chain three calls第 3 步 · 串联三次调用

One call is a question. A chain feeds the output of one call into the next. Here, one model invents a question, a second answers it, and a third judges the answer. Press Next to move one small step at a time. Nothing runs by itself, so read at your own pace.

一次调用就是一个问题。调用链把上一次的输出喂给下一次。这里，第一个模型出题，第二个回答，第三个评判答案。点下一步，一次只走一小步。没有任何东西会自动运行，你可以按自己的节奏阅读。

The key trick关键技巧Store each reply in a variable, then drop it into the next prompt with an f-string ({question}). That's all "chaining" is.把每次的回复存进变量，再用 f-string（{question}）放进下一个提示词。这就是“串联”的全部含义。

模型越大越聪明，但更慢也更贵。简单步骤用小模型，需要判断力的地方用强模型。

Show a hint查看提示 
def ask(prompt, model="gpt-5.4-mini"):
    messages = [{"role": "user", "content": prompt}]
    response = client.chat.completions.create(model=model, messages=messages)
    return response.choices[0].message.content

business_area = ask("Pick a business area worth exploring for an agentic AI opportunity. Respond only with the area.")
pain_point = ask(f"Present a pain-point in the {business_area} industry that an agentic solution could solve. Respond only with the pain-point.")
solution = ask(f"Propose an agentic AI solution for this pain-point in {business_area}: {pain_point}")
print(solution)

Quick check小测验

What does load_dotenv() do?load_dotenv() 的作用是什么？

That's how OpenAI() later finds your key without it being written in your code.这样 OpenAI() 之后就能找到密钥，而不必把密钥写在代码里。

Where is the model's reply text?模型的回复文本在哪里？

The response holds a list of choices; the first one's message has the content.响应里有一个 choices 列表，第一项的 message 里就是 content。

Why do we paste the question and answer into the third call?为什么要把问题和答案粘贴进第三次调用？

No memory between calls, so you carry information forward yourself. That's the heart of chaining.调用之间没有记忆，所以信息要由你自己带到下一步。这正是串联的核心。
