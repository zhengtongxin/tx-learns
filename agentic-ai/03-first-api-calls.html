An agent (an AI that picks its own next steps, covered in the lesson before this) is built from many such calls, so this small skill is the foundation of everything that follows.

Step 1 · Keep your key safe第 1 步 · 安全保管密钥

Learn先学

Your API key is like a password that also bills your credit card. Never paste it into code. Put it in a file named .env in your project folder, and let Python read it from there.

API 密钥就像一个会扣你信用卡的密码。不要把它写进代码里，而是放在项目文件夹的 .env 文件中，让 Python 从那里读取。

Text file · .env (saved in the project root)纯文本文件 · .env（保存在项目根目录）

OPENAI_API_KEY=sk-...your-key...
Never share your key不要泄露密钥Don't commit .env to Git, paste it in chat, or put it in a screenshot. If it leaks, delete it in your account and make a new one.不要把 .env 提交到 Git、贴到聊天里或放进截图。一旦泄露，立刻在账户里删除并重新创建。

Step 2 · Make your first call第 2 步 · 完成第一次调用

Learn先学

This is the entire program for Aina's first call. Four lines do the real work: load the key, create a client (your connection to the model), send the messages, and dig the text out of the reply. import os and os.getenv read the key back, and the if check stops with a clear message when it is missing (None). The print line only says the key was found, so you can check it exists without showing any of it. from openai import OpenAI brings in the official client library, which many other providers also accept.

这就是 Aina 第一次调用的完整程序。真正干活的是四行：加载密钥、创建客户端（你与模型的连接）、发送消息、从回复里取出文字。import os 和 os.getenv 把密钥读回来，if 检查在密钥缺失（None）时用一句清楚的话停下来。print 那一行只说一句“找到了”，让你确认它存在，又不显示它的任何部分。from openai import OpenAI 引入官方客户端库，许多其他服务商也兼容它。

Python · notebook cells (first_call.ipynb)Python · 笔记本单元格（first_call.ipynb）

# once, in a terminal: pip install openai python-dotenv from dotenv import load_dotenv load_dotenv(override=True) import os openai_api_key = os.getenv("OPENAI_API_KEY") if openai_api_key is None: raise SystemExit("OPENAI_API_KEY not found: check your .env file") print("OPENAI_API_KEY found") # say it was found; never print any part of the key from openai import OpenAI client = OpenAI() messages = [{"role": "user", "content": "Tell me a fun fact"}] response = client.chat.completions.create(model="gpt-5.4-nano", messages=messages) print(response.choices[0].message.content)

Match each line to what it does.

把每一行和它的作用配起来。

Digging out the reply取出回复response.choices[0].message.content reads as: the response → its list of choices → the first one → its message → the content (your text).response.choices[0].message.content 的意思是：响应 → 其 choices 列表 → 第一项 → 它的 message → 其中的 content（你要的文字）。
Learn先学

Messages are a list. Each message is a small dictionary (labelled values in curly braces) with a role and some content. Today you only need the user role (that's you speaking). And each call starts fresh: the model remembers nothing between calls, so anything it should know must be inside the messages you send.

消息是一个列表。每条消息都是一个小字典（放在花括号里、带标签的值），里面有角色和内容。今天只需要 user 角色（也就是你在说话）。而且每次调用都从零开始：模型在两次调用之间什么都不记得，它需要知道的内容，必须写在你发送的消息里。

Step 3 · Chain three calls第 3 步 · 串联三次调用

Learn先学

One call is a question. A chain feeds the output of one call into the next. Aina's chain: one model invents a question, a second answers it, and a third judges the answer. Press the button to move one small step at a time. Nothing runs by itself, so read at your own pace. (It is a simulated example, and real replies will differ.)

一次调用就是一个问题。调用链把上一次的输出喂给下一次。Aina 的调用链：第一个模型出题，第二个回答，第三个评判答案。点按钮，一次只走一小步。没有任何东西会自动运行，你可以按自己的节奏阅读。（这是模拟示例，真实回复会不同。）

Python · notebook cells (first_call.ipynb). Call 1 is the same kind of call as step 2, with this prompt. Every call after it is made the same way, with a new prompt in messages.Python · 笔记本单元格（first_call.ipynb）。第 1 次调用和第 2 步是同一种写法，只是换了这个提示词。之后每次调用写法都一样，只是 messages 里换成新的提示词。

# call 1: ask the model to write the question messages = [{"role": "user", "content": "Write one hard, open question a customer might ask a kopitiam helper. Reply with only the question."}] response = client.chat.completions.create(model="gpt-5.4-mini", messages=messages) question = response.choices[0].message.content # keep call 1's reply in a variable # call 2: send the question, keep the reply messages = [{"role": "user", "content": question}] response = client.chat.completions.create(model="gpt-5.4-mini", messages=messages) answer = response.choices[0].message.content # call 3: the judge sees both message = f""" Here is a question: {question} And here is a possible answer that might be correct or incorrect: {answer} Please evaluate if the answer is correct or incorrect. """ messages = [{"role": "user", "content": message}] response = client.chat.completions.create(model="gpt-5.4", messages=messages) print(response.choices[0].message.content)
The key trick关键技巧Store each reply in a variable, then drop it into the next prompt with an f-string ({question}). That's all "chaining" is. An f-string is text that starts with f, where {name} is replaced by that variable's value.把每次的回复存进变量，再用 f-string（{question}）放进下一个提示词。这就是“串联”的全部含义。f-string 是以 f 开头的文字，其中的 {name} 会被换成该变量的值。

Step 4 · Pick the right model size第 4 步 · 选对模型大小

Learn先学

Bigger models are smarter but slower and pricier. Use small ones for easy steps and a strong one where judgment matters. nano (gpt-5.4-nano) is cheapest, for quick facts and simple tasks. mini (gpt-5.4-mini) is balanced, good for writing the question and answer. full (gpt-5.4) is strongest, the final judge.

模型越大越聪明，但更慢也更贵。简单步骤用小模型，需要判断力的地方用强模型。nano（gpt-5.4-nano）最便宜，适合简单问答与任务。mini（gpt-5.4-mini）均衡，适合出题与作答。full（gpt-5.4）最强，担任最终评判。

Using another provider?想用别的模型服务商？

Many providers (Gemini, DeepSeek, local Ollama) accept the same OpenAI client. You only change the base URL (the web address the client sends requests to), the key and the model name.

许多服务商（Gemini、DeepSeek、本地 Ollama）都兼容同一个 OpenAI 客户端，只需更换 base URL（客户端发送请求的网址）、密钥和模型名。

Takeaways要点回顾

• An LLM API is a function: messages in, text out.
• Keep the key in .env, load it with load_dotenv, and never print or share it.
• The reply text is at response.choices[0].message.content.
• Each call starts fresh, so you carry information forward yourself.
• Chaining is: store a reply in a variable, drop it into the next prompt with an f-string.
• Small models for easy steps, a strong one for the final judgment.

• LLM API 就是一个函数：输入消息，输出文本。
• 密钥放在 .env，用 load_dotenv 加载，绝不打印或分享。
• 回复文字在 response.choices[0].message.content。
• 每次调用都从零开始，信息要由你自己带到下一步。
• 串联就是：把回复存进变量，再用 f-string 放进下一个提示词。
• 简单步骤用小模型，最后的判断用强模型。
