Step 1 · Two tools, two jobs第 1 步 · 两个工具，两项工作

Learn先学

Alex's career twin should do two real things, using words alone to decide when:

• record_user_details: someone wants to get in touch, so save their email.
• record_unknown_question: the twin could not answer, so log the question and learn what is missing.

Alex 的职业分身要做两件实事，何时做只靠文字来决定：

• record_user_details：有人想联系，保存他们的邮箱。
• record_unknown_question：分身答不上来，记录问题，了解还缺什么资料。

# push(): Pushover is a service that sends a notification to your phone (set up under Step 4) import os, requests # requests: a library for sending web requests (pip install requests) from dotenv import load_dotenv load_dotenv(override=True) # read .env; override=True lets a changed .env win over an old value still in memory def push(message): if not os.getenv("PUSHOVER_USER"): # no Pushover account yet: print the message instead print("Push:", message) return payload = {"user": os.getenv("PUSHOVER_USER"), "token": os.getenv("PUSHOVER_TOKEN"), "message": message} requests.post("https://api.pushover.net/1/messages.json", data=payload) def record_user_details(email, name="name not given", notes="not given"): push(f"Someone wants to get in touch: {name}, {email}. Notes: {notes}") return "Recorded" def record_unknown_question(question): push(f"Could not answer: {question}") return "Recorded"

Step 2 · The description is the trigger第 2 步 · 描述就是触发器

Learn先学

The model picks a tool from its description, so strong wording (“Always use this tool”) makes it reliable. required lists what the model must collect before acting; here only email.

模型靠描述来选工具，所以语气强（“Always use this tool”）更可靠。required 列出行动前必须收集的信息；这里只有 email。

record_user_details_json = { "name": "record_user_details", "description": "Use this tool to record that a user is interested in being in touch and provided an email address", "parameters": { "type": "object", "properties": { "email": {"type": "string", "description": "The email address of this user"}, "name": {"type": "string", "description": "The user's name, if they gave it"} }, "required": ["email"], "additionalProperties": False # the model may send only the fields listed above } } # record_unknown_question_json is written the same way: "Always use this tool to record any question that couldn't be answered", required: ["question"]

Step 3 · The prompt decides the behaviour第 3 步 · 提示词决定行为

Learn先学

Tools alone are not enough: the system prompt says when to use them. A good line names the situation and the action: “If X, do Y with your tool.” “Be helpful” changes nothing. The twin below has both tools and an empty prompt. Switch lines on until all four visitors are handled right.

光有工具不够：系统提示词说明何时使用。好的一句话写明情境和动作：“如果 X，就用你的工具做 Y。”“要乐于助人”没有作用。下面的分身有两个工具，提示词为空。逐条打开，直到四位访客都处理对。

Step 4 · From a tool name to a real call, then ship第 4 步 · 从工具名到真正的调用，再上线

Learn先学

The model returns only a tool's name as text. Your code turns it into a call. **arguments unpacks a dictionary into named inputs. For a public app, look the name up in a dictionary of allowed tools, so the model can never call anything else. (A common shortcut, globals(), searches every name your program has defined, which is too much to hand a stranger.)

模型返回的只是工具的文字名字，由你的代码变成调用。**arguments 把字典展开成带名字的输入。公开应用里，请在允许工具的字典里按名字查找，这样模型永远调不到别的函数。（常见的捷径 globals() 会在程序定义过的所有名字里查找，交给陌生人就太多了。）

import json # inside the loop over the model's tool calls (the loop from “Autonomy and tools”): # call is one entry of response.choices[0].message.tool_calls: it has the tool name and its arguments as text ALLOWED = {"record_user_details": record_user_details, "record_unknown_question": record_unknown_question} tool = ALLOWED.get(call.function.name) # text name -> function, or None arguments = json.loads(call.function.arguments) # e.g. {"email": "mei@example.com"} result = tool(**arguments) if tool else "Unknown tool"
Privacy and abuse隐私与滥用Visitors' emails are personal data: store them carefully. A public tool that buzzes your phone can be spammed, so cap how often it fires.访客的邮箱是个人数据，要妥善保存。会让你手机震动的公开工具可能被刷屏，所以要限制触发频率。

Takeaways要点回顾

• One tool per job; the description is what the model reads to choose.
• required fields must be collected before the tool is called.
• The system prompt says when to act: “If X, do Y with your tool.”
• A tool name comes back as text; map it to a function through an allowed list.
• Secrets live in .env or host settings, never in code.

• 一个工具一项工作，模型靠描述来选择。
• 调用工具前必须先收集 required 字段。
• 系统提示词说明何时行动：“如果 X，就用你的工具做 Y。”
• 工具名以文字返回，通过允许列表映射到函数。
• 密钥放在 .env 或平台设置里，绝不写进代码。
