Where we left off上回讲到

Last time the assistant could save an order and note a regular's drink. It still fails when a customer asks something it has no notes for, like the closing time, or whether Kak Ros does halal catering for 80: it guesses or goes silent. We fix that kind of failure with words alone: tool descriptions and a prompt that say when to answer and when to hand over. To practise, today's worked example is Alex's career twin below; the Kopi Corner version of the same idea is at the end of the side case.

上回助手能记订单、记熟客的饮料。它还是会出问题：顾客问到它没有资料的事，比如几点关门，或者 Kak Ros 能不能承办 80 人的清真外烩，它要么乱猜，要么不吭声。这类问题只用文字就能解决：写好工具描述和提示词，说清什么时候回答、什么时候交给人。为了练习，今天的示范例子是 Alex 的职业分身；同样的做法放到 Kopi Corner 是什么样，见支线案例的最后。

Side case支线案例

Alex's twin is live. Today four visitors arrive: Maya, a recruiter who wants to talk; Raj, who asks something that is not in Alex's files; Sam, who asks for a poem; and Lee, who asks “are you a real person?”. Alex wants his phone to buzz for the first two, and the twin to behave well for all four. You will do it without changing any code logic, using only words. Alex 的分身上线了。今天来了四位访客：想联系他的猎头 Maya；问了 Alex 资料里没有的问题的 Raj；要求写首诗的 Sam；还有问“你是真人吗？”的 Lee。Alex 希望前两位出现时手机会震动，并且分身对四个人都表现得体。你不用改任何代码逻辑，只用文字来做到。放到 Kopi Corner，这两个工具就是“记下熟客的电话”和“记下 Lim 叔叔必须回答的问题”。

Step 1 · Two tools, two jobs第 1 步 · 两个工具，两项工作

Learn先学

The twin should do two real things. record_user_details: someone wants to get in touch, so save their email (name and notes are optional). record_unknown_question: the twin could not answer, so log the question and learn what is missing. Both finish with the same one-liner that buzzes your phone:

分身要做两件实事。record_user_details：有人想联系，保存他们的邮箱（姓名和备注可选）。record_unknown_question：分身答不上来，就记录问题，了解还缺什么资料。两者最后都调用同一行代码，让你的手机震动：

# packages: requests (sends the web request) and python-dotenv (reads .env) import os import requests from dotenv import load_dotenv load_dotenv(override=True) pushover_user = os.getenv("PUSHOVER_USER") # who receives the push (set up in Step 5) pushover_token = os.getenv("PUSHOVER_TOKEN") # which app sends it pushover_url = "https://api.pushover.net/1/messages.json" def push(message): payload = {"user": pushover_user, "token": pushover_token, "message": message} requests.post(pushover_url, data=payload)

The two tools are plain functions that call push. Each returns a short text, which goes back to the model:

两个工具就是调用 push 的普通函数。每个都返回一小段文字，交还给模型：

def record_user_details(email, name="name not given", notes="not given"): push(f"Someone wants to get in touch: {name}, {email}. Notes: {notes}") return "Recorded" def record_unknown_question(question): push(f"Could not answer: {question}") return "Recorded"

The model never sees this code. It only sees each tool's name and description, and chooses from those. Act as the model:

模型永远看不到这段代码，它只能看到每个工具的名字和描述，并据此选择。现在由你来扮演模型：

Step 2 · The description is the trigger第 2 步 · 描述就是触发器

Learn先学

Compare how the two descriptions are worded. The second says “Always use this tool”. Strong wording makes the model reliable. Also notice required: only email is listed, so the model may call the tool as soon as it has an email.

对比两个描述的写法。第二个写的是“Always use this tool”。语气强，模型就更可靠。另外看 required：只列了 email，所以模型一拿到邮箱就可以调用。

record_user_details → "Use this tool to record that a user is interested in being in touch and provided an email address" record_unknown_question → "Always use this tool to record any question that couldn't be answered as you didn't know the answer"

Here is the full description for the first tool, so you can see required in place. It is written as a Python dictionary, which looks like JSON (a text format for data) but is not identical: Python writes False with a capital F, while JSON writes false in lower case. The second tool is written the same way, with "question" as its only required input.

下面是第一个工具的完整描述，可以看到 required 的位置。它写成 Python 字典，看起来像 JSON（一种数据文本格式），但并不完全一样：Python 里 False 首字母大写，JSON 里 false 全是小写。第二个工具写法相同，只有 "question" 是必填输入。

record_user_details_json = { "name": "record_user_details", "description": "Use this tool to record that a user is interested in being in touch and provided an email address", "parameters": { "type": "object", "properties": { "email": {"type": "string", "description": "The email address of this user"}, "name": {"type": "string", "description": "The user's name, if they gave it"}, "notes": {"type": "string", "description": "Anything else worth recording"} }, "required": ["email"], "additionalProperties": False } }

Step 3 · The prompt decides the behaviour第 3 步 · 提示词决定行为

Learn先学

Tools alone are not enough: the model still needs the system prompt to tell it when to use them. A good line names the situation and the action: “If X, then do Y with your tool.” Vague wishes like “be helpful” change nothing. Below, the twin has both tools but an empty prompt. Switch lines on and watch what each visitor gets. Goal: all four handled right.

光有工具还不够：模型还需要系统提示词告诉它什么时候用。好的一句话要写明情境和动作：“如果 X，就用你的工具做 Y。”“要乐于助人”这类空话没有作用。下面的分身有两个工具，但提示词是空的。逐条打开，看看每位访客得到什么。目标：四位访客都处理对。

You changed no code, only words. That is context prompting. Remember: calls are stateless, so this whole prompt is sent again on every call.你没有改任何代码，只改了文字，这就是上下文提示。记住：调用是无状态的，所以整段提示词每次调用都会重发。

Step 4 · From a tool name to a real call第 4 步 · 从工具名到真正的调用

Learn先学

When the model picks a tool, it returns only a name as text, for example "record_user_details". Your code must turn that name into a real function call. Two ways: an if / elif chain with one branch per tool, or a lookup that finds the function by its name.

模型选中工具时，返回的只是文字形式的名字，比如 "record_user_details"。你的代码得把这个名字变成真正的函数调用。有两种办法：每个工具一个分支的 if / elif，或者按名字查找函数。

import json # inside the loop over the model's tool calls (as in Lesson 5): tool_name = call.function.name # text, e.g. "record_user_details" arguments = json.loads(call.function.arguments) # e.g. {"email": "mei@example.com"} # way 1: one branch per tool if tool_name == "record_user_details": result = record_user_details(**arguments) elif tool_name == "record_unknown_question": result = record_unknown_question(**arguments) else: result = "Unknown tool" # way 2: look the function up by its name tool = globals().get(tool_name) result = tool(**arguments) if tool else "Unknown tool"

Two bits of Python in that code. **arguments unpacks a dictionary into named inputs: if arguments = {"email": "mei@example.com"}, then tool(**arguments) means tool(email="mei@example.com"). globals() is the dictionary of every name defined in your file, so globals().get("record_user_details") hands back that function, or None when no such name exists.

这段代码里有两个 Python 小知识。**arguments 把字典展开成带名字的输入：如果 arguments = {"email": "mei@example.com"}，那么 tool(**arguments) 就等于 tool(email="mei@example.com")。globals() 是你文件里所有已定义名字的字典，所以 globals().get("record_user_details") 会返回那个函数；没有这个名字就返回 None。

Public app?公开应用？Use an explicit dictionary of allowed tools instead of globals(), so the model can never call anything else.改用一个明确列出允许工具的字典，而不是 globals()，这样模型永远调不到别的函数。

C · DeployC · 部署

uv is a fast Python tool (install it once from its website). In your project folder, run uv init once, then uv add gradio openai pypdf python-dotenv requests to add the packages the app needs. After that, uv run app.py runs the app. A host is a website service that runs your app on the internet for you, for example Hugging Face Spaces: you sign up, connect your project folder, and paste your keys into its secrets page.

uv 是一个很快的 Python 工具（从它的官网安装一次即可）。在项目文件夹里先运行一次 uv init，再用 uv add gradio openai pypdf python-dotenv requests 添加应用需要的包。之后用 uv run app.py 运行应用。托管平台是替你在互联网上运行应用的网站服务，例如 Hugging Face Spaces：注册、连接你的项目文件夹，再把密钥粘贴到它的密钥页面。

Common errors常见错误

• ModuleNotFoundError: No module named 'gradio': The packages are not installed in the environment uv uses. Fix: uv add gradio openai pypdf python-dotenv requests, then uv run app.py again.
• FileNotFoundError: [Errno 2] No such file or directory: 'twin/linkedin.pdf': You started the app from a different folder. Fix: run it from the project folder, or build the path from __file__.
• TypeError: record_user_details() got an unexpected keyword argument 'e_mail': The JSON description names an input differently from the Python function. Fix: make the names in parameters and in the def line identical.
• The phone never buzzes (no error): PUSHOVER_USER or PUSHOVER_TOKEN is empty on the host. Fix: add both in the host's secrets settings and restart the app.

• ModuleNotFoundError: No module named 'gradio'：uv 使用的环境里没装这些包。解决：uv add gradio openai pypdf python-dotenv requests，再运行 uv run app.py。
• FileNotFoundError: [Errno 2] No such file or directory: 'twin/linkedin.pdf'：你在别的文件夹里启动了应用。解决：在项目文件夹里运行，或用 __file__ 拼出路径。
• TypeError: record_user_details() got an unexpected keyword argument 'e_mail'：JSON 描述里的输入名和 Python 函数里的不一样。解决：让 parameters 和 def 那一行的名字完全相同。
• The phone never buzzes (no error)：托管平台上的 PUSHOVER_USER 或 PUSHOVER_TOKEN 是空的。解决：在托管平台的密钥设置里补上两个，然后重启应用。

Takeaways要点回顾

• One tool per job. The description is what the model reads to choose.
• required fields are what the model must collect before acting.
• The system prompt says when to act: “If X, do Y with your tool.”
• A tool name comes back as text; your code maps it to a real function.
• Secrets live in .env or host settings, never in code.

• 一个工具一项工作，模型靠描述来选择。
• required 字段是模型行动前必须收集的信息。
• 系统提示词说明何时行动：“如果 X，就用你的工具做 Y。”
• 工具名以文字返回，由你的代码映射到真正的函数。
• 密钥放在 .env 或平台设置里，绝不写进代码。
