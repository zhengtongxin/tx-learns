Your personal career agent你的个人职业智能体

Make the twin act at the right moment using words alone, then ship it · ~20 min · hands-on只靠文字，让分身在正确的时刻行动，然后把它发布出去 · 约 20 分钟 · 动手实践

Last lesson, the model could ask your code to run a function. But who decides when it asks? Not an if in your code. Words decide. Two kinds of words steer the twin: the tool descriptions and the system prompt. Today you learn to write both, then ship the twin.

上一课里，模型可以请求你的代码运行一个函数。可是什么时候该请求，由谁来决定？不是你代码里的 if，而是文字。有两种文字在牵引分身：工具描述和系统提示词。今天你会学着写好这两样，然后把分身发布出去。

Two tools, two jobs两个工具，两项职责

Why: the twin should do two real things for you. Buzz your phone when someone wants to talk, and log every question it could not answer, so you know what is missing. One tool per job.

为什么：分身应该替你做两件实事：有人想联系你时让手机震动；把它答不上来的问题都记下来，让你知道资料里缺什么。一项工作，一个工具。

record_user_details

Someone wants to get in touch. Needs an email. Name and notes are optional.

有人想联系你。必须提供邮箱，姓名和备注是可选的。

record_unknown_question

The twin could not answer. Records the question, so you learn what is missing.

分身答不上来时，把这个问题记录下来，让你知道资料里缺了什么。

Both end in the same one-liner: a push notification to your phone.

两个工具最后都落到同一行：给你的手机发一条推送。

def push(message): payload = {"user": pushover_user, "token": pushover_token, "message": message} requests.post(pushover_url, data=payload)

The model never sees this code. It sees only each tool's name and description, and chooses from those. Notice how the second one is worded.

模型永远看不到这段代码。它只看得到每个工具的名字和描述，并据此做选择。注意第二个描述的措辞。

record_user_details: "Use this tool to record that a user is interested in being in touch and provided an email address" record_unknown_question: "Always use this tool to record any question that couldn't be answered as you didn't know the answer"

“Always use this tool…” is strong wording, and it makes the model reliable. Your turn. Act as the model: read each visitor message and pick the tool that should fire.

“Always use this tool…” 是很强的措辞，能让模型更可靠。轮到你了。扮演模型：读每条访客消息，选出该触发的工具。

In record_user_details, only email is listed under required. Why does that matter?在 record_user_details 里，required 只列出了 email。这有什么意义？

Required fields tell the model what it must collect before acting. Optional ones are a bonus.必填字段告诉模型行动前必须收集什么，可选字段只是锦上添花。

The lookup finds any function by name. The if chain needs a new branch every time. For a public app, use an explicit dictionary of allowed tools so the model cannot call anything else.查找方式能按名字找到任意函数，而 if 链每次都要加一个分支。对公开应用，建议用一个显式的“允许工具”字典，避免模型调用其他函数。

Takeaways要点回顾

• A tool acts on the real world, but words decide when it fires: the description and the prompt are your controls.
• Write tool descriptions as “when to use”, and mark what is required.
• Context prompting: describe the situation and the action. No code change needed.
• The model only returns a tool name. Your code looks it up and runs it. In public apps, restrict the list.
• A checklist tool makes the loop visible: every tick is another round.
• Setup: keys in .env, code split into modules, secrets in the host's settings, then deploy.

• 工具作用于现实世界，但什么时候触发由文字决定：工具描述和提示词就是你的控制手段。
• 工具描述要写成“什么时候用”，并标明哪些是必填项。
• 上下文提示词：写清情境和动作，不需要改代码。
• 模型只返回工具名字，你的代码去查找并运行。公开应用里要限制可用工具列表。
• 清单工具让循环变得可见：每打一次勾就是多转一圈。
• 配置：密钥放 .env，代码拆成模块，密钥放进托管平台设置，然后部署。
