Framework tour · Lesson 1框架巡礼 · 第 1 课

Agent-to-agent protocols智能体之间的协议

Let an agent in another process do a job for yours, like a stall next door · ~30 min · hands-on让另一个进程里的智能体替你的智能体干活，就像隔壁摊位 · 约 30 分钟 · 动手实践

The story故事

You are helping Mei, who runs a drinks stall at a night market. Next to her, Uncle Hock grills satay. He takes no drink orders, and Mei sells no food. When a customer asks Mei for satay, she does not learn to grill. She walks over, reads his signboard (what he sells, the prices, where to order), passes the order on and brings the plate back. Today you build both stalls as agents, and the walk between them is the A2A (Agent2Agent) protocol.

你在帮 Mei，她在夜市摆饮料摊。隔壁是 Hock 叔，他烤沙爹，不收饮料单；Mei 也不卖吃的。顾客向 Mei 点沙爹时，她不会去学烤沙爹，而是走过去看他的招牌（卖什么、多少钱、在哪里下单），把单子递过去，再把盘子端回来。今天你要把两个摊位都做成智能体，而它们之间的这段路就是 A2A（Agent2Agent）协议。

Step 1 · One agent in Google ADK第 1 步 · 用 Google ADK 做一个智能体

Learn先学

Before two agents can talk, you need one. In Google's Agent Development Kit (ADK), an LlmAgent is just a model plus an instruction, the same idea as the agents you already know. run_debug opens a session, sends one message and prints the whole trace (the step-by-step log of what the agent did). It is for experiments only. It reads your Google key (a secret password for the model) from a .env file, so the key never sits inside the code.

两个智能体要对话，先得有一个。在 Google 的智能体开发套件（ADK）里，LlmAgent 就是一个模型加一段 instruction，和你已经认识的智能体是同一个概念。run_debug 会新建会话、发一条消息并打印完整过程（逐步的运行记录），只适合做实验。它从 .env 文件里读取你的 Google 密钥（调用模型用的密码），这样密钥就不会写进代码里。

pip install "google-adk[a2a,mcp]" python-dotenv requests from dotenv import load_dotenv from google.adk.agents import LlmAgent from google.adk.runners import InMemoryRunner load_dotenv(override=True) # reads GOOGLE_API_KEY drinks = LlmAgent( model="gemini-2.5-flash", name="drinks_stall", instruction="You sell drinks at a night market. Answer in one short sentence.", ) await InMemoryRunner(agent=drinks).run_debug("What is iced barley?", verbose=True)

Step 2 · Tools and MCP第 2 步 · 工具与 MCP

Learn先学

Mei needs to remember orders, so she needs tools. In ADK a tool is a plain typed function with a docstring. No decorator: ADK reads the type hints and the docstring, just like the SDK you met earlier.

Mei 要记订单，所以需要工具。在 ADK 里，工具就是带类型标注和文档字符串的普通函数，不需要装饰器：ADK 会读类型标注和文档字符串，和你之前见过的 SDK 一样。

Tools that someone else wrote plug in through MCP, a standard plug for tools (it gets its own topic later). Scope it to one folder, so the agent cannot touch anything else.

别人写好的工具通过 MCP 接入，它是工具的标准插头（之后会有单独的主题）。把它限定在一个文件夹里，智能体就碰不到别的东西。

notepad = [] # Mei's notepad: a plain list def save_order(item: str, qty: int) -> str: """Write one customer order on the notepad. Use it after the customer confirms.""" notepad.append((item, qty)) return "saved" from pathlib import Path from google.adk.tools.mcp_tool import McpToolset, StdioConnectionParams from mcp import StdioServerParameters stall = Path("stall_files").resolve() files = McpToolset(connection_params=StdioConnectionParams( server_params=StdioServerParameters(command="npx", args=["-y", "@modelcontextprotocol/server-filesystem", str(stall)], cwd=str(stall)), timeout=30)) drinks = LlmAgent(model="gemini-2.5-flash", name="drinks_stall", instruction="Take drink orders and write them down.", tools=[save_order, files])

Step 3 · The real run loop第 3 步 · 真正的运行循环

Learn先学

In real code you own the session and read the stream of events. Each event is one thing that happened: a tool call, a tool result or the final reply. It is the loop you once wrote by hand, now with labels.

真实代码里，你自己持有会话并读取事件流。每个事件是发生的一件事：一次工具调用、一个工具结果或最终回复。这就是你曾经手写的循环，只是现在每一步都有标签。

from google.genai import types runner = InMemoryRunner(agent=drinks) session = await runner.session_service.create_session(app_name=runner.app_name, user_id="mei") async for ev in runner.run_async(user_id="mei", session_id=session.id, new_message=types.UserContent("Two iced barley, please")): for call in ev.get_function_calls(): print("tool:", call.name, call.args) if ev.is_final_response(): print(ev.content.parts[0].text)
Debug view调试界面If you put the agent in a folder (agent.py that exposes root_agent, made with adk create my_agent), then adk web shows a visual trace where every tool call lights up. It only lists agents in the folder you start it from.如果把智能体放进一个文件夹（agent.py 里暴露 root_agent，可用 adk create my_agent 生成），运行 adk web 就能看到可视化的过程，每次工具调用都会亮起来。它只会列出你启动时所在文件夹里的智能体。

Step 4 · Put Uncle Hock behind a signboard第 4 步 · 把 Hock 叔放到招牌后面

Learn先学

Uncle Hock runs in his own process: a separate program with its own door (a port, a numbered entrance on your computer), like a stall with its own street number. to_a2a wraps his agent in a small web app that serves two things: the A2A endpoint, and his agent card. The card is a JSON file at a well-known address that says his name, his skills and where to reach him. That is the signboard. uvicorn is the small server program that opens that port and runs the app.

Hock 叔运行在他自己的进程里：一个单独运行的程序，有自己的门（端口，电脑上的一个编号入口），就像有自己门牌号的摊位。to_a2a 把他的智能体包进一个小型网络应用，提供两样东西：A2A 接口，以及他的智能体名片（agent card）。名片是放在固定地址的 JSON 文件，写着他的名字、技能和联系地址，也就是那块招牌。uvicorn 是把这个应用打开端口、运行起来的小型服务程序。

# satay_server.py from google.adk.agents import LlmAgent from google.adk.a2a.utils.agent_to_a2a import to_a2a hock = LlmAgent( model="gemini-2.5-flash", name="satay_hock", description="Takes satay orders and confirms them with a price in RM.", instruction="Confirm the satay order (how many sticks, chicken or beef) and give the price.", ) a2a_app = to_a2a(hock, port=8001) # serves the card and the endpoint # in a terminal (curl just fetches the card and prints it): uvicorn satay_server:a2a_app --host localhost --port 8001 curl http://localhost:8001/.well-known/agent-card.json

Step 5 · Mei walks over第 5 步 · Mei 走过去

Learn先学

On Mei's side, Uncle Hock becomes a RemoteA2aAgent and goes into her sub_agents like any local helper. Her instruction says what to do herself and what to hand over. Notice that nothing finds him for you: you point at his card address.

在 Mei 这边，Hock 叔变成一个 RemoteA2aAgent，和本地帮手一样放进她的 sub_agents。她的指令写明哪些自己做、哪些交出去。注意没有任何东西会替你去找他：你要把名片地址告诉她。

from google.adk.agents.remote_a2a_agent import RemoteA2aAgent, AGENT_CARD_WELL_KNOWN_PATH hock_remote = RemoteA2aAgent( name="satay_hock", description="Remote stall that takes satay orders.", agent_card=f"http://localhost:8001{AGENT_CARD_WELL_KNOWN_PATH}", # the full card URL ) root_agent = LlmAgent( model="gemini-2.5-flash", name="mei_stall", instruction="Handle drinks yourself. For any satay order, hand it to satay_hock.", sub_agents=[hock_remote], )

Is each case a local sub-agent or a remote A2A agent? Sort them.

下面每个情景是本地子智能体，还是远程 A2A 智能体？逐个分类。

What I got wrong我踩过的坑I expected A2A agents to find each other. They do not: the client is pointed at a known card URL, and agent_card= wants the full URL, not a bare host. Worse, the port in to_a2a(..., port=8001) is only what the card advertises. When uvicorn ran on another port, the card pointed at the wrong place and calls failed quietly. Keep the two ports equal. Also stop an old adk web before starting the next one, and filter the many [EXPERIMENTAL] warnings (notices that a feature is still being tested) with warnings.filterwarnings so the trace stays readable.我以为 A2A 的智能体会自动互相发现，其实不会：客户端要指向一个已知的名片地址，而且 agent_card= 要的是完整 URL，不是只有主机。更坑的是，to_a2a(..., port=8001) 里的端口只是名片上声明的地址。uvicorn 跑在别的端口时，名片指向错的地方，调用悄悄失败。两个端口要一致。另外，启动新的 adk web 前要先停掉旧的；大量 [EXPERIMENTAL] 警告（提示某个功能仍在测试中）可以用 warnings.filterwarnings 过滤，让过程保持可读。

Now make it yours现在把它变成你的

Takeaways要点回顾

• An ADK LlmAgent is a model plus an instruction. run_debug is only for experiments.
• A tool is a typed function with a docstring. ADK reads both. No decorator.
• Scope MCP file tools to one folder.
• run_async gives you events: tool calls, results, the final reply. InMemoryRunner forgets when the process stops.
• A2A lets an agent in another process (or another company) act like a local sub-agent.
• The agent card is the signboard: name, skills, address, at a well-known URL.
• No auto-discovery: you give the full card URL, and the advertised port must match the real one.

• ADK 的 LlmAgent 就是模型加 instruction。run_debug 只适合做实验。
• 工具就是带类型标注和文档字符串的函数，ADK 两样都会读，不需要装饰器。
• 把 MCP 文件工具限定在一个文件夹里。
• run_async 给你事件：工具调用、结果、最终回复。InMemoryRunner 在进程结束后就忘了一切。
• A2A 让另一个进程（甚至另一家公司）里的智能体，像本地子智能体一样工作。
• 智能体名片就是招牌：名字、技能、地址，放在固定的 URL。
• 没有自动发现：你要给出完整的名片 URL，而且声明的端口必须和实际端口一致。
