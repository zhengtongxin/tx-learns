Project: a paper-trading simulation项目：模拟交易实验

Watch autonomous agents trade pretend money and learn from the result · ~60 min · project看自主的智能体用模拟的钱做交易，并从结果中学习 · 约 60 分钟 · 项目

The story故事

Every morning at the kopitiam, four uncles argue about stocks over roti bakar. Uncle Wong only buys solid, boring companies. Uncle Muthu chases whatever is in the news. Uncle Ah Kow trades on chart patterns. Uncle Hamid buys what everyone else is selling. None of them ever proves who is right. So you build a paper trading floor: four agent uncles, each with RM10,000 of pretend money, a written strategy and the same tools, trading four made-up tickers on a timer. It is play money only. The point is to watch autonomous agents and a feedback loop, not to trade for real.

每天早上，咖啡店里四位大叔一边吃烤面包，一边争论股票。Wong 叔只买扎实无聊的公司。Muthu 叔追着新闻跑。Ah Kow 叔看图表形态交易。Hamid 叔买别人都在卖的。可没有一个人能证明自己才对。于是你搭一个模拟交易场：四个智能体大叔，每人有 10,000 令吉的模拟资金、一份写好的策略和同样的工具，按定时器交易四只虚构的股票。这只是玩具钱，目的是观察自主的智能体和反馈循环，不是真的去交易。

Step 1 · The floor is built from MCP servers第 1 步 · 交易场由 MCP 服务端搭成

Learn先学

Every uncle is an agent whose tools come from MCP servers. The accounts server is your own FastMCP, like the tab book you wrote earlier: it holds cash and shares. The market server gives prices. Its prices come from a simulator, a small made-up price function you write first, in the code below. The push server has one tool that pings your phone after a trade.

每位大叔都是一个智能体，工具来自 MCP 服务端。账户服务端是你自己写的 FastMCP，就像之前的账本：管现金和股份。行情服务端提供价格，价格来自一个模拟器（一个小型的虚构价格函数），下面的代码里先把它写好。推送服务端只有一个工具，每笔交易后给你的手机发通知。

Each uncle also has a researcher: another agent with its own servers (fetch, filtered web search, memory). It is handed to the trader as a tool, the pattern from the Agent SDKs topic.

每位大叔还有一个研究员：另一个智能体，有自己的服务端（抓取网页、过滤后的搜索、记忆）。它作为工具交给交易员，用的就是智能体 SDK 主题里的那种模式。

pip install openai-agents "mcp[cli]<2" gradio fastapi uvicorn python-dotenv requests # keys in .env: OPENAI_API_KEY, TAVILY_API_KEY, PUSHOVER_USER, PUSHOVER_TOKEN # optional: RUN_EVERY_N_MINUTES Uncle (trader agent) ---- accounts server (my FastMCP: balance, holdings, buy, sell, change_strategy) | |------------- market server (lookup_price) | '------------- push server (one tool: ping my phone) '-- Researcher (agent, used as a tool) -- fetch + filtered search + memory servers # floor/market.py (the price simulator: made-up prices that move slowly) import math, time BASE = {"KOPI": 10.0, "ROTI": 5.0, "TEHT": 8.0, "NASI": 12.0} def get_price(symbol: str) -> float: t = time.time() / 600 # a slow clock: a gentle change every few minutes seed = sum(map(ord, symbol)) wave = math.sin(t + seed) * 0.6 + math.sin(t * 2.3 + seed * 1.7) * 0.3 return round(BASE[symbol] * (1 + 0.08 * wave), 2) # floor/accounts_server.py (Account is a plain ledger class, like Tab before) @mcp.tool() async def buy_shares(name: str, symbol: str, qty: int) -> str: """Buy shares at the current price from this account's cash. Fails if cash is short.""" return Account.get(name).buy(symbol, qty, get_price(symbol)) @mcp.resource("strategy://{name}") async def strategy_page(name: str) -> str: """The written strategy of one uncle.""" return Account.get(name).strategy STRATEGIES = { "Wong": "Buy only solid, boring companies and hold them.", "Muthu": "Chase whatever is in the news.", "AhKow": "Trade on chart patterns.", "Hamid": "Buy what everyone else is selling.", }

Step 2 · A market and a push server, with a simulator inside第 2 步 · 行情与推送服务端，里面藏着模拟器

Learn先学

Real prices need a data account and a key. So the prices come from the simulator you wrote in Step 1: a made-up price that moves slowly and smoothly with time, so two calls a second apart do not jump wildly. The ticker list is made up too: KOPI, ROTI, TEHT, NASI.

真实行情需要数据账号和密钥。所以价格来自你在第 1 步写好的模拟器：一个随时间缓慢、平滑变化的虚构价格，这样相隔一秒的两次调用不会大起大落。股票代码也是虚构的：KOPI、ROTI、TEHT、NASI。

Because the market is its own server, you can swap in a real provider later without touching any uncle.

因为行情是独立的服务端，以后换成真实数据源时，不用动任何一位大叔。

# floor/market_server.py from mcp.server.fastmcp import FastMCP from floor.market import get_price mcp = FastMCP("market") @mcp.tool() async def lookup_price(symbol: str) -> float: """Latest price of a ticker, in RM.""" return get_price(symbol) if __name__ == "__main__": mcp.run(transport="stdio") # floor/push_server.py: one tool, same shape import os, requests mcp = FastMCP("push") @mcp.tool() async def push(message: str) -> str: """Send a short note to my phone, e.g. after a trade.""" r = requests.post("https://api.pushover.net/1/messages.json", data={ "user": os.getenv("PUSHOVER_USER"), "token": os.getenv("PUSHOVER_TOKEN"), "message": message}) return "sent" if r.ok else "failed"

Step 3 · One uncle, one researcher第 3 步 · 一位大叔，一位研究员

Learn先学

Each uncle needs three servers for trading and the researcher needs three of its own. Six async with blocks nested inside each other would be unreadable, so use AsyncExitStack: it opens servers in a loop and closes them all, even if the run fails.

每位大叔交易要用三个服务端，研究员又要三个自己的。六层嵌套的 async with 根本没法读，所以用 AsyncExitStack：用循环打开服务端，结束时全部关掉，即使运行失败也一样。

researcher.as_tool(...) turns the researcher into a tool of the uncle. The uncle stays in charge and gets its answer back. The trace id carries the uncle's name, so Step 5 can tell whose run each span belongs to. max_turns=30 stops a runaway run.

researcher.as_tool(...) 把研究员变成大叔的一个工具。大叔始终做主，并拿回研究员的答案。trace id 里带着大叔的名字，第 5 步就能分清每一段记录属于谁。max_turns=30 能防止一次运行失控。

import os, secrets from contextlib import AsyncExitStack from agents import Agent, Runner, trace from agents.mcp import MCPServerStdio, create_static_tool_filter STRATEGY_NOTE = "Look at how your past trades actually performed, and update your strategy if the results say you should." RESEARCH_RULES = "Research the ticker you are asked about: news first, then context. Reply in three lines." def trader_rules(name): return f"{STRATEGIES[name]} Trade only KOPI, ROTI, TEHT, NASI. Never guess prices. {STRATEGY_NOTE}" async def build_message(name): return f"You are {name}. Check your account and strategy, trade if it is worthwhile, then push a short note." def make_trace_id(tag): # "trace_" + 32 chars; the name rides in front return "trace_" + (tag + "0" + secrets.token_hex(16))[:32] only_search = create_static_tool_filter(allowed_tool_names=["tavily_search"]) def trader_servers(): p = [{"command": "uv", "args": ["run", "-m", "floor.accounts_server"]}, {"command": "uv", "args": ["run", "-m", "floor.push_server"]}, {"command": "uv", "args": ["run", "-m", "floor.market_server"]}] return [MCPServerStdio(x, client_session_timeout_seconds=120) for x in p] def researcher_servers(name): return [MCPServerStdio({"command": "uvx", "args": ["mcp-server-fetch"]}, client_session_timeout_seconds=120), MCPServerStdio({"command": "npx", "args": ["-y", "tavily-mcp@latest"], "env": {"TAVILY_API_KEY": os.getenv("TAVILY_API_KEY")}}, tool_filter=only_search, client_session_timeout_seconds=120), MCPServerStdio({"command": "npx", "args": ["-y", "@modelcontextprotocol/server-memory"], "env": {"MEMORY_FILE_PATH": os.path.abspath(f"memory/{name.lower()}.json")}}, client_session_timeout_seconds=120)] async def run_uncle(name: str, model: str = "gpt-4o-mini"): async with AsyncExitStack() as stack: t_srv = [await stack.enter_async_context(s) for s in trader_servers()] r_srv = [await stack.enter_async_context(s) for s in researcher_servers(name)] researcher = Agent(name="Researcher", instructions=RESEARCH_RULES, model=model, mcp_servers=r_srv) uncle = Agent(name=name, instructions=trader_rules(name), model=model, mcp_servers=t_srv, tools=[researcher.as_tool(tool_name="Researcher", tool_description="Research news and prices for a ticker")]) with trace(f"{name}-trading", trace_id=make_trace_id(name.lower())): await Runner.run(uncle, await build_message(name), max_turns=30)

Step 4 · Run all four on a timer第 4 步 · 让四位大叔按定时器运行

Learn先学

asyncio.gather runs the four uncles at the same time. Then the floor sleeps, and the loop starts again. The pause comes from an environment variable, so you can change it without editing code.

asyncio.gather 让四位大叔同时运行。然后交易场休息一会儿，再重新开始。休息的时间来自环境变量，不用改代码就能调整。

Watch the cost. Four traders, each with a researcher and six servers, every N minutes, adds up while you sleep.

要留意费用。四位交易员，每人带一个研究员和六个服务端，每隔 N 分钟就跑一次，你睡觉的时候钱也在花。

import asyncio async def floor(): while True: await asyncio.gather(*(run_uncle(n) for n in ["Wong", "Muthu", "AhKow", "Hamid"])) await asyncio.sleep(int(os.getenv("RUN_EVERY_N_MINUTES", "60")) * 60) # floor/trading_floor.py ends with: if __name__ == "__main__": asyncio.run(floor())

Step 5 · See inside with your own tracer第 5 步 · 用自己的追踪器看清内部

Learn先学

Four uncles running at once make a messy log. The SDK lets you plug in a TracingProcessor: it is called for every span (an agent step, a tool call or a model call). Yours writes each span to a database with the uncle's name, and the dashboard reads those rows as a live, colour-coded log.

四位大叔同时运行，日志会乱成一团。SDK 允许你接入一个 TracingProcessor：每一个 span（智能体的一步、一次工具调用或一次模型调用）都会交给它。你的追踪器把每个 span 连同大叔的名字写进数据库，仪表盘把这些记录读成实时的彩色日志。

The trick is the name inside trace_id, which make_trace_id put in front. Every span can then be traced back to its owner. _who reads the name back out: the text between the first underscore and the 0. In the lines that start with (w := ...), the w := gives the result a name, and and means "only if there is a name, write the row".

关键在 trace_id 里的名字，也就是 make_trace_id 放在最前面的那部分。这样每个 span 都能追回它的主人。_who 把名字读回来：取第一个下划线和 0 之间的文字。以 (w := ...) 开头的那几行里，w := 是给结果起名叫 w，and 的意思是“只有有名字，才写这一行记录”。

from agents import TracingProcessor, add_trace_processor from floor.db import write_log # a small helper that inserts a row into SQLite class FloorLog(TracingProcessor): def _who(self, x): # trace ids look like trace_<name>0<random> tag = x.trace_id.split("_")[1] return tag.split("0")[0] if "0" in tag else None def on_trace_start(self, t): (w := self._who(t)) and write_log(w, "trace", f"start {t.name}") def on_trace_end(self, t): (w := self._who(t)) and write_log(w, "trace", f"end {t.name}") def on_span_start(self, s): if (w := self._who(s)) and s.span_data: write_log(w, s.span_data.type, f"start {getattr(s.span_data, 'name', '')}") def on_span_end(self, s): pass def shutdown(self): pass def force_flush(self): pass add_trace_processor(FloorLog())

Step 6 · Let them rewrite their own strategy第 6 步 · 让他们改写自己的策略

Learn先学

The most interesting idea: change_strategy is one of the account tools, and the instructions (STRATEGY_NOTE) tell the uncle to look at how past trades performed and update if the results say so. Profit and loss is a real-world evaluation that feeds into the next decision. That makes a loop that learns, not a fixed prompt.

最有意思的想法是：change_strategy 是账户工具之一，指令（STRATEGY_NOTE）叫大叔去看过往交易的表现，结果说该改就改。盈亏就是一种真实世界的评估，会反馈到下一次决策里。这就成了一个会学习的循环，而不是固定不变的提示词。

For the screen, split it like a real product. A thin, read-only FastAPI app serves the roster, values, holdings, transactions and logs. A Vite + TypeScript page (Vite is the tool that serves a web page while you build it) asks it for new numbers every couple of seconds. That repeated asking is called polling. The page draws a chart per uncle. Browsers block a page from reading data on another address, a rule called CORS. Vite's dev server passes /api requests on to port 8000, so the browser sees one address and you set nothing up.

屏幕那边，像真正的产品一样拆开。一个很薄的只读 FastAPI 应用提供名单、总值、持仓、交易和日志。一个 Vite + TypeScript 页面（Vite 是你开发时用来提供网页的工具）每隔几秒向它要一次最新数字，这种反复询问叫做轮询，页面还会给每位大叔画一张图。浏览器默认不允许网页读取另一个地址上的数据，这条规则叫 CORS。Vite 的开发服务器会把 /api 的请求转给 8000 端口，所以浏览器只看到一个地址，你什么都不用设置。

# floor/accounts_server.py @mcp.tool() async def change_strategy(name: str, new_strategy: str) -> str: """Replace this uncle's written strategy. Use it only after reviewing real results.""" return Account.get(name).set_strategy(new_strategy) # floor/api.py: read-only, one endpoint shown from fastapi import FastAPI app = FastAPI() @app.get("/api/portfolio/{name}") def portfolio(name: str): return Account.get(name).summary() # value, cash, holdings; nothing here can trade # three terminals: uv run uvicorn floor.api:app --port 8000 # terminal 1 cd frontend && npm run dev # terminal 2 -> http://localhost:5173 uv run -m floor.trading_floor # terminal 3: the uncles start trading
What I got wrong我踩过的坑I did not expect the cost of a timer. Four traders, a researcher each and several servers, every N minutes, adds up while you sleep. Now I set RUN_EVERY_N_MINUTES high, use small models and stop the floor when I am done watching. Nesting six async with blocks was unreadable until I used AsyncExitStack, and each server needs a generous timeout (I use 120 s) because uv run start-up and first-time downloads are slow. Last, I wanted different uncles on different providers. The SDK takes a plain model name for OpenAI, and an OpenAIChatCompletionsModel(model=..., openai_client=AsyncOpenAI(base_url=...)) for any OpenAI-compatible provider (one that speaks the same API), so I route by model-name prefix. Each provider needs its own key variable, so a missing one only breaks that uncle.我没想到定时器会这么花钱。四位交易员、各带一个研究员和好几个服务端，每隔 N 分钟跑一次，你睡觉的时候钱也在花。现在我把 RUN_EVERY_N_MINUTES 设得很大，用小模型，看完就停掉交易场。嵌套六层 async with 根本没法读，直到用上 AsyncExitStack；每个服务端还要给足超时（我用 120 秒），因为 uv run 启动和第一次下载都很慢。最后，我想让不同的大叔用不同的模型提供商。SDK 对 OpenAI 直接接受模型名字；对任何兼容 OpenAI 的提供商（即说同一种接口的提供商），要用 OpenAIChatCompletionsModel(model=..., openai_client=AsyncOpenAI(base_url=...))，所以我按模型名字的前缀来分流。每个提供商都要有自己的密钥变量，缺一个只会让对应的那位大叔出问题。

Now make it yours现在把它变成你的

Takeaways要点回顾

• A whole system can be made of MCP servers: your own accounts server, a market server and a push server.
• Put a simulator behind the market server, and a real data source can replace it later without touching the agents.
• A researcher agent is handed to the trader as a tool, so the trader stays in charge.
• AsyncExitStack opens many servers in a loop and closes them all, even on failure.
• A custom TracingProcessor plus the name inside the trace id gives a live log per agent.
• Profit and loss is real feedback: letting agents rewrite their strategy turns a fixed prompt into a loop that learns.
• Timers cost money while you sleep: slow interval, small models, stop when done. And it is pretend money only.

• 整个系统可以由 MCP 服务端搭成：你自己的账户服务端、行情服务端和推送服务端。
• 在行情服务端后面放一个模拟器，以后换成真实数据源时，不用动智能体。
• 研究员智能体作为工具交给交易员，交易员始终做主。
• AsyncExitStack 用循环打开很多服务端，并且即使失败也会全部关掉。
• 自定义的 TracingProcessor 加上 trace id 里的名字，就能得到每个智能体各自的实时日志。
• 盈亏是真实的反馈：让智能体改写自己的策略，就把固定的提示词变成了会学习的循环。
• 定时器会在你睡觉时花钱：间隔拉长、用小模型、看完就停。而且这只是模拟的钱。
