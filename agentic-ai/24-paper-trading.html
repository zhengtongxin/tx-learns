Where we left off上回讲到

Last time the Kopi Corner assistant could use many MCP servers at once. Today it fails when the pieces have never run together: each works alone, but nothing proves they hold up as one system. We fix it with a final project that combines agents, tools, MCP servers, a timer and a tracer.

上回 Kopi Corner 助手已经能同时用好几个 MCP 服务端。今天的问题是：各个部件单独都行，却从没一起跑过，没人证明它们合起来还稳。我们用一个收尾项目，把智能体、工具、MCP 服务端、定时器和追踪合在一起。

Every morning at the kopitiam, four uncles argue about stocks over roti bakar. Uncle Wong only buys solid, boring companies. Uncle Muthu chases whatever is in the news. So you build a paper trading floor: four agent uncles, each with S$10,000 of pretend money, a written strategy and the same tools, trading four made-up tickers on a timer. It is play money only. 每天早上，咖啡店里四位大叔一边吃烤面包，一边争论股票。Wong 叔只买扎实无聊的公司。Muthu 叔追着新闻跑。Ah Kow 叔看图表形态交易。Hamid 叔买别人都在卖的。可没有一个人能证明自己才对。于是你搭一个模拟交易场：四个智能体大叔，每人有 10,000 新元的模拟资金、一份写好的策略和同样的工具，按定时器交易四只虚构的股票。这只是玩具钱，目的是观察自主的智能体和反馈循环，不是真的去交易。Aina 给 Kopi Corner 搭的是同样的结构，只是限制换成了 Lim 叔的点头，而不是 10,000 新元。

Step 1 · The floor is built from MCP servers第 1 步 · 交易场由 MCP 服务端搭成

Learn先学

Every uncle is an agent whose tools come from MCP servers. The accounts server is your own FastMCP (the small Python helper that builds an MCP server), like the tab book you wrote in the build-your-own-server lesson: it holds cash and shares, and every uncle starts with S$10,000. The market server gives prices. Its prices come from a simulator, a small made-up price function you write first, in the code below. The push server has one tool that pings your phone after a trade.

每位大叔都是一个智能体，工具来自 MCP 服务端。账户服务端是你自己写的 FastMCP（用来搭 MCP 服务端的小型 Python 工具），就像你在“自己搭服务端”那一课写的账本：管现金和股份，每位大叔起始都有 10,000 新元。行情服务端提供价格，价格来自一个模拟器（一个小型的虚构价格函数），下面的代码里先把它写好。推送服务端只有一个工具，每笔交易后给你的手机发通知。

Each uncle also has a researcher: another agent with its own servers (fetch, filtered web search, memory). It is handed to the trader as a tool, the pattern from the Agent SDKs topic.

每位大叔还有一个研究员：另一个智能体，有自己的服务端（抓取网页、过滤后的搜索、记忆）。它作为工具交给交易员，用的就是智能体 SDK 主题里的那种模式。

Uncle (trader agent) ---- accounts server (my FastMCP: balance, holdings, buy, sell, past_trades, change_strategy) | |------------- market server (lookup_price) | '------------- push server (one tool: ping my phone) '-- Researcher (agent, used as a tool) -- fetch + filtered search + memory servers
# floor/market.py (the price simulator: made-up prices that move slowly) import math, time BASE = {"KOPI": 10.0, "ROTI": 5.0, "TEHT": 8.0, "NASI": 12.0} def get_price(symbol: str) -> float: t = time.time() / 600 # a slow clock: a gentle change every few minutes seed = sum(map(ord, symbol)) wave = math.sin(t + seed) * 0.6 + math.sin(t * 2.3 + seed * 1.7) * 0.3 return round(BASE[symbol] * (1 + 0.08 * wave), 2)
# floor/accounts_server.py (Account is a plain ledger class, like Tab before) import json, os from mcp.server.fastmcp import FastMCP from floor.market import get_price mcp = FastMCP("accounts") DB = "accounts.json" # a file, so cash survives between runs class Account: def __init__(self, name, data=None): self.name = name # a new uncle starts with S$10,000 of pretend cash d = data or {"cash": 10000.0, "holdings": {}, "trades": [], "strategy": STRATEGIES[name]} self.__dict__.update(d) @classmethod def get(cls, name): data = json.load(open(DB)) if os.path.exists(DB) else {} return cls(name, data.get(name)) def save(self): data = json.load(open(DB)) if os.path.exists(DB) else {} data[self.name] = {k: getattr(self, k) for k in ("cash", "holdings", "trades", "strategy")} json.dump(data, open(DB, "w")) def buy(self, symbol, qty, price): if qty * price > self.cash: return "Not enough cash" self.cash -= qty * price self.holdings[symbol] = self.holdings.get(symbol, 0) + qty self.trades.append({"side": "buy", "symbol": symbol, "qty": qty, "price": price}) self.save() return f"Bought {qty} {symbol} at S${price}" def set_strategy(self, text): self.strategy = text self.save() return "Strategy updated" def summary(self): value = self.cash + sum(q * get_price(s) for s, q in self.holdings.items()) return {"value": round(value, 2), "cash": round(self.cash, 2), "holdings": self.holdings} @mcp.tool() async def buy_shares(name: str, symbol: str, qty: int) -> str: """Buy shares at the current price from this account's cash. Fails if cash is short.""" return Account.get(name).buy(symbol, qty, get_price(symbol)) @mcp.resource("strategy://{name}") async def strategy_page(name: str) -> str: """The written strategy of one uncle.""" return Account.get(name).strategy @mcp.tool() async def past_trades(name: str) -> list: """The last 10 trades this uncle made, so he can judge how his strategy did.""" return Account.get(name).trades[-10:] STRATEGIES = { "Wong": "Buy only solid, boring companies and hold them.", "Muthu": "Chase whatever is in the news.", "AhKow": "Trade on chart patterns.", "Hamid": "Buy what everyone else is selling.", }

Step 2 · A market and a push server, with a simulator inside第 2 步 · 行情与推送服务端，里面藏着模拟器

Learn先学

Real prices need a data account and a key. So the prices come from the simulator you wrote in Step 1: a made-up price that moves slowly and smoothly with time, so two calls a second apart do not jump wildly. The ticker list is made up too: KOPI, ROTI, TEHT, NASI. In the code, seed comes from the letters of the ticker, so each ticker gets its own wave instead of all moving together.

真实行情需要数据账号和密钥。所以价格来自你在第 1 步写好的模拟器：一个随时间缓慢、平滑变化的虚构价格，这样相隔一秒的两次调用不会大起大落。股票代码也是虚构的：KOPI、ROTI、TEHT、NASI。代码里的 seed 由股票代码的字母算出，所以每只股票有自己的波动，不会一起涨跌。

Because the market is its own server, you can swap in a real provider later without touching any uncle.

因为行情是独立的服务端，以后换成真实数据源时，不用动任何一位大叔。

# floor/market_server.py from mcp.server.fastmcp import FastMCP from floor.market import get_price mcp = FastMCP("market") @mcp.tool() async def lookup_price(symbol: str) -> float: """Latest price of a ticker, in S$.""" return get_price(symbol) if __name__ == "__main__": mcp.run(transport="stdio")
# floor/push_server.py: one tool, same shape import os, requests mcp = FastMCP("push") @mcp.tool() async def push(message: str) -> str: """Send a short note to my phone, e.g. after a trade.""" r = requests.post("https://api.pushover.net/1/messages.json", data={ "user": os.getenv("PUSHOVER_USER"), "token": os.getenv("PUSHOVER_TOKEN"), "message": message}) return "sent" if r.ok else "failed"

Step 3 · One uncle, one researcher第 3 步 · 一位大叔，一位研究员

Learn先学

Each uncle needs three servers for trading and the researcher needs three of its own. Six async with blocks nested inside each other would be unreadable, so use AsyncExitStack: it opens servers in a loop and closes them all, even if the run fails.

每位大叔交易要用三个服务端，研究员又要三个自己的。六层嵌套的 async with 根本没法读，所以用 AsyncExitStack：用循环打开服务端，结束时全部关掉，即使运行失败也一样。

researcher.as_tool(...) turns the researcher into a tool of the uncle. The uncle stays in charge and gets its answer back. The trace id carries the uncle's name, so Step 5 can tell whose run each span belongs to. max_turns=30 stops a runaway run. only_search is a tool filter: the Tavily server offers several tools, and this keeps just tavily_search. The uncle can change his strategy with a tool you add in Step 6; for now he only trades.

researcher.as_tool(...) 把研究员变成大叔的一个工具。大叔始终做主，并拿回研究员的答案。trace id 里带着大叔的名字，第 5 步就能分清每一段记录属于谁。max_turns=30 能防止一次运行失控。only_search 是工具过滤器：Tavily 服务端有好几个工具，这里只留下 tavily_search。大叔改策略要用第 6 步才加的工具，现在他只会交易。

import os, secrets from contextlib import AsyncExitStack from agents import Agent, Runner, trace from agents.mcp import MCPServerStdio, create_static_tool_filter STRATEGY_NOTE = "Look at how your past trades actually performed, and update your strategy if the results say you should." RESEARCH_RULES = "Research the ticker you are asked about: news first, then context. Reply in three lines." def trader_rules(name): return f"{STRATEGIES[name]} Trade only KOPI, ROTI, TEHT, NASI. Never guess prices. {STRATEGY_NOTE}" async def build_message(name): return f"You are {name}. Check your account and strategy, trade if it is worthwhile, then push a short note." def make_trace_id(tag): # "trace_" + 32 chars; the name rides in front return "trace_" + (tag + "0" + secrets.token_hex(16))[:32] only_search = create_static_tool_filter(allowed_tool_names=["tavily_search"]) def trader_servers(): p = [{"command": "uv", "args": ["run", "-m", "floor.accounts_server"]}, {"command": "uv", "args": ["run", "-m", "floor.push_server"]}, {"command": "uv", "args": ["run", "-m", "floor.market_server"]}] return [MCPServerStdio(x, client_session_timeout_seconds=120) for x in p] def researcher_servers(name): return [MCPServerStdio({"command": "uvx", "args": ["mcp-server-fetch"]}, client_session_timeout_seconds=120), MCPServerStdio({"command": "npx", "args": ["-y", "tavily-mcp@latest"], "env": {"TAVILY_API_KEY": os.getenv("TAVILY_API_KEY")}}, tool_filter=only_search, client_session_timeout_seconds=120), MCPServerStdio({"command": "npx", "args": ["-y", "@modelcontextprotocol/server-memory"], "env": {"MEMORY_FILE_PATH": os.path.abspath(f"memory/{name.lower()}.json")}}, client_session_timeout_seconds=120)] async def run_uncle(name: str, model: str = "gpt-4o-mini"): async with AsyncExitStack() as stack: t_srv = [await stack.enter_async_context(s) for s in trader_servers()] r_srv = [await stack.enter_async_context(s) for s in researcher_servers(name)] researcher = Agent(name="Researcher", instructions=RESEARCH_RULES, model=model, mcp_servers=r_srv) uncle = Agent(name=name, instructions=trader_rules(name), model=model, mcp_servers=t_srv, tools=[researcher.as_tool(tool_name="Researcher", tool_description="Research news and prices for a ticker")]) with trace(f"{name}-trading", trace_id=make_trace_id(name.lower())): await Runner.run(uncle, await build_message(name), max_turns=30)

Step 4 · Run all four on a timer第 4 步 · 让四位大叔按定时器运行

Learn先学

async/await let a program wait for something slow (a server, a model) without freezing. asyncio.gather runs the four uncles at the same time. Then the floor sleeps, and the loop starts again. The pause comes from an environment variable, so you can change it without editing code.

async/await 让程序在等慢的东西（服务端、模型）时不会卡住。asyncio.gather 让四位大叔同时运行。然后交易场休息一会儿，再重新开始。休息的时间来自环境变量，不用改代码就能调整。

Watch the cost. Four traders, each with a researcher and six servers, every N minutes, adds up while you sleep.

要留意费用。四位交易员，每人带一个研究员和六个服务端，每隔 N 分钟就跑一次，你睡觉的时候钱也在花。

import asyncio, os async def floor(): while True: await asyncio.gather(*(run_uncle(n) for n in ["Wong", "Muthu", "AhKow", "Hamid"])) await asyncio.sleep(int(os.getenv("RUN_EVERY_N_MINUTES", "60")) * 60) # floor/trading_floor.py ends with: if __name__ == "__main__": asyncio.run(floor())

Step 5 · See inside with your own tracer第 5 步 · 用自己的追踪器看清内部

Learn先学

Four uncles running at once make a messy log. The SDK lets you plug in a TracingProcessor: it is called for every span (an agent step, a tool call or a model call). Yours writes each span to a database with the uncle's name, and the dashboard reads those rows as a live, colour-coded log.

四位大叔同时运行，日志会乱成一团。SDK 允许你接入一个 TracingProcessor：每一个 span（智能体的一步、一次工具调用或一次模型调用）都会交给它。你的追踪器把每个 span 连同大叔的名字写进数据库，仪表盘把这些记录读成实时的彩色日志。

The trick is the name inside trace_id, which make_trace_id put in front. Every span can then be traced back to its owner. _who reads the name back out: the text between the first underscore and the 0. In each method, w holds the name, and the row is written only if there is a name.

关键在 trace_id 里的名字，也就是 make_trace_id 放在最前面的那部分。这样每个 span 都能追回它的主人。_who 把名字读回来：取第一个下划线和 0 之间的文字。每个方法里，w 存着名字，只有 if 有名字，才写这一行记录。

from agents import TracingProcessor, add_trace_processor from floor.db import write_log # a small helper that inserts a row into SQLite class FloorLog(TracingProcessor): def _who(self, x): # trace ids look like trace_<name>0<random> tag = x.trace_id.split("_")[1] return tag.split("0")[0] if "0" in tag else None def on_trace_start(self, t): w = self._who(t) if w: write_log(w, "trace", f"start {t.name}") def on_trace_end(self, t): w = self._who(t) if w: write_log(w, "trace", f"end {t.name}") def on_span_start(self, s): if (w := self._who(s)) and s.span_data: write_log(w, s.span_data.type, f"start {getattr(s.span_data, 'name', '')}") def on_span_end(self, s): pass def shutdown(self): pass def force_flush(self): pass add_trace_processor(FloorLog())

Step 6 · Let them rewrite their own strategy第 6 步 · 让他们改写自己的策略

Learn先学

The most interesting idea: change_strategy is one of the account tools, and the instructions (STRATEGY_NOTE) tell the uncle to look at how past trades performed (the past_trades tool from Step 1 returns them) and update if the results say so. Profit and loss is a real-world evaluation that feeds into the next decision. That makes a loop that learns, not a fixed prompt.

最有意思的想法是：change_strategy 是账户工具之一，指令（STRATEGY_NOTE）叫大叔去看过往交易的表现（第 1 步的 past_trades 工具会返回它们），结果说该改就改。盈亏就是一种真实世界的评估，会反馈到下一次决策里。这就成了一个会学习的循环，而不是固定不变的提示词。

For the screen, split it like a real product. A small, read-only FastAPI app serves the roster, values, holdings, transactions and logs. A Vite + TypeScript page (Vite is the tool that serves a web page while you build it) asks it for new numbers every couple of seconds. That repeated asking is called polling. The page draws a chart per uncle. Browsers block a page from reading data on another address, a rule called CORS. Vite's dev server passes /api requests on to port 8000, so the browser sees one address and you set nothing up.

屏幕那边，像真正的产品一样拆开。一个小巧的只读 FastAPI 应用提供名单、总值、持仓、交易和日志。一个 Vite + TypeScript 页面（Vite 是你开发时用来提供网页的工具）每隔几秒向它要一次最新数字，这种反复询问叫做轮询，页面还会给每位大叔画一张图。浏览器默认不允许网页读取另一个地址上的数据，这条规则叫 CORS。Vite 的开发服务器会把 /api 的请求转给 8000 端口，所以浏览器只看到一个地址，你什么都不用设置。

What I got wrong我踩过的坑I did not expect the cost of a timer. Four traders, a researcher each and several servers, every N minutes, adds up while you sleep. Now I set RUN_EVERY_N_MINUTES high, use small models and stop the floor when I am done watching. Nesting six async with blocks was unreadable until I used AsyncExitStack, and each server needs a generous timeout (I use 120 s) because uv run start-up and first-time downloads are slow. Last, I wanted different uncles on different providers. The SDK takes a plain model name for OpenAI, and an OpenAIChatCompletionsModel(model=..., openai_client=AsyncOpenAI(base_url=...)) for any OpenAI-compatible provider (one that speaks the same API), so I route by model-name prefix. (A provider is the company that hosts a model. The routing is not in this lesson's code: it is an idea for later.) Each provider needs its own key variable, so a missing one only breaks that uncle.我没想到定时器会这么花钱。四位交易员、各带一个研究员和好几个服务端，每隔 N 分钟跑一次，你睡觉的时候钱也在花。现在我把 RUN_EVERY_N_MINUTES 设得很大，用小模型，看完就停掉交易场。嵌套六层 async with 根本没法读，直到用上 AsyncExitStack；每个服务端还要给足超时（我用 120 秒），因为 uv run 启动和第一次下载都很慢。最后，我想让不同的大叔用不同的模型提供商。SDK 对 OpenAI 直接接受模型名字；对任何兼容 OpenAI 的提供商（即说同一种接口的提供商），要用 OpenAIChatCompletionsModel(model=..., openai_client=AsyncOpenAI(base_url=...))，所以我按模型名字的前缀来分流。（提供商就是托管模型的公司。这段分流没有写在本课的代码里，留作以后的想法。）每个提供商都要有自己的密钥变量，缺一个只会让对应的那位大叔出问题。

Common errors常见错误

• ModuleNotFoundError: No module named 'floor': You ran the file from inside the folder. Fix: run from the project root with uv run -m floor.trading_floor.
• agents.exceptions.MaxTurnsExceeded: Max turns (30) exceeded: An uncle kept calling tools. Fix: tighten his strategy text or accept the limit, since the round simply ends.
• Address already in use: An earlier run still holds port 8000. Fix: stop it, or pass --port 8001 and update the front end.
• Insufficient funds / not enough shares (returned by a tool): Not a crash: the ledger refused the trade. Fix: nothing; the agent should read the message and adjust.

• ModuleNotFoundError: No module named 'floor'：你在文件夹内部运行了文件。解决：在项目根目录用 uv run -m floor.trading_floor 运行。
• agents.exceptions.MaxTurnsExceeded: Max turns (30) exceeded：某位大叔一直在调用工具。解决：把他的策略写得更明确，或接受这个上限，这一轮会直接结束。
• Address already in use：上一次运行还占着 8000 端口。解决：先停掉它，或加上 --port 8001 并同步改前端。
• Insufficient funds / not enough shares (returned by a tool)：不是崩溃：账本拒绝了这笔交易。解决：不用处理；智能体应读到这条信息并调整。

Takeaways要点回顾

• A whole system can be made of MCP servers: your own accounts server, a market server and a push server.
• Put a simulator behind the market server, and a real data source can replace it later without touching the agents.
• A researcher agent is handed to the trader as a tool, so the trader stays in charge.
• AsyncExitStack opens many servers in a loop and closes them all, even on failure.
• A custom TracingProcessor plus the name inside the trace id gives a live log per agent.
• Profit and loss is real feedback: letting agents rewrite their strategy turns a fixed prompt into a loop that learns.
• Timers cost money while you sleep: slow interval, small models, stop when done. And it is pretend money only.

• 整个系统可以由 MCP 服务端搭成：你自己的账户服务端、行情服务端和推送服务端。
• 在行情服务端后面放一个模拟器，以后换成真实数据源时，不用动智能体。
• 研究员智能体作为工具交给交易员，交易员始终做主。
• AsyncExitStack 用循环打开很多服务端，并且即使失败也会全部关掉。
• 自定义的 TracingProcessor 加上 trace id 里的名字，就能得到每个智能体各自的实时日志。
• 盈亏是真实的反馈：让智能体改写自己的策略，就把固定的提示词变成了会学习的循环。
• 定时器会在你睡觉时花钱：间隔拉长、用小模型、看完就停。而且这只是模拟的钱。

Recap三句回顾

• One MCP server per job (accounts, prices, push), one agent per uncle.
• Tracing and a read-only API let you watch without touching the money.
• Paper money first: test the loop and guardrails before anything real.

• 一个任务一个 MCP 服务（账户、价格、推送），每位大叔一个智能体。
• 追踪日志加只读 API，让你只看不碰钱。
• 先用模拟资金：在碰真钱之前，把循环和护栏测好。
