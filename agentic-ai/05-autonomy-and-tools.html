Autonomy and tools自主性与工具

How a model that can only talk ends up doing things · ~18 min · hands-on只会说话的模型，是怎样开始做事的 · 约 18 分钟 · 动手实践

Step 1 · A model only talks第 1 步 · 模型只会说话

Learn先学

A model turns text into text. Saving a file or sending an email must be done by your code. Example: a digital twin on Alex's website, and a visitor, Mei, who leaves her email. The code around the model is the harness: it builds the input, reads the output, acts on it and repeats. We add four pieces: context, memory, a tool, a loop.

模型只把文字变成文字。存文件、发邮件必须由你的代码来做。示例：Alex 网站上的数字分身，访客 Mei 留下了邮箱。模型外面的那层代码叫外壳（harness）：构造输入、读取输出、据此行动并重复。我们加四块：上下文、记忆、工具、循环。

Step 2 · Context and memory第 2 步 · 上下文与记忆

Learn先学

Context: the model knows nothing about Alex, so paste what it needs into the system prompt (the instructions sent first on every call) and tell it to admit gaps.

Memory: every call is stateless. A chat feels continuous only because your code resends the whole conversation each time.

上下文：模型对 Alex 一无所知，所以把它需要的内容贴进系统提示词（每次调用最先发送的指令），并要求它承认不知道。

记忆：每次调用都是无状态的。聊天看起来连续，只是因为你的代码每次都把整段对话重发一遍。

# summary.txt: a few lines about Alex in your own words with open("twin/summary.txt") as f: summary = f.read() system_prompt = f"You are Alex's digital twin. Answer questions about his career.\n## Summary\n{summary}\nIf you don't know something, say so. Never make things up." def chat(message, history): messages = [{"role": "system", "content": system_prompt}] + history + [{"role": "user", "content": message}] response = client.chat.completions.create(model="gpt-5.4-mini", messages=messages) return response.choices[0].message.content history = [] reply = chat("Hi, who is Alex?", history) history += [{"role": "user", "content": "Hi, who is Alex?"}, {"role": "assistant", "content": reply}] # this list is the memory

Step 3 · A tool: let the model ask第 3 步 · 工具：让模型来请求

Learn先学

A tool has three parts: 1) a plain Python function, 2) a description the model can read, and 3) your code that runs the function when the model asks. The model never saves anything; it asks, your code acts, the result goes back.

工具有三部分：1) 普通 Python 函数，2) 模型能读懂的描述，3) 模型请求时运行函数的代码。模型自己什么也不存：它提出请求，你的代码执行，结果再送回。

def record_email_tool(email): with open("emails.txt", "a") as f: f.write(email + "\n") return "Email recorded" # the model cannot see your Python, so describe the tool in JSON (labels and values) record_email_tool_json = { "name": "record_email_tool", "description": "???", "parameters": {"type": "object", "properties": {"email": {"type": "string", "description": "The email address of this user"}}, "required": ["email"]} }

Step 4 · The loop第 4 步 · 循环

Learn先学

The model may need one tool's result before choosing the next, so keep going while it keeps asking for tools. finish_reason says why it stopped: "tool_calls" means run my tools, "stop" means done. One reply can ask for several tools, so the helper loops over a list.

模型可能要先拿到一个工具的结果才能决定下一步，所以只要它还在请求工具就继续循环。finish_reason 说明停下的原因："tool_calls" 表示请运行我的工具，"stop" 表示答完了。一次回复可能请求好几个工具，所以辅助函数遍历一个列表。

import json tools = [{"type": "function", "function": record_email_tool_json}] # the JSON description from step 3 def handle_tool_calls(tool_calls): results = [] for call in tool_calls: arguments = json.loads(call.function.arguments) # inputs arrive as JSON text if call.function.name == "record_email_tool": output = record_email_tool(**arguments) else: output = "Unknown tool" results.append({"role": "tool", "tool_call_id": call.id, "content": output}) # the id says which request this result answers return results def chat(message, history): messages = [{"role": "system", "content": system_prompt}] + history + [{"role": "user", "content": message}] for _ in range(5): # at most 5 rounds, so it can never loop forever response = client.chat.completions.create(model="gpt-5.4-mini", messages=messages, tools=tools) if response.choices[0].finish_reason != "tool_calls": break # the model is done messages.append(response.choices[0].message) messages.extend(handle_tool_calls(response.choices[0].message.tool_calls)) return response.choices[0].message.content
You just wrote an agent loop你刚写出了一个智能体循环An LLM, tools and a loop that runs until the model stops asking (or the round limit hits). A framework only hides these lines behind a neat name.一个大模型、几个工具，加一个循环，直到模型不再请求（或达到轮数上限）。框架只是把这些代码藏在了漂亮的名字后面。
Common error常见错误BadRequestError ... role 'tool' must be a response to a preceeding message with 'tool_calls': append the model's own tool request to messages before the results, as above. If the model keeps asking for tools, always return a short result string; the round limit above stops it either way.BadRequestError ... role 'tool' must be a response to a preceeding message with 'tool_calls'：像上面那样，先把模型自己的工具请求加进 messages，再加结果。如果模型一直请求工具，总要返回一个简短的结果字符串；上面的轮数上限无论如何都会让它停下。

Now make it yours现在轮到你

Takeaways要点回顾

• A model turns text into text; your code does everything else.
• Context goes in the system prompt; tell the model to admit gaps.
• Memory: calls are stateless, so resend the history.
• Tool: function + description + code that runs it. The description decides when it is used.
• Loop: keep calling while the model asks for tools.

• 模型只把文字变成文字，其余都靠你的代码。
• 上下文放进系统提示词，并要求模型承认不知道。
• 记忆：调用无状态，所以重发历史。
• 工具：函数 + 描述 + 运行它的代码，描述决定何时使用。
• 循环：模型还在请求工具就继续调用。
