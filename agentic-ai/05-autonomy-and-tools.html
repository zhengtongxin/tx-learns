The problem: a model only talks问题：模型只会说话

Learn先学

A model turns text into text. That is all. Saving a file, sending an email, looking something up must be done by your code. Watch what happens to Mei's message on a plain model with nothing around it.

模型只会把文字变成文字，仅此而已。存文件、发邮件、查资料，都得由你的代码来做。看看 Mei 的消息交给一个没有任何配套的模型会怎样。

So you need code around the model. That code is called the harness: it builds the input, reads the output, acts on it, and repeats. The next four steps build it one piece at a time: ① Context, ② Memory, ③ Tool, ④ Loop.

所以模型外面要有一层代码，叫外壳（harness）：它构造输入、读取输出、据此行动、必要时重复。接下来四步一块一块把它搭起来：① 上下文、② 记忆、③ 工具、④ 循环。

① Context: tell it who it is① 上下文：告诉它它是谁

Learn先学

The model knows nothing about Alex. Anything it should say about him must be pasted into its system prompt, the instructions sent first on every call. Two files do the job: linkedin.pdf (your profile saved as PDF) and summary.txt (a few lines in your own words). Your code turns them into two text variables:

模型对 Alex 一无所知。想让它说关于他的事，就得把内容贴进系统提示词，也就是每次调用最先发送的指令。两个文件就够了：linkedin.pdf（导出的个人资料 PDF）和 summary.txt（用自己的话写的几行介绍）。代码把它们变成两个文本变量：

# once, in a terminal: pip install pypdf from pypdf import PdfReader reader = PdfReader("twin/linkedin.pdf") linkedin = "" for page in reader.pages: text = page.extract_text() if text: linkedin += text with open("twin/summary.txt") as f: summary = f.read() system_prompt = f"You are Alex's digital twin. Answer questions about his career.\n## Summary\n{summary}\n## LinkedIn\n{linkedin}\nIf you don't know something, say so. Never make things up."

② Memory: why a chat feels continuous② 记忆：为什么聊天看起来是连续的

Learn先学

Every call to a model is stateless: it remembers nothing from the last call. A chat feels continuous only because your code sends the whole conversation so far each time. Mei says “My name is Mei”, then later asks “What's my name?”. For the model to answer, the first message must travel again with the second.

每次调用模型都是无状态的：它不记得上一次的任何内容。聊天看起来连续，只是因为你的代码每次都把到目前为止的整段对话一起发过去。Mei 先说“我叫 Mei”，之后问“我叫什么？”。模型要答得出来，第一条消息必须和第二条一起再发一遍。

def chat(message, history): messages = [{"role": "system", "content": system_prompt}] + history + [{"role": "user", "content": message}] response = client.chat.completions.create(model="gpt-5.4-mini", messages=messages) return response.choices[0].message.content

A chat window such as Gradio's ChatInterface (Gradio is a Python library that turns a function into a small web page) passes history to your function on every turn.Gradio 的 ChatInterface 这类聊天窗口（Gradio 是一个 Python 库，能把一个函数变成一个小网页），会在每一轮把 history 传给你的函数。

③ Tool: let the model ask your code to act③ 工具：让模型请求你的代码去执行

Learn先学

Back to Mei's email. The fix is to let the model ask. A tool has three parts: 1) a plain Python function you write, 2) a description the model can read, and 3) your code that runs the function when the model asks. Part 1 saves an email:

回到 Mei 的邮箱。办法是让模型提出请求。一个工具有三部分：1) 你写的普通 Python 函数，2) 模型能读懂的描述，3) 当模型请求时运行函数的代码。第 1 部分负责存邮箱：

def record_email_tool(email): with open("emails.txt", "a") as f: f.write(email + "\n") return "Email recorded"

The model cannot see your Python. So part 2 describes the tool in JSON (a plain-text format of labels and values that code and models can both read): a name, what it is for, and the inputs it needs. The "???" is a blank for you to fill in: the quiz below helps you choose.

模型看不到你的 Python 代码。所以第 2 部分用 JSON（一种由标签和值组成、代码和模型都能读的纯文本格式）描述这个工具：名字、用途和需要的输入。其中的 "???" 是留给你填写的空白，下面的小测会帮你选。

record_email_tool_json = { "name": "record_email_tool", "description": "???", "parameters": {"type": "object", "properties": {"email": {"type": "string", "description": "The email address of this user"}}, "required": ["email"]} }

Now all three parts work together. Step through what happens to Mei's message, one half-step at a time.

现在三部分一起工作。一步一步看 Mei 的消息经历了什么。

④ Loop: what if one call is not enough?④ 循环：一次调用不够怎么办？

Learn先学

The walk-through handled one request with an if. But the model might need one tool's result before choosing the next. You cannot know how many rounds a task takes, so you keep going while the model keeps asking for tools:

上面的演示用一个 if 就处理完了。但模型要先拿到一个工具的结果才能决定下一步。你无法预知需要几轮，所以只要模型还在请求工具，就一直循环：

Two helpers first, because the loop uses them. tools is the list of JSON descriptions you hand the model. handle_tool_calls runs each tool the model asked for and builds the reply messages. One model reply can ask for several tools at once (these are parallel tool calls), so it loops over a list. The model also says why it stopped in finish_reason: "tool_calls" means "I want tools run", "stop" means "I am done, here is my answer".

先写两个辅助，因为循环要用到它们。tools 是交给模型的 JSON 描述列表。handle_tool_calls 负责运行模型请求的每个工具，并生成回复消息。模型的一次回复可能同时请求好几个工具（即并行工具调用），所以这里要遍历一个列表。模型还会在 finish_reason 里说明它为什么停下："tool_calls" 表示“请帮我运行工具”，"stop" 表示“我答完了”。

import json tools = [{"type": "function", "function": record_email_tool_json}] # the JSON description from above def handle_tool_calls(tool_calls): results = [] for call in tool_calls: # one reply can hold several requests arguments = json.loads(call.function.arguments) # the inputs arrive as JSON text if call.function.name == "record_email_tool": output = record_email_tool(**arguments) # ** unpacks the dict into named inputs: email="..." else: output = "Unknown tool" results.append({"role": "tool", "tool_call_id": call.id, "content": output}) return results
def chat(message, history): messages = [{"role": "system", "content": system_prompt}] + history + [{"role": "user", "content": message}] done = False while not done: response = client.chat.completions.create(model="gpt-5.4-mini", messages=messages, tools=tools) if response.choices[0].finish_reason == "tool_calls": messages.append(response.choices[0].message) messages.extend(handle_tool_calls(response.choices[0].message.tool_calls)) else: done = True return response.choices[0].message.content

You just wrote an agent loop你刚写出了一个智能体循环An LLM, tools, and a while loop that runs until the model stops asking for tools. That is the core of every agent. A framework only hides these lines behind a neat name.一个大模型、几个工具，加一个 while 循环，直到模型不再请求工具为止。这就是所有智能体的核心。框架只是把这些代码藏在了漂亮的名字后面。
What changed这一课之后Now the assistant can call tools: when a regular leaves an email address, it asks for record_email_tool and the address is saved to a file, the way Aina's order pad keeps a note. A similar tool could note that Auntie Suria's regular takes kopi-o kosong. Like the chalkboard menu, it can only do what is on its tool list. The next problem is that this tool loop has only met tidy messages; real customers ask messy things.现在助手会调用工具了：熟客留下邮箱时，它会请求 record_email_tool，邮箱就被存进一个文件，就像 Aina 的点单本记下一条备注。类似的工具还能记下 Suria 阿姨的熟客喝 kopi-o kosong。就像墙上的黑板菜单，它只能做工具清单上有的事。下一个问题是：这个工具循环只见过整齐的消息，真实的顾客会问各种乱七八糟的事。

Common errors常见错误

• openai.AuthenticationError: Error code: 401 - Incorrect API key provided: The key is missing, mistyped or .env was not loaded. Fix: check OPENAI_API_KEY, call load_dotenv(override=True) first and restart the notebook.
• NameError: name 'handle_tool_calls' is not defined: The loop calls a helper you have not built yet. Fix: define handle_tool_calls (and tools) from step ④ before you run chat.
• openai.BadRequestError: Invalid parameter: messages with role 'tool' must be a response to a preceeding message with 'tool_calls': You sent the tool results without first adding the model's own tool request to messages. Fix: messages.append(response.choices[0].message) before extending with the results.
• The loop never ends (no error, the cell just keeps running): The model keeps asking for a tool because your function returned nothing useful. Fix: always return a short result string, and cap the rounds with a counter.

• openai.AuthenticationError: Error code: 401 - Incorrect API key provided：密钥没填、填错，或 .env 没加载。解决：检查 OPENAI_API_KEY，先调用 load_dotenv(override=True)，再重启 notebook。
• NameError: name 'handle_tool_calls' is not defined：循环调用了你还没写的辅助函数。解决：先定义第 ④ 步里的 handle_tool_calls 和 tools，再运行 chat。
• openai.BadRequestError: Invalid parameter: messages with role 'tool' must be a response to a preceeding message with 'tool_calls'：你发回了工具结果，却没有先把模型自己的工具请求加进 messages。解决：先 messages.append(response.choices[0].message)，再追加工具结果。
• The loop never ends (no error, the cell just keeps running)：模型一直请求工具，因为你的函数没返回有用的东西。解决：总是返回一个简短的结果字符串，并用计数器限制轮数。

Takeaways要点回顾

• A model turns text into text. Your code does everything else.
• Context: put what it must know into the system prompt, and tell it to admit gaps.
• Memory: calls are stateless, so resend the history every time.
• Tool: function + description + code that runs it. The description decides when it is used.
• Loop: keep calling while the model asks for tools. The model decides whether to act.

• 模型只把文字变成文字，其余都靠你的代码。
• 上下文：把它必须知道的放进系统提示词，并要求它承认不知道。
• 记忆：调用是无状态的，所以每次都重发历史。
• 工具：函数 + 描述 + 运行它的代码，描述决定何时被使用。
• 循环：模型还在请求工具就继续调用，由模型决定要不要行动。
