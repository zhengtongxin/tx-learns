Autonomy and tools自主性与工具

Why a model alone cannot act, and the four parts that make it act · ~18 min · hands-on为什么模型自己无法行动，以及让它行动起来的四个部分 · 约 18 分钟 · 动手实践

A chatbot can only talk. Yet a useful agent saves a visitor's email, looks things up, and keeps going until a job is done. This lesson answers one question: what must you add around an LLM so that it can act? You will build a digital twin step by step, with no framework.

聊天机器人只会说话。可一个有用的智能体能记下访客的邮箱、查资料，并且一直做到任务完成。这节课只回答一个问题：要在大模型外面加上什么，它才能行动？你会不借助任何框架，一步步搭出一个数字分身。

The problem: a model only talks问题：模型只会说话

A visitor on your twin's website types their email. You want it saved so you can reply. Try it on a plain model with nothing around it.

访客在你的分身网站上输入了自己的邮箱。你希望把它存下来，方便回复。拿一个没有任何外壳的普通模型试试。

A model turns text into text. Anything else, like saving a file, must be done by your code. The harness is that code: it builds the input, reads the output, acts on it, and repeats.

模型只能把文字变成文字。保存文件之类的其他事，必须由你的代码来做。外壳就是这些代码：构造输入、读取输出、据此行动，然后重复。

① Context: tell it who it is① 上下文：告诉它它是谁

Why: the model knows nothing about Alex. Whatever it should say about him, you have to put into its prompt.

为什么：模型对 Alex 一无所知。它该说的关于他的一切，都得由你放进提示词里。

The project is a digital twin: a chat assistant on a website that answers questions about one person's career. It needs two files in a folder called twin. Tick them off.

这个项目是一个数字分身：网站上的聊天助手，回答关于某个人职业经历的问题。它需要在 twin 文件夹里放两个文件。做完一项就勾一项。

reader = PdfReader("twin/linkedin.pdf") linkedin = "" for page in reader.pages: text = page.extract_text() if text: # scanned pages return nothing linkedin += text with open("twin/summary.txt") as f: summary = f.read()

That code turns both files into two plain text variables, linkedin and summary. Everything after this is about what you do with those two strings.

这段代码把两个文件变成两个普通文本变量：linkedin 和 summary。接下来的一切，都是围绕怎么使用这两段文字展开的。

② Memory: why a chat feels continuous② 记忆：聊天为什么感觉连贯

Why: a visitor says “my name is Ed”, then asks about it a message later. The twin must connect the two. Predict whether it can.

为什么：访客先说“我叫 Ed”，下一条消息又问起这件事。分身必须把两者联系起来。先预测它能不能做到。

Every call to an LLM is stateless. The model remembers nothing between calls. A chat only feels continuous because your code sends the whole conversation so far each time.

每一次调用大模型都是无状态的，两次调用之间模型什么都不记得。聊天之所以感觉连贯，只是因为你的代码每次都把到目前为止的整段对话一起发了过去。

def chat(message, history): messages = [{"role": "system", "content": system_prompt}] + history + [{"role": "user", "content": message}] response = client.chat.completions.create(model="gpt-5.4-mini", messages=messages) return response.choices[0].message.content

That highlighted history is the whole trick. A chat window such as Gradio's ChatInterface hands it to your function every turn.

高亮的 history 就是全部的秘密。像 Gradio 的 ChatInterface 这样的聊天界面，每一轮都会把它交给你的函数。

③ Tool: let the model ask your code to act③ 工具：让模型请求你的代码行动

Back to the problem: the model said “saved” but did nothing. The fix is to let it ask. A tool has three parts: a plain function you write, a description the model can read, and your code that runs the function when the model asks. Part 1 is the function. This one records an email address.

回到最初的问题：模型说了“已保存”，却什么也没做。解决办法是让它去请求。一个工具有三部分：你写的普通函数、模型能读到的描述，以及在模型提出请求时运行函数的你的代码。第 1 部分是函数。这个函数负责记录邮箱。

def record_email_tool(email): print(f"Tool called to record an email: {email}") with open("emails.txt", "a") as f: f.write(email + "\n") return "Email recorded"

The model cannot see your Python. So you also describe the tool in JSON: its name, what it is for, and what inputs it needs.

模型看不到你的 Python 代码。所以你还要用 JSON 来描述这个工具：名字、用途、需要哪些输入。

record_email_tool_json = { "name": "record_email_tool", "description": "???", "parameters": {"type": "object", "properties": {"email": {"type": "string", "description": "The email address of this user"}}, "required": ["email"]} } tools = [{"type": "function", "function": record_email_tool_json}]

Fill in the ???. Which description lets the model decide when to call the tool?填空 ???。哪一个描述能让模型判断什么时候该调用这个工具？

The model reads the description to decide whether the tool fits the moment. Say when to use it, not how it is built.模型靠读描述来判断这个工具是否适用于当下。要写清楚什么时候用，而不是它怎么实现的。

Walk through one tool call走一遍一次工具调用

Now all three parts work together. A visitor writes: “Hi, you can reach me at ed@example.com”. Step through, one half-step at a time. At the first reply, predict before you continue.

现在三个部分一起工作。访客写道：“你好，可以通过 ed@example.com 联系我”。一次走半步。在第一个回复处，先预测再继续。

④ Loop: what if one call is not enough?④ 循环：一次调用不够怎么办？

Why: the walk-through handled one request with an if. But a visitor might share two emails at once, or the model might need one tool's result before choosing the next. You cannot know in advance how many rounds a task takes. Three versions of the same function, each handling more. Click to compare.

为什么：刚才的流程只用一个 if 处理一次请求。但访客可能一次给出两个邮箱，模型也可能要先拿到一个工具的结果，才能决定下一个。你无法提前知道任务要几轮。同一个函数的三个版本，一个比一个能处理的情况多。点击对比。

Your turn. For each situation, choose the simplest version that handles it.

轮到你了。对每种情况，选出能处理它的最简单的版本。

You just wrote an agent loop你刚刚写出了一个智能体循环An LLM, tools, and a while loop that keeps going until the model stops asking for tools. That is the core of every agent. A framework simply hides these if and while lines behind a neat abstraction.一个大模型、一组工具，加上一个会一直转到模型不再请求工具为止的 while 循环。这就是所有智能体的核心。框架只是把这些 if 和 while 藏在一层整洁的抽象后面。

Where the autonomy comes from自主性从哪里来

Look back at the code. Nowhere did you write “if the message contains an email, record it”. The model made that call on its own, from the tool description alone.

回头看看代码。你从来没有写过“如果消息里有邮箱，就记录下来”。是模型自己、仅凭工具描述做出了这个判断。

Who decides to call record_email_tool?谁来决定调用 record_email_tool？

The model decides whether and with what inputs. Your code decides how it runs. That split is what “autonomous” means here.模型决定要不要调用以及传什么参数，你的代码决定怎么执行。这种分工就是这里所说的“自主”。
Autonomy has a price自主性是有代价的A model that chooses its own actions can choose wrongly. Keep tools small and safe, and describe them carefully.能自己选择行动的模型，也可能选错。让工具保持小而安全，并认真写好描述。

Where frameworks fit框架在哪里

Why now: you just hand-wrote a whole harness: prompt, history, tool, loop. An agent framework is helper code that packages these same jobs so they are faster to write. Match each task to the job it belongs to.

为什么现在讲：你刚刚亲手写完了一整套外壳：提示词、历史、工具、循环。智能体框架就是辅助代码，把这些同样的工作打包起来，让它们写得更快。把每项任务对应到它所属的那件事上。

You can pick any of these, or none. Frameworks are never required.

这些你可以任选一个，也可以一个都不用。框架从来不是必需品。

Takeaways要点回顾

• A plain model only turns text into text. It can say “saved” without saving anything.
• The harness is your code around the model: build the input, read the output, act, repeat.
• ① Context: put what it should know in the system prompt, plus a rule to admit gaps.
• ② Memory: every call is stateless, so your code resends the conversation.
• ③ Tool: a function plus a description. The model asks, your code runs it.
• ④ Loop: if for one call, for for several, while for an unknown number.
• Frameworks package these jobs. You never need one.

• 普通模型只会把文字变成文字。它可以说“已保存”，却什么也没保存。
• 外壳就是包在模型外面的你的代码：构造输入、读取输出、行动、重复。
• ① 上下文：把它该知道的放进系统提示词，再加一条“不知道就承认”的规则。
• ② 记忆：每次调用都是无状态的，所以你的代码要重新发送对话。
• ③ 工具：一个函数加一份描述。模型提出请求，你的代码来执行。
• ④ 循环：一次调用用 if，多次用 for，次数不确定用 while。
• 框架只是把这些工作打包起来。你从来不需要它。
