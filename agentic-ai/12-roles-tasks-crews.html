Step 1 · Agents, tasks and a crew第 1 步 · 智能体、任务与团队

Learn先学

CrewAI is built on a coffee-shop picture: each worker does one job and the boss assigns work.

• An agent is a worker with a role, a goal and a backstory.
• A task is one order slip: what to do and what done looks like.
• A crew is the shop: the workers plus the slips.

CrewAI 基于一幅咖啡店画面：每个工人做一件事，由老板分派工作。

• 智能体是有角色、目标和背景故事的工人。
• 任务是一张订单：做什么，做成什么样才算完成。
• 团队（crew）就是整间店：工人加订单。

Our practice crew settles one question, such as whether durian cendol belongs on a stall menu: one agent argues for, then against, and a picky regular picks the winner. Pin the library version, because it changes fast:

我们的练习团队解决一个问题，比如摊位菜单上该不该加榴莲 cendol：一个智能体先正后反地陈述，再由一位挑剔的熟客选出赢家。要锁定库的版本，因为它更新很快：

uv tool install crewai==1.14.4 crewai create crew menu_argument cd menu_argument crewai run # src/menu_argument/config/agents.yaml who the workers are # src/menu_argument/config/tasks.yaml the order slips # src/menu_argument/crew.py wires them into a crew # src/menu_argument/main.py the start button

Step 2 · Workers and slips in YAML第 2 步 · 用 YAML 写工人和订单

Learn先学

Prompts live in YAML, so you can reword them without touching Python. Anything in {curly braces} is a blank filled in at start. llm picks a model per agent as provider/model. A task has a description (the order), an expected_output (the finish line) and an agent. One worker can take many slips.

提示词放在 YAML 里，改措辞不用动 Python。{花括号} 里的内容是启动时填入的空格。llm 用 提供商/模型 给每个智能体选模型。任务有 description（订单内容）、expected_output（终点线）和 agent。一个工人可以接多张单。

# config/agents.yaml arguer: role: > Stall owner who loves a good pitch goal: > Make one short, convincing case about this menu idea: {idea} backstory: > You have sold food at night markets for years and know what people pay for. llm: openai/gpt-4o-mini regular: role: > Picky regular customer goal: > Read both cases about {idea} and pick the stronger one. Judge only the arguments. backstory: > You eat here every morning and you are hard to impress. llm: openai/gpt-4o-mini
# config/tasks.yaml argue_for: description: > Argue in favour of: {idea}. Keep it tight. expected_output: > A short, punchy argument for the idea. agent: arguer output_file: output/for.md argue_against: description: > Argue against: {idea}. expected_output: > A short, punchy argument against the idea. agent: arguer output_file: output/against.md verdict: description: > Read both arguments, decide which side wins and say why. expected_output: > The winning side plus two or three reasons. agent: regular output_file: output/verdict.md

Step 3 · Wire it up and start it第 3 步 · 接线并启动

Learn先学

crew.py turns the YAML into objects. The @agent and @task decorators collect methods in the order they are written. In a sequential crew that is the running order, and each task sees the results before it, so verdict reads both arguments with nothing passed by hand. kickoff(inputs=...) fills the blanks, so every {blank} needs a key.

crew.py 把 YAML 变成对象。@agent 和 @task 装饰器按方法书写顺序收集它们。在顺序式（sequential）团队里这就是执行顺序，每个任务都能看到前面的结果，所以 verdict 不用手动传递就能读到两份论点。kickoff(inputs=...) 填空，所以每个 {空格} 都要有对应的键。

# crew.py from crewai import Agent, Crew, Process, Task from crewai.project import CrewBase, agent, crew, task @CrewBase class MenuArgument(): @agent def arguer(self) -> Agent: return Agent(config=self.agents_config["arguer"], verbose=True) @agent def regular(self) -> Agent: return Agent(config=self.agents_config["regular"], verbose=True) @task # the order here is the running order def argue_for(self) -> Task: return Task(config=self.tasks_config["argue_for"]) @task def argue_against(self) -> Task: return Task(config=self.tasks_config["argue_against"]) @task def verdict(self) -> Task: return Task(config=self.tasks_config["verdict"]) @crew def crew(self) -> Crew: return Crew(agents=self.agents, tasks=self.tasks, process=Process.sequential, verbose=True) # main.py def run(): idea = input("Menu idea to argue about: ") result = MenuArgument().crew().kickoff(inputs={"idea": idea}) print(result.raw)

Step 4 · Sequential or hierarchical?第 4 步 · 顺序式还是层级式？

Learn先学

Sequential (the default) runs the slips in order: predictable and cheap. Hierarchical adds a manager that hands out tasks and can send work back: more flexible, but it uses more tokens and is less predictable. Choose it only when the order cannot be fixed in advance.

顺序式（默认）按顺序执行：可预期，也便宜。层级式加了一位主管来分派任务，还能把活打回去：更灵活，但更耗 token，也更难预料。只有顺序没法事先定好时才选它。

# inside crew() in the class above, swap the Crew(...) call for this one Crew( agents=self.agents, tasks=self.tasks, process=Process.hierarchical, manager_llm="openai/gpt-4o", # a manager model hands out the slips )

Takeaways要点回顾

• An agent is a worker with a role, goal and backstory; a task is an order slip; a crew runs them.
• Prompts live in YAML, wiring in Python.
• In a sequential crew, method order is running order, and each task sees what came before.
• Hierarchical adds a manager: more flexible, but costlier and less predictable.
• Pin the version and give every {blank} an input key.

• 智能体是有角色、目标和背景故事的工人；任务是订单；团队负责执行。
• 提示词放 YAML，接线放 Python。
• 顺序式团队里，方法顺序就是执行顺序，每个任务都能看到前面的结果。
• 层级式加了一位主管：更灵活，但更贵，也更难预料。
• 锁定版本，并让每个 {空格} 都有输入键。
