OpenAI Agents SDK: the basicsOpenAI Agents SDK 基础

Last week you hand-built the harness. Now the SDK does it in a few lines · ~20 min · hands-on上周你亲手写了外壳，现在 SDK 几行代码就能搞定 · 约 20 分钟 · 动手实践

Last week you wrote the prompt, the history, the tool JSON and the while loop yourself. The OpenAI Agents SDK is a lightweight framework that packages exactly those jobs. Today: one new keyword pair (async / await), then four building blocks: Agent, Runner, tools and memory. Then a preview of how agents work together.

上周你亲手写了提示词、历史记录、工具 JSON 和 while 循环。OpenAI Agents SDK 是一个轻量框架，把这些工作打包好了。今天先学一对新关键字（async / await），再学四个积木：Agent、Runner、工具和记忆，最后预览智能体如何协作。

First: async and await先学：async 与 await

Why: every SDK example uses await Runner.run(...). Calling a model means waiting on the network, and async is how Python waits without freezing everything else.

为什么：SDK 的每个例子都用 await Runner.run(...)。调用模型要等网络，async 就是让 Python 等待时不卡住其他事情的办法。

async def

Defines a function that is allowed to pause while it waits.

定义一个可以在等待时暂停的函数。

await

Means "wait here for this result". Only allowed inside an async def.

表示“在这里等这个结果”。只能写在 async def 里面。

Your turn. Will each line run? One twist: a Jupyter notebook already runs an event loop, so it lets you await at the top level.

轮到你了。每段代码能运行吗？有个特例：Jupyter 笔记本本身已经有事件循环，所以允许在最外层直接 await。

Rule of thumb经验法则Calling an agent? Put await in front. In a notebook, just write it. In a .py file, wrap it in async def main() and start it with asyncio.run(main()).调用智能体？前面加 await。在笔记本里直接写；在 .py 文件里，包进 async def main()，并用 asyncio.run(main()) 启动。

Agent: a model with a role and toolsAgent：带角色和工具的模型

Why: an agent is simply one LLM, plus a system prompt, plus tools. Click each part to see where it lives in the code and what it replaced.

为什么：智能体就是一个大模型，加上系统提示词，再加上工具。点开每个部分，看它在代码里的位置，以及它取代了你上周写的什么。

Runner: the agent loop, for freeRunner：现成的智能体循环

Why: last week's loop was the hard part. See how much of your Week 1 harness the SDK now carries. Match each Week 1 job to its SDK piece.

为什么：上周最难的就是那个循环。看看 SDK 现在替你承担了多少。把上周的每项工作对应到 SDK 里的零件。

agent = Agent(name="Jokester", instructions="You are a joke teller", model="gpt-5.4-mini") result = await Runner.run(agent, "Tell a joke about Autonomous AI Agents") print(result.final_output) # the answer result.to_input_list() # every message of the run

Runner.run keeps calling the model and running tools until the model stops asking for tools: your while loop, with a turn limit built in. final_output is the answer; to_input_list() shows every message, handy for debugging.

Runner.run 会不断调用模型、运行工具，直到模型不再请求工具：就是你写的 while 循环，还自带轮数上限。final_output 是最终答案；to_input_list() 展示每一条消息，方便调试。

Install name安装名称The package is openai-agents (pip install openai-agents), imported as from agents import Agent, Runner. Do not pip install agents: that is a different, older library.安装包名是 openai-agents（pip install openai-agents），导入写 from agents import Agent, Runner。不要装 agents，那是另一个旧的库。

See inside: trace and stream看清内部：trace 与流式输出

with trace("Telling a joke"): result = await Runner.run(agent, "Tell a joke about Autonomous AI Agents") result = Runner.run_streamed(agent, input="Please tell me 5 jokes about AI Agents.") async for event in result.stream_events(): if event.type == "raw_response_event" and isinstance(event.data, ResponseTextDeltaEvent): print(event.data.delta, end="", flush=True)

trace groups the calls under one name so you can inspect every step at platform.openai.com/traces. run_streamed hands you the text piece by piece, as it is written.

trace 把这些调用归在一个名字下，你可以在 platform.openai.com/traces 查看每一步。run_streamed 则边生成边把文字一段段交给你。

What does streaming change?流式输出改变了什么？

Same answer, delivered sooner. That is why chat apps feel fast.答案相同，只是更早到达。聊天应用因此显得很快。

Tools: one decorator工具：一个装饰器

Why: last week you wrote the tool's JSON by hand. The SDK reads your function instead. You already have the plain function, push, from last week.

为什么：上周你手写了工具的 JSON，现在 SDK 直接读你的函数。上周的普通函数 push 你已经有了。

@function_tool def push_tool(message: str) -> str: """ Send the given message to the user as a push notification """ payload = {"user": pushover_user, "token": pushover_token, "message": message} result = requests.post(pushover_url, data=payload).status_code return f"Push sent with API status code {result}" notifier = Agent(name="Notifier", model="gpt-5.4-mini", instructions="You notify the user upon request", tools=[push_tool])

The SDK builds the tool JSON for you. Where does it get the tool's description (when to use it)?SDK 帮你生成了工具 JSON。工具的描述（什么时候用）从哪里来？

So the docstring is now your tool description. Same rule as last week: say when to use it. Check with push_tool.description.所以文档字符串就是你的工具描述。规则和上周一样：写清什么时候用。可用 push_tool.description 查看。

Memory: sessions记忆：Session

Why: each Runner.run starts fresh, just like last week's stateless calls. Predict first, then switch the session on.

为什么：每次 Runner.run 都是全新开始，和上周讲的无状态调用一样。先预测，再打开 session 看看。

session = SQLiteSession("12346") # in memory. For a file: SQLiteSession("12346", "memory.db") response = await Runner.run(agent, "Hi there. My name is Ed.", session=session) response = await Runner.run(agent, "What's my name?", session=session)

Two ways to remember. By hand: response.to_input_list() + [{"role": "user", ...}], exactly Week 1's history. With a session: the SDK stores and replays it for you.

两种记忆方式。手动：response.to_input_list() + [{"role": "user", ...}]，就是第 1 周的历史记录。用 session：SDK 替你保存并回放。

Preview: agents working together预览：智能体如何协作

Why: one agent is only the start. The next labs combine them in two ways. The key question is always: who talks to the user next?

为什么：一个智能体只是开始，后面的实验会用两种方式把它们组合起来。关键问题永远是：接下来由谁来和用户说话？

Agent as a tool智能体当工具

A manager calls another agent like a function, gets its result back, and stays in control.

主管像调用函数一样调用另一个智能体，拿回结果，并且继续掌控全局。

Handoff交接（Handoff）

One agent passes the conversation to another, which takes over and replies.

一个智能体把对话交给另一个，由后者接手并回复。

Guardrails: controls护栏：控制措施

A guardrail is a check that can stop a run. An input guardrail checks what comes in, before the main work. An output guardrail checks what goes out, before the user sees it.

护栏是一道可以叫停运行的检查。输入护栏在主要工作开始前检查传入的内容；输出护栏在用户看到之前检查传出的内容。

Takeaways要点回顾

• await waits for the model. Only inside async def, or at the top level of a notebook.
• An Agent is a model, instructions (the system prompt) and tools.
• Runner.run is the agent loop. final_output is the answer.
• trace shows every step. Streaming shows text as it is written.
• @function_tool builds the tool JSON from your function, using the docstring as the description.
• Each run is stateless. Pass a session (or the history list) to remember.
• Preview: agents as tools keep control, handoffs pass it on, guardrails check inputs and outputs.

• await 用来等模型，只能写在 async def 里，或笔记本的最外层。
• Agent = 模型 + instructions（系统提示词）+ 工具。
• Runner.run 就是智能体循环，final_output 是最终答案。
• trace 展示每一步，流式输出边写边显示。
• @function_tool 根据你的函数生成工具 JSON，文档字符串就是描述。
• 每次运行都是无状态的，传入 session（或历史列表）才能记住。
• 预览：智能体当工具会保持控制，交接会把控制权交出去，护栏检查输入和输出。
