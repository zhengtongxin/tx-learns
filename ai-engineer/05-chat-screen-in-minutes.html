Quick chat screen快速聊天界面

You will put a real chat screen on your model without learning front-end · ~15 min · hands-on你会不用学前端，就给自己的模型配上一个真正的聊天界面 · 约 15 分钟 · 动手实践

Step 1 · Any function becomes a form第 1 步 · 任何函数都能变成表单

Learn先学

A UI is a wrapper around a function. Gradio starts a small web server and serves a page that calls it. gr.Interface(fn, inputs, outputs) is the simplest level. Options: inbrowser=True opens the page; auth=(user, password) adds a login (password in .env); share=True makes a temporary public link that also exposes your running code to anyone with it.

界面是函数外面的一层包装。Gradio 启动一个小型网页服务器，提供一个调用它的页面。gr.Interface(fn, inputs, outputs) 是最简单的一档。选项：inbrowser=True 自动打开页面；auth=(user, password) 加登录（密码放 .env）；share=True 生成临时公开链接，拿到链接的人也能接触到你正在运行的代码。

# pip install gradio openai import gradio as gr from openai import OpenAI client = OpenAI() MODEL = "gpt-5-mini" def ask_once(text): reply = client.chat.completions.create(model=MODEL, messages=[{"role": "user", "content": text}]) return reply.choices[0].message.content gr.Interface(fn=ask_once, inputs="text", outputs="text").launch(inbrowser=True)

Step 2 · A chat screen, and why memory bites第 2 步 · 聊天界面，以及“没记忆”的麻烦

Learn先学

gr.ChatInterface(fn) gives you a chatbot. Your function receives (message, history). Models are stateless, so you rebuild the messages list every turn from that history. yield instead of return streams words as they arrive.

gr.ChatInterface(fn) 给你一个聊天机器人。你的函数会收到 (message, history)。模型无状态，所以每一轮都要你从这份历史重建 messages 列表。用 yield 代替 return，文字就边到边显示。

system_message = "You are the helper of a neighbourhood provision shop." def chat(message, history): past = [{"role": h["role"], "content": h["content"]} for h in history] messages = [{"role": "system", "content": system_message}] + past + [{"role": "user", "content": message}] stream = client.chat.completions.create(model=MODEL, messages=messages, stream=True) text = "" for chunk in stream: text += chunk.choices[0].delta.content or "" yield text gr.ChatInterface(fn=chat, type="messages").launch()

Step 3 · The system message is the product第 3 步 · system 消息就是产品

Learn先学

Same screen, same model: the system message decides what the assistant is like. A one-shot example in it shows the style you want. You can also extend it for one turn only, say adding today's stock when the message mentions umbrellas. That is the seed of retrieval (RAG) later.

同一个界面、同一个模型：助手是什么样，由 system 消息决定。在里面放一个示范，就能给出想要的风格。你也可以只为这一轮扩充它，比如消息提到雨伞时加上今天的库存。这就是后面检索（RAG）的种子。

system_message = """You are the helper of a provision shop. Be friendly and brief. Mention items on sale when they fit. Example: Customer: Do you have rice? You: Yes! 5 kg bags are on sale this week, a good deal.""" def chat(message, history): past = [{"role": h["role"], "content": h["content"]} for h in history] system = system_message if "umbrella" in message.lower(): system += "\nToday only 3 umbrellas are left, at S$6 each." messages = [{"role": "system", "content": system}] + past + [{"role": "user", "content": message}] # ...the same streaming loop as before

Step 4 · Three levels of Gradio第 4 步 · Gradio 的三档

Learn先学

Ladder: Interface (one function), then ChatInterface (a chatbot), then gr.Blocks() (your own rows, columns, chatbot, image box and buttons). You do not need Blocks yet.

阶梯：Interface（一个函数），然后 ChatInterface（聊天机器人），然后 gr.Blocks()（自己搭行、列、聊天框、图片框和按钮）。你现在还用不上 Blocks。

Common errors常见报错

• OSError: Cannot find empty port. An older screen is still running. Stop it or pass server_port=7861.
• A TypeError about history. The function must take (message, history) in that order, with type="messages". History items carry extra keys, so keep only role and content.

• OSError: Cannot find empty port：上一个界面还在运行。停掉它，或传入 server_port=7861。
• 和 history 有关的 TypeError：参数必须是 (message, history) 这个顺序，并设 type="messages"。历史条目带额外的键，只保留 role 和 content。

Now make it yours现在把它变成你的

Takeaways要点回顾

• A UI is a wrapper around a function.
• ChatInterface gives you a chatbot in about ten lines.
• Models are stateless: rebuild the messages from the history every turn.
• The system message is the product's personality; extra context can be added for one turn.
• share=True makes your code reachable by anyone with the link.

• 界面是函数外面的一层包装。
• ChatInterface 大约十行代码就是一个聊天机器人。
• 模型无状态：每一轮都从历史重建 messages。
• system 消息就是产品的性格，也可以只为一轮加额外背景。
• share=True 会让拿到链接的人都能接触到你的代码。
