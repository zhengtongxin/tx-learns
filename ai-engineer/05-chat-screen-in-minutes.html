Step 1 · Any function becomes a form第 1 步 · 任何函数都能变成表单

Learn先学

A UI is just a wrapper around a function. Gradio starts a small web server and serves a page that calls your function. gr.Interface(fn, inputs, outputs) is the simplest level. Wei Jie began with a silly function that shouts text in capitals, then swapped in a model call. Useful options: inbrowser=True opens the page for you. auth=(user, password) adds a login (keep the password in .env, not in the notebook). share=True makes a temporary public link, which also exposes your laptop's code to anyone with it.

界面只是函数外面的一层包装。Gradio 会启动一个小型网页服务器，提供一个会调用你函数的页面。gr.Interface(fn, inputs, outputs) 是最简单的一档。Wei Jie 先写了个把文字变大写的傻函数，再换成模型调用。常用选项：inbrowser=True 自动打开页面；auth=(user, password) 加登录（密码放 .env，别写进 notebook）；share=True 生成临时公开链接，同时也会把你电脑上的代码暴露给拿到链接的任何人。

import gradio as gr from openai import OpenAI client = OpenAI() MODEL = "gpt-5-mini" def shout(text): return text.upper() def ask_once(text): reply = client.chat.completions.create(model=MODEL, messages=[{"role": "user", "content": text}]) return reply.choices[0].message.content # first try: gr.Interface(fn=shout, inputs="text", outputs="text").launch() # then swap in the model call: gr.Interface(fn=ask_once, inputs="text", outputs="text").launch(inbrowser=True)
* Running on local URL: http://127.0.0.1:7860

Step 2 · A chat screen, and why memory bites第 2 步 · 聊天界面，以及“没记忆”的麻烦

Learn先学

gr.ChatInterface(fn) gives you a chatbot in a few lines. Your function receives (message, history). Remember that models are stateless: Gradio hands you the history, and you rebuild the messages list every turn. Use yield instead of return and Gradio shows words as they arrive. (A generator is a function that yields many times.)

gr.ChatInterface(fn) 几行代码就给你一个聊天机器人。你的函数会收到 (message, history)。别忘了模型是无状态的：Gradio 把历史交给你，每一轮的 messages 列表要你自己重建。用 yield 代替 return，Gradio 就会边收边显示。（生成器就是会多次 yield 的函数。）

system_message = "You are the helper of a neighbourhood provision shop." def chat(message, history): past = [{"role": h["role"], "content": h["content"]} for h in history] messages = [{"role": "system", "content": system_message}] + past + [{"role": "user", "content": message}] stream = client.chat.completions.create(model=MODEL, messages=messages, stream=True) text = "" for chunk in stream: text += chunk.choices[0].delta.content or "" yield text gr.ChatInterface(fn=chat, type="messages").launch()
* Running on local URL: http://127.0.0.1:7860

Step 3 · The system message is the product第 3 步 · system 消息就是产品

Learn先学

Same screen, same model: only the system message decides what the assistant is like. Wei Jie wrote one for the shop: be friendly, nudge people towards items on sale, and show one example reply (one-shot prompting). Change that text while testing and the behaviour changes at once. For testing, a quick global variable is fine.

同一个界面、同一个模型：助手是什么样，全由 system 消息决定。Wei Jie 给小店写了一条：友好，引导顾客留意特价商品，再给一个示范回复（单样本提示）。测试时改这段文字，行为立刻就变。测试阶段用个全局变量图快，没问题。

system_message = """You are the helper of Mdm Tan's provision shop. Be friendly and brief. Mention items on sale when they fit. Example: Customer: Do you have rice? You: Yes! 5 kg bags are on sale this week, a good deal.""" # run the screen again and chat: the same code now behaves differently

Step 4 · Inject context for one turn第 4 步 · 只为这一轮注入背景信息

Learn先学

You can also change the system message for one turn only. If the customer's message mentions “umbrella”, add one extra sentence for that call, such as today's stock. Nothing is stored for later turns. Putting extra facts into a single call like this is cheap and powerful, and it is the seed of retrieval (RAG) later in this track.

你也可以只为这一轮改动 system 消息。顾客的消息里提到“雨伞”，就为这次调用多加一句，比如今天的库存。后面的轮次不会留下任何东西。像这样把额外事实放进单次调用，又便宜又好用，也是后面检索（RAG）的种子。

def chat(message, history): past = [{"role": h["role"], "content": h["content"]} for h in history] system = system_message if "umbrella" in message.lower(): system += "\nToday only 3 umbrellas are left, at S$6 each." messages = [{"role": "system", "content": system}] + past + [{"role": "user", "content": message}] # ...the same streaming loop as before

Step 5 · Your own layout with Blocks第 5 步 · 用 Blocks 自己排版

Learn先学

When the ready-made screen is not enough, gr.Blocks() lets you build your own: rows, columns, a chatbot, an image box, buttons and callbacks. That is level three. You do not need it yet. Just know it is there, so you can see the ladder: Interface, then ChatInterface, then Blocks. The next lessons and the project use it.

现成的界面不够用时，gr.Blocks() 让你自己搭：行、列、聊天框、图片框、按钮和回调。这是第三档。你现在还用不上，只要知道有它，就看清了这个阶梯：Interface，然后 ChatInterface，然后 Blocks。后面的课和项目会用到它。

with gr.Blocks() as screen: with gr.Row(): chatbot = gr.Chatbot(type="messages") picture = gr.Image() box = gr.Textbox(label="Ask the shop helper") screen.launch() # without this, nothing shows

What I got wrong我搞错的地方Gradio's history items carry extra keys, but the API wants only role and content, so I had to clean them first. I also left share=True on and forgot the link was public.Gradio 给的历史条目带有额外的键，而 API 只要 role 和 content，所以要先清理。我还开着 share=True 忘了关，链接其实是公开的。

Common errors常见报错

• OSError: Cannot find empty port in range: 7860-7860. An older screen is still running. Stop the old cell (or restart the kernel), or pass server_port=7861.
• A blank reply or TypeError about history. The chat function must take (message, history) in that order, and the screen needs type="messages".
• AuthenticationError: Incorrect API key provided. The key is missing, has a stray space or newline, or the .env file was not loaded. Print len(os.getenv('OPENAI_API_KEY')), fix the file, then restart the notebook.

• OSError: Cannot find empty port in range: 7860-7860：上一个界面还在运行。停掉旧单元格（或重启内核），或者传入 server_port=7861。
• 回复为空，或出现和 history 有关的 TypeError：聊天函数的参数必须是 (message, history) 这个顺序，界面也要设 type="messages"。
• AuthenticationError: Incorrect API key provided：密钥缺失、首尾有空格或换行，或者 .env 没有加载。先打印 len(os.getenv('OPENAI_API_KEY'))，改好文件，再重启笔记本。

Takeaways要点回顾

• A UI is a wrapper around a function.
• ChatInterface gives you a chatbot in about ten lines.
• Models are stateless: rebuild the messages from the history every turn.
• Clean history items down to role and content.
• yield streams the words as they arrive.
• The system message is the product's personality.
• Injecting extra context for one turn is cheap and powerful.
• share=True makes your code reachable by anyone with the link.

• 界面是函数外面的一层包装。
• ChatInterface 大约十行代码就能给你一个聊天机器人。
• 模型无状态：每一轮都要从历史重建 messages。
• 把历史条目清理成只有 role 和 content。
• yield 让文字边到边显示。
• system 消息就是产品的性格。
• 为单轮注入额外背景，又便宜又好用。
• share=True 会让拿到链接的人都能接触到你的代码。
