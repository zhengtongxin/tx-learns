Project: a stall brochure maker项目：摊位宣传册生成器

You will chain two model calls so that a shop's website turns into a short brochure · ~25 min · hands-on你会把两次模型调用串起来，让一家店的网站变成一份简短的宣传册 · 约 25 分钟 · 动手实践

Where we left off上回讲到

Last time the helper could follow a chat by resending it, but every answer came from a single call. Today it fails when Uncle Raj's board has dozens of notices and only a few matter this month. We fix it by chaining two calls: one picks, the next writes.

上回助手靠重发对话能接住追问，但每个回答都只来自一次调用。今天它的毛病是 Raj 叔叔的公告板上有几十条通知，这个月只有几条重要。解决办法是串起两次调用：先挑，再写。

Side case支线案例

Ah Boy sells second-hand gadgets online and has a website, but nothing short to hand to a new customer or a job seeker. Wei Jie offers to build a brochure maker: give it a name and a web address, get back one page. It is Wei Jie's first time chaining more than one model call, and the first small taste of an agentic pattern. The brochure maker is a side case: its pick-then-write chain is how the helper will choose which notices to announce.

Ah Boy 在网上卖二手数码产品，有个网站，却没有一份可以递给新顾客或求职者的简短介绍。Wei Jie 提出做一个宣传册生成器：给它店名和网址，就得到一页纸。这是 Wei Jie 第一次把不止一次模型调用串起来，也是智能体模式的第一次小小尝试。 宣传册生成器是支线案例：它“先挑后写”的链条，就是助手挑选该播哪些通知的方法。

Step 1 · A summariser for one page第 1 步 · 只总结一个页面

Learn先学

Start small: one page in, one summary out. A system prompt sets the task and tone. A user prompt carries the page text. First a helper fetches the page and strips it to plain text (remove scripts, styles and images). Pages that need JavaScript to draw themselves come back nearly empty this way, and some sites block scrapers with a 403. That is a limit of this simple helper, not of the model.

先做最小的：一个页面进，一份摘要出。system 提示词定任务和语气，user 提示词装页面文字。先用一个辅助函数抓取页面，把它剥成纯文字（去掉脚本、样式和图片）。靠 JavaScript 才能画出内容的页面，用这个办法抓回来几乎是空的，有些网站还会用 403 拒绝爬取。这是这个简单函数的局限，不是模型的问题。

import requests from bs4 import BeautifulSoup from openai import OpenAI client = OpenAI() def page_text(url): soup = BeautifulSoup(requests.get(url, timeout=10).text, "html.parser") for junk in soup(["script", "style", "img"]): junk.decompose() return soup.get_text(separator="\n", strip=True) def ask(system, user): reply = client.chat.completions.create(model="gpt-5-mini", messages=[ {"role": "system", "content": system}, {"role": "user", "content": user}]) return reply.choices[0].message.content print(ask("Summarise this shop page in three lines.", page_text("https://example.com")))

Step 2 · Let the model choose the links第 2 步 · 让模型挑出有用的链接

Learn先学

A brochure needs the About and Careers pages, not the Privacy page. That is hard to write as rules and easy for a model. So call 1 gets the links on the landing page and returns JSON only. Show one example in the prompt (one-shot prompting) so the model copies the shape. Ask for JSON mode, then json.loads the reply, because it arrives as a string, not a Python dict.

一份宣传册需要“关于我们”和“招聘”页，不需要“隐私”页。这很难写成规则，对模型却很简单。所以第 1 次调用拿到首页上的链接，只返回 JSON。在提示词里给一个例子（单样本提示），让模型照着它的格式写。开启 JSON 模式，再用 json.loads 解析，因为回来的是字符串，不是 Python 字典。

import json from urllib.parse import urljoin def all_links(url): soup = BeautifulSoup(requests.get(url, timeout=10).text, "html.parser") return [urljoin(url, a["href"]) for a in soup.find_all("a", href=True)] link_system = """Pick the links a customer or job seeker would want. Skip terms, privacy and mailto. Reply as JSON like: {"links": [{"type": "about page", "url": "https://shop.example/about"}]}""" def pick_links(url, links): reply = client.chat.completions.create(model="gpt-5-mini", messages=[ {"role": "system", "content": link_system}, {"role": "user", "content": f"Site: {url}\nLinks:\n" + "\n".join(links)}], response_format={"type": "json_object"}) return json.loads(reply.choices[0].message.content)["links"]

Step 3 · Gather the pages and write the brochure第 3 步 · 收集页面，写宣传册

Learn先学

Call 2 needs the text of the landing page plus every page call 1 picked. Join them under headings, then cut the combined text to a fixed length so the call stays cheap and inside the context window. A second system prompt asks for a short markdown brochure. Change one sentence of that prompt, say “formal” to “funny”, and the tone changes. Tone is just prompt.

第 2 次调用需要首页文字，加上第 1 次挑出的每个页面。把它们放在小标题下拼起来，再把总文字截到固定长度，这样调用既便宜又不超出上下文窗口。第二个 system 提示词要求写一份简短的 markdown 宣传册。把其中一句从“正式”改成“搞笑”，语气就变了。语气不过是提示词。

brochure_system = "Write a short brochure in markdown for customers and job seekers. Include culture, customers and careers if present. Tone: warm and plain." def build_material(url): parts = ["Landing page:\n" + page_text(url)] for link in pick_links(url, all_links(url)): parts.append("Link: " + link["type"] + "\n" + page_text(link["url"])) return "\n\n".join(parts)[:5000] def brochure(url): return ask(brochure_system, build_material(url))

Which job belongs to the model, and which to plain code?

哪些活交给模型，哪些交给普通代码？

Step 4 · Stream the answer第 4 步 · 把回答流式显示

Learn先学

A long brochure can take several seconds, and a blank screen feels broken. Pass stream=True and the reply comes in small chunks. Add each chunk's delta to the text so far and redraw. It is the same call, but the reader sees words straight away. It does not make the model faster, it just stops the waiting from feeling like nothing.

长的宣传册可能要好几秒，空白的屏幕让人觉得坏了。传入 stream=True，回复就会一小块一小块地到来。把每块的 delta 加到已有文字后面，再重画一次。调用本身没变，读的人却立刻看到字。它不会让模型变快，只是让等待不再像什么都没发生。

def brochure_stream(url): stream = client.chat.completions.create(model="gpt-5-mini", stream=True, messages=[ {"role": "system", "content": brochure_system}, {"role": "user", "content": build_material(url)}]) text = "" for chunk in stream: text += chunk.choices[0].delta.content or "" yield text for so_far in brochure_stream("https://example.com"): print(so_far[-40:])
What I got wrong我搞错的地方I pasted a whole website into one prompt and hit the length limit. Choosing the pages first, then cutting the text, fixed it. I also forgot the link list came back as a JSON string until I added json.loads.我把整个网站塞进一个提示词，撞上了长度上限。先挑页面、再截断文字，问题就解决了。我还忘了链接列表回来的是 JSON 字符串，直到加上 json.loads 才好。

Now make it yours现在把它变成你的

What changed这一课之后Now the helper can read the board, pick the few notices that matter and write one short announcement for Uncle Raj, streamed so the screen is never blank. Choosing first and writing second keeps the announcement short. The next problem is deciding which model should do each call, because a cheap one may be enough for picking and a better one is needed for writing.现在助手能读公告板，挑出几条重要的通知，为 Raj 叔叔写一条简短的公告，并且流式显示，屏幕不会空白。先挑后写，公告才简短。下一个问题是每次调用该用哪个模型：挑选也许用便宜的就够，写作则需要更好的。

Takeaways要点回顾

• Two small calls beat one giant one.
• Let the model make the fuzzy choice (which links). Let code do the plumbing.
• Show one example in the prompt so the reply copies its shape.
• JSON replies arrive as strings: json.loads them.
• Prompts set tone. Change one sentence and the voice changes.
• Cut the input so the call stays cheap and inside the context window.
• Stream the output so the reader sees words straight away.

• 两次小调用胜过一次巨大的调用。
• 模糊的判断（选哪些链接）交给模型，管道活交给代码。
• 在提示词里给一个例子，回复就会照着它的格式。
• JSON 回复是字符串，要用 json.loads 解析。
• 提示词决定语气，改一句话，口吻就变了。
• 截短输入，调用才便宜，也不超出上下文窗口。
• 流式输出，让读的人立刻看到字。
