Step 1 · One class holds the system第 1 步 · 一个类把系统装起来

Learn先学

Wrap everything in a single framework class. It creates each agent once, holds the memory, and exposes one method, run(), that returns the new opportunities. The screen will only ever call run(), so you can swap any agent for a different implementation behind the same method name without touching the screen. Test it from a notebook before any screen exists.

把一切包进一个框架类。它只创建一次每个智能体，持有记忆，并只暴露一个方法 run()，返回新的机会。界面只会调用 run()，所以你可以把任何一个智能体换成别的实现，只要方法名不变，界面就不用改。在做界面之前，先在笔记本里测试它。

# the agents come from the last lesson: scanner, ensemble, messenger, planner class DealSystem: def __init__(self): self.planner = PlannerAgent(ScannerAgent(), build_ensemble(), MessengerAgent(), threshold=50) self.opportunities = [] # kept between runs def run(self): new = self.planner.run(fetch_feed()) self.opportunities.extend(new) return self.opportunities system = DealSystem() print(system.run()) # test it with no screen at all

Step 2 · The screen: a table first第 2 步 · 界面：先做一张表

Learn先学

Build the screen one piece at a time, and start with the dullest: a static table. Use Gradio Blocks with a title and a table of opportunities seen so far: description, price, estimate, discount and link. Selecting a row shows more details. Get this working with a button before adding anything clever.

界面一次做一块，先从最朴素的开始：一张静态表。用 Gradio Blocks，放一个标题和一张到目前为止见到的机会的表：描述、价格、估价、折扣、链接。选中某一行会显示更多细节。先用一个按钮让它跑通，再加花哨的东西。

import gradio as gr def table_rows(): system.run() return [[d.description, d.price, round(est), round(est - d.price), d.url] for d, est in system.opportunities] with gr.Blocks(title="Deal hunter") as screen: gr.Markdown("# Deals found while you sleep") table = gr.Dataframe(headers=["Item", "Price", "Estimate", "Discount", "Link"], interactive=False) gr.Button("Look now").click(table_rows, outputs=table) screen.launch()

Step 3 · A timer that runs while you sleep第 3 步 · 睡觉时也会跑的定时器

Learn先学

Now add a timer that triggers run() every few minutes, so nobody has to press the button. Mind the cost: the scanner and the planner use models on every run, so pick cheap ones and a sensible interval. A timer that fires every ten seconds will spend money all night for nothing.

现在加一个每隔几分钟触发一次 run() 的定时器，不用谁去按按钮。注意成本：扫描员和规划者每次运行都要用模型，所以选便宜的模型，间隔也要合理。每十秒触发一次的定时器，整晚都在白白花钱。

with gr.Blocks(title="Deal hunter") as screen: gr.Markdown("# Deals found while you sleep") table = gr.Dataframe(headers=["Item", "Price", "Estimate", "Discount", "Link"], interactive=False) gr.Button("Look now").click(table_rows, outputs=table) timer = gr.Timer(300) # every five minutes timer.tick(table_rows, outputs=table)

Step 4 · A live log, handed over safely第 4 步 · 实时日志，安全地交给界面

Learn先学

Watching the agents work is half the fun and most of the debugging. Each agent logs a line in its own colour. But the agents run in several threads, and if they all write to the screen at once the lines get interleaved. So the agents drop their lines into a queue, and the screen reads from the queue at its own pace. A queue is safe to share between threads.

看智能体干活既有趣，又是调试的主要手段。每个智能体用自己的颜色记一行日志。但智能体在多个线程里运行，如果它们同时往界面写，行就会交错混乱。所以智能体把日志行丢进一个队列，界面按自己的节奏从队列里读。队列在线程之间共享是安全的。

import queue log_queue = queue.Queue() COLOURS = {"scanner": "#4ea1ff", "ensemble": "#ffb347", "messenger": "#5fd38d", "planner": "#c792ea"} def log(agent, text): log_queue.put(f'<span style="color:{COLOURS[agent]}">[{agent}] {text}</span>') lines = [] def drain_log(): while not log_queue.empty(): lines.append(log_queue.get()) return "<br>".join(lines[-30:]) # inside the Blocks screen: # log_box = gr.HTML() # timer.tick(drain_log, outputs=log_box)

Step 5 · Run it, then watch cost and cold starts第 5 步 · 跑起来，然后盯着成本和冷启动

Learn先学

To test, reset the memory file to just a couple of old deals, start the app and watch new ones appear. The very first run is slow, because the serverless GPU has a cold start, so do not panic. Keep an eye on API spend: scanning and planning use models every run. A 3D plot of the vector store with the current items highlighted is nice to see, but optional: add it last, once everything else works.

测试时，把记忆文件重置成只剩几个旧优惠，启动应用，看新的优惠出现。第一次运行很慢，因为无服务器 GPU 有冷启动，别慌。盯住 API 开销：扫描和规划每次运行都要用模型。把向量库画成 3D 图并高亮当前商品很好看，但可有可无：等其他一切都好了再最后加。

# reset the memory to two old deals, then start import json json.dump(["https://example.com/old-deal-1", "https://example.com/old-deal-2"], open("seen_deals.json", "w")) screen.queue().launch() # first run: expect a cold start, then watch the log panel fill

Takeaways要点回顾

• A system is many small agents, plus memory, plus a loop, plus a screen.
• Wrap the agents in one class with a single run() method.
• Build the screen one piece at a time: table, timer, log, then the optional plot.
• Use a queue to hand log lines from several threads to the screen safely.
• Test each piece alone before connecting it to the next.
• Watch API cost: choose cheap models and a sensible timer.
• Expect a slow first run because of the cold start.

• 系统就是许多小智能体，加记忆，加循环，加界面。
• 把智能体包进一个只有 run() 方法的类。
• 界面一块一块做：表、定时器、日志，最后才是可选的图。
• 用队列把多个线程的日志安全地交给界面。
• 每一块都先单独测试，再接到下一块。
• 盯住 API 成本：选便宜的模型和合理的定时间隔。
• 预期第一次运行会因为冷启动而很慢。
