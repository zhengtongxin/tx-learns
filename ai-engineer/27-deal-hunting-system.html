Step 1 · One class holds the system第 1 步 · 一个类把系统装起来

Learn先学

The system has four agents: a scanner that picks deals out of a feed, an ensemble that estimates a fair price, a messenger that sends a phone alert, and a planner that runs them in order and remembers what it already sent. The real ones need API keys and a rented GPU. The project package below also has a demo mode (DEMO_MODE=1, the default) with stand-in agents and a sample feed: no keys, no GPU, no cost. Wrap everything in one class that creates each agent once, holds the memory and exposes one method, run(), returning the new opportunities. The screen only ever calls run(), so any agent can be swapped without touching it. Test it with no screen first.

系统有四个智能体：扫描员从列表里挑出优惠，集成估价估出合理价格，信使发手机提醒，规划者按顺序调用它们，并记住已经发过什么。真实版本需要 API 密钥和租来的 GPU。下面的项目包还带演示模式（DEMO_MODE=1，默认）：用替身智能体和一份示例列表，不要密钥、不要 GPU、不花钱。把一切包进一个类：它只创建一次每个智能体，持有记忆，只暴露一个方法 run()，返回新的机会。界面只会调用 run()，所以换任何智能体都不用改界面。先不开界面直接测试。

# the agents come from the last lesson: scanner, ensemble, messenger, planner # build_ensemble() and fetch_feed() are small helpers of yours: one assembles the three # guessers into the ensemble, the other downloads the current deals feed as text class DealSystem: def __init__(self): self.planner = PlannerAgent(ScannerAgent(), build_ensemble(), MessengerAgent(), threshold=50) self.opportunities = [] # kept between runs def run(self): new = self.planner.run(fetch_feed()) self.opportunities.extend(new) return self.opportunities system = DealSystem() print(system.run()) # test it with no screen at all
[(Deal(description='Used phone, 128 GB ...', price=95.0, url='https://...'), 162.0)] # (deal, estimate) pairs

Step 2 · A table, then a timer第 2 步 · 先做表，再加定时器

Learn先学

Build the screen one piece at a time. First a Gradio table of opportunities (description, price, estimate, discount, link) with a button. Once that works, add a timer that calls run() every few minutes. Mind the cost: every run uses models, so pick cheap ones and a sensible interval.

界面一块一块做。先用 Gradio 做一张机会表（描述、价格、估价、折扣、链接）加一个按钮。跑通后，再加一个每隔几分钟调用一次 run() 的定时器。注意成本：每次运行都要用模型，所以选便宜的模型和合理的间隔。

import gradio as gr # same file as Step 1, below the line system = DealSystem() def table_rows(): system.run() return [[d.description, d.price, round(est), round(est - d.price), d.url] # discount = estimate minus price, in dollars for d, est in system.opportunities] with gr.Blocks(title="Deal hunter") as screen: gr.Markdown("# Deals found while you sleep") table = gr.Dataframe(headers=["Item", "Price", "Estimate", "Discount", "Link"], interactive=False) gr.Button("Look now").click(table_rows, outputs=table) timer = gr.Timer(300) # every five minutes timer.tick(table_rows, outputs=table) screen.queue().launch() # start the screen; open the address it prints

Step 3 · A live log, handed over safely第 3 步 · 实时日志，安全地交给界面

Learn先学

Each agent logs a line in its own colour, but agents run in several threads, and lines written straight to the screen interleave. So agents drop lines into a queue (safe to share between threads) and the screen reads it at its own pace.

每个智能体用自己的颜色记一行日志，但智能体在多个线程里运行，直接往界面写，行会交错。所以智能体把日志行丢进队列（线程之间共享是安全的），界面按自己的节奏读。

import queue, html log_queue = queue.Queue() COLOURS = {"scanner": "#4ea1ff", "ensemble": "#ffb347", "messenger": "#5fd38d", "planner": "#c792ea"} def log(agent, text): # each agent calls this where it used to print, e.g. log("scanner", "5 deals found") log_queue.put(f'<span style="color:{COLOURS[agent]}">[{agent}] {html.escape(text)}</span>') # listing text is untrusted: escape it lines = [] def drain_log(): while not log_queue.empty(): lines.append(log_queue.get()) return "<br>".join(lines[-30:]) # inside the Blocks screen: # log_box = gr.HTML() # timer.tick(drain_log, outputs=log_box)

Now make it yours现在把它变成你的

Takeaways要点回顾

• A system is small agents, plus memory, plus a loop, plus a screen.
• Wrap the agents in one class with a single run().
• Build the screen piece by piece: table, timer, log.
• Use a queue to pass log lines between threads; watch API cost and expect a slow first run.

• 系统就是小智能体，加记忆，加循环，加界面。
• 把智能体包进一个只有 run() 的类。
• 界面一块一块做：表、定时器、日志。
• 用队列在线程之间传日志行；盯住 API 成本，并预期第一次运行会很慢。
