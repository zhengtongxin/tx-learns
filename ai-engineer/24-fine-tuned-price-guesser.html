Fine-tuned price guesser微调价格估算器

You will build a small tuned model that guesses prices and test it honestly against the alternatives · ~30 min · hands-on你会做出一个会估价的小型微调模型，并和其他方案做一次诚实的比较 · 约 30 分钟 · 动手课

Step 1 · Prepare the data, split it once第 1 步 · 准备数据，只切分一次

Learn先学

Each example is a prompt ending in "Price is $" plus a completion that is just the number. Cut long descriptions at a token limit. Split into train, validation and test once, save them to the hub, and never touch the test set again.

每个例子是以 “Price is $” 结尾的提示，加上只有数字的回答。长描述按 token 上限截断。把数据切成训练、验证、测试三份，只切一次，存到 hub，之后再也不碰测试集。

import random from datasets import Dataset, DatasetDict # all_tags: your list of {"description", "price"}; shorten() cuts text at a token limit def to_example(tag): text = shorten(tag["description"], max_tokens=160) return {"prompt": f"{text}\nPrice is $", "completion": str(round(tag["price"]))} rows = [to_example(t) for t in all_tags] random.Random(42).shuffle(rows) # shuffle once with a fixed seed, so the split is repeatable sets = DatasetDict({ "train": Dataset.from_list(rows[:20000]), "validation": Dataset.from_list(rows[20000:21000]), "test": Dataset.from_list(rows[21000:22000]), # never trained on, never tuned on }) sets.push_to_hub("your-hub-name/price-tags")

Step 3 · Guess a price第 3 步 · 估价

Learn先学

Load the base plus the adapter, give it the prompt ending in "Price is $", and read the probabilities of the next token, where the number starts. Smoother than the single top token: take the few most likely number tokens and average them, weighted by probability. If no number token appears, fall back to the training average so evaluate never crashes.

加载底座和附加件，给它以 “Price is $” 结尾的提示，读下一个 token（数字从这里开始）的概率。比只取第一名更平滑的办法：取最可能的几个数字 token，按概率加权平均。没有数字 token 就退回训练集平均价，这样 evaluate 不会崩。

import torch # model: the 4-bit base with your adapter loaded; tok: its tokenizer (AutoTokenizer, same model name); # average: the average price in the training set def guess_price(prompt): ids = tok(prompt, return_tensors="pt").to(model.device) with torch.no_grad(): logits = model(**ids).logits[0, -1] probs = torch.softmax(logits, dim=-1) top = torch.topk(probs, 5) total, weight = 0.0, 0.0 for p, i in zip(top.values, top.indices): word = tok.decode(i).strip() if word.isdigit(): total += float(word) * float(p) weight += float(p) return total / weight if weight else average # fallback: the training average, never None

Step 4 · Test it fairly第 4 步 · 公平地测试

Learn先学

Use the same harness and the same test set as the earlier lessons, so every guesser is scored in dollars against the same true prices. Add cost per 1,000 guesses and seconds per guess. A tuned 3 to 8 billion weight model trained on tens of thousands of examples can match or beat a frontier model on a narrow task like this, far cheaper per call and fully yours. With a few hundred examples it will not.

用和前面几课同样的流程和测试集，让每个预测器都按美元对照同样的真实价格打分。再加上每 1000 次估价的成本和每次的秒数。一个 30 到 80 亿权重、用几万条例子训练的微调模型，在这种窄任务上可以追平甚至超过大型云端模型，每次调用便宜得多，而且完全属于你。只有几百条例子就做不到。

Takeaways要点回顾

• Split train, validation and test once; never touch the test set.
• Examples are a prompt ending in "Price is $" and a short completion.
• Try a tiny subset first, then the full run, and push the adapter with a run name.
• Score every contender on the same test set; a tuned small model with enough data on a narrow task can be cheap, fast and good.

• 训练、验证、测试只切分一次，不碰测试集。
• 例子是以 “Price is $” 结尾的提示，加一个短回答。
• 先试很小的子集，再跑完整训练，并用运行名字推送附加件。
• 每个参赛方案都用同一份测试集打分；窄任务加足够数据，小的微调模型可以又便宜、又快、又好。
