Step 1 · Prepare the data, split it once第 1 步 · 准备数据，只切分一次

Learn先学

Each example becomes a prompt that ends with "Price is $" and a completion that is just the number. Cut long descriptions at a token limit so every prompt fits. Then split into train, validation and test once, save the three sets to the hub, and never touch the test set again. Everything later depends on this wall staying up.

每个例子变成一个以 “Price is $” 结尾的提示，加上只有数字的回答。长描述按 token 上限截断，让每条提示都装得下。然后把数据切成训练、验证、测试三份，只切一次，把三份都存到 hub，之后再也不碰测试集。后面的一切都靠这堵墙不倒。

import random from datasets import Dataset, DatasetDict # all_tags: your list of {"description", "price"}; shorten() cuts text at a token limit def to_example(tag): text = shorten(tag["description"], max_tokens=160) return {"prompt": f"{text}\nPrice is $", "completion": str(round(tag["price"]))} rows = [to_example(t) for t in all_tags] random.Random(42).shuffle(rows) # shuffle once with a fixed seed, so the split is repeatable sets = DatasetDict({ "train": Dataset.from_list(rows[:20000]), "validation": Dataset.from_list(rows[20000:21000]), "test": Dataset.from_list(rows[21000:22000]), # never trained on, never tuned on }) sets.push_to_hub("your-hub-name/price-tags")

Step 3 · Guess a price, and smooth it out第 3 步 · 估价，并让结果更平滑

Learn先学

To guess, load the base plus the adapter, give it the prompt that ends in "Price is $", and look at the model's probabilities for the very next token, which is where the number starts. Taking the single most likely token (greedy) is repeatable. Here is a nice trick: instead of trusting only the top token, take the probabilities of the few most likely number tokens and compute a weighted average. That gives a smoother estimate. It works when the model's tokenizer gives a whole number as one token. If no number token shows up, the function falls back to the training average, so evaluate never crashes; a fuller version would read the number digit by digit.

要估价，就加载底座和附加件，给它以 “Price is $” 结尾的提示，看模型对下一个 token（数字从这里开始）的概率。只取最可能的那个 token（贪心）是可重复的。有个好用的小技巧：不要只信第一名的 token，而是取最可能的几个数字 token 的概率，算一个加权平均，估计会更平滑。这在分词器把整个数字当成一个 token 时有效。如果没有出现数字 token，函数就退回训练集平均价，这样 evaluate 不会崩；更完整的做法是一位一位地读数字。

import torch def guess_price(prompt): ids = tok(prompt, return_tensors="pt").to(model.device) with torch.no_grad(): logits = model(**ids).logits[0, -1] probs = torch.softmax(logits, dim=-1) top = torch.topk(probs, 5) total, weight = 0.0, 0.0 for p, i in zip(top.values, top.indices): word = tok.decode(i).strip() if word.isdigit(): total += float(word) * float(p) weight += float(p) return total / weight if weight else average # fallback: the training average, never None

Step 4 · Test it fairly第 4 步 · 公平地测试

Use the same evaluation harness and the same test set as the earlier projects: the average, the linear and forest baselines, and the big frontier model. Compute the average error in dollars over the test set for each. Fairness is the whole point, so the test items and the scoring rule must be identical for everyone. In plain words用大白话说

Words this lesson uses, in one line each.
• Train, validation, test: three separate piles: learn from the first, tune with the second, judge once on the third.
• Push to the hub: upload the saved adapter to a model website so any notebook can load it later.
• Logits: the raw scores for the next token; the code turns them into a price.

这一课用到的词，每个一句话。
• 训练、验证、测试：三份互不相同的数据：用第一份学习，用第二份调整，用第三份只做一次评判。
• 推送到 hub：把保存好的适配器上传到模型网站，之后任何笔记本都能加载。
• logits：下一个词元的原始分数，代码再把它们换算成价格。

Common errors常见报错

• The tuned model prints text instead of a price. The prompt ends differently from training. Use the exact same prompt shape, ending with Price is $.
• HfHubHTTPError: 401 when pushing. You are not logged in, or the token cannot write. Log in again with a write token.
• torch.OutOfMemoryError: CUDA out of memory. The model or batch is too big for the GPU. Load it in 4-bit, lower the batch size, or pick a smaller model.

• 微调后的模型打印出一段文字而不是价格：提示的结尾和训练时不同。用完全相同的提示格式，以 Price is $ 结尾。
• 推送时报 HfHubHTTPError: 401：没登录，或令牌没有写权限。用有写权限的令牌重新登录。
• torch.OutOfMemoryError: CUDA out of memory：模型或批量对显卡来说太大。改用 4-bit 加载、调小批量，或换更小的模型。

Takeaways要点回顾

• Build the train, validation and test split once, and never touch the test set.
• Examples are a prompt ending in "Price is $" and a short completion.
• Try a tiny subset first, then the full run, and push the adapter with a run name.
• Guess with greedy generation, and optionally average the top number candidates.
• Use the same harness and test set for every contender.
• A tuned small model on a narrow task with enough data can be cheap, fast and good.
• With only a few hundred examples, do not expect it to win.

• 训练、验证、测试只切分一次，之后不碰测试集。
• 例子是以 “Price is $” 结尾的提示，加一个短回答。
• 先试很小的子集，再跑完整训练，并用运行名字推送附加件。
• 用贪心生成来估价，还可以对最可能的几个数字候选取平均。
• 每个参赛方案都用同一套流程和同一份测试集。
• 窄任务加足够数据，小的微调模型可以又便宜、又快、又好。
• 只有几百条例子的话，别指望它能赢。
