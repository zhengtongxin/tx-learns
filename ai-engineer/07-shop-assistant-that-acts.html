Step 1 · The data and the tools第 1 步 · 数据和工具

Learn先学

Shape: user text, then the chat loop (model plus database tools), then reply text, a picture of the place and speech, on one screen. Build it in small pieces. Start with a short, accurate system message that allows “I don’t know”, and a SQLite table of trip prices. Gradio, the screen library, runs your function on a different thread (a separate line of work inside the program) from the one that opened the database. SQLite refuses that unless you open it with check_same_thread=False.

形状：用户文字，然后聊天循环（模型加数据库工具），然后是回复文字、地点图片和语音，全在一个界面里。拆成小块来做。先写简短准确、允许说“我不知道”的 system 消息，再准备一张 SQLite 的行程价格表。界面库 Gradio 会在另一个线程（程序里另一条并行的工作线）上运行你的函数，而不是打开数据库的那个线程。SQLite 默认不允许这样，所以要用 check_same_thread=False 打开。

system_message = """You are the desk assistant for weekend coach trips. Be short, polite and accurate. Use the tools for prices. If you are not sure, say you do not know.""" import sqlite3 db = sqlite3.connect("trips.db", check_same_thread=False) db.execute("CREATE TABLE IF NOT EXISTS prices (place TEXT PRIMARY KEY, price REAL)") db.execute("INSERT OR IGNORE INTO prices VALUES ('sentosa', 48), ('mandai', 62), ('changi', 55)") db.commit() looked_up = [] # places the tools touched during this question def get_price(place): looked_up.append(place) row = db.execute("SELECT price FROM prices WHERE place = ?", (place.lower(),)).fetchone() return f"{place}: S${row[0]}" if row else f"{place}: no such trip" def set_price(place, price): db.execute("INSERT OR REPLACE INTO prices VALUES (?, ?)", (place.lower(), price)) db.commit() return f"{place} is now S${price}"

Step 2 · The tools and the chat loop第 2 步 · 工具和聊天循环

Learn先学

Describe each function, then run the loop from the last lesson: ask, run what was requested, answer, repeat. A customer may ask about two trips in one sentence, so handle many calls. A dispatch table maps tool name to function. A description is a hint, not a lock: the real guard is keeping set_price out of the customer's tool list (it stays here only for testing).

描述每个函数，再跑上一课的循环：请求、执行、回答、重复。顾客可能一句话问两个行程，所以要处理多个调用。dispatch 表把工具名映射到函数。描述只是提示，不是锁：真正的防线是把 set_price 从顾客的工具列表里拿掉（这里留着只为测试）。

import json from openai import OpenAI client = OpenAI() MODEL = "gpt-5-mini" def make_tool(name, text, props): return {"type": "function", "function": {"name": name, "description": text, "parameters": {"type": "object", "properties": props, "required": list(props)}}} tools = [make_tool("get_price", "Get the coach trip price for a place.", {"place": {"type": "string"}}), make_tool("set_price", "Change a trip price. Staff only.", {"place": {"type": "string"}, "price": {"type": "number"}})] dispatch = {"get_price": get_price, "set_price": set_price} def run_chat(history): messages = [{"role": "system", "content": system_message}] + history reply = client.chat.completions.create(model=MODEL, messages=messages, tools=tools) while reply.choices[0].finish_reason == "tool_calls": asked = reply.choices[0].message messages.append(asked) for call in asked.tool_calls: print("tool call:", call.function.name, call.function.arguments) result = dispatch[call.function.name](**json.loads(call.function.arguments)) messages.append({"role": "tool", "tool_call_id": call.id, "content": result}) reply = client.chat.completions.create(model=MODEL, messages=messages, tools=tools) return reply.choices[0].message.content

Step 3 · Picture, voice and the screen第 3 步 · 图片、声音和界面

Learn先学

Draw a picture only when a tool actually looked up a place (looked_up): images cost money and seconds. Voice is cheap enough for every reply. In gr.Blocks, send runs two callbacks: the first only adds the user's message, the second calls the model and updates chat, image and audio. One callback doing both would let two writers overwrite the same history.

只有工具真的查过地点（looked_up）才画图：图片花钱又要几秒。语音便宜，每条回复都读也行。在 gr.Blocks 里，发送按顺序运行两个回调：第一个只加入用户消息，第二个调用模型并更新聊天、图片和音频。一个回调包办两件事，会让两个写入者互相覆盖同一份历史。

# same file as the two boxes above, in this order: client, the database and chat() are already defined import base64, gradio as gr from io import BytesIO from PIL import Image def draw(place): result = client.images.generate(model="gpt-image-1", size="1024x1024", prompt=f"A bright pop-art poster of {place}, a weekend coach trip destination") return Image.open(BytesIO(base64.b64decode(result.data[0].b64_json))) def speak(text): audio = client.audio.speech.create(model="gpt-4o-mini-tts", voice="alloy", input=text) with open("reply.mp3", "wb") as f: f.write(audio.content) return "reply.mp3" def answer_everything(history): looked_up.clear() text = run_chat(history) picture = draw(looked_up[-1]) if looked_up else None return text, picture, speak(text) with gr.Blocks() as screen: with gr.Row(): chatbot = gr.Chatbot(type="messages", height=400) picture = gr.Image(height=400) audio = gr.Audio(autoplay=True) box = gr.Textbox(label="Ask about a coach trip") def add_user(text, history): return "", history + [{"role": "user", "content": text}] def answer(history): clean = [{"role": h["role"], "content": h["content"]} for h in history] text, pic, voice = answer_everything(clean) return history + [{"role": "assistant", "content": text}], pic, voice box.submit(add_user, [box, chatbot], [box, chatbot]).then(answer, chatbot, [chatbot, picture, audio]) screen.launch()

Common errors常见报错

• A loop that never ends or repeats one tool. Cap it: for _ in range(5): instead of while.
• KeyError: 'place'. The model used other argument names. Name the exact parameters in the tool description.

• 循环不停或一直重复同一个工具：加上限，用 for _ in range(5): 代替 while。
• KeyError: 'place'：模型用了别的参数名。在工具描述里写清准确的参数名。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Chat model plus tools plus media models makes an assistant that does things.
• Build in small, testable pieces; print tool calls while testing.
• Handle many and chained tool calls with a loop.
• Generate an image only when a tool looked something up.
• Split “add the user message” from “get the answer” in the screen.

• 聊天模型加工具，再加媒体模型，就成了会动手的助手。
• 拆成小而可测试的部分；测试时打印工具调用。
• 用循环处理多个、连续的工具调用。
• 只有工具真的查过东西，才生成图片。
• 界面里把“加入用户消息”和“得到回答”拆开。
