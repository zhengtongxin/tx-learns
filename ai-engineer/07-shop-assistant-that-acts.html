Step 1 · The brief, the voice of the desk and the data第 1 步 · 需求、柜台的口吻和数据

Learn先学

The finished shape is: user text, then the chat loop (model plus database tools), then the reply text, then a picture of the place and speech of the reply, all on one screen. Build it in small, testable pieces. Start with the system message: short, polite, accurate, and willing to say “I don't know”. Then the data: a SQLite table of trip prices.

成品的形状是：用户文字，然后聊天循环（模型加数据库工具），然后回复文字，再然后是地点图片和回复的语音，全部放在一个界面里。把它拆成小而可测试的部分来做。先写 system 消息：简短、有礼貌、准确，不确定就说“我不知道”。再准备数据：一张 SQLite 的旅游价格表。

system_message = """You are the desk assistant for Uncle Raj's weekend coach trips. Be short, polite and accurate. Use the tools for prices. If you are not sure, say you do not know.""" import sqlite3 db = sqlite3.connect("trips.db") db.execute("CREATE TABLE IF NOT EXISTS prices (place TEXT PRIMARY KEY, price REAL)") db.execute("INSERT OR IGNORE INTO prices VALUES ('sentosa', 48), ('mandai', 62), ('changi', 55)") db.commit() looked_up = [] # places the tools touched during this question def get_price(place): looked_up.append(place) row = db.execute("SELECT price FROM prices WHERE place = ?", (place.lower(),)).fetchone() return f"{place}: S${row[0]}" if row else f"{place}: no such trip" def set_price(place, price): db.execute("INSERT OR REPLACE INTO prices VALUES (?, ?)", (place.lower(), price)) db.commit() return f"{place} is now S${price}"

Step 2 · The tools and the chat loop第 2 步 · 工具和聊天循环

Learn先学

Describe each function to the model and run the loop from the last lesson: ask, run what was requested, answer, and repeat while the model keeps asking. A customer may ask about two trips in one sentence, so handle many calls and chained calls. Print each call while testing so you can see what the model asked for. A dispatch table maps the tool name to the function.

把每个函数向模型描述一遍，再跑上一课的循环：请求、执行被请求的调用、回答，模型继续请求就继续。顾客可能一句话问两个行程，所以要处理多个调用和连续调用。测试时把每个调用打印出来，看看模型到底请求了什么。用一张 dispatch 表把工具名映射到函数。

import json from openai import OpenAI client = OpenAI() MODEL = "gpt-5-mini" def make_tool(name, text, props): return {"type": "function", "function": {"name": name, "description": text, "parameters": {"type": "object", "properties": props, "required": list(props)}}} tools = [make_tool("get_price", "Get the coach trip price for a place.", {"place": {"type": "string"}}), make_tool("set_price", "Change a trip price. Staff only.", {"place": {"type": "string"}, "price": {"type": "number"}})] dispatch = {"get_price": get_price, "set_price": set_price} def run_chat(history): messages = [{"role": "system", "content": system_message}] + history reply = client.chat.completions.create(model=MODEL, messages=messages, tools=tools) while reply.choices[0].finish_reason == "tool_calls": asked = reply.choices[0].message messages.append(asked) for call in asked.tool_calls: print("tool call:", call.function.name, call.function.arguments) result = dispatch[call.function.name](**json.loads(call.function.arguments)) messages.append({"role": "tool", "tool_call_id": call.id, "content": result}) reply = client.chat.completions.create(model=MODEL, messages=messages, tools=tools) return reply.choices[0].message.content

Step 3 · A picture and a voice, only when needed第 3 步 · 图片和声音，需要时才用

Learn先学

Add the two helpers: one draws a pop-art style picture of a place, one turns the reply into audio. The trap is calling them on every message. A picture costs money and takes seconds, so draw only when a tool actually looked up a place. That is what looked_up is for. The voice is cheap enough to run on every reply.

加入两个辅助函数：一个画地点的波普风格图片，一个把回复变成音频。陷阱是每条消息都调用它们。图片花钱又要几秒，所以只有工具真的查过某个地点才画。这就是 looked_up 的用处。语音便宜，每条回复都读也行。

import base64 from io import BytesIO from PIL import Image def draw(place): result = client.images.generate(model="gpt-image-1", size="1024x1024", prompt=f"A bright pop-art poster of {place}, a weekend coach trip destination") return Image.open(BytesIO(base64.b64decode(result.data[0].b64_json))) def speak(text): audio = client.audio.speech.create(model="gpt-4o-mini-tts", voice="alloy", input=text) with open("reply.mp3", "wb") as f: f.write(audio.content) return "reply.mp3" def answer_everything(history): looked_up.clear() text = run_chat(history) picture = draw(looked_up[-1]) if looked_up else None return text, picture, speak(text)

Step 4 · The screen, with two callbacks第 4 步 · 界面，用两个回调

Learn先学

Use gr.Blocks: a row with the chatbot on the left and an image panel on the right, a text box underneath and an audio player for the reply. The send action runs two callbacks in order. The first only puts the user's message into the chat, so it shows up straight away. The second calls the model and then updates the chat, the image and the audio. Wei Jie first tried one callback that did everything, and two callbacks fought over the same history list.

用 gr.Blocks：一行里左边是聊天框、右边是图片面板，下面是文本框，再加一个播放回复的音频播放器。发送动作按顺序运行两个回调。第一个只把用户的消息放进聊天，所以马上就能看到。第二个调用模型，然后更新聊天、图片和音频。Wei Jie 起初用一个回调包办一切，结果两个回调抢着改同一个历史列表。

import gradio as gr with gr.Blocks() as screen: with gr.Row(): chatbot = gr.Chatbot(type="messages", height=400) picture = gr.Image(height=400) audio = gr.Audio(autoplay=True) box = gr.Textbox(label="Ask about a coach trip") def add_user(text, history): return "", history + [{"role": "user", "content": text}] def answer(history): clean = [{"role": h["role"], "content": h["content"]} for h in history] text, pic, voice = answer_everything(clean) return history + [{"role": "assistant", "content": text}], pic, voice box.submit(add_user, [box, chatbot], [box, chatbot]).then(answer, chatbot, [chatbot, picture, audio]) screen.launch()

What I got wrong我搞错的地方I generated an image on every message. It cost money and was slow, so now it only happens when a tool looked up a place. I also had two callbacks fighting over the same history list, until I split “add the user message” from “get the answer”.我曾经每条消息都生成一张图，又花钱又慢，现在只在工具查过地点时才生成。我还让两个回调抢同一个历史列表，直到把“加入用户消息”和“得到回答”拆开。

Common errors常见报错

• The loop never ends or calls the same tool again and again. There is no step cap. Stop after a few rounds and return what you have.
• KeyError: 'place'. The model sent different argument names than the function expects. Make the tool description name the exact parameters.
• AuthenticationError: Incorrect API key provided. The key is missing, has a stray space or newline, or the .env file was not loaded. Print len(os.getenv('OPENAI_API_KEY')), fix the file, then restart the notebook.

• 循环不停，或一直重复调用同一个工具：没设步数上限。几轮之后就停，返回已有的结果。
• KeyError: 'place'：模型传来的参数名和函数要的不一致。在工具描述里写清准确的参数名。
• AuthenticationError: Incorrect API key provided：密钥缺失、首尾有空格或换行，或者 .env 没有加载。先打印 len(os.getenv('OPENAI_API_KEY'))，改好文件，再重启笔记本。

Takeaways要点回顾

• Chat model plus tools plus other media models makes an assistant that does things.
• Build it in small, testable pieces, one at a time.
• Handle many and chained tool calls with a loop.
• Print tool calls while testing.
• Call image generation only when a tool actually looked something up.
• Split “add the user message” from “get the answer” in the screen.
• Cost control matters: images and long histories add up.
• This is the bridge into agents.

• 聊天模型加工具，再加其他媒体模型，就成了会动手的助手。
• 拆成小而可测试的部分，一块一块地做。
• 用循环处理多个、连续的工具调用。
• 测试时把工具调用打印出来。
• 只有工具真的查过东西，才调用图片生成。
• 界面里把“加入用户消息”和“得到回答”拆开。
• 成本要控制：图片和很长的历史会越积越多。
