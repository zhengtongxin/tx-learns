Benchmarks and leaderboards基准与排行榜

You will learn to read a leaderboard as a shortlist, then settle the choice with your own small test · ~15 min · concept你会学会把排行榜当成候选名单来读，再用自己的小测试定下选择 · 约 15 分钟 · 概念课

Step 1 · What the charts measure第 1 步 · 图表到底量了什么

Learn先学

A benchmark is a fixed set of questions with known answers (knowledge, coding, instructions, long text, tools). Arenas let people vote between two anonymous answers and compute an Elo-style rating. Beside quality sit the practical columns: price per million tokens, speed, context size and licence.

基准是一套答案已知的固定题目（知识、编程、指令、长文本、工具）。竞技场让人在两个匿名回答之间投票，再算出类似 Elo 的评分。除了质量，还有实用的几列：每百万 token 价格、速度、上下文大小和许可证。

Step 2 · Why a score can mislead第 2 步 · 为什么分数会误导

Learn先学

• Leakage: the model may have seen the test questions in training.
• Saturation: when everyone scores 95 percent, the test separates no one.
• Style: arena votes reward long, friendly answers as much as correct ones.
• Averages: a model that is top overall can be mediocre at your narrow job.

• 泄漏：模型训练时可能见过测试题。
• 饱和：大家都拿 95% 时，这套题分不出任何人。
• 风格：竞技场投票奖励又长又友好的回答，不只是对的回答。
• 平均数：总分第一的模型，做你那个窄任务可能很普通。

Step 3 · Your own twenty questions第 3 步 · 你自己的二十道题

Learn先学

Shortlist three to five models from public rankings plus price and speed. Write twenty real examples from your own job, each with a known answer. Run every model on them with the identical prompt, and record score, time and cost. Pick the cheapest model that is good enough, not the top of the chart, and re-test every few months. (Needs pip install openai and OPENAI_API_KEY; each call costs a little.)

从公开排名加价格和速度里挑三到五个候选模型。从你自己的工作里写二十个真实例子，每个都有已知答案。用完全相同的提示词让每个模型都跑一遍，记录得分、耗时和成本。选够用的最便宜的模型，而不是图表最上面的，并每隔几个月重测。（需要 pip install openai 和 OPENAI_API_KEY；每次调用都要花一点钱。）

import time from openai import OpenAI client = OpenAI() cases = [("Where is my parcel? It is three days late", "delivery"), ("Can I get a refund for the broken kettle", "refund"), # ... eighteen more real messages with the answer you want ] def run_one(model, message): start = time.time() reply = client.chat.completions.create(model=model, messages=[ {"role": "system", "content": "Reply with one word: delivery, refund or other."}, {"role": "user", "content": message}]) return reply.choices[0].message.content.strip().lower(), time.time() - start candidates = ["gpt-4.1", "gpt-4.1-mini", "gpt-4.1-nano"] # model names your account can call for model in candidates: right, seconds = 0, 0.0 for message, wanted in cases: got, took = run_one(model, message) right += (got == wanted) seconds += took print(model, f"{right}/{len(cases)}", f"{seconds:.1f}s") # add cost from your usage page

Common errors常见报错

• RateLimitError: 429. Too many calls or no credit. Add a short time.sleep and check billing.
• Scores jump between runs. Use at least 20 cases and compare after .strip().lower().

• RateLimitError: 429：调用太多或没有余额。加一小段 time.sleep，并检查账单。
• 每次跑分数都在变：至少用 20 道题，并在 .strip().lower() 之后再比较。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Benchmarks are a starting list, not a verdict.
• Read the practical columns too: price, speed, context size, licence.
• Scores can be flattered by leakage, saturate, and reward style.
• Test three to five models on twenty real examples with one prompt.
• Pick the cheapest model that is good enough, and re-test every few months.

• 基准是起点名单，不是裁决。
• 也要看实用的几列：价格、速度、上下文大小、许可证。
• 分数可能因泄漏而偏高、会饱和，还奖励风格。
• 用同一份提示词，在二十个真实例子上测三到五个模型。
• 选够用的最便宜的模型，并每隔几个月重测。
