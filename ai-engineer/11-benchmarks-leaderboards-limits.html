Step 1 · What the charts measure第 1 步 · 图表到底量了什么

Learn先学

A benchmark is a fixed set of questions with known answers. There are sets for exam-style knowledge and reasoning, for coding (write a function that passes hidden tests), for following instructions, for recalling facts in long text and for using tools. Arenas work differently: people compare two anonymous answers and vote, and a rating like a chess Elo is computed. Beside the quality columns sit the practical ones: price per million tokens in and out, speed in tokens per second, context size and licence.

基准就是一套答案已知的固定题目。有考试式的知识和推理题、有编程题（写一个能通过隐藏测试的函数）、有指令遵循、有在长文本里找回事实、还有工具使用。竞技场的做法不同：人们比较两个匿名的回答并投票，再算出类似国际象棋 Elo 的评分。除了质量列，还有实用的几列：每百万 token 的输入输出价格、每秒生成 token 的速度、上下文大小和许可证。

Step 2 · Why a score can mislead第 2 步 · 为什么分数会误导

Learn先学

Four traps. Leakage: a model may have seen the test questions while training, so the score flatters it. Saturation: when everyone gets 95 percent the test no longer separates anyone. Style: arena votes reward long, confident, friendly answers as much as correct ones. Averages: a model that is top overall can be mediocre at your narrow job. And models change monthly, so any notes about them age fast.

四个陷阱。泄漏：模型训练时可能见过测试题，分数就偏高。饱和：大家都拿 95% 时，这套题已经分不出高下。风格：竞技场的投票奖励又长、又自信、又友好的回答，不只是对的回答。平均数：总分第一的模型，做你那个窄任务可能很普通。而且模型每月都在变，关于它们的笔记很快就过时。

Step 3 · Your own twenty questions第 3 步 · 你自己的二十道题

Learn先学

First shortlist three to five models from public rankings plus price and speed. Then write twenty real examples from your own job, each with a known good answer. Priya's tip: collect real messages, not invented ones. Run every model on them with the identical prompt, and score by a simple rule, or by another model acting as judge. Record cost and time too. These examples call a paid API: run pip install openai, set OPENAI_API_KEY, and expect each call to cost a small amount.

先从公开排名加上价格和速度里，挑出三到五个候选模型。然后从你自己的工作里写二十个真实例子，每个都有已知的好答案。Priya 的建议：收集真实的留言，别自己编。用完全相同的提示词让每个模型都跑一遍，用简单规则打分，或者让另一个模型当裁判。成本和耗时也要记录。这些例子调用的是付费接口：先运行 pip install openai，设置 OPENAI_API_KEY，每次调用都会花一点钱。

import time from openai import OpenAI client = OpenAI() cases = [("Where is my parcel? It is three days late", "delivery"), ("Can I get a refund for the broken kettle", "refund"), # ... eighteen more real messages with the answer you want ] def run_one(model, message): start = time.time() reply = client.chat.completions.create(model=model, messages=[ {"role": "system", "content": "Reply with one word: delivery, refund or other."}, {"role": "user", "content": message}]) return reply.choices[0].message.content.strip().lower(), time.time() - start

Step 4 · The table, and the cheapest good-enough第 4 步 · 表格，以及最便宜的够用模型

Learn先学

Loop over the shortlist and fill a small table: correct out of the total, seconds, and cost. Then pick the cheapest model that is good enough for the job, not the one at the top of the chart. Test again every few months, because new models keep arriving. A leaderboard gets you the shortlist. Your table gets you the decision.

遍历候选名单，填一张小表：答对几道（共几道）、耗时、成本。然后选对这份工作来说够用的最便宜的模型，而不是图表最上面的那个。每隔几个月再测一次，因为新模型不断出现。排行榜给你候选名单，你的表格才给你决定。

candidates = ["gpt-4.1", "gpt-4.1-mini", "gpt-4.1-nano"] # your shortlist: model names your account can call for model in candidates: right, seconds = 0, 0.0 for message, wanted in cases: got, took = run_one(model, message) right += (got == wanted) seconds += took print(model, f"{right}/{len(cases)}", f"{seconds:.1f}s") # add the cost from your usage page

What I got wrong我搞错的地方I chose a model because it topped one chart, then paid ten times more than needed for a task a small model did equally well. I only found out when I ran my own examples.我因为一个模型在某张图表上排第一就选了它，结果为一个小模型同样能做好的任务多花了十倍的钱。直到我跑了自己的例子才发现。

Common errors常见报错

• RateLimitError: 429. Too many calls in a short time, or the account has no credit. Wait a minute, add a short time.sleep in loops, and check the billing page.
• A score that jumps between runs. The test set is too small or the model answers with extra words. Use at least 20 cases and compare after .strip().lower().
• model_not_found for a name from the leaderboard. A leaderboard name is not always the name the API wants. Check the provider's model list.

• RateLimitError: 429：短时间调用太多，或账户没有余额。等一分钟，循环里加一小段 time.sleep，并检查账单页面。
• 每次跑分数都在变：测试题太少，或模型回答里多了字。至少用 20 道题，并在 .strip().lower() 之后再比较。
• 排行榜上的名字报 model_not_found：榜单上的名字不一定是接口要的名字。查提供商的模型列表。

Now make it yours现在把它变成你的

What changed这一课之后Now the helper's model is picked from a table of score, seconds and cost on Mdm Tan's own twenty messages, not from a leaderboard; the cheapest good-enough one stays. The next problem is a sharper test: a job with an objective score, so a stopwatch rather than opinion can say which model is better.助手的模型现在是看一张表选出来的：在 Tan 太太自己的二十条留言上的得分、用时和费用，而不是看排行榜；够用又最便宜的那个留下。下一个问题是更硬的测试：找一项有客观分数的任务，让秒表而不是看法来说哪个模型更好。

Takeaways要点回顾

• Benchmarks are a starting list, not a verdict.
• Read the practical columns too: price, speed, context size and licence.
• Scores can be flattered by leakage, and saturate when everyone is near the top.
• Arena votes reward style as well as correctness.
• A top overall average can hide a mediocre result on your own job.
• Test three to five models on twenty real examples with the same prompt.
• Pick the cheapest model that is good enough, and re-test every few months.

• 基准是起点名单，不是裁决。
• 也要看实用的几列：价格、速度、上下文大小和许可证。
• 分数可能因泄漏而偏高，大家都接近满分时也会饱和。
• 竞技场投票奖励风格，也奖励正确。
• 总分第一，可能掩盖它在你那份工作上的平庸表现。
• 用同一份提示词，在二十个真实例子上测三到五个模型。
• 选够用的最便宜的模型，并每隔几个月重测。
