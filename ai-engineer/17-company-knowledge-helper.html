Step 1 · Smarter chunks, made once by a model第 1 步 · 更聪明的块，由模型做一次

Learn先学

Cutting every 1000 characters ignores where ideas start and end. Instead, have a model split each document into overlapping chunks, each with a headline, a short summary and the original text. A fixed answer shape (the Pieces class) gives you a clean list back.

每隔 1000 字符切一刀，不管想法在哪里开始和结束。改成让模型把每份文档切成有重叠的块，每块有标题、简短摘要和原文。固定的答案格式（Pieces 类）让你拿回干净的列表。

It is slow, so run it once, in parallel, and save the store.

这很慢，所以只做一次、并行跑，并把库存下来。

# docs (the loaded documents) and embedder come from the earlier lessons on chunks and the retrieval chain import os from concurrent.futures import ThreadPoolExecutor from pydantic import BaseModel from langchain_core.documents import Document from langchain_openai import ChatOpenAI from langchain_chroma import Chroma class Piece(BaseModel): headline: str # a few words likely to match a question summary: str original_text: str class Pieces(BaseModel): pieces: list[Piece] # with_structured_output(Pieces) makes the model answer as a Pieces object (a Pydantic class: named, typed fields), not loose text cutter = ChatOpenAI(model="gpt-4.1-mini", temperature=0).with_structured_output(Pieces) def smart_chunks(doc): plan = ("Split this document into overlapping pieces that each cover one idea. " "For every piece give a headline, a short summary and the original text.\n\n" + doc.page_content) return [Document(page_content=f"{p.headline}\n{p.summary}\n{p.original_text}", metadata={"source": doc.metadata["source"]}) for p in cutter.invoke(plan).pieces] if not os.path.exists("council_db_smart"): # slow step: run once, then reuse with ThreadPoolExecutor(max_workers=4) as pool: groups = list(pool.map(smart_chunks, docs)) store = Chroma.from_documents([c for g in groups for c in g], embedder, persist_directory="council_db_smart") else: store = Chroma(persist_directory="council_db_smart", embedding_function=embedder)

Step 2 · Fetch more, then rerank第 2 步 · 多取一些，再重新排序

Learn先学

A chunk can rank high because it sounds like the question, not because it answers it. Fetch about 20, ask a model to order them by usefulness, and keep the best few.

某一块可能因为听起来像问题而排得很前，其实没回答问题。先取约 20 块，让模型按“多有用”排序，只留最好的几块。

class Order(BaseModel): ranked: list[int] # chunk numbers, best first sorter = ChatOpenAI(model="gpt-4.1-mini", temperature=0).with_structured_output(Order) def rerank(question, chunks, keep=5): listing = "\n\n".join(f"[{i}] {c.page_content}" for i, c in enumerate(chunks)) order = sorter.invoke(f"Question: {question}\n\nPut these chunk numbers in order, " f"most useful for answering first:\n\n{listing}").ranked return [chunks[i] for i in order if 0 <= i < len(chunks)][:keep] candidates = store.similarity_search("Which officer used to drive buses?", k=20) best = rerank("Which officer used to drive buses?", candidates)

Step 3 · Rewrite the question before searching第 3 步 · 搜索之前先改写问题

Learn先学

Follow-ups fail because search sees only "and her manager?". Ask a model to turn the question plus the chat history into one standalone query that names the person. A rewrite can drift, so search with both the original and the rewrite, merge and drop duplicates.

追问失败，是因为搜索只看到“那她的上司呢？”。让模型把问题加聊天记录改写成一句点名那个人、能独立成立的搜索语句。改写可能跑偏，所以原问题和改写都搜，再合并去重。

llm = ChatOpenAI(model="gpt-4.1-mini", temperature=0) def rewrite(question, history): chat = "\n".join(f"{m['role']}: {m['content']}" for m in history) return llm.invoke(f"Chat so far:\n{chat}\n\nTurn the last question into one standalone " f"search query that names every person or thing. Query only.\n\n{question}").content.strip() def fetch(question, history): rewritten = rewrite(question, history) seen, merged = set(), [] for q in (question, rewritten): # keep both: the rewrite may drift for c in store.similarity_search(q, k=20): if c.page_content not in seen: seen.add(c.page_content) merged.append(c) return rerank(rewritten, merged) if USE_RERANK else merged[:10] USE_RERANK = True # set to False to measure what reranking adds

Step 4 · Cite sources, then prove it helped第 4 步 · 标出出处，再证明它有用

Learn先学

Put each chunk's file name in the context and ask the model to list the files it used, so a reader can check. Then re-run the test set from the last lesson through fetch and compare per category.

把每块的文件名放进上下文，并让模型列出用到的文件，读者就能核对。然后用上一课的测试集，通过 fetch 重跑一遍，按类别比较。

def answer(question, history): chunks = fetch(question, history) context = "\n\n".join(f"Source: {c.metadata['source']}\n{c.page_content}" for c in chunks) system = ("Answer using only the context below. " "End with a line starting 'Sources:' listing the file names you used.\n\n" + context) messages = [("system", system)] + [(m["role"], m["content"]) for m in history] messages.append(("user", question)) return llm.invoke(messages).content # prove it: the same test set as before, but through fetch(), scored per category. # tests = [json.loads(line) for line in open("tests.jsonl")]: each has "question", "keywords" and "category" from collections import defaultdict hits, asked = defaultdict(int), defaultdict(int) for t in tests: found = " ".join(c.page_content for c in fetch(t["question"], [])).lower() asked[t["category"]] += 1 hits[t["category"]] += all(k.lower() in found for k in t["keywords"]) for cat in asked: print(f"{cat:12} {hits[cat]}/{asked[cat]}")

Takeaways要点回顾

• Each upgrade fixes one specific failure.
• Model-made chunks carry a headline, a summary and the original text; build them once.
• Fetch many, rerank, keep the best few.
• Rewrite follow-ups, but search with the original too.
• Cite sources, and measure every change with the same test set.

• 每个升级只修一个具体的失败。
• 模型做的块带标题、摘要和原文；只建一次。
• 多取一些，重排序，只留最好的几块。
• 改写追问，但也要用原问题搜。
• 标出出处，每个改动都用同一份测试集衡量。
