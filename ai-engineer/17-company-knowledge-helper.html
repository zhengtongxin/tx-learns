Step 1 · Smarter chunks, made once by a model第 1 步 · 更聪明的块，由模型做一次

Learn先学

Cutting every 1000 characters ignores where ideas begin and end. Instead, ask a model to split each document into overlapping chunks. Each chunk gets a headline (a few words likely to match a question), a short summary and the original text. You name the exact shape of the answer (the Pieces class below), so you get a clean list back, not a paragraph. It is slow, so run it once, run documents in parallel (four at a time, with ThreadPoolExecutor) unless the service says slow down (a rate limit), and save the store. Embed the headline, summary and text together.

每隔 1000 字符就切一刀，不管想法从哪里开始、到哪里结束。改成让模型把每份文档切成有重叠的块。每块有一个标题（几个可能匹配问题的词）、一段简短摘要，和原文。先告诉模型答案的确切格式（下面的 Pieces 类），就能拿回一份干净的列表，而不是一段文字。这很慢，所以只做一次；多份文档并行跑（一次四份，用 ThreadPoolExecutor），除非服务说“慢一点”（也就是速率限制）；然后把库存下来。标题、摘要和原文合在一起做向量。

import os from concurrent.futures import ThreadPoolExecutor from pydantic import BaseModel from langchain_core.documents import Document from langchain_openai import ChatOpenAI from langchain_chroma import Chroma class Piece(BaseModel): headline: str # a few words likely to match a question summary: str original_text: str class Pieces(BaseModel): pieces: list[Piece] cutter = ChatOpenAI(model="gpt-4.1-mini", temperature=0).with_structured_output(Pieces) def smart_chunks(doc): plan = ("Split this document into overlapping pieces that each cover one idea. " "For every piece give a headline, a short summary and the original text.\n\n" + doc.page_content) return [Document(page_content=f"{p.headline}\n{p.summary}\n{p.original_text}", metadata={"source": doc.metadata["source"]}) for p in cutter.invoke(plan).pieces] if not os.path.exists("council_db_smart"): # slow step: run once, then reuse with ThreadPoolExecutor(max_workers=4) as pool: groups = list(pool.map(smart_chunks, docs)) store = Chroma.from_documents([c for g in groups for c in g], embedder, persist_directory="council_db_smart") else: store = Chroma(persist_directory="council_db_smart", embedding_function=embedder)

Step 2 · Fetch more, then rerank第 2 步 · 多取一些，再重新排序

Learn先学

A vector search can put a chunk high because it sounds close to the question, not because it answers it. So fetch many chunks, say 20, and ask a model to put them in order of relevance to the question. Keep only the best few. A chunk that sounds close but does not answer drops down. Wei Jie's question about who used to drive buses only worked after reranking lifted the right chunk from rank 15 to the top.

向量搜索可能因为某一块和问题“听起来很像”，就把它排得很前，而它其实没回答问题。所以先多取一些，比如 20 块，再让模型按“和问题多相关”排序，只留最好的几块。只是听起来像、却没有回答问题的块会掉下去。Wei Jie 那个“谁以前开过公交车”的问题，要等重排序把正确的块从第 15 名提到最前面，才答对。

class Order(BaseModel): ranked: list[int] # chunk numbers, best first sorter = ChatOpenAI(model="gpt-4.1-mini", temperature=0).with_structured_output(Order) def rerank(question, chunks, keep=5): listing = "\n\n".join(f"[{i}] {c.page_content}" for i, c in enumerate(chunks)) order = sorter.invoke(f"Question: {question}\n\nPut these chunk numbers in order, " f"most useful for answering first:\n\n{listing}").ranked return [chunks[i] for i in order if 0 <= i < len(chunks)][:keep] candidates = store.similarity_search("Which officer used to drive buses?", k=20) best = rerank("Which officer used to drive buses?", candidates)

Step 3 · Rewrite the question before searching第 3 步 · 搜索之前先改写问题

Learn先学

Last time follow-ups failed because search saw only "and her manager?". So before searching, ask a model to turn the question plus the chat history into one precise, standalone search query. "And her manager?" becomes a full question that names the person. But a rewrite can drift from what the user meant. So search with both the original and the rewritten question, merge the results and drop duplicates.

上次追问失败，是因为搜索只看到“那她的上司呢？”。所以搜索之前，先让模型把问题加上聊天记录，改写成一句精确、能独立成立的搜索语句。“那她的上司呢？”会变成点名那个人的完整问题。但改写可能偏离用户的原意。所以原问题和改写后的问题都拿去搜，合并结果并去掉重复。

llm = ChatOpenAI(model="gpt-4.1-mini", temperature=0) def rewrite(question, history): chat = "\n".join(f"{m['role']}: {m['content']}" for m in history) return llm.invoke(f"Chat so far:\n{chat}\n\nTurn the last question into one standalone " f"search query that names every person or thing. Query only.\n\n{question}").content.strip() def fetch(question, history): rewritten = rewrite(question, history) seen, merged = set(), [] for q in (question, rewritten): # keep both: the rewrite may drift for c in store.similarity_search(q, k=20): if c.page_content not in seen: seen.add(c.page_content) merged.append(c) return rerank(rewritten, merged)

Step 4 · Cite sources, then prove it helped第 4 步 · 标出出处，再证明它有用

Learn先学

Put each chunk's source file name in the context, and tell the model to mention the file names it used. Now Auntie Lim can open the page and check. Last, re-run the test set from the last lesson, now scored through the full fetch. Compare the scores before and after, per category. In Wei Jie's run, MRR and coverage went up, and the holistic category improved most.

把每个块的来源文件名放进上下文，并告诉模型回答时说出用到的文件名。这样 Lim 阿姨就能打开那一页去核对。最后，重新跑上一课的测试集（这次通过完整的 fetch 来打分），按类别比较前后的分数。在 Wei Jie 那次运行中，MRR 和覆盖率都升了，进步最大的是整体性问题那一类。

def answer(question, history): chunks = fetch(question, history) context = "\n\n".join(f"Source: {c.metadata['source']}\n{c.page_content}" for c in chunks) system = ("Answer using only the context below. If it is not there, say you do not know. " "End with a line starting 'Sources:' listing the file names you used.\n\n" + context) messages = [("system", system)] + [(m["role"], m["content"]) for m in history] messages.append(("user", question)) return llm.invoke(messages).content def score_retrieval(test, k=10): # now scores fetch(): rewrite, merge and rerank included chunks = fetch(test["question"], []) # k is unused here: fetch keeps the best 5 ranks = [first_rank(w, chunks) for w in test["keywords"]] mrr = sum(1 / r for r in ranks if r) / len(ranks) coverage = sum(1 for r in ranks if r) / len(ranks) return mrr, coverage report(10) # the same test set as the last lesson: compare per category with the basic chain

What I got wrong我搞错的地方I rewrote queries so boldly that the rewrite drifted from what the user meant, and good hits disappeared. Now I search with the original and the rewrite and merge both. I also ran the slow model-based chunking on every start. Now it runs once and the store is reused.我把问题改写得太大胆，改写后的话偏离了用户的原意，好的结果反而不见了。现在我同时用原问题和改写后的问题去搜，再合并。我还曾在每次启动时都跑慢速的模型分块，现在只跑一次，之后重复使用这个库。

Common errors常见报错

• ValidationError from the reorder step. The model returned numbers outside the range. Ignore any index that is out of range, as the code does.
• Follow-up questions find nothing ("what about its fee?"). The question was not rewritten with the chat history. Call rewrite before searching.
• RateLimitError: 429. Too many calls in a short time, or the account has no credit. Wait a minute, add a short time.sleep in loops, and check the billing page.

• 重排这一步出现 ValidationError：模型返回的编号超出范围。像代码那样忽略越界的编号。
• 追问找不到东西（“那它的费用呢？”）：没有结合聊天记录改写问题。搜索前先调用 rewrite。
• RateLimitError: 429：短时间调用太多，或账户没有余额。等一分钟，循环里加一小段 time.sleep，并检查账单页面。

Takeaways要点回顾

• Each upgrade fixes one specific failure.
• Model-made chunks carry a headline, a summary and the original text.
• Fetch many chunks, rerank, keep the best few.
• Rewrite follow-ups into standalone queries, but merge with the original query.
• Cite the source file in every answer.
• Measure every change with the same test set.
• Do not rebuild the store on every start.

• 每个升级只修一个具体的失败。
• 模型做的块带有标题、摘要和原文。
• 多取一些块，重排序，只留最好的几块。
• 把追问改写成能独立成立的搜索语句，但要和原问题的结果合并。
• 每个回答都标出来源文件。
• 每个改动都用同一份测试集来衡量。
• 别在每次启动时都重建向量库。

Recap小结

1. Cut documents by their own structure, not by a fixed size alone.
2. Rewrite follow-ups with the chat history, then rerank what you found.
3. Judge every change with the same test set from the last lesson.

1. 按文件自己的结构来切，不要只按固定长度。
2. 用聊天记录改写追问，再对找到的内容重排。
3. 每次改动都用上一课的同一套测试来评判。
