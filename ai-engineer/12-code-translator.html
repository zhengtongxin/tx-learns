Ah Boy 有个 Python 脚本，用来算二手手机的最佳转售价，每次要跑二十秒。Wei Jie 给他做了个翻译器：输入 Python，得到打印同样结果的快速 C++。它也是上一课的好测试，因为分数是客观的：能不能跑，跑得多快。这场计时赛的赢家，就是助手可以放心交给它写代码的模型。

Step 1 · The compile command comes first第 1 步 · 先搞定编译命令

Learn先学

C++ must be compiled before it runs, and the right compiler depends on your machine. You can paste a short report of your operating system, chip and installed tools to a model and ask what to use. Then write down the exact commands yourself. The flags matter: -O3 optimises hard, -march=native uses your own chip's features and -flto optimises across the whole program. Wei Jie forgot them once and saw almost no speedup.

C++ 要先编译才能运行，而合适的编译器取决于你的机器。你可以把操作系统、芯片和已安装工具的简短报告贴给模型，问该用什么。然后自己把确切的命令记下来。参数很重要：-O3 全力优化，-march=native 用上你自己芯片的特性，-flto 跨整个程序优化。Wei Jie 有一次忘了加，结果几乎没有加速。

COMPILE = ["g++", "-O3", "-march=native", "-flto", "main.cpp", "-o", "main"] RUN = ["./main"]

Step 2 · The prompt, and cleaning the reply第 2 步 · 提示词，以及清理回复

Learn先学

The system message asks for fast C++, code only, same output. The user message carries the Python and one warning that is easy to miss: Python integers never overflow, but C++ ones do: a number too big for its box wraps around to a wrong value, with no error. So use 64-bit or wider types (bigger boxes). Models like to wrap code in markdown fences (the lines that start with three backticks), so strip them before saving, or the compiler chokes on the backticks.

system 消息要求：快速 C++，只要代码，输出相同。user 消息带上 Python 代码，还有一条容易漏掉的提醒：Python 的整数不会溢出，C++ 的会：数字超出它的“盒子”就会绕回一个错误的值，而且不报错。所以要用 64 位或更宽的类型（更大的盒子）。模型喜欢把代码包在 markdown 围栏里（以三个反引号开头的那几行），保存前要去掉，否则编译器会被反引号噎住。

SYSTEM = """Convert the given Python into fast C++. Reply with code only. It must print exactly the same output. Add comments only where they really help.""" def make_user_prompt(python_code): return ("Translate this to C++ that prints the same output. " "Python integers never overflow but C++ ones do, so use 64-bit or wider types.\n\n" + python_code) def strip_fences(reply): lines = [ln for ln in reply.splitlines() if not ln.strip().startswith("```")] return "\n".join(lines)

Step 3 · Ask, compile, run, time第 3 步 · 提问、编译、运行、计时

Learn先学

One helper does the whole chain for any model: ask, strip, write main.cpp, compile, run and time. Another runs the Python for comparison. Now every model gets two objective numbers, and nothing relies on how the code looks. On a loop that sums a series millions of times, Python took about twenty seconds and one model's C++ finished in about 0.08 seconds.

一个函数对任何模型完成整条链：提问、去围栏、写入 main.cpp、编译、运行、计时。另一个函数运行 Python 做对照。这样每个模型都有两个客观数字，不靠代码好不好看。在一个把级数求和几百万次的循环上，Python 花了约二十秒，某个模型写的 C++ 约 0.08 秒就跑完。

import subprocess, time from openai import OpenAI # pip install openai; set OPENAI_API_KEY (calls cost money) client = OpenAI() def timed(cmd): start = time.time() done = subprocess.run(cmd, capture_output=True, text=True) return done.stdout.strip(), time.time() - start def translate_and_run(model, python_code): reply = client.chat.completions.create(model=model, messages=[ {"role": "system", "content": SYSTEM}, {"role": "user", "content": make_user_prompt(python_code)}]) open("main.cpp", "w").write(strip_fences(reply.choices[0].message.content)) built = subprocess.run(COMPILE, capture_output=True, text=True) if built.returncode != 0: return None, None # did not even compile return timed(RUN) def run_python(path): return timed(["python", path])

Step 4 · Verify the output, then rank the models第 4 步 · 核对输出，再给模型排名

Learn先学

Fast is worthless if it is wrong, so compare the printed output with Python's, line for line. Wei Jie first trusted the output and two models silently printed a wrong number. Use a harder program too: save one as hard_program.py. It could be a random-number generator feeding a search with big numbers, because sloppy translations break there. Then rank by speedup divided by cost (tokens used times the price per token, from your usage page), not by speed alone. A simple hard_program.py:

快但错了毫无价值，所以要把打印的输出和 Python 的逐行对比。Wei Jie 起初相信了输出，结果有两个模型悄悄打印了错误的数字。再加一个更难的程序：存成 hard_program.py，可以是用随机数生成器喂给一个涉及大数的搜索，因为马虎的翻译会在这里露馅。然后按加速倍数除以成本（用掉的 token 数乘以每个 token 的价格，见用量页面）来排名，不要只看速度。下面是一个简单的 hard_program.py：

# hard_program.py: a random-number generator feeding a big-number search x, total = 12345, 0 for _ in range(5_000_000): x = (x * 1103515245 + 12345) % 2147483648 total += x % 1000 print(total) # prints one number; the C++ must print the same one
py_out, py_time = run_python("hard_program.py") hard_code = open("hard_program.py").read() for model in ["gpt-4.1", "gpt-4.1-mini", "gpt-4.1-nano"]: # your shortlist out, took = translate_and_run(model, hard_code) if out is None: print(model, "failed to compile") elif out != py_out: print(model, "WRONG OUTPUT", out) else: print(model, f"ok, {py_time / took:.0f}x faster")

Common errors常见报错

• error: 'x' was not declared in this scope from g++. The model's C++ is wrong. Show the compiler error back to the model, or try another model.
• The C++ prints a different number. Integers overflowed or the maths changed. Ask for fixed-size types such as long long and compare outputs exactly.
• FileNotFoundError: 'g++'. The compiler is not installed. Install it (for example sudo apt install g++) or change COMPILE to your compiler.

• g++ 报 error: 'x' was not declared in this scope：模型写的 C++ 有错。把编译器的报错发回给模型，或换一个模型。
• C++ 打印出不同的数字：整数溢出，或算法变了。要求用 long long 这类定长类型，并逐字比较输出。
• FileNotFoundError: 'g++'：没装编译器。安装它（例如 sudo apt install g++），或把 COMPILE 改成你的编译器。

Takeaways要点回顾

• Pick models by running them on a task with an objective score.
• Compile with optimisation flags, or you will see almost no speedup.
• Tell the model about integer overflow when translating from Python.
• Strip markdown fences before compiling.
• Always compare the output with Python's, not just whether it compiles.
• A hard test program separates models that an easy one cannot.
• Speedups can be huge, but only for correct code.
• Rank by speedup divided by cost: a cheap open model can come close.

• 选模型，就让它们去跑一个有客观分数的任务。
• 编译时要加优化参数，不然几乎看不到加速。
• 从 Python 翻译时，要提醒模型整数溢出的问题。
• 编译前先去掉 markdown 围栏。
• 一定要把输出和 Python 的对比，不能只看能不能编译。
• 难的测试程序能分出简单程序分不出的模型。
• 加速可以很惊人，但只对正确的代码成立。
• 按加速倍数除以成本排名：便宜的开源模型也可能很接近。
