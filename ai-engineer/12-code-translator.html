Project: a code translator项目：代码翻译器

You will turn slow Python into fast C++ with a model, and score models by what actually runs · ~30 min · hands-on你会用模型把慢的 Python 变成快的 C++，并按真正跑出来的结果给模型打分 · 约 30 分钟 · 动手实践

The story故事

Ah Boy has a Python script that works out the best resale price for his second-hand phones, and it takes twenty seconds on every run. Wei Jie builds him a translator: give it Python, get back fast C++ that prints the same output. It is also a neat test for the last lesson, because the score is objective: does it run, and how fast.

Ah Boy 有个 Python 脚本，用来算二手手机的最佳转售价，每次要跑二十秒。Wei Jie 给他做了个翻译器：输入 Python，得到打印同样结果的快速 C++。它也是上一课的好测试，因为分数是客观的：能不能跑，跑得多快。

Step 1 · The compile command comes first第 1 步 · 先搞定编译命令

Learn先学

C++ must be compiled before it runs, and the right compiler depends on your machine. You can paste a short report of your operating system, chip and installed tools to a model and ask what to use. Then write down the exact commands yourself. The flags matter: -O3 optimises hard, -march=native uses your own chip's features and -flto optimises across the whole program. Wei Jie forgot them once and saw almost no speedup.

C++ 要先编译才能运行，而合适的编译器取决于你的机器。你可以把操作系统、芯片和已安装工具的简短报告贴给模型，问该用什么。然后自己把确切的命令记下来。参数很重要：-O3 全力优化，-march=native 用上你自己芯片的特性，-flto 跨整个程序优化。Wei Jie 有一次忘了加，结果几乎没有加速。

COMPILE = ["g++", "-O3", "-march=native", "-flto", "main.cpp", "-o", "main"] RUN = ["./main"]

Step 2 · The prompt, and cleaning the reply第 2 步 · 提示词，以及清理回复

Learn先学

The system message asks for fast C++, code only, same output. The user message carries the Python and one warning that is easy to miss: Python integers never overflow, but C++ ones do, so use 64-bit or wider types. Models like to wrap code in markdown fences, so strip them before saving, or the compiler chokes on the backticks.

system 消息要求：快速 C++，只要代码，输出相同。user 消息带上 Python 代码，还有一条容易漏掉的提醒：Python 的整数不会溢出，C++ 的会，所以要用 64 位或更宽的类型。模型喜欢把代码包在 markdown 围栏里，保存前要去掉，否则编译器会被反引号噎住。

SYSTEM = """Convert the given Python into fast C++. Reply with code only. It must print exactly the same output. Add comments only where they really help.""" def make_user_prompt(python_code): return ("Translate this to C++ that prints the same output. " "Python integers never overflow but C++ ones do, so use 64-bit or wider types.\n\n" + python_code) def strip_fences(reply): lines = [ln for ln in reply.splitlines() if not ln.strip().startswith("```")] return "\n".join(lines)

Step 3 · Ask, compile, run, time第 3 步 · 提问、编译、运行、计时

Learn先学

One helper does the whole chain for any model: ask, strip, write main.cpp, compile, run and time. Another runs the Python for comparison. Now every model gets two objective numbers, and nothing relies on how the code looks. On a loop that sums a series millions of times, Python took about twenty seconds and one model's C++ finished in about 0.08 seconds.

一个函数对任何模型完成整条链：提问、去围栏、写入 main.cpp、编译、运行、计时。另一个函数运行 Python 做对照。这样每个模型都有两个客观数字，不靠代码好不好看。在一个把级数求和几百万次的循环上，Python 花了约二十秒，某个模型写的 C++ 约 0.08 秒就跑完。

import subprocess, time from openai import OpenAI client = OpenAI() def timed(cmd): start = time.time() done = subprocess.run(cmd, capture_output=True, text=True) return done.stdout.strip(), time.time() - start def translate_and_run(model, python_code): reply = client.chat.completions.create(model=model, messages=[ {"role": "system", "content": SYSTEM}, {"role": "user", "content": make_user_prompt(python_code)}]) open("main.cpp", "w").write(strip_fences(reply.choices[0].message.content)) built = subprocess.run(COMPILE, capture_output=True, text=True) if built.returncode != 0: return None, None # did not even compile return timed(RUN) def run_python(path): return timed(["python", path])

Step 4 · Verify the output, then rank the models第 4 步 · 核对输出，再给模型排名

Learn先学

Fast is worthless if it is wrong, so compare the printed output with Python's, line for line. Wei Jie first trusted the output and two models silently printed a wrong number. Use a harder program too, such as a random-number generator feeding a search with big numbers, because sloppy translations break there. Then rank by speedup divided by cost, not by speed alone.

快但错了毫无价值，所以要把打印的输出和 Python 的逐行对比。Wei Jie 起初相信了输出，结果有两个模型悄悄打印了错误的数字。再加一个更难的程序，比如用随机数生成器喂给一个涉及大数的搜索，因为马虎的翻译会在这里露馅。然后按加速倍数除以成本来排名，不要只看速度。

py_out, py_time = run_python("hard_program.py") hard_code = open("hard_program.py").read() for model in ["big-model-a", "mid-model-b", "small-model-c"]: # your shortlist out, took = translate_and_run(model, hard_code) if out is None: print(model, "failed to compile") elif out != py_out: print(model, "WRONG OUTPUT", out) else: print(model, f"ok, {py_time / took:.0f}x faster")

每个结果说明这个模型怎么样？

What I got wrong我搞错的地方I trusted the output without comparing it to the Python output, and two models quietly printed a wrong number. I also forgot the optimisation flags and saw almost no speedup. Now the check against Python runs every time, and the flags live in one place.我没拿输出和 Python 的输出对比就相信了它，结果有两个模型悄悄打印了错误的数字。我还忘了优化参数，几乎没看到加速。现在每次都和 Python 对一遍，参数也只放在一处。

Back at the void deck回到组屋底层Ah Boy never trusts a phone just because the box looks new. He powers it on and runs it first. Treat translated code the same way: it is not good until it runs and gives the same answer.Ah Boy 从不因为盒子看起来新就相信一部手机。他会先开机跑一跑。对翻译出来的代码也一样：能跑、且答案相同，才算好。

Takeaways要点回顾

• Pick models by running them on a task with an objective score.
• Compile with optimisation flags, or you will see almost no speedup.
• Tell the model about integer overflow when translating from Python.
• Strip markdown fences before compiling.
• Always compare the output with Python's, not just whether it compiles.
• A hard test program separates models that an easy one cannot.
• Speedups can be huge, but only for correct code.
• Rank by speedup divided by cost: a cheap open model can come close.

• 选模型，就让它们去跑一个有客观分数的任务。
• 编译时要加优化参数，不然几乎看不到加速。
• 从 Python 翻译时，要提醒模型整数溢出的问题。
• 编译前先去掉 markdown 围栏。
• 一定要把输出和 Python 的对比，不能只看能不能编译。
• 难的测试程序能分出简单程序分不出的模型。
• 加速可以很惊人，但只对正确的代码成立。
• 按加速倍数除以成本排名：便宜的开源模型也可能很接近。
