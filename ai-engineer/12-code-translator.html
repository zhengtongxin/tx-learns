Step 1 · The compile command and the prompt第 1 步 · 编译命令和提示词

Learn先学

C++ must be compiled before it runs. The flags matter: -O3 optimises hard, -march=native uses your chip's features, -flto optimises across the program. Forget them and you see almost no speedup. In the prompt, warn the model that Python integers never overflow but C++ ones wrap around silently, so use 64-bit types. Models wrap code in markdown fences (lines starting with three backticks): strip them before saving.

C++ 要先编译才能运行。参数很重要：-O3 全力优化，-march=native 用上你芯片的特性，-flto 跨整个程序优化。忘了加，几乎看不到加速。提示词里要提醒模型：Python 整数不会溢出，C++ 的会悄悄回绕，所以要用 64 位类型。模型喜欢把代码包在 markdown 围栏里（以三个反引号开头的行），保存前要去掉。

COMPILE = ["g++", "-O3", "-march=native", "-flto", "main.cpp", "-o", "main"] RUN = ["./main"] SYSTEM = """Convert the given Python into fast C++. Reply with code only. It must print exactly the same output.""" def make_user_prompt(python_code): return ("Translate this to C++ that prints the same output. " "Python integers never overflow but C++ ones do, so use 64-bit or wider types.\n\n" + python_code) def strip_fences(reply): lines = [ln for ln in reply.splitlines() if not ln.strip().startswith("```")] return "\n".join(lines)

Step 2 · Ask, compile, run, time第 2 步 · 提问、编译、运行、计时

Learn先学

One helper runs the whole chain for any model: ask, strip, write main.cpp, compile, run, time. Another runs the Python for comparison. Every model gets two objective numbers, whatever the code looks like: does the output match Python's, and how many times faster it ran.

一个函数对任何模型完成整条链：提问、去围栏、写入 main.cpp、编译、运行、计时。另一个运行 Python 做对照。不管代码好不好看，每个模型都有两个客观数字：输出和 Python 的是否一致，以及快了多少倍。

# same file as Step 1, below it: SYSTEM, make_user_prompt, strip_fences, COMPILE and RUN are defined there import subprocess, time # subprocess runs another program (the compiler, the result) and captures what it prints from openai import OpenAI # pip install openai; set OPENAI_API_KEY (calls cost money) client = OpenAI() def timed(cmd): start = time.time() done = subprocess.run(cmd, capture_output=True, text=True) return done.stdout.strip(), time.time() - start def translate_and_run(model, python_code): reply = client.chat.completions.create(model=model, messages=[ {"role": "system", "content": SYSTEM}, {"role": "user", "content": make_user_prompt(python_code)}]) open("main.cpp", "w").write(strip_fences(reply.choices[0].message.content)) built = subprocess.run(COMPILE, capture_output=True, text=True) if built.returncode != 0: return None, None, 0 # did not even compile out, took = timed(RUN) return out, took, reply.usage.total_tokens # tokens used: multiply by the model's price for the cost def run_python(path): return timed(["python", path])

Step 3 · Verify the output, then rank第 3 步 · 核对输出，再排名

Learn先学

Fast is worthless if wrong: compare the printed output with Python's. Use a hard program too, since sloppy translations break on big numbers. Rank by speedup divided by cost (tokens used times price), not speed alone.

快但错了毫无价值：把打印的输出和 Python 的对比。再用一个难的程序，因为马虎的翻译会在大数上露馅。按加速倍数除以成本（用掉的 token 数乘以价格）排名，不要只看速度。

# hard_program.py: a random-number generator feeding a big-number loop x, total = 12345, 0 for _ in range(5_000_000): x = (x * 1103515245 + 12345) % 2147483648 total += x % 1000 print(total) # --- compare.py --- py_out, py_time = run_python("hard_program.py") hard_code = open("hard_program.py").read() for model in ["gpt-4.1", "gpt-4.1-mini", "gpt-4.1-nano"]: # your shortlist out, took, tokens = translate_and_run(model, hard_code) if out is None: print(model, "failed to compile") elif out != py_out: print(model, "WRONG OUTPUT", out) else: print(model, f"ok, {py_time / took:.0f}x faster, {tokens} tokens")

Common errors常见报错

• error: ... was not declared in this scope. The model's C++ is wrong. Show the error back to the model, or try another.
• FileNotFoundError: 'g++'. Install the compiler or change COMPILE.

• error: ... was not declared in this scope：模型写的 C++ 有错。把报错发回给模型，或换一个。
• FileNotFoundError: 'g++'：安装编译器，或改 COMPILE。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Pick models by running them on a task with an objective score.
• Compile with optimisation flags, or the speedup disappears.
• Warn about integer overflow, and strip markdown fences before compiling.
• Always compare the output with Python's, not just whether it compiles.
• Rank by speedup divided by cost; a cheap open model can come close.

• 选模型，就让它们去跑一个有客观分数的任务。
• 编译要加优化参数，不然加速就没了。
• 提醒整数溢出，编译前去掉 markdown 围栏。
• 一定要把输出和 Python 的对比，不能只看能不能编译。
• 按加速倍数除以成本排名；便宜的开源模型也可能很接近。
