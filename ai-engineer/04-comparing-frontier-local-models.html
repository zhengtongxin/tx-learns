Step 1 · One helper, many providers第 1 步 · 一个函数，多家服务商

Learn先学

Most providers copy the same chat-completions shape. So you keep one helper and only swap three things: the base URL, the key and the model name. Some providers, and a local server such as Ollama, offer an OpenAI-compatible address, so the very same OpenAI(...) object works. Think of one plug that fits many wall sockets.

大多数服务商都照搬同一种 chat-completions 格式。所以你只留一个辅助函数，只换三样：base URL、密钥和模型名。有些服务商，以及 Ollama 这样的本地服务，提供兼容 OpenAI 的地址，所以同一个 OpenAI(...) 对象就能用。就像一个插头能插进许多插座。

from openai import OpenAI clients = { "cloud-a": OpenAI(), "cloud-b": OpenAI(base_url="https://<provider>/v1/", api_key=KEY_B), "local": OpenAI(base_url="http://localhost:11434/v1", api_key="ollama"), } def ask(which, model, prompt, **extra): reply = clients[which].chat.completions.create( model=model, messages=[{"role": "user", "content": prompt}], **extra) return reply.choices[0].message.content

Step 2 · Easy prompts tell you nothing第 2 步 · 简单的题看不出差别

Learn先学

Wei Jie first asked two providers for a joke. Both answered fine. Easy prompts hide the differences, so a good test is a hard prompt with a trap. A favourite: “Two coins are flipped. At least one is heads. What is the chance the other is tails?” The tempting answer is one half. A careful one lists the possible pairs: HH, HT, TH, TT. TT is ruled out, and 2 of the 3 left have a tails, so the answer is 2/3. (The local entry in the code below needs Ollama, which Step 4 sets up; run only the cloud entry until then.)

Wei Jie 先让两家服务商讲个笑话，两边都答得不错。简单的题会把差别藏起来，所以好的测试是带陷阱的难题。一个常用的：“抛两枚硬币，至少有一枚是正面，另一枚是反面的概率是多少？”诱人的答案是二分之一，仔细的人会把可能的组合一一列出来：正正、正反、反正、反反。反反被排除，剩下 3 种里有 2 种含反面，所以答案是 2/3。（下面代码里的 local 一项需要 Ollama，第 4 步才会装好；在那之前先只运行云端那一项。）

question = "Two coins are flipped. At least one is heads. What is the chance the other is tails? Explain briefly." for which, model in [("cloud-a", "gpt-5-mini"), ("local", "llama3.2")]: print(which, "->", ask(which, model, question))
cloud-a -> The chance is 2/3, because ... local -> The chance is 1/2, because ... # a small model can slip here

Step 3 · Two dials: size and thinking第 3 步 · 两个旋钮：大小与思考

Learn先学

A small model with no thinking gets the coin puzzle wrong. Give it a low reasoning effort and it often fixes itself. A bigger reasoning model gets it right too. So there are two dials. One is a bigger model (scale at training time). The other is more thinking before answering (scale at answer time). The second dial is cheap to try, but it costs more tokens and more time.

没有思考的小模型会答错硬币谜题。给它一个低档的推理力度，它往往就自己改对了。更大的推理模型也能答对。所以有两个旋钮：一个是更大的模型（训练时的规模），另一个是回答前多想一会儿（回答时的规模）。第二个旋钮试起来便宜，但要多花 token 和时间。

import time for effort in ["minimal", "low", "high"]: start = time.time() answer = ask("cloud-a", "gpt-5-mini", question, reasoning_effort=effort) print(effort, round(time.time() - start, 1), "s,", len(answer), "chars")
minimal 1.8 s, 410 chars low 4.2 s, 780 chars high 15.6 s, 1450 chars

Step 4 · Going local, and being honest about it第 4 步 · 用本地模型，并诚实地看待

Learn先学

A local model runs on your own laptop. Run ollama pull llama3.2, then point the client at localhost (that is the local entry above). It is free per call and private, because your text never leaves the laptop. It is usually weaker too. One rule: never pull a model bigger than your laptop's memory. The B stands for billions of parameters (the numbers a model learns), so a 20B model has 20 billion. A 16 GB laptop copes with roughly 20B-sized open models. A small laptop should use a 1B to 3B size.

本地模型跑在你自己的笔记本上。运行 ollama pull llama3.2，再让客户端指向 localhost（就是上面的 local 那一项）。它每次调用不花钱，而且私密，因为文字不会离开你的电脑。一般也更弱一些。有一条规矩：别拉取比笔记本内存还大的模型。B 是十亿个参数（模型学到的数字），所以 20B 就是 200 亿个。16 GB 的笔记本大约能跑 20B 左右的开源模型，小笔记本就用 1B 到 3B 的。

# in a terminal, once: ollama pull llama3.2
print(ask("local", "llama3.2", question))

For each case, is a local model a good fit?

每种情况，本地模型合适吗？

What I got wrong我搞错的地方I assumed the newest model always gives the best answer. On easy tasks a cheap, fast model gave the same answer. On tricky ones the thinking dial mattered more than the logo. Also, asking a handful of prompts and picking a favourite is opinion, not a benchmark.我以为最新的模型一定答得最好。简单的任务上，便宜又快的模型答得一样。在刁钻的题上，思考这个旋钮比牌子更重要。另外，问几道题就挑出最爱，只是意见，不是基准测试。

Common errors常见报错

• openai.APIConnectionError: Connection error for the local client. Ollama is not running. Start it (ollama serve) and check the port is 11434.
• model 'llama3.2' not found. You have not pulled it yet. Run ollama pull llama3.2 once.
• Unsupported value: 'temperature'. Some reasoning models fix their own temperature. Drop the argument for those models.

• 本地客户端报 openai.APIConnectionError: Connection error：Ollama 没在运行。启动它（ollama serve），并确认端口是 11434。
• model 'llama3.2' not found：还没下载这个模型。运行一次 ollama pull llama3.2。
• Unsupported value: 'temperature'：有些推理模型自己固定温度。对这类模型去掉这个参数。

Takeaways要点回顾

• One helper, many providers: swap only the base URL, key and model name.
• Easy prompts hide differences. Use a hard prompt with a trap.
• Two dials: a bigger model, and more thinking before the answer.
• More thinking costs more tokens and time.
• Cost and speed matter as much as the answer.
• Local is free per call and private, but usually weaker.
• A few prompts give an opinion, not a benchmark. Proper comparison comes later.

• 一个辅助函数，多家服务商：只换 base URL、密钥和模型名。
• 简单的题看不出差别，要用带陷阱的难题。
• 两个旋钮：更大的模型，和回答前更多的思考。
• 多想会多花 token 和时间。
• 成本和速度与答案同样重要。
• 本地模型每次调用免费又私密，但通常更弱。
• 几道题只是意见，不是基准。正式的对比留到后面。
