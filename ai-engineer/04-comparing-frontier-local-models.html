Comparing frontier and local models对比云端模型与本地模型

You will ask several models the same question through one helper and see which dials really change the answer · ~15 min · hands-on你会用同一个辅助函数向多个模型问同一个问题，看看哪些旋钮真正会改变答案 · 约 15 分钟 · 动手实践

The story故事

Priya, the tuition teacher, sets Wei Jie a challenge: “Which model is best for checking my students' answers?” Wei Jie does not want a separate script per provider. He wants one helper, many models, and a fair look at which one deserves the job.

补习老师 Priya 给 Wei Jie 出了道题：“哪个模型最适合批改我学生的答案？”Wei Jie 不想为每家服务商各写一个脚本。他想要一个辅助函数、许多模型，再公平地看看谁配得上这份活。

Step 1 · One helper, many providers第 1 步 · 一个函数，多家服务商

Learn先学

Most providers copy the same chat-completions shape. So you keep one helper and only swap three things: the base URL, the key and the model name. Some providers, and a local server such as Ollama, offer an OpenAI-compatible address, so the very same OpenAI(...) object works. Keep each key in .env, not in the code (KEY_B is the second provider's key). Think of one plug that fits many wall sockets.

大多数服务商都照搬同一种 chat-completions 格式。所以你只留一个辅助函数，只换三样：base URL、密钥和模型名。有些服务商，以及 Ollama 这样的本地服务，提供兼容 OpenAI 的地址，所以同一个 OpenAI(...) 对象就能用。密钥放在 .env 里，别写进代码（KEY_B 就是第二家服务商的密钥）。就像一个插头能插进许多插座。

from openai import OpenAI clients = { "cloud-a": OpenAI(), "cloud-b": OpenAI(base_url="https://<provider>/v1/", api_key=KEY_B), "local": OpenAI(base_url="http://localhost:11434/v1", api_key="ollama"), } def ask(which, model, prompt, **extra): reply = clients[which].chat.completions.create( model=model, messages=[{"role": "user", "content": prompt}], **extra) return reply.choices[0].message.content

Step 2 · Easy prompts tell you nothing第 2 步 · 简单的题看不出差别

Learn先学

Wei Jie first asked two providers for a joke. Both answered fine. Easy prompts hide the differences, so a good test is a hard prompt with a trap. A favourite: “Two coins are flipped. One is heads. What is the chance the other is tails?” The tempting answer is one half. A careful one works through the possible pairs: HH, HT and TH, each equally likely once we know at least one is heads. The other coin is tails in two of those three, so the answer is 2/3.

Wei Jie 先让两家服务商讲个笑话，两边都答得不错。简单的题会把差别藏起来，所以好的测试是带陷阱的难题。一个常用的：“抛两枚硬币，其中一枚是正面，另一枚是反面的概率是多少？”诱人的答案是二分之一。仔细的人会把可能的组合一一列出来：已知至少一枚是正面，就只剩 HH、HT、TH 三种，各自等可能。另一枚是反面的有两种，所以答案是 2/3。

question = "Two coins are flipped. At least one is heads. What is the chance the other is tails? Explain briefly." for which, model in [("cloud-a", "gpt-5-mini"), ("local", "llama3.2")]: print(which, "->", ask(which, model, question))

哪种提示词能看出模型之间的差别？

Step 3 · Two dials: size and thinking第 3 步 · 两个旋钮：大小与思考

Learn先学

A small model with no thinking gets the coin puzzle wrong. Give it a low reasoning effort and it often fixes itself. A bigger reasoning model gets it right too. So there are two dials. One is a bigger model (scale at training time). The other is more thinking before answering (scale at answer time). The second dial is cheap to try, but it costs more tokens and more time.

没有思考的小模型会答错硬币谜题。给它一个低档的推理力度，它往往就自己改对了。更大的推理模型也能答对。所以有两个旋钮：一个是更大的模型（训练时的规模），另一个是回答前多想一会儿（回答时的规模）。第二个旋钮试起来便宜，但要多花 token 和时间。

import time for effort in ["minimal", "low", "high"]: start = time.time() answer = ask("cloud-a", "gpt-5-mini", question, reasoning_effort=effort) print(effort, round(time.time() - start, 1), "s,", len(answer), "chars")

Step 4 · Going local, and being honest about it第 4 步 · 用本地模型，并诚实地看待

Learn先学

A local model runs on your own laptop. Run ollama pull llama3.2, then point the client at localhost (that is the local entry above). It is free per call and private, because your text never leaves the laptop. It is usually weaker too. One rule: never pull a model bigger than your laptop's memory. A 16 GB laptop copes with roughly 20B-sized open models. A small laptop should use a 1B to 3B size.

本地模型跑在你自己的笔记本上。运行 ollama pull llama3.2，再让客户端指向 localhost（就是上面的 local 那一项）。它每次调用不花钱，而且私密，因为文字不会离开你的电脑。一般也更弱一些。有一条规矩：别拉取比笔记本内存还大的模型。16 GB 的笔记本大约能跑 20B 左右的开源模型，小笔记本就用 1B 到 3B 的。

# in a terminal, once: # ollama pull llama3.2 print(ask("local", "llama3.2", question))

For each case, is a local model a good fit?

每种情况，本地模型合适吗？

What I got wrong我搞错的地方I assumed the newest model always gives the best answer. On easy tasks a cheap, fast model gave the same answer. On tricky ones the thinking dial mattered more than the logo. Also, asking a handful of prompts and picking a favourite is opinion, not a benchmark.我以为最新的模型一定答得最好。简单的任务上，便宜又快的模型答得一样。在刁钻的题上，思考这个旋钮比牌子更重要。另外，问几道题就挑出最爱，只是意见，不是基准测试。

Takeaways要点回顾

• One helper, many providers: swap only the base URL, key and model name.
• Easy prompts hide differences. Use a hard prompt with a trap.
• Two dials: a bigger model, and more thinking before the answer.
• More thinking costs more tokens and time.
• Cost and speed matter as much as the answer.
• Local is free per call and private, but usually weaker.
• A few prompts give an opinion, not a benchmark. Proper comparison comes later.

• 一个辅助函数，多家服务商：只换 base URL、密钥和模型名。
• 简单的题看不出差别，要用带陷阱的难题。
• 两个旋钮：更大的模型，和回答前更多的思考。
• 多想会多花 token 和时间。
• 成本和速度与答案同样重要。
• 本地模型每次调用免费又私密，但通常更弱。
• 几道题只是意见，不是基准。正式的对比留到后面。
