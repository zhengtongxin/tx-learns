Meeting minutes writer会议纪要助手

You will chain two open models, ears then brain, to turn a recording into minutes · ~25 min · hands-on你会把两个开源模型接起来，先听后写，把录音变成会议纪要 · 约 25 分钟 · 动手实践

Step 1 · Ears: speech to text第 1 步 · 耳朵：语音转文字

Learn先学

The first model only listens: a speech-recognition pipeline takes an audio file and returns text. In a cloud notebook, mount your drive so the recording is reachable. An empty transcript usually means a wrong audio format or sampling rate.

第一个模型只负责听：语音识别 pipeline 接收音频文件，返回文字。在云 notebook 里，先挂载云盘才能读到录音。文字稿为空，多半是音频格式或采样率不对。

from transformers import pipeline SPEECH_MODEL = "openai/whisper-small" ears = pipeline("automatic-speech-recognition", model=SPEECH_MODEL, device="cuda") transcript = ears("/content/drive/MyDrive/residents_meeting.mp3")["text"] print(transcript[:300])

Step 2 · Brain: a chat model with a minutes prompt, streamed第 2 步 · 大脑：配纪要提示词的聊天模型，流式输出

Learn先学

The second model writes. Load an open chat model in 4-bit so it fits beside the first. The system message sets the shape of the minutes (summary, decisions, action items with owners); the user message is the transcript. Generation is next-token prediction in a loop, and a streamer prints each token as it lands.

第二个模型负责写。用 4 位加载一个开源聊天模型，让它和第一个一起放得下。system 消息定下纪要的格式（摘要、决定、带负责人的待办事项），user 消息就是文字稿。生成就是循环地预测下一个 token，流式输出器把每个 token 一落地就打印出来。

import torch from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig, TextStreamer CHAT_MODEL = "Qwen/Qwen2.5-7B-Instruct" # any open chat model from the hub tok = AutoTokenizer.from_pretrained(CHAT_MODEL) small = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_compute_dtype=torch.bfloat16) brain = AutoModelForCausalLM.from_pretrained(CHAT_MODEL, device_map="auto", quantization_config=small) MINUTES_PROMPT = """Write meeting minutes in markdown with these parts: a short summary, discussion points, decisions, and action items with an owner for each.""" messages = [{"role": "system", "content": MINUTES_PROMPT}, {"role": "user", "content": "Transcript:\n" + transcript}] inputs = tok.apply_chat_template(messages, add_generation_prompt=True, return_tensors="pt").to("cuda") brain.generate(inputs, streamer=TextStreamer(tok, skip_prompt=True), max_new_tokens=2000)

Step 3 · Long meetings and misspelled names第 3 步 · 长会议和写错的名字

Learn先学

A two-hour meeting overflows the context window: split the transcript into chunks, summarise each, then summarise the summaries. Speech models also misspell names, so list the real ones in the prompt.

两小时的会议会塞爆上下文窗口：把文字稿切成块，每块先做摘要，再总结这些摘要。语音模型也常把名字写错，所以把真实名字列在提示词里。

NAMES = "Names that may appear: Mdm Tan, Uncle Raj, Priya, Wei Jie, Auntie Lim." def ask(system, text): msgs = [{"role": "system", "content": system}, {"role": "user", "content": text}] ids = tok.apply_chat_template(msgs, add_generation_prompt=True, return_tensors="pt").to("cuda") out = brain.generate(ids, max_new_tokens=700) return tok.decode(out[0][ids.shape[1]:], skip_special_tokens=True) def minutes_for_long(transcript, size=6000): parts = [transcript[i:i + size] for i in range(0, len(transcript), size)] notes = [ask("Summarise this part of a meeting. " + NAMES, p) for p in parts] return ask(MINUTES_PROMPT + " " + NAMES, "Part summaries:\n" + "\n".join(notes))

Common errors常见报错

• ffmpeg was not found. The speech model cannot read the file. Install ffmpeg.
• CUDA out of memory. Load in 4-bit or pick a smaller model.

• ffmpeg was not found：语音模型读不了音频文件。安装 ffmpeg。
• CUDA out of memory：改用 4 位加载或换更小的模型。

Takeaways要点回顾

• Two models in a row: ears (speech to text), then brain (text to minutes).
• The system message defines the shape of the minutes.
• Open models plus 4-bit quantisation run free on a small GPU.
• Generation is next-token prediction in a loop; a streamer shows it live.
• Chunk what does not fit, and give the real names in the prompt.

• 两个模型串起来：耳朵（语音转文字），再大脑（文字转纪要）。
• system 消息决定纪要的格式。
• 开源模型加 4 位量化，在小 GPU 上免费就能跑。
• 生成就是循环地预测下一个 token，流式输出器让你实时看到。
• 放不下的就分块，并在提示词里给出真实名字。
