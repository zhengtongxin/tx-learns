Step 1 · Ears: speech to text第 1 步 · 耳朵：语音转文字

Learn先学

The first model only listens. A speech-recognition pipeline takes an audio file and returns text. In a cloud notebook, mount your drive storage so the recording is reachable. If the transcript comes back empty, suspect the audio: a wrong format or sampling rate is the usual cause.

第一个模型只负责听。语音识别 pipeline 接收音频文件，返回文字。在云 notebook 里，要先挂载云盘，才能读到录音。如果文字稿是空的，先怀疑音频：格式或采样率不对是最常见的原因。

from transformers import pipeline SPEECH_MODEL = "openai/whisper-small" ears = pipeline("automatic-speech-recognition", model=SPEECH_MODEL, device="cuda") transcript = ears("/content/drive/MyDrive/residents_meeting.mp3")["text"] print(transcript[:300])
Good morning everyone, let us begin with the lift upgrade at Block 12...

Step 2 · Brain: a small chat model with a minutes prompt第 2 步 · 大脑：配一份纪要提示词的小聊天模型

Learn先学

The second model writes. Load an open chat model in 4-bit (each number is stored in 4 bits instead of 16, so the model needs about a quarter of the memory) so it fits beside the first one. The system message sets the shape of the minutes: summary, discussion points, decisions, and action items with owners. The user message is the transcript. Build the messages and encode them with the chat template, exactly as in the last lesson.

第二个模型负责写。用 4 位加载（每个数字只存 4 位而不是 16 位，所以模型大约只要四分之一的内存）一个开源聊天模型，让它能和第一个模型一起放得下。system 消息定下纪要的格式：摘要、讨论要点、决定、带负责人的待办事项。user 消息就是文字稿。按上一课的做法，用对话模板构造并编码 messages。

import torch from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig CHAT_MODEL = "Qwen/Qwen2.5-7B-Instruct" # any open chat model from the hub (a public site where open models are shared) tok = AutoTokenizer.from_pretrained(CHAT_MODEL) small = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_compute_dtype=torch.bfloat16) brain = AutoModelForCausalLM.from_pretrained(CHAT_MODEL, device_map="auto", quantization_config=small) MINUTES_PROMPT = """Write meeting minutes in markdown with these parts: a short summary, discussion points, decisions, and action items with an owner for each.""" messages = [{"role": "system", "content": MINUTES_PROMPT}, {"role": "user", "content": "Transcript:\n" + transcript}] inputs = tok.apply_chat_template(messages, add_generation_prompt=True, return_tensors="pt").to("cuda")

Step 3 · Stream the minutes第 3 步 · 流式输出纪要

Learn先学

Generation is just “predict the next token” in a loop. The model gives a probability for every possible next token, one is picked and added, and it repeats. A streamer prints each token as it lands, so Mdm Tan sees the minutes growing. Some APIs can also return the top candidates for each step, and you can watch the model hesitate between two words.

生成不过是循环地“预测下一个 token”。模型给每个可能的下一个 token 一个概率，选出一个加进去，再重复。流式输出器把每个 token 一落地就打印出来，Tan 太太就能看着纪要一点点长出来。有些 API 还能返回每一步的前几名候选，你能看到模型在两个词之间犹豫。

from transformers import TextStreamer def write_minutes(inputs): streamer = TextStreamer(tok, skip_prompt=True) return brain.generate(inputs, streamer=streamer, max_new_tokens=2000) write_minutes(inputs)

Step 4 · Long meetings and misspelled names第 4 步 · 长会议和写错的名字

Learn先学

A two-hour meeting will not fit in the context window (the most text a model can read in one go). Split the transcript into chunks, summarise each chunk, then summarise the summaries. Speech models also misspell names, so list the real names in the prompt. Both fixes go into one helper that reuses the pieces above.

两小时的会议塞不进上下文窗口（模型一次能读的文字上限）。把文字稿切成块，每块先做摘要，再把这些摘要总结一遍。语音模型也常把名字写错，所以把真实名字列在提示词里。两个办法都放进一个复用上面各部分的函数里。

NAMES = "Names that may appear: Mdm Tan, Uncle Raj, Priya, Wei Jie, Auntie Lim." def ask(system, text): msgs = [{"role": "system", "content": system}, {"role": "user", "content": text}] ids = tok.apply_chat_template(msgs, add_generation_prompt=True, return_tensors="pt").to("cuda") out = brain.generate(ids, max_new_tokens=700) return tok.decode(out[0][ids.shape[1]:], skip_special_tokens=True) def minutes_for_long(transcript, size=6000): parts = [transcript[i:i + size] for i in range(0, len(transcript), size)] notes = [ask("Summarise this part of a meeting. " + NAMES, p) for p in parts] return ask(MINUTES_PROMPT + " " + NAMES, "Part summaries:\n" + "\n".join(notes))

Common errors常见报错

• RuntimeError: Found no NVIDIA driver on your system. The notebook has no GPU. Switch the runtime to a GPU one, restart, and run again.
• ffmpeg was not found but is required to load audio files. The speech model cannot read the file. Install ffmpeg and try again.
• torch.OutOfMemoryError: CUDA out of memory. The model or batch is too big for the GPU. Load it in 4-bit, lower the batch size, or pick a smaller model.

• RuntimeError: Found no NVIDIA driver on your system：笔记本没有分到显卡。把运行环境切换成 GPU，重启后再运行。
• ffmpeg was not found but is required to load audio files：语音模型读不了音频文件。安装 ffmpeg 再试。
• torch.OutOfMemoryError: CUDA out of memory：模型或批量对显卡来说太大。改用 4-bit 加载、调小批量，或换更小的模型。

Takeaways要点回顾

• Two models in a row: ears, then brain.
• Speech to text first, then text to minutes.
• A wrong audio format or sampling rate gives an empty transcript.
• The system message defines the shape of the minutes.
• Open models plus 4-bit quantisation make it free to run on a small GPU.
• Generation is next-token prediction in a loop, and a streamer shows it live.
• Chunk what does not fit: summarise the pieces, then the summaries.
• Give the real names in the prompt, and check them.

• 两个模型串起来：先耳朵，后大脑。
• 先语音转文字，再文字转纪要。
• 音频格式或采样率不对，文字稿会是空的。
• system 消息决定纪要的格式。
• 开源模型加 4 位量化，在小 GPU 上免费就能跑。
• 生成就是循环地预测下一个 token，流式输出器让你实时看到。
• 放不下的就分块：先总结每块，再总结这些总结。
• 在提示词里给出真实名字，并且核对。
