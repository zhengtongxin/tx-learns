Step 1 · Set up the run第 1 步 · 设置训练

Learn先学

Use the supervised fine-tuning trainer from the TRL library. A few words first: a step is one update of the model, a batch is the handful of examples used in one step, the learning rate is how big each update is, a checkpoint is a saved copy of the add-on partway through, and the hub is the online store where checkpoints go. Give it the 4-bit base, the LoRA config, a training set and a validation set. The config holds the knobs: one to three epochs (passes over the data), a small learning rate around 1e-4 to 2e-4 for LoRA, a cosine schedule with a short warm-up, and a memory-saving optimiser. If the GPU cannot hold a big batch, feed small ones and accumulate.

用 TRL 库的监督微调训练器。先认几个词：step（步）是模型更新一次，batch（批量）是一步里用的那一小撮例子，学习率是每次更新迈多大，检查点是训练中途存下的附加件副本，hub 是存检查点的线上仓库。把 4 位底座、LoRA 配置、训练集和验证集交给它。配置里是各种旋钮：一到三个 epoch（把数据过几遍）、LoRA 常用的小学习率（约 1e-4 到 2e-4）、带短暂热身的余弦调度，以及省内存的优化器。GPU 装不下大批量，就喂小批量再累积。

from trl import SFTConfig, SFTTrainer args = SFTConfig( output_dir="price-run-01", num_train_epochs=1, per_device_train_batch_size=4, gradient_accumulation_steps=8, # acts like a batch of 32 learning_rate=1e-4, lr_scheduler_type="cosine", warmup_ratio=0.03, optim="paged_adamw_8bit", eval_strategy="steps", eval_steps=200, save_steps=200, push_to_hub=True, # a checkpoint goes online every 200 steps report_to="wandb", run_name="price-run-01", ) trainer = SFTTrainer(model=model, args=args, peft_config=lora, train_dataset=train_set, eval_dataset=val_set) trainer.train()

Step 2 · Two curves: training and validation第 2 步 · 两条曲线：训练与验证

Learn先学

Training loss says how wrong the model is on examples it is learning from. Validation loss says how wrong it is on examples it never trains on. Training loss should go down steadily, though noisily. If validation loss starts to climb while training loss keeps falling, the model is memorising the practice sheet. Stop early, or use fewer epochs.

训练损失告诉你模型在它正在学的例子上错得多厉害。验证损失告诉你它在从不训练的例子上错得多厉害。训练损失应该稳步下降，只是有些抖动。如果验证损失开始上升而训练损失还在下降，模型就是在背练习卷。要提前停，或者少跑几个 epoch。

step train loss validation loss 200 1.10 1.12 400 0.92 0.95 600 0.81 0.93 # validation slowing 800 0.70 0.96 # validation now rising: memorising

Step 3 · Warning signs on the dashboard第 3 步 · 仪表盘上的警告信号

Learn先学

Log the metrics to a dashboard such as Weights & Biases so you can watch from your phone. A loss that spikes or turns into "not a number" garbage usually means the learning rate is too high. GPU memory sitting at the cap means you should lower the batch size or shorten the token cutoff. Time per step times the hourly price gives the bill, so stop if it is blowing the budget. And read a few real generations during the run: a number on a chart can look fine while the answers are nonsense.

把指标记到 Weights & Biases 之类的仪表盘上，就能用手机盯着看。损失突然飙高或变成乱码数字，多半是学习率太高。GPU 内存顶着上限，就减小批量或缩短 token 上限。每步耗时乘以每小时价格就是账单，超预算就停。还要在训练中读几条真实的生成结果：图上的数字可能很好看，答案却是胡说。

signal first thing to try loss shoots up, then garbage numbers ... lower the learning rate out of memory, or memory at the cap ... smaller batch, shorter cutoff validation rising, training falling ... stop, keep the best checkpoint hours x hourly price over budget ...... stop and shrink the run

Step 4 · After the run: the same test as before第 4 步 · 训练之后：用和之前同样的测试

Learn先学

Loss is a proxy. The real question is whether the guesses are good. Load the base model and the saved adapter, then run the same evaluation function on the same held-out test set as the earlier lessons, so the numbers compare fairly. Name every run with a timestamp and save the revision id on the hub, so you can reproduce it.

损失只是替身，真正的问题是估价准不准。加载底座和保存好的附加件，用和前面几课同一个评估函数、同一批留出的测试集来跑，数字才能公平比较。每次训练都用时间戳命名，并记下 hub 上的修订号，才能复现。

# compare checkpoints by test error, not by loss alone # load_with_adapter: a small helper of yours that loads the 4-bit base, then the saved adapter # revisions: the commit ids or branches your checkpoints were pushed under for rev in ["step-400", "step-600", "step-800"]: guesser = load_with_adapter("your-hub-name/price-run-01", revision=rev) print(rev, evaluate(guesser, test_set)) # the same evaluate as before
step-400 64.2 step-600 59.1 step-800 61.7 # step-600 is the one to keep

In plain words用大白话说

Words this lesson uses, in one line each.
• Loss: a score for how wrong the model is; lower is better.
• Checkpoint: a saved copy of the adapter at one moment in training.
• Learning rate: how big each correction step is; too big and training goes wild.
• Epoch: one full pass over the training examples.

这一课用到的词，每个一句话。
• 损失：衡量模型错得多厉害的分数，越低越好。
• 检查点：训练中某一时刻保存下来的适配器副本。
• 学习率：每次修正的步子有多大，太大训练就会失控。
• 轮（epoch）：把全部训练样例完整过一遍。

Common errors常见报错

• torch.OutOfMemoryError: CUDA out of memory. The model or batch is too big for the GPU. Load it in 4-bit, lower the batch size, or pick a smaller model.
• Validation loss goes up while training loss keeps falling. The run is memorising. Stop at the best checkpoint and keep it.
• The loss jumps to a huge number then nan. The learning rate is too high. Cut it by a factor of ten and restart.

• torch.OutOfMemoryError: CUDA out of memory：模型或批量对显卡来说太大。改用 4-bit 加载、调小批量，或换更小的模型。
• 训练损失继续降，验证损失却在升：模型在死记。停在最好的检查点并保留它。
• 损失突然飙到很大然后变成 nan：学习率太高。降到十分之一后重新开始。

Takeaways要点回顾

• Use a supervised fine-tuning trainer with the 4-bit base and the LoRA config.
• One to three epochs, a small learning rate, and accumulate small batches.
• Training loss falling is normal; validation loss rising means memorising.
• Spikes or garbage numbers: lower the learning rate. Memory at the cap: smaller batch or shorter cutoff.
• Watch time and cost, and read a few real generations.
• Push checkpoints, name runs, and save the revision id.
• Judge success with the same test harness as before.

• 用监督微调训练器，配 4 位底座和 LoRA 配置。
• 一到三个 epoch、小学习率，小批量用累积来凑。
• 训练损失下降是正常的；验证损失上升就是在死记。
• 飙高或出现乱码数字：降低学习率。内存顶满：减小批量或缩短截断。
• 盯着耗时和成本，并读几条真实的生成结果。
• 推送检查点、给每次训练命名、记下修订号。
• 用和之前同一套测试流程来判断成败。

Recap小结

1. Watch validation loss, not only training loss.
2. If it rises while training loss falls, the model is memorising: stop and use an earlier checkpoint.
3. Pick the checkpoint by test error in dollars, not by loss.

1. 看验证损失，而不只是训练损失。
2. 如果训练损失在降、验证损失却在升，说明在死记：停下来，用更早的检查点。
3. 用测试集上的美元误差来选检查点，而不是看损失。
