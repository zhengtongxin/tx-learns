Step 1 · Name the job, get a tool第 1 步 · 说出任务名，拿到工具

Learn先学

Hugging Face is the hub where open models live (models anyone can download and run themselves). Its transformers library has two levels. The high level is pipeline("task"): you say the job, it hands back a ready tool. The low level, tokenizer plus model, comes next lesson. Think of ordering at a hawker stall: you say “chicken rice” and do not explain how to cook it.

Hugging Face 是开源模型聚集的地方（任何人都能下载、自己运行的模型）。它的 transformers 库分两层。高层是 pipeline("任务名")：你说出任务，它递给你一个现成的工具。低层是分词器加模型，下一课再讲。就像在小贩中心点餐：你说“鸡饭”，不用解释怎么煮。

from transformers import pipeline feel = pipeline("sentiment-analysis") print(feel("Teacher Priya explains slowly and my son finally gets fractions")) # [{'label': 'POSITIVE', 'score': 0.99...}]
[{'label': 'POSITIVE', 'score': 0.9981}]

Step 2 · One job per pipeline第 2 步 · 一个任务一条 pipeline

Learn先学

Each task name gives a different tool: summarising, translating, answering a question from a passage, pulling out names, or sorting text into labels you invent. The last one, zero-shot-classification, is perfect for Priya: she makes up the labels and needs no training data. The output shape changes with the task, so print it first and look.

每个任务名对应不同的工具：做摘要、翻译、从一段文字里回答问题、抽出人名地名，或者把文字分到你自己定的标签里。最后一个 zero-shot-classification 正适合 Priya：标签自己编，不需要训练数据。输出的形状随任务而变，所以先打印出来看看。

from transformers import pipeline sorter = pipeline("zero-shot-classification") slip = "Please tell me when the next term payment is due." result = sorter(slip, candidate_labels=["praise", "complaint", "fees"]) print(result["labels"][0], result["scores"][0]) # fees 0.9...
fees 0.87

Step 3 · Where it runs, and the first-call download第 3 步 · 在哪里运行，以及第一次调用的下载

Learn先学

The first call to a pipeline downloads a default model, which can be gigabytes. After that it is cached. Then comes the device: on a CPU a big model crawls, so switch the notebook runtime to a GPU and pass device="cuda". Think of the aircon compressor at the void deck: the GPU is the loud machine that does the heavy lifting. You can also choose a different model from the hub for the same task, by name.

第一次调用 pipeline 会下载一个默认模型，可能有好几个 GB，之后就有缓存了。然后是设备：CPU 跑大模型慢得像爬，所以把 notebook 的运行环境切到 GPU，并传 device="cuda"。想想组屋底层嗡嗡响的冷气压缩机：GPU 就是干重活的那台响机器。你也可以按名字从 hub 里换一个别的模型来做同一个任务。

from transformers import pipeline long_letter = open("parent_letter.txt").read() shorten = pipeline("summarization", device="cuda") # or pick the model yourself: # shorten = pipeline("summarization", model="some-org/some-summary-model", device="cuda") print(shorten(long_letter, max_length=60)[0]["summary_text"])

Step 4 · Why bother, when an API exists?第 4 步 · 有 API 了，为什么还要自己跑？

Learn先学

Three reasons. No per-call bill, and the data stays with you. A small model built for one narrow job is often cheaper and faster than a huge general one. And you can swap models freely. The price is that you now own the setup: the GPU, the downloads and the library versions.

三个理由。没有按次计费，数据也留在你手里。专为一个窄任务做的小模型，往往比巨大的通用模型更便宜更快。而且模型可以随便换。代价是整套环境归你管：GPU、下载和库的版本。

What I got wrong我搞错的地方I ran it on a CPU runtime and waited ages, then wondered if it was broken. It just needed a GPU runtime. I also forgot that the first call downloads gigabytes, so I thought the notebook had frozen.我在 CPU 运行环境下跑，等了很久，还以为坏了。其实只要换成 GPU 环境。我还忘了第一次调用会下载好几个 GB，以为 notebook 卡死了。

Common errors常见报错

• OSError: ... can't load model or a very slow first run. The first call downloads the model. Wait for it, check the internet, and keep the disk space free.
• ValueError: Cannot use device 'cuda' or no GPU found. Remove device="cuda" to run on the CPU, slower but it works.
• Token indices sequence length is longer than the specified maximum. The text is longer than the model reads. Split it into parts and summarise each.

• OSError: ... can't load model，或第一次运行特别慢：第一次调用要下载模型。等它下完，检查网络并留够磁盘空间。
• ValueError 提示找不到 cuda 或没有显卡：去掉 device="cuda"，在 CPU 上运行，慢一点但能用。
• Token indices sequence length is longer than the specified maximum：文本比模型能读的更长。切成几段，各自总结。

• You save the API bill but own the setup.
