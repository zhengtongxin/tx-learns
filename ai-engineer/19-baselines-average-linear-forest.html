Predicting with data · Lesson 2用数据做预测 · 第 2 课

Baselines: average, linear, forest基线：平均值、线性、随机森林

You will learn to measure how bad a silly guesser is, so you can tell whether a clever one really helps · ~20 min · concept你会学会先量出“笨办法”有多差，才能判断聪明的办法是不是真的有用 · 约 20 分钟 · 概念课

Where we left off上回讲到

Last time the helper got a clean set of Ah Boy's gadget prices. Today it cannot tell whether a guess for Mdm Tan's second-hand radio is any good. We fix it by building one scoring board and climbing from the silliest guesser upwards.

上回，帮手拿到了 Ah Boy 整理干净的二手价格数据。今天它还没法判断，给 Mdm Tan 那台二手收音机报的价到底准不准。我们先做一块统一的计分板，再从最笨的估价法一路往上试。

Side case支线案例

Wei Jie now has a clean set of gadget descriptions and prices from Ah Boy. He is itching to try a fancy model. Ah Boy stops him: "If a trick cannot beat saying the usual price every time, it is not helping." So Wei Jie builds a fair scoring board first, then climbs from the silliest guesser upwards. The helper has to price things from Ah Boy's data, so it learns how to score a guess first.

Wei Jie 现在有了 Ah Boy 给的、干净的数码产品描述和价格。他迫不及待想试花哨的模型。Ah Boy 拦住他：“如果一个招数赢不过每次都报‘平常价’，那它根本没用。”于是 Wei Jie 先搭一块公平的计分板，再从最笨的猜法一路往上爬。帮手要靠 Ah Boy 的数据估价，所以先学会怎么给估价打分。

Step 1 · One scoring board for everyone第 1 步 · 人人共用一块计分板

Learn先学

Write one function, evaluate(pricer_fn, test_items). It runs every test item through a predictor, then works out the error in dollars for each and the average error. It also draws a scatter plot of guess against truth (the code below does it with matplotlib), where the line y = x is a perfect score. Every predictor is just a function from an item to a number, so any of them plugs in. It is like Priya marking every student with the same answer sheet.

写一个函数 evaluate(pricer_fn, test_items)。它让每个测试项都过一遍预测器，算出每个的美元误差和平均误差，还可以画“猜测对真实”的散点图，y = x 那条线就是满分。每个预测器都只是“从一个 item 到一个数字”的函数，所以谁都能接上。就像 Priya 用同一份答案纸批改每个学生。

import matplotlib.pyplot as plt def evaluate(pricer_fn, test_items): errors = [] for item in test_items: guess = pricer_fn(item) errors.append(abs(guess - item.price)) avg = sum(errors) / len(errors) print(f"average error: ${avg:.2f} over {len(errors)} items") plt.scatter([i.price for i in test_items], [pricer_fn(i) for i in test_items], s=8) plt.xlabel("true price"); plt.ylabel("guess"); plt.show() # the closer to y = x, the better return avg

Step 2 · The floor and the bar第 2 步 · 底线与门槛

Learn先学

First guesser: a random price between 1 and 1000. It is terrible, and that is useful, because it is the floor. Second guesser: always say the average price of the training items. That is the bar. Anything fancier must beat "just say the average", or it is not worth running. train and test are two lists of items from the cleaned dataset: the guessers learn from train, and only test is used for scoring.

第一个猜法：在 1 到 1000 之间随便报个价。它糟透了，但这有用，因为它就是底线。第二个猜法：永远报训练集的平均价。这是门槛。任何更花哨的办法都得赢过“直接报平均价”，否则不值得跑。train 和 test 是整理好的数据集里切出的两份商品清单：预测器从 train 学，只有 test 用来打分。

import random def random_pricer(item): return random.randint(1, 1000) average = sum(i.price for i in train) / len(train) def constant_pricer(item): return average evaluate(random_pricer, test) evaluate(constant_pricer, test)
average error: $412.50 over 250 items average error: $162.40 over 250 items

Step 3 · Numbers vs words第 3 步 · 数字对比文字

Learn先学

Linear regression draws the best straight-line rule from inputs to a price. Give it a few hand-made numbers (weight, a "weight unknown" flag, text length) and it barely improves, because the price information is not in those numbers. Give it word counts instead: count the 1,000 to 2,000 most frequent words, ignoring boring "stop words" like "the". Now "stainless" or "professional" carry signal, and the error drops clearly on the board (your own run shows by how much).

线性回归会画出从输入到价格的最佳直线规则。只给它几个手工做的数字（重量、“重量未知”标记、文字长度），几乎没有改进，因为价格的信息不在这些数字里。改成给它词频：统计最常见的 1000 到 2000 个词，忽略“the”这类无聊的停用词。这样“stainless”“professional”这类词就带上了信号，计分板上的误差明显下降（下降多少，看你自己跑出的结果）。

from sklearn.feature_extraction.text import CountVectorizer from sklearn.linear_model import LinearRegression counter = CountVectorizer(max_features=1500, stop_words="english") X_train = counter.fit_transform([i.summary for i in train]) model = LinearRegression().fit(X_train, [i.price for i in train]) def words_linear_pricer(item): return float(model.predict(counter.transform([item.summary]))[0])

Step 4 · A forest of trees第 4 步 · 一片决策树森林

Learn先学

A random forest is many small decision trees, each asking a chain of yes/no questions, with the answers averaged, a bit like a vote. It catches patterns a straight line cannot, such as "expensive only when both words appear". The cost is time: it is slower to train. Gradient boosting (XGBoost is a popular library for it) grows trees one after another, each fixing the last one's mistakes, and plugs into the harness the same way.

随机森林是许多小决策树，每棵问一连串是非题，答案取平均，有点像投票。它能抓到直线抓不到的规律，比如“两个词同时出现才贵”。代价是时间：训练更慢。梯度提升（XGBoost 是常用的库）让树一棵接一棵地长，每棵修正上一棵的错误，在评分板里用法一样。

from sklearn.ensemble import RandomForestRegressor forest = RandomForestRegressor(n_estimators=100, n_jobs=-1, random_state=42) forest.fit(X_train, [i.price for i in train]) def forest_pricer(item): return float(forest.predict(counter.transform([item.summary]))[0]) evaluate(forest_pricer, test) # same test set as before
average error: $71.30 over 250 items

Put each baseline where it belongs on the ladder, from worst to best.

把每个基线放到阶梯上合适的位置，从最差到最好。

What I got wrong我搞错的地方I compared models on different slices of the data by accident, so the scores meant nothing. I fixed it with one shared test set that every predictor goes through the same evaluate. Also, a few big misses on expensive items dominate the average error, so I look at the scatter plot too.我不小心拿不同的数据切片去比较模型，分数毫无意义。后来改成所有预测器都用同一个测试集、同一个 evaluate。另外，贵东西上的几次大失误会拉高平均误差，所以我也会看散点图。

Common errors常见报错

• ValueError: X has 5000 features, but LinearRegression is expecting .... You fitted on one vectoriser and predicted with another. Reuse the same counter object.
• ZeroDivisionError in evaluate. The test list is empty. Print len(test) first.
• A forest that scores far better on training than on test. It memorised the training rows. Always judge on the held-out test set.

• ValueError: X has 5000 features, but LinearRegression is expecting ...：拟合和预测用了不同的向量器。要复用同一个 counter 对象。
• evaluate 里出现 ZeroDivisionError：测试集是空的。先打印 len(test)。
• 随机森林在训练集上很好、测试集上很差：它把训练行背下来了。永远用留出的测试集来评判。

Now make it yours现在把它变成你的

What changed这一课之后Now the helper can score any price guess on one fair board, so Mdm Tan's radio is judged against the usual-price bar before anything fancy is trusted. The next problem is that averages and forests only see numbers; the next lesson asks whether a neural network or a big cloud model reads the words better.现在帮手能在同一块公平的计分板上给任何估价打分，Mdm Tan 的收音机也先和“平常价”这道门槛比过，再决定要不要信更花哨的办法。下一个问题是平均值和森林只看得懂数字；下一课就看神经网络或云端大模型能不能把文字读得更好。

Takeaways要点回顾

• Build the scoring harness first, then the baselines.
• A random guess is the floor; the training average is the bar.
• Hand-made numbers barely help when the signal is in the words.
• Word counts plus linear regression is a big, cheap jump.
• A random forest finds non-linear patterns but is slower.
• Judge every step with the same metric, on the same test set.
• Traditional ML on good features is a serious opponent for fancy models.

• 先搭评分板，再做基线。
• 随机猜是底线，训练集平均值是门槛。
• 信号藏在文字里时，手工数字帮助很小。
• 词频加线性回归，是便宜又显著的一大步。
• 随机森林能找到非线性规律，但更慢。
• 每一步都用同一个指标、同一个测试集来评判。
• 在好特征上的传统机器学习，是花哨模型的强劲对手。

Recap小结

1. A baseline is a simple guess you must beat: the average, a line, a forest.
2. One evaluate function on one test set keeps every comparison fair.
3. If a fancy model cannot beat the baseline, it is not worth the cost.

1. 基线就是你必须打败的简单猜法：平均数、一条线、一片森林。
2. 同一个 evaluate 函数配同一个测试集，比较才公平。
3. 花哨的模型如果赢不了基线，就不值得那份成本。
