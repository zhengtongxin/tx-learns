Anatomy of an LLM call大模型调用解剖

Calling a model is not magic. It is one web request, and you can write it yourself · ~15 min · hands-on调用模型并不神秘，它就是一次网络请求，你自己也能写 · 约 15 分钟 · 动手实践

Step 1 · A call is one web request第 1 步 · 调用就是一次网络请求

Learn先学

You send one POST to a URL (the endpoint) with a JSON body: a model name and a list of messages. The answer comes back as JSON, nested a few levels deep: a list called choices (usually one answer), whose first item holds a message, whose content is the text. That is the path on the last line of the code. Your API key rides in a header, like a card you tap at a gate.

你向一个网址（endpoint，端点）发一次 POST 请求，请求体是 JSON：模型名加一串消息。答案同样以 JSON 返回，而且套了几层：一个叫 choices 的列表（通常只有一个答案），第一项里有 message，它的 content 才是文字。代码最后一行走的就是这条路径。API key 放在请求头里，就像闸机前刷的那张卡。

# pip install requests openai python-dotenv # save as first_call.py and run: python first_call.py (or paste into one notebook cell) # .env file, one line: OPENAI_API_KEY=your-key-here import os, requests from dotenv import load_dotenv load_dotenv() headers = {"Authorization": f"Bearer {os.getenv('OPENAI_API_KEY')}", "Content-Type": "application/json"} payload = { "model": "gpt-5-mini", "messages": [ {"role": "system", "content": "You are a friendly neighbourhood helper."}, {"role": "user", "content": "Give me one fun fact about durian."}, ], } r = requests.post("https://api.openai.com/v1/chat/completions", headers=headers, json=payload) print(r.json()["choices"][0]["message"]["content"])

Step 2 · Messages: who is speaking第 2 步 · 消息：是谁在说话

Learn先学

Each message has a role and content.
• system: who the model is and what tone to use, set once.
• user: the actual request.
• assistant: what the model said earlier, replayed to rebuild a chat.

每条消息有 role（角色）和 content（内容）。
• system：模型是谁、用什么语气，设一次就行。
• user：真正的请求。
• assistant：模型之前说过的话，回放它来还原对话。

Step 3 · The library is a wrapper; providers share one shape第 3 步 · 库只是包装，各家共用一种格式

Learn先学

Step 1 wrote the request by hand with requests. The openai package is the usual shortcut: it builds the very same request for you. It has no model inside: the model runs on the provider's machine. Many providers copy this format (an OpenAI-compatible endpoint), so switching means changing only base_url, api_key and the model name. Click each to see.

第 1 步用 requests 手写了请求。openai 包是平时用的捷径：它替你构造的是一模一样的请求。它里面没有模型：模型运行在提供商的机器上。许多提供商照搬了这种格式（OpenAI 兼容端点），所以换服务商只需改 base_url、api_key 和模型名。点开看看。

What I got wrong我搞错的地方A key is a password. Keep it in .env, never in a notebook or git. When a call fails, check the key first (stray space or newline), then run the file again (in a notebook, run the cells top to bottom).密钥就是密码：放在 .env 里，别写进笔记本或 git。调用失败时先查密钥（多余的空格或换行），再把文件重新运行一遍（用笔记本的话，把单元格从上到下运行）。

Common errors常见报错

• AuthenticationError: Incorrect API key provided. Key missing, stray space, or .env not loaded. Fix the file and run again (in a notebook, restart it first).
• model_not_found. Wrong model name. Copy it exactly from the provider's list.

• AuthenticationError: Incorrect API key provided：密钥缺失、有多余空格，或 .env 没加载。改好文件，再运行一次（用笔记本的话先重启）。
• model_not_found：模型名写错。从提供商的列表里原样复制。

Now make it yours现在把它变成你的

Takeaways要点回顾

• A model call is one POST with a JSON body; the answer is JSON.
• The body is a model name plus messages, each with a role and content.
• The client library is a thin wrapper with no model inside.
• Providers share one shape: change base URL, key and model to switch.
• A key is a password. Check it first when a call fails.

• 一次模型调用就是带 JSON 请求体的 POST，答案也是 JSON。
• 请求体是模型名加一串消息，每条有角色和内容。
• 客户端库只是薄薄一层包装，里面没有模型。
• 提供商共用一种格式：改基础网址、密钥和模型名即可切换。
• 密钥就是密码，调用失败时先检查它。
