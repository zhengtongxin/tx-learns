Step 1 · A call is one web request第 1 步 · 调用就是一次网络请求

Learn先学

Think of the EZ-Link gate: you tap, the gate answers. A model call has the same shape. You send one POST request to a URL (the endpoint) with a JSON body: a model name and a list of messages. The answer comes back as JSON. Your API key rides along in a header, like your card.

想想 EZ-Link 闸机：你一刷卡，闸机就回应。调用模型也是这个形状。你向一个网址（endpoint，端点）发一次 POST 请求，请求体是 JSON：一个模型名加一串消息。答案同样以 JSON 返回。你的 API key 放在请求头里，就像那张卡。

# one-time setup: pip install requests openai python-dotenv # .env file next to this notebook, one line: OPENAI_API_KEY=your-key-here import os, requests from dotenv import load_dotenv load_dotenv() # reads OPENAI_API_KEY from your .env file headers = {"Authorization": f"Bearer {os.getenv('OPENAI_API_KEY')}", "Content-Type": "application/json"} payload = { "model": "gpt-5-mini", "messages": [ {"role": "system", "content": "You are a friendly neighbourhood helper."}, {"role": "user", "content": "Give me one fun fact about durian."}, ], } r = requests.post("https://api.openai.com/v1/chat/completions", headers=headers, json=payload) print(r.json()["choices"][0]["message"]["content"])
Durians have thorns so sharp that fallen fruit can hurt people, yet the smell is strong enough to be banned on some trains. # example only: the model's wording will differ every run

Step 2 · Messages: who is speaking第 2 步 · 消息：是谁在说话

Learn先学

The messages list is a script. Each item has a role and some content. system says who the model is and what tone to use, set once. user is the actual request. assistant is what the model said earlier, used later to replay a chat.

messages 列表就像一份剧本。每一项有 role（角色）和 content（内容）。system 说明模型是谁、用什么语气，设一次就行；user 是真正的请求；assistant 是模型之前说过的话，之后用来回放对话。

Step 3 · The library is only a wrapper第 3 步 · 库只是一层包装

Learn先学

Typing headers every time gets old. The openai Python package builds that same request for you. It has no model inside. It is a thin helper that posts and reads the JSON back.

每次都手写请求头太烦。openai 这个 Python 包会替你构造同样的请求。它里面没有模型，只是一个很薄的帮手，负责发送请求、读回 JSON。

from openai import OpenAI client = OpenAI() reply = client.chat.completions.create(model="gpt-5-mini", messages=payload["messages"]) print(reply.choices[0].message.content)

What I got wrong我搞错的地方I thought calling a model was magic, and that the openai package had a model inside it. It does not. It only builds the request. The model runs on someone else's machine, and the package just talks to it.我以为调用模型很神秘，还以为 openai 这个包里装着模型。其实不是。它只负责构造请求，模型运行在别人的机器上，这个包只是去和它通信。

Step 4 · One shape, many providers第 4 步 · 一种格式，多家提供商

Learn先学

This chat format got so popular that other providers copied it. They call it an OpenAI-compatible endpoint. So the same client works elsewhere if you change only base_url, api_key and the model name. Even a model on your own laptop (Ollama) speaks it. Click each to see what changes.

这种聊天格式太流行，其他提供商都照着做了，称为 OpenAI 兼容端点。所以只要改 base_url、api_key 和模型名，同一个客户端就能用在别处。连你自己笔记本上的模型（Ollama）也说这种格式。点开看看改了什么。

Step 5 · When the call will not work第 5 步 · 调用跑不通的时候

Learn先学

Check the key before you blame the code. Common causes: no key found, a stray space or newline at either end of the key, or the notebook ran before the .env file was loaded. Run notebook cells top to bottom, or you get a NameError. Models are also retired every few months, so use a current one from the same provider when a name stops working. And a key is a password: keep it in .env, never in the notebook (the file where you run code cell by cell, such as Jupyter), never in git.

先查密钥，再怀疑代码。常见原因：没找到密钥、密钥首尾多了空格或换行、笔记本在加载 .env 之前就运行了。笔记本的单元格要从上到下运行，否则会 NameError。模型也每隔几个月就会下线，名字失效时换成同一家提供商的新模型。另外，密钥就是密码：放在 .env 里，别写进笔记本（一格一格运行代码的文件，例如 Jupyter），别提交到 git。

Common errors常见报错

• AuthenticationError: Incorrect API key provided. The key is missing, has a stray space or newline, or the .env file was not loaded. Print len(os.getenv('OPENAI_API_KEY')), fix the file, then restart the notebook.
• BadRequestError: Unsupported parameter or model_not_found. The model name is wrong or your account cannot use it. Copy the exact name from the provider's list.
• NameError: name 'client' is not defined. A cell ran before the one that creates it. Run the cells from top to bottom.

• AuthenticationError: Incorrect API key provided：密钥缺失、首尾有空格或换行，或者 .env 没有加载。先打印 len(os.getenv('OPENAI_API_KEY'))，改好文件，再重启笔记本。
• BadRequestError: Unsupported parameter 或 model_not_found：模型名写错，或你的账户用不了它。从提供商的列表里原样复制模型名。
• NameError: name 'client' is not defined：定义它的单元格还没运行。请从上到下依次运行单元格。

Takeaways要点回顾

• A model call is one POST with a JSON body. The answer is JSON too.
• The body is a model name plus a list of messages, each with a role and content.
• system sets the tone, user asks, assistant is what was said before.
• The client library is a thin wrapper. There is no model inside it.
• Many providers share one shape, so switching is cheap: change base URL, key and model.
• Local models are private and free to call, but weaker than the big cloud ones.
• A key is a password. Check it first when a call fails.

• 一次模型调用就是带 JSON 请求体的一个 POST，答案也是 JSON。
• 请求体是模型名加一串消息，每条有角色和内容。
• system 定语气，user 提问，assistant 是之前说过的话。
• 客户端库只是薄薄一层包装，里面没有模型。
• 许多提供商共用一种格式，所以切换很便宜：改基础网址、密钥和模型名。
• 本地模型私密、调用免费，但比大型云端模型弱。
• 密钥就是密码。调用失败时先检查它。
