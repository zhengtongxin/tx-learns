Tools, images and voice工具、图像与语音

You will let a model ask your code for facts, then add a picture and a voice · ~20 min · hands-on你会让模型向你的代码要事实，再加上图片和声音 · 约 20 分钟 · 动手实践

Step 1 · A tool is a function you own第 1 步 · 工具就是你自己的函数

Learn先学

A tool is a normal Python function plus a JSON description: name, plain-English purpose, parameters. The model never runs it. It only replies “please call get_price with item=sardines”. The description is a prompt, so write it clearly.

工具就是一个普通 Python 函数，加上一段 JSON 描述：名字、一句大白话的用途、参数。模型从不自己运行它，只会回复“请用 item=沙丁鱼 调用 get_price”。描述就是提示词，要写清楚。

shop_prices = {"sardines": 2.2, "rice 5kg": 11.5, "umbrella": 6.0} def get_price(item): return f"{item}: S${shop_prices.get(item.lower(), 'unknown')}" price_tool = {"type": "function", "function": { "name": "get_price", "description": "Get the price of one item in the shop.", "parameters": {"type": "object", "properties": {"item": {"type": "string"}}, "required": ["item"]}}}

Step 2 · The loop: ask, run, answer第 2 步 · 循环：请求、执行、回答

Learn先学

Call the model with tools=[price_tool]. If finish_reason is "tool_calls", run each requested call (arguments arrive as a JSON string, so json.loads them). Append the assistant message (the model's own reply that asked for the tools; it has to stay in the list), then one tool message per call with its tool_call_id, and call the model again. Wrapped in while, the model can chain tools.

带着 tools=[price_tool] 调用模型。如果 finish_reason 是 "tool_calls"，就执行每个被请求的调用（参数是 JSON 字符串，要先 json.loads）。先加入助手消息（也就是模型自己那条请求工具的回复，必须留在列表里），再为每个调用加一条带 tool_call_id 的 tool 消息，然后再调用模型。用 while 包起来，模型就能连着用工具。

import json from openai import OpenAI client = OpenAI() MODEL = "gpt-5-mini" def run_chat(messages): reply = client.chat.completions.create(model=MODEL, messages=messages, tools=[price_tool]) while reply.choices[0].finish_reason == "tool_calls": asked = reply.choices[0].message messages.append(asked) for call in asked.tool_calls: args = json.loads(call.function.arguments) messages.append({"role": "tool", "tool_call_id": call.id, "content": get_price(**args)}) reply = client.chat.completions.create(model=MODEL, messages=messages, tools=[price_tool]) return reply.choices[0].message.content print(run_chat([{"role": "user", "content": "How much is an umbrella and a tin of sardines?"}]))

Step 3 · Real data, and risk第 3 步 · 真实数据与风险

Learn先学

A dict is a toy; a database makes tools useful. Here a small SQLite table backs get_price, and a second tool changes a price. Reader tools are low risk. Writer tools need care: who may ask for the change? Register the new tool in tools and have your loop run the right function by name.

字典只是玩具，数据库才让工具有用。这里用一张小 SQLite 表支撑 get_price，再加一个会修改价格的工具。只读工具风险低，会写入的工具要小心：谁有权请求修改？把新工具加进 tools，让循环按名字运行对应的函数。

# put this at the top of tool_loop.py: it replaces the toy dict, and the loop below it stays the same import sqlite3 db = sqlite3.connect("shop.db") db.execute("CREATE TABLE IF NOT EXISTS prices (item TEXT PRIMARY KEY, price REAL)") db.execute("INSERT OR IGNORE INTO prices VALUES ('sardines', 2.2), ('umbrella', 6.0)") db.commit() # save the changes to the file def get_price(item): # SQL reads: give me the price column from the prices table for this item. # The ? is filled in safely from the tuple after it; fetchone() returns the first matching row, or None. row = db.execute("SELECT price FROM prices WHERE item = ?", (item.lower(),)).fetchone() return f"{item}: S${row[0]}" if row else f"{item}: unknown" def set_price(item, price): db.execute("INSERT OR REPLACE INTO prices VALUES (?, ?)", (item.lower(), price)) db.commit() return f"{item} is now S${price}" set_price_tool = {"type": "function", "function": { "name": "set_price", "description": "Change the price of one item in the shop.", "parameters": {"type": "object", "properties": {"item": {"type": "string"}, "price": {"type": "number"}}, "required": ["item", "price"]}}} tools = [price_tool, set_price_tool] # pass tools=tools in run_chat functions = {"get_price": get_price, "set_price": set_price} # in the loop: functions[call.function.name](**args)

给一个面向公众的聊天机器人，哪种工具风险更大？

Step 4 · Images and voice are more calls第 4 步 · 图像和语音只是更多的调用

Learn先学

The chat model decides what to say; other models draw or speak it. An image model returns base64 text you decode with PIL; a text-to-speech model returns audio bytes. They are two more API calls. Images cost cents each, so keep them out of loops.

聊天模型决定说什么，别的模型负责画或读出来。图像模型返回 base64 文本，用 PIL 解码；语音合成模型返回音频字节。它们只是再多两次 API 调用。图片每张几分钱，别放进循环里。

import base64 from io import BytesIO from PIL import Image def draw(prompt): result = client.images.generate(model="gpt-image-1", prompt=prompt, size="1024x1024") return Image.open(BytesIO(base64.b64decode(result.data[0].b64_json))) def speak(text): audio = client.audio.speech.create(model="gpt-4o-mini-tts", voice="alloy", input=text) with open("reply.mp3", "wb") as f: f.write(audio.content)

Common errors常见报错

• messages with role 'tool' must follow a tool_calls message. Append the model's tool call first, then the result.
• JSONDecodeError on call.function.arguments. It is a string: json.loads it first.

• messages with role 'tool' must follow a tool_calls message：先加入模型的工具调用，再加结果。
• 对 call.function.arguments 报 JSONDecodeError：它是字符串，先 json.loads。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Tools: the model asks, your code acts.
• The tool description is a prompt; write it clearly.
• Return one tool message for every call id; a while loop allows chained calls.
• Writer tools need care; reader tools are low risk.
• Images and voice are separate models behind separate calls, and images cost money.

• 工具：模型提出请求，你的代码去执行。
• 工具描述就是提示词，要写清楚。
• 每个 call id 都要返回一条 tool 消息；while 循环允许连续调用。
• 会写入的工具要小心，只读工具风险低。
• 图像和语音是不同的模型、不同的调用，图片要花钱。
