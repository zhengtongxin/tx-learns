Step 1 · A tool is a function you own第 1 步 · 工具就是你自己的函数

Learn先学

A tool is a normal Python function. You describe it to the model in JSON: a name, a plain-English description and its parameters. The model never runs it. It only replies “please call get_price with item=sardines”. The description is the prompt, so write it clearly.

工具就是一个普通的 Python 函数。你用 JSON 向模型描述它：名字、一句大白话的说明和参数。模型从不自己运行它，只会回复“请用 item=沙丁鱼 调用 get_price”。说明就是提示词，所以要写清楚。

shop_prices = {"sardines": 2.2, "rice 5kg": 11.5, "umbrella": 6.0} def get_price(item): return f"{item}: S${shop_prices.get(item.lower(), 'unknown')}" price_tool = {"type": "function", "function": { "name": "get_price", "description": "Get the price of one item in Mdm Tan's shop.", "parameters": {"type": "object", "properties": {"item": {"type": "string"}}, "required": ["item"]}}}

Step 2 · The loop: ask, run, answer第 2 步 · 循环：请求、执行、回答

Learn先学

Call the model with tools=[price_tool]. The model sends its arguments back as a JSON string, so json.loads turns it into a dict, and **args spreads that dict into named arguments (get_price(item="sardines")). If the finish_reason is "tool_calls", run each requested call. There can be several in one reply. Append the assistant message, then one tool message per call, each with its tool_call_id. Call the model again so it can answer in words. Wrap it in while so the model can chain tools one after another.

调用模型时带上 tools=[price_tool]。模型把参数以 JSON 字符串的形式传回来，json.loads 把它变成字典，**args 再把字典展开成具名参数（get_price(item="sardines")）。如果 finish_reason 是 "tool_calls"，就执行每一个被请求的调用，一次回复里可能有好几个。先加入助手消息，再为每个调用加一条 tool 消息，各带自己的 tool_call_id。然后再调用一次模型，让它用话说出答案。用 while 包起来，模型就能一个接一个地连着用工具。

import json from openai import OpenAI client = OpenAI() MODEL = "gpt-5-mini" def run_chat(messages): reply = client.chat.completions.create(model=MODEL, messages=messages, tools=[price_tool]) while reply.choices[0].finish_reason == "tool_calls": asked = reply.choices[0].message messages.append(asked) for call in asked.tool_calls: args = json.loads(call.function.arguments) messages.append({"role": "tool", "tool_call_id": call.id, "content": get_price(**args)}) reply = client.chat.completions.create(model=MODEL, messages=messages, tools=[price_tool]) return reply.choices[0].message.content print(run_chat([{"role": "user", "content": "How much is an umbrella and a tin of sardines?"}]))
An umbrella costs S$6.0 and a tin of sardines costs S$2.2.
What I got wrong我搞错的地方I thought the model ran my function. It does not, it only asks. I also forgot to return a tool message for every call id, which gives an API error.我以为模型会运行我的函数。其实不会，它只是发出请求。我还漏了为每个 call id 返回 tool 消息，结果 API 报错。

Step 3 · Real data behind the tool第 3 步 · 工具背后放真实数据

Learn先学

A dict in memory is a toy. Wei Jie swapped it for a small SQLite table and added a second tool that changes a price. Now the model reads and writes real state. That raises a new question: who is allowed to ask for the change? A reader tool is low risk. A writer tool needs thought. SQLite is a database in one file, and SQL is its query language: SELECT reads rows and INSERT writes them. The model must be told about the new tool too, and your loop must run the right function by name.

放在内存里的字典只是玩具。Wei Jie 把它换成一张小小的 SQLite 表，再加了第二个会修改价格的工具。现在模型读写的是真实状态。这就带来新问题：谁有权请求修改？只读的工具风险低，会写入的工具得好好想想。SQLite 是存在一个文件里的数据库，SQL 是它的查询语言：SELECT 读取行，INSERT 写入行。新工具也要告诉模型，而且你的循环要按名字运行对应的函数。

import sqlite3 db = sqlite3.connect("shop.db") db.execute("CREATE TABLE IF NOT EXISTS prices (item TEXT PRIMARY KEY, price REAL)") db.execute("INSERT OR IGNORE INTO prices VALUES ('sardines', 2.2), ('umbrella', 6.0)") # start with some rows db.commit() def get_price(item): row = db.execute("SELECT price FROM prices WHERE item = ?", (item.lower(),)).fetchone() return f"{item}: S${row[0]}" if row else f"{item}: unknown" def set_price(item, price): db.execute("INSERT OR REPLACE INTO prices VALUES (?, ?)", (item.lower(), price)) db.commit() return f"{item} is now S${price}" set_price_tool = {"type": "function", "function": { "name": "set_price", "description": "Change the price of one item in Mdm Tan's shop.", "parameters": {"type": "object", "properties": {"item": {"type": "string"}, "price": {"type": "number"}}, "required": ["item", "price"]}}} tools = [price_tool, set_price_tool] # pass tools=tools in run_chat functions = {"get_price": get_price, "set_price": set_price} # in the loop: functions[call.function.name](**args)

Step 4 · Images and voice are more calls第 4 步 · 图像和语音只是更多的调用

Learn先学

The chat model decides what to say. Other models draw or speak it. An image model takes a prompt and a size and sends back base64 text, which you decode with PIL. A text-to-speech model takes text and a voice and returns audio bytes. These are just two more API calls. Images cost a few cents each, so do not call them in a loop.

聊天模型决定说什么，别的模型负责画或读出来。图像模型收到提示词和尺寸，返回 base64 文本，你用 PIL 解码。语音合成模型收到文字和音色，返回音频字节。它们不过是再多两次 API 调用。图片每张要花几分钱，别放进循环里调用。

import base64 from io import BytesIO from PIL import Image def draw(prompt): result = client.images.generate(model="gpt-image-1", prompt=prompt, size="1024x1024") return Image.open(BytesIO(base64.b64decode(result.data[0].b64_json))) def speak(text): audio = client.audio.speech.create(model="gpt-4o-mini-tts", voice="alloy", input=text) with open("reply.mp3", "wb") as f: f.write(audio.content) return "reply.mp3"

Common errors常见报错

• BadRequestError: messages with role 'tool' must follow a tool_calls message. You sent the tool result without first appending the model's tool call. Append both, in order.
• json.decoder.JSONDecodeError on call.function.arguments. The arguments arrive as a string. Run json.loads on it before use.
• sqlite3.OperationalError: no such table: prices. The table was never created in this file. Run the CREATE TABLE IF NOT EXISTS line first.

• BadRequestError: messages with role 'tool' must follow a tool_calls message：你只发了工具结果，没有先把模型的工具调用加进消息。两者都要按顺序加上。
• 对 call.function.arguments 报 JSONDecodeError：参数是字符串形式传来的，用之前要先 json.loads。
• sqlite3.OperationalError: no such table: prices：这个文件里还没建表。先运行 CREATE TABLE IF NOT EXISTS 那一行。

Takeaways要点回顾

• Tools: the model asks, your code acts.
• The tool description is a prompt, so write it clearly.
• Return one tool message for every call id.
• A while loop lets the model make many and chained calls.
• Real data (a database) makes tools useful. Writer tools need care.
• Images and voice are separate models behind separate calls.
• Images cost money, so do not call them without a reason.
• This is a first step towards agents.

• 工具：模型提出请求，你的代码去执行。
• 工具说明就是提示词，要写清楚。
• 每个 call id 都要返回一条 tool 消息。
• while 循环让模型可以多次、连续地调用。
• 真实数据（数据库）让工具有用，会写入的工具要小心。
• 图像和语音是不同的模型、不同的调用。
• 图片要花钱，没有理由就别调用。
• 这是通往智能体的第一步。
