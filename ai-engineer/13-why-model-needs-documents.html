Last time we chose the helper's model with our own test. Today a resident asks who handles lift complaints, and it names an officer who does not exist. We fix it by giving it Auntie Lim's files along with the question.

上回我们用自己的测试选出了助手的模型。今天居民问谁负责电梯投诉，它却说出一个根本不存在的职员。我们的办法是把 Lim 阿姨的档案连同问题一起交给它。

The story故事

Auntie Lim, the town council clerk, keeps a thick file on every officer and every service. Residents keep asking her the same things. Wei Jie offers to build a helper that answers for her. First he asks a plain model who handles lift complaints, and it replies with a confident name that does not exist.

市镇理事会的文员 Lim 阿姨手上有一厚叠档案，记着每位职员和每项服务。居民总是问她同样的问题。Wei Jie 说他可以做个助手替她回答。他先问一个普通模型：谁负责处理电梯投诉？它自信地答了一个根本不存在的名字。

Step 1 · The model has never seen your files第 1 步 · 模型没见过你的文件

Learn先学

A model learnt from public text up to a cutoff date. It has never read Auntie Lim's files, last week's notice or your company's staff list. When it does not know, it does not stay quiet. It writes something that sounds right. Think of a stranger at the void deck who answers every question with total confidence.

模型学的是截至某个日期的公开文字。它从没读过 Lim 阿姨的档案、上周的通告，或你公司的员工名单。不知道的时候，它不会沉默，而是写出一段听起来很对的话。就像组屋底层来了个陌生人，不管问什么都说得信心十足。

from openai import OpenAI # pip install openai; set OPENAI_API_KEY (calls cost money) client = OpenAI() def ask_plain(question): reply = client.chat.completions.create(model="gpt-5-mini", messages=[ {"role": "user", "content": question}]) return reply.choices[0].message.content print(ask_plain("Who handles lift complaints at Block 12 town council?")) # a smooth answer with a made-up officer name
The lift complaints at Block 12 are handled by Officer Tan Wei Ming. # smooth and confident, and the name is made up

Step 2 · The simplest fix: paste the facts第 2 步 · 最简单的办法：把事实贴进去

Learn先学

If the model lacks the facts, give them to it in the prompt. Wei Jie loads a small folder of markdown files into a dictionary, one file per key, with the key in lowercase. A small function looks at each word of the question. If a word matches a key, that file's text goes into the system message (the hidden note the model reads before your question) for this turn only.

模型缺事实，就在提示词里给它。Wei Jie 把一小个文件夹的 markdown 文件读进一个字典，一个文件对应一个键，键用小写。一个小函数逐个看问题里的词：只要某个词对上了键，这个文件的内容就加进这一轮的 system 消息（模型在读你的问题之前先读的隐藏说明）里。

from pathlib import Path files = {} for path in Path("council_files").glob("*.md"): files[path.stem.lower()] = path.read_text() # "hafiz" -> his page def add_facts(question): words = question.lower().replace("?", "").split() return "\n\n".join(files[w] for w in words if w in files) def ask(question): system = ("Answer about our town council using only the facts below. " "If they do not cover it, say you do not know.\n\n" + add_facts(question)) reply = client.chat.completions.create(model="gpt-5-mini", messages=[ {"role": "system", "content": system}, {"role": "user", "content": question}]) return reply.choices[0].message.content

Step 3 · Why the simple version breaks第 3 步 · 简单版本为什么会坏

Learn先学

This is already RAG: Retrieval first, then Augmented Generation. But it only works on exact words. "Who started the council?" matches no key, so nothing is added. Pasting every file instead is costly and may not fit in the context window (the most text a model can read at once). Even when it fits, a pile of extra text can bury the one useful sentence.

这其实已经是 RAG：先检索（Retrieval），再增强生成（Augmented Generation）。但它只认完全相同的词。“谁创办了理事会？”对不上任何键，所以什么也没加。反过来把所有文件都贴进去，既贵又可能超出上下文窗口（模型一次能读的最多文字）。就算放得下，一大堆多余的文字也会把那句有用的话淹没。

add_facts("Who is Hafiz?") # finds hafiz.md add_facts("Who looks after the lifts?") # words: who, looks, after, the, lifts # no key is called "lifts" -> empty add_facts("Who runs the estate office?") # no matching word -> empty

Step 4 · The RAG recipe, and what else you could try第 4 步 · RAG 的做法，以及其他选择

Learn先学

Real RAG replaces word matching with search by meaning. Prepare once: split the documents into chunks, turn each chunk into a vector (a list of numbers that stands for its meaning), and store them. At question time: turn the question into a vector, fetch the closest chunks, put them in the prompt with the rule "say you do not know if the answer is not here", and let the model answer. The next lessons build each part.

真正的 RAG 用“按意思搜索”取代词语匹配。先准备一次：把文档切成块，把每块变成向量（一串代表它意思的数字），存起来。提问时：把问题也变成向量，取出最接近的几块，放进提示词，并加一条规则“答案不在这里就说不知道”，然后让模型回答。后面几课会逐个造出这些部分。

PREPARE (once) documents -> chunks -> vectors -> store ASK (every question) question -> vector -> closest chunks chunks + rule "say I do not know" -> prompt -> answer Other options: fine-tuning retrains on examples: teaches a style or skill, poor for facts that change long context one huge prompt holding many files: slow and costly on every question RAG cheap, updatable (swap one file), can point to its source

Sort each step: does it happen once beforehand, or on every question?

给每一步分类：是事先做一次，还是每个问题都要做？

What I got wrong我搞错的地方I thought RAG was a database query. It is not. It is a search by meaning, followed by a normal prompt with the found text pasted in. The model still just writes text. We only gave it better pages to read.我以为 RAG 就是查数据库。其实不是。它是按意思去搜，然后把找到的文字贴进一个普通的提示词里。模型照样只是在写文字，只不过我们给了它更好的资料来读。

Common errors常见报错

• AuthenticationError: Incorrect API key provided. The key is missing, has a stray space or newline, or the .env file was not loaded. Print len(os.getenv('OPENAI_API_KEY')), fix the file, then restart the notebook.
• An answer with a confident but made-up name. The model had no documents. Give it the facts and tell it to say "I do not know" when they are missing.
• UnicodeDecodeError: 'charmap' codec can't decode. Open files with encoding="utf-8".

• AuthenticationError: Incorrect API key provided：密钥缺失、首尾有空格或换行，或者 .env 没有加载。先打印 len(os.getenv('OPENAI_API_KEY'))，改好文件，再重启笔记本。
• 答案很自信，名字却是编的：模型手里没有文件。把事实给它，并告诉它缺资料时就说“我不知道”。
• UnicodeDecodeError: 'charmap' codec can't decode：打开文件时加上 encoding="utf-8"。

Now make it yours现在把它变成你的

What changed这一课之后Now the helper reads Auntie Lim's files pasted into the prompt and says what they say instead of guessing a name. The next problem is that this only works on exact words and the thick file will not fit in a prompt, so it must search by meaning.助手现在会读贴进提示词里的 Lim 阿姨的档案，照着档案说，而不是瞎猜名字。下一个问题是这办法只认一模一样的词，而且那叠厚档案塞不进提示词，所以得改成按意思搜索。

Takeaways要点回顾

• A model does not know your private files, and it will guess.
• Put the right facts in the prompt and it answers from them.
• Word lookup is RAG in miniature, but it breaks on different wording.
• Pasting everything is costly, may not fit, and can bury the answer.
• The recipe: chunk, vector, store; then fetch, prompt, answer.
• Fine-tuning suits skills, long context is costly, RAG is cheap and updatable.
• RAG is a search by meaning plus a normal prompt, not a database query.

• 模型不认识你的私人文件，而且它会瞎猜。
• 把对的事实放进提示词，它就会照着回答。
• 词语查找是迷你版 RAG，但换个说法就会失灵。
• 全部贴进去很贵、可能放不下，还会淹没答案。
• 做法：切块、变向量、存起来；然后检索、拼提示词、回答。
• 微调适合技能，长上下文太贵，RAG 便宜又好更新。
• RAG 是“按意思搜索”加一个普通提示词，不是数据库查询。

Recap小结

1. A model alone guesses. Documents give it facts it can quote.
2. Retrieval means finding the few relevant pieces first, then asking.
3. If the pieces do not contain the answer, the helper should say so.

1. 模型单靠自己只能猜，文件能给它可引用的事实。
2. 检索就是先找出少数相关的片段，再提问。
3. 如果片段里没有答案，小帮手应该直说。
