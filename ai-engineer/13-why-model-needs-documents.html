Why models need documents模型为何需要文档

You will see why a model makes things up about your files, and how handing it the right pages fixes that · ~15 min · concept你会明白为什么模型会对你的文件胡编，以及把对的那几页递给它为什么能解决问题 · 约 15 分钟 · 概念课

Step 1 · The model has never seen your files第 1 步 · 模型没见过你的文件

Learn先学

A model learnt from public text up to a cutoff date. It has never read your files, last week's notice or your staff list. When it does not know, it does not stay quiet: it writes something that sounds right.

模型学的是截至某个日期的公开文字。它没读过你的文件、上周的通告或你的员工名单。不知道的时候，它不会沉默，而是写出一段听起来很对的话。

from openai import OpenAI # pip install openai; set OPENAI_API_KEY (calls cost money) client = OpenAI() def ask_plain(question): reply = client.chat.completions.create(model="gpt-5-mini", messages=[ {"role": "user", "content": question}]) return reply.choices[0].message.content print(ask_plain("Who handles lift complaints at Block 12 town council?")) # a smooth answer with a made-up officer name

Step 2 · The simplest fix: paste the facts第 2 步 · 最简单的办法：把事实贴进去

Learn先学

Give the model the facts in the prompt. Load a folder of markdown files into a dictionary (one per lowercase key). For each word of the question, if it matches a key, add that file to the system message for this turn only. This is RAG in miniature: retrieve, then generate. But it breaks: “Who looks after the lifts?” matches no key, and pasting every file is costly, may not fit the context window, and can bury the answer.

在提示词里把事实给模型。把一个文件夹的 markdown 文件读进字典（每个文件一个小写键）。问题里的每个词，若对上某个键，就把那个文件加进这一轮的 system 消息。这是迷你版 RAG：先检索，再生成。但它会坏：“谁负责电梯？”对不上任何键；而把所有文件都贴进去又贵，可能超出上下文窗口，还会淹没答案。

from pathlib import Path files = {} for path in Path("council_files").glob("*.md"): files[path.stem.lower()] = path.read_text(encoding="utf-8") # "hafiz" -> his page def add_facts(question): words = question.lower().replace("?", "").split() return "\n\n".join(files[w] for w in words if w in files) def ask(question): system = ("Answer about our town council using only the facts below. " "If they do not cover it, say you do not know.\n\n" + add_facts(question)) reply = client.chat.completions.create(model="gpt-5-mini", messages=[ {"role": "system", "content": system}, {"role": "user", "content": question}]) return reply.choices[0].message.content

Which are problems of word matching, and which of pasting everything?

哪些是词语匹配的问题，哪些是把所有东西都贴进去的问题？

Step 3 · The RAG recipe第 3 步 · RAG 的做法

Learn先学

Real RAG searches by meaning. Once: split documents into chunks, turn each into a vector (numbers standing for its meaning), store them. Every question: vector the question, fetch the closest chunks, put them in the prompt with the rule “say you do not know if it is not here”. Fine-tuning suits skills, not changing facts; long context is slow and costly on every call. RAG is cheap, updatable and can cite its source.

真正的 RAG 按意思搜索。事先一次：把文档切成块，每块变成向量（代表它意思的数字），存起来。每个问题：把问题变成向量，取出最接近的几块，放进提示词，并加规则“答案不在这里就说不知道”。微调适合技能，不适合会变的事实；长上下文每次调用都又慢又贵。RAG 便宜、好更新，还能指出出处。

Does each step happen once beforehand, or on every question?

每一步是事先做一次，还是每个问题都做？

Common errors常见报错

• A confident, made-up name. The model had no documents: give it the facts and tell it to say “I do not know” when they are missing.
• UnicodeDecodeError. Open files with encoding="utf-8".

• 答案很自信、名字却是编的：模型手里没有文件。把事实给它，并告诉它缺资料时说“我不知道”。
• UnicodeDecodeError：打开文件时加上 encoding="utf-8"。

Now make it yours现在把它变成你的

Takeaways要点回顾

• A model does not know your private files, and it will guess.
• Put the right facts in the prompt and it answers from them.
• Word lookup is RAG in miniature, but breaks on different wording.
• The recipe: chunk, vector, store once; then fetch, prompt, answer per question.
• RAG is search by meaning plus a normal prompt, not a database query.

• 模型不认识你的私人文件，而且它会瞎猜。
• 把对的事实放进提示词，它就会照着回答。
• 词语查找是迷你版 RAG，换个说法就会失灵。
• 做法：切块、变向量、存起来（一次）；每个问题再检索、拼提示词、回答。
• RAG 是按意思搜索加一个普通提示词，不是数据库查询。
