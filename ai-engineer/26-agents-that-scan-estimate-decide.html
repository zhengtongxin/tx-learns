Step 1 · Small agents and an ensemble第 1 步 · 小智能体与组合

Learn先学

Here an agent is a small class with one job that calls a model or a tool. Two price agents:

这里的智能体是只做一件事、去调用模型或工具的小类。两个估价智能体：

  • Specialist: calls a small model you fine-tuned on prices, running as a remote function on Modal (a service that rents a GPU by the second).
  • Frontier agent: finds the five most similar items with known prices, shows them in the prompt, then asks a big model for the price. “Similar” works through embeddings: embedder.encode turns a description into a list of numbers, close numbers mean close meaning, and Chroma is the store that searches them.
  • 专家：调用你用价格数据微调过的小模型，它作为远程函数跑在 Modal（按秒出租 GPU 的服务）上。
  • 云端模型智能体：找出五个价格已知、最相似的商品，放进提示，再让大模型给出价格。“相似”靠向量（embedding）：embedder.encode 把一段描述变成一串数字，数字相近表示意思相近，Chroma 就是用来搜索这些数字的库。

An ensemble agent then combines several estimates with weights fitted on a validation set. Guessers err in different ways, so the mix usually lands closer than any one.

组合智能体再用在验证集上拟合出的权重，把几个估价合起来。估价者犯的错各不相同，混合起来通常比任何一个都更接近真值。

import modal, re class SpecialistAgent: def price(self, description: str) -> float: fn = modal.Function.from_name("price-guesser", "price") return fn.remote(description) class FrontierAgent: def __init__(self, store, embedder, client): # store: a Chroma collection you filled with past items (description as the document, price as metadata) # embedder: a sentence-transformers model; client: an OpenAI client self.store, self.embedder, self.client = store, embedder, client def price(self, description: str) -> float: vec = self.embedder.encode([description]).tolist() near = self.store.query(query_embeddings=vec, n_results=5) lines = [f"{d} costs ${m['price']}" for d, m in zip(near["documents"][0], near["metadatas"][0])] ask = "Similar items and what they cost:\n" + "\n".join(lines) + f"\n\nNow price this one, number only: {description}" reply = self.client.chat.completions.create(model="your-big-model", messages=[{"role": "user", "content": ask}]) found = re.search(r"\d[\d,]*\.?\d*", reply.choices[0].message.content) # the first number, even in "About $120 maybe" return float(found.group().replace(",", "")) if found else 0.0
import numpy as np from sklearn.linear_model import LinearRegression class EnsembleAgent: def __init__(self, agents, val_guesses, val_truth): # agents: any list of guessers with a price() method. Two here; a third (say a random forest) fits the same way. # val_guesses: one column per agent, from validation items self.agents = agents self.fit = LinearRegression(positive=True).fit(val_guesses, val_truth) def price(self, description: str) -> float: guesses = np.array([[a.price(description) for a in self.agents]]) return float(self.fit.predict(guesses)[0])

Step 2 · A scanner and a messenger第 2 步 · 扫描员和信使

Learn先学

The scanner pulls a feed of deals and asks a model to pick the five best-described ones in a strict schema (description, price, link), so the next step never guesses at text. The messenger sends a short push notification when a deal looks good.

扫描员拉取优惠信息，让模型按严格的结构（描述、价格、链接）挑出描述最清楚的五个，下一步就不用猜文字。信使在优惠看起来不错时发一条简短的推送通知。

import os from openai import OpenAI from pydantic import BaseModel import requests client = OpenAI() APP_TOKEN, USER_KEY = os.getenv("PUSHOVER_TOKEN"), os.getenv("PUSHOVER_USER") # from .env class Deal(BaseModel): description: str price: float url: str class DealList(BaseModel): deals: list[Deal] class ScannerAgent: def scan(self, feed_text: str) -> list[Deal]: reply = client.beta.chat.completions.parse( model="your-cheap-model", response_format=DealList, messages=[{"role": "user", "content": "Pick the five deals with the clearest descriptions:\n" + feed_text}]) return reply.choices[0].message.parsed.deals class MessengerAgent: def alert(self, deal: Deal, estimate: float) -> None: text = f"Deal: {deal.description} for ${deal.price} (worth about ${estimate:.0f}) {deal.url}" requests.post("https://api.pushover.net/1/messages.json", data={"token": APP_TOKEN, "user": USER_KEY, "message": text})

Step 3 · The planner: a fixed workflow first第 3 步 · 规划者：先做固定流程

Learn先学

The planner coordinates. The simplest version is a workflow you write yourself: scan, ask the ensemble for each deal, notify if estimate minus price passes a threshold. It is predictable and cheap. Add memory: keep sent deals in a JSON file so none is sent twice.

规划者负责协调。最简单的版本是你自己写的流程：扫描，对每个优惠请组合智能体估价，估价减去标价超过阈值就通知。它可预测又便宜。再加上记忆：把已发的优惠存进 JSON 文件，不会发两次。

import json, os SEEN = "seen_deals.json" class PlannerAgent: def __init__(self, scanner, ensemble, messenger, threshold=50): self.scanner, self.ensemble, self.messenger, self.threshold = scanner, ensemble, messenger, threshold self.seen = set(json.load(open(SEEN))) if os.path.exists(SEEN) else set() def run(self, feed_text): found = [] for deal in self.scanner.scan(feed_text): if deal.url in self.seen: continue estimate = self.ensemble.price(deal.description) if estimate - deal.price > self.threshold: self.messenger.alert(deal, estimate) self.seen.add(deal.url) found.append((deal, estimate)) json.dump(sorted(self.seen), open(SEEN, "w")) return found

Step 4 · Let the planner decide: tools and a step cap第 4 步 · 让规划者自己决定：工具和步数上限

Learn先学

The alternative is autonomy: let a model choose the order. A tool is a function of yours that you describe to the model in JSON: a name, what it does, and its inputs. The model cannot run it. It replies with a tool call (a name and arguments), your loop runs the matching function from handlers, appends the result as a tool message, and asks again, until the model answers in plain text. Build the loop first with fake tools returning canned data. Always add a step cap and a clear instruction, or it may loop.

另一种选择是自主：让模型自己选顺序。工具就是你自己的函数，用 JSON 向模型描述：名字、做什么、要什么输入。模型不能直接运行它，只会回复一个工具调用（名字和参数）；你的循环从 handlers 里找到对应函数去运行，把结果作为 tool 消息追加进去，再问一次，直到模型用普通文字回答。先用返回固定数据的假工具把循环搭出来。一定要加步数上限和明确的指示，否则它可能原地打转。

import json from openai import OpenAI client = OpenAI() tools = [{"type": "function", "function": {"name": name, "description": desc, "parameters": {"type": "object", "properties": props, "required": list(props)}}} for name, desc, props in [ ("scan_for_bargains", "Get the five best current deals", {}), ("estimate_value", "Estimate the true price of an item", {"description": {"type": "string"}}), ("notify_user", "Send a phone alert about one deal", {"message": {"type": "string"}})]] def run_planner(handlers, max_steps=8): messages = [{"role": "system", "content": "Scan once, estimate each deal once, notify only for big gaps, then stop."}, {"role": "user", "content": "Find me bargains."}] for _ in range(max_steps): # the cap reply = client.chat.completions.create(model="your-cheap-model", messages=messages, tools=tools) msg = reply.choices[0].message messages.append(msg) if not msg.tool_calls: return msg.content for call in msg.tool_calls: result = handlers[call.function.name](**json.loads(call.function.arguments)) messages.append({"role": "tool", "tool_call_id": call.id, "content": json.dumps(result)}) return "Stopped: step cap reached." # fake tools first: one plain function per tool name, each returning canned data handlers = { "scan_for_bargains": lambda: [{"description": "Mirrorless camera kit", "price": 420}], "estimate_value": lambda description: {"estimate": 610}, "notify_user": lambda message: {"sent": True}, } print(run_planner(handlers))

Fixed workflow or autonomous planner?

固定流程还是自主规划者？

What I got wrong我搞错的地方I gave the planner too much freedom and it kept re-scanning. A step cap and "scan once, estimate each deal once" fixed it.我给规划者的自由太多，它不停地重复扫描。加上步数上限和“只扫描一次，每个优惠只估价一次”就好了。
Common errors常见报错Function price-guesser/price not found: deploy the remote app under that name first. The loop never ends: keep max_steps. The same deal alerts every run: save seen_deals.json after each run.Function price-guesser/price not found：先用这个名字部署远程应用。循环停不下来：保留 max_steps。同一个优惠每次都提醒：每次运行后写入 seen_deals.json。

Now make it yours现在把它变成你的

Takeaways要点回顾

• An agent here is a small class with one job that calls a model or a tool.
• Combine several imperfect opinions with weights fitted on a validation set.
• Structured outputs keep hand-offs dependable.
• A fixed workflow is cheap and predictable; autonomy is flexible but needs a step cap and memory.

• 这里的智能体是只做一件事、调用模型或工具的小类。
• 用在验证集上拟合出权重的方式，把几个不完美的意见合起来。
• 结构化输出让交接可靠。
• 固定流程便宜且可预测；自主灵活，但需要步数上限和记忆。
