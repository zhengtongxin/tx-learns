Step 1 · Small agents, one job each第 1 步 · 小智能体，各司其职

Learn先学

Here an agent is not magic. It is a small class with one job that calls a model or a tool. The specialist calls the tuned model on the serverless GPU. The frontier agent uses retrieval: it embeds the item with a small sentence model (384 numbers), fetches the five most similar items with known prices from a Chroma store, shows them in the prompt as "similar items and what they cost", then asks a big model for the price. Both return a number.

这里的智能体并不神秘。它就是一个只做一件事、去调用模型或工具的小类。专家去调用无服务器 GPU 上的微调模型。云端模型智能体用检索：用一个小的句子模型把商品变成 384 个数字，从 Chroma 库里取出五个价格已知、最相似的商品，在提示里作为“相似商品和它们的价钱”展示，再让大模型给出价格。两者都返回一个数字。

class SpecialistAgent: def price(self, description: str) -> float: fn = modal.Function.from_name("price-guesser", "price") return fn.remote(description) class FrontierAgent: def __init__(self, store, embedder, client): self.store, self.embedder, self.client = store, embedder, client def price(self, description: str) -> float: vec = self.embedder.encode([description]).tolist() near = self.store.query(query_embeddings=vec, n_results=5) lines = [f"{d} costs ${m['price']}" for d, m in zip(near["documents"][0], near["metadatas"][0])] ask = "Similar items and what they cost:\n" + "\n".join(lines) + f"\n\nNow price this one, number only: {description}" reply = self.client.chat.completions.create(model="your-big-model", messages=[{"role": "user", "content": ask}]) return float(reply.choices[0].message.content.strip().lstrip("$"))

Step 2 · Several opinions beat one第 2 步 · 几个意见胜过一个

Learn先学

Add the small trained neural network from the earlier lessons as a third opinion. Then an ensemble agent combines the three estimates with a weighted average. Pick the weights by fitting them on a validation set, so the better guessers count for more. Individual guessers are imperfect in different ways, and the mix usually lands closer than any one of them.

把前面几课训练的小神经网络加进来，当作第三个意见。然后由组合智能体用加权平均把三个估价合起来。权重用验证集拟合出来，让更准的估价者占更大比重。每个估价者的不完美各不相同，混合起来通常比其中任何一个都更接近真值。

import numpy as np from sklearn.linear_model import LinearRegression class EnsembleAgent: def __init__(self, agents, val_guesses, val_truth): # val_guesses: one column per agent, from validation items self.agents = agents self.fit = LinearRegression(positive=True).fit(val_guesses, val_truth) def price(self, description: str) -> float: guesses = np.array([[a.price(description) for a in self.agents]]) return float(self.fit.predict(guesses)[0])

Step 3 · A scanner and a messenger第 3 步 · 扫描员和信使

Learn先学

The scanner agent pulls a feed of current deals from the web, then asks a model to pick the five best-described ones and return them in a strict structured shape: description, price, link. Structured outputs force the model to fill that exact schema, so the next step never has to guess at text. The messenger agent sends a push notification to Wei Jie's phone with a short, model-written message when a deal looks good.

扫描智能体从网上拉取当前的优惠信息，再让模型挑出描述最清楚的五个，按严格的结构返回：描述、价格、链接。结构化输出会强制模型填满这个固定格式，下一步就不用去猜文字。信使智能体在优惠看起来不错时，往 Wei Jie 的手机发一条由模型写的简短推送通知。

from pydantic import BaseModel import requests class Deal(BaseModel): description: str price: float url: str class DealList(BaseModel): deals: list[Deal] class ScannerAgent: def scan(self, feed_text: str) -> list[Deal]: reply = client.beta.chat.completions.parse( model="your-cheap-model", response_format=DealList, messages=[{"role": "user", "content": "Pick the five deals with the clearest descriptions:\n" + feed_text}]) return reply.choices[0].message.parsed.deals class MessengerAgent: def alert(self, deal: Deal, estimate: float) -> None: text = f"Deal: {deal.description} for ${deal.price} (worth about ${estimate:.0f}) {deal.url}" requests.post("https://api.pushover.net/1/messages.json", data={"token": APP_TOKEN, "user": USER_KEY, "message": text})

Step 4 · The planner, fixed workflow first第 4 步 · 规划者：先做固定流程

Learn先学

The planning agent is the coordinator. The simplest version is a fixed workflow you wrote yourself: scan, then for each deal ask the ensemble for the estimate, then if the estimate minus the deal price is bigger than a threshold, notify. It is predictable and cheap. Add memory: keep the deals you have already sent in a JSON file so the same one is never sent twice, and give each agent its own colour in the log so you can watch the flow.

规划智能体是协调者。最简单的版本是你自己写好的固定流程：先扫描，再对每个优惠请组合智能体估价，如果“估价减去优惠价”大于某个阈值，就通知。它可预测，也便宜。再加上记忆：把已经发过的优惠存进一个 JSON 文件，同一个就不会发两次；日志里让每个智能体用自己的颜色，方便你看流程。

import json, os SEEN = "seen_deals.json" class PlannerAgent: def __init__(self, scanner, ensemble, messenger, threshold=50): self.scanner, self.ensemble, self.messenger, self.threshold = scanner, ensemble, messenger, threshold self.seen = set(json.load(open(SEEN))) if os.path.exists(SEEN) else set() def run(self, feed_text): found = [] for deal in self.scanner.scan(feed_text): if deal.url in self.seen: continue estimate = self.ensemble.price(deal.description) if estimate - deal.price > self.threshold: self.messenger.alert(deal, estimate) self.seen.add(deal.url) found.append((deal, estimate)) json.dump(sorted(self.seen), open(SEEN, "w")) return found

Step 5 · Let the planner decide: tools and a step cap第 5 步 · 让规划者自己决定：工具和步数上限

Learn先学

The other option is autonomy. Give the planner a model and three tools with JSON descriptions: scan for bargains, estimate true value, notify the user. Then let it choose the order. Build the loop first with fake tool functions that return canned data, so you can see the tool-calling loop work before any real agent or money is involved. Always add a cap on steps and a clear instruction, or it may loop.

另一种选择是自主。给规划者一个模型和三个带 JSON 描述的工具：扫描优惠、估算真实价值、通知用户。然后让它自己选顺序。先用返回固定数据的假工具函数把循环搭出来，这样在涉及真正的智能体和钱之前，你就能看到工具调用循环怎么跑。一定要加步数上限和明确的指示，否则它可能原地打转。

tools = [{"type": "function", "function": {"name": name, "description": desc, "parameters": {"type": "object", "properties": props, "required": list(props)}}} for name, desc, props in [ ("scan_for_bargains", "Get the five best current deals", {}), ("estimate_value", "Estimate the true price of an item", {"description": {"type": "string"}}), ("notify_user", "Send a phone alert about one deal", {"message": {"type": "string"}})]] def run_planner(handlers, max_steps=8): messages = [{"role": "system", "content": "Scan once, estimate each deal once, notify only for big gaps, then stop."}, {"role": "user", "content": "Find me bargains."}] for _ in range(max_steps): # the cap reply = client.chat.completions.create(model="your-cheap-model", messages=messages, tools=tools) msg = reply.choices[0].message messages.append(msg) if not msg.tool_calls: return msg.content for call in msg.tool_calls: result = handlers[call.function.name](**json.loads(call.function.arguments)) messages.append({"role": "tool", "tool_call_id": call.id, "content": json.dumps(result)}) return "Stopped: step cap reached."

Fixed workflow or autonomous planner?

固定流程还是自主规划者？

What I got wrong我搞错的地方I gave the autonomous planner too much freedom and it kept re-scanning in a loop. A cap on the number of steps and a clear instruction ("scan once, then estimate each deal once") fixed it.我给自主规划者的自由太多，它不停地重复扫描，陷入循环。加上步数上限和一句明确的指示（“只扫描一次，每个优惠只估价一次”）就好了。

Takeaways要点回顾

• Agents here are small classes with one job that call a model or a tool.
• Retrieval grounds a big model's guess in similar items with known prices.
• Combine several imperfect opinions with weights fitted on a validation set.
• Structured outputs keep hand-offs between agents dependable.
• A fixed workflow is cheap and predictable; autonomy is flexible but needs limits.
• Test the tool loop with fake tools before wiring real agents.
• Add memory so nothing is repeated, a step cap, and logs.

• 这里的智能体是只做一件事、调用模型或工具的小类。
• 检索让大模型的估价有“带已知价格的相似商品”做依据。
• 用在验证集上拟合出权重的方式，把几个不完美的意见合起来。
• 结构化输出让智能体之间的交接可靠。
• 固定流程便宜且可预测；自主灵活，但需要限制。
• 先用假工具测试工具循环，再接上真正的智能体。
• 加上记忆避免重复、步数上限和日志。
