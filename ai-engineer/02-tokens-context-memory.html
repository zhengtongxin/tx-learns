Step 1 · Tokens: what the model reads第 1 步 · token：模型读的东西

Learn先学

Models read tokens, not letters or words: text chunks turned into numbers. A common word is often one token; a rare word or name splits into several. Price and the context window (the most tokens one call can hold) are both counted in tokens.

模型读的是 token，不是字母或单词：被切成小块并变成数字的文本。常见词往往是一个 token，生僻词或人名会拆成几个。价格和上下文窗口（一次调用最多能装的 token 数）都按 token 计。

Step 2 · A model has no memory第 2 步 · 模型没有记忆

Learn先学

Every call is stateless, like tapping a gate: it does not know you tapped yesterday. A chat app “remembers” by sending the whole conversation so far on every turn. Try it below.

每次调用都是无状态的，就像刷卡过闸机：它不知道你昨天刷过。聊天应用靠每一轮都把到目前为止的整段对话发出去来“记住”。下面试试。

Step 3 · You write the loop第 3 步 · 循环由你来写

Learn先学

Keep a list. Append the user message, call the model, append the reply, repeat. The list is the memory.

留一个列表：加入用户消息，调用模型，加入回复，如此循环。这个列表就是记忆。

from openai import OpenAI client = OpenAI() history = [{"role": "system", "content": "You are a helpful assistant"}] def chat(text): history.append({"role": "user", "content": text}) reply = client.chat.completions.create(model="gpt-5-mini", messages=history) answer = reply.choices[0].message.content history.append({"role": "assistant", "content": answer}) return answer

Step 4 · The cost and the cap第 4 步 · 成本与上限

Learn先学

Each turn re-sends everything, so a long chat costs more every turn. The context window is the cap: past it, you must drop or summarise old turns. Putting facts into the messages is also how you give a model knowledge it never had, which leads to retrieval (RAG) later.

每一轮都要把全部内容重发，所以聊得越长越贵。上下文窗口就是上限：超出时，必须丢掉或总结旧的对话。把事实放进消息里，也是给模型它原本没有的知识的办法，后面的检索（RAG）就由此而来。

Common errors常见报错

• BadRequestError: ... maximum context length. The history outgrew the limit. Trim or summarise old messages before sending.
• NameError: name 'client' is not defined. Run cells top to bottom.

• BadRequestError: ... maximum context length：聊天记录超过了上限。发送前先裁掉或总结旧消息。
• NameError: name 'client' is not defined：请从上到下依次运行单元格。

Takeaways要点回顾

• Models read tokens; price and the context limit are counted in them.
• Rare words, names and typos split into more tokens.
• Every call is stateless: “memory” is the app resending the conversation.
• You manage the history: append, call, append, repeat.
• Long chats cost more every turn and eventually hit the context window.

• 模型读的是 token，价格和上下文上限都按它计。
• 生僻词、人名和错别字会拆成更多 token。
• 每次调用都无状态：“记忆”就是应用把对话重发一遍。
• 历史由你管理：加入、调用、加入，再循环。
• 长对话每轮更贵，最终会撞上上下文窗口。
