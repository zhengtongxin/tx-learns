Step 1 · Tokens: what the model really reads第 1 步 · token：模型真正读的东西

Learn先学

Models do not read letters or words. They read tokens: chunks of text turned into numbers. A common word is often one token. A rare word or a name splits into several. You can look with tiktoken (install it with pip install tiktoken): encode turns text into token numbers and decode turns a number back into its text chunk. Why care? Price is per token (in and out), and the context window (the most tokens one call can hold, explained in Step 5) is a limit counted in tokens.

模型读的不是字母或单词，而是 token：被切成小块并变成数字的文本。常见的词往往是一个 token，生僻词或人名会被拆成几个。你可以用 tiktoken（pip install tiktoken 安装）看一看：encode 把文字变成 token 编号，decode 把编号变回对应的文字块。为什么要在意？因为价格按 token 算（输入和输出都算），上下文窗口（一次调用最多能装下的 token 数，第 5 步会讲）的上限也是按 token 数的。

import tiktoken enc = tiktoken.get_encoding("o200k_base") ids = enc.encode("Two teh peng, one chicken rice, less chilli please") for i in ids: print(i, repr(enc.decode([i])))
<id> 'Two' <id> ' te' <id> 'h' <id> ' peng' <id> ',' <id> ' one' <id> ' chicken' <id> ' rice' <id> ',' <id> ' less' <id> ' chilli' <id> ' please' # shape only: each <id> is a number, and the exact pieces depend on the tokenizer

Step 2 · A model has no memory第 2 步 · 模型没有记忆

Learn先学

Every call is stateless, like tapping into a gate: it does not know you tapped in yesterday. Wei Jie told the model what was wrong with the phone in one call and asked about it in the next, and got nothing. The second call never contained the first. Try it below.

每次调用都是无状态的，就像刷卡过闸机：它不知道你昨天刷过。Wei Jie 在一次调用里告诉模型手机哪里坏了，下一次调用再问，结果一无所知，因为第二次调用里根本没有第一次的内容。下面试试。

Step 3 · Memory is the whole chat, sent again第 3 步 · 记忆就是把整段对话再发一遍

Learn先学

A chat app “remembers” by sending the whole conversation so far on every turn. The model just predicts the most likely next tokens. If the text says “I fix phones” earlier, the likeliest answer to “what do I do?” contains “fix phones”.

聊天应用靠每一轮都把到目前为止的整段对话发出去来“记住”。模型只是预测最可能的下一批 token。如果前面的文字里有“我修手机”，那么回答“我是做什么的？”时，最可能的答案就会包含“修手机”。

messages = [ {"role": "system", "content": "You are a helpful assistant"}, {"role": "user", "content": "Hi, I'm Wei Jie and I fix phones."}, {"role": "assistant", "content": "Hi Wei Jie! How can I help?"}, {"role": "user", "content": "What do I do for a living?"}, ]
What I got wrong我搞错的地方I thought the model remembered me between sessions. It does not. When a product seems to remember you, the product stored it and sent it again.我以为模型在不同会话之间会记得我。其实不会。产品看起来记得你，是因为产品自己存了下来，再发给模型。

Step 4 · You write the loop第 4 步 · 循环由你来写

Learn先学

So you manage memory yourself. Keep a list. Append the user message, call the model, append the reply, repeat. The list is the memory. This reuses the call from the last lesson.

所以记忆要你自己管理。留一个列表：加入用户消息，调用模型，加入回复，如此循环。这个列表就是记忆。调用方式沿用上一课。

from openai import OpenAI client = OpenAI() history = [{"role": "system", "content": "You are a helpful assistant"}] def chat(text): history.append({"role": "user", "content": text}) reply = client.chat.completions.create(model="gpt-5-mini", messages=history) answer = reply.choices[0].message.content history.append({"role": "assistant", "content": answer}) return answer

Step 5 · The cost and the cap第 5 步 · 成本与上限

Learn先学

Each turn re-sends everything, so a long chat costs more with every turn. The context window is the cap, counted in tokens. When a chat grows past it, something must be dropped or summarised. Putting facts into the messages is also how you give a model knowledge it never had. That idea leads straight to retrieval (RAG, retrieval-augmented generation: look up the right text first, then put it in the prompt) later.

每一轮都要把全部内容重发，所以聊得越长，每一轮越贵。上下文窗口就是上限，按 token 计数。对话超出时，必须丢掉一些或做摘要。把事实放进消息里，也是给模型它原本没有的知识的办法，这个想法后面会直接通向检索（RAG，检索增强生成：先查出相关文字，再放进提示词）。

Takeaways要点回顾

• Models read tokens, not letters or words.
• Price and the context limit are both counted in tokens, in and out.
• Rare words, names and typos split into more tokens, so they cost more.
• Every call is stateless. The model remembers nothing between calls.
• “Memory” is the app sending the whole conversation again each turn.
• Long chats cost more every turn and hit the context window.
• You manage the history: append, call, append, repeat.

• 模型读的是 token，不是字母或单词。
• 价格和上下文上限都按 token 计，输入输出都算。
• 生僻词、人名和错别字会被拆成更多 token，所以更贵。
• 每次调用都是无状态的，两次调用之间模型什么都不记得。
• “记忆”就是应用每一轮把整段对话再发一遍。
• 长对话每一轮都更贵，还会撞上上下文窗口。
• 历史由你来管理：加入、调用、加入，再循环。
