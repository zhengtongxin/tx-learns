Step 1 · A tokenizer turns text into numbers第 1 步 · 分词器把文字变成数字

Learn先学

A model only reads numbers. The tokenizer cuts text into pieces and gives each piece an id from its vocabulary. Every model family has its own tokenizer, so the same sentence becomes different ids and a different count in each. It is like the EZ-Link gate: each system reads only its own card.

模型只读数字。分词器把文字切成小块，从词表里给每块一个 id。每个模型家族有自己的分词器，所以同一句话在不同家族里 id 和数量都不一样。就像 EZ-Link 闸机：每个系统只认自己的卡。

from transformers import AutoTokenizer name = "some-org/some-chat-model" # pick an open chat model from the hub tok = AutoTokenizer.from_pretrained(name) ids = tok.encode("The lift on level 7 is under repair") print(len(ids), ids) print(tok.decode(ids))
8 [1, 791, 11, 389, 3, 10, 5, 22] # your ids differ per model The lift on level 7 is under repair

Step 2 · The chat template: the layout it was trained on第 2 步 · 对话模板：训练时用的版式

Learn先学

A chat model was trained on text laid out in a specific way, with special tokens marking who is speaking. Different families use different markers. Do not hand-write them. Give the tokenizer the same list of role-and-content dicts you use with an API, and apply_chat_template builds the exact layout. API providers do this for you behind the scenes.

聊天模型训练时见到的文字有特定的版式，用特殊 token 标明谁在说话。不同家族的标记不一样，不要手写。把和 API 一样的角色加内容列表交给分词器，apply_chat_template 就会生成准确的版式。API 服务商在背后替你做了这件事。

messages = [ {"role": "system", "content": "You read lift notices in a warm, clear voice."}, {"role": "user", "content": "Lift B is closed on Tuesday for servicing."}, ] text = tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True) print(text) # look at the special markers it added

Step 3 · Load the model and generate第 3 步 · 加载模型并生成

Learn先学

Now pair the tokenizer with its model. Both must come from the same family and name, or you get nonsense. device_map="auto" puts the weights on the GPU. Then encode the chat, call generate, and decode the new ids. Some models need you to accept a licence and use an access token (a key you create on the hub's website) first.

现在把分词器和它的模型配成一对。两者必须来自同一个家族、同一个名字，否则会出一堆乱码。device_map="auto" 会把权重放到 GPU 上。然后编码对话、调用 generate、再把新生成的 id 解码。有些模型需要你先接受许可协议，并使用 hub 的访问令牌（你在 hub 网站上生成的一串密钥）。

from transformers import AutoModelForCausalLM model = AutoModelForCausalLM.from_pretrained(name, device_map="auto") print(model.get_memory_footprint() / 1e9, "GB") inputs = tok.apply_chat_template(messages, add_generation_prompt=True, return_tensors="pt").to("cuda") out = model.generate(inputs, max_new_tokens=80) print(tok.decode(out[0][inputs.shape[1]:])) # only the new ids
15.2 GB Lift B is closed on Tuesday for a service. Please use Lift A.

Step 4 · Squeeze it with 4-bit quantisation, and stream第 4 步 · 用 4 位量化压缩，并流式输出

Learn先学

A full-precision model of a few billion parameters (the numbers inside it) can fill a whole free GPU. Quantisation stores each weight in 4 bits instead of 16, so memory drops to about a quarter and quality dips only a little. That is how an 8-billion-parameter model fits. Memory, not speed, is the first wall. Add a text streamer so words appear as they are made, instead of a blank cell.

几十亿参数（模型内部的数字）的全精度模型，可能就把一整块免费 GPU 占满。量化把每个权重从 16 位改成 4 位存，内存降到大约四分之一，质量只掉一点点。80 亿参数的模型就是这样塞得下的。第一堵墙是内存，不是速度。再加一个文本流式输出器，让字边生成边显示，不用盯着空白格子。

import torch from transformers import BitsAndBytesConfig, TextStreamer small = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_compute_dtype=torch.bfloat16) model = AutoModelForCausalLM.from_pretrained(name, device_map="auto", quantization_config=small) print(model.get_memory_footprint() / 1e9, "GB") # roughly a quarter streamer = TextStreamer(tok) model.generate(inputs, streamer=streamer, max_new_tokens=80)
4.1 GB Lift B is closed on Tuesday for a service. Please use Lift A.

What I got wrong我搞错的地方I paired a tokenizer from one family with a model from another and got nonsense, because the ids meant different things. Tokenizer and model must match. I also hit a locked model: I had to accept its licence and log in with a hub token first.我把一个家族的分词器配给另一个家族的模型，结果全是乱码，因为同一个 id 的含义不同。分词器和模型必须配对。我还遇到过上锁的模型：得先接受它的许可协议，并用 hub 令牌登录。

Common errors常见报错

• OSError ... is a gated repo / 401 Unauthorized. The model asks you to accept its licence first. Accept it on the model page, then log in with huggingface-cli login.
• torch.OutOfMemoryError: CUDA out of memory. The model or batch is too big for the GPU. Load it in 4-bit, lower the batch size, or pick a smaller model.
• Garbled output or a repeated prompt in the answer. You decoded the whole output. Slice from inputs.shape[1] to print only the new tokens.

• OSError ... is a gated repo / 401 Unauthorized：该模型要先同意它的许可。到模型页面点同意，再用 huggingface-cli login 登录。
• torch.OutOfMemoryError: CUDA out of memory：模型或批量对显卡来说太大。改用 4-bit 加载、调小批量，或换更小的模型。
• 输出乱码，或答案里夹着重复的提问：你解码了整段输出。从 inputs.shape[1] 之后切片，只打印新生成的部分。

Takeaways要点回顾

• A tokenizer turns text into ids, and each model family has its own.
• The same sentence has different token counts in different families.
• The chat template is the layout the model was trained on: never hand-write it.
• The tokenizer and the model are a pair and must match.
• get_memory_footprint() tells you what the model costs in GPU memory.
• 4-bit quantisation cuts memory to about a quarter for a small quality loss.
• Memory, not speed, is the first wall. Stream the output so you are not staring at a blank cell.

• 分词器把文字变成 id，每个模型家族都有自己的一套。
• 同一句话在不同家族里 token 数量不同。
• 对话模板是模型训练时的版式：不要手写。
• 分词器和模型是一对，必须匹配。
• get_memory_footprint() 告诉你模型占多少 GPU 内存。
• 4 位量化把内存砍到约四分之一，质量只损失一点。
• 第一堵墙是内存，不是速度。用流式输出，免得盯着空白格子。
