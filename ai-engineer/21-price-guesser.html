Step 1 · Load the lite data and keep the scoring board第 1 步 · 加载 lite 数据，沿用计分板

Learn先学

Start with the small "lite" dataset from the cleaning lesson, so each run takes seconds. Then extend the shared evaluate: besides the average error, count the guesses that land within a tolerance (say $40 or 20% of the real price), and (in the predictors below) count how many replies could not be read. Note the change from the last lessons: this evaluate takes rows with a text and a price, so every guesser takes plain text, and it returns a small dictionary instead of one number. One test set, one board, every guesser.

先用整理数据那课的小号“lite”数据集，每次运行只要几秒。然后扩展共用的 evaluate：除了平均误差，还要数一数落在容忍范围内的猜测（比如误差不超过 40 美元或真实价格的 20%），并在下面的预测器里数一数有多少回复读不出来。注意和前几课的不同：这个 evaluate 接收带 text 和 price 的行，所以每个预测器都接收纯文本，返回的也是一个小字典，而不是单个数字。一个测试集、一块计分板、所有预测器共用。

from datasets import load_dataset lite = load_dataset("your-name/gadget-prices-lite") # built in the cleaning lesson train, test = lite["train"], lite["test"] def evaluate(pricer_fn, rows, tol_dollars=40, tol_pct=0.2): errors, hits = [], 0 for row in rows: guess = pricer_fn(row["text"]) err = abs(guess - row["price"]) errors.append(err) if err <= tol_dollars or err <= tol_pct * row["price"]: hits += 1 return {"avg_error": sum(errors) / len(errors), "hit_rate": hits / len(errors)}

Step 2 · The baselines and their scores第 2 步 · 基线与它们的分数

Learn先学

Rebuild the three classic guessers from the baseline lesson: the constant average, word counts plus linear regression, and a random forest. This time each takes plain text, so they all fit the same shape. Save each score in a small dictionary: it becomes the table in step 5.

重新做出基线那课的三个传统预测器：常数平均值、词频加线性回归、随机森林。这次每个都接收纯文本，形状一致。把每个分数存进一个小字典：它会变成第 5 步的表格。

from sklearn.feature_extraction.text import CountVectorizer from sklearn.linear_model import LinearRegression from sklearn.ensemble import RandomForestRegressor counter = CountVectorizer(max_features=1500, stop_words="english") X = counter.fit_transform(train["text"]) y = train["price"] average = sum(y) / len(y) linear = LinearRegression().fit(X, y) forest = RandomForestRegressor(n_estimators=100, n_jobs=-1, random_state=42).fit(X, y) def average_pricer(text): return average def linear_pricer(text): return float(linear.predict(counter.transform([text]))[0]) def forest_pricer(text): return float(forest.predict(counter.transform([text]))[0]) scores = {} for name, fn in [("average", average_pricer), ("linear", linear_pricer), ("forest", forest_pricer)]: scores[name] = evaluate(fn, test)

Step 3 · The frontier predictor, parsed defensively第 3 步 · 云端大模型预测器，防御式解析

Learn先学

Send the description with a one-line instruction and parse a number from the reply. Models do not always obey "price only": you may get "About $120 maybe". Wei Jie's first version failed to parse such replies and scored them as zero, which quietly ruined the average. Now a failed parse is counted separately, and a fallback (the training average) is used.

把描述加一行指令发过去，从回复里解析出数字。模型并不总听“只回答价格”：你可能收到“About $120 maybe”。Wei Jie 第一版解析不了这种回复，就当成零，悄悄毁掉了平均误差。现在解析失败会单独计数，并使用备用值（训练集平均价）。

import re from openai import OpenAI client = OpenAI() unparsed = 0 def frontier_pricer(text): global unparsed reply = client.chat.completions.create(model="your-big-model", messages=[ {"role": "user", "content": "Estimate the price in dollars. Reply with the number only.\n\n" + text}]) found = re.search(r"\d[\d,]*\.?\d*", reply.choices[0].message.content) if not found: unparsed += 1 return average # fallback, and we know we used it return float(found.group().replace(",", ""))

Step 4 · A tuned small model第 4 步 · 微调的小模型

Learn先学

Fine-tune a hosted small model on 100 examples, as in the last lesson, then wrap the resulting model name in a tuned_pricer with the same shape as every other guesser. We try hosted tuning here because it is the quickest way to see what tuning does; the next lesson moves to a small open model you can run and own yourself. With so few examples, expect only a small gain. It is still worth knowing, because a cheap tuned model can be more consistent.

像上一课那样，用 100 条样例微调一个托管的小模型，再把得到的模型名包进 tuned_pricer，形状和其他预测器一样。这里用托管微调，是因为它最快能看到微调的效果；下一课会换成你能自己运行、自己拥有的小型开源模型。样例这么少，只能期待小幅提升。但仍然值得知道，因为便宜的微调模型可能更稳定。

TUNED_MODEL = "ft:your-small-model:your-org::abc123" # name returned by your tuning job def tuned_pricer(text): global unparsed reply = client.chat.completions.create(model=TUNED_MODEL, messages=[ {"role": "user", "content": "Estimate the price: " + text}]) found = re.search(r"\d[\d,]*\.?\d*", reply.choices[0].message.content) if not found: unparsed += 1 return average return float(found.group().replace(",", ""))

Step 5 · One table, three numbers第 5 步 · 一张表，三个数字

Learn先学

Put every guesser in one table: name, average error, cost per 1,000 guesses and seconds per guess. The usual pattern is random worse than average, then linear, then forest and neural net, then a prompted frontier model on top, with tuning helping a little. The cheapest acceptable winner is often a classic model. The most accurate is often the frontier or tuned model. That trade-off is the whole lesson.

把所有预测器放进一张表：名字、平均误差、每 1000 次猜测的成本、每次猜测的秒数。常见规律是：随机比平均差，然后依次是线性、森林和神经网络，最上面是提示词大模型，微调略有帮助。最便宜的“够用”赢家通常是传统模型，最准的通常是大模型或微调模型。这种取舍就是这一课的重点。

import time def row_for(name, fn, cost_per_1000): start = time.time() result = evaluate(fn, test) secs = (time.time() - start) / len(test) return {"name": name, **result, "cost_per_1000": cost_per_1000, "sec_per_guess": round(secs, 3)} table = [row_for("average", average_pricer, 0.0), row_for("forest", forest_pricer, 0.0), row_for("frontier", frontier_pricer, 1.5)] # use your own price list print("unreadable replies:", unparsed)

Step 6 · A tiny screen where they disagree第 6 步 · 一个让它们“吵起来”的小界面

Learn先学

Wrap it in a small Gradio screen (Gradio is a Python library that turns a function into a web page): a text box in, the estimated price out, with the other guessers' answers beside it and a warning when they spread far apart. When they disagree a lot, that is a sign to be careful. A guesser that is only off by a little everywhere is easier to trust.

用 Gradio（一个能把函数变成网页的 Python 库）包成一个小界面：左边输入文字，输出估价，旁边列出其他预测器的答案，分歧很大时还会给出警告。当它们分歧很大，就是该小心的信号。一个到处都只差一点点的预测器，反而更容易信任。

import gradio as gr GUESSERS = {"average": average_pricer, "forest": forest_pricer, "frontier": frontier_pricer} def guess_all(text): answers = {name: round(fn(text)) for name, fn in GUESSERS.items()} spread = max(answers.values()) - min(answers.values()) warning = "They disagree: check by hand" if spread > 50 else "They roughly agree" return answers["frontier"], answers, warning # main answer, everyone's, then the flag gr.Interface(fn=guess_all, inputs=gr.Textbox(label="Describe the gadget"), outputs=[gr.Number(label="Estimated price"), gr.JSON(label="All guessers"), gr.Textbox(label="Trust")]).launch()

I added a fallback and a count of unparsed replies, so I can see the problem instead of hiding it.我忘了处理“About $120 maybe”这样的回复。解析失败，猜测被当成零，让大模型看起来糟糕透顶。我加了备用值和“读不出来的回复”计数，这样问题看得见，而不是被藏起来。

Common errors常见报错

• ValueError: could not convert string to float from a model reply. Ask for the number only and keep the pattern that pulls it out. Count the misses.
• NotFoundError: model 'ft:...' does not exist. The tuned model id is a placeholder. Paste the name your tuning job returned.
• Tolerance scores that look great but the average error is bad. A hit rate hides large misses. Report both numbers.

• 模型回复报 ValueError: could not convert string to float：要求只回数字，保留取数字的正则，并统计取不到的次数。
• NotFoundError: model 'ft:...' does not exist：微调模型的 id 还是占位符。粘贴你的微调任务返回的名字。
• 容差命中率很好看，平均误差却很差：命中率会掩盖大的失误。两个数字都要报告。

Takeaways要点回顾

• Always report accuracy, cost and speed together.
• Use the same test set for every guesser.
• Start with the lite data so each run is quick.
• Parse model replies defensively, with a fallback and a count of failures.
• Classic models are often the cheapest acceptable winner.
• Frontier and tuned models are often the most accurate, at a cost.
• Disagreement between guessers is a useful warning.

• 永远把准确度、成本和速度放在一起报告。
• 所有预测器共用同一个测试集。
• 先用 lite 数据，每次运行才快。
• 防御式解析模型回复：有备用值，也数一数失败次数。
• 传统模型常常是最便宜的“够用”赢家。
• 大模型和微调模型常常最准，但要花钱。
• 预测器之间的分歧是有用的警告。

Recap小结

1. Put every guesser behind the same function so they can be compared.
2. Report error, cost and unreadable replies together.
3. Pick the one that fits the budget, not only the one with the lowest error.

1. 把每个估价器放在同一个函数后面，才能互相比较。
2. 误差、成本和读不出的回复要一起报告。
3. 选合预算的那个，而不只是误差最低的那个。
