The story故事

Wei Jie now has Auntie Lim's files as markdown, sorted into folders such as staff, services and notices. He wants a question about lifts to find the lift page without anyone typing the exact word. So he prepares the files: cut them up, turn the pieces into numbers, and keep them somewhere searchable.

Wei Jie 现在有了 Lim 阿姨的档案，都是 markdown，按文件夹分成职员、服务、通告等。他希望问到电梯的问题能找到电梯那一页，不用谁去打出完全一样的词。于是他先处理这些文件：切开、把碎片变成数字，再放进一个能搜索的地方。

Step 1 · Measure first, then cut into chunks第 1 步 · 先量一量，再切成块

Learn先学

First count what you have: files, characters and tokens (the small pieces a model reads and is billed by). If everything fits in the context window (the most text a model can read at once), ask whether you need RAG at all. If not, cut each file into chunks of about 1000 characters with a 200-character overlap. The overlap means a sentence cut at the edge still appears whole in the neighbour. The recursive splitter tries paragraph breaks first, then sentences, then single characters. Each chunk keeps metadata, such as the folder it came from.

先数一数手上有什么：多少个文件、多少字符、多少 token（模型读写的小片段，也是计费的单位）。如果全部放得进上下文窗口（模型一次能读的最多文字），就先问问自己到底要不要 RAG。放不下，就把每个文件切成约 1000 字符的块，前后重叠 200 字符。重叠的意思是：在边缘被切断的句子，会在相邻的那块里完整出现。递归切分器先试段落分隔，再试句子，最后才按单个字符切。每个块都保留元数据，比如它来自哪个文件夹。

# pip install langchain-core langchain-text-splitters langchain-openai langchain-chroma langchain-huggingface sentence-transformers tiktoken numpy matplotlib scikit-learn # (LangChain is a library that joins models, splitters and stores) from pathlib import Path import tiktoken from langchain_core.documents import Document from langchain_text_splitters import RecursiveCharacterTextSplitter docs = [] for path in Path("council_files").glob("**/*.md"): docs.append(Document(page_content=path.read_text(encoding="utf-8"), metadata={"source": path.name, "kind": path.parent.name})) enc = tiktoken.get_encoding("cl100k_base") print(len(docs), "files,", sum(len(enc.encode(d.page_content)) for d in docs), "tokens") splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200) chunks = splitter.split_documents(docs) # metadata is copied to every chunk print(len(chunks), "chunks")
6 files, 2310 tokens 11 chunks

Step 2 · Embeddings: meaning as numbers第 2 步 · 向量：把意思变成数字

Learn先学

An embedding model turns a piece of text into a vector: a list of numbers, often 384 to 3072 long. Texts with similar meaning get vectors that land near each other. "Lift stuck" and "elevator broken" end up neighbours, even with no shared word. Wei Jie tried a free small open model that runs on his laptop, and a paid hosted one. Both work. The hosted one is usually better and costs a little.

向量模型（embedding model）把一段文字变成一个向量：一串数字，通常有 384 到 3072 个。意思相近的文字，向量会落在彼此附近。“电梯卡住了”和“电梯坏了”会成为邻居，哪怕没有一个相同的词。Wei Jie 试了在笔记本上就能跑的免费小型开源模型，也试了付费的托管模型。两种都行，托管的通常更好，花一点点钱。

# free and local, or paid and hosted: pick one from langchain_huggingface import HuggingFaceEmbeddings from langchain_openai import OpenAIEmbeddings embedder = HuggingFaceEmbeddings(model_name="sentence-transformers/all-MiniLM-L6-v2") # embedder = OpenAIEmbeddings(model="text-embedding-3-small") vector = embedder.embed_query("The lift is stuck") print(len(vector)) # 384 numbers for the small local model
384

Step 3 · The vector store第 3 步 · 向量库

Learn先学

A vector store is a database built to answer "which stored vectors are closest to this one?". Wei Jie used Chroma and saved it to a folder, so he does not pay to embed everything on each start. To rebuild, delete the folder. He prints the count and the number of dimensions, just to see what he has. The same embedder must be used for the chunks and for every question later.

向量库是专门回答“哪些存着的向量离这一个最近？”的数据库。Wei Jie 用了 Chroma，并存到一个文件夹，这样每次启动都不用重新花钱做向量。想重建，就删掉那个文件夹。他会打印数量和维度，看看手上到底有什么。之后，块和每个问题必须用同一个向量模型。

import os from langchain_chroma import Chroma if os.path.exists("council_db"): # built last time: reuse it, no new embedding store = Chroma(persist_directory="council_db", embedding_function=embedder) else: store = Chroma.from_documents(documents=chunks, embedding=embedder, persist_directory="council_db") # embeds once, saved on disk print(store._collection.count(), "chunks stored") sample = store._collection.get(limit=1, include=["embeddings"])["embeddings"][0] print(len(sample), "dimensions") for hit in store.similarity_search("Who fixes a stuck lift?", k=3): print(hit.metadata["source"])
11 chunks stored 384 dimensions hafiz.md lifts.md fees.md

Step 4 · Seeing meaning as location第 4 步 · 看见“意思就是位置”

Learn先学

A vector with hundreds of numbers cannot be drawn. t-SNE (a common tool for drawing many-number points on a flat page) squashes them into 2D (or 3D) while trying to keep neighbours together. Wei Jie coloured each point by folder. Chunks about the same topic formed clusters, with fuzzy overlaps between related folders. Only the clusters mean something: the exact distances are rough, so do not read them as measurements. That picture made "meaning is location" click for him.

几百个数字的向量没法直接画出来。t-SNE（一种把很多数字的点画到平面上的常用方法）会把它们压成 2D（或 3D），同时尽量让邻居还是邻居。Wei Jie 按文件夹给每个点上色。同一话题的块聚成一团，相关的文件夹之间有模糊的重叠。只有成团这件事有意义：具体的距离并不精确，别当成测量值。这张图让他一下子懂了“意思就是位置”。

import numpy as np import matplotlib.pyplot as plt from sklearn.manifold import TSNE data = store._collection.get(include=["embeddings", "metadatas"]) flat = TSNE(n_components=2, random_state=0).fit_transform(np.array(data["embeddings"])) kinds = [m["kind"] for m in data["metadatas"]] for kind in sorted(set(kinds)): pick = [i for i, k in enumerate(kinds) if k == kind] plt.scatter(flat[pick, 0], flat[pick, 1], label=kind) plt.legend(); plt.show()

Sort each statement: is it about chunks, embeddings or the store?

给每句话分类：它说的是分块、向量，还是向量库？

What I got wrong我搞错的地方I changed the embedding model but kept the old store. The questions were in one number space and the chunks in another, so the results were rubbish. One embedding model for both sides, always. If I change it, I delete the store folder and rebuild.我换了向量模型，却保留了旧的库。问题在一个数字空间，块在另一个，结果全是垃圾。两边永远用同一个向量模型。要换的话，就删掉库的文件夹，重新建。

Common errors常见报错

• ModuleNotFoundError: No module named 'X'. The package is not installed in the environment this notebook uses. Run pip install X in a cell, then restart the kernel.
• chromadb ... Embedding dimension 1536 does not match collection dimensionality 384. You embedded with a different model than the one that built the store. Use the same embedder for both, or delete the store folder and rebuild.
• sqlite3.OperationalError: database is locked or a stale store. Two programs are using the same folder. Close the other one, or point to a fresh folder.

• ModuleNotFoundError: No module named 'X'：当前笔记本的环境没装这个包。在单元格里运行 pip install X，然后重启内核。
• Embedding dimension 1536 does not match collection dimensionality 384：建库和查询用了不同的嵌入模型。两边用同一个，或者删掉库文件夹重建。
• sqlite3.OperationalError: database is locked，或库里是旧数据：两个程序在用同一个文件夹。关掉另一个，或换一个新文件夹。

Now make it yours现在把它变成你的

What changed这一课之后Auntie Lim's file is now a searchable store: ask about lifts and the nearest chunks come back, lifts beside lifts. The next problem is that nothing yet turns those chunks into an answer a resident can read.Lim 阿姨的档案现在是一个可搜索的库：问到电梯，最近的块就回来了，电梯的挨着电梯。下一个问题是，还没有东西把这些块变成居民读得懂的回答。

Takeaways要点回顾

• Measure your files first. If it all fits in the context window, RAG may not be needed.
• Chunk about 1000 characters with a 200 overlap, so cut sentences survive.
• Each chunk keeps metadata, such as where it came from.
• An embedding turns text into a vector; similar meaning means nearby vectors.
• A vector store finds the closest vectors; save it to disk to avoid re-embedding.
• Use the same embedding model on both sides.

• 先量一量文件有多大。全部放得进上下文窗口的话，也许根本不需要 RAG。
• 每块约 1000 字符、重叠 200，被切断的句子才不会丢。
• 每个块都带着元数据，比如来自哪里。
• 向量模型把文字变成向量；意思相近，向量就相近。
• 向量库负责找最近的向量；存到磁盘，就不用重复做向量。
• 两边必须用同一个向量模型。

Recap小结

1. Chunks are small pieces of a document, cut so each holds one idea.
2. An embedding turns a chunk into numbers, so similar meanings sit close together.
3. A vector store keeps those numbers and finds the closest chunks to a question.

1. 块（chunk）是把文件切成的小段，每段只讲一个意思。
2. 嵌入（embedding）把每一块变成一串数字，意思相近的会靠得近。
3. 向量库保存这些数字，并找出离问题最近的块。
