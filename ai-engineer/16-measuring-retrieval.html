Measuring retrieval衡量检索

You will replace "looks good in the chat" with numbers that move when you improve things · ~20 min · concept你会用会随改进而变化的数字，取代“聊天里看起来不错” · 约 20 分钟 · 概念课

Step 1 · Test set and retrieval score第 1 步 · 测试集和检索分数

Learn先学

"Looks good in the chat" is a feeling. You need a number that moves. Build a test set, one JSON record per line, each with:

“聊天里看起来不错”只是感觉。你需要一个会变化的数字。做一个测试集，每行一条 JSON 记录，包含：

  • a question, keywords that must appear in the right chunks, a reference answer;
  • a category (direct, relationship, holistic), so you see which kind is weak.
  • 问题、必须出现在正确块里的关键词、标准答案；
  • 类别（直接、关系、整体），这样能看出哪一类弱。

Score the search first, before the model writes anything. MRR is 1 divided by the rank of the first chunk containing a keyword (rank 1 gives 1, rank 3 gives 0.33, missing gives 0). Coverage is the fraction of keywords found in the top k.

先给搜索打分，这时模型还没写任何东西。MRR 是第一块含关键词的结果名次的倒数（第 1 名得 1，第 3 名得 0.33，没找到得 0）。覆盖率是前 k 块里找到的关键词所占比例。

{"question": "Who is in charge of lift repairs?", "keywords": ["lift", "Hafiz"], "reference": "Hafiz Rahman handles lift repairs.", "category": "direct"} {"question": "Which services have a fee?", "keywords": ["fee", "bulky waste", "hall booking"], "reference": "Bulky waste pickup and hall booking.", "category": "holistic"}
import json # store is the Chroma vector store from the last lesson tests = [json.loads(line) for line in open("tests.jsonl", encoding="utf-8")] def first_rank(keyword, chunks): for rank, c in enumerate(chunks, start=1): if keyword.lower() in c.page_content.lower(): return rank return None # not found def score_retrieval(test, k=10): chunks = store.similarity_search(test["question"], k=k) ranks = [first_rank(w, chunks) for w in test["keywords"]] mrr = sum(1 / r for r in ranks if r) / len(ranks) coverage = sum(1 for r in ranks if r) / len(ranks) return mrr, coverage

Step 2 · Score the answer with a judge model第 2 步 · 用裁判模型给回答打分

Learn先学

Good chunks do not guarantee a good answer, so score the answer separately. A second model judges it against the reference: accuracy, completeness and relevance, 1 to 5 each, in a fixed shape (the Verdict class) your code can read. Rule: any wrong answer scores 1.

块好不等于回答好，所以回答要单独打分。让第二个模型对照标准答案来评：准确度、完整度、相关度，各 1 到 5 分，格式固定（Verdict 类），代码可以直接读取。规则：只要答错，就给 1 分。

Step 3 · Change one thing at a time第 3 步 · 一次只改一样

Learn先学

Change one setting (chunk size, overlap, k or the embedding model), re-run the whole test set and compare the average per category. A weak category shows what to fix. Change two things at once and you cannot tell which helped.

只改一个设置（块大小、重叠、k 或向量模型），重跑整个测试集，按类别比较平均分。哪一类弱，就修哪里。同时改两样，就分不清是哪样起了作用。

from collections import defaultdict def report(k): by_cat = defaultdict(list) for t in tests: by_cat[t["category"]].append(score_retrieval(t, k)) for cat, rows in by_cat.items(): print(cat, "MRR %.2f" % (sum(r[0] for r in rows) / len(rows)), "coverage %.2f" % (sum(r[1] for r in rows) / len(rows))) for k in (3, 10): # change one thing: k print("k:", k); report(k)
k: 3 direct MRR 0.80 coverage 0.85 holistic MRR 0.40 coverage 0.50 k: 10 direct MRR 0.88 coverage 0.95 holistic MRR 0.55 coverage 0.75
What I got wrong我搞错的地方I judged by feel after one lucky question. A single good answer proves nothing, and the judge is imperfect too: spot-check some of its scores by hand.我问了一个运气好的问题就凭感觉下结论。一个好答案什么也证明不了，裁判也不完美：手动抽查一部分分数。

Takeaways要点回顾

• Build the test set first, so there is a number to move.
• Score retrieval (MRR, coverage) and answers (judge) separately.
• Spot-check the judge by hand.
• Change one thing at a time and compare per category.

• 先做测试集，这样才有数字可以推动。
• 检索（MRR、覆盖率）和回答（裁判）分开打分。
• 手动抽查裁判的打分。
• 一次只改一样，并按类别比较。
