Measuring whether retrieval works怎么衡量检索好不好

You will replace "looks good in the chat" with numbers that move when you improve things · ~20 min · concept你会用会随改进而变化的数字，取代“聊天里看起来不错” · 约 20 分钟 · 概念课

The story故事

Wei Jie asks the chatbot three questions, gets three good answers, and feels proud. Priya, who checks answers for a living, asks him one thing: "How would you know if it got worse?" He had no answer. So he builds a small test set, the way Priya marks a class.

Wei Jie 问聊天机器人三个问题，得到三个好答案，很得意。以批改答案为生的 Priya 只问了他一句：“如果它变差了，你怎么知道？”他答不上来。于是他像 Priya 批改全班那样，做了一份小小的测试集。

Step 1 · A test set of questions with known answers第 1 步 · 带标准答案的测试集

Learn先学

"Looks good in the chat" is a feeling, not evidence. You want a number that moves when you improve things. For that you need a test set: one JSON object per line, in a file (JSON is plain text that writes a record as named fields, like the lines below). Each has a question, a few keywords that must appear in the right chunks, a reference answer and a category: a direct fact, a relationship, a comparison, or a holistic question that spans many documents. A few dozen questions across the categories is enough to start.

“聊天里看起来不错”只是感觉，不是证据。你需要一个会随改进而变化的数字。为此要有测试集：一个文件，每行一个 JSON 对象（JSON 是一种纯文本格式，用带名字的字段来写一条记录，就像下面的几行）。每条有问题、几个必须出现在正确块里的关键词、标准答案，以及类别：直接事实、关系、比较，或是跨很多文档的整体性问题。每个类别有几十道题，就足够起步了。

# tests.jsonl (one question per line, made-up examples) {"question": "Who is in charge of lift repairs?", "keywords": ["lift", "Hafiz"], "reference": "Hafiz Rahman handles lift repairs.", "category": "direct"} {"question": "Which officer reports to the estate manager?", "keywords": ["estate manager", "reports"], "reference": "The lift officer reports to her.", "category": "relationship"} {"question": "Which services have a fee?", "keywords": ["fee", "bulky waste", "hall booking"], "reference": "Bulky waste pickup and hall booking.", "category": "holistic"}

Step 2 · Score retrieval: did the right chunks come back?第 2 步 · 给检索打分：对的块回来了吗？

Learn先学

Score the search on its own, before the model writes anything. For each keyword, find the rank of the first retrieved chunk that contains it. MRR (mean reciprocal rank) is 1 divided by that rank, averaged: top hit scores 1, third scores 0.33, missing scores 0. Keyword coverage is the fraction of keywords found in the top k.

先单独给搜索打分，这时模型还没写任何东西。对每个关键词，找出第一块含有它的检索结果的名次。MRR（平均倒数名次）就是这个名次的倒数再取平均：排第一得 1，排第三得 0.33，没找到得 0。关键词覆盖率是前 k 块里找到的关键词所占的比例。

import json tests = [json.loads(line) for line in open("tests.jsonl", encoding="utf-8")] def first_rank(keyword, chunks): for rank, c in enumerate(chunks, start=1): if keyword.lower() in c.page_content.lower(): return rank return None # not found def score_retrieval(test, k=10): chunks = store.similarity_search(test["question"], k=k) ranks = [first_rank(w, chunks) for w in test["keywords"]] mrr = sum(1 / r for r in ranks if r) / len(ranks) coverage = sum(1 for r in ranks if r) / len(ranks) return mrr, coverage

Step 3 · Score the answer with a judge model第 3 步 · 用裁判模型给回答打分

Learn先学

Good chunks do not guarantee a good answer, so score the answer separately. Another model acts as judge. Give it the question, the reference answer and the chatbot's answer. It returns accuracy, completeness and relevance, each from 1 to 5, with a line of feedback, in a fixed shape (the Verdict class below) so your code can read each number by name. One rule Wei Jie likes: any wrong answer must score 1.

块好不等于回答好，所以回答要单独打分。让另一个模型当裁判。把问题、标准答案和聊天机器人的回答给它，它返回准确度、完整度、相关度，各 1 到 5 分，再加一句反馈，并且格式固定（下面的 Verdict 类），你的代码可以按名字读出每个数字。Wei Jie 喜欢的一条规则：只要答错，就必须给 1 分。

Step 4 · Change one thing at a time第 4 步 · 一次只改一样

Learn先学

Now improving becomes a loop. Change one setting only: chunk size, overlap, k or the embedding model. Re-run the whole test set. Compare the average per category. A weak category tells you what to fix. Holistic questions usually need more or better chunks. Relationship questions need related documents fetched together. Change two things at once and you cannot tell which one helped.

现在改进变成一个循环。每次只改一个设置：块大小、重叠、k 或向量模型。把整个测试集重跑一遍，按类别比较平均分。哪一类弱，就告诉你该修哪里。整体性问题通常需要更多或更好的块；关系类问题需要把相关的文档一起取出来。同时改两样，你就分不清是哪样起了作用。

from collections import defaultdict def report(k): by_cat = defaultdict(list) for t in tests: by_cat[t["category"]].append(score_retrieval(t, k)) for cat, rows in by_cat.items(): print(cat, "MRR %.2f" % (sum(r[0] for r in rows) / len(rows)), "coverage %.2f" % (sum(r[1] for r in rows) / len(rows))) for k in (3, 5, 10): # change one thing: k print("k =", k); report(k)
What I got wrong我搞错的地方I judged by feel after one lucky question and felt done. A single good answer proves nothing. And the judge model is not perfect either, so I now spot-check some of its scores by hand.我问了一个运气好的问题就凭感觉下结论，以为完成了。一个好答案什么也证明不了。裁判模型也不是完美的，所以我现在会手动抽查它给的一部分分数。

Takeaways要点回顾

• Build the test set first, so there is a number to move.
• Each test has a question, keywords, a reference answer and a category.
• Score retrieval and answers separately.
• MRR rewards a high rank; coverage counts how many keywords were found.
• A judge model scales checking, but spot-check its scores by hand.
• Change one thing at a time and compare per category.

• 先做测试集，这样才有数字可以推动。
• 每条测试包括问题、关键词、标准答案和类别。
• 检索和回答要分开打分。
• MRR 奖励靠前的名次；覆盖率数找到了多少个关键词。
• 裁判模型能让检查规模化，但要手动抽查它的分数。
• 一次只改一样，并按类别比较。
