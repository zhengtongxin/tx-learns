Step 1 · Trace every step第 1 步 · 追踪每一步

Learn先学

A trace is the record of one run: every model call and every tool call, in order, with its time and its tokens. Without one, an agent is a black box that returns an answer. With one, you can read what happened, like the flight recorder on a plane. Tools such as Langfuse, Arize Phoenix or LangSmith collect traces for you and show them on a dashboard. To keep this runnable with nothing to sign up for, here is the same idea in a few lines of your own. Save it as tracing.py. It builds on the bench.py helpers from the model-picking lessons.

追踪（trace）是一次运行的记录：每一次模型调用和工具调用，按顺序，带着耗时和 token 数。没有它，智能体就是个只会给答案的黑盒；有了它，你能读到发生了什么，就像飞机上的黑匣子。Langfuse、Arize Phoenix、LangSmith 这类工具可以替你收集追踪并放在仪表板上。为了让这里什么都不用注册就能跑，我们用几行自己的代码来做同一件事。存成 tracing.py。它建立在挑模型那几课的 bench.py 之上。

# tracing.py import time from contextlib import contextmanager TRACE = [] # every step of the current run, in order @contextmanager def step(kind, name, **info): """Time one step and write it into TRACE.""" record = {"kind": kind, "name": name, **info} start = time.perf_counter() try: yield record finally: record["secs"] = round(time.perf_counter() - start, 2) TRACE.append(record) # experiments.py from bench import claims, key, small_prompt, ask, gateway, PRICE from tracing import TRACE, step MODEL = "openai/gpt-5.4-mini" def agent_v1(claim): with step("model", MODEL) as s: decision, tin, tout, _ = ask(gateway, MODEL, small_prompt(claim)) s["tin"], s["tout"] = tin, tout return decision def show_trace(): for s in TRACE: extra = {k: v for k, v in s.items() if k not in ("kind", "name", "secs")} print(f"{s['kind']:6} {s['name']:30} {s['secs']:5.2f}s", extra)

Step 2 · A dataset of harder claims第 2 步 · 一份更难的理赔数据集

Learn先学

An experiment needs a fixed set of questions with the right answers beside them: a dataset. Easy claims are no use here, because every version gets them right and you learn nothing. So take the harder ones, with the handlers’ decisions as the reference. Every experiment uses exactly this set. Change the set between experiments and you cannot tell whether the agent or the set changed.

实验需要一组固定的题目，旁边放着正确答案：这就是数据集。简单理赔在这里没用，因为每个版本都会答对，你什么也学不到。所以挑难一点的，以理赔员的决定作参考答案。每个实验都用同一组。实验之间换了数据集，你就分不清是智能体变了，还是数据变了。

# experiments.py, continued hard = [c for c in claims if key[c["id"]]["difficulty"] != "easy"] # medium and tricky print(len(hard), "claims in the harder set")

Step 3 · One task, several evaluators第 3 步 · 一个任务，几位评分员

Learn先学

Two small ideas. The task is what you run on one claim: here, the agent. An evaluator is a small function that scores one result against the reference. Use several, because they catch different failures. Decision match checks the action. Payout match checks the money to within S$1. Cost adds up the tokens in the trace. Then a runner applies the task to every claim in the dataset and averages each score. Cost uses the token prices from bench.py, in US$ per million tokens. This PRICE is not the S$ mistake prices from the first lesson of this topic.

两个小概念。任务是你对一份理赔要运行的东西：这里就是智能体。评分员是一个小函数，拿一次结果去和参考答案对照打分。多用几个，因为它们抓住的毛病不同。决定匹配查动作，赔付匹配查金额是否在 S$1 以内，成本把追踪里的 token 加起来。然后让一个运行器把任务应用到数据集里的每一份理赔上，再把每项分数取平均。成本用的是 bench.py 里的 token 单价，按每百万 token 计的美元价格。这里的 PRICE 不是这个主题第一课那个以新元计的错误价格。

# experiments.py, continued def decision_match(decision, want, trace): return decision["action"] == want["action"] def payout_match(decision, want, trace): return abs(float(decision["payout"]) - want["payout"]) <= 1 def cost_us(decision, want, trace): price_in, price_out = PRICE[MODEL] tokens = sum(s.get("tin", 0) * price_in + s.get("tout", 0) * price_out for s in trace) return tokens / 1_000_000 EVALUATORS = [decision_match, payout_match, cost_us] def run_experiment(name, agent, dataset, evaluators=EVALUATORS): rows = [] for claim in dataset: TRACE.clear() # a fresh trace for each claim decision = agent(claim) want = key[claim["id"]] rows.append({e.__name__: e(decision, want, TRACE) for e in evaluators}) summary = {e.__name__: sum(r[e.__name__] for r in rows) / len(rows) for e in evaluators} print(name, {k: round(v, 4) for k, v in summary.items()}) return summary

Step 4 · Experiment one: the baseline第 4 步 · 实验一：基线

Learn先学

First run the agent as it is. This is your baseline, the number every later version has to beat. Then do the most useful thing in the whole lesson: before guessing a fix, read the trace of a claim whose payout was wrong. Trace first, then guess.

先让智能体原样跑一遍。这是你的基线，之后每个版本都要超过的数字。然后做整节课里最有用的一件事：在猜修法之前，先读一份赔付算错的理赔的追踪。先追踪，再猜测。

base = run_experiment("baseline", agent_v1, hard) # find the first claim whose payout was wrong, and keep its trace for claim in hard: TRACE.clear() if abs(float(agent_v1(claim)["payout"]) - key[claim["id"]]["payout"]) > 1: break show_trace()

预期输出 （示例：你的数字和措辞会不同）

Step 5 · Experiment two: a payout tool第 5 步 · 实验二：赔付工具

Learn先学

The trace showed one model call and nothing else, so the model was doing sums from memory. Models are good at reading and weak at exact arithmetic. So give it a tool: a function it can ask your code to run. The company’s payout rule lives in code, where it is exact: the amount claimed, capped at the policy limit, minus the excess. The model only chooses to call it. The code below assumes each claim has a type field, and your policy file lists limits by claim type and an excess. Change those lines to match your files. The loop runs at most four rounds, so a confused model cannot go round forever.

追踪里只有一次模型调用，别的什么都没有，说明模型是凭记忆在心算。模型擅长阅读，不擅长精确算术。所以给它一个工具：一个它可以请你的代码去运行的函数。公司的赔付规则写在代码里，这样才精确：申报金额，封顶到保单限额，再减去自负额。模型只负责决定去调用它。下面的代码假定每份理赔都有一个 type 字段，并且你的保单文件按理赔类型列出限额、有一个自负额，请把这几行改成你自己文件的格式。循环最多跑四轮，所以迷糊的模型不会转个没完。

# experiments.py, continued import json from bench import POLICIES def work_out_payout(claim_id): """The company's rule: amount claimed, capped at the limit, minus the excess.""" claim = next(c for c in claims if c["id"] == claim_id) policy = POLICIES[claim["policy_id"]] limit = policy["limits"][claim["type"]] # assumed shapes of claims.json and policies.json: adjust return max(0, min(claim["amount"], limit) - policy["excess"]) TOOLS = [{"type": "function", "function": { "name": "work_out_payout", "description": "Works out the payout in S$ for a claim by the company's rules.", "parameters": {"type": "object", "properties": {"claim_id": {"type": "string"}}, "required": ["claim_id"]}}}] def agent_v2(claim): prompt = small_prompt(claim) + "\nFor the payout, call work_out_payout. Do not work it out yourself." messages = [{"role": "user", "content": prompt}] for _ in range(4): with step("model", MODEL) as s: reply = gateway.chat.completions.create(model=MODEL, messages=messages, tools=TOOLS) s["tin"], s["tout"] = reply.usage.prompt_tokens, reply.usage.completion_tokens message = reply.choices[0].message if not message.tool_calls: # no more tool requests: this is the answer text = message.content return json.loads(text[text.index("{"): text.rindex("}") + 1]) messages.append(message) for call in message.tool_calls: args = json.loads(call.function.arguments) with step("tool", call.function.name, args=args) as s: result = work_out_payout(**args) s["result"] = result messages.append({"role": "tool", "tool_call_id": call.id, "content": str(result)}) return {"action": "refer", "payout": 0, "reason": "no answer after four rounds"} with_tool = run_experiment("payout tool", agent_v2, hard)

Step 6 · Compare, one change at a time第 6 步 · 对比，一次只改一样

Learn先学

Now put the two summaries side by side. The comparison only means something because both used the same dataset, the same evaluators and differed in one thing. Change two things at once and a better score has two possible causes, and you cannot say which. After that, write one sentence each experiment supports. If you sent traces to an observability tool, delete the test dataset and traces when you are done, so test claims never mix with real ones.

现在把两份汇总并排放。这个对比之所以有意义，是因为两次用的是同一个数据集、同一批评分员，并且只有一样东西不同。一次改两样，分数变好就有两种可能的原因，你说不清是哪个。然后给每个实验写一句它能支持的话。如果你把追踪发给了观测工具，用完要删掉测试数据集和追踪，免得测试用的理赔和真的混在一起。

for name in base: print(f"{name:15} {base[name]:8.4f} -> {with_tool[name]:8.4f}") TRACE.clear() # tidy up: nothing from the test stays around

Common errors常见错误

ImportError: cannot import name 'TRACE' from 'tracing'
Cause: the list is defined in a different file or under a different name. Fix: check that tracing.py defines TRACE = [] at the top level.

ImportError: cannot import name 'TRACE' from 'tracing'
原因：这个列表定义在别的文件，或者名字不同。解决：确认 tracing.py 的最上层有 TRACE = []。

ZeroDivisionError: division by zero
Cause: the harder set came out empty, so there is nothing to average. Fix: print its length first, then check the filter that builds it.

ZeroDivisionError: division by zero
原因：较难的那一组是空的，没有东西可以求平均。解决：先打印它的长度，再检查生成它的筛选条件。

TypeError: float() argument must be a string or a real number, not 'NoneType'
Cause: the agent returned no payout for a claim it declined. Fix: use decision.get("payout") or 0 before comparing.

TypeError: float() argument must be a string or a real number, not 'NoneType'
原因：智能体拒赔时没有给出赔付金额。解决：比较之前用 decision.get("payout") or 0。

Recap小结

• A trace is a list of what happened inside one run: each model call and each tool call, with time and tokens.
• An experiment runs two versions on the same claims and compares the same numbers.
• Read one failing trace before you change anything; the change is then aimed, not guessed.

• 追踪就是一次运行里发生了什么的清单：每次模型调用和工具调用，带上耗时和 token。
• 实验是让两个版本跑同一批理赔，再比较同样的数字。
• 改动之前先读一条失败的追踪；这样的改动是有目标的，而不是瞎猜。

Takeaways要点回顾

• Trace first, then guess: read what the agent actually did before you change anything.
• A trace lists every model call and tool call with its time and tokens.
• An experiment needs a fixed dataset with reference answers, and harder claims teach more than easy ones.
• Use several evaluators: decision match, payout match and cost catch different failures.
• Run a baseline first, and use the same dataset for every experiment.
• Change one thing at a time, or a better score has no clear cause.
• Tools beat prompts for anything exact, like payout sums.

• 先追踪，再猜测：动手改之前，先读智能体到底做了什么。
• 追踪列出每一次模型调用和工具调用，带着耗时和 token 数。
• 实验需要一个有参考答案的固定数据集，难的理赔比简单的教得更多。
• 用多个评分员：决定匹配、赔付匹配和成本，抓的是不同的毛病。
• 先跑基线，每个实验用同一个数据集。
• 一次只改一样，否则分数变好也说不清原因。
• 凡是要精确的事，比如赔付算术，工具胜过提示词。
