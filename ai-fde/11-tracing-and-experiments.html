Tracing and experiments追踪与实验

See every step of a run, then compare two versions of the agent on the same claims, changing one thing at a time · ~20 min · concept with one runnable idea看清一次运行的每一步，然后在同样的理赔上比较智能体的两个版本，一次只改一样 · 约 20 分钟 · 概念课，附一个可动手的做法

Step 1 · Trace every step第 1 步 · 追踪每一步

Learn先学
  • A trace is the record of one run: every model and tool call, in order, with time and tokens. Without one, an agent is a black box.
  • Langfuse, Arize Phoenix and LangSmith collect traces for you. To stay sign-up free, here is the same idea in a few lines. It builds on bench.py.
  • 追踪（trace）是一次运行的记录：每一次模型和工具调用，按顺序，带着耗时和 token 数。没有它，智能体就是个黑盒。
  • Langfuse、Arize Phoenix、LangSmith 可以替你收集追踪。为了什么都不用注册，这里用几行代码做同一件事。它建立在 bench.py 之上。
# tracing.py import time from contextlib import contextmanager TRACE = [] # every step of the current run, in order @contextmanager def step(kind, name, **info): """Time one step and write it into TRACE.""" record = {"kind": kind, "name": name, **info} start = time.perf_counter() try: yield record finally: record["secs"] = round(time.perf_counter() - start, 2) TRACE.append(record) # experiments.py from bench import claims, key, small_prompt, ask, gateway, PRICE from tracing import TRACE, step MODEL = "openai/gpt-5.4-mini" def agent_v1(claim): with step("model", MODEL) as s: decision, tin, tout, _ = ask(gateway, MODEL, small_prompt(claim)) s["tin"], s["tout"] = tin, tout return decision def show_trace(): for s in TRACE: extra = {k: v for k, v in s.items() if k not in ("kind", "name", "secs")} print(f"{s['kind']:6} {s['name']:30} {s['secs']:5.2f}s", extra)

Step 2 · A fixed dataset and evaluators第 2 步 · 固定的数据集和评分员

Learn先学
  • An experiment needs a fixed dataset: questions with the right answers beside them. Use the harder claims, since easy ones teach nothing. Never change the set between experiments.
  • The task is what you run on one claim: the agent. An evaluator scores one result against the reference. Use several, because they catch different failures: decision match, payout match (within S$1) and cost.
  • Cost uses bench.py’s token prices in US$ per million, not the S$ mistake prices from the last lesson.
  • 实验需要固定的数据集：题目旁边放着正确答案。用难一点的理赔，简单的学不到东西。实验之间不要换数据集。
  • 任务是你对一份理赔要运行的东西：智能体。评分员拿一次结果去和参考答案对照打分。多用几个，因为它们抓住的毛病不同：决定匹配、赔付匹配（S$1 以内）和成本。
  • 成本用 bench.py 里每百万 token 的美元单价，不是上一课那个以新元计的错误价格。
# experiments.py, continued hard = [c for c in claims if key[c["id"]]["difficulty"] != "easy"] # medium and tricky def decision_match(decision, want, trace): return decision["action"] == want["action"] def payout_match(decision, want, trace): return abs(float(decision["payout"]) - want["payout"]) <= 1 def cost_us(decision, want, trace): price_in, price_out = PRICE[MODEL] tokens = sum(s.get("tin", 0) * price_in + s.get("tout", 0) * price_out for s in trace) return tokens / 1_000_000 EVALUATORS = [decision_match, payout_match, cost_us] def run_experiment(name, agent, dataset, evaluators=EVALUATORS): rows = [] for claim in dataset: TRACE.clear() # a fresh trace for each claim decision = agent(claim) want = key[claim["id"]] rows.append({e.__name__: e(decision, want, TRACE) for e in evaluators}) summary = {e.__name__: sum(r[e.__name__] for r in rows) / len(rows) for e in evaluators} print(name, {k: round(v, 4) for k, v in summary.items()}) return summary

Step 3 · Baseline, trace, then change one thing第 3 步 · 基线、追踪，再改一样

Learn先学
  • Run the agent as it is: the baseline every later version must beat. Then, before guessing a fix, read the trace of a claim whose payout was wrong.
  • A one-line trace means the model did sums from memory. Give it a tool: a function it can ask your code to run. The payout rule lives in code, where it is exact; the model only chooses to call it.
  • Change one thing at a time. Change two and a better score has two possible causes.
  • The code assumes each claim has a type and your policy file has limits by type and an excess: adjust to your files.
  • 先让智能体原样跑一遍：这是之后每个版本都要超过的基线。然后在猜修法之前，先读一份赔付算错的理赔的追踪。
  • 只有一行的追踪，说明模型是凭记忆在心算。给它一个工具：一个它可以请你的代码去运行的函数。赔付规则写在代码里才精确；模型只负责决定去调用它。
  • 一次只改一样。一次改两样，分数变好就有两种可能的原因。
  • 代码假定每份理赔有 type，保单文件按类型列出限额并有一个自负额：请按你的文件调整。
base = run_experiment("baseline", agent_v1, hard) # find the first claim whose payout was wrong, and read its trace for claim in hard: TRACE.clear() if abs(float(agent_v1(claim)["payout"]) - key[claim["id"]]["payout"]) > 1: break show_trace() import json from bench import POLICIES def work_out_payout(claim_id): """The company's rule: amount claimed, capped at the limit, minus the excess.""" claim = next(c for c in claims if c["id"] == claim_id) policy = POLICIES[claim["policy_id"]] limit = policy["limits"][claim["type"]] # assumed shapes of claims.json and policies.json: adjust return max(0, min(claim["amount"], limit) - policy["excess"]) TOOLS = [{"type": "function", "function": { "name": "work_out_payout", "description": "Works out the payout in S$ for a claim by the company's rules.", "parameters": {"type": "object", "properties": {"claim_id": {"type": "string"}}, "required": ["claim_id"]}}}] def agent_v2(claim): prompt = small_prompt(claim) + "\nFor the payout, call work_out_payout. Do not work it out yourself." messages = [{"role": "user", "content": prompt}] for _ in range(4): # at most four rounds with step("model", MODEL) as s: reply = gateway.chat.completions.create(model=MODEL, messages=messages, tools=TOOLS) s["tin"], s["tout"] = reply.usage.prompt_tokens, reply.usage.completion_tokens message = reply.choices[0].message if not message.tool_calls: # no more tool requests: this is the answer text = message.content return json.loads(text[text.index("{"): text.rindex("}") + 1]) messages.append(message) for call in message.tool_calls: args = json.loads(call.function.arguments) with step("tool", call.function.name, args=args) as s: result = work_out_payout(**args) s["result"] = result messages.append({"role": "tool", "tool_call_id": call.id, "content": str(result)}) return {"action": "refer", "payout": 0, "reason": "no answer after four rounds"} with_tool = run_experiment("payout tool", agent_v2, hard) for name in base: print(f"{name:15} {base[name]:8.4f} -> {with_tool[name]:8.4f}")

Takeaways要点回顾

• A trace records every step of a run, so the agent is not a black box.
• Fix the dataset and the evaluators, then compare versions.
• Run a baseline, and read a trace before guessing a fix.
• Exact rules belong in tools, not in the model’s head.
• Change one thing per experiment.

• 追踪记录一次运行的每一步，智能体不再是黑盒。
• 固定数据集和评分员，再比较版本。
• 先跑基线，猜修法之前先读追踪。
• 精确的规则放进工具，而不是模型的脑子里。
• 每个实验只改一样。
