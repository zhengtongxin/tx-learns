Agent scoreboard智能体计分板

Turn “is the new version better?” from an argument into numbers: agreement, mistake costs, straight-through rate, kappa, cost and time, kept for every run · ~25 min · hands-on把“新版本是不是更好”从一场争论变成数字：一致率、错误成本、直通率、kappa、花费和时间，每一轮都留着 · 约 25 分钟 · 动手实践

Step 1 · Hold out claims the agent has never seen第 1 步 · 留出智能体从没见过的理赔

Learn先学
  • A student who saw the exam questions in advance proves nothing, and neither does an agent tuned on its test claims.
  • Set aside a held-out set: pick it once at random, save the list in a file, and never tune on it. A good score then means it copes with unseen claims.
  • This uses scoring.py from the last topic lesson.
  • 提前见过考题的学生什么也证明不了，在测试理赔上调过的智能体也一样。
  • 留出一个留出集：随机挑一次，把名单存进文件，绝不拿它来调试。这样高分才意味着能应付没见过的理赔。
  • 这里用到上一课存的 scoring.py。
# scoreboard.py import json, os, random, threading from datetime import datetime from bench import claims, key, small_prompt, ask, gateway, PRICE from scoring import matrix, accuracy, mistakes, mistake_cost, kappa, straight_through def load_held_out(path="data/held_out_ids.json"): if os.path.exists(path): # already chosen: never choose again return set(json.load(open(path))) ids = sorted(c["id"] for c in claims) random.Random(7).shuffle(ids) held = sorted(ids[:10]) json.dump(held, open(path, "w")) return set(held) HELD_OUT = load_held_out() held_claims = [c for c in claims if c["id"] in HELD_OUT]

Step 2 · Score a run: agreement, cost and time第 2 步 · 给一轮打分：一致率、花费和时间

Learn先学
  • For every claim keep a list of events: each model call with its tokens and seconds.
  • Count working time only. A claim waiting for a handler’s sign-off is the handler’s time, so tag it human_wait and leave it out, or a slow handler makes the agent look slow.
  • One function turns a run into every number the scoreboard shows, straight from scoring.py. Cost is in US$ (how labs bill); mistake cost is in S$.
  • 每份理赔都记一张事件清单：每次模型调用，带着 token 数和秒数。
  • 只算工作时间。理赔等理赔员签字的时间是理赔员的，所以标成 human_wait 并排除，否则理赔员慢了，智能体就显得慢。
  • 一个函数把一轮结果变成计分板要显示的每个数，直接来自 scoring.py。花费用美元（实验室按美元收费），错误成本用新元。
# scoreboard.py, continued MODEL = "openai/gpt-5.4-mini" def run_claim(claim): """Run the agent on one claim and note every call it makes.""" decision, tin, tout, secs = ask(gateway, MODEL, small_prompt(claim)) events = [{"kind": "model", "secs": secs, "tin": tin, "tout": tout}] return decision, events def working_secs(events): return sum(e["secs"] for e in events if e["kind"] != "human_wait") def cost_us(events): price_in, price_out = PRICE[MODEL] return sum(e.get("tin", 0) * price_in + e.get("tout", 0) * price_out for e in events) / 1_000_000 def score_run(results): """results: one {"id", "decision", "events"} per claim.""" pairs = [(key[r["id"]]["action"], r["decision"]["action"]) for r in results] grid = matrix(pairs) n = len(results) return {"claims": n, "agreement": accuracy(grid), "mistakes": mistakes(grid), "mistake_cost_sgd": mistake_cost(grid), "straight_through": straight_through(grid), "kappa": kappa(grid), "cost_per_claim_usd": sum(cost_us(r["events"]) for r in results) / n, "secs_per_claim": sum(working_secs(r["events"]) for r in results) / n}

Step 3 · Keep every run, then compare第 3 步 · 保留每一轮，然后对比

Learn先学
  • Save each evaluation as its own file named by time. Never overwrite “the latest”: old files are what you compare against.
  • Allow one evaluation at a time with a lock, or two runs mix their cost and time. A second start is refused at once. (A web start button would answer HTTP 409, “conflict”, in that case.)
  • Mark each number better, same or worse. Higher is better for agreement, kappa and straight-through rate; lower is better for mistake cost, cost and time. Run it after every change and a regression shows up the same day.
  • 把每次评估存成一个以时间命名的文件。绝不覆盖“最新的那份”：旧文件正是你用来对比的东西。
  • 用一把锁让同一时间只跑一次评估，否则两次会混在一起算花费和时间。第二次启动会被立刻拒绝。（网页上的启动按钮在这种情况下会回应 HTTP 409，即“冲突”。）
  • 把每个数标成更好、持平或更差。一致率、kappa、直通率越高越好；错误成本、花费和时间越低越好。每次改动后都跑一下，退步当天就能发现。
# scoreboard.py, continued RUNS = "runs" os.makedirs(RUNS, exist_ok=True) _lock = threading.Lock() class Busy(Exception): pass def run_evaluation(label): if not _lock.acquire(blocking=False): # someone else is already running one raise Busy("an evaluation is already running") try: results = [] for claim in held_claims: decision, events = run_claim(claim) results.append({"id": claim["id"], "decision": decision, "events": events}) now = datetime.now() report = {"label": label, "model": MODEL, "at": now.isoformat(timespec="seconds"), "scores": score_run(results)} name = now.strftime("%Y%m%d-%H%M%S") + ".json" json.dump(report, open(os.path.join(RUNS, name), "w"), indent=2) return name, report finally: _lock.release() def list_runs(): return [{**json.load(open(os.path.join(RUNS, n))), "run": n} for n in sorted(os.listdir(RUNS))] HIGHER_IS_BETTER = {"agreement": True, "kappa": True, "straight_through": True, "mistake_cost_sgd": False, "cost_per_claim_usd": False, "secs_per_claim": False} def compare(old, new): worse = [] for metric, higher in HIGHER_IS_BETTER.items(): a, b = old["scores"][metric], new["scores"][metric] if a == b: verdict = "same" elif (b > a) == higher: verdict = "better" else: verdict = "WORSE" worse.append(metric) print(f"{metric:20} {a:10.4f} -> {b:10.4f} {verdict}") return worse # after two evaluations: # runs = list_runs() # compare(runs[-2], runs[-1])

Takeaways要点回顾

• Hold out claims the agent has never been tuned on, and choose them once.
• Show agreement, mistake costs, straight-through rate, kappa, cost and working time together.
• Count working time only: leave out time spent waiting for a human.
• Keep every run as its own file, one evaluation at a time, and run it after every change.

• 留出智能体从没被拿来调过的理赔，并且只选一次。
• 把一致率、错误成本、直通率、kappa、花费和工作时间放在一起展示。
• 只算工作时间：等人的时间不算。
• 每一轮都存成单独的文件，同一时间只跑一次评估，每次改动后都跑一遍。
