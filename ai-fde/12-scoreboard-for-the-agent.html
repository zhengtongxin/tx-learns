Project: a scoreboard for the agent项目：智能体计分板

Turn “is the new version better?” from an argument into numbers: agreement, mistake costs, straight-through rate, kappa, cost and time, kept for every run · ~30 min · hands-on把“新版本是不是更好”从一场争论变成数字：一致率、错误成本、直通率、kappa、花费和时间，每一轮都留着 · 约 30 分钟 · 动手实践

Where we left off上回讲到

Last time the pilot’s payouts became exact, and the trace showed why. Today every Friday change leaves Aisha and Mr Goh asking on Monday whether it is better. We fix it by building a scoreboard the handlers can open themselves.

上回试点的赔付变准了，追踪也说明了原因。今天每个星期五的改动，都让 Aisha 和 Goh 先生到星期一还在问是不是变好了。我们的办法是建一块理赔员自己能打开的计分板。

The story故事

Every Friday, Mei Ling changes something in the claims agent, and every Monday Aisha and Mr Goh ask the same thing: is it better now? Nobody can say. So she builds a scoreboard that the handlers can open themselves. It runs the agent on claims it has never seen, shows how often it agrees with the handlers, what its mistakes cost, and what a claim costs in money and in time, and it remembers every run. It uses the scoring functions from the first lesson of this topic, saved in scoring.py.

每个星期五，Mei Ling 都会改一点理赔智能体，每个星期一，Aisha 和 Goh 先生都问同一句：现在是不是更好了？没人答得上来。所以她做了一块理赔员自己就能打开的计分板。它让智能体去跑它从没见过的理赔，显示它和理赔员一致的频率、错误的成本、一份理赔花多少钱、用多少时间，并且记住每一轮的结果。它用的是这个主题第一课存进 scoring.py 的打分函数。

Step 1 · Hold out claims the agent has never seen第 1 步 · 留出智能体从没见过的理赔

Learn先学

A student who has seen the exam questions in advance gets a great mark and proves nothing. The same goes for the agent. So set aside a held-out set: claims you promise never to tune the prompt on, scored only by the scoreboard. Pick them once, at random, and save the list in a file so it never changes. Tune on the other claims. Now a good score means the agent copes with claims it has not seen.

提前见过考题的学生，分数很高，却什么也证明不了。智能体也是这样。所以留出一个留出集：你保证绝不拿它们来调提示词，只由计分板来打分。随机挑一次，把名单存进文件，让它永远不变。调试用其他的理赔。这样，高分才意味着智能体能应付没见过的理赔。

# scoreboard.py import json, os, random, threading from datetime import datetime from bench import claims, key, small_prompt, ask, gateway, PRICE from scoring import matrix, accuracy, mistakes, mistake_cost, kappa, straight_through def load_held_out(path="data/held_out_ids.json"): if os.path.exists(path): # already chosen: never choose again return set(json.load(open(path))) ids = sorted(c["id"] for c in claims) random.Random(7).shuffle(ids) held = sorted(ids[:10]) json.dump(held, open(path, "w")) return set(held) HELD_OUT = load_held_out() held_claims = [c for c in claims if c["id"] in HELD_OUT]

Step 2 · Record cost and working time第 2 步 · 记录花费和工作时间

Learn先学

For every claim, keep a list of events: each model call with its tokens and seconds. Cost comes from the tokens and the prices, as before. Time needs care. In live use a claim can sit in the queue waiting for a handler’s sign-off, and that wait is the handler’s time, not the agent’s. So tag those waits human_wait and leave them out when you add up working time. Otherwise a slow handler makes the agent look slow.

每份理赔都记一张事件清单：每次模型调用，带着 token 数和秒数。花费照旧由 token 数和价格算出。时间要小心。真实使用时，一份理赔可能在队列里等理赔员签字，那段等待是理赔员的时间，不是智能体的。所以把这些等待标成 human_wait，加总工作时间时不算它们。否则理赔员慢了，智能体就显得慢。

# scoreboard.py, continued MODEL = "openai/gpt-5.4-mini" def run_claim(claim): """Run the agent on one claim and note every call it makes.""" decision, tin, tout, secs = ask(gateway, MODEL, small_prompt(claim)) events = [{"kind": "model", "secs": secs, "tin": tin, "tout": tout}] return decision, events def working_secs(events): return sum(e["secs"] for e in events if e["kind"] != "human_wait") def cost_us(events): price_in, price_out = PRICE[MODEL] return sum(e.get("tin", 0) * price_in + e.get("tout", 0) * price_out for e in events) / 1_000_000

Step 3 · Score a run第 3 步 · 给一轮运行打分

Learn先学

Now bring it together in one function. It takes the results of one run and returns every number the scoreboard shows: agreement, the mistakes, what they cost in S$, straight-through rate, kappa, and the average cost and working time per claim. Cost is in US$, since that is how the labs bill. Everything else comes straight from scoring.py, so the scoreboard and the lesson always use the same maths.

现在把它们合进一个函数。它拿一轮的结果，返回计分板要显示的每个数：一致率、各种错误、错误的新元成本、直通率、kappa，以及每份理赔的平均花费和工作时间。花费用美元，因为各家实验室按美元收费。其余的全部直接来自 scoring.py，所以计分板和那节课用的是同一套算法。

# scoreboard.py, continued def score_run(results): """results: one {"id", "decision", "events"} per claim.""" pairs = [(key[r["id"]]["action"], r["decision"]["action"]) for r in results] grid = matrix(pairs) n = len(results) return {"claims": n, "agreement": accuracy(grid), "mistakes": mistakes(grid), "mistake_cost_sgd": mistake_cost(grid), "straight_through": straight_through(grid), "kappa": kappa(grid), "cost_per_claim_usd": sum(cost_us(r["events"]) for r in results) / n, "secs_per_claim": sum(working_secs(r["events"]) for r in results) / n}

Step 4 · Run it, and keep every run第 4 步 · 跑一遍，并保留每一轮

Learn先学

An evaluation runs the agent on every held-out claim, scores it, and saves the report as its own file, named by the time. Never overwrite “the latest”. The old files are what you compare against. Also let only one evaluation run at a time: two at once would mix their cost and time, and double the bill. A lock does this. Trying to take it while someone else holds it fails at once, and we turn that into a clear refusal.

一次评估，就是让智能体跑完每一份留出的理赔，打分，再把报告存成一个以时间命名的文件。绝不要覆盖“最新的那份”，旧文件正是你用来对比的东西。同一时间也只让一次评估在跑：两次同时跑，会混在一起算花费和时间，账单还翻倍。用一把锁来做到这一点。别人拿着锁时你再去拿会立刻失败，我们把它变成一句清楚的拒绝。

# scoreboard.py, continued RUNS = "runs" os.makedirs(RUNS, exist_ok=True) _lock = threading.Lock() class Busy(Exception): pass def run_evaluation(label): if not _lock.acquire(blocking=False): # someone else is already running one raise Busy("an evaluation is already running") try: results = [] for claim in held_claims: decision, events = run_claim(claim) results.append({"id": claim["id"], "decision": decision, "events": events}) now = datetime.now() report = {"label": label, "model": MODEL, "at": now.isoformat(timespec="seconds"), "scores": score_run(results)} name = now.strftime("%Y%m%d-%H%M%S") + ".json" json.dump(report, open(os.path.join(RUNS, name), "w"), indent=2) return name, report finally: _lock.release() def list_runs(): return [{**json.load(open(os.path.join(RUNS, n))), "run": n} for n in sorted(os.listdir(RUNS))]

Step 5 · A start button on the dashboard第 5 步 · 仪表板上的启动按钮

Learn先学

Handlers should not need a terminal. Add two web routes to the backend from the pilot: one that starts an evaluation, and one that lists the saved runs. The dashboard’s “Run evaluation” button calls the first, and the table reads the second. If someone presses start while a run is going, the answer is HTTP 409, which means “conflict, not now”. Install with pip install flask. To keep it simple, the request waits until the run is done. For a bigger held-out set you would run it in the background.

理赔员不该需要用终端。给试点的后端加两条网页路由：一条启动评估，一条列出存好的各轮结果。仪表板上的“运行评估”按钮调用第一条，表格读第二条。如果有人在一轮还在跑的时候又按了启动，回应是 HTTP 409，意思是“冲突，现在不行”。用 pip install flask 安装。为了简单，这个请求会一直等到这一轮跑完。留出集大了，你就该让它在后台跑。

# app.py from flask import Flask, jsonify, request from scoreboard import run_evaluation, list_runs, Busy app = Flask(__name__) @app.post("/evaluations") def start_evaluation(): label = (request.get_json(silent=True) or {}).get("label", "unnamed") try: name, report = run_evaluation(label) except Busy: return jsonify(error="an evaluation is already running"), 409 return jsonify(run=name, **report), 201 @app.get("/evaluations") def evaluations(): return jsonify(list_runs())

Step 6 · Compare this run with an earlier one第 6 步 · 把这一轮和早先的一轮对比

Learn先学

The payoff. Take two saved runs and line up every number. For some numbers higher is better (agreement, kappa, straight-through rate). For others lower is better (mistake cost, cost and time per claim). Mark each one better, the same or worse, and return the worse ones. Run it after every change and you see a regression the same day it is made, not three weeks later.

回报来了。拿两轮存好的结果，把每个数对齐。有的数越高越好（一致率、kappa、直通率），有的越低越好（错误成本、每份理赔的花费和时间）。把每一项标成更好、持平或更差，并把更差的项返回。每次改动后都跑一下，你会在改动当天就看到退步，而不是三周以后。

# scoreboard.py, continued HIGHER_IS_BETTER = {"agreement": True, "kappa": True, "straight_through": True, "mistake_cost_sgd": False, "cost_per_claim_usd": False, "secs_per_claim": False} def compare(old, new): worse = [] for metric, higher in HIGHER_IS_BETTER.items(): a, b = old["scores"][metric], new["scores"][metric] if a == b: verdict = "same" elif (b > a) == higher: verdict = "better" else: verdict = "WORSE" worse.append(metric) print(f"{metric:20} {a:10.4f} -> {b:10.4f} {verdict}") return worse # after two evaluations: # runs = list_runs() # compare(runs[-2], runs[-1])

Common errors常见错误

ModuleNotFoundError: No module named 'flask'
Cause: Flask is not installed. Fix: pip install flask.

FileNotFoundError: [Errno 2] No such file or directory: 'runs/20261124-101500.json'
Cause: the runs folder does not exist yet. Fix: create it with os.makedirs(RUNS, exist_ok=True) before the first save.

FileNotFoundError: [Errno 2] No such file or directory: 'runs/20261124-101500.json'
原因：runs 文件夹还不存在。解决：第一次保存之前用 os.makedirs(RUNS, exist_ok=True) 建好。

OSError: [Errno 98] Address already in use
Cause: an old copy of the scoreboard is still running. Fix: stop it, or start the new one on another port.

Recap小结

• The scoreboard saves every evaluation as one file, so any two runs can be compared later.
• It shows the same few numbers every time: agreement, mistake cost, time and cost per claim.
• A change counts as better only when the numbers say so, not when it feels better.

• 计分板把每次评估存成一个文件，以后任意两次都能比较。
• 每次显示同样的几个数字：一致率、错误代价、每份理赔的耗时和成本。
• 只有数字说更好才算更好，感觉更好不算。

Takeaways要点回顾

• Hold out a set of claims the agent has never been tuned on, and choose it once.
• Show agreement, mistake costs, straight-through rate and kappa together, not one number.
• Record tokens and cost for every model call.
• Count working time only: leave out time spent waiting for a human.
• Keep every run as its own file so you can compare with an earlier one.
• Allow one evaluation at a time, and refuse a second start with a clear message.
• Run it after every change: a regression shows up the same day.

• 留出一组智能体从没被拿来调过的理赔，并且只选一次。
• 一致率、错误成本、直通率和 kappa 放在一起展示，不要只给一个数。
• 每一次模型调用都记录 token 和花费。
• 只算工作时间：等人的时间不算。
• 每一轮都存成单独的文件，才能和早先的一轮对比。
• 同一时间只允许一次评估，第二次启动要明确拒绝。
• 每次改动后都跑一遍：退步当天就能发现。
