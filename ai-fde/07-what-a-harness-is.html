What a harness is什么是 harness

See an agent as a model plus everything around it, and why that “everything” is where most of the gains are · ~15 min · concept把智能体看成“模型加上它周围的一切”，并明白大部分进步为什么来自这个“一切” · 约 15 分钟 · 概念课

Where we left off上回讲到

Last time the pilot got its model and a fallback. Today it is slow, carries the whole wording on every claim, and claim C014 sat “in progress” for ever after a crash. We fix it by naming the harness around the model and planning its parts.

上回试点定下了模型和后备。今天的麻烦是：它很慢，每份理赔都背着整份条款，而 C014 崩溃后一直停在“处理中”。我们的办法是给模型周围的那一圈起个名字，叫 harness，并规划它的各个部分。

The story故事

Mei Ling’s claims pilot at Kaya Travel Cover works, but Mr Goh has watched it run and he is not happy. It is slow. Every claim carries the whole policy wording. And claim C014 crashed halfway and sat there marked “in progress” for ever. “The model is clever,” he says. “So why is the system so clumsy?” Mei Ling realises the clumsiness is not in the model at all. It is in everything her code wraps around it. That wrapping has a name: the harness.

Mei Ling 在 Kaya Travel Cover 的理赔试点能跑，但 Mr Goh 看着它运行，并不满意。它很慢，每份理赔都背着整本保单条款，而理赔 C014 跑到一半崩了，从此一直挂着“处理中”。“模型很聪明，”他说，“那为什么整个系统这么笨拙？”Mei Ling 意识到，笨拙根本不在模型，而在她的代码包在模型外面的那一切。这层包装有个名字：harness。

Step 1 · Where the pilot is clumsy第 1 步 · 试点笨在哪里

Learn先学

In the pilot, the model does one small thing: it reads a claim and answers. Everything else is Mei Ling’s code. It picks the order, pastes in the whole wording, and trusts every call to succeed. Like a manager who hands out each customer slip one at a time and never lets the clerk decide anything.

在试点里，模型只做一件小事：读一份理赔，给出答案。其余全是 Mei Ling 的代码在管：它挑顺序、贴上整本条款，还默认每次调用都会成功。就像一个经理，把顾客单子一张一张递给职员，从不让职员自己做任何决定。

# the pilot loop from the claims desk project for claim_id in list(queue): # my code picks the order, one at a time start(claim_id) # decide() pastes the WHOLE policy wording into every prompt # if this line raises an error, the claim stays in_progress for ever record_decision(claim_id, decide(queue[claim_id]["claim"]))

Which of these jobs should the agent do for itself, and which should stay in code?

下面这些事，哪些该让智能体自己做，哪些该留在代码里？

Step 2 · Name the harness第 2 步 · 给 harness 起个名

Learn先学

An agent is a model plus a harness. The model does the thinking. The harness is everything around it that lets the thinking turn into work. Think of the model as a very good clerk and the harness as the desk: the manual on the shelf, the to-do tray, the rule that big payouts wait for the red stamp, and someone to call when it goes wrong. A tool is a plain function your code offers the model, which the model can ask your code to run.

智能体 = 模型 + harness。模型负责思考，harness 是围在它身边、让思考变成工作的一切。把模型想成一位很能干的职员，harness 就是他的办公桌：架子上的手册、待办托盘、“大额赔付要等红色图章”的规矩，还有出事时可以找的人。工具是你的代码提供给模型的普通函数，模型可以请你的代码去运行它。

agent = model + harness harness for the claims desk: 1. instructions what the job is and what good looks like 2. tools look up a manual section, record a decision 3. a to-do list what is waiting, in progress, done 4. helpers a fresh worker for each sub-job 5. middleware code that catches errors and retries

Is each of these part of the model or part of the harness?

下面每一项，属于模型还是属于 harness？

Step 3 · The goal: one run, a list to watch, a fresh helper per claim第 3 步 · 目标：一次运行、一张看得见的清单、每份理赔一个新帮手

Learn先学

Here is what Mei Ling wants. One run works the whole queue. The agent chooses the order itself and keeps a to-do list the handlers can watch. For each claim it hands the job to a helper: a fresh model call that starts clean, sees only that claim, and reports back in one line. A fresh start matters because a long chat drags every earlier claim along, and you pay for all of it each time.

这是 Mei Ling 想要的：一次运行处理完整条队列。智能体自己选顺序，并维护一张理赔员看得到的待办清单。每份理赔，它交给一个帮手：一次全新的模型调用，从干净状态开始，只看这一份理赔，最后用一行话回报。重新开始很重要，因为长对话会把之前所有的理赔都拖着走，而你每次都要为它们付费。

to do C015 C016 C017 in progress C014 done C001 approve S$310 · C002 decline S$0 · C003 refer for handler C009 failed twice

Step 4 · Let the agent find what it needs第 4 步 · 让智能体自己找需要的内容

Learn先学

The pilot pasted the whole wording into every prompt, even for a cancelled flight that needs one paragraph. Better: give the agent a list of section titles and a tool that reads one section. It looks up only what it needs, like opening one drawer of the grey filing cabinet instead of carrying out the whole cabinet.

试点把整本条款贴进每个提示词，哪怕一份航班取消只需要其中一段。更好的做法：给智能体一张章节标题清单，再给它一个能读取某一节的工具。它只查需要的，就像只拉开灰色档案柜的一个抽屉，而不是把整个柜子搬出来。

SECTIONS = {"Flight delays": "...", "Lost baggage": "...", "Reasonable costs": "..."} def read_section(title): """Return one section of the manual, by its title.""" return SECTIONS.get(title, "No such section.")

Step 5 · Make problems fix themselves第 5 步 · 让问题自己修好

Learn先学

Long runs fail somewhere: a timeout, a bad reply, a crash. The harness decides what happens next, so the model never has to. The rule here: a failed claim goes back to the queue once, and if it fails again it is left for a handler. One bad claim must never stop the run. A rule in code is a locked door; a rule in the prompt is only a request.

长时间运行总会在某处出错：超时、坏回复、崩溃。接下来怎么办由 harness 决定，模型不用操心。这里的规矩是：失败的理赔回到队列一次，再失败就留给理赔员。一份坏理赔绝不能拖垮整次运行。代码里的规矩是锁住的门，提示词里的规矩只是请求。

# uses queue, decide and record_decision from the claims desk pilot MAX_TRIES = 2 tries = {} # claim id -> attempts so far def run_one(claim_id): tries[claim_id] = tries.get(claim_id, 0) + 1 try: record_decision(claim_id, decide(queue[claim_id]["claim"])) except Exception: again = tries[claim_id] < MAX_TRIES queue[claim_id]["state"] = "to_do" if again else "for_handler"
What I got wrong我当时想错了Every time something went wrong, I added another rule to the prompt: “if you fail, try again”, “never leave a claim half done”. It did not help: when the call itself crashes, the model never gets to read the prompt, so nothing written there can run. What worked was giving the agent a tool and a to-do list, and letting plain code handle the retries.每次出问题，我就往提示词里再加一条规矩：“失败了就重试”“不要让理赔做到一半”。没有用：调用本身一崩，模型就读不到提示词，写在里面的话也就没机会执行。真正管用的是：给智能体一个工具和一张待办清单，重试这类事交给普通代码。

Now make it yours现在把它变成你的

What changed这一课之后Now the pilot has a plan for its harness: one run, a to-do list, a fresh helper per claim and failures that fix themselves, with the model only doing the thinking. The next problem is choosing how to build it, with an agent SDK or an open framework.现在试点有了 harness 的计划：一次运行、一张待办清单、每份理赔一个新助手、失败自己修复，而模型只负责思考。下一个问题是怎么建：用 agent SDK，还是用开源框架。

Takeaways要点回顾

• An agent is a model plus a harness.
• The harness is instructions, tools, a to-do list, helpers and middleware.
• Most improvements come from the harness, not a smarter model.
• Give the agent tools and a plan, not a longer prompt.
• Use a fresh helper for each unit of work, so cost does not grow as the run goes on.
• Let the agent look things up instead of pasting everything in.
• Failure handling is the harness’s job, so one bad claim never stops the run.

• 智能体 = 模型 + harness。
• harness 包括指令、工具、待办清单、帮手和中间件。
• 大部分进步来自 harness，而不是更聪明的模型。
• 给智能体工具和计划，而不是更长的提示词。
• 每个工作单元用一个新帮手，这样运行越久成本也不会越涨。
• 让智能体自己去查，而不是把所有东西都贴进去。
• 失败处理是 harness 的活，所以一份坏理赔不会拖垮整次运行。
