What a harness is什么是 harness

See an agent as a model plus everything around it, and why that “everything” is where most of the gains are · ~10 min · concept把智能体看成“模型加上它周围的一切”，并明白大部分进步为什么来自这个“一切” · 约 10 分钟 · 概念课

Step 1 · Model plus harness第 1 步 · 模型加 harness

Learn先学
  • An agent is a model plus a harness. The model does the thinking; the harness is everything around it that turns thinking into work.
  • When a pilot is slow, pastes the whole manual into every call, or leaves a claim “in progress” for ever after a crash, the clumsiness is in the harness, not the model.
  • A tool is a plain function your code offers the model, which it can ask your code to run.
  • 智能体 = 模型 + harness。模型负责思考，harness 是围在它身边、让思考变成工作的一切。
  • 试点很慢、每次调用都贴整本手册、崩溃后让理赔永远挂在“处理中”，笨拙的是 harness，不是模型。
  • 工具是你的代码提供给模型的普通函数，模型可以请你的代码去运行它。
agent = model + harness harness for the claims desk: 1. instructions what the job is and what good looks like 2. tools look up a manual section, record a decision 3. a to-do list what is waiting, in progress, done 4. helpers a fresh worker for each sub-job 5. middleware code that catches errors and retries

Is each of these part of the model or part of the harness?

下面每一项，属于模型还是属于 harness？

Step 2 · Let the agent look things up第 2 步 · 让智能体自己去查

Learn先学

Do not paste the whole wording into every prompt. Give the agent a list of section titles and a tool that reads one section, like opening one drawer instead of carrying out the whole cabinet. For each claim, use a fresh helper call that sees only that claim, so cost does not grow as the run goes on.

别把整份条款贴进每个提示词。给智能体一张章节标题清单，再给它一个读取某一节的工具，就像只拉开一个抽屉，而不是把整个柜子搬出来。每份理赔用一个全新的帮手调用，只看这一份，这样运行越久成本也不会越涨。

SECTIONS = {"Flight delays": "...", "Lost baggage": "...", "Reasonable costs": "..."} def read_section(title): """Return one section of the manual, by its title.""" return SECTIONS.get(title, "No such section.")

Step 3 · Make failures fix themselves第 3 步 · 让失败自己修好

Learn先学

When a call crashes, the model never gets to read the prompt, so a rule written there cannot run. Put the rule in code: a failed claim goes back to the queue once, and if it fails again it is left for a handler. One bad claim must never stop the run.

调用一崩，模型就读不到提示词，写在里面的规矩也没机会执行。把规矩放进代码：失败的理赔回到队列一次，再失败就留给理赔员。一份坏理赔绝不能拖垮整次运行。

# uses queue, decide and record_decision from the claims desk pilot MAX_TRIES = 2 tries = {} # claim id -> attempts so far def run_one(claim_id): tries[claim_id] = tries.get(claim_id, 0) + 1 try: record_decision(claim_id, decide(queue[claim_id]["claim"])) except Exception: again = tries[claim_id] < MAX_TRIES queue[claim_id]["state"] = "to_do" if again else "for_handler"

Now make it yours现在把它变成你的

Takeaways要点回顾

• An agent is a model plus a harness: instructions, tools, a to-do list, helpers, middleware.
• Most improvements come from the harness, not a smarter model.
• Let the agent look things up instead of pasting everything in.
• Use a fresh helper per unit of work.
• Failure handling is code, so one bad claim never stops the run.

• 智能体 = 模型 + harness：指令、工具、待办清单、帮手、中间件。
• 大部分进步来自 harness，而不是更聪明的模型。
• 让智能体自己去查，而不是把所有东西都贴进去。
• 每个工作单元用一个新帮手。
• 失败处理是代码的活，所以一份坏理赔不会拖垮整次运行。
