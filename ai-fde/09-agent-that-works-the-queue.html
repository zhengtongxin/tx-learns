Queue-working agent处理队列的智能体

Turn the pilot into one run that works the whole queue, with a to-do list to watch and failures that fix themselves · ~25 min · hands-on把试点变成一次运行就处理整条队列，有张能看的待办清单，失败也能自己修好 · 约 25 分钟 · 动手实践

Step 1 · Let the agent pick the order第 1 步 · 让智能体挑顺序

Learn先学
  • It builds on the small claims desk desk_queue.py in the project package: queue maps a claim id to its record (claim and decision, empty at first), start(id) marks a claim as picked up, and record_decision(id, decision) stores the decision and holds any payout over the sign-off limit for a handler. POLICIES maps a policy id to its cover; client is an OpenAI client.
  • Handlers tackle big or urgent claims first: ask the model for the order, work through it, then write a short summary.
  • response_format={"type": "json_object"} makes the reply valid JSON with no chat around it, so json.loads can read it. Still check the order: drop ids the model invented and add any it forgot.
  • 这一课建立在项目包里的小理赔台 desk_queue.py 之上：queue 把理赔 id 对应到它的记录（理赔内容和决定，决定起初为空），start(id) 把一份理赔标成已接手，record_decision(id, decision) 保存决定，并把超过签字上限的赔付留给理赔员。POLICIES 把保单 id 对应到保障内容；client 是 OpenAI 客户端。
  • 理赔员先处理金额大或紧急的：让模型排序，逐份处理，最后写简短总结。
  • response_format={"type": "json_object"} 让回复是不带闲话的合法 JSON，json.loads 才读得了。顺序仍然要检查：去掉模型编出来的 id，补上它漏掉的。
import json from openai import OpenAI from desk_queue import queue, start, record_decision # the small claims desk in the package client = OpenAI() POLICIES = json.load(open("data/policies.json")) def pick_order(ids): brief = [{"id": i, "amount": queue[i]["claim"]["amount"]} for i in ids] reply = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": "Order these insurance claims the way a careful handler would tackle them. " 'Reply with JSON only: {"order": [claim ids]}\n' + json.dumps(brief)}], response_format={"type": "json_object"}) order = json.loads(reply.choices[0].message.content)["order"] return [i for i in order if i in ids] + [i for i in ids if i not in order] def summarise(lines): reply = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": "Write three short sentences for the claims handlers about this run:\n" + "\n".join(lines)}]) return reply.choices[0].message.content

Step 2 · A to-do board and a fresh helper per claim第 2 步 · 待办板，和每份理赔一个新帮手

Learn先学
  • Keep a to-do list with four states (to do, in progress, done, for handler) and save it to a file on every change. The queue page just reads that file.
  • A helper is a fresh model call that sees one claim only and returns one line, so the 25th claim costs about the same as the first.
  • Give the helper the section titles and one tool, read_manual. The model cannot run code: it asks for a section, your loop runs the function, sends the text back as a tool message (repeating the request's id as tool_call_id) and asks again. Log each title read, to show what a decision was based on.
  • 维护一张有四种状态的待办清单（待办、处理中、已完成、留给理赔员），每次有变化就存进文件。队列页面只要读这个文件。
  • 帮手是只看一份理赔、只返回一行话的全新模型调用，所以第 25 份的成本和第 1 份差不多。
  • 给帮手章节标题和一个工具 read_manual。模型自己不能运行代码：它请求某一节，你的循环运行函数，把文字作为 tool 消息送回去（用 tool_call_id 重复请求的 id），再问一次。记下读过的每个标题，就能显示决定的依据。
TODO_FILE = "todo.json" todo = {} # claim id -> {"state", "tries", "line", "read"} def save_todo(): json.dump(todo, open(TODO_FILE, "w"), indent=1) def plan(ids): for claim_id in ids: todo.setdefault(claim_id, {"state": "to_do", "tries": 0, "line": "", "read": []}) save_todo() SECTIONS = json.load(open("data/manual.json")) # section title -> text, one entry per section TOOLS = [{"type": "function", "function": { "name": "read_manual", "description": "Read one section of the claims manual or policy wording by its exact title.", "parameters": {"type": "object", "properties": {"title": {"type": "string"}}, "required": ["title"]}}}] def decide_with_manual(claim, read_log): policy = POLICIES[claim["policy_id"]] messages = [{"role": "user", "content": f"You help a travel insurer's claims desk. Section titles: {list(SECTIONS)}\n" f"Read only what you need with read_manual. Policy: {json.dumps(policy)}\n" f"Claim: {json.dumps(claim)}\n" 'Then reply with JSON only, no code fences: {"action": "approve" or "decline" or "refer", ' '"payout": a number in S$, "reason": two or three short sentences}'}] for _ in range(6): # at most six rounds, so a helper that keeps reading cannot run forever # 1. ask: the whole conversation so far, plus the tool the model may request message = client.chat.completions.create( model="gpt-5.4-mini", messages=messages, tools=TOOLS).choices[0].message # 2. no tool request: this is the final answer if not message.tool_calls: return json.loads(message.content) # 3. the model asked for sections: keep its request, then answer each one messages.append(message) for call in message.tool_calls: title = json.loads(call.function.arguments)["title"] read_log.append(title) messages.append({"role": "tool", "tool_call_id": call.id, "content": SECTIONS.get(title, "No such section.")}) raise RuntimeError("helper read too many sections without answering") def run_helper(claim_id): """A fresh call: it sees this claim and nothing else.""" read_log = [] decision = decide_with_manual(queue[claim_id]["claim"], read_log) todo[claim_id]["read"] = read_log record_decision(claim_id, decision) return f"{claim_id}: {decision['action']} S${decision['payout']}"

Step 3 · Failures that fix themselves第 3 步 · 会自己修好的失败

Learn先学
  • A claim that fails goes back to the queue once; if it fails twice, it is left for a handler. No claim is decided twice, and every claim ends in a clear state.
  • After a killed run, recover() loads the saved to-do file and puts anything still “in progress” back to “to do”. The file is what remembers “done” across a restart.
  • 失败的理赔回到队列一次；失败两次，就留给理赔员。任何理赔都不会被决定两次，每份最终都处于明确的状态。
  • 运行被杀掉之后，recover() 读回保存的待办文件，把仍停在“处理中”的理赔放回“待办”。跨重启记住“已完成”的，就是这个文件。
import os MAX_TRIES = 2 def recover(): """After a killed run, nothing may stay in_progress.""" if os.path.exists(TODO_FILE): todo.update(json.load(open(TODO_FILE))) # load what the last run saved for item in todo.values(): if item["state"] == "in_progress": item["state"] = "to_do" save_todo() def work_one(claim_id): item = todo[claim_id] if item["state"] != "to_do": return if queue[claim_id]["decision"] is not None: # never decide twice item["state"] = "done" save_todo() return item["state"] = "in_progress" item["tries"] += 1 save_todo() try: start(claim_id) item["line"] = run_helper(claim_id) item["state"] = "done" except Exception as err: if item["tries"] < MAX_TRIES: item["state"] = "to_do" else: item["state"] = "for_handler" item["line"] = f"{claim_id}: failed twice ({type(err).__name__})" save_todo() def run(ids): recover() plan(ids) order = pick_order(ids) while any(todo[i]["state"] == "to_do" for i in ids): for claim_id in order: work_one(claim_id) print(summarise([todo[i]["line"] for i in ids])) run(list(queue)) # start: work every claim that is in the queue

Takeaways要点回顾

• Let the agent order its own queue and write the summary.
• Show a visible to-do list: to do, in progress, done, for handler.
• Use one fresh helper per claim, and look things up by section.
• Retry once, then leave it for a human, and never decide twice.
• Every item must always end in a clear state.

• 让智能体自己给队列排序、写总结。
• 显示一张看得见的待办清单：待办、处理中、已完成、留给理赔员。
• 每份理赔一个新帮手，按章节查资料。
• 重试一次，再不行就留给人，而且绝不决定两次。
• 每个事项最终都必须处于明确的状态。
