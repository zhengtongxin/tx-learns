Project: an agent that remembers customers项目：记得客户的智能体

Build a returning-customer flow with three data sources, each with its own owner and its own rule · ~30 min · hands-on做一个回头客流程，用三个数据源，每个有各自的主人和各自的规则 · 约 30 分钟 · 动手实践

Where we left off上回讲到

Last time the pilot could save and read customer notes through a small memory server. Today it fails when Mr Tan’s second claim arrives: notes, claims records and policy data are mixed together, and nobody knows who may change what. We fix it by keeping three stores apart, each with its own owner.

上回，试点能通过一个小记忆服务端存取客户笔记。今天的问题是：Tan 先生的第二份理赔进来时，笔记、理赔记录和保单数据混在一起，没人说得清谁能改什么。我们的办法是把三个存储分开，各有各的主人。

The story故事

Mr Tan files a claim for a lost bag. A month later he files another. Auntie Siew greets him by name, but the agent treats him like a stranger. Mei Ling wants the second claim to go faster and be better explained. The tricky part is not the notes. It is deciding who owns what: the claims records, the agent’s own notes, and the policy data that nobody on the desk should change by accident.

Tan 先生提交了一份丢行李的理赔。一个月后，他又提交了一份。Siew 阿姨叫得出他的名字，但智能体把他当陌生人。Mei Ling 希望第二份理赔更快、解释得更清楚。难点不在笔记本身，而在谁拥有什么：理赔记录、智能体自己的笔记，以及柜台上谁都不该不小心改动的保单数据。

Words in this lesson这一课用到的词Reference data: facts a person keeps, such as policy limits; the agent may read them but never change them.
Notes: what the agent writes about each customer; they help later claims and a person can read them.
Read-only: a connection that can look but cannot change anything.参考数据：由人维护的事实，比如保单限额；智能体可以读，但绝不能改。
笔记：智能体对每位客户写下的内容；对以后的理赔有帮助，人也能读。
只读：只能看、不能改任何东西的连接。

Step 1 · Three stores, kept apart第 1 步 · 三个存储，分开放

Learn先学

Keep three separate stores. Records (claims.db) are the system of record: what was decided and paid. Memory (memory.db) is the agent’s own notes, keyed by customer. Reference (reference.db) holds policy data, which the agent may only read. If the memory is lost or wrong, the records are untouched. Each store is a SQLite file: a small database kept in one file, with no server to run. Run make_reference.py once first, because the read-only connection needs the file to exist already. Install with pip install openai.

把三个存储分开。记录（claims.db）是权威记录：决定了什么、赔了多少。记忆（memory.db）是智能体自己的笔记，按客户编号存放。参考数据（reference.db）放保单资料，智能体只能读。记忆丢了或错了，记录也不受影响。每个存储都是一个 SQLite 文件：装在一个文件里的小型数据库，不需要单独运行服务器。先运行一次 make_reference.py，因为只读连接要求文件已经存在。用 pip install openai 安装。

# make_reference.py: run once by a person (Kumar), never by the agent import sqlite3 setup = sqlite3.connect("reference.db") setup.execute("CREATE TABLE IF NOT EXISTS policies (id TEXT PRIMARY KEY, cover TEXT, limit_amt REAL)") setup.execute("INSERT OR REPLACE INTO policies VALUES ('P003', 'trip cancellation and lost baggage', 2000)") setup.commit() # desk.py: the agent's side import json, datetime, sqlite3 from openai import OpenAI client = OpenAI() db = sqlite3.connect("claims.db") # records: owned by the handlers mem = sqlite3.connect("memory.db") # notes: owned by the agent ref = sqlite3.connect("file:reference.db?mode=ro", uri=True) # reference: read only db.execute("""CREATE TABLE IF NOT EXISTS claims (id TEXT PRIMARY KEY, customer_id TEXT, story TEXT, amount REAL, action TEXT, payout REAL, reason TEXT, notes_used TEXT)""") mem.execute("CREATE TABLE IF NOT EXISTS notes (customer_id TEXT, note TEXT, claim_id TEXT, saved TEXT)")

Step 2 · After each claim, write a short note第 2 步 · 每份理赔之后，写一条短笔记

Learn先学

When a claim is decided, ask the model what the memory should keep. Give it clear limits: at most two notes, facts only, nothing private. Each note is stored with the claim it came from and the date, so a handler can trace it later.

理赔决定之后，问模型记忆该留下什么。给它明确的限制：最多两条，只要事实，不要私密信息。每条笔记都连同出处理赔和日期存下来，理赔员以后能追溯。

def write_notes(claim, decision): prompt = f"""A claim was just decided. Write at most two short notes that the claims desk may want the next time this customer files. Facts only, taken from the claim and decision below. No guesses, no card or passport numbers. Reply with JSON only: {{"notes": ["...", "..."]}} (an empty list is fine) Claim: {json.dumps(claim)} Decision: {json.dumps(decision)}""" reply = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": prompt}], response_format={"type": "json_object"}) return json.loads(reply.choices[0].message.content)["notes"] def remember(claim, decision): for note in write_notes(claim, decision): mem.execute("INSERT INTO notes VALUES (?, ?, ?, ?)", (claim["customer_id"], note, claim["id"], datetime.date.today().isoformat())) mem.commit()

Step 3 · Before a claim, read that customer’s notes第 3 步 · 理赔之前，读这位客户的笔记

Learn先学

Reading is a lookup by customer id. Then the notes go into the prompt, marked as leads to check, not as proof. The policy cover and limit come from the read-only reference store. The agent only returns an answer; the code decides what to save.

读取就是按客户编号查一下。然后把笔记放进提示词，并标明它们是待核实的线索，不是证据。保单的赔付范围和上限来自只读的参考数据。智能体只返回答案，存什么由代码决定。

def recall(customer_id): rows = mem.execute("SELECT note, claim_id, saved FROM notes WHERE customer_id = ? ORDER BY saved", (customer_id,)).fetchall() return [f"{note} (claim {cid}, saved {saved})" for note, cid, saved in rows] def decide(claim, notes): cover, limit_amt = ref.execute("SELECT cover, limit_amt FROM policies WHERE id = ?", (claim["policy_id"],)).fetchone() prompt = f"""You decide travel insurance claims for Kaya Travel Cover. Policy cover: {cover}. Limit: S${limit_amt}. Notes from this customer's earlier claims (leads to check against today's claim, not proof): {json.dumps(notes)} The claim: {json.dumps(claim)} If a note helped you, say so in the reason. Reply with JSON only: {{"action": "approve" or "decline" or "refer", "payout": a number in S$, "reason": two or three short sentences}}""" reply = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": prompt}], response_format={"type": "json_object"}) return json.loads(reply.choices[0].message.content)

Step 4 · A fresh queue: first claim, then the second第 4 步 · 全新的队列：先第一份，再第二份

Learn先学

One function ties it together: read the notes, decide, save the claim to the records, then write new notes. We also save the notes the agent read next to the decision. Step 5 uses that to show the handler. Delete memory.db and claims.db first so the queue is fresh.

用一个函数把它们串起来：读笔记、做决定、把理赔存进记录、再写新笔记。我们还把智能体读过的笔记和决定存在一起，第 5 步用它给理赔员看。先删掉 memory.db 和 claims.db，让队列是全新的。

def process(claim): notes = recall(claim["customer_id"]) decision = decide(claim, notes) db.execute("INSERT OR REPLACE INTO claims VALUES (?, ?, ?, ?, ?, ?, ?, ?)", (claim["id"], claim["customer_id"], claim["story"], claim["amount"], decision["action"], decision["payout"], decision["reason"], json.dumps(notes))) db.commit() remember(claim, decision) return decision c1 = {"id": "C041", "customer_id": "K-0412", "policy_id": "P003", "story": "My checked bag never arrived. Receipts for everything inside are attached.", "amount": 420} c2 = {"id": "C042", "customer_id": "K-0412", "policy_id": "P003", "story": "My bag was lost again on the flight home. Receipts attached.", "amount": 380} print(process(c1)) print(process(c2))

Step 5 · Show the handler what the agent used第 5 步 · 让理赔员看到智能体用了什么

Learn先学

A decision that rests on invisible notes is hard to trust. Aisha should see, on the claim page, which notes the agent read. If a note is wrong, she can see it and fix it. For the pilot, a printout is enough.

一个靠看不见的笔记做出的决定，很难让人信任。Aisha 应该能在理赔页面上看到智能体读了哪些笔记。如果某条笔记错了，她看得到，也能改。试点阶段，打印出来就够了。

def show_claim(claim_id): action, payout, reason, used = db.execute( "SELECT action, payout, reason, notes_used FROM claims WHERE id = ?", (claim_id,)).fetchone() print(f"{claim_id} {action} S${payout}") print(" why:", reason) print(" notes the agent read:") for note in json.loads(used) or ["(none)"]: print(" -", note) show_claim("C042")

Expected output

预期输出

C042 refer S$0 why: second lost-bag claim by K-0412 in 9 days notes the agent read: - C041: bag lost on outbound flight, S$420 approved

Step 6 · Three sources, three owners第 6 步 · 三个数据源，三个主人

Learn先学

Now name the owners. Records belong to the handlers: they are the truth. Memory belongs to the agent: it is a helpful guess that can be deleted. Reference data belongs to the people who maintain it, and the agent only reads it. “Read only” must be enforced by permissions, not by an instruction. In Step 1 the reference store was opened with mode=ro, so even a bug cannot write to it.

现在给它们定主人。记录属于理赔员：它是事实。记忆属于智能体：它是有用的参考，可以删掉。参考数据属于维护它的人，智能体只读。“只读”必须靠权限来保证，而不是靠一句指令。第 1 步里参考数据是用 mode=ro 打开的，所以哪怕有 bug 也写不进去。

Common errors常见错误

sqlite3.OperationalError: no such table: notes
Cause: the database file is new and the table was never created. Fix: run the CREATE TABLE IF NOT EXISTS line first.

sqlite3.OperationalError: no such table: notes
原因：数据库文件是新的，表从来没建过。解决：先运行 CREATE TABLE IF NOT EXISTS 那一行。

sqlite3.OperationalError: database is locked
Cause: two programs write to the file at once. Fix: close the other one, and keep each write short with commit() right after.

sqlite3.OperationalError: database is locked
原因：两个程序同时写这个文件。解决：关掉另一个，并让每次写入都短，写完立刻 commit()。

sqlite3.OperationalError: attempt to write a readonly database
Cause: this one is on purpose; the agent's connection to the reference data is read-only. Fix: nothing; write through the notes function only.

sqlite3.OperationalError: attempt to write a readonly database
原因：这是故意的，智能体对参考数据的连接是只读的。解决：不用改；只通过笔记函数写入。

Recap小结

• Keep two stores: reference data the agent only reads, and notes it may write.
• Open the reference data read-only, so a mistake cannot change it.
• Show which notes were read for each claim.

• 分成两个存储：智能体只读的参考数据，和它可以写的笔记。
• 参考数据用只读方式打开，出错也改不了它。
• 每份理赔都显示读了哪些笔记。

Takeaways要点回顾

• Keep three sources apart: records, memory, reference data.
• The database stays the system of record. Memory is the agent’s own notes and can be deleted.
• Write short, factual notes after a claim and read them before the next one.
• Key notes by customer, so one customer never sees another’s notes.
• Show the handler which notes the agent used.
• Three sources have three owners and three rules.
• Enforce read-only with permissions, not with instructions.

• 把三个数据源分开：记录、记忆、参考数据。
• 数据库仍然是权威记录。记忆是智能体自己的笔记，可以删掉。
• 理赔之后写简短的事实笔记，下一次理赔前先读。
• 笔记按客户存放，这样一位客户不会看到另一位的笔记。
• 让理赔员看到智能体用了哪些笔记。
• 三个数据源，三个主人，三条规则。
• 用权限来保证只读，而不是靠指令。
