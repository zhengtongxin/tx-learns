Customer-memory agent记得客户的智能体

Build a returning-customer flow with three data sources, each with its own owner and its own rule · ~30 min · hands-on做一个回头客流程，用三个数据源，每个有各自的主人和各自的规则 · 约 30 分钟 · 动手实践

Step 1 · Three stores, three owners第 1 步 · 三个存储，三个主人

Learn先学
  • Records (claims.db): what was decided and paid. Owner: the handlers. This is the truth.
  • Memory (memory.db): the agent's own notes per customer. Owner: the agent. A helpful guess, safe to delete.
  • Reference (reference.db): policy limits. Owner: the people who maintain it. The agent only reads it.
  • 记录（claims.db）：决定了什么、赔了多少。主人：理赔员。这是事实。
  • 记忆（memory.db）：智能体按客户写的笔记。主人：智能体。是有用的参考，可以删。
  • 参考数据（reference.db）：保单上限。主人：维护它的人。智能体只读。
# make_reference.py: run once by a person, never by the agent import sqlite3 setup = sqlite3.connect("reference.db") setup.execute("CREATE TABLE IF NOT EXISTS policies (id TEXT PRIMARY KEY, cover TEXT, limit_amt REAL)") setup.execute("INSERT OR REPLACE INTO policies VALUES ('P003', 'trip cancellation and lost baggage', 2000)") setup.commit() # desk.py: the agent's side (pip install openai) import json, datetime, sqlite3 from openai import OpenAI client = OpenAI() db = sqlite3.connect("claims.db") # records: the handlers' truth mem = sqlite3.connect("memory.db") # notes: the agent's own ref = sqlite3.connect("file:reference.db?mode=ro", uri=True) # reference: read only db.execute("""CREATE TABLE IF NOT EXISTS claims (id TEXT PRIMARY KEY, customer_id TEXT, story TEXT, amount REAL, action TEXT, payout REAL, reason TEXT)""") mem.execute("CREATE TABLE IF NOT EXISTS notes (customer_id TEXT, note TEXT, claim_id TEXT, saved TEXT)")

Step 2 · Read notes, decide, write notes第 2 步 · 读笔记、决定、写笔记

Learn先学
  • Before a claim: look up that customer's notes and put them in the prompt as leads to check, not proof.
  • After a claim: ask the model for at most two factual notes, stored with the claim id and date.
  • The code decides what is saved; the agent only returns an answer.
  • 理赔之前：查这位客户的笔记，放进提示词，作为待核实的线索，不是证据。
  • 理赔之后：让模型写最多两条事实笔记，连同理赔编号和日期存下来。
  • 存什么由代码决定；智能体只返回答案。
def recall(customer_id): rows = mem.execute("SELECT note, claim_id, saved FROM notes WHERE customer_id = ? ORDER BY saved", (customer_id,)).fetchall() return [f"{note} (claim {cid}, saved {saved})" for note, cid, saved in rows] def ask(prompt): reply = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": prompt}], response_format={"type": "json_object"}) return json.loads(reply.choices[0].message.content) def decide(claim, notes): cover, limit_amt = ref.execute("SELECT cover, limit_amt FROM policies WHERE id = ?", (claim["policy_id"],)).fetchone() return ask(f"""You decide travel insurance claims. Policy cover: {cover}. Limit: S${limit_amt}. Notes from earlier claims (leads, not proof): {json.dumps(notes)} Claim: {json.dumps(claim)} Reply with JSON only: {{"action": "approve" or "decline" or "refer", "payout": number in S$, "reason": short}}""") def remember(claim, decision): notes = ask(f"""Write at most two short factual notes for the next time this customer files. No guesses, no card or passport numbers. Reply with JSON only: {{"notes": ["..."]}} Claim: {json.dumps(claim)} Decision: {json.dumps(decision)}""")["notes"] for note in notes: mem.execute("INSERT INTO notes VALUES (?, ?, ?, ?)", (claim["customer_id"], note, claim["id"], datetime.date.today().isoformat())) mem.commit() def process(claim): decision = decide(claim, recall(claim["customer_id"])) db.execute("INSERT OR REPLACE INTO claims VALUES (?, ?, ?, ?, ?, ?, ?)", (claim["id"], claim["customer_id"], claim["story"], claim["amount"], decision["action"], decision["payout"], decision["reason"])) db.commit() remember(claim, decision) return decision c1 = {"id": "C041", "customer_id": "K-0412", "policy_id": "P003", "story": "My checked bag never arrived. Receipts attached.", "amount": 420} c2 = {"id": "C042", "customer_id": "K-0412", "policy_id": "P003", "story": "My bag was lost again on the flight home. Receipts attached.", "amount": 380} print(process(c1)) print(process(c2))

Step 3 · Enforce read-only with permissions第 3 步 · 用权限保证只读

Learn先学

“Read only” must come from permissions, not from an instruction. The reference store was opened with mode=ro, so even a bug cannot change a policy limit.

“只读”必须靠权限来保证，而不是靠一句指令。参考数据是用 mode=ro 打开的，所以哪怕有 bug 也改不了保单上限。

Takeaways要点回顾

• Keep records, memory and reference data apart; each has its own owner.
• Records are the truth; memory is the agent's deletable notes.
• Write short factual notes after a claim, key them by customer, read them before the next.
• Enforce read-only with permissions, not instructions.

• 把记录、记忆、参考数据分开，各有各的主人。
• 记录是事实；记忆是智能体可删除的笔记。
• 理赔后写简短的事实笔记，按客户存放，下次理赔前先读。
• 用权限而不是指令来保证只读。
