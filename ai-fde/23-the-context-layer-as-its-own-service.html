The context layer as its own service把上下文层做成独立服务

Keep the business’s definitions and rules in a read-only service with an owner, so they can change without a deployment · ~30 min · concept with one runnable idea把业务的定义和规则放进一个有主人的只读服务里，改它们不用重新部署 · 约 30 分钟 · 概念课，带一段能跑的代码

Last time the pilot’s actions went through Kumar’s keys, gateway and policy. Today it fails when Mr Goh asks which wording of the baggage rule a payout followed and who last checked it: the rules were pasted into the prompt, and nobody owns them. We fix it by moving them to a service of their own, owned by data governance.

上回，试点的动作都要经过 Kumar 的密钥、网关和策略。今天的问题是 Goh 先生问一笔赔付依据哪一版行李规则的措辞、最后是谁核对的：规则是贴在提示词里的，没有主人。我们的办法是把它们搬进一个独立的服务，由数据治理部门负责。

The story故事

Mr Goh points at a payout on the claim page and asks two questions. “Which wording of the baggage rule did the agent follow? And who last checked it?” Mei Ling goes quiet. She had pasted the plan limits and the rules straight into the agent’s prompt and code. Nobody owns a pasted rule, and nobody can say when it was last checked. So she moves them out, to a service of their own, owned by data governance. You need Flask and requests (pip install flask requests) and the gateway and agent tools from the last lesson.

Goh 先生指着理赔页上的一笔赔付，问了两个问题。“智能体照的是哪一版行李规则的措辞？最后是谁核对过的？”Mei Ling 一时答不上来。她把保单限额和规则直接贴进了智能体的提示词和代码里。贴进去的规则没有主人，也没人说得出上次核对是什么时候。所以她把它们搬出来，放进一个独立的服务，由数据治理部门负责。你需要 Flask 和 requests（pip install flask requests），还有上一课的网关和智能体工具。

Words in this lesson这一课用到的词Context layer: the shared, reviewed facts the agent reads: glossary, rules, limits, each with an owner.
Manifest: a list saying where each file came from, who owns it and when it was last reviewed.
Read-only service: a service with no way to write, so the agent cannot change what it reads.上下文层：智能体读取的、共享并审核过的事实：词汇表、规则、限额，各有负责人。
清单：一份列表，写明每个文件的来源、负责人和上次审核时间。
只读服务：没有写入入口的服务，智能体改不了它读到的内容。

Step 1 · Three sources, three owners第 1 步 · 三个来源，三个主人

Learn先学

Everything the agent knows comes from one of three places. The context layer holds the business’s own definitions and rules, copied from other systems. Data governance owns it, and the agent may only read it. Memory is the agent’s own notes, which it may write. The database is the system of record: claims and payments. Think of the shophouse: the printed manual on the wall, Auntie Siew’s notebook of regulars, and the receipt book at the till.

智能体知道的一切，都来自三个地方之一。上下文层放业务自己的定义和规则，是从其他系统复制来的。它归数据治理部门所有，智能体只能读。记忆是智能体自己的笔记，它可以写。数据库是权威记录：理赔和付款。想想店屋里的东西：墙上贴的手册、Siew 阿姨记着老客人的小本子，还有收银台上的收据本。

SOURCES = { "context layer": {"holds": "definitions and rules from other systems", "owner": "data governance", "agent may": "read"}, "memory": {"holds": "the agent’s own notes about customers", "owner": "the agent", "agent may": "read and write"}, "database": {"holds": "claims and payments, the system of record", "owner": "the backend", "agent may": "only through the gateway’s tools"}, } for name, s in SOURCES.items(): print(name, "| owner:", s["owner"], "| agent may:", s["agent may"])

Step 2 · Seven files, each with an owner and a date第 2 步 · 七个文件，每个有主人和日期

Learn先学

Data governance supplies seven files: plans, claim rules, a glossary, a data dictionary, reference data, the wording of customer letters, and the claims manual. Next to them goes a manifest: a small file that says, for each one, where it came from, who owns it and when it was last reviewed. A rule without those three things is just a rumour. The script below stands in for governance’s own export.

数据治理部门提供七个文件：保险计划、理赔规则、术语表、数据字典、参考数据、给客户的信函措辞，以及理赔手册。旁边再放一个清单文件（manifest）：它为每个文件写明来自哪里、谁负责、上次什么时候复核。缺了这三样的规则，只是一句传言。下面的脚本代替治理部门自己的导出。

# make_context.py: stands in for data governance’s export import json, pathlib FILES = { "plans": ("policy admin system", {"P003": {"name": "Trip Care", "baggage_limit": 1000, "excess": 100}}), "claim_rules": ("claims manual", {"baggage": {"payout": "min(claimed - excess, baggage_limit)", "signoff_above": 800}}), "glossary": ("data governance", {"excess": "The part of a claim the customer pays first."}), "data_dictionary": ("data warehouse", {"claimed": "Amount the customer asks for, in S$"}), "reference_data": ("finance system", {"causes": ["lost baggage", "delay", "cancellation"]}), "wording": ("compliance", {"approve": "We are glad to approve your claim.", "decline": "We are sorry, this claim is not covered."}), "manual": ("claims manual", {"version": "2026.3", "text": "Baggage claims are paid after the excess, up to the plan limit."}), } root = pathlib.Path("context") root.mkdir(exist_ok=True) manifest = {} for name, (source, content) in FILES.items(): (root / (name + ".json")).write_text(json.dumps(content, indent=2)) manifest[name] = {"source": source, "owner": "data governance", "reviewed": "2026-11-02"} (root / "manifest.json").write_text(json.dumps(manifest, indent=2)) print(len(manifest), "files written")

Step 3 · Serve them as a small service with its own sign-in第 3 步 · 做成有自己登录的小服务

Learn先学

Now serve the files from a service of their own, with its own key, like the backend in the last lesson. The key check uses hmac.compare_digest. It takes the same time however much of a wrong key matches, so nobody can guess the key one character at a time by timing replies. It has only read routes, so there is no way to write through it. It opens a file fresh on every request. That is what lets governance change a rule and have it show up without a deployment. And it only opens names found in the manifest, so a request like ../secrets goes nowhere.

现在用一个独立的服务把这些文件提供出去，它有自己的密钥，和上一课的后端一样。密钥检查用的是 hmac.compare_digest：不管错的密钥有多少字符对上，它花的时间都一样，所以没人能靠测算回复的时间，一个字符一个字符地猜出密钥。它只有读的路由，没有任何办法通过它写入。每次请求都重新打开文件，所以治理部门改了规则，不用部署就能生效。它也只打开清单里有的名字，所以像 ../secrets 这样的请求哪里也去不了。

# context_service.py import hmac, json, os, pathlib from flask import Flask, jsonify, request if len(os.environ.get("CONTEXT_KEY", "")) < 32: raise SystemExit("CONTEXT_KEY is missing or too short: refusing to start") app = Flask(__name__) ROOT = pathlib.Path(os.environ.get("CONTEXT_DIR", "context")) def manifest(): return json.loads((ROOT / "manifest.json").read_text()) @app.before_request def need_key(): sent = request.headers.get("X-API-Key", "") if not hmac.compare_digest(sent.encode(), os.environ["CONTEXT_KEY"].encode()): return jsonify(error="missing or wrong key"), 401 @app.get("/context") def index(): return jsonify(manifest()) @app.get("/context/<name>") def one(name): meta = manifest().get(name) if meta is None: return jsonify(error="unknown file"), 404 content = json.loads((ROOT / (name + ".json")).read_text()) return jsonify(name=name, meta=meta, content=content) # try_it.py # import os # os.environ["CONTEXT_KEY"] = "ctx-" + "z" * 40 # demo value only # from context_service import app # client, key = app.test_client(), {"X-API-Key": os.environ["CONTEXT_KEY"]} # print(client.get("/context/glossary", headers=key).status_code) # 200 # print(client.post("/context/glossary", json={"excess": "x"}, headers=key).status_code) # 405: no write route

Step 4 · A second target behind the same gateway第 4 步 · 挂在同一个网关后面的第二个目标

Learn先学

The agent should not hold a key for this service either. Add the context service as a second target of the action gateway from the last lesson. The gateway checks the agent’s key, then forwards the read with the context key that only it holds. Reads now pass the same door as actions, and the same log sees them. The agent gets one more tool, read_context. Set CONTEXT_KEY (and optionally CONTEXT_URL) for the gateway too.

智能体也不该持有这个服务的密钥。把上下文服务加成上一课那个动作网关的第二个目标。网关核对智能体的密钥，再用只有它才有的上下文密钥转发这次读取。读取和动作走同一扇门，同一份日志也看得到它们。智能体多了一个工具 read_context。网关也要设置 CONTEXT_KEY（以及可选的 CONTEXT_URL）。

# action_gateway.py: add below the existing routes (re, requests, jsonify and os are already imported) CONTEXT_URL = os.environ.get("CONTEXT_URL", "http://127.0.0.1:5002") CONTEXT_KEY = os.environ["CONTEXT_KEY"] # only the gateway holds this @app.get("/context/<name>") def read_context(name): if not re.fullmatch(r"[a-z_]{1,40}", name): return jsonify(error="bad name"), 400 reply = requests.get(CONTEXT_URL + "/context/" + name, headers={"X-API-Key": CONTEXT_KEY}, timeout=10) return jsonify(reply.json()), reply.status_code # agent_tools.py: one more tool, next to record_decision and pay_claim @function_tool def read_context(name: str) -> str: """Read one governed file: plans, claim_rules, glossary, data_dictionary, reference_data, wording or manual.""" reply = requests.get(GATEWAY_URL + "/context/" + name, headers=HEADERS, timeout=10) return str(reply.status_code) + " " + reply.text

Step 5 · A decision record you could audit第 5 步 · 一份经得起审计的判定记录

Learn先学

Because every read has an owner and a date, the record of a decision can now be complete. It keeps the calculation as numbers, who or what decided, the version of the manual it followed, and every file it read with its source and review date. Store the facts as they were that day, not pointers to files that may change tomorrow.

既然每次读取都有主人和日期，判定记录就能做到完整。它把计算过程用数字记下来，写明是谁或什么做的决定、依据的手册版本，以及读过的每个文件、它的来源和复核日期。要把当天的事实存下来，而不是存指向明天可能会变的文件的指针。

# record.py import datetime def calculate(claimed, plan): payout = max(0, min(claimed - plan["excess"], plan["baggage_limit"])) return payout, "min(%s - %s, %s) = %s" % (claimed, plan["excess"], plan["baggage_limit"], payout) def build_record(claim_id, claimed, plan_id, ctx, decided_by): """ctx holds what the agent read: file name -> the service’s reply (meta and content).""" payout, calculation = calculate(claimed, ctx["plans"]["content"][plan_id]) return { "claim_id": claim_id, "payout": payout, "calculation": calculation, "decided_by": decided_by, "manual_version": ctx["manual"]["content"]["version"], "read": [{"file": n, "source": c["meta"]["source"], "reviewed": c["meta"]["reviewed"]} for n, c in ctx.items()], "at": datetime.datetime.now(datetime.timezone.utc).isoformat(), } # try_it.py # meta = {"source": "claims manual", "owner": "data governance", "reviewed": "2026-11-02"} # ctx = {"plans": {"meta": meta, "content": {"P003": {"baggage_limit": 1000, "excess": 100}}}, # "manual": {"meta": meta, "content": {"version": "2026.3"}}} # print(build_record("C007", 1400, "P003", ctx, "agent")["calculation"]) # min(1400 - 100, 1000) = 1000

Step 6 · Show every step on the claim page第 6 步 · 在理赔页上展示每一步

Learn先学

A record nobody can see does not help Mr Goh. Turn it into an ordered list on the claim page: what was read, from where, the sum, and who decided. Text that came from files goes through escape, so a stray < in a file can never become markup on the page.

没人看得到的记录，对 Goh 先生没有用。把它变成理赔页上一份有顺序的清单：读了什么、来自哪里、算式，以及谁做的决定。来自文件的文字都要过一遍 escape，这样文件里偶然出现的 < 永远不会变成页面上的标记。

# claim_page.py from html import escape def page(r): steps = ["Read %s (from %s)" % (f["file"], f["source"]) for f in r["read"]] steps.append("Worked out: " + r["calculation"]) steps.append("Decided by %s, following manual %s" % (r["decided_by"], r["manual_version"])) items = "".join("<li>" + escape(s) + "</li>" for s in steps) return "<h1>Claim " + escape(r["claim_id"]) + ": S$" + escape(str(r["payout"])) + "</h1><ol>" + items + "</ol>"

The next export from data governance silently overwrote my fix, and for a while nobody knew why the agent’s wording had changed back. They are not mine. The agent only reads them, and a change goes to the owner, who changes it at the source.在我看来，治理部门的文件就像配置文件，所以我当成自己的东西。术语表里有一行写得不好，我就直接改了。数据治理部门下一次导出时，悄悄把我的修改覆盖掉了，有一阵子没人知道为什么智能体的措辞又变回去了。它们不是我的。智能体只读，要改就找主人，让他们从源头改。

Common errors常见错误

SystemExit: CONTEXT_KEY is missing or too short
Cause: the service refuses to start without a long key. Fix: make one and export CONTEXT_KEY before starting.

SystemExit: CONTEXT_KEY is missing or too short
原因：没有足够长的密钥，服务拒绝启动。解决：生成一把，并在启动前 export CONTEXT_KEY。

FileNotFoundError: context/manifest.json
Cause: the export has not been made yet. Fix: run make_context.py first.

FileNotFoundError: context/manifest.json
原因：还没生成导出文件。解决：先运行 make_context.py。

405 Method Not Allowed
Cause: you tried to write to the context layer. Fix: that is on purpose; changes go through its owner, not through the agent.

405 Method Not Allowed
原因：你想往上下文层写东西。解决：这是故意的；修改要通过它的负责人，不是通过智能体。

Recap小结

• Move the shared facts into their own service, with an owner for each source.
• The agent can read the context layer but has no route to change it.
• Every answer carries which context it used and when it was reviewed.

• 把共享的事实搬进独立的服务，每个来源有负责人。
• 智能体可以读上下文层，但没有任何途径去改它。
• 每个答案都带上它用了哪些上下文、什么时候审核的。

Takeaways要点回顾

• The agent reads from three places: the context layer, its own memory and the database. Each has a different owner.
• Context has an owner, a source and a review date, written in a manifest.
• The agent only reads the context layer. A fix goes to the owner, never into the files.
• Serve context as its own service, with its own key and no write routes, so a rule can change without a deployment.
• Put the service behind the same gateway as a second target, so reads pass the same door as actions.
• A decision record keeps the calculation, who or what decided, the manual version and the files read, as they were that day.
• Show those steps on the claim page, with text escaped.

• 智能体从三个地方读：上下文层、自己的记忆和数据库。每个地方的主人不同。
• 上下文有主人、有来源、有复核日期，写在清单文件里。
• 智能体对上下文层只读。要改就找主人，绝不直接改文件。
• 把上下文做成独立服务，有自己的密钥，没有写入路由，规则才能不用部署就更新。
• 把服务放在同一个网关后面当第二个目标，读取和动作走同一扇门。
• 判定记录保存算式、是谁或什么做的决定、手册版本和读过的文件，都是当天的样子。
• 把这些步骤展示在理赔页上，文字要转义。
