Approval and resume批准与恢复

Make the agent able to wait for a person and carry on after a restart, without paying twice · ~25 min · concept with one runnable idea让智能体能等人批准，重启之后接着干，而且不会重复付款 · 约 25 分钟 · 概念课，附一个可动手的做法

Step 1 · Steps, edges and a checkpointer第 1 步 · 步骤、连线和存档器

Learn先学
  • Progress can only be saved if it has a shape: draw the agent as a graph. A node is a step, an edge says what comes next, the state is the notebook that travels along.
  • A checkpointer saves the state after every step, in a database. Not in a file beside the code: a server is replaced on every deploy or crash and its files go with it, while a database lives somewhere else and is still there after a restart.
  • Each claim gets a thread id, its folder label. Same id later, same folder.
  • 进度要有“形状”才存得下来：把智能体画成一张图。节点是步骤，边说明下一步去哪，状态是沿途传递的笔记本。
  • 存档器在每一步之后保存状态，放在数据库里。不能放在代码旁边的文件里：服务器每次部署或崩溃都会被换掉，文件也跟着没了；数据库在别处，重启之后还在。
  • 每份理赔有一个线程 id，就是文件夹标签。以后用同一个 id，就找到同一个文件夹。

Uses LangGraph: pip install langgraph langgraph-checkpoint-postgres "psycopg[binary]", and set DATABASE_URL to a Postgres connection string (it starts with postgresql://). A free hosted Postgres such as Neon or Supabase shows that string after you create a database. No database yet? Use InMemorySaver() from langgraph.checkpoint.memory as the checkpointer to try the steps; it forgets everything on exit.

这里用 LangGraph：pip install langgraph langgraph-checkpoint-postgres "psycopg[binary]"，并把 DATABASE_URL 设成 Postgres 连接串（以 postgresql:// 开头）。Neon 或 Supabase 这类免费托管的 Postgres，建好数据库后就会给出这串字符。还没有数据库？先用 langgraph.checkpoint.memory 里的 InMemorySaver() 当存档器来试这几步；它一退出就全忘了。

import os from typing import TypedDict from langgraph.graph import StateGraph, START, END from langgraph.checkpoint.postgres import PostgresSaver SIGNOFF_LIMIT = 800 # Stand-ins so this runs on its own. Swap in the real agent and payment call later. def decide_claim(claim): return {"action": "approve", "payout": claim["amount"]} def send_payment(claim_id, amount): print("paying", claim_id, amount) class ClaimState(TypedDict, total=False): claim: dict decision: dict paid: bool def decide(state): return {"decision": decide_claim(state["claim"])} def pay(state): if state["decision"]["action"] != "approve": return {"paid": False} send_payment(state["claim"]["id"], state["decision"]["payout"]) return {"paid": True} builder = StateGraph(ClaimState) builder.add_node("decide", decide) builder.add_node("pay", pay) builder.add_edge(START, "decide") builder.add_edge("decide", "pay") builder.add_edge("pay", END) with PostgresSaver.from_conn_string(os.environ["DATABASE_URL"]) as checkpointer: checkpointer.setup() # creates its tables the first time graph = builder.compile(checkpointer=checkpointer) config = {"configurable": {"thread_id": "C-1042"}} result = graph.invoke({"claim": {"id": "C-1042", "amount": 600}}, config) print(result["paid"])

Step 2 · Stop for a person, then resume第 2 步 · 停下等人，再接着干

Learn先学
  • A node that calls interrupt() saves everything, hands a question to whoever is watching, and ends the run. Nothing waits in memory; the process can exit.
  • Who answers? Your own code passes the question on. The first invoke returns with the question under __interrupt__; show it to the handler (a page, a chat message). When she answers, your code calls the graph again, as the last lines of the box show.
  • A conditional edge sends only payouts over the limit down this path.
  • To resume, call the graph again with the same thread id and Command(resume=...). The answer becomes the return value of interrupt().
  • Catch: the node restarts from its first line, so code above interrupt() must be safe to run twice (no payments, no emails).
  • 调用 interrupt() 的节点会存好一切，把问题交给在看的人，然后结束这次运行。内存里没有东西在等；进程可以退出。
  • 谁来回答？由你自己的代码转交问题。第一次 invoke 返回时，问题就在 __interrupt__ 里；把它显示给理赔员（一个页面、一条聊天消息）。她回答后，你的代码再次调用这张图，就是代码框最后几行。
  • 一条条件边只让超过限额的赔付走这条路。
  • 要恢复，就用同一个线程 id 和 Command(resume=...) 再次调用这张图。答案成为 interrupt() 的返回值。
  • 陷阱：节点会从第一行重新开始，所以 interrupt() 上面的代码必须能安全地跑两遍（不付款，不发邮件）。
from langgraph.types import interrupt, Command class ClaimState(TypedDict, total=False): claim: dict decision: dict signed_off: bool paid: bool def approve(state): d = state["decision"] answer = interrupt({"claim": state["claim"]["id"], "payout": d["payout"]}) return {"signed_off": answer["ok"]} # runs only after a person answers def after_decide(state): d = state["decision"] big = d["action"] == "approve" and float(d["payout"]) > SIGNOFF_LIMIT return "approve" if big else "pay" def after_approve(state): return "pay" if state["signed_off"] else END builder = StateGraph(ClaimState) builder.add_node("decide", decide) builder.add_node("approve", approve) builder.add_node("pay", pay) builder.add_edge(START, "decide") builder.add_conditional_edges("decide", after_decide, ["approve", "pay"]) builder.add_conditional_edges("approve", after_approve, ["pay", END]) builder.add_edge("pay", END) # compile again inside the with block, so graph keeps its checkpointer # graph = builder.compile(checkpointer=checkpointer) # config = {"configurable": {"thread_id": "C-1200"}} # result = graph.invoke({"claim": {"id": "C-1200", "amount": 1200}}, config) # result["__interrupt__"][0].value -> {"claim": "C-1200", "payout": 1200} # # hours later, maybe from another process: # result = graph.invoke(Command(resume={"ok": True}), config) # pays after the sign-off

Step 3 · Survive a crash without paying twice第 3 步 · 崩溃后不重复付款

Learn先学
  • After a restart, graph.get_state(config) shows where the claim stands and invoke(None, config) carries on. Finished steps are not run again.
  • If the process dies after a payment went out but before the checkpoint saved, pay runs again. Fix: an idempotency key, a unique label sent with each payment. The backend ignores a key it has seen.
  • The backend also checks the sign-off rule itself; never trust the agent alone.
  • 重启后，graph.get_state(config) 显示这份理赔停在哪，invoke(None, config) 接着干。已完成的步骤不会重跑。
  • 如果进程在付款发出之后、存档之前挂了，pay 会再跑一遍。解法：幂等键，每笔付款带一个唯一标签，后端忽略见过的键。
  • 后端也自己检查签字规则；不能只信智能体。
# after a crash: rebuild the graph, then # snapshot = graph.get_state(config); print(snapshot.next) # e.g. ('pay',) # if snapshot.next: graph.invoke(None, config) paid_keys = {} # in real life: a table where the key column must be unique def send_payment(claim_id, amount, key, signed_off=False): if key in paid_keys: # a repeat after a restart: do nothing return paid_keys[key] if amount > SIGNOFF_LIMIT and not signed_off: raise ValueError("over the limit and not signed off") paid_keys[key] = {"claim": claim_id, "amount": amount} return paid_keys[key] def pay(state): if state["decision"]["action"] != "approve": return {"paid": False} claim_id = state["claim"]["id"] send_payment(claim_id, state["decision"]["payout"], key="pay-" + claim_id, # same claim, same key, every time signed_off=state.get("signed_off", False)) return {"paid": True}

Takeaways要点回顾

• Draw the agent as steps and edges; a checkpointer saves state after every step, one thread id per claim.
• Pause by saving, not by waiting: interrupt() stops the run, a later resume carries on.
• A resumed node restarts from its first line, so keep side effects out of the code above interrupt().
• Make every step safe to repeat: a unique key per payment, and the backend enforces the sign-off rule.

• 把智能体画成步骤和连线；存档器在每一步之后保存状态，每份理赔一个线程 id。
• 用存档来暂停，而不是干等：interrupt() 停下运行，之后恢复就能接着干。
• 恢复的节点从第一行重新开始，所以 interrupt() 上面的代码不能有副作用。
• 让每一步都能安全重复：每笔付款一个唯一键，签字规则由后端把关。
