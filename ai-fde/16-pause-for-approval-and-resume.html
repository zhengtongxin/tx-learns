Pausing and working in parallel · Lesson 1暂停与并行 · 第 1 课

Pause for approval, resume after a crash等人批准再继续，崩溃后接着干

Make the agent able to wait for a person and carry on after a restart, without paying twice · ~25 min · concept with one runnable idea让智能体能等人批准，重启之后接着干，而且不会重复付款 · 约 25 分钟 · 概念课，附一个可动手的做法

Where we left off上回讲到

Last time the pilot knew each returning customer and kept its notes apart from the records. Today it fails when a S$1,200 payout needs Aisha’s stamp and she is at lunch: a power cut would wipe the claim, and a restart might pay twice. We fix it by saving the pilot’s place after every step.

上回，试点认得每位回头客，也把笔记和记录分开存放。今天的问题是：一笔 S$1,200 的赔付要 Aisha 盖章，而她在吃午饭，一次断电就会让这份理赔消失，重启还可能付两次钱。我们的办法是每走一步就存一次档。

The story故事

Mei Ling’s claims agent decides a S$1,200 payout. Anything over S$800 needs a handler’s sign-off, and Aisha is at lunch. If the agent just waits in memory, one power cut or restart and it forgets the whole claim. Worse, if it starts again and pays twice, Mr Goh will find out. So Mei Ling makes the agent a worker that saves its place: it can stop for hours, survive a crash, and carry on from the exact spot.

Mei Ling 的理赔智能体判定了一笔 S$1,200 的赔付。超过 S$800 的赔付要理赔员签字，而 Aisha 正在吃午饭。如果智能体只是在内存里干等，一次断电或重启，它就把整份理赔忘光了。更糟的是，要是它重头再来、付了两次钱，Goh 先生一定会发现。所以 Mei Ling 把智能体做成一个会存档的工人：它可以停几个小时，扛得住崩溃，还能从原地接着干。

Words in this lesson这一课用到的词Checkpoint: a saved copy of the run's state after each step, so it can continue after a stop or crash.
Interrupt: a deliberate stop in the graph that waits for a person's answer.
Idempotency key: a label on a payment; a repeat with the same label is ignored, so nobody is paid twice.检查点：每一步之后保存的运行状态，停下或崩溃后可以接着跑。
中断：流程里故意设的停点，等人给出答案。
幂等键：付款上的标签；同一标签的重复请求会被忽略，所以不会付两次。

Step 1 · Turn the agent into steps and edges第 1 步 · 把智能体拆成步骤和连线

Learn先学

You can only save progress if progress has a shape. So draw the agent as a graph: each node is one step (decide, pay) and each edge is an arrow saying what comes next. The state is the notebook that travels along the arrows. Like the queue-number ticket machine: every claim has a number and always sits at one known place in the line. This uses LangGraph; install it with pip install langgraph langgraph-checkpoint-postgres "psycopg[binary]".

进度要有“形状”才存得下来。所以把智能体画成一张图：每个节点是一个步骤（判定、付款），每条边是一个箭头，说明下一步去哪。状态就是沿着箭头传递的笔记本。就像取号机：每份理赔有一个号码，永远排在已知的某个位置。这里用的是 LangGraph，用 pip install langgraph langgraph-checkpoint-postgres "psycopg[binary]" 安装。

from typing import TypedDict from langgraph.graph import StateGraph, START, END SIGNOFF_LIMIT = 800 # Stand-ins so this runs on its own. Swap in the real agent and payment call later. def decide_claim(claim): return {"action": "approve", "payout": claim["amount"]} def send_payment(claim_id, amount): print("paying", claim_id, amount) class ClaimState(TypedDict, total=False): claim: dict decision: dict paid: bool def decide(state): return {"decision": decide_claim(state["claim"])} def pay(state): if state["decision"]["action"] != "approve": return {"paid": False} send_payment(state["claim"]["id"], state["decision"]["payout"]) return {"paid": True} builder = StateGraph(ClaimState) builder.add_node("decide", decide) builder.add_node("pay", pay) builder.add_edge(START, "decide") builder.add_edge("decide", "pay") builder.add_edge("pay", END)

Step 2 · Add a checkpointer第 2 步 · 加一个存档器

Learn先学

A checkpointer saves the state after every step, like the grey filing cabinet that keeps each claim’s folder. Point it at a hosted database, because a file on your laptop disappears with your laptop. Each claim gets a thread id, its folder label. Use the same label later and the agent finds the same folder. Set DATABASE_URL to your database’s address first.

存档器会在每一步之后保存状态，就像灰色档案柜给每份理赔留一个文件夹。让它指向一个托管的数据库，因为放在笔记本电脑上的文件会随电脑一起消失。每份理赔有一个线程 id，就是文件夹上的标签。以后用同一个标签，智能体就能找到同一个文件夹。先把 DATABASE_URL 设成你的数据库地址。

import os from langgraph.checkpoint.postgres import PostgresSaver claim = {"id": "C-1042", "amount": 600} with PostgresSaver.from_conn_string(os.environ["DATABASE_URL"]) as checkpointer: checkpointer.setup() # creates its tables the first time graph = builder.compile(checkpointer=checkpointer) config = {"configurable": {"thread_id": claim["id"]}} result = graph.invoke({"claim": claim}, config) print(result["paid"])

Step 3 · Stop and wait for a person第 3 步 · 停下来等人

Learn先学

Now the agent can stop. Add a node that calls interrupt(): the graph saves everything it worked out, hands a question to whoever is watching, and ends the run. Nothing waits in memory; the process can even exit. A conditional edge sends only payouts over the limit down this path. Like a clerk who clips a note to the folder, “needs the stamp”, and moves on to the next customer. Compile the builder again inside Step 2’s with block, so graph still has its checkpointer.

现在智能体可以停下来了。加一个调用 interrupt() 的节点：图会把已经算出来的一切存好，把问题交给在看的人，然后结束这次运行。没有任何东西在内存里干等，进程甚至可以退出。再用一条条件边，只让超过限额的赔付走这条路。就像柜员在文件夹上夹一张“需要盖章”的便条，然后去招呼下一位客人。再在第 2 步的 with 块里把 builder 重新编译一次，让 graph 仍然带着存档器。

from langgraph.types import interrupt, Command class ClaimState(TypedDict, total=False): claim: dict decision: dict signed_off: bool paid: bool def approve(state): d = state["decision"] answer = interrupt({"claim": state["claim"]["id"], "payout": d["payout"]}) return {"signed_off": answer["ok"]} # runs only after a person answers def after_decide(state): d = state["decision"] big = d["action"] == "approve" and float(d["payout"]) > SIGNOFF_LIMIT return "approve" if big else "pay" def after_approve(state): return "pay" if state["signed_off"] else END builder = StateGraph(ClaimState) builder.add_node("decide", decide) builder.add_node("approve", approve) builder.add_node("pay", pay) builder.add_edge(START, "decide") builder.add_conditional_edges("decide", after_decide, ["approve", "pay"]) builder.add_conditional_edges("approve", after_approve, ["pay", END]) builder.add_edge("pay", END) # graph = builder.compile(checkpointer=checkpointer) # compile again inside Step 2's with block # claim = {"id": "C-1200", "amount": 1200} -> the run now stops at "approve". # result = graph.invoke({"claim": claim}, config) # result["__interrupt__"][0].value -> {"claim": "C-1200", "payout": 1200}

Step 4 · A handler signs off, the agent carries on第 4 步 · 理赔员签字，智能体接着干

Learn先学

When Aisha clicks “sign off” in the dashboard, your code calls the graph again with the same thread id and a Command(resume=...). Her answer becomes the return value of interrupt(). One catch: when it resumes, the approve node starts again from its first line. So anything above interrupt() must be safe to run twice. Keep that part to plain reading, with no payments and no emails.

Aisha 在看板上点“签字”时，你的代码用同一个线程 id 和 Command(resume=...) 再次调用这张图。她的回答就成了 interrupt() 的返回值。有一个陷阱：恢复时，approve 节点是从第一行重新开始跑的。所以 interrupt() 上面的代码必须能安全地跑两遍，只放读取，不放付款，也不放发邮件。

# later, maybe hours after the stop, maybe from another process config = {"configurable": {"thread_id": "C-1200"}} result = graph.invoke(Command(resume={"ok": True}), config) print(result["paid"]) # True: it paid, after the sign-off # a "no" instead: Command(resume={"ok": False}) ends the run with nothing paid

Step 5 · Kill it halfway, then restart第 5 步 · 半路杀掉进程，再重启

Learn先学

Because every finished step is saved, a crash costs you at most the step that was running. After a restart, ask the graph where that claim stands, then call invoke(None, config). Passing None means “no new input, carry on”. It is the same claim and the same attempt, not a new one. Steps that already finished are not run again, so you do not pay the model for them twice.

每个完成的步骤都存过档，所以崩溃最多让你损失当时正在跑的那一步。重启后，先问这张图那份理赔停在哪，再调用 invoke(None, config)。传 None 的意思是“没有新输入，接着干”。这是同一份理赔、同一次尝试，不是新的一次。已经完成的步骤不会重跑，所以不会为它们再付一次模型的钱。

# a new process after the crash: rebuild the graph and open the same database config = {"configurable": {"thread_id": "C-1200"}} snapshot = graph.get_state(config) print(snapshot.next) # e.g. ('pay',): the step still to run if snapshot.next: graph.invoke(None, config) # carry on from the last checkpoint

Step 6 · Make every step safe to repeat第 6 步 · 让每一步都能安全重复

Learn先学

Saving is the easy half. If the process dies after the payment went out but before the checkpoint was saved, the restart runs pay again. A step is idempotent when doing it twice gives the same result as doing it once. The fix is an idempotency key: a unique label sent with each payment, like a receipt number. The payment backend remembers the keys it has seen and ignores a repeat. It also checks the sign-off rule itself, so it never trusts the agent’s say-so alone.

存档是容易的那一半。如果进程在付款发出之后、存档之前挂了，重启就会把 pay 再跑一遍。做两次和做一次的结果一样，就叫幂等。解法是幂等键：每笔付款都带一个唯一标签，像收据编号。付款后端记住见过的键，遇到重复就忽略。它还自己检查签字规则，不会只听智能体一面之词。

paid_keys = {} # in real life: a table where the key column must be unique def send_payment(claim_id, amount, key, signed_off=False): if key in paid_keys: # a repeat after a restart: do nothing return paid_keys[key] if amount > SIGNOFF_LIMIT and not signed_off: raise ValueError("over the limit and not signed off") paid_keys[key] = {"claim": claim_id, "amount": amount} return paid_keys[key] def pay(state): if state["decision"]["action"] != "approve": return {"paid": False} claim_id = state["claim"]["id"] send_payment(claim_id, state["decision"]["payout"], key="pay-" + claim_id, # same claim, same key, every time signed_off=state.get("signed_off", False)) return {"paid": True}

Common errors常见错误

ValueError: Checkpointer requires one or more of the following 'configurable' keys: thread_id
Cause: invoke was called without a thread_id. Fix: always pass config with the claim id as thread_id.

ValueError: Checkpointer requires one or more of the following 'configurable' keys: thread_id
原因：调用 invoke 时没给 thread_id。解决：每次都传 config，用理赔编号做 thread_id。

psycopg.OperationalError: connection failed
Cause: DATABASE_URL is wrong or the database is not running. Fix: check the address, user and password, then test it with psql.

Recap小结

• Save the state after every step, keyed by claim id.
• Stop at the approval step and wait; resume with the person's answer, even from another process.
• Give each payment a key, so a retry never pays twice.

• 每一步之后保存状态，用理赔编号作键。
• 在批准那一步停下等待；用人的回答继续，即使换了进程。
• 每笔付款带一个键，重试时就不会付两次。

Takeaways要点回顾

• Draw the agent as steps and edges so its progress has a shape that can be saved.
• A checkpointer in a hosted database saves state after every step, under one thread id per claim.
• Pause by saving, not by waiting in memory: interrupt() stops the run and a later resume carries on.
• After a crash, continue from the last checkpoint; it is the same attempt, not a new one.
• A resumed step starts from its first line, so keep the code above interrupt() free of side effects.
• Make every step safe to repeat: each payment carries a unique key and the backend ignores repeats.
• The backend still enforces the sign-off rule; never rely on the agent alone.

• 把智能体画成步骤和连线，让进度有一个可以保存的形状。
• 托管数据库里的存档器在每一步之后保存状态，每份理赔一个线程 id。
• 用存档来暂停，而不是在内存里干等：interrupt() 停下这次运行，之后恢复就能接着干。
• 崩溃之后从最近的存档继续；这是同一次尝试，不是新的一次。
• 恢复的步骤从第一行重新开始，所以 interrupt() 之前的代码不能有副作用。
• 让每一步都能安全重复：每笔付款带唯一的键，后端忽略重复。
• 签字规则仍由后端把关，不能只靠智能体。
