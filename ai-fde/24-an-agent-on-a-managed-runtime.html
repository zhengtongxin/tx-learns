Agent on managed runtime托管运行时上的智能体

Run the same agent where someone else keeps the servers, and write its long jobs so they survive session limits · ~30 min · concept with one runnable idea让同一个智能体跑在别人维护服务器的地方，并把长任务写得能熬过会话的时限 · 约 30 分钟 · 概念课，带一段能跑的代码

Step 1 · An app with two doors第 1 步 · 有两扇门的应用

Learn先学
  • A managed runtime starts, stops and scales your agent so you run no server. It does not care what is inside; it needs two doors: /invocations takes work, /ping answers “are you alive?”. Many runtimes use these names on port 8080; check yours.
  • Test at home first with Flask's test client; the same code runs on the runtime, only the address changes.
  • After deploying, the first call is a cold start (the runtime starts a fresh copy) and is slow; later calls are warm and fast.
  • 托管运行时替你启动、停止并伸缩智能体，你不用跑服务器。它不在乎里面是什么，只需要两扇门：/invocations 接收工作，/ping 回答“你还活着吗？”。很多运行时用这两个名字、端口 8080；要核对你用的那个。
  • 先在家里用 Flask 的测试客户端测试；同一份代码在运行时上跑，只有地址不同。
  • 部署后，第一次调用是冷启动（运行时要启动一份新副本），比较慢；之后是热调用，很快。

Install with pip install flask requests. The agent stays a stand-in, so everything runs on its own.

用 pip install flask requests 安装。智能体仍用替身，所以一切都能独立运行。

Step 2 · Sessions end, so show long work is alive第 2 步 · 会话会结束，所以要亮出长任务还活着

Learn先学
  • Each run gets its own session: a separate little computer. Two claims never share variables.
  • A session ends after about a minute idle (no request in flight), even if your background thread is still running. Anything in its memory or disk goes with it; only what is stored outside survives.
  • So report long work: count running jobs and let /ping say “busy” while the count is above zero, and write each step down so a person sees progress. busy() adds one when work starts and removes it when it ends, even after a crash. The word for “busy” varies by runtime.
  • 每次运行有自己的会话：一台独立的小电脑。两份理赔永远不共用变量。
  • 会话在空闲（没有请求在处理）约一分钟后结束，哪怕你的后台线程还在跑。内存或磁盘里的东西随它消失；只有存在外面的才活得下来。
  • 所以要汇报长任务：数一数正在跑的任务，只要数字大于零，就让 /ping 回答“忙”，并把每一步记下来，让人看得到进度。busy() 在工作开始时加一，结束时减一，即使崩溃也会减回去。“忙”这个词各家不同。
# agent_app.py, added (import threading, time and from contextlib import contextmanager at the top) BUSY, LOCK, JOBS = 0, threading.Lock(), {} @contextmanager def busy(): global BUSY with LOCK: BUSY += 1 try: yield finally: with LOCK: BUSY -= 1 def long_job(claim_id): with busy(): for step in ("read the file", "decide", "write the record"): JOBS[claim_id] = {"step": step, "at": time.time()} # progress anyone can read time.sleep(20) # stands in for slow model and tool calls JOBS[claim_id] = {"step": "done", "at": time.time()} @app.post("/jobs/<claim_id>") def start_job(claim_id): threading.Thread(target=long_job, args=(claim_id,), daemon=True).start() return jsonify(started=claim_id), 202 # and ping becomes: @app.get("/ping") def ping(): return jsonify(status="HealthyBusy" if BUSY else "Healthy")

Step 3 · Pause in one session, resume in another第 3 步 · 在一个会话里暂停，在另一个会话里继续

Learn先学
  • A payout over S$800 waits for a handler, maybe hours; the session that started it will be gone. Park the waiting claim outside the session, in a database, under its claim id. Any new session that gets the answer takes it out and carries on.
  • This is a local SQLite file so it runs at home; on the runtime use a hosted database.
  • A handler can also send back with a note (“receipt shows a smaller bag”): the agent decides again in a new session with the note as extra input. A plain sign-off carries no reason.
  • 超过 S$800 的赔付要等理赔员，可能几个小时；发起它的会话到时已不在。把等待中的理赔放在会话外面，放进数据库，用理赔编号做标签。任何收到答复的新会话都把它取出来接着干。
  • 这里用本地 SQLite 文件，方便在家里运行；在运行时上要换成托管数据库。
  • 理赔员也可以附上一句话退回（“收据显示箱子更小”）：智能体在新会话里把这句话当额外输入重新判定。单纯签字不带理由。
# agent_app.py, added (import json, os and sqlite3 at the top) SIGNOFF_LIMIT = 800 db = sqlite3.connect(os.environ.get("STATE_DB", "state.db"), check_same_thread=False) db.execute("CREATE TABLE IF NOT EXISTS parked (claim_id TEXT PRIMARY KEY, claim TEXT, decision TEXT)") def park(claim, decision): db.execute("INSERT OR REPLACE INTO parked VALUES (?, ?, ?)", (claim["id"], json.dumps(claim), json.dumps(decision))) db.commit() def take(claim_id): row = db.execute("SELECT claim, decision FROM parked WHERE claim_id = ?", (claim_id,)).fetchone() if row is None: return None db.execute("DELETE FROM parked WHERE claim_id = ?", (claim_id,)) db.commit() return json.loads(row[0]), json.loads(row[1]) def decide_claim(claim, note=""): payout = float(claim["amount"]) if note: # stand-in: a real agent reads the note in its prompt payout = min(payout, SIGNOFF_LIMIT) return {"action": "approve", "payout": payout} def settle(claim, decision): if decision["payout"] > SIGNOFF_LIMIT: park(claim, decision) return jsonify(waiting=True, payout=decision["payout"]) return jsonify(paid=decision["payout"]) # stand-in for the real payment call # in invocations(): a resume carries no new claim, so handle it right after "body = ...", before the 400 check resume = body.get("resume") # e.g. {"claim_id": "C-2002", "ok": True} or {..., "send_back": "note"} if resume: found = take(resume.get("claim_id")) if found is None: return jsonify(error="nothing is waiting for that claim"), 404 claim, decision = found if resume.get("send_back"): return settle(claim, decide_claim(claim, note=resume["send_back"])) return jsonify(paid=decision["payout"] if resume.get("ok") else False) # and the last line of invocations() becomes: return settle(claim, decide_claim(claim))

Common errors常见错误

requests.exceptions.ReadTimeout: Read timed out. (read timeout=60)
Cause: a cold start plus a slow model. Fix: call again; the second call is faster.

requests.exceptions.ReadTimeout: Read timed out. (read timeout=60)
原因：冷启动加上模型较慢。解决：再调用一次，第二次会快些。

400 Bad Request: {"error":"send a claim"}
Fix: send {"claim": {...}} with an id and an amount.

Takeaways要点回顾

• The same agent runs on a laptop or a runtime; it needs one door for work and one for a health ping.
• Expect a slow cold start and fast warm calls.
• Each run gets its own session; nothing in its memory or disk outlives it.
• Keep long work visibly alive: a busy ping and a progress step at each stage.
• Park waiting work in a database under its claim id; sending back with a note matters as much as signing off.

• 同一个智能体在笔记本或运行时上都能跑；它需要一扇接收工作的门，一扇健康探测的门。
• 冷启动慢，热调用快。
• 每次运行有自己的会话；它内存和磁盘里的东西活不过会话。
• 让长任务清清楚楚地活着：忙碌的 ping，加上每个阶段的进度记录。
• 把等待中的工作按理赔编号放进数据库；带着理由退回，和签字批准一样重要。
