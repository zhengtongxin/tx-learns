Claims desk pilot理赔台试点

Build the smallest thing the customer can react to: sample claims, a queue with a hard sign-off rule, and an agent that decides · ~25 min · hands-on做出客户能有反应的最小东西：样本理赔、带硬性签字规则的队列，以及会做决定的智能体 · 约 25 分钟 · 动手实践

Step 1 · Invent the claims, hide the answer key第 1 步 · 编出理赔，藏好答案

Learn先学
  • You cannot test on real customers, so invent 25 claims, their policies and a plain policy wording.
  • Write down what handlers decided for each. That is the answer key, and it lives in a folder the agent never reads.
  • 不能拿真实客户来测试，所以自己编 25 份理赔、对应的保单和一份朴素的条款。
  • 把理赔员对每份的决定写下来，这就是答案，放在智能体永远读不到的文件夹里。
pilot/ data/ # the agent may read this claims.json # 25 invented claims policies.json # policy id -> cover and limits policy_wording.txt # the plain wording of the cover answer_key/ # the agent must NEVER read this handler_decisions.json # what the handlers decided # one claim in claims.json {"id": "C007", "policy_id": "P003", "customer": "Mr Tan", "story": "My flight was cancelled and I paid for a hotel.", "amount": 420}

Step 2 · A queue with a hard rule第 2 步 · 带硬性规则的队列

Learn先学
  • Every claim is in exactly one state: waiting, in_progress, waiting_signoff or decided.
  • Any payout over the sign-off limit (S$800 here), and any referral, must wait for a handler.
  • Put that rule in the code, not the prompt: a prompt is a request the model may ignore, code is a locked door.
  • 每份理赔只处于一个状态：waiting、in_progress、waiting_signoff 或 decided。
  • 任何超过签字上限（这里是 S$800）的赔付，以及任何转交，都必须等理赔员。
  • 把规则放进代码而不是提示词：提示词只是请求，模型可能不听；代码是一扇锁住的门。
# backend.py queue = {} # claim id -> its record SIGNOFF_LIMIT = 800 def add_claim(claim): queue[claim["id"]] = {"claim": claim, "state": "waiting", "decision": None} def start(claim_id): queue[claim_id]["state"] = "in_progress" def record_decision(claim_id, decision): item = queue[claim_id] item["decision"] = decision too_big = decision["action"] == "approve" and decision["payout"] > SIGNOFF_LIMIT needs_human = too_big or decision["action"] == "refer" item["state"] = "waiting_signoff" if needs_human else "decided" def sign_off(claim_id, handler): queue[claim_id]["state"] = "decided" queue[claim_id]["signed_by"] = handler

Step 3 · The agent, then run the queue第 3 步 · 智能体，然后跑整条队列

Learn先学
  • The agent gets one claim, with its policy and the wording pasted into the prompt, and returns JSON: action, payout, reason.
  • It never touches the queue; record_decision decides what happens next. It is one model call with no tools.
  • Setup: pip install openai and set OPENAI_API_KEY in your terminal.
  • 智能体拿到一份理赔，保单和条款已贴在提示词里，返回 JSON：action、payout、reason。
  • 它不碰队列，接下来怎么处理由 record_decision 决定。它就是一次不带工具的模型调用。
  • 准备：pip install openai，并在终端里设置 OPENAI_API_KEY。
# agent.py import json from openai import OpenAI client = OpenAI() POLICIES = json.load(open("data/policies.json")) WORDING = open("data/policy_wording.txt").read() def decide(claim): policy = POLICIES[claim["policy_id"]] prompt = f"""You help a travel insurer's claims desk. Policy wording: {WORDING} This customer's policy: {json.dumps(policy)} The claim: {json.dumps(claim)} Reply with JSON only: {{"action": "approve" or "decline" or "refer", "payout": a number in S$, "reason": two or three short sentences}}""" reply = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": prompt}], response_format={"type": "json_object"}) return json.loads(reply.choices[0].message.content)
# run_pilot.py import json from backend import queue, add_claim, start, record_decision from agent import decide for claim in json.load(open("data/claims.json")): add_claim(claim) for claim_id in list(queue): start(claim_id) record_decision(claim_id, decide(queue[claim_id]["claim"])) print(claim_id, queue[claim_id]["state"], queue[claim_id]["decision"]["action"]) # Scoring: the ONLY code that opens the answer key ({claim id: action}) key = json.load(open("answer_key/handler_decisions.json")) agree = sum(1 for cid, item in queue.items() if item["decision"]["action"] == key[cid]) print(f"agrees with handlers on {agree} of {len(key)} claims")

Takeaways要点回顾

• Build the smallest thing the customer can react to.
• Invent your own sample claims, and keep the answer key where the agent cannot read it.
• Enforce the sign-off rule in the backend, not in the prompt.
• The agent only returns an answer; the backend decides what happens to it.
• Where the pilot fails is the plan for what comes next.

• 做出客户能有反应的最小东西。
• 样本理赔自己编，答案放在智能体读不到的地方。
• 签字规则放在后端执行，而不是写在提示词里。
• 智能体只返回答案，怎么处理由后端决定。
• 试点出错的地方，就是接下来要做的事。
