Two ways to build a harness搭 harness 的两种路线

上回 Mei Ling 在纸上规划了 harness。今天她得建一个 Kumar 能维持运转的，而常见的路有两条。我们的办法是在同样的理赔上用两种方式各建一遍同一个智能体，再来比较。

The story故事

Mei Ling knows what a harness is. Now she has to build one for the Kaya Travel Cover claims desk, and there are two popular roads. One is an agent SDK: a ready-made kit where the tools for files, planning and sub-agents are already built in. The other is an open framework: you pick the model and write the tools yourself. Kumar, the one-person IT team, will have to keep whichever she chooses alive. So she builds the same agent both ways and compares.

Mei Ling 知道了什么是 harness。现在她要为 Kaya Travel Cover 的理赔台搭一个，而眼前有两条常见的路。一条是智能体 SDK：现成的工具包，文件、规划、子智能体的工具都已内置。另一条是开放框架：模型自己选，工具自己写。一人 IT 团队 Kumar 得把她选的那个一直维护下去。所以她把同一个智能体两种方式各搭一遍，再来比较。

Step 1 · The same desk, the same task第 1 步 · 同一个理赔台，同一项任务

Learn先学

A fair comparison changes one thing at a time. So both builds get the same queue, the same manual and the same instruction. Only the harness differs. Keep the task in one small file that both builds import. Both builds also use the same parts: a tool is a function the model can ask your code to run, and a helper is a smaller agent started for one job.

公平的比较一次只改一样东西。所以两种搭法拿到同样的队列、同样的手册、同样的指令，只有 harness 不同。把任务写在一个小文件里，让两边都引用它。两种搭法用的是同样的部件：工具是模型可以请你的代码去运行的函数，帮手是为一项工作临时启动的小智能体。

# shared.py: used by both builds # queue.json: the claims. manual/: one text file per manual section. TASK = """Work the claims queue in queue.json. Give each claim to a helper that reads only the manual sections it needs. Each helper reports one line: action (approve, decline or refer), payout in S$, reason. Keep a to-do list as you go. Save every decision in decisions.json."""

Which parts stay the same in both builds, and which can change?

下面哪些在两种搭法里保持一样，哪些可以变？

Step 2 · Way one: an agent SDK第 2 步 · 路线一：智能体 SDK

Learn先学

With an SDK, the harness mostly comes in the box. Reading files, searching, a to-do tool and a way to start a helper are all built in. In the list, Read, Glob and Grep read and search files, TodoWrite keeps the to-do list and Task starts a helper. You only switch on the tools you want and describe your helper. It is like renting a fitted desk: the drawers are already there. Install with pip install claude-agent-sdk and set your ANTHROPIC_API_KEY. Here the manual is just files, so the built-in file tools can already read it.

用 SDK 的话，harness 大部分是现成的。读文件、搜索、待办工具、启动帮手，全都内置。下面清单里，Read、Glob、Grep 负责读取和搜索文件，TodoWrite 管待办清单，Task 负责启动帮手。你只需打开想要的工具，再描述你的帮手。就像租了一张配好抽屉的办公桌。用 pip install claude-agent-sdk 安装，并设置好 ANTHROPIC_API_KEY。这里手册就是一堆文件，所以内置的文件工具已经能读。

import asyncio from claude_agent_sdk import query, ClaudeAgentOptions, AgentDefinition, ResultMessage from shared import TASK options = ClaudeAgentOptions( allowed_tools=["Read", "Glob", "Grep", "Write", "TodoWrite", "Task"], permission_mode="acceptEdits", agents={"claim-helper": AgentDefinition( description="Decides one claim and reports one line back.", prompt="You get one claim id. Read that claim and only the manual files you need. Reply with one line.", tools=["Read", "Glob", "Grep"])}, max_turns=60) async def main(): async for message in query(prompt=TASK, options=options): if isinstance(message, ResultMessage): print(message.result) print("cost in US$:", message.total_cost_usd) asyncio.run(main())

Expected output (an example: your numbers and wording will differ)

预期输出 （示例：你的数字和措辞会不同）

Worked 25 claims: 21 done, 4 for a handler. See todo.md. cost in US$: 0.64

Step 3 · Way two: an open framework第 3 步 · 路线二：开放框架

Learn先学

An open framework gives you a similar agent with planning and helpers, but you choose the model and write your own tools. You can also add middleware: code that sits around the agent’s steps, for example to log them or to catch errors. The model learns what a tool does from its name and its docstring (the text in triple quotes), so write both clearly. More to write, more to control. This one needs pip install deepagents and a key for whichever model you pick.

开放框架同样给你一个带规划和帮手的智能体，但模型你自己选，工具你自己写。你还可以加中间件：围在智能体每一步外面的代码，比如记录日志或接住错误。模型靠工具的名字和它的文档字符串（三引号里的那段文字）来了解工具是做什么的，所以两者都要写清楚。要写得更多，掌控也更多。这个需要 pip install deepagents，以及你所选模型的密钥。

import json from deepagents import create_deep_agent from shared import TASK def read_manual_section(title: str) -> str: """Return one manual section by its title.""" if "/" in title: return "No such section." try: return open(f"manual/{title}.md").read() except FileNotFoundError: return "No such section." def save_decision(claim_id: str, action: str, payout: float, reason: str) -> str: """Save one decision to decisions.json.""" try: saved = json.load(open("decisions.json")) except FileNotFoundError: saved = {} saved[claim_id] = {"action": action, "payout": payout, "reason": reason} json.dump(saved, open("decisions.json", "w"), indent=1) return "saved" agent = create_deep_agent( model="openai:gpt-5.4-mini", tools=[read_manual_section, save_decision], system_prompt="You work the claims queue for a travel insurer.", subagents=[{"name": "claim-helper", "description": "Decides one claim and reports one line back.", "system_prompt": "Read your claim and only the manual sections you need. Reply with one line.", "tools": [read_manual_section]}]) result = agent.invoke({"messages": [{"role": "user", "content": TASK}]}) print(result["messages"][-1].content)

Expected output (an example: your numbers and wording will differ)

预期输出 （示例：你的数字和措辞会不同）

Worked 25 claims: 20 done, 5 for a handler. todo.md saved.

Step 4 · Look at how each did, and compare第 4 步 · 看看各自表现，然后比较

Learn先学

Run both on the same five claims, then compare on four things: setup effort, control over the model, cost and visibility (how easily you can see what the agent did). Mei Ling found the SDK got going fastest and felt very capable on a strong model. The framework took more writing, but let her swap models and watch cost. Neither always wins.

两种都用同样的五份理赔跑一遍，然后从四件事比较：搭建功夫、对模型的掌控、成本和可见度（看清智能体做了什么有多容易）。Mei Ling 发现 SDK 上手最快，配强模型时表现很能干；框架要写得更多，但能换模型、盯成本。没有哪个永远赢。

way one (SDK) way two (framework) setup effort low: kit is built in higher: write tools control over model little you choose it cost cost printed at end depends on your model visibility to-do list + messages the messages and a step-by-step log

Which way is stronger for each point?

下面每一点，哪条路更占优势？

Step 5 · Practise for free, then choose第 5 步 · 免费练习，然后做选择

Learn先学

You do not have to spend money to practise. With the framework, point it at a local model running on your own machine (Ollama is a free program that runs models there). With the SDK, cap the run at five claims and use a small model, or check whether your tool can talk to a local server that answers in the same format. A free local model must support calling tools (asking your code to run a function), or the agent cannot act. Then choose by who will live with it, not by who won the demo.

练习不一定要花钱。用框架的话，让它指向你自己机器上跑的本地模型（Ollama 是一个免费程序，能在你的电脑上跑模型）。用 SDK 的话，把运行限制在五份理赔、换用小模型，或者看看你的工具能不能连到用同样格式应答的本地服务器。免费的本地模型必须支持调用工具（即请你的代码运行某个函数），否则智能体没法行动。然后，按谁要长期维护来选，而不是按谁在演示里赢了来选。

ollama pull qwen3:8b pip install langchain-ollama
from langchain_ollama import ChatOllama local_model = ChatOllama(model="qwen3:8b") # then pass model=local_model to create_deep_agent(...) in Step 3
What I got wrong我当时想错了I treated the two as rival teams and thought I had to pick a side before I started. They share the same ideas: tools, a plan, helpers. Once I had built the first, the second took a fraction of the time, because I already knew what to put where.我把这两个当成对立的两队，以为开始之前得先站队。其实它们共用同样的想法：工具、计划、帮手。做完第一个之后，第二个只花了一小部分时间，因为我已经知道什么该放在哪。

Now make it yours现在把它变成你的

The next problem is growing the chosen build into a full working run on the real queue.现在试点有了用两种方式建好的 harness，也有一份 Kumar 看得懂的比较：搭建的力气、对模型的掌控、成本，以及下雨的星期五好不好修。下一个问题是把选中的那种扩成一次能处理整个真实队列的完整运行。

Common errors常见错误

claude_agent_sdk._errors.CLINotFoundError: Claude Code not found
Cause: the SDK drives the Claude Code program, and it is not installed. Fix: install Claude Code first, then run again.

claude_agent_sdk._errors.CLINotFoundError: Claude Code not found
原因：SDK 靠 Claude Code 程序运行，而它没装。解决：先安装 Claude Code，再运行。

ModuleNotFoundError: No module named 'deepagents'
Cause: the framework is not installed. Fix: pip install deepagents.

ModuleNotFoundError: No module named 'deepagents'
原因：没有安装这个框架。解决：pip install deepagents。

ConnectionRefusedError: [Errno 111] Connection refused (local model)
Cause: Ollama is not running. Fix: start it, then check ollama list shows qwen3:8b.

Takeaways要点回顾

• You can build a harness with a ready-made SDK or an open framework.
• The SDK gets going fastest because tools, planning and helpers are built in.
• The framework gives you control of the model and cost, but you write more.
• Compare on four things: setup, control, cost and visibility.
• Compare fairly: same queue, same manual, same task.
• Learn the harness ideas, not one framework; they carry over.
• Choose the one the customer’s team can maintain.

• 搭 harness 可以用现成 SDK，也可以用开放框架。
• SDK 上手最快，因为工具、规划和帮手都内置。
• 框架让你掌控模型和成本，但要写得更多。
• 从四件事比较：搭建、掌控、成本、可见度。
• 公平地比：同样的队列、同样的手册、同样的任务。
• 学 harness 的思路，而不是某一个框架，思路是通用的。
• 选客户团队能维护的那一个。
