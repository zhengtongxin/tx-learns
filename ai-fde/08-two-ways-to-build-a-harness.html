Two ways to build a harness搭 harness 的两种路线

Build the same agent with a ready-made SDK and with an open framework, and learn how to choose · ~20 min · concept with code用现成的 SDK 和开放框架各搭一次同一个智能体，学会怎么选 · 约 20 分钟 · 概念加代码

Step 1 · Way one: an agent SDK第 1 步 · 路线一：智能体 SDK

Learn先学
  • An agent SDK is a ready-made kit: file tools, a to-do tool and sub-agents come built in. You switch on the tools you want and describe your helper.
  • Both builds get the same task, so any difference comes from the harness. A helper is a smaller agent started for one job.
  • Setup: pip install claude-agent-sdk and set ANTHROPIC_API_KEY. The manual is just files, so the built-in file tools can read it.
  • 智能体 SDK是现成的工具包：文件工具、待办工具、子智能体都已内置。你只需打开想要的工具，再描述你的帮手。
  • 两种搭法拿到同样的任务，所以差别都来自 harness。帮手是为一项工作临时启动的小智能体。
  • 准备：pip install claude-agent-sdk，并设置 ANTHROPIC_API_KEY。手册就是一堆文件，内置的文件工具已经能读。
# shared.py: used by both builds # queue.json: the claims. manual/: one text file per manual section. TASK = """Work the claims queue in queue.json. Give each claim to a helper that reads only the manual sections it needs. Each helper reports one line: action (approve, decline or refer), payout in S$, reason. Keep a to-do list as you go. Save every decision in decisions.json."""
import asyncio from claude_agent_sdk import query, ClaudeAgentOptions, AgentDefinition, ResultMessage from shared import TASK options = ClaudeAgentOptions( allowed_tools=["Read", "Glob", "Grep", "Write", "TodoWrite", "Task"], permission_mode="acceptEdits", agents={"claim-helper": AgentDefinition( description="Decides one claim and reports one line back.", prompt="You get one claim id. Read that claim and only the manual files you need. Reply with one line.", tools=["Read", "Glob", "Grep"])}, max_turns=60) async def main(): async for message in query(prompt=TASK, options=options): if isinstance(message, ResultMessage): print(message.result) print("cost in US$:", message.total_cost_usd) asyncio.run(main())

Step 2 · Way two: an open framework第 2 步 · 路线二：开放框架

Learn先学
  • An open framework gives you a similar agent with planning and helpers, but you choose the model and write the tools.
  • The model learns what a tool does from its name and docstring, so write both clearly.
  • Setup: pip install deepagents and a key for the model you pick. To practise for free, point it at a local model (Ollama) that supports tool calling.
  • 开放框架同样给你一个带规划和帮手的智能体，但模型你自己选，工具你自己写。
  • 模型靠工具的名字和文档字符串来了解工具是做什么的，所以两者都要写清楚。
  • 准备：pip install deepagents，以及你所选模型的密钥。想免费练习，可以指向支持工具调用的本地模型（Ollama）。
import json from deepagents import create_deep_agent from shared import TASK def read_manual_section(title: str) -> str: """Return one manual section by its title.""" if "/" in title: return "No such section." try: return open(f"manual/{title}.md").read() except FileNotFoundError: return "No such section." def save_decision(claim_id: str, action: str, payout: float, reason: str) -> str: """Save one decision to decisions.json.""" try: saved = json.load(open("decisions.json")) except FileNotFoundError: saved = {} saved[claim_id] = {"action": action, "payout": payout, "reason": reason} json.dump(saved, open("decisions.json", "w"), indent=1) return "saved" agent = create_deep_agent( model="openai:gpt-5.4-mini", tools=[read_manual_section, save_decision], system_prompt="You work the claims queue for a travel insurer.", subagents=[{"name": "claim-helper", "description": "Decides one claim and reports one line back.", "system_prompt": "Read your claim and only the manual sections you need. Reply with one line.", "tools": [read_manual_section]}]) result = agent.invoke({"messages": [{"role": "user", "content": TASK}]}) print(result["messages"][-1].content)

Step 3 · Compare, then choose第 3 步 · 比较，然后选择

Learn先学
  • Run both on the same five claims and compare four things: setup effort, control over the model, cost and visibility (how easily you see what the agent did).
  • The SDK gets going fastest. The framework takes more writing but lets you swap models and watch cost. Neither always wins.
  • Choose by who will live with it, not by who won the demo.
  • 两种都用同样的五份理赔跑一遍，比较四件事：搭建功夫、对模型的掌控、成本和可见度（看清智能体做了什么有多容易）。
  • SDK 上手最快；框架要写得更多，但能换模型、盯成本。没有哪个永远赢。
  • 按谁要长期维护来选，而不是按谁在演示里赢了来选。

Takeaways要点回顾

• You can build a harness with a ready-made SDK or an open framework.
• The SDK gets going fastest; the framework gives control of the model and cost.
• Compare on setup, control, cost and visibility, with the same queue, manual and task.
• Learn the harness ideas, not one framework; they carry over.
• Choose the one the customer’s team can maintain.

• 搭 harness 可以用现成 SDK，也可以用开放框架。
• SDK 上手最快；框架让你掌控模型和成本。
• 用同样的队列、手册和任务，从搭建、掌控、成本、可见度来比较。
• 学 harness 的思路，而不是某一个框架，思路是通用的。
• 选客户团队能维护的那一个。
