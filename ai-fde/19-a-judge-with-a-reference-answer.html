Judge with a reference带参考答案的评委

Grade the agent’s explanations automatically, and know how far to trust the grades · ~25 min · concept with one runnable idea自动给智能体的解释打分，并知道这些分数能信到什么程度 · 约 25 分钟 · 概念课，带一段能跑的代码

Step 1 · Judge against a reference answer第 1 步 · 对照参考答案来评判

Learn先学
  • Grading “is this a good explanation?” by feel wobbles. Grading “does it match what an expert wrote?” is steadier. The expert text is the reference answer.
  • A judge is a second model (a different one from the agent) that returns a grade A to F, a score 0 to 3, and two yes/no checks: same grounds, same section of the wording. The checks make a grade explainable.
  • If letter and number disagree, the letter wins: it came from the rubric.
  • 凭感觉给“这是不是好解释”打分会晃。给“它和专家写的是否一致”打分更稳。专家写的文字就是参考答案。
  • 评委是第二个模型（和智能体用不同的模型），返回 A 到 F 的等级、0 到 3 的分数，以及两项是非检查：理由是否一致，引用的是否同一节条款。有了检查，等级才说得清楚。
  • 字母和数字对不上时，以字母为准：它是按评分标准给的。

This uses bench.py from the scoreboard lesson (gateway, key, held_claims, small_prompt, ask); each key entry also needs the handler's reason.

这里用到计分板那课的 bench.py（gateway、key、held_claims、small_prompt、ask）；key 的每一项还要有理赔员的 reason（理由）。

# judge.py import json from bench import gateway, key, held_claims, small_prompt, ask AGENT = "anthropic/claude-haiku-5-5" JUDGE = "anthropic/claude-sonnet-5-5" # a different model from the agent def collect(): pairs = [] for claim in held_claims: decision, tin, tout, secs = ask(gateway, AGENT, small_prompt(claim)) pairs.append({"id": claim["id"], "agent_reason": decision["reason"], "handler_reason": key[claim["id"]]["reason"]}) return pairs pairs = collect() GRADE_SCORE = {"A": 3, "B": 2, "C": 1, "F": 0} def judge_prompt(pair): return f"""You grade how well a claims agent explained a decision. The handler's reason is the reference answer. Compare the agent's explanation with it. Handler's reason: {pair["handler_reason"]} Agent's explanation: {pair["agent_reason"]} A = same grounds and the same section of the policy wording B = same grounds, but no section named, or a different one C = some overlap, but the main ground is different F = different grounds, or it contradicts the handler Reply with JSON only: {{"grade": "A" or "B" or "C" or "F", "same_grounds": true or false, "same_section": true or false}}""" def judge_all(pairs): verdicts = {} for p in pairs: verdict, tin, tout, secs = ask(gateway, JUDGE, judge_prompt(p)) verdict["score"] = GRADE_SCORE[verdict["grade"]] # the letter wins verdicts[p["id"]] = verdict return verdicts

评委的提示词里该放什么？来分一分。

Step 2 · Check the judge against a person第 2 步 · 拿人来检查评委

Learn先学
  • A judge can be wrong in its own ways. Grade ten explanations yourself first, without looking at its grades, and save them as {"C007": 2, ...} in answer_key/my_grades.json.
  • Measure how often you agree, exactly and within one point.
  • Look for a lean: does it score longer explanations higher than you do?
  • 评委有它自己的出错方式。先自己给十份解释打分，别看它的分数，按 {"C007": 2, ...} 的格式存进 answer_key/my_grades.json。
  • 算你们有多常一致：完全相同，以及相差不超过一分。
  • 找一找有没有偏向：它是不是比你更偏爱长的解释？
# judge.py, continued verdicts = judge_all(pairs) human = json.load(open("answer_key/my_grades.json")) # {claim id: 0 to 3}, graded by you first def agreement(verdicts): ids = [i for i in human if i in verdicts] exact = sum(verdicts[i]["score"] == human[i] for i in ids) near = sum(abs(verdicts[i]["score"] - human[i]) <= 1 for i in ids) return exact / len(ids), near / len(ids) def length_gap(verdicts, pairs): ranked = sorted(pairs, key=lambda p: len(p["agent_reason"])) ids = [p["id"] for p in ranked[len(ranked) // 2:] if p["id"] in human] # the longer half return sum(verdicts[i]["score"] - human[i] for i in ids) / len(ids) # above 0: kinder than you print(agreement(verdicts), length_gap(verdicts, pairs)) # if the gap is above 0, add to judge_prompt: "Length earns nothing. A short explanation with the right grounds can score A."

Step 3 · Measure the noise第 3 步 · 量一量噪声

Learn先学

Ask the same judge the same questions three times and the scores still move. That movement is the noise, like a bathroom scale showing 60.2 kg, then 60.5 kg. Only a change bigger than the noise is real.

让同一个评委把同样的题目问三遍，分数还是会晃动。这个晃动就是噪声，就像体重秤先显示 60.2 公斤，再显示 60.5 公斤。只有比噪声大的变化才是真的。

# judge.py, continued def mean_score(verdicts): return sum(v["score"] for v in verdicts.values()) / len(verdicts) runs = [judge_all(pairs) for _ in range(3)] # the same judge, the same pairs, three times means = [mean_score(v) for v in runs] noise = max(means) - min(means) print("means", means, "noise", noise) def real_change(before, after): return abs(after - before) > noise

Expected output

预期输出

means [3.6, 3.8, 3.7] noise 0.19999999999999996

Common errors常见错误

json.decoder.JSONDecodeError: Expecting value
Cause: the judge wrote a paragraph, not JSON. Fix: ask for JSON only, and count an unreadable verdict as missing.

json.decoder.JSONDecodeError: Expecting value
原因：评委写了一段话，不是 JSON。解决：只要 JSON；读不出来的评分算缺失。

KeyError: 'grade'
Cause: the verdict uses a different field name. Fix: put the exact field names in the prompt and check them in code.

KeyError: 'grade'
原因：评分里的字段名不一样。解决：在提示里写明字段名，并在代码里检查。

Takeaways要点回顾

• Give a judge a reference answer; it is far steadier than grading by feel.
• Ask for a grade plus checks, so every grade can be explained.
• Use a different model as the judge from the one being judged.
• Check the judge against a person first, and look for a lean such as favouring length.
• Only a change bigger than the noise counts.

• 给评委一份参考答案；它比凭感觉打分稳得多。
• 要等级，也要检查项，这样每个等级都说得清楚。
• 评委用的模型，要和被评的模型不同。
• 先拿人来检查评委，并找找有没有偏向，比如偏爱长文。
• 只有比噪声大的变化才算数。
