A judge with a reference answer带参考答案的评委

Grade the agent’s explanations automatically, and know how far to trust the grades · ~25 min · concept with one runnable idea自动给智能体的解释打分，并知道这些分数能信到什么程度 · 约 25 分钟 · 概念课，带一段能跑的代码

Where we left off上回讲到

Last time the pilot’s queue could be run from the dashboard and scored on whether its decisions match the handlers’. Today it fails when Mr Goh asks for the reasons: Aisha cannot read a hundred explanations a day. We fix it by asking a second model, a judge, to grade each one against the handler’s own reason.

上回，试点的队列能从看板上跑，也能按判定是否和理赔员一致来打分。今天的问题是 Goh 先生要看理由：Aisha 一天读不完一百份解释。我们的办法是请第二个模型当评委，对照理赔员自己的理由给每份打分。

The story故事

The scoreboard tells Mei Ling whether the agent’s decision matches the handlers’. But Mr Goh also reads the agent’s explanation, and he wants it to give the same grounds a handler would. Aisha cannot read a hundred explanations a day. So Mei Ling asks a second model to grade them. This lesson uses bench.py from the scoreboard lesson (gateway, key, held_claims, small_prompt, ask). It assumes each entry in key also holds the handler’s reason; add it if yours does not.

计分板告诉 Mei Ling，智能体的判定和理赔员的是否一致。但 Goh 先生还要看智能体的解释，他要它给出和理赔员一样的理由。Aisha 一天读不完一百份解释。于是 Mei Ling 请第二个模型来打分。这一课用到计分板那课的 bench.py（gateway、key、held_claims、small_prompt、ask）。它假设 key 里每一项还带着理赔员的 reason（理由）；你的没有就补上。

Words in this lesson这一课用到的词Judge: a second model that reads an answer and a reference answer and gives a score.
Noise: how much a score moves when you run the same thing again; a change smaller than this means nothing.
Agreement: how often the judge and a person give the same verdict.评委：第二个模型，读一份回答和参考答案，然后打分。
噪声：同样的东西再跑一次，分数会晃动多少；比这小的变化没有意义。
一致率：评委和人给出同样结论的比例。

Step 1 · Put the two reasons side by side第 1 步 · 把两个理由摆在一起

Learn先学

Grading “is this a good explanation?” by feel gives wobbly answers. Grading “does it match what an expert wrote?” is much steadier. The expert’s text is the reference answer, like a marking scheme a teacher holds while marking. So for every held-out claim (one kept back from tuning, as in the scoreboard lesson) we keep two texts: the agent’s explanation and the handler’s reason.

凭感觉给“这是不是好解释”打分，答案会晃来晃去。给“它和专家写的是否一致”打分，就稳得多。专家写的那段文字就是参考答案，像老师改卷时手边的评分标准。所以每份留出的理赔（就是计分板那课里不拿来调校的那些），我们留两段文字：智能体的解释，和理赔员的理由。

# judge.py import json from bench import gateway, key, held_claims, small_prompt, ask AGENT = "anthropic/claude-haiku-5-5" JUDGE = "anthropic/claude-sonnet-5-5" # a different model from the agent def collect(): pairs = [] for claim in held_claims: decision, tin, tout, secs = ask(gateway, AGENT, small_prompt(claim)) pairs.append({"id": claim["id"], "agent_reason": decision["reason"], "handler_reason": key[claim["id"]]["reason"], "agent_tokens": (tin, tout)}) return pairs pairs = collect()

Step 2 · Ask the judge for a grade and two checks第 2 步 · 让评委给一个等级和两项检查

Learn先学

The judge gets only what it needs. It returns a grade (A, B, C or F), a score from 0 to 3, and two yes/no checks: same grounds, and same section of the policy wording. The checks make a grade explainable. If a letter and a number ever disagree, the letter wins, because the letter came from the rubric.

评委只拿到它需要的东西。它返回一个等级（A、B、C 或 F）、一个 0 到 3 的分数，以及两项是非检查：理由是否一致，保单条款引用的是否同一节。有了检查，等级才说得清楚。如果字母和数字对不上，以字母为准，因为字母是按评分标准给的。

# judge.py, continued GRADE_SCORE = {"A": 3, "B": 2, "C": 1, "F": 0} def judge_prompt(pair): return f"""You grade how well a claims agent explained a decision. The handler's reason is the reference answer. Compare the agent's explanation with it. Handler's reason: {pair["handler_reason"]} Agent's explanation: {pair["agent_reason"]} A = same grounds and the same section of the policy wording B = same grounds, but no section named, or a different one C = some overlap, but the main ground is different F = different grounds, or it contradicts the handler Reply with JSON only: {{"grade": "A" or "B" or "C" or "F", "score": 3 or 2 or 1 or 0, "same_grounds": true or false, "same_section": true or false}}""" def judge_one(pair): verdict, tin, tout, secs = ask(gateway, JUDGE, judge_prompt(pair)) verdict["score"] = GRADE_SCORE[verdict["grade"]] # the letter wins return verdict, (tin, tout) def judge_all(pairs): verdicts, spent = {}, [0, 0] for p in pairs: verdict, (tin, tout) = judge_one(p) verdicts[p["id"]] = verdict spent[0] += tin spent[1] += tout return verdicts, spent

Step 3 · Check the judge against a person第 3 步 · 拿人来检查评委

Learn先学

A judge is just another model, so it can be wrong in its own ways. Grade ten of the explanations yourself first, without looking at its grades, and save them in answer_key/my_grades.json as {"C007": 2, ...}. Then measure how often you agree, exactly and within one point. Also look for a lean: does the judge give higher marks to longer explanations than you do?

评委也只是另一个模型，它有它自己的出错方式。先自己给其中十份解释打分，别看它的分数，存进 answer_key/my_grades.json，格式是 {"C007": 2, ...}。然后算你们有多常一致：完全相同，以及相差不超过一分。还要找一找有没有偏向：评委是不是比你更偏爱长的解释？

# judge.py, continued verdicts, spent = judge_all(pairs) human = json.load(open("answer_key/my_grades.json")) # {claim id: 0 to 3}, graded by you first def agreement(verdicts): ids = [i for i in human if i in verdicts] exact = sum(verdicts[i]["score"] == human[i] for i in ids) near = sum(abs(verdicts[i]["score"] - human[i]) <= 1 for i in ids) return exact / len(ids), near / len(ids) def length_gap(verdicts, pairs): ranked = sorted(pairs, key=lambda p: len(p["agent_reason"])) ids = [p["id"] for p in ranked[len(ranked) // 2:] if p["id"] in human] # the longer half return sum(verdicts[i]["score"] - human[i] for i in ids) / len(ids) # above 0: kinder than you print(agreement(verdicts), length_gap(verdicts, pairs)) # if the gap is above 0, add this line to judge_prompt and measure again: # "Length earns nothing. A short explanation with the right grounds can score A."

Step 4 · Measure the noise第 4 步 · 量一量噪声

Learn先学

Ask the same judge the same questions three times and the scores still move a little. That movement is the noise. Like a bathroom scale that shows 60.2 kg, then 60.5 kg: a loss of 0.1 kg means nothing. The rule is simple. Only a change bigger than the noise counts as a real change.

让同一个评委把同样的题目问三遍，分数还是会有一点晃动。这个晃动就是噪声。就像浴室的体重秤，先显示 60.2 公斤，再显示 60.5 公斤：瘦了 0.1 公斤说明不了什么。规则很简单：只有比噪声大的变化，才算真的变化。

# judge.py, continued def mean_score(verdicts): return sum(v["score"] for v in verdicts.values()) / len(verdicts) runs = [judge_all(pairs) for _ in range(3)] # the same judge, the same pairs, three times means = [mean_score(v) for v, _ in runs] noise = max(means) - min(means) moved = sum(len({v[p["id"]]["score"] for v, _ in runs}) > 1 for p in pairs) print("means", means, "noise", noise, "claims whose score moved:", moved, "of", len(pairs)) def real_change(before, after): return abs(after - before) > noise

预期输出 （示例：你的数字和措辞会不同）

means [3.6, 3.8, 3.7] noise 0.19999999999999996 claims whose score moved: 6 of 20

Step 5 · Count the judge’s cost on its own line第 5 步 · 把评委的花费单独记一行

Learn先学

A judge makes its own model calls, so it has its own bill. A stronger judge reading two texts can cost as much as the agent that wrote one. If you lump them together, you cannot tell which to cut. The prices below are examples; use your gateway’s price list.

评委自己也要调用模型，所以它有自己的账单。一个更强的评委读两段文字，花的钱可能和写出一段文字的智能体一样多。要是把两笔混在一起，你就不知道该砍哪一笔。下面的价格只是例子；请用你的网关的价格表。

# judge.py, continued AGENT_PRICE = (1.0, 5.0) # US$ per million tokens, in and out: examples only JUDGE_PRICE = (3.0, 15.0) def dollars(tokens, price): return (tokens[0] * price[0] + tokens[1] * price[1]) / 1_000_000 agent_tokens = (sum(p["agent_tokens"][0] for p in pairs), sum(p["agent_tokens"][1] for p in pairs)) n = len(pairs) print("agent per claim:", dollars(agent_tokens, AGENT_PRICE) / n) print("judge per claim:", dollars(spent, JUDGE_PRICE) / n)

Expected output (an example: your numbers and wording will differ)

预期输出 （示例：你的数字和措辞会不同）

agent per claim: 0.0121 judge per claim: 0.0064

Common errors常见错误

json.decoder.JSONDecodeError: Expecting value
Cause: the judge wrote a paragraph instead of the JSON verdict. Fix: ask for JSON only, and count an unreadable verdict as missing, not as a score.

json.decoder.JSONDecodeError: Expecting value
原因：评委写了一段话，而不是 JSON 评分。解决：只要 JSON；读不出来的评分算缺失，不要当作分数。

KeyError: 'score'
Cause: the verdict has a different field name than the code expects. Fix: put the exact field names in the judge prompt and check them in code.

KeyError: 'score'
原因：评分里的字段名和代码预期的不一样。解决：在评委提示里写明字段名，并在代码里检查。

ZeroDivisionError: division by zero
Cause: pairs is empty, so there are no claims to average over. Fix: check that collect() found the saved runs.

ZeroDivisionError: division by zero
原因：pairs 是空的，没有理赔可以求平均。解决：确认 collect() 找到了保存的运行。

Recap小结

• A judge model scores answers against a reference answer, so you can test more than the exact match.
• Measure the judge itself: does it agree with people, and does it just like long answers?
• Run twice to find the noise, and only trust changes bigger than that.

• 评委模型对照参考答案打分，所以能测的不只是完全一样。
• 要测评委本身：它和人一致吗？是不是只偏爱长答案？
• 跑两次找出噪声，只相信比噪声大的变化。

Takeaways要点回顾

• Give a judge a reference answer; it is far steadier than grading by feel.
• Ask for a grade plus checks, so every grade can be explained.
• Use a different model as the judge from the one being judged.
• Check the judge against a person before you trust it, and look for a lean such as favouring length.
• Scores move between runs, so only a change bigger than the noise counts.
• Record the judge’s cost separately from the agent’s.

• 给评委一份参考答案；它比凭感觉打分稳得多。
• 要等级，也要检查项，这样每个等级都说得清楚。
• 评委用的模型，要和被评的模型不同。
• 信任评委之前，先拿人来检查它，并找找有没有偏向，比如偏爱长文。
• 每轮分数会晃动，只有比噪声大的变化才算数。
• 评委的花费要和智能体的分开记。
