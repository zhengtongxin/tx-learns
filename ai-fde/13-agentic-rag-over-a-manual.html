The story故事

The pilot at Kaya Travel Cover handles easy claims well. The hard ones need facts that are not in the policy: a strike at the airport, a typhoon warning, the rule on old bags. Mr Goh keeps those in a thick claims manual. Mei Ling could paste the whole manual into every prompt, but it grows every month. So she builds a small knowledge base and gives the agent a search tool, so it can look things up the way Aisha does.

Kaya Travel Cover 的试点处理简单理赔很顺手。难的那些需要保单里没有的事实：机场罢工、台风警报、旧行李的赔偿规则。Goh 先生把这些都记在一本厚厚的理赔手册里。Mei Ling 可以把整本手册贴进每个提示词，但手册每个月都在变厚。所以她建了一个小小的知识库，再给智能体一个搜索工具，让它像 Aisha 那样自己去查。

Step 1 · A small knowledge base第 1 步 · 一个小小的知识库

Learn先学

Pasting everything into the prompt costs money on every claim, and a long prompt buries the one line that matters. Instead, cut the material into small sections, each with an id, and let the agent fetch only what it needs. This idea is called RAG: retrieve the right pieces, then answer from them. Think of the grey filing cabinet: nobody reads every folder, you pull the one you need.

把所有东西贴进提示词，每份理赔都要花钱，而且提示词太长，会把关键的那一行埋掉。换个办法：把资料切成小段落，每段有个编号，让智能体只取它需要的。这个做法叫 RAG：先取回合适的片段，再根据它们回答。就像那个灰色档案柜：没人会把每个文件夹都读一遍，你只抽出需要的那一份。

KB = [ {"id": "M4.2", "title": "Strikes", "text": "A delay or cancellation caused by a strike is covered only if the strike was not announced before the policy was bought."}, {"id": "M6.1", "title": "Used items", "text": "Lost or damaged items are paid at their current value, not the price when new. A bag two years old is paid at about half."}, {"id": "M2.3", "title": "Storms and weather", "text": "A cancellation caused by an official typhoon warning is covered. A delay with no warning is not."}, {"id": "E1", "title": "Airport handlers strike", "text": "Baggage handlers at the main airport announced a strike on 3 March. It ran from 10 to 12 March."}, {"id": "E2", "title": "Typhoon in the north", "text": "An official typhoon warning covered the northern coast from 20 to 22 August."}]

Step 2 · A search tool第 2 步 · 一个搜索工具

Learn先学

A search tool takes a short question and returns the best-matching sections. This one is the simplest kind: it counts how many words the question shares with each section, and drops sections that share none. A real system would match by meaning, using embeddings (a list of numbers for each section, where similar meanings get similar numbers). The idea is the same.

搜索工具接收一个简短的问题，返回匹配度最高的段落。这个是最简单的那种：数一数问题和每段共有多少个词，一个词都不共有的就丢掉。真正的系统会按意思匹配：用嵌入向量（每段话变成一串数字，意思相近的，数字也相近），但道理是一样的。

import re def words(text): return set(re.findall(r"[a-z0-9]+", text.lower())) def search(query, top=2): q = words(query) def score(s): return len(q & words(s["title"] + " " + s["text"])) best = sorted(KB, key=score, reverse=True) return [s for s in best[:top] if score(s) > 0]

Step 3 · The agent chooses its own searches第 3 步 · 智能体自己决定怎么搜

Learn先学

Now hand the search to the agent as a tool, as in the pilot. It reads the claim, decides what it is missing, searches, reads the result, and can search again. That loop is the “agentic” part. A tool is a function you write: the model asks for it, you run it, and the result goes back into the chat. max_searches is a safety cap so it cannot loop forever; once it is reached, the tool is taken away and the agent must answer. Install with pip install openai.

现在把搜索当成工具交给智能体，和试点里一样。它读理赔，判断自己缺什么，去搜，读结果，还可以再搜。这个循环就是“智能体式”的部分。工具就是你自己写的函数：模型来请求，你来运行，结果再送回对话里。max_searches 是一道安全上限，防止它无限循环；到了上限，工具就被收走，智能体必须作答。用 pip install openai 安装。

import json from openai import OpenAI client = OpenAI() RULES = """You decide travel insurance claims for Kaya Travel Cover. If you do not have the facts you need, reply refer. Reply with JSON only: {"action": "approve" or "decline" or "refer", "payout": a number in S$, "reason": two or three short sentences}""" LOOKUP = "\nBefore you decide, use search_kb to look up the manual and notes on outside events." TOOLS = [{"type": "function", "function": { "name": "search_kb", "description": "Search the claims manual and notes on outside events.", "parameters": {"type": "object", "properties": {"query": {"type": "string"}}, "required": ["query"]}}}] def decide(claim, max_searches=4): messages = [{"role": "system", "content": RULES + LOOKUP}, {"role": "user", "content": json.dumps(claim)}] searches = 0 while True: tools = {"tools": TOOLS} if searches < max_searches else {} # no tools once the cap is reached reply = client.chat.completions.create( model="gpt-5.4-mini", messages=messages, **tools) message = reply.choices[0].message if not message.tool_calls: return json.loads(message.content) messages.append(message) for call in message.tool_calls: query = json.loads(call.function.arguments)["query"] searches += 1 messages.append({"role": "tool", "tool_call_id": call.id, "content": json.dumps(search(query))})

Step 4 · Ask short, specific questions第 4 步 · 问得短、问得具体

Learn先学

A search only works as well as its question. If the agent searches with the customer’s whole story, every common word matches something, and you get noise. A short question with the one fact it needs finds the right section. Tell the agent so, in the instruction and in the tool description, which it reads each time.

搜索的好坏取决于问题。如果智能体拿客户的整段故事去搜，每个常见的词都能匹配到点什么，结果全是噪音。一个只带它所需那一个事实的短问题，才找得到对的段落。在指令和工具描述里都告诉它，它每次都会读。

LOOKUP = ("\nBefore you decide, use search_kb to look up the manual and notes on outside events." "\nSearch with a short, specific question of 3 to 6 words, for example 'strike announced before policy'." "\nNever paste the customer's story. Search again if you still miss a fact.") TOOLS[0]["function"]["description"] = "Search with ONE short specific question (3 to 6 words). Returns up to 2 sections with ids."

Sort these searches.

Step 5 · Compare with one-shot retrieval第 5 步 · 和一次性检索比一比

Learn先学

Plain RAG searches once, with the claim’s story, and always pastes the same top sections. That is cheap and fine for simple claims. It fails when a claim needs two facts joined. Take Mr Tan: the strike note says the strike was announced on 3 March, and the manual says a strike announced before purchase is not covered. He bought on 5 March. Only the agent can search for the date first and then for the rule.

普通 RAG 只搜一次，用理赔的故事去搜，永远贴同样的前几段。这样便宜，处理简单理赔也够了。但当一份理赔需要把两个事实连起来时，它就不行了。拿 Tan 先生来说：罢工笔记说罢工 3 月 3 日宣布，手册说购买前已宣布的罢工不赔，而他 3 月 5 日才买。只有智能体能先搜日期、再搜规则。

def decide_oneshot(claim): top = search(claim["story"], top=2) # one search, the whole story prompt = f"""{RULES} Sections found for you: {json.dumps(top)} The claim: {json.dumps(claim)}""" reply = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": prompt}]) return json.loads(reply.choices[0].message.content) claim = {"id": "C031", "customer": "Mr Tan", "bought": "5 March", "story": "My flight on 11 March was cancelled and I paid S$420 for a hotel. The airline said it was a strike.", "amount": 420} print(decide(claim)) # searches the strike note, then the strike rule: decline print(decide_oneshot(claim)) # one try; it may miss a fact

Step 6 · Show where the facts came from第 6 步 · 说清事实从哪来

Learn先学

Aisha will not trust “decline” without a reason she can check. Keep a list of every section id the agent was shown, and return it with the decision. The handler’s claim page can then show “read: E1, M4.2”. A cap on searches also becomes a safety setting: when the agent runs out of searches, the rules already tell it to reply refer.

Aisha 不会相信一个说不出理由的“拒赔”。把智能体看过的每个段落编号记下来，随决定一起返回。理赔员的页面就能显示“读过：E1、M4.2”。搜索次数的上限也成了安全开关：智能体搜索次数用完时，规则已经告诉它回答 refer（转交）。

def decide(claim, max_searches=4): messages = [{"role": "system", "content": RULES + LOOKUP}, {"role": "user", "content": json.dumps(claim)}] read = [] # every section id the agent saw searches = 0 while True: tools = {"tools": TOOLS} if searches < max_searches else {} # no tools once the cap is reached reply = client.chat.completions.create( model="gpt-5.4-mini", messages=messages, **tools) message = reply.choices[0].message if not message.tool_calls: decision = json.loads(message.content) decision["read"] = sorted(set(read)) return decision messages.append(message) for call in message.tool_calls: query = json.loads(call.function.arguments)["query"] searches += 1 found = search(query) read += [s["id"] for s in found] messages.append({"role": "tool", "tool_call_id": call.id, "content": json.dumps(found)})
What I got wrong我当时想错了My agent searched with the customer’s whole story and got noise back. The fix was not a better search: it was telling the agent to ask a short, specific question. That worked far better.我的智能体拿客户的整段故事去搜，结果全是噪音。解决办法不是换更好的搜索，而是告诉智能体问一个简短、具体的问题。效果好得多。

Takeaways要点回顾

• Do not stuff everything into the prompt: cut it into sections and let the agent search.
• Let the agent choose its own searches, and search again when a fact is missing.
• Short, specific queries beat pasting the whole story.
• Agentic search wins when a claim needs two facts joined.
• It costs more calls, so use it only where one shot fails.
• Keep the section ids the agent read and show them to the handler.
• When the searches run out, the safe answer is to refer.

• 不要把所有东西塞进提示词：切成段落，让智能体去搜。
• 让智能体自己决定怎么搜，缺了事实就再搜一次。
• 简短、具体的问题，胜过把整段故事贴进去。
• 理赔需要把两个事实连起来时，智能体式搜索更胜一筹。
• 它要多花几次调用，所以只在一次检索不行的地方用。
• 记下智能体读过的段落编号，并展示给理赔员。
• 搜索次数用完时，稳妥的答案是转交。
