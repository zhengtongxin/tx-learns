Agentic RAG over a manual手册上的智能体检索

Let the agent look things up in the claims manual and in notes on outside events, choosing its own searches · ~20 min · concept + one runnable idea让智能体自己在理赔手册和外部事件笔记里查资料，自己决定怎么搜 · 约 20 分钟 · 概念 + 一个能跑的想法

Step 1 · A small knowledge base and a search第 1 步 · 一个小知识库和一个搜索

Learn先学
  • Pasting a whole manual into every prompt costs money and buries the one line that matters. RAG (retrieval-augmented generation) cuts the material into small sections with ids, retrieves the right ones, then answers from them.
  • This search is the simplest kind: it counts words shared with each section. A real system matches by meaning, using embeddings. The idea is the same.
  • 把整本手册贴进每个提示词，既花钱，又会埋掉关键的那一行。RAG（检索增强生成）把资料切成带编号的小段落，取回合适的几段，再根据它们回答。
  • 这个搜索是最简单的那种：数一数和每段共有多少个词。真正的系统会按意思匹配，用嵌入向量。道理是一样的。
KB = [ {"id": "M4.2", "title": "Strikes", "text": "A delay or cancellation caused by a strike is covered only if the strike was not announced before the policy was bought."}, {"id": "M6.1", "title": "Used items", "text": "Lost or damaged items are paid at their current value, not the price when new. A bag two years old is paid at about half."}, {"id": "M2.3", "title": "Storms and weather", "text": "A cancellation caused by an official typhoon warning is covered. A delay with no warning is not."}, {"id": "E1", "title": "Airport handlers strike", "text": "Baggage handlers at the main airport announced a strike on 3 March. It ran from 10 to 12 March."}, {"id": "E2", "title": "Typhoon in the north", "text": "An official typhoon warning covered the northern coast from 20 to 22 August."}] import re def words(text): return set(re.findall(r"[a-z0-9]+", text.lower())) def search(query, top=2): q = words(query) def score(s): return len(q & words(s["title"] + " " + s["text"])) best = sorted(KB, key=score, reverse=True) return [s for s in best[:top] if score(s) > 0]

Step 2 · The agent chooses its own searches第 2 步 · 智能体自己决定怎么搜

Learn先学
  • Hand the search to the agent as a tool. It reads the claim, decides what it is missing, searches, reads the result and can search again. That loop is the “agentic” part (agentic RAG).
  • max_searches is a safety cap: once reached, the tool is taken away and the agent must answer, or refer.
  • Searches work only as well as the question. Tell the agent to ask a short, specific question (3 to 6 words), never the customer’s whole story.
  • Return the section ids it read, so a handler can check a “decline” for themselves.
  • Install with pip install openai.
  • 把搜索当成工具交给智能体。它读理赔，判断自己缺什么，去搜，读结果，还可以再搜。这个循环就是“智能体式”的部分（智能体式 RAG）。
  • max_searches 是一道安全上限：到了上限，工具就被收走，智能体必须作答，或者转交。
  • 搜索的好坏取决于问题。告诉智能体问一个简短、具体的问题（3 到 6 个词），不要贴客户的整段故事。
  • 把它读过的段落编号一起返回，理赔员就能亲自核对一个“拒绝”。
  • 用 pip install openai 安装。
import json from openai import OpenAI client = OpenAI() RULES = """You decide travel insurance claims. If you do not have the facts you need, reply refer. Reply with JSON only: {"action": "approve" or "decline" or "refer", "payout": a number in S$, "reason": two or three short sentences}""" LOOKUP = ("\nBefore you decide, use search_kb to look up the manual and notes on outside events." "\nSearch with a short, specific question of 3 to 6 words, for example 'strike announced before policy'." "\nNever paste the customer's story. Search again if you still miss a fact.") TOOLS = [{"type": "function", "function": { "name": "search_kb", "description": "Search with ONE short specific question (3 to 6 words). Returns up to 2 sections with ids.", "parameters": {"type": "object", "properties": {"query": {"type": "string"}}, "required": ["query"]}}}] def decide(claim, max_searches=4): messages = [{"role": "system", "content": RULES + LOOKUP}, {"role": "user", "content": json.dumps(claim)}] read = [] # every section id the agent saw searches = 0 while True: tools = {"tools": TOOLS} if searches < max_searches else {} # no tools once the cap is reached reply = client.chat.completions.create( model="gpt-5.4-mini", messages=messages, **tools) message = reply.choices[0].message if not message.tool_calls: decision = json.loads(message.content) decision["read"] = sorted(set(read)) return decision messages.append(message) for call in message.tool_calls: query = json.loads(call.function.arguments)["query"] searches += 1 found = search(query) read += [s["id"] for s in found] messages.append({"role": "tool", "tool_call_id": call.id, "content": json.dumps(found)})

Step 3 · Compare with one-shot retrieval第 3 步 · 和一次性检索比一比

Learn先学

Plain RAG searches once, with the claim’s story. It is cheap and fine for simple claims, but fails when a claim needs two facts joined. Here the strike note says the strike was announced on 3 March, the manual says a strike announced before purchase is not covered, and he bought on 5 March. Only the agent can search for the date first, then for the rule.

普通 RAG 只搜一次，用理赔的故事去搜。这样便宜，处理简单理赔也够了，但当一份理赔需要把两个事实连起来时就不行了。这里罢工笔记说罢工 3 月 3 日宣布，手册说购买前已宣布的罢工不赔，而他 3 月 5 日才买。只有智能体能先搜日期、再搜规则。

def decide_oneshot(claim): top = search(claim["story"], top=2) # one search, the whole story prompt = f"""{RULES} Sections found for you: {json.dumps(top)} The claim: {json.dumps(claim)}""" reply = client.chat.completions.create( model="gpt-5.4-mini", messages=[{"role": "user", "content": prompt}]) return json.loads(reply.choices[0].message.content) claim = {"id": "C031", "customer": "Mr Tan", "bought": "5 March", "story": "My flight on 11 March was cancelled and I paid S$420 for a hotel. The airline said it was a strike.", "amount": 420} print(decide(claim)) # searches the strike note, then the strike rule: decline print(decide_oneshot(claim)) # one try; it may miss a fact

Takeaways要点回顾

• Do not paste the whole manual; search it in small sections.
• Let the model choose short, specific searches and search again, with a cap.
• One-shot retrieval fails when two facts must be joined.
• Record which sections it read, so a handler can check the answer.

• 不要把整本手册贴进去，而是在小段落里检索。
• 让模型自己选简短、具体的检索词，可以再搜，但要有上限。
• 需要把两个事实连起来时，一次性检索就不行了。
• 记录它读了哪些段落，方便理赔员核对答案。
