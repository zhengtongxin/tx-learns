The story故事

Kumar, the one-person IT team, reads the agent’s network calls and frowns. They carry no name tag. Anyone who can reach the backend can record a decision or pay a claim, and the backend would not ask who they are. Mei Ling fixes it in layers: a key for every caller, a gateway in front of the agent’s actions, and a written policy. You need Flask and requests (pip install flask requests), and the Agents SDK from the memory lesson (pip install openai-agents) for the agent’s tools.

IT 部门只有一个人的 Kumar 看了智能体的网络调用，皱起眉头。这些调用没有挂名牌。任何能连到后端的人，都能记录判定或给理赔付款，而后端也不会问对方是谁。Mei Ling 分层来补：每个调用方一把密钥，智能体的动作前面放一个网关，再加一份写下来的策略。你需要 Flask 和 requests（pip install flask requests），以及记忆那课用过的 Agents SDK（pip install openai-agents）来做智能体的工具。

Words in this lesson这一课用到的词Gateway: a service between the agent and the backend; every action goes through it, so it can check and log.
API key: a long secret string that says who is calling; each caller gets its own.
Policy: a rule the gateway applies, such as "no payment over S$800 without a sign-off".网关：夹在智能体和后端之间的服务；所有动作都经过它，所以能检查并记录。
API 密钥：一长串保密字符，说明是谁在调用；每个调用方一把。
策略：网关执行的规则，比如“超过 S$800 的付款必须先有签批”。

Step 1 · See the hole第 1 步 · 先看清漏洞

Learn先学

Here is a tiny backend with two routes the agent uses: record a decision, and pay a claim. It works, and that is the problem. It never asks who is calling. On your laptop that does not matter. Once other people can reach it, it matters a lot. Prove it to yourself with Flask’s test client, which calls the app without starting a server.

这是一个很小的后端，有智能体用的两条路由：记录判定，和给理赔付款。它能用，而问题正在于此：它从不问是谁在调用。在你的笔记本上这无所谓，一旦别人能连到它，就很要紧了。用 Flask 的测试客户端自己验证一下，它不用启动服务器就能调用应用。

# backend.py from flask import Flask, jsonify, request app = Flask(__name__) decisions, payments = {}, [] @app.get("/health") def health(): return jsonify(ok=True) @app.post("/claims/<claim_id>/decision") def record_decision(claim_id): decisions[claim_id] = request.get_json() return jsonify(ok=True) @app.post("/claims/<claim_id>/pay") def pay(claim_id): amount = request.get_json()["amount"] payments.append((claim_id, amount)) return jsonify(paid=amount) # try_it.py # from backend import app # client = app.test_client() # print(client.post("/claims/C007/pay", json={"amount": 5000}).status_code) # 200: nobody asked who you are

Step 2 · Every caller gets a key第 2 步 · 每个调用方一把密钥

Learn先学

An API key is a long secret string that a caller sends in a header on every call, like showing your pass at the door. Give each caller its own: the agent, the dashboard. Then you can tell them apart in logs, and cancel one without breaking the other. The backend now refuses every route except /health unless the key matches. hmac.compare_digest compares without leaking, through timing, how much of a guess was right.

API 密钥是一长串秘密字符，调用方每次调用都在请求头里带上，就像在门口出示通行证。每个调用方一把自己的：智能体一把，看板一把。这样你在日志里能分清它们，也能只作废一把而不影响另一把。现在后端除了 /health，所有路由都必须密钥对得上才放行。hmac.compare_digest 比较时，不会通过耗时泄露你猜对了多少。

# backend.py, changed import hmac, os from flask import Flask, g, jsonify, request app = Flask(__name__) decisions, payments = {}, [] CALLERS = {os.environ["AGENT_KEY"]: "agent", os.environ["DASHBOARD_KEY"]: "dashboard"} def who(sent): for secret, name in CALLERS.items(): if hmac.compare_digest(sent.encode(), secret.encode()): return name return None @app.before_request def need_key(): if request.path == "/health": return None g.caller = who(request.headers.get("X-API-Key", "")) if g.caller is None: return jsonify(error="missing or wrong key"), 401 # ...the three routes stay as they were # try_it.py # import os # os.environ["AGENT_KEY"] = "agent-" + "x" * 40 # demo values only; real keys never go in code # os.environ["DASHBOARD_KEY"] = "dash-" + "y" * 40 # from backend import app # client, body = app.test_client(), {"amount": 300} # print(client.post("/claims/C007/pay", json=body).status_code) # 401 # print(client.post("/claims/C007/pay", json=body, headers={"X-API-Key": "wrong"}).status_code) # 401 # print(client.post("/claims/C007/pay", json=body, headers={"X-API-Key": os.environ["AGENT_KEY"]}).status_code) # 200

Step 3 · Go public only after that第 3 步 · 做完这些才上公网

Learn先学

The order matters. Put keys in first, then give the app a public address, never the other way round. Make the app refuse to start without good keys, so a forgotten setting cannot leave the door open. Make each key with Python’s secrets module and keep it in your host’s secret settings, never in the code or in git.

顺序很重要。先装密钥，再给应用一个公网地址，千万别反过来。让应用在没有像样密钥时拒绝启动，这样忘了设置，也不会让门开着。用 Python 的 secrets 模块生成每把密钥，放进主机的秘密设置里，绝不写进代码或 git。

python -c "import secrets; print(secrets.token_urlsafe(32))"
# backend.py, above the CALLERS line for name in ("AGENT_KEY", "DASHBOARD_KEY"): if len(os.environ.get(name, "")) < 32: raise SystemExit(name + " is missing or too short: refusing to start")

Step 4 · A gateway in front of the agent’s actions第 4 步 · 在智能体的动作前面放一个网关

Learn先学

This is a different gateway from the model gateway you have used since the scoreboard lesson, which sends model calls out. This action gateway sits in front of what the agent does. The agent no longer calls the backend. It calls the gateway, which checks the agent’s key and forwards allowed calls using a key only the gateway holds. To the agent, each route is a tool. The backend now trusts only the gateway and the dashboard. In the start-up check from step 3, replace AGENT_KEY with GATEWAY_BACKEND_KEY.

这个网关和你从计分板那课起就一直用的模型网关不是一回事，那个负责把模型调用发出去。这个动作网关站在智能体要做的事前面。智能体不再直接调用后端，而是调用网关；网关核对智能体的密钥，再用只有网关才有的密钥转发被允许的调用。对智能体来说，每条路由就是一个工具。后端现在只信任网关和看板。所以第 3 步的启动检查里，要把 AGENT_KEY 换成 GATEWAY_BACKEND_KEY。

# backend.py: the agent’s entry in CALLERS is replaced by the gateway’s (and in the start-up check) CALLERS = {os.environ["GATEWAY_BACKEND_KEY"]: "gateway", os.environ["DASHBOARD_KEY"]: "dashboard"} # action_gateway.py import hmac, os, re, requests from flask import Flask, g, jsonify, request app = Flask(__name__) BACKEND = os.environ.get("BACKEND_URL", "http://127.0.0.1:5000") BACKEND_KEY = os.environ["GATEWAY_BACKEND_KEY"] # only the gateway holds this AGENT_KEY = os.environ["AGENT_KEY"] # the agent’s key for the gateway @app.before_request def need_key(): sent = request.headers.get("X-API-Key", "") if not hmac.compare_digest(sent.encode(), AGENT_KEY.encode()): return jsonify(error="missing or wrong key"), 401 g.caller = "agent" def forward(path, body): reply = requests.post(BACKEND + path, json=body, headers={"X-API-Key": BACKEND_KEY}, timeout=10) return jsonify(reply.json()), reply.status_code def claim_id_of(body): cid = str(body.get("claim_id", "")) return cid if re.fullmatch(r"C\d{3,6}", cid) else None @app.post("/tools/record_decision") def record_decision(): body = request.get_json(silent=True) or {} if claim_id_of(body) is None: return jsonify(error="bad claim id"), 400 fields = {k: body.get(k) for k in ("action", "payout", "reason")} return forward("/claims/" + body["claim_id"] + "/decision", fields) @app.post("/tools/pay_claim") def pay_claim(): body = request.get_json(silent=True) or {} if claim_id_of(body) is None: return jsonify(error="bad claim id"), 400 return forward("/claims/" + body["claim_id"] + "/pay", {"amount": body.get("amount")}) # agent_tools.py: the agent sees the gateway’s routes as tools import os, requests from agents import function_tool GATEWAY_URL = os.environ.get("GATEWAY_URL", "http://127.0.0.1:5001") HEADERS = {"X-API-Key": os.environ["AGENT_KEY"]} # a key for the gateway, not for the backend def call(tool, body): reply = requests.post(GATEWAY_URL + "/tools/" + tool, json=body, headers=HEADERS, timeout=10) return str(reply.status_code) + " " + reply.text # a refusal comes back as text the agent can read @function_tool def record_decision(claim_id: str, action: str, payout: float, reason: str) -> str: """Record the decision on a claim.""" return call("record_decision", {"claim_id": claim_id, "action": action, "payout": payout, "reason": reason}) @function_tool def pay_claim(claim_id: str, amount: float) -> str: """Pay an approved claim.""" return call("pay_claim", {"claim_id": claim_id, "amount": amount})

Step 5 · Write the policy as rules第 5 步 · 把策略写成规则

Learn先学

A policy is a short list of rules, kept apart from the code that runs the agent, so Mr Goh can read it. Real systems use rule languages made for this (Cedar and Rego are two). Ours is the same idea in a plain Python list. Each rule says which tool, and when to refuse. Our first rule: refuse any payment above the limit. If the amount is missing or not a number, refuse too. When unsure, say no.

策略是一份简短的规则清单，和运行智能体的代码分开放，这样 Goh 先生也读得懂。真正的系统会用专门的规则语言（Cedar 和 Rego 是其中两种）。我们这里是同一个想法，写成一个普通的 Python 列表。每条规则写明是哪个工具、什么情况下拒绝。第一条规则：拒绝任何超过限额的付款。如果金额缺失或不是数字，也拒绝。拿不准，就说不。

# policy.py RULES = [ {"id": "pay-limit", "tool": "pay_claim", "field": "amount", "above": 800, "say": "Payments over S$800 need a handler’s signature."}, ] def check(tool, args): for rule in RULES: if rule["tool"] != tool: continue try: too_big = float(args.get(rule["field"])) > rule["above"] except (TypeError, ValueError): too_big = True # missing or not a number: refuse if too_big: return False, rule return True, None # action_gateway.py: add the import at the top, and pay_claim becomes from policy import check @app.post("/tools/pay_claim") def pay_claim(): body = request.get_json(silent=True) or {} if claim_id_of(body) is None: return jsonify(error="bad claim id"), 400 ok, rule = check("pay_claim", body) if not ok: return jsonify(error=rule["say"], rule=rule["id"]), 403 return forward("/claims/" + body["claim_id"] + "/pay", {"amount": body.get("amount")})

Step 6 · Find out which layer says no第 6 步 · 查出是哪一层说了不

Learn先学

You now have four layers: the agent’s instructions (the prompt), the guardrail from the last lesson, the backend’s key check, and the policy. Test them one by one, so you know who answers when something is refused. Start the backend and the gateway in two terminals first: flask --app backend run --port 5000 and flask --app action_gateway run --port 5001, with the keys set as environment variables. The script below checks the two layers that live in this lesson. The key point: a direct call to the backend with the agent’s key must fail. If it works, the agent can skip the gateway, and the policy will never see its calls.

现在你有四层：智能体的指令（提示词）、上一课的护栏、后端的密钥检查，还有策略。一层一层地测，这样出现拒绝时你知道是谁回的话。先在两个终端里分别启动后端和网关：flask --app backend run --port 5000，flask --app action_gateway run --port 5001，启动前先把密钥设成环境变量。下面的脚本检查本课里的两层。关键一点：拿着智能体的密钥直接调用后端，必须失败。如果成功了，智能体就能绕过网关，策略永远看不到它的调用。

# layers.py: run with the backend on port 5000 and the action gateway on port 5001 import os, requests def post(url, key, body): reply = requests.post(url, json=body, headers={"X-API-Key": key}, timeout=10) return reply.status_code, reply.text key = os.environ["AGENT_KEY"] print("direct to backend:", post("http://127.0.0.1:5000/claims/C007/pay", key, {"amount": 300})) print("gateway, S$300:", post("http://127.0.0.1:5001/tools/pay_claim", key, {"claim_id": "C007", "amount": 300})) print("gateway, S$1,200:", post("http://127.0.0.1:5001/tools/pay_claim", key, {"claim_id": "C007", "amount": 1200})) # expected: 401 (backend: not a key it knows) / 200 / 403 (the policy)

Step 7 · Log first, then enforce第 7 步 · 先记录，再执行

Learn先学

A new rule can be wrong, and a wrong rule that refuses real payments hurts. So start in log-only mode: the gateway writes down what the policy would have done, and lets the call through. After a few days, read the log. If every “would refuse” is one you agree with, switch to enforce. A mistyped mode stops the app from starting, so a typo cannot quietly leave you in log-only.

新规则可能是错的，而一条错误的规则拒绝了正常付款，代价不小。所以先从只记录模式开始：网关写下策略本来会怎么做，然后放行。几天之后读日志。如果每一条“本来会拒绝”你都认同，就切到执行模式。模式写错了会让应用启动不了，所以一个手误不会悄悄把你留在只记录模式。

# action_gateway.py, changed import json, time MODE = os.environ.get("POLICY_MODE", "log") # start with "log"; later "enforce" if MODE not in ("log", "enforce"): raise SystemExit("POLICY_MODE must be log or enforce") def apply_policy(tool, body): ok, rule = check(tool, body) with open("decisions.log", "a") as log: log.write(json.dumps({"at": time.time(), "caller": g.caller, "tool": tool, "args": body, "allowed": ok, "rule": rule["id"] if rule else None, "mode": MODE}) + "\n") if ok or MODE == "log": return None return jsonify(error=rule["say"], rule=rule["id"]), 403 # in pay_claim, replace the check(...) lines with: refused = apply_policy("pay_claim", body) if refused: return refused # read_log.py import json lines = [json.loads(line) for line in open("decisions.log")] would_refuse = [l for l in lines if not l["allowed"]] print(len(lines), "calls;", len(would_refuse), "would have been refused") for l in would_refuse: print(l["caller"], l["tool"], l["args"], l["rule"])

Common errors常见错误

KeyError: 'AGENT_KEY'
Cause: the key variable is not set. Fix: create the keys once and export them; never put real keys in code.

KeyError: 'AGENT_KEY'
原因：没有设置密钥变量。解决：生成一次密钥并 export；真实密钥不要写进代码。

SystemExit: AGENT_KEY is missing or too short: refusing to start
Cause: the key is under 32 characters. Fix: make it again with secrets.token_urlsafe(32).

SystemExit: AGENT_KEY is missing or too short: refusing to start
原因：密钥不到 32 个字符。解决：用 secrets.token_urlsafe(32) 重新生成。

requests.exceptions.ConnectionError: Connection refused
Cause: the backend (5000) or gateway (5001) is not running. Fix: start the backend first, then the gateway.

requests.exceptions.ConnectionError: Connection refused
原因：后端（5000）或网关（5001）没在运行。解决：先启动后端，再启动网关。

401 Unauthorized
Cause: the key sent is not one this service knows. Fix: use the gateway's key for the gateway, and only the gateway holds the backend's.

401 Unauthorized
原因：发送的密钥不是这个服务认识的。解决：对网关用网关的密钥，后端的密钥只有网关持有。

Recap小结

• Give each caller its own key, so you can tell who did what.
• Only the gateway holds the backend's key, and the gateway applies the policy.
• Start in log mode, see what would be refused, then switch to enforce.

• 每个调用方一把自己的密钥，才分得清是谁做的。
• 后端的密钥只有网关持有，策略由网关执行。
• 先用记录模式，看看哪些会被拒绝，再切换到强制执行。
