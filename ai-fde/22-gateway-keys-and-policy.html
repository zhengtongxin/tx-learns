Gateway, keys, policy网关、密钥与策略

Make sure only known callers can act, and that every action passes a written rule first · ~30 min · concept with one runnable idea确保只有认得的调用方才能动手，并且每个动作都先过一条写下来的规则 · 约 30 分钟 · 概念课，带一段能跑的代码

Step 1 · Every caller gets a key第 1 步 · 每个调用方一把密钥

Learn先学
  • A backend that never asks who is calling lets anyone who can reach it pay a claim. Fine on your laptop, not once others can reach it.
  • An API key is a long secret string sent in a header on every call. Give each caller its own (agent, dashboard), so you can tell them apart and cancel one alone.
  • Keys first, public address second. Make the app refuse to start without good keys, so a forgotten setting cannot leave the door open.
  • Make keys with secrets and keep them in your host's secret settings, never in code or git.
  • 一个从不问“是谁在调用”的后端，会让任何能连到它的人给理赔付款。在你的笔记本上没事，别人能连上就不行了。
  • API 密钥是一长串秘密字符，每次调用都在请求头里带上。每个调用方一把自己的（智能体、看板），这样分得清谁是谁，也能只作废一把。
  • 先装密钥，再给公网地址。让应用在没有像样密钥时拒绝启动，这样忘了设置也不会让门开着。
  • 用 secrets 生成密钥，放进主机的秘密设置里，绝不写进代码或 git。

Install with pip install flask requests. Make a key with python -c "import secrets; print(secrets.token_urlsafe(32))".

用 pip install flask requests 安装。生成密钥：python -c "import secrets; print(secrets.token_urlsafe(32))"。

# backend.py import hmac, os from flask import Flask, g, jsonify, request for name in ("AGENT_KEY", "DASHBOARD_KEY"): if len(os.environ.get(name, "")) < 32: raise SystemExit(name + " is missing or too short: refusing to start") app = Flask(__name__) payments = [] CALLERS = {os.environ["AGENT_KEY"]: "agent", os.environ["DASHBOARD_KEY"]: "dashboard"} def who(sent): for secret, name in CALLERS.items(): if hmac.compare_digest(sent.encode(), secret.encode()): # no timing leak return name return None @app.before_request def need_key(): if request.path == "/health": return None g.caller = who(request.headers.get("X-API-Key", "")) if g.caller is None: return jsonify(error="missing or wrong key"), 401 @app.get("/health") def health(): return jsonify(ok=True) @app.post("/claims/<claim_id>/pay") def pay(claim_id): amount = request.get_json()["amount"] payments.append((claim_id, amount)) return jsonify(paid=amount) # try_it.py: Flask's test client calls the app without a server # client = app.test_client() # client.post("/claims/C007/pay", json={"amount": 300}).status_code # 401 # client.post("/claims/C007/pay", json={"amount": 300}, headers={"X-API-Key": "wrong"}).status_code # 401 # client.post("/claims/C007/pay", json={"amount": 300}, headers={"X-API-Key": os.environ["AGENT_KEY"]}).status_code # 200

Step 2 · A gateway and a written policy第 2 步 · 网关和一份写下来的策略

Learn先学
  • An action gateway (not the model gateway) sits in front of what the agent does. The agent calls the gateway with its key; the gateway forwards allowed calls with a key only it holds. The backend trusts only the gateway and the dashboard.
  • To the agent, each gateway route is a tool.
  • A policy is a short written list of rules kept apart from the agent's code, so anyone can read it. First rule: refuse any payment above S$800. If the amount is missing or not a number, refuse too: when unsure, say no.
  • 动作网关（不是模型网关）站在智能体要做的事前面。智能体带着自己的密钥调用网关；网关用只有它持有的密钥转发被允许的调用。后端只信任网关和看板。
  • 对智能体来说，网关的每条路由就是一个工具。
  • 策略是一份简短的书面规则，和智能体的代码分开放，谁都读得懂。第一条规则：拒绝任何超过 S$800 的付款。金额缺失或不是数字也拒绝：拿不准，就说不。
# backend.py: replace the agent's entry in CALLERS (and in the start-up check) with the gateway's CALLERS = {os.environ["GATEWAY_BACKEND_KEY"]: "gateway", os.environ["DASHBOARD_KEY"]: "dashboard"} # policy.py RULES = [{"id": "pay-limit", "tool": "pay_claim", "field": "amount", "above": 800, "say": "Payments over S$800 need a handler’s signature."}] def check(tool, args): for rule in RULES: if rule["tool"] != tool: continue try: too_big = float(args.get(rule["field"])) > rule["above"] except (TypeError, ValueError): too_big = True # missing or not a number: refuse if too_big: return False, rule return True, None # action_gateway.py import hmac, os, re, requests from flask import Flask, jsonify, request from policy import check app = Flask(__name__) BACKEND = os.environ.get("BACKEND_URL", "http://127.0.0.1:5000") BACKEND_KEY = os.environ["GATEWAY_BACKEND_KEY"] # only the gateway holds this AGENT_KEY = os.environ["AGENT_KEY"] # the agent's key for the gateway @app.before_request def need_key(): sent = request.headers.get("X-API-Key", "") if not hmac.compare_digest(sent.encode(), AGENT_KEY.encode()): return jsonify(error="missing or wrong key"), 401 @app.post("/tools/pay_claim") def pay_claim(): body = request.get_json(silent=True) or {} claim_id = str(body.get("claim_id", "")) if not re.fullmatch(r"C\d{3,6}", claim_id): return jsonify(error="bad claim id"), 400 ok, rule = check("pay_claim", body) if not ok: return jsonify(error=rule["say"], rule=rule["id"]), 403 reply = requests.post(BACKEND + "/claims/" + claim_id + "/pay", json={"amount": body["amount"]}, headers={"X-API-Key": BACKEND_KEY}, timeout=10) return jsonify(reply.json()), reply.status_code

Step 3 · Find out which layer says no第 3 步 · 查出是哪一层说了不

Learn先学
  • You have four layers: the agent's instructions, the guardrail from the last lesson, the backend's key check, and the policy. Test them one by one.
  • Start the backend (flask --app backend run --port 5000) and gateway (flask --app action_gateway run --port 5001) with the keys exported.
  • A direct call to the backend with the agent's key must fail. If it works, the agent can skip the gateway and the policy never sees its calls.
  • 你有四层：智能体的指令、上一课的护栏、后端的密钥检查，还有策略。一层一层地测。
  • 设好密钥后启动后端（flask --app backend run --port 5000）和网关（flask --app action_gateway run --port 5001）。
  • 拿着智能体的密钥直接调用后端，必须失败。如果成功了，智能体就能绕过网关，策略永远看不到它的调用。
# layers.py: run with the backend on port 5000 and the action gateway on port 5001 import os, requests def post(url, key, body): reply = requests.post(url, json=body, headers={"X-API-Key": key}, timeout=10) return reply.status_code, reply.text key = os.environ["AGENT_KEY"] print("direct to backend:", post("http://127.0.0.1:5000/claims/C007/pay", key, {"amount": 300})) print("gateway, S$300:", post("http://127.0.0.1:5001/tools/pay_claim", key, {"claim_id": "C007", "amount": 300})) print("gateway, S$1,200:", post("http://127.0.0.1:5001/tools/pay_claim", key, {"claim_id": "C007", "amount": 1200}))

Expected output

预期输出

direct to backend: (401, '{"error":"missing or wrong key"}\n') gateway, S$300: (200, '{"paid":300}\n') gateway, S$1,200: (403, '{"error":"Payments over S$800 need a handler’s signature.","rule":"pay-limit"}\n')

Which layer says no in each case? Sort them.

每种情况是哪一层说了不？来分一分。

Common errors常见错误

SystemExit: AGENT_KEY is missing or too short: refusing to start
Fix: make the key with secrets.token_urlsafe(32) and export it.

Takeaways要点回顾

• Every caller gets its own key; the backend refuses calls without one.
• Keys first, public address second; refuse to start when keys are missing.
• An action gateway sits in front of what the agent does, and only it holds the backend's key.
• A policy is a short written list of rules that fails closed.
• A policy only protects what goes through it: test which layer says no.

• 每个调用方一把自己的密钥；没有密钥，后端拒绝调用。
• 先装密钥，再上公网；缺了密钥就拒绝启动。
• 动作网关站在智能体要做的事前面，后端的密钥只有它持有。
• 策略是一份简短的书面规则，拿不准就拒绝。
• 策略只保护经过它的东西：测出是哪一层说了不。
