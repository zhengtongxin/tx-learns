Project: an improver a human approves项目：由人批准的改进者

Let a second agent suggest improvements, with a person saying yes and code deciding what stays · ~30 min · hands-on让第二个智能体提改进建议，由人点头，由代码决定哪些留下 · 约 30 分钟 · 动手实践

Where we left off上回讲到

Last time the pilot could grade its own explanations with a judge. Today it fails because every week someone tweaks the agent’s instructions, and nobody knows what changed or whether it helped. We fix it with an improver that only proposes, while Aisha says yes or no and plain code decides what stays.

上回，试点能用评委给自己的解释打分。今天的问题是：每个星期都有人调智能体的指令，没人知道改了什么，也不知道有没有用。我们的办法是做一个只能提议的改进者，由 Aisha 说行或不行，再由普通代码决定改动要不要留下。

The story故事

Every week someone tweaks the claims agent’s instructions, and nobody remembers what changed or whether it helped. Mei Ling wants a helper that proposes tweaks. But Mr Goh will not have a machine quietly rewriting the agent that touches payouts. So the rules are: the helper only proposes, Aisha says yes or no, and plain code decides whether a change stays. This project uses bench.py and scoreboard.py from the scoreboard lesson (claims, key, small_prompt, ask, gateway, HELD_OUT, held_claims) and scoring.py (matrix, accuracy, mistake_cost).

每个星期都有人调一调理赔智能体的指令，没人记得改了什么，也不知道有没有用。Mei Ling 想要一个会提建议的帮手。但 Goh 先生不会允许一台机器悄悄改写那个碰赔付的智能体。所以规矩是：帮手只能提议，Aisha 说行或不行，由普通代码决定改动要不要留下。这个项目用到计分板那课的 bench.py 和 scoreboard.py（claims、key、small_prompt、ask、gateway、HELD_OUT、held_claims），以及 scoring.py（matrix、accuracy、mistake_cost）。

Words in this lesson这一课用到的词Version: one saved copy of the agent's instructions, with a number, so you can go back.
Improver: an agent that proposes edits to the instructions after reading the failures.
Put back in use: a person chooses which kept version is live; the improver cannot do it.版本：带编号的、保存下来的一份智能体指令，可以退回去。
改进者：读了失败案例后，对指令提出修改的智能体。
投入使用：由人选择哪个保留的版本上线；改进者做不到。

Step 1 · The agent’s setup, in numbered versions第 1 步 · 把智能体的设置存成带编号的版本

Learn先学

Three things decide how the agent behaves: its extra instructions, its model and its reasoning effort (how long the model thinks). Keep them together as one configuration. Every change makes a new numbered version; old ones are never edited. Each version records what changed, why, who proposed it and who approved it. Like the shophouse’s filing cabinet: you add a new page, you never rub out the old one.

三样东西决定智能体的行为：额外的指令、模型，以及推理力度（模型想多久）。把它们放在一起，称为一份配置。每次改动都产生一个带编号的新版本；旧版本绝不修改。每个版本都记下改了什么、为什么、谁提议、谁批准。就像店屋里的档案柜：你加一页新的，从不擦掉旧的。

# versions.py import json, os FILE = "versions.json" FIELDS = ("instructions", "model", "effort") def save(state): json.dump(state, open(FILE, "w"), indent=2) def load(): if not os.path.exists(FILE): save({"active": 1, "log": [], "versions": [{ "n": 1, "instructions": "", "model": "anthropic/claude-haiku-5-5", "effort": "low", "changed": "starting point", "why": "the agent as it ran on the scoreboard", "proposed_by": "Mei Ling", "approved_by": "Mei Ling", "status": "kept", "scores": None}]}) return json.load(open(FILE)) def find(state, n): return next(v for v in state["versions"] if v["n"] == n) def active(state): return find(state, state["active"])

Step 2 · The improver follows a recipe, and has limits第 2 步 · 改进者照着配方走，并且有界限

Learn先学

A recipe is a short list of steps the improver must follow, kept in a file so people can read it. Read the results, propose one change, stop and wait for a person, then run the evaluation. The improver sees only the practice claims, never the held-out ones (the claims kept back for the final test). It must change exactly one of the three fields. And only one round can be open at a time.

配方是改进者必须照着走的一份简短步骤，存在文件里，人人看得懂。读结果，提一个改动，停下来等人，再跑评估。改进者只能看到练习用的理赔，根本看不到留出的那些（留着做最后考试的理赔）。它必须正好改三个字段中的一个。而且同一时间只能开一轮。

# improver.py import json, os from bench import gateway, claims, key, small_prompt, ask from scoreboard import HELD_OUT from versions import load, save, find, active, FIELDS IMPROVER = "anthropic/claude-sonnet-5-5" practice = [c for c in claims if c["id"] not in HELD_OUT] # the improver never sees held-out claims DEFAULT_RECIPE = """1. Read the results on the practice claims and see where the agent differs from the handlers. 2. Propose ONE change to ONE of: instructions, model, effort. Say why. 3. Stop and wait for a person to approve. 4. Only after approval does code run the held-out evaluation. 5. Say in one sentence how this recipe could be better.""" def recipe(): return open("recipe.txt").read() if os.path.exists("recipe.txt") else DEFAULT_RECIPE class Busy(Exception): pass def run_config(config, claim): reply = gateway.chat.completions.create( model=config["model"], messages=[{"role": "user", "content": config["instructions"] + "\n" + small_prompt(claim)}], extra_body={"reasoning": {"effort": config["effort"]}}) # check your gateway's name for this text = reply.choices[0].message.content return json.loads(text[text.index("{"): text.rindex("}") + 1]) def propose(): state = load() if any(v["status"] in ("proposed", "testing") for v in state["versions"]): raise Busy("a round is already open") config = active(state) results = [{"story": c["story"], "agent": run_config(config, c)["action"], "handler": key[c["id"]]["action"]} for c in practice] prompt = f"""You improve a claims agent by following this recipe: {recipe()} Current setup: {json.dumps({f: config[f] for f in FIELDS})} Results on practice claims: {json.dumps(results)} Reply with JSON only: {{"field": "instructions" or "model" or "effort", "value": "the new value", "why": "one sentence"}}""" proposal = ask(gateway, IMPROVER, prompt)[0] if proposal["field"] not in FIELDS or not str(proposal["value"]).strip(): raise ValueError("the improver must change exactly one of: " + ", ".join(FIELDS)) n = len(state["versions"]) + 1 new = {f: config[f] for f in FIELDS} new[proposal["field"]] = proposal["value"] state["versions"].append({"n": n, **new, "changed": proposal["field"], "why": proposal["why"], "proposed_by": "improver", "approved_by": None, "status": "proposed", "scores": None}) save(state) return n

哪些东西改进者可以自己提议改？来分一分。

Step 3 · A person says yes, or no第 3 步 · 由人说行，或不行

Learn先学

A proposal just sits there, marked proposed, until a person acts. Approving records the name and moves it to testing. Rejecting records the name and closes the round, and nothing else changes: the agent keeps running the version it had. Rejecting is also how a handler stops a round.

提议只是放在那里，标着 proposed，直到有人动手。批准会记下名字，并把它变成 testing。拒绝会记下名字并结束这一轮，其余什么都不变：智能体继续跑它原来的版本。拒绝也是理赔员叫停一轮的办法。

# improver.py, continued def approve(n, who): state = load() version = find(state, n) if version["status"] != "proposed": raise ValueError("this version is not waiting for approval") version["approved_by"] = who version["status"] = "testing" save(state) def reject(n, who): state = load() version = find(state, n) if version["status"] != "proposed": raise ValueError("this version is not waiting for approval") version["rejected_by"] = who version["status"] = "rejected" save(state)

Step 4 · Code decides: keep, or roll back第 4 步 · 代码来定：留下，还是回滚

Learn先学

After approval, code runs the held-out claims with the new version and compares the scores with the version in use. Keep it only if agreement is no lower, the cost of mistakes is no higher, and at least one of the two is better. Otherwise it is rolled back, which just means the agent stays on the old version. The improver never marks its own work.

批准之后，代码用新版本去跑留出的理赔，把分数和正在用的版本比。只有同时满足三点才留下：一致率没有更低，错误的代价没有更高，而且两者之中至少有一个更好。否则就回滚，意思只是智能体继续用旧版本。改进者从不给自己的作业打分。

# improver.py, continued from scoreboard import held_claims from scoring import matrix, accuracy, mistake_cost def evaluate(config): grid = matrix([(key[c["id"]]["action"], run_config(config, c)["action"]) for c in held_claims]) return {"agreement": accuracy(grid), "mistake_cost_sgd": mistake_cost(grid)} def keep_or_roll_back(old, new): no_worse = new["agreement"] >= old["agreement"] and new["mistake_cost_sgd"] <= old["mistake_cost_sgd"] better = new["agreement"] > old["agreement"] or new["mistake_cost_sgd"] < old["mistake_cost_sgd"] return no_worse and better def finish_round(n): state = load() version, current = find(state, n), active(state) if version["status"] != "testing": raise ValueError("this version has not been approved") if current["scores"] is None: current["scores"] = evaluate(current) version["scores"] = evaluate(version) if keep_or_roll_back(current["scores"], version["scores"]): version["status"] = "kept" state["active"] = n else: version["status"] = "rolled_back" save(state) return version["status"]

Step 5 · The recipe’s last step: improve the recipe第 5 步 · 配方的最后一步：改进配方

Learn先学

The recipe’s fifth step lets the improver suggest a better recipe. But a suggestion is only a suggestion: it is stored as pending until a person approves it. Code also refuses any new recipe without the words “wait for a person”, so the improver cannot talk its way out of its own leash. That is a plain text check, not a full guarantee, so a person still reads every edit.

配方的第五步，让改进者可以建议一份更好的配方。但建议只是建议：它存成 pending，等人批准。代码还会拒绝任何不含“等人批准”这几个字的新配方，所以改进者没法自己把自己的缰绳解开。这只是一段文字检查，算不上万无一失，所以人还是要读每一处改动。

# improver.py, continued EDITS = "recipe_edits.json" def edits(): return json.load(open(EDITS)) if os.path.exists(EDITS) else [] def suggest_recipe_edit(n): version = find(load(), n) prompt = f"""Here is your recipe: {recipe()} Round {n} ended as {version["status"]}, scores {json.dumps(version["scores"])}. Suggest one better recipe. Reply with JSON only: {{"recipe": "the whole new recipe", "why": "one sentence"}}""" suggestion = ask(gateway, IMPROVER, prompt)[0] json.dump(edits() + [{**suggestion, "status": "pending"}], open(EDITS, "w"), indent=2) def approve_recipe_edit(i, who): all_edits = edits() new_recipe = all_edits[i]["recipe"] if "wait for a person" not in new_recipe.lower(): raise ValueError("a recipe must keep its step that waits for a person") open("recipe.txt", "w").write(new_recipe) all_edits[i]["status"] = "approved by " + who json.dump(all_edits, open(EDITS, "w"), indent=2)

Step 6 · A Configuration page, and a way back第 6 步 · 一个配置页，和一条回头路

Learn先学

Handlers should see every version, its scores and what changed, without opening a file. Add a page to the backend app, with routes to approve, reject and roll back. Rolling back to an older kept version only moves the pointer; nothing is deleted. Install with pip install flask, then start it with flask --app config_app run --port 5001. The handler’s name here is just typed in; the next lessons in this topic add real keys. The approve route waits for the whole evaluation, as the scoreboard lesson did.

理赔员应该不用打开文件，就能看到每个版本、它的分数和改了什么。给后端应用加一个页面，再加批准、拒绝和回滚的路由。回滚到更早的已留下版本，只是挪动指针，什么都不删。用 pip install flask 安装，再用 flask --app config_app run --port 5001 启动。这里理赔员的名字只是手输的；这个主题后面的课会加上真正的密钥。批准路由会等整个评估跑完，和计分板那课一样。

# config_app.py import html from flask import Flask, jsonify, request from versions import load, save, find from improver import propose, approve, reject, finish_round, Busy app = Flask(__name__) @app.get("/configuration") def configuration(): state = load() rows = "" for v in state["versions"]: scores = v["scores"] or {} cells = [("▶ " if v["n"] == state["active"] else "") + str(v["n"]), v["status"], v["changed"], v["why"], v["proposed_by"], v["approved_by"] or "", scores.get("agreement", ""), scores.get("mistake_cost_sgd", "")] rows += "<tr>" + "".join("<td>" + html.escape(str(c)) + "</td>" for c in cells) + "</tr>" head = "Version,Status,Changed,Why,Proposed by,Approved by,Agreement,Mistake cost S$".split(",") return "<h1>Configuration</h1><table><tr>" + "".join("<th>" + h + "</th>" for h in head) + "</tr>" + rows + "</table>" @app.post("/rounds") def new_round(): try: return jsonify(version=propose()), 201 except Busy as e: return jsonify(error=str(e)), 409 @app.post("/versions/<int:n>/approve") def approve_route(n): approve(n, request.get_json()["handler"]) return jsonify(result=finish_round(n)) @app.post("/versions/<int:n>/reject") def reject_route(n): reject(n, request.get_json()["handler"]) return jsonify(result="rejected") @app.post("/versions/<int:n>/use") def roll_back_to(n): state = load() if find(state, n)["status"] != "kept": return jsonify(error="only a kept version can be put back in use"), 400 state["active"] = n state["log"].append({"handler": request.get_json()["handler"], "put_back": n}) save(state) return jsonify(active=n)

Common errors常见错误

KeyError: 'active'
Cause: versions.json is missing or empty. Fix: create the first version with the starting prompt before you start the improver.

KeyError: 'active'
原因：versions.json 不存在或是空的。解决：启动改进者之前，先用起始提示建好第一个版本。

400 Bad Request: only a kept version can be put back in use
Cause: you asked to use a version that was dropped. Fix: pick a version whose status is "kept".

400 Bad Request: only a kept version can be put back in use
原因：你要用的版本已被放弃。解决：选状态是“kept”的版本。

json.decoder.JSONDecodeError: Expecting value
Cause: the proposed edit came back as plain words. Fix: ask for JSON only, and skip a proposal you cannot read.

json.decoder.JSONDecodeError: Expecting value
原因：提出的修改是一段普通文字。解决：只要 JSON，读不出来的提案直接跳过。

Recap小结

• The improver may propose, test and keep a version, but never switch it on.
• A person reads the scores and the edit, then decides.
• Every switch is logged with the handler's name, so it can be undone.

• 改进者可以提议、测试并保留版本，但不能自己启用。
• 由人看分数和修改，再决定。
• 每次切换都记下理赔员的名字，随时可以撤回。

Takeaways要点回顾

• Keep instructions, model and effort as one configuration, in numbered versions that are never edited.
• Record what changed, why, who proposed it and who approved it.
• The improver proposes one change at a time and never sees the held-out claims.
• A person approves; rejecting changes nothing.
• Code, not the improver, decides keep or roll back on held-out claims.
• A recipe edit is also a proposal, and code refuses one that drops the words “wait for a person”.
• One round at a time, with a page where anyone can see every version.

• 把指令、模型和力度放进同一份配置，存成带编号、从不修改的版本。
• 记下改了什么、为什么、谁提议、谁批准。
• 改进者一次只提一个改动，并且看不到留出的理赔。
• 由人批准；拒绝不会改变任何东西。
• 留下还是回滚，由代码根据留出理赔的成绩来定，不由改进者定。
• 改配方也是一个提议，代码会拒绝不含“等人批准”字样的配方。
• 一次只开一轮，并有一个页面让任何人都能看到每个版本。
