The story故事

The pilot at Kaya Travel Cover works, and Mr Goh asks the question Mei Ling expected: “Why that model?” She has no good answer yet. A frontier model is one of the biggest, most capable models from the leading labs, rented over the internet. There are several, and she has only tried one. So she lines them up and gives each the same 25 claims, the same prompt and the same marking, then writes down what each is right about and what it costs.

Kaya Travel Cover 的试点跑通了，Goh 先生问了 Mei Ling 早就料到的问题：“为什么是这个模型？”她还答不上来。前沿模型就是主流实验室出的最大、最强的那批模型，通过网络租用。有好几个，而她只试过一个。于是她把它们排成一排，给每个同样的 25 份理赔、同样的提示词、同样的评分，再记下各自对在哪、花了多少钱。

Step 1 · Same claims, same prompt, same marking第 1 步 · 同样的理赔、提示词和评分

Learn先学

A comparison is only fair if one thing changes: the model. Everything else is fixed, like a taste test where every cup comes from the same pot of water. So write the prompt once, as a function of the claim, and give every model exactly that. Put this in a file called bench.py, next to the data files from the pilot. The next lessons add to it.

只有一样东西在变，比较才公平：模型。其余都固定，就像盲测咖啡，每一杯都用同一壶水。所以把提示词写成一个以理赔为输入的函数，每个模型拿到的都一模一样。把它放进一个叫 bench.py 的文件，和试点里的数据文件放在一起。后面几课会往里加东西。

# bench.py import json claims = json.load(open("data/claims.json")) # the 25 invented claims POLICIES = json.load(open("data/policies.json")) WORDING = open("data/policy_wording.txt").read() def build_prompt(claim): policy = POLICIES[claim["policy_id"]] return f"""You help a travel insurer's claims desk. Policy wording: {WORDING} This customer's policy: {json.dumps(policy)} The claim: {json.dumps(claim)} Reply with JSON only: {{"action": "approve" or "decline" or "refer", "payout": a number in S$, "reason": two or three short sentences}}"""

In this comparison, which things stay the same for every model, and which are allowed to differ?

在这次比较里，哪些东西对每个模型都不变，哪些允许不同？

Step 2 · One gateway, many models第 2 步 · 一个网关，多个模型

Learn先学

Every lab has its own sign-up, key and bill. A gateway is one service that sits in front of many labs: one key, one bill, and one way to call them all. Many gateways copy how OpenAI’s Python library is called (openai), so the code barely changes. Here the gateway is OpenRouter (others exist). Run pip install openai and set GATEWAY_API_KEY to the secret key the gateway gives you when you sign up. This new decide(model, claim) replaces Lesson 3’s decide(claim): it takes the model name too, calls the gateway instead of OpenAI(), and also hands back the token counts, which Step 4 needs.

每家实验室都有自己的注册、密钥和账单。网关是站在许多实验室前面的一个服务：一把密钥、一张账单、一种调用方式。很多网关照搬 OpenAI 的 Python 库的调用方式，所以代码几乎不用改。这里的网关是 OpenRouter（也有别的）。运行 pip install openai，并把 GATEWAY_API_KEY 设为注册网关时拿到的密钥。这个新的 decide(model, claim) 替代第 3 课的 decide(claim)：多了模型名这个输入，调用的是网关而不是 OpenAI()，还会把 token 数一起返回，第 4 步要用。

# bench.py, continued import os from openai import OpenAI gateway = OpenAI(base_url="https://openrouter.ai/api/v1", api_key=os.environ["GATEWAY_API_KEY"]) # check the exact names on your gateway's model list MODELS = ["openai/gpt-5.4-mini", "anthropic/claude-haiku-5-5", "anthropic/claude-sonnet-5-5"] def decide(model, claim): reply = gateway.chat.completions.create( model=model, messages=[{"role": "user", "content": build_prompt(claim)}]) text = reply.choices[0].message.content # keep only the {...} part, in case a model adds chatter around it decision = json.loads(text[text.index("{"): text.rindex("}") + 1]) return decision, reply.usage.prompt_tokens, reply.usage.completion_tokens def run_model(model): return {c["id"]: decide(model, c) for c in claims}

Step 3 · Score it, and split by difficulty第 3 步 · 打分，并按难度拆开

Learn先学

A claim is right when the action matches the handler’s and the payout is within S$1. Add a difficulty (easy, medium or tricky) to each answer in the answer key, so you can score each group on its own. One overall number hides where a model is weak. Then read the wrong ones line by line: the reasons often show whether the model misread the wording or the claim.

动作和理赔员一致，并且赔付金额相差不超过 S$1，才算对。给答案里的每一条加上 difficulty（easy 简单、medium 中等、tricky 刁钻），就能分组打分。只看一个总数，会藏住模型弱在哪里。然后逐条读错的那些：理由常常能看出模型是看错了条款，还是看错了理赔。

# bench.py, continued from collections import defaultdict # {"C007": {"action": "approve", "payout": 420, "difficulty": "easy"}, ...} key = json.load(open("answer_key/handler_decisions.json")) # only scoring reads this (the job score.py did in Lesson 3) def matches(decision, want): return (decision["action"] == want["action"] and abs(float(decision["payout"]) - want["payout"]) <= 1) def score(run): tally = defaultdict(lambda: [0, 0]) # difficulty -> [right, total] for cid, (decision, _, _) in run.items(): want = key[cid] right = matches(decision, want) tally[want["difficulty"]][0] += right tally[want["difficulty"]][1] += 1 if not right: print(cid, decision["action"], "vs", want["action"], "|", decision["reason"]) return dict(tally)

Step 4 · Put the cost beside the score第 4 步 · 把成本放在分数旁边

Learn先学

Models read and write in tokens, small pieces of text of about four letters. You pay per million tokens, with one price for what goes in and a higher one for what comes out. Multiply the token counts by the prices and you get the cost of the run. Work it out per 1,000 claims, because that is a number Mr Goh can picture. Prices are in US dollars, since that is how the labs bill. Payouts stay in S$, since that is what the insurer pays.

模型读写的单位是 token，一小段文字，大约四个字母。按每百万 token 收费，输入一个价，输出一个更高的价。把 token 数乘上价格，就得到这一轮的成本。算成每 1,000 份理赔，因为这个数 Goh 先生想象得出来。价格用美元，因为各家实验室按美元收费；赔付仍用新元，因为保险公司付的是新元。

# bench.py, continued # US$ per million tokens: (input, output). Invented numbers: copy your gateway's real list. PRICE = { "openai/gpt-5.4-mini": (0.40, 1.60), "anthropic/claude-haiku-5-5": (1.00, 5.00), "anthropic/claude-sonnet-5-5": (3.00, 15.00)} def cost_per_1000(model, run): price_in, price_out = PRICE[model] total = sum(tin * price_in + tout * price_out for _, tin, tout in run.values()) / 1_000_000 return total / len(run) * 1000

Step 5 · Run twice before you believe a gap第 5 步 · 先跑两遍，再信差距

Learn先学

Ask a model the same question twice and the answers can differ a little. So a one-claim gap between two models can be luck, like two runners whose order flips when you time them twice. Run every model at least twice. Only trust a gap that is bigger than how much one model moves against itself.

同一个问题问模型两遍，答案可能略有不同。所以两个模型差一份理赔，可能只是运气，就像两个跑者，计时两次结果会互换。每个模型至少跑两遍，只信比“自己和自己的波动”更大的差距。

runs = {m: [run_model(m), run_model(m)] for m in MODELS} for model, two in runs.items(): rights = [sum(right for right, _ in score(run).values()) for run in two] print(model, "right per run:", rights, f"US${cost_per_1000(model, two[0]):.2f} per 1,000 claims")

Expected output (an example: your numbers and wording will differ)

预期输出 （示例：你的数字和措辞会不同）

openai/gpt-5.4-mini right per run: [19, 19] US$0.85 per 1,000 claims anthropic/claude-haiku-5-5 right per run: [20, 20] US$1.90 per 1,000 claims anthropic/claude-sonnet-5-5 right per run: [22, 21] US$5.70 per 1,000 claims

Each model was run twice on 25 claims. Is each gap real, or just noise?

每个模型在 25 份理赔上跑了两遍。每个差距是真的，还是只是噪声？

What I got wrong我当时想错了I compared models on a single run and told myself one model was “better” because it got one more claim right. Run again and the order flipped. Models vary from run to run, so now I run each twice and only trust gaps bigger than the noise.我只跑了一遍就下结论，说某个模型“更好”，因为它多对了一份理赔。再跑一遍，顺序就倒过来了。模型每次跑都会有波动，所以现在我每个都跑两遍，只信比噪声更大的差距。

Common errors常见错误

KeyError: 'GATEWAY_API_KEY'
Cause: the environment variable is not set in this terminal. Fix: export it first, or put it in your .env file and load that.

KeyError: 'GATEWAY_API_KEY'
原因：这个终端里没设这个环境变量。解决：先 export，或者写进 .env 文件再加载。

openai.NotFoundError: Error code: 404 - model not found
Cause: the model name is spelled differently from the gateway's list. Fix: copy the exact name from the gateway's model page.

openai.NotFoundError: Error code: 404 - model not found
原因：模型名称和网关列表里的写法不一样。解决：从网关的模型页面复制准确的名字。

openai.RateLimitError: Error code: 429
Cause: too many requests in a short time. Fix: wait a few seconds and retry, or run the claims one after another instead of all at once.

openai.RateLimitError: Error code: 429
原因：短时间内请求太多。解决：等几秒再试，或者让理赔一份接一份地跑。

Takeaways要点回顾

• Same task, same data, same scoring for every model: only the model changes.
• A gateway lets one script call many models by changing just the name.
• Report accuracy by difficulty, not one number.
• Bigger models usually win on tricky claims. On easy ones the gap is often small.
• Show cost beside accuracy: the best model can cost many times more per claim.
• Work out the cost from token counts, per 1,000 claims.
• Run twice before believing a small gap.

• 同样的任务、数据和评分，每个模型都一样：只有模型在变。
• 有了网关，一个脚本只改名字就能调用许多模型。
• 按难度汇报准确率，而不是只给一个数。
• 大模型通常在刁钻理赔上赢；简单理赔上差距往往很小。
• 把成本放在准确率旁边：最强的模型每份理赔可能贵好多倍。
• 用 token 数算成本，按每 1,000 份理赔来算。
• 差距很小时，先跑两遍再相信。
