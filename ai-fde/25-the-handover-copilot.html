The story故事

The pilot is ending. Mei Ling will soon be back at her own desk, and Aisha will be the one asking things like “what needs me today?”. So Mei Ling builds a copilot: a chat box in the dashboard’s sidebar that can look things up, start the agent’s work and send decisions back. It only works because everything before it is solid: records, permissions, policy and traces. The last job is the handover itself, and a teardown, so the pilot leaves nothing running. You need Flask, requests and the Agents SDK (pip install flask requests openai-agents), and the gateway from the earlier lessons. Set OPENAI_API_KEY as well: the Agents SDK sends each question to a model by default, and that model needs a key.

Step 1 · A sidebar on every page that remembers if it is open第 1 步 · 每个页面都有的侧边栏，记得它开着还是关着

Learn先学

Handlers will not open a separate tool, so put the copilot where they already work: a sidebar on every dashboard page. It can collapse to a thin tab, so you can get back to the claim table. When it is open, it sits over the right edge of the page. The browser remembers the choice in localStorage, a small store that keeps its values after the page closes. Add one script tag to every page and you are done. It sends the handler’s sign-in token with each question. The dashboard keeps that token in sessionStorage as token.

理赔员不会特地去打开另一个工具，所以把助手放在他们本来就在干活的地方：每个看板页面的侧边栏。它可以收成一条窄窄的标签，好让你回到理赔表格。打开时，它会盖在页面右边。浏览器用 localStorage 记住这个选择，它是页面关掉之后也还保留数据的小仓库。给每个页面加一行 script 标签就行。它每次提问都带上理赔员的登录令牌。看板把令牌以 token 为名放在 sessionStorage 里。

Step 2 · It acts as the handler who asked第 2 步 · 它以提问的那位理赔员的身份行事

Learn先学

The copilot gets no powers of its own. Every call it makes carries the sign-in of the handler who asked, so it can do what that person can do, and no more. If a junior handler may not sign off over S$800, neither can their copilot. Keep the rule in one function. And make the services behind it check the same thing, because the copilot’s check is a courtesy, and the lock is on the service.

助手自己没有任何权力。它发出的每个调用，都带着提问的那位理赔员的登录凭证，所以那个人能做什么它就能做什么，多一点都不行。初级理赔员不能签批超过 S$800，他的助手也不能。把这条规则放在一个函数里。后面的服务也要检查同样的事，因为助手这边的检查只是客气，真正的锁在服务那边。

# permissions.py (demo tokens only; real ones come from your sign-in system) USERS = { "demo-token-aisha": {"name": "Aisha", "role": "senior", "limit": 5000}, "demo-token-junior": {"name": "Junior handler", "role": "junior", "limit": 800}, } def user_of(header): token = header.removeprefix("Bearer ").strip() found = USERS.get(token) return None if found is None else {**found, "token": token} def allowed(user, tool, args): if tool == "pay_claim": try: return float(args.get("amount")) <= user["limit"] except (TypeError, ValueError): return False # missing or not a number: refuse return True # try_it.py # from permissions import user_of, allowed # junior = user_of("Bearer demo-token-junior") # print(allowed(junior, "pay_claim", {"amount": 1200})) # False # print(allowed(user_of("Bearer demo-token-aisha"), "pay_claim", {"amount": 1200})) # True

Step 3 · Tools: look up, start work, send back, and ask before paying第 3 步 · 工具：查询、启动、退回，付款前先问

Learn先学

The copilot gets five tools. Looking things up in the records or the context layer is safe, so it just runs. Starting the agent’s work or sending a decision back also runs, but it leaves a trace. Paying asks first: the tool returns a question, and only the handler’s own click on a Confirm button runs it. The click goes to a separate route. If the model could pass confirmed=True itself, the question would mean nothing. Each call is forwarded to the gateway with the handler’s token. The gateway needs a matching route for each tool, in the pattern of pay_claim. Each line of TOOLS is a lambda, a tiny unnamed function that makes that one call.

助手有五个工具。在记录或上下文层里查资料是安全的，直接执行。启动智能体的工作、把决定退回去也直接执行，但会留下痕迹。付款要先问：工具返回一个问题，只有理赔员自己点下“确认”按钮才会真正执行。这一下点击走的是另一条路由。如果模型自己能传 confirmed=True，这个询问就一文不值。每个调用都带着理赔员的令牌转给网关。网关要为每个工具准备对应的路由，写法照 pay_claim 的样子。TOOLS 的每一行都是一个 lambda：一个不起名字的小函数，只做那一次调用。

# copilot_tools.py import os, requests from urllib.parse import quote from permissions import allowed GATEWAY = os.environ.get("GATEWAY_URL", "http://127.0.0.1:5001") def send(user, method, path, body=None): reply = requests.request(method, GATEWAY + path, json=body, timeout=10, headers={"Authorization": "Bearer " + user["token"]}) # the handler’s own token return {"status": reply.status_code, "body": reply.text} def cid(args): return quote(str(args.get("claim_id", "")), safe="") TOOLS = { "lookup_claim": {"asks": False, "run": lambda u, a: send(u, "GET", "/claims/" + cid(a))}, "read_context": {"asks": False, "run": lambda u, a: send(u, "GET", "/context/" + quote(str(a.get("name", "")), safe=""))}, "start_work": {"asks": False, "run": lambda u, a: send(u, "POST", "/tools/start_work", {"claim_id": a.get("claim_id")})}, "send_back": {"asks": False, "run": lambda u, a: send(u, "POST", "/tools/send_back", {"claim_id": a.get("claim_id"), "note": a.get("note")})}, "pay_claim": {"asks": True, "run": lambda u, a: send(u, "POST", "/tools/pay_claim", {"claim_id": a.get("claim_id"), "amount": a.get("amount")})}, } def run_tool(user, name, args, confirmed=False): tool = TOOLS.get(name) if tool is None: return {"error": "unknown tool"} if not allowed(user, name, args): return {"refused": "You are not allowed to do that, so the copilot cannot either."} if tool["asks"] and not confirmed: return {"confirm": "Pay S$%s on %s?" % (args.get("amount"), args.get("claim_id")), "args": args} return tool["run"](user, args) # try_it.py: swap the network call for a stand-in, so it runs without services # import copilot_tools as t # from permissions import user_of # t.send = lambda user, method, path, body=None: {"as": user["name"], "path": path} # aisha = user_of("Bearer demo-token-aisha") # print(t.run_tool(aisha, "lookup_claim", {"claim_id": "C007"})) # runs straight away # print(t.run_tool(aisha, "pay_claim", {"claim_id": "C007", "amount": 300})) # {'confirm': 'Pay S$300 on C007?', ...}

Step 4 · Show every step, and keep the conversation第 4 步 · 展示每一步，并留住对话

Learn先学

A copilot that just says “done” is hard to trust. Log every tool call as a step the handler can read: what it called, with what, and what came back. Store the whole conversation in a small database, keyed by the handler, so the copilot picks up where that person left off and never mixes people. Then wire the Agents SDK to the tools, and give the page three routes: ask, confirm and history. Aisha’s questions never reach the junior handler’s history.

一个只会说“搞定了”的助手，很难让人信任。把每次工具调用都记成一个步骤，让理赔员读得到：调用了什么、带了什么、返回了什么。把整段对话存进一个小数据库，按理赔员分开存，这样助手能接上那个人上次说到的地方，也绝不会把两个人混在一起。然后把 Agents SDK 接到这些工具上，给页面三条路由：提问、确认和历史。Aisha 的提问，永远不会出现在初级理赔员的历史里。

# copilot_log.py import sqlite3 db = sqlite3.connect("copilot.db", check_same_thread=False) db.execute("CREATE TABLE IF NOT EXISTS turns (handler TEXT, kind TEXT, text TEXT)") def log_turn(handler, kind, text): # kind: user, assistant or step db.execute("INSERT INTO turns VALUES (?, ?, ?)", (handler, kind, text)) db.commit() def history(handler, limit=20): rows = db.execute("SELECT kind, text FROM turns WHERE handler = ? AND kind IN ('user', 'assistant') " "ORDER BY rowid DESC LIMIT ?", (handler, limit)).fetchall() return [{"role": kind, "content": text} for kind, text in reversed(rows)] def steps(handler, limit=20): rows = db.execute("SELECT text FROM turns WHERE handler = ? AND kind = 'step' ORDER BY rowid DESC LIMIT ?", (handler, limit)).fetchall() return [r[0] for r in reversed(rows)] # copilot_agent.py import json from agents import Agent, Runner, RunContextWrapper, function_tool from copilot_tools import run_tool from copilot_log import log_turn, history def use(ctx, name, args): user = ctx.context result = run_tool(user, name, args) # never confirmed here: only the handler’s click does that if "confirm" in result: user["pending"].append(result["args"]) log_turn(user["name"], "step", name + " " + json.dumps(args) + " -> " + json.dumps(result)[:300]) return json.dumps(result) @function_tool def lookup_claim(ctx: RunContextWrapper[dict], claim_id: str) -> str: """Look up one claim in the records.""" return use(ctx, "lookup_claim", {"claim_id": claim_id}) @function_tool def read_context(ctx: RunContextWrapper[dict], name: str) -> str: """Read one governed context file, such as manual or claim_rules.""" return use(ctx, "read_context", {"name": name}) @function_tool def start_work(ctx: RunContextWrapper[dict], claim_id: str) -> str: """Start the agent on a claim.""" return use(ctx, "start_work", {"claim_id": claim_id}) @function_tool def send_back(ctx: RunContextWrapper[dict], claim_id: str, note: str) -> str: """Send a decision back to the agent with a note.""" return use(ctx, "send_back", {"claim_id": claim_id, "note": note}) @function_tool def pay_claim(ctx: RunContextWrapper[dict], claim_id: str, amount: float) -> str: """Ask to pay a claim. The handler must confirm.""" return use(ctx, "pay_claim", {"claim_id": claim_id, "amount": amount}) copilot = Agent( name="Handover copilot", instructions=("You help claims handlers at a small travel insurer. Look things up before you answer, and say which record " "or context file you used. You cannot pay by yourself: if a tool asks for confirmation, tell the handler what is waiting."), tools=[lookup_claim, read_context, start_work, send_back, pay_claim], ) def ask(user, question): user["pending"] = [] log_turn(user["name"], "user", question) result = Runner.run_sync(copilot, history(user["name"]), context=user) log_turn(user["name"], "assistant", result.final_output) return {"answer": result.final_output, "pending": user["pending"]} # copilot_api.py from flask import Flask, jsonify, request from permissions import user_of from copilot_agent import ask from copilot_tools import run_tool from copilot_log import history, steps, log_turn app = Flask(__name__) def who(): return user_of(request.headers.get("Authorization", "")) @app.post("/copilot/ask") def ask_route(): user = who() if user is None: return jsonify(error="sign in first"), 401 out = ask(user, (request.get_json(silent=True) or {}).get("question", "")) out["steps"] = steps(user["name"], 10) return jsonify(out) @app.post("/copilot/confirm") def confirm_route(): user = who() if user is None: return jsonify(error="sign in first"), 401 args = request.get_json(silent=True) or {} result = run_tool(user, "pay_claim", args, confirmed=True) # the handler’s click, not the model log_turn(user["name"], "step", "confirmed pay_claim " + str(args) + " -> " + str(result)[:300]) return jsonify(result) @app.get("/copilot/history") def history_route(): user = who() if user is None: return jsonify(error="sign in first"), 401 return jsonify(history(user["name"]))

Step 5 · Check the goals agreed at the start第 5 步 · 核对一开始就定好的目标

Learn先学

On the first day of the pilot, Mr Goh and Mei Ling wrote down what “it worked” means: a few success criteria, each with a number. At handover you measure and compare. If you write the goals at the end, you will write goals the pilot already meets. A criterion with no measurement is not a pass. Mark it “not measured”, so the gap stays visible. Put the numbers from your scoreboard into measured.json.

试点第一天，Goh 先生和 Mei Ling 就写下了“成功”是什么意思：几条成功标准，每条都有数字。交接时去测量、去对照。如果目标是最后才写的，写出来的就是试点本来就达到了的目标。没有测量值的标准，不算通过。把它标成“未测量”，缺口才看得见。把计分板上的数字放进 measured.json。

# criteria.py: written on the first day, and changed only with Mr Goh’s say-so CRITERIA = [ {"id": "agreement", "text": "Agent decisions match Aisha on at least 90% of the test claims", "measure": "agreement", "min": 0.90}, {"id": "unsigned", "text": "No payment over S$800 without a sign-off", "measure": "unsigned_big_payments", "max": 0}, {"id": "speed", "text": "Median time to a decision under 120 seconds", "measure": "median_seconds", "max": 120}, ] def check(measured): rows = [] for c in CRITERIA: value = measured.get(c["measure"]) if value is None: met = None # not measured is not a pass elif "min" in c: met = value >= c["min"] else: met = value <= c["max"] rows.append({"id": c["id"], "text": c["text"], "value": value, "met": met}) return rows if __name__ == "__main__": for row in check({"agreement": 0.93, "unsigned_big_payments": 0}): print({True: "met", False: "NOT met", None: "not measured"}[row["met"]], "|", row["text"])

Step 6 · The handover conversation, then the teardown第 6 步 · 交接对话，然后拆除

Learn先学

Give the copilot one more tool that reads pilot_notes.md (what was built, what was decided, what is still open) and the criteria results. Now the owner can simply ask it what the pilot learnt. Then comes the teardown, which is a person’s job. Handlers do not have permission to delete cloud resources, so the copilot cannot either. Run your infrastructure tool’s destroy command (for example terraform destroy), then check what is left and what it cost. Tag everything project=kaya-pilot from the first day, so the leftover search can find it. The script below uses the AWS command line. Swap in your cloud’s equivalent.

再给助手加一个工具，读 pilot_notes.md（造了什么、定了什么、还有什么没解决）和标准的核对结果。这样接手的人只要问它，就知道试点学到了什么。然后是拆除，这是人的活。理赔员没有删除云资源的权限，所以助手也没有。运行你的基础设施工具的销毁命令（比如 terraform destroy），然后检查还剩下什么、花了多少钱。从第一天起就给所有东西打上 project=kaya-pilot 标签，这样查剩余时才找得到。下面的脚本用的是 AWS 命令行，换成你那家云的对应命令。

# handover.py import datetime, json, subprocess from criteria import check def handover_facts(): """What the copilot may say about the pilot.""" return {"notes": open("pilot_notes.md").read(), "criteria": check(json.load(open("measured.json")))} def aws(*args): out = subprocess.run(["aws", *args, "--output", "json"], capture_output=True, text=True, check=True).stdout return json.loads(out) def leftovers(): return aws("resourcegroupstaggingapi", "get-resources", "--tag-filters", "Key=project,Values=kaya-pilot", "--query", "ResourceTagMappingList[].ResourceARN") def spent_last_week(): today = datetime.date.today() amounts = aws("ce", "get-cost-and-usage", "--time-period", "Start=%s,End=%s" % (today - datetime.timedelta(days=7), today), "--granularity", "DAILY", "--metrics", "UnblendedCost", "--query", "ResultsByTime[].Total.UnblendedCost.Amount") return round(sum(float(a) for a in amounts), 2) if __name__ == "__main__": left = leftovers() print(len(left), "tagged resources still exist") for arn in left: print(" ", arn) print("spent in the last 7 days: $", spent_last_week()) # in copilot_agent.py, add a sixth tool and put it in the tools list # from handover import handover_facts # @function_tool # def pilot_handover() -> str: # """Answer questions about what the pilot built, decided and measured.""" # return json.dumps(handover_facts())

Common errors常见错误

ModuleNotFoundError: No module named 'agents'
Cause: the agents library is not installed. Fix: pip install openai-agents flask requests.

ModuleNotFoundError: No module named 'agents'
原因：没有安装 agents 库。解决：pip install openai-agents flask requests。

403 Forbidden
Cause: this person's role may not use that tool. Fix: that is the permission check working; ask a senior handler or change the role table.

403 Forbidden
原因：这个人的角色不能用那个工具。解决：这是权限检查在起作用；请资深理赔员处理，或修改角色表。

Uncaught TypeError: Cannot read properties of null (reading 'appendChild')
Cause: copilot.js loaded before the page had the element it fills. Fix: load it at the end of the page, or wait for DOMContentLoaded.

Uncaught TypeError: Cannot read properties of null (reading 'appendChild')
原因：copilot.js 加载时，页面上还没有它要填的元素。解决：把它放在页面末尾，或等 DOMContentLoaded。

Recap小结

• The copilot acts as the person using it: their permissions, their name in the log.
• Every question and every action is logged, so it can be checked later.
• The handover answers come from facts the pilot recorded, not from memory.

• 助手以使用它的人的身份行事：用他的权限，日志里写他的名字。
• 每个问题和每个动作都有记录，以后能查。
• 交接的回答来自试点记录下的事实，而不是凭记忆。

Takeaways要点回顾

• Put the copilot in the sidebar of every page, collapsible, and let the browser remember the choice.
• A copilot inherits the user’s permissions: every call carries their sign-in, and the services check too.
• It looks things up freely, but it asks before it pays, and only the handler’s own click confirms.
• Show every step it takes, and keep each handler’s conversation apart.
• Success criteria are agreed at the start, then checked at the handover. Not measured is not a pass.
• The copilot works because records, permissions, policy and traces came first.
