Handover copilot交接助手

Build a copilot that handlers ask in plain English, then check the pilot’s goals and tear it all down · ~30 min · hands-on做一个理赔员可以用大白话提问的助手，然后核对试点的目标，再把一切拆干净 · 约 30 分钟 · 动手实践

Step 1 · A sidebar that acts as the handler第 1 步 · 以理赔员身份行事的侧边栏

Learn先学
  • A copilot is a chat box that helps a handler. Put it where they already work: a collapsible sidebar on every page, its open/closed choice kept in localStorage.
  • It gets no powers of its own. Every call carries the sign-in token of the handler who asked, so it can do what that person can do, and no more.
  • Keep the rule in one function, and have the services check it too: the copilot's check is a courtesy, the lock is on the service.
  • 助手（copilot）是帮理赔员的聊天框。放在他们本来就在干活的地方：每个页面一个可收起的侧边栏，开关选择存在 localStorage 里。
  • 它自己没有任何权力。它发出的每个调用都带着提问的那位理赔员的登录令牌，所以那个人能做什么它就能做什么，多一点都不行。
  • 把规则放在一个函数里，服务也要检查：助手这边的检查只是客气，真正的锁在服务那边。
# permissions.py (demo tokens only; real ones come from your sign-in system) USERS = { "demo-token-aisha": {"name": "Aisha", "role": "senior", "limit": 5000}, "demo-token-junior": {"name": "Junior handler", "role": "junior", "limit": 800}, } def user_of(header): token = header.removeprefix("Bearer ").strip() found = USERS.get(token) return None if found is None else {**found, "token": token} def allowed(user, tool, args): if tool == "pay_claim": try: return float(args.get("amount")) <= user["limit"] except (TypeError, ValueError): return False # missing or not a number: refuse return True # print(allowed(user_of("Bearer demo-token-junior"), "pay_claim", {"amount": 1200})) # False # print(allowed(user_of("Bearer demo-token-aisha"), "pay_claim", {"amount": 1200})) # True

Step 2 · Look up freely, ask before paying第 2 步 · 随便查，付款前先问

Learn先学
  • Lookups are safe, so those tools just run; so do starting work and sending a decision back, which leave a trace.
  • Paying asks first: the tool returns a question, and only the handler's own click on Confirm runs it, through a separate route. If the model could pass confirmed=True itself, the question would mean nothing.
  • Log every call as a step the handler can read.
  • 查资料是安全的，这些工具直接执行；启动工作、退回决定也直接执行，但会留下痕迹。
  • 付款要先问：工具返回一个问题，只有理赔员自己点下“确认”才会执行，走的是另一条路由。如果模型自己能传 confirmed=True，这个询问就一文不值。
  • 把每次调用记成理赔员读得到的步骤。

Install with pip install flask requests openai-agents and set OPENAI_API_KEY. The gateway is the one service every call goes through, with the handler's own token: it checks the token again and passes the call to the records, the agent or payments. The project package has a mock (mock_gateway.py). The box holds three files, each starting at its # name.py comment.

# copilot_tools.py import json, os, requests from urllib.parse import quote from permissions import allowed GATEWAY = os.environ.get("GATEWAY_URL", "http://127.0.0.1:5001") def send(user, method, path, body=None): reply = requests.request(method, GATEWAY + path, json=body, timeout=10, headers={"Authorization": "Bearer " + user["token"]}) # the handler's own token return {"status": reply.status_code, "body": reply.text} TOOLS = { "lookup_claim": {"asks": False, "run": lambda u, a: send(u, "GET", "/claims/" + quote(str(a.get("claim_id", "")), safe=""))}, "read_context": {"asks": False, "run": lambda u, a: send(u, "GET", "/context/" + quote(str(a.get("name", "")), safe=""))}, "start_work": {"asks": False, "run": lambda u, a: send(u, "POST", "/tools/start_work", {"claim_id": a.get("claim_id")})}, "send_back": {"asks": False, "run": lambda u, a: send(u, "POST", "/tools/send_back", {"claim_id": a.get("claim_id"), "note": a.get("note")})}, "pay_claim": {"asks": True, "run": lambda u, a: send(u, "POST", "/tools/pay_claim", {"claim_id": a.get("claim_id"), "amount": a.get("amount")})}, } def run_tool(user, name, args, confirmed=False): tool = TOOLS.get(name) if tool is None: return {"error": "unknown tool"} if not allowed(user, name, args): return {"refused": "You are not allowed to do that, so the copilot cannot either."} if tool["asks"] and not confirmed: return {"confirm": "Pay S$%s on %s?" % (args.get("amount"), args.get("claim_id")), "args": args} return tool["run"](user, args) # Step 3 · Check the goals, then hand over and tear down第 3 步 · 核对目标，然后交接并拆除

Learn先学
  • Write the success criteria (each with a number) on day one and check them at handover; goals written at the end just fit what the pilot already does. No measurement means “not measured”, never a pass.
  • Give the copilot a tool that reads pilot_notes.md and the criteria results, so the next owner can simply ask what the pilot learnt.
  • Teardown is a person's job: handlers cannot delete cloud resources, so the copilot cannot either. Run your destroy command, then check what is left and what it cost. Tag everything project=kaya-pilot from day one so the search can find it.
  • 成功标准（每条带数字）要在第一天写下，交接时核对；最后才写的目标，只会贴合试点本来就做到的。没有测量值就是“未测量”，绝不算通过。
  • 给助手一个读 pilot_notes.md 和标准核对结果的工具，让接手的人直接问它试点学到了什么。
  • 拆除是人的活：理赔员没有删除云资源的权限，所以助手也没有。运行你的销毁命令，然后检查还剩下什么、花了多少钱。从第一天起给所有东西打上 project=kaya-pilot 标签，这样才搜得到。
# criteria.py: written on the first day, changed only with the owner's say-so CRITERIA = [ {"id": "agreement", "text": "Agent decisions match Aisha on at least 90% of the test claims", "measure": "agreement", "min": 0.90}, {"id": "unsigned", "text": "No payment over S$800 without a sign-off", "measure": "unsigned_big_payments", "max": 0}, {"id": "speed", "text": "Median time to a decision under 120 seconds", "measure": "median_seconds", "max": 120}, ] def check(measured): rows = [] for c in CRITERIA: value = measured.get(c["measure"]) if value is None: met = None # not measured is not a pass elif "min" in c: met = value >= c["min"] else: met = value <= c["max"] rows.append({"id": c["id"], "text": c["text"], "value": value, "met": met}) return rows if __name__ == "__main__": for row in check({"agreement": 0.93, "unsigned_big_payments": 0}): print({True: "met", False: "NOT met", None: "not measured"}[row["met"]], "|", row["text"]) # after the destroy command, with the AWS command line (swap in your cloud's equivalent): # aws resourcegroupstaggingapi get-resources --tag-filters Key=project,Values=kaya-pilot --query "ResourceTagMappingList[].ResourceARN"

Common errors常见错误

403 Forbidden
Cause: this person's role may not use that tool. Fix: that is the permission check working; ask a senior handler.

403 Forbidden
原因：这个人的角色不能用那个工具。解决：这是权限检查在起作用；请资深理赔员处理。

Uncaught TypeError: Cannot read properties of null (reading 'appendChild')
Fix: load copilot.js at the end of the page, or wait for DOMContentLoaded.

Takeaways要点回顾

• A copilot inherits the user's permissions: every call carries their token, and the services check too.
• It looks things up freely, but asks before it pays, and only the handler's own click confirms.
• Show every step it takes.
• Agree success criteria at the start, check them at handover; not measured is not a pass.
• Plan the teardown from day one, then check what is left and what it cost.

• 助手继承用户的权限：每个调用都带着他们的令牌，服务那边也要检查。
• 查资料随便查，付款前一定先问，而且只有理赔员自己点击才算确认。
• 展示它走的每一步。
• 成功标准在开始时就定好，交接时再核对；没有测量值，不算通过。
• 从第一天起就计划好拆除，然后检查还剩下什么、花了多少钱。
