Plan first, then build with a coding agent先做计划，再让编程智能体来建

Where we left off上回讲到

Last time Mei Ling wrote the claims job in one paragraph after an afternoon beside Aisha. Today a coding agent could build the wrong pilot, because it forgets everything between sessions. We fix it by putting the brief, a standing instruction and a plan into plain files first.

上回 Mei Ling 在 Aisha 身边坐了一个下午，把理赔的工作写成了一段话。今天的麻烦是：编程智能体每次开工都会忘光，可能建出一个错的试点。我们的办法是先把需求、固定指令和计划写进普通文件。

The story故事

Mei Ling, the forward-deployed engineer at Kaya Travel Cover, has watched Aisha work the claims queue and written down the job. Now she wants a first pilot, fast. She will not type it all herself: a coding agent (an AI tool that reads and writes code files for you) will build it. But a coding agent is only as good as what it reads first. So she starts with documents, not code.

Kaya Travel Cover 的前线部署工程师 Mei Ling 已经看过 Aisha 处理理赔队列，也写下了这份工作。现在她想尽快做出第一个试点。她不打算全靠自己敲：让一个编程智能体（能替你读写代码文件的 AI 工具）来建。可编程智能体的水平取决于它先读到什么，所以她先从文档下手，而不是代码。

Step 1 · Put the brief in plain documents第 1 步 · 把需求写成朴素的文档

Learn先学

A chat message gets forgotten. A folder of files does not. Mei Ling puts everything the agent needs into one folder, one file per question: what the business needs, what to build with, how code should look, how to work, how it should feel, and where things stand. The spec is the file that says what the business needs, in plain words. Think of handing a new colleague a binder instead of talking at them in the corridor.

聊天消息会被忘掉，文件夹里的文件不会。Mei Ling 把智能体需要的一切放进一个文件夹，一个问题一个文件：业务要什么、用什么技术做、代码长什么样、怎么协作、整体观感、现在做到哪了。其中需求文档（spec）用大白话写清业务要什么。就像给新同事一本活页夹，而不是在走廊里对着他说一通。

docs/ spec.md # what the business needs, in the customer's words tech.md # which language, which libraries, where it runs standards.md # how the code should be written and named process.md # how we work: plan, build, check, record brand.md # tone and look, so screens feel like Kaya status.md # what is built so far and how to run it

Match each question to the file that should answer it.

把每个问题配给应该回答它的文件。

Step 2 · One standing instruction: read these first第 2 步 · 一份长期指令：先读这些

Learn先学

Most coding agents read one instruction file at the start of every session (some call it CLAUDE.md). Keep it short, like a sticky note on the fridge that says what to read, not a novel. It lists the documents, in order, and sets one rule: read first, touch nothing until you have. Otherwise the agent starts from guesses.

多数编程智能体每次开工都会先读一份指令文件（有的叫 CLAUDE.md）。把它写得像贴在冰箱上的便利贴，只写要读什么，不要写成长篇小说：按顺序列出文档，再立一条规矩：先读完，读完之前什么都不要动。否则智能体就是凭猜测开工。

Before you change anything, read these in order: 1. docs/spec.md 2. docs/tech.md 3. docs/standards.md 4. docs/process.md 5. docs/brand.md 6. docs/status.md Never build anything the documents do not ask for. When you finish a piece of work, update docs/status.md.

Step 3 · Ask for a plan, not code第 3 步 · 要计划，不要代码

Learn先学

Code is expensive to read and expensive to undo. A plan is a page. So Mei Ling’s first request is only “plan the pilot”. The agent writes a plan document with phases and a reason for each. If it misunderstood the brief, the plan shows it while it is still cheap to fix, like checking a floor plan before the walls go up.

代码读起来贵，推倒重来也贵；计划只有一页。所以 Mei Ling 的第一个请求只是“为试点做计划”。智能体写出一份分阶段、每阶段带理由的计划文档。如果它误解了需求，计划会在改动还很便宜的时候暴露出来，就像墙还没砌就先看户型图。

Plan the pilot. Write docs/plan.md with phases. For each phase say what you will build and why. Do not write any code yet. # what comes back (shortened): Phase 1 Sample claims and a policy wording why: nothing else can be tested without them Phase 2 A queue that tracks each claim why: handlers need to see what is waiting Phase 3 A first agent that decides a claim why: this is the thing Aisha will react to

Step 4 · Review the plan, push back, then build第 4 步 · 审计划、提意见，再动手建

Learn先学

Now Mei Ling reads the plan against the spec, line by line. She pushes back where it drifts: “Phase 3 decides payouts, but the spec says big ones need a handler.” Only when the plan matches the brief does she say “implement the plan”. After each phase she checks the result against the spec before the next one starts.

接着 Mei Ling 对照需求，逐行读这份计划。哪里跑偏就提出来：“第 3 阶段会决定赔付，可需求里写了大额要由理赔员批准。”只有计划和需求对上了，她才说“按计划实施”。每个阶段完成后，她先对照需求检查，再开始下一个。

Which reply to the plan is right? Decide for each.

对计划的哪种回应是对的？逐个判断。

Step 5 · Keep a short status file第 5 步 · 留一份简短的状态文件

Learn先学

A coding agent forgets everything between sessions. A status file is its memory: what is built, how to run it, what is next. Keep it short enough to read in a minute, and the next session starts informed instead of from zero.

编程智能体每次会话之间什么都不记得。状态文件就是它的记忆：做了什么、怎么运行、下一步是什么。保持一分钟能读完的长度，下一次会话就是带着信息开始，而不是从零开始。

# Status Built: sample claims (phase 1), claim queue (phase 2) Not built yet: the agent (phase 3) Run it: python backend.py # an example file name: the queue code from Phase 2 Open question: does a refer (the agent passing a claim to a person) count as waiting for sign-off?
What I got wrong我当时想错了I asked for code straight away on a vague brief and got a tidy dashboard that answered the wrong question. Writing the brief better took ten minutes. Unpicking the build took an hour. With good documents a coding agent can build a working pilot in one sitting; with vague ones it builds something confident and wrong.我在需求含糊的情况下，一上来就让它写代码，结果得到一个漂亮的看板，却在回答错误的问题。把需求写好只花了十分钟，拆掉重来却花了一小时。文档好的话，编程智能体一次就能做出能用的试点；文档含糊，它做出来的东西自信满满却是错的。

Now make it yours现在把它变成你的

What changed这一课之后Now the pilot has a folder with the brief, a standing instruction, a plan Mei Ling checked line by line and a status file the agent reads at the end of its list. The next problem is turning that plan into a running first pilot that Mr Goh (the owner, who signs off payouts) and Aisha (the senior claims handler) can react to.现在试点有了一个文件夹：需求、固定指令、Mei Ling 逐行核对过的计划，还有智能体最后读的进度文件。下一个问题是把计划变成能跑的第一版试点，让 Goh 先生（老板，负责签字赔付）和 Aisha（资深理赔员）有东西可看。

Common errors常见错误

The agent starts writing code before you approved the plan
Cause: the prompt did not say plan only. Fix: stop it, then say again: read the documents first, write only the plan, and write no code until you say so.

The agent starts writing code before you approved the plan
原因：提示里没写“只做计划”。解决：先让它停下，再说一遍：先读文档，只写计划，在你说可以之前不要写代码。

The agent's work ignores your standards (wrong names, wrong style)
Cause: it never read docs/standards.md, or the reading order was not in the prompt. Fix: start every session with the read-first prompt, and ask it to name the three documents it read.

The agent's work ignores your standards (wrong names, wrong style)
原因：它没读 docs/standards.md，或者提示里没写阅读顺序。解决：每次会话都用先读文档的提示，并让它说出读过的三份文档。

The next session does not know what is already built
Cause: docs/status.md was not updated at the end of the last session. Fix: make updating it the last line of your prompt, and check it before you close the session.

The next session does not know what is already built
原因：上一次会话结束时没更新 docs/status.md。解决：把更新它写成提示的最后一句，关闭会话前检查一下。

Takeaways要点回顾

• Documents are the real interface to a coding agent.
• One standing instruction file says what to read first, and in what order.
• Ask for a plan before code. A plan is cheap to change.
• Review the plan against the spec, not just the code afterwards.
• Never let it build ahead of the brief.
• Keep a short status file so the next session starts informed.

• 文档才是你和编程智能体之间真正的接口。
• 一份长期指令文件，写明先读什么、按什么顺序读。
• 先要计划，再要代码；计划改起来很便宜。
• 对照需求审计划，而不是只在事后看代码。
• 绝不让它超出需求去建东西。
• 留一份简短的状态文件，让下一次会话带着信息开始。
