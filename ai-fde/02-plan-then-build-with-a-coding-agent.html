Plan, then build先计划再构建

Give a coding agent good documents, ask for a plan, review it, then let it build: ten minutes of reading saves an hour of unpicking · ~10 min · concept给编程智能体好文档，先要计划，审过再让它动手：花十分钟读计划，能省一小时拆烂摊子 · 约 10 分钟 · 概念课

Step 1 · Put the brief in files第 1 步 · 把需求写进文件

Learn先学
  • A coding agent reads and writes code files for you, and forgets everything between sessions.
  • So give it a folder of files, one per question, plus one short instruction file that says read these first, touch nothing until you have.
  • 编程智能体替你读写代码文件，而且每次会话之间都会忘光。
  • 所以给它一个文件夹，一个问题一个文件，再加一份简短的指令文件：先读这些，读完之前什么都不要动。
docs/ spec.md # what the business needs, in the customer's words tech.md # which language, which libraries, where it runs standards.md # how the code should be written and named status.md # what is built so far and how to run it
Before you change anything, read these in order: docs/spec.md, docs/tech.md, docs/standards.md, docs/status.md Never build anything the documents do not ask for. When you finish a piece of work, update docs/status.md.

Match each question to the file that should answer it.

把每个问题配给应该回答它的文件。

Step 2 · Ask for a plan, not code第 2 步 · 要计划，不要代码

Learn先学

Code is expensive to read and to undo; a plan is one page. If the agent misread the brief, the plan shows it while the fix is still cheap.

代码读起来贵、推倒重来也贵；计划只有一页。如果智能体误解了需求，计划会在改动还很便宜的时候暴露出来。

Plan the pilot. Write docs/plan.md with phases. For each phase say what you will build and why. Do not write any code yet. # what comes back (shortened): Phase 1 Sample claims and a policy wording why: nothing else can be tested without them Phase 2 A queue that tracks each claim why: handlers need to see what is waiting Phase 3 A first agent that decides a claim why: this is the thing handlers will react to

Step 3 · Review the plan, then build第 3 步 · 审计划，再动手建

Learn先学
  • Read the plan against the spec line by line and push back where it drifts.
  • Say “implement the plan” only when it matches the brief, and check each phase before the next.
  • Keep status.md short: the next session starts informed, not from zero.
  • 对照需求逐行读计划，哪里跑偏就提出来。
  • 计划和需求对上了才说“按计划实施”，每个阶段检查完再进入下一个。
  • 让 status.md 保持简短：下一次会话带着信息开始，而不是从零开始。

Which reply to the plan is right? Decide for each.

对计划的哪种回应是对的？逐个判断。

Now make it yours现在把它变成你的

Takeaways要点回顾

• Documents are the real interface to a coding agent.
• One short instruction file says what to read first.
• Ask for a plan before code: a plan is cheap to change.
• Review the plan against the spec, and never let it build ahead of the brief.
• Keep a short status file for the next session.

• 文档才是你和编程智能体之间真正的接口。
• 一份简短的指令文件，写明先读什么。
• 先要计划，再要代码：计划改起来很便宜。
• 对照需求审计划，绝不让它超出需求去建东西。
• 留一份简短的状态文件给下一次会话。
