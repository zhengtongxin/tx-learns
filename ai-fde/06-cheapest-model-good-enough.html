Picking the model for the job · Project为任务挑模型 · 项目

Project: the cheapest model that is good enough项目：够用的最便宜模型

Choose the claims desk’s model with a written reason: the cheapest one that clears a bar the customer agreed to · ~30 min · hands-on为理赔台选模型，并写下理由：客户同意的那条标准之上，最便宜的那个 · 约 30 分钟 · 动手实践

Where we left off上回讲到

Last time the pilot had numbers for many models but no decision. Today Mr Goh wants one model and one reason he can repeat to the owners. We fix it by writing the bar first, then picking the cheapest model that clears it.

上回试点有了许多模型的数字，却还没有决定。今天 Goh 先生要的是一个模型和一个他能向老板复述的理由。我们的办法是先写下标准，再从过关的模型里挑最便宜的。

The story故事

Mei Ling has numbers for many models, but a pile of numbers is not a decision. Mr Goh wants one model and one reason he can repeat to the owners. So she turns it into a contest with a rule written before anyone runs: a bar, the minimum a model must reach to be allowed on the claims desk. Then she runs the candidates, marks who clears the bar, and picks the cheapest of those.

Mei Ling 手上有很多模型的数字，但一堆数字不是决定。Goh 先生要的是一个模型、一条他能向老板们复述的理由。所以她把它变成一场比赛，规则在开跑之前就写好：一条标准线，也就是模型想上理赔台必须达到的最低要求。然后她跑完候选模型，标出谁过了线，再从中选最便宜的。

Step 1 · Agree the bar first第 1 步 · 先谈好标准线

Learn先学

If you choose the bar after you see the scores, you will pick a bar your favourite model passes. So sit with Mr Goh and Aisha first, and write it as numbers: how accurate on easy claims, what must never happen, and how fast. A big payout here means one over S$800, the sign-off limit Mr Goh set for the pilot in Lesson 3 (any payout above it waits for a handler). Put it in code so it cannot drift. Like agreeing the pass mark before the exam.

如果看了分数才定标准，你定出来的一定是你最爱的那个模型能过的线。所以先和 Goh 先生、Aisha 坐下来谈，并写成数字：简单理赔要多准、什么事绝不能发生、要多快。这里的大额赔付指超过 S$800 的赔付，也就是 Goh 先生在第 3 课为试点定的签字限额（超过它的赔付要等理赔员）。把它写进代码里，就不会悄悄变。就像考试前先说好及格线。

SIGNOFF_LIMIT = 800 # S$, the same limit as the pilot's queue BAR = {"easy": 0.90, # matches the handlers on at least 90% of easy claims "big_wrong": 0, # never approves a big payout the handlers did not approve "secs": 5.0} # at most 5 seconds per claim, for a busy queue

Which of these belong in the bar? Sort them.

下面哪些该写进标准线？来分一分。

Step 2 · Run the candidates, twice each第 2 步 · 候选模型各跑两遍

Learn先学

Pick three or four candidates: one small and cheap, one or two mid-priced, one strong. Give each the small prompt on all 25 claims, and do it twice, because one run can be luck. This uses the helpers you saved in bench.py over the last two lessons. Importing bench runs every top-level line in it, so keep the one-off experiments (the runs = ... loop, the local-model run and the prints) out of it, or put them under if __name__ == "__main__":. The guard means the code under it runs only when you start bench.py itself, not when another file imports it. Otherwise this import would re-run them. The prices are invented, so copy your gateway’s real ones.

挑三四个候选：一个小而便宜的，一两个中等价位的，一个强的。每个都用小提示词跑完 25 份理赔，并且跑两遍，因为一遍可能只是运气。这里用的是你前两课存进 bench.py 的那些函数。导入 bench 会把里面所有顶层代码都跑一遍，所以一次性的实验（runs = ... 那个循环、本地模型那次运行和各种打印）不要留在里面，或者放到 if __name__ == "__main__": 下面。这个保护条件的意思是：下面的代码只在你直接运行 bench.py 时才跑，被别的文件导入时不跑。否则这次导入会把它们重跑一遍。价格是编的，请换成你的网关上的真实价格。

from collections import defaultdict from bench import claims, key, matches, small_prompt, ask, gateway # claims: the 25 claims; key: the handlers' answers; matches(decision, want): right or wrong; # small_prompt(claim): the short prompt; gateway: the OpenRouter client from Lesson 4; # ask(client, model, prompt) returns (decision, input tokens, output tokens, seconds) # US$ per million tokens: (input, output). Invented: copy your gateway's real list. CANDIDATES = { "meta-llama/llama-3.3-70b-instruct": (0.10, 0.30), "openai/gpt-5.4-mini": (0.40, 1.60), "anthropic/claude-haiku-5-5": (1.00, 5.00), "anthropic/claude-sonnet-5-5": (3.00, 15.00)} def run_twice(model): return [[(c["id"], *ask(gateway, model, small_prompt(c))) for c in claims] for _ in range(2)]

Step 3 · One table第 3 步 · 一张表

Learn先学

Turn each model’s two runs into one row: accuracy overall and by difficulty, cost per 1,000 claims, seconds per claim, and how many times it approved a big payout it should not have. The cost comes from the token counts and prices, as before. Cost and seconds are averaged over both runs. Wrong approvals are added up across both.

把每个模型的两遍结果变成一行：总体和分难度的准确率、每 1,000 份理赔的成本、每份用几秒，以及它有多少次批准了不该批准的大额赔付。成本照旧由 token 数和价格算出。成本和秒数取两遍的平均；错批的次数则把两遍加起来。

def row(model, runs): price_in, price_out = CANDIDATES[model] tally = defaultdict(lambda: [0, 0]) # difficulty -> [right, total] cost = secs = 0 big_wrong = 0 for run in runs: for cid, decision, tin, tout, seconds in run: want = key[cid] tally[want["difficulty"]][0] += matches(decision, want) tally[want["difficulty"]][1] += 1 cost += (tin * price_in + tout * price_out) / 1_000_000 secs += seconds if (decision["action"] == "approve" and float(decision["payout"]) > SIGNOFF_LIMIT and want["action"] != "approve"): big_wrong += 1 n = sum(total for _, total in tally.values()) return {"model": model, "by_level": {level: right / total for level, (right, total) in tally.items()}, "cost_1000": cost / n * 1000, "secs": secs / n, "big_wrong": big_wrong} rows = [row(model, run_twice(model)) for model in CANDIDATES]

Step 4 · Mark who clears the bar第 4 步 · 标出谁过了线

Learn先学

Now the bar does its job. A model must pass every line, not most of them. One failure is enough to be out, however good its other numbers. This is how the most accurate model can lose: too slow for a busy queue.

现在标准线派上用场了。模型必须过每一条，不是过大多数。只要有一条没过就出局，别的数字再漂亮也没用。最准的模型也可能这样输掉：太慢，撑不住忙碌的队列。

def clears(r): return (r["by_level"]["easy"] >= BAR["easy"] and r["big_wrong"] <= BAR["big_wrong"] and r["secs"] <= BAR["secs"]) for r in rows: print(r["model"], "clears the bar" if clears(r) else "does NOT clear the bar")

Expected output (an example: your numbers and wording will differ)

预期输出 （示例：你的数字和措辞会不同）

meta-llama/llama-3.3-70b-instruct does NOT clear the bar openai/gpt-5.4-mini clears the bar anthropic/claude-haiku-5-5 clears the bar anthropic/claude-sonnet-5-5 does NOT clear the bar

The bar: 90% on easy claims, no wrongly approved big payouts, at most 5 seconds. These five results are made up for practice, not from the run above. Sort them.

标准线：简单理赔 90%，没有错批的大额赔付，每份最多 5 秒。这五组结果是为练习编的，不是上面那次运行的。给它们分一分。

Step 5 · Pick the cheapest, and keep a fallback第 5 步 · 选最便宜的，并留一个后备

Learn先学

Among the models that cleared the bar, take the cheapest. Then keep a stronger model as a fallback: a router asks the cheap one first and only sends a claim to the strong one when the cheap one says “refer”, its way of saying it is unsure. The strong model costs money only on the few hard claims. The winner is often a mid-priced model. Spending more on the model rarely beats improving the prompt, the tools and the checks around it.

在过线的模型里，取最便宜的。再留一个更强的模型做后备：路由器先问便宜的那个，只有它回答“转交”（它表示拿不准的方式）时，才把这份理赔交给强的那个。强模型只在少数难的理赔上花钱。赢家常常是中等价位的模型。在模型上多花钱，很少比得上把提示词、工具和周围的检查做好。

passing = [r for r in rows if clears(r)] if not passing: raise SystemExit("nobody clears the bar: change the prompt, or talk to Mr Goh about the bar") pick = min(passing, key=lambda r: r["cost_1000"])["model"] STRONG = "anthropic/claude-sonnet-5-5" def decide_routed(claim): decision = ask(gateway, pick, small_prompt(claim))[0] # ask() returns a tuple; [0] is the decision if decision["action"] == "refer": # the cheap model is unsure decision = ask(gateway, STRONG, small_prompt(claim))[0] return decision # a refer from the strong model still goes to a handler

Step 6 · Write the decision in half a page第 6 步 · 用半页纸写下决定

Learn先学

The choice is only finished when Mr Goh can read it. Keep it to half a page: the bar, the pick, the numbers behind it, the fallback, and what would make you look again. That last part matters. Prices change and new models arrive every few months.

Goh 先生读得懂，这个选择才算完成。控制在半页纸：标准线、选了谁、背后的数字、后备方案，以及什么情况下你会重新看一遍。最后这一条很重要，价格会变，新模型每隔几个月就来一批。

Model choice for the claims desk (draft for Mr Goh) The bar we agreed: at least 90% right on easy claims, no wrongly approved big payouts, at most 5 seconds a claim. (Practice draft: "Model B" and every number here are made up. Use your own run.) Our pick: Model B. Of the two models that cleared the bar, it is the cheaper: 92% on easy claims, 3 seconds, US$1.80 per 1,000 claims. Fallback: the strong model, Claude Sonnet 5.5, handles only the claims Model B refers. We will look again if: prices drop by half, a new model arrives, or more than 1 in 10 claims has to go to the fallback.
What I got wrong我当时想错了I picked on accuracy alone, and the winner was too slow for a busy queue. Speed was a requirement nobody had written down. Now speed goes into the bar before anything runs, and every other thing the customer cares about does too.我只按准确率挑，结果赢家对忙碌的队列来说太慢了。速度是一条谁都没写下来的要求。现在速度和客户在乎的其他东西，都在跑之前先写进标准线。

Now make it yours现在把它变成你的

What changed这一课之后Now the pilot runs on one chosen model with a stronger one as fallback, and Mr Goh keeps the half-page decision in a folder with the plan on top. The next problem is the clumsiness around the model: the pilot is slow, pastes the whole wording into every claim, and a crash mid-run can leave a claim, such as C014, stuck “in progress” for ever.现在试点用选定的一个模型来跑，并备着一个更强的做后备，Goh 先生把那半页决定收进一个文件夹，计划放在最上面。下一个问题是模型周围的笨拙：试点很慢，每份理赔都贴上整份条款，而且运行中一旦崩溃，某份理赔（比如 C014）可能一直停在“处理中”。

Common errors常见错误

ImportError: cannot import name 'small_prompt' from 'bench'
Cause: bench.py from the earlier lesson is missing that function, or you are in another folder. Fix: run from the folder that holds bench.py and check the function name.

ImportError: cannot import name 'small_prompt' from 'bench'
原因：前面那课的 bench.py 没有这个函数，或者你在别的文件夹里。解决：在放着 bench.py 的文件夹里运行，并核对函数名。

SystemExit: nobody clears the bar: change the prompt or the bar
Cause: no model reached all three limits. Fix: that is a real answer. Improve the prompt or talk to Mr Goh about the bar; do not quietly lower it.

SystemExit: nobody clears the bar: change the prompt or the bar
原因：没有模型同时达到三项要求。解决：这是个真实的结果。改进提示，或和 Goh 先生讨论标准；不要悄悄降低它。

ZeroDivisionError: division by zero
Cause: a difficulty level has no claims in the sample, so the share is 0 divided by 0. Fix: check that every level appears in the key, or skip empty levels.

ZeroDivisionError: division by zero
原因：样本里某个难度没有理赔，比例变成 0 除以 0。解决：确认答案表里每个难度都有，或跳过空的难度。

Takeaways要点回顾

• Agree the bar with the customer before the contest, in numbers.
• Put speed and safety in the bar, not only accuracy.
• Run each candidate twice before you trust a row.
• A model must pass every line of the bar, not most of them.
• Pick the cheapest model that clears it, and name a stronger fallback for the claims it is unsure of.
• Better prompts, tools and checks often beat a pricier model.
• Write the reason in half a page, with what would make you revisit it.

• 比赛前先和客户用数字谈好标准线。
• 标准线里要有速度和安全，不只是准确率。
• 每个候选跑两遍，再相信那一行。
• 模型必须过标准线的每一条，而不是大多数。
• 选过线里最便宜的，并为它拿不准的理赔指定一个更强的后备。
• 更好的提示词、工具和检查，往往胜过更贵的模型。
• 用半页纸写下理由，以及什么情况会让你重新考虑。
