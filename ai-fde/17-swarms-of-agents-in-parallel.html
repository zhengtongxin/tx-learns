Step 1 · A plain-code dispatcher第 1 步 · 用普通代码做调度器

Learn先学
  • A dispatcher hands each claim to an agent. Its job is fixed, so use plain code, no model: free, instant, the same every time.
  • async def marks a function that can pause, and await is the spot where it pauses (waiting for the model) and lets the others run. asyncio.run starts the whole thing from normal code.
  • asyncio.gather starts one job per claim and waits for all of them, so the slow waits (for the model) overlap instead of queueing.
  • Test with a stand-in that just sleeps, not the real agent: it is slow, costs money and can hide your own bugs.
  • 调度器把每份理赔交给一个智能体。它的活是固定的，所以用普通代码，不用模型：免费、即时、每次都一样。
  • async def 标出一个可以暂停的函数，await 就是它暂停（等模型）并让别的任务先跑的地方。asyncio.run 从普通代码里把整件事启动起来。
  • asyncio.gather 给每份理赔开一个任务并等它们全部做完，这样（等模型的）慢等待是重叠的，不是排队。
  • 用只会睡一会儿的替身来测，而不是真智能体：它又慢又花钱，还可能盖住你自己的 bug。
import asyncio, random async def dispatch(claims, agent): # start one piece of work per claim, then wait for all of them results = await asyncio.gather(*(agent(c) for c in claims)) return dict(zip([c["id"] for c in claims], results)) async def stand_in(claim): await asyncio.sleep(random.uniform(0.5, 1.5)) # pretend to think return {"action": "approve", "payout": claim["amount"]} claims = [{"id": f"C-{i}", "amount": 100 * i} for i in range(1, 26)] print(asyncio.run(dispatch(claims, stand_in)))

预期输出

Step 2 · Track state, isolate failures, cap the swarm第 2 步 · 记状态、隔离失败、给群设上限

Learn先学
  • Report each change (waiting, running, done, failed) to a small record, so you can see the whole batch.
  • Catch errors inside each claim: one bad claim becomes a “failed” line, not a crashed batch.
  • Starting all 25 at once is how you hit the provider's rate limit. An asyncio.Semaphore is N tickets at the door: at most N agents at a time, the rest wait.
  • 把每次变化（等待、运行、完成、失败）报给一份小记录，这样整批的情况一目了然。
  • 在每份理赔内部接住错误：一份有问题的理赔只变成一行“失败”，不会让整批崩掉。
  • 一次放出 25 个，正是撞上供应商速率限制的办法。asyncio.Semaphore 就是门口的 N 张票：同一时间最多 N 个智能体，其余的等。
state = {} def on_change(claim_id, status): state[claim_id] = status async def run_one(claim, agent, on_change, gate): async with gate: # wait here until a ticket is free on_change(claim["id"], "running") try: result = await agent(claim) except Exception: on_change(claim["id"], "failed") # one bad claim stays one bad claim return None on_change(claim["id"], "done") return result async def dispatch(claims, agent, on_change, cap=3): gate = asyncio.Semaphore(max(1, cap)) # cap tickets; at least 1, or nothing would ever run for c in claims: on_change(c["id"], "waiting") results = await asyncio.gather(*(run_one(c, agent, on_change, gate) for c in claims)) return dict(zip([c["id"] for c in claims], results))

Step 3 · Retries: wait or go back第 3 步 · 重试：等一等，还是退回去

Learn先学
  • A rate limit or timeout means “not now”: wait and ask again. It is the same attempt, not a strike against the claim.
  • Any other failure goes back once. A second failure is left for a handler.
  • Going parallel cuts the time a lot; the cost per claim stays the same.
  • 速率限制或超时只是“现在不行”：等一会儿再问。这是同一次尝试，不算这份理赔的一次失败。
  • 其他任何失败退回一次。第二次失败就留给理赔员。
  • 并行能大幅缩短时间；每份理赔的成本不变。
import openai # the "not now" errors of your provider. Add your own to the tuple for tests with a stand-in. NOT_NOW = (openai.RateLimitError, openai.APITimeoutError) WAIT_SECONDS = 2 async def attempt(claim, agent): failures = 0 while True: try: return await agent(claim) except NOT_NOW: await asyncio.sleep(WAIT_SECONDS) # same attempt, just later except Exception: failures += 1 if failures == 2: # second real failure: give up raise # in run_one, one line changes: result = await attempt(claim, agent)

Common errors常见错误

RuntimeError: asyncio.run() cannot be called from a running event loop
Fix: in a notebook use await dispatch(...); otherwise run a plain script.

RuntimeError: asyncio.run() cannot be called from a running event loop
解决：在笔记本里用 await dispatch(...)；否则当作普通脚本运行。

openai.RateLimitError: Error code: 429
Fix: lower the cap, and treat the error as “try later”, not a decision.

openai.RateLimitError: Error code: 429
解决：调低上限，并把这个错误当成“稍后再试”，不是一个决定。

Takeaways要点回顾

• Dispatch with plain code and test it with stand-in agents first.
• Keep state so you can see who is waiting, running, done or failed.
• Cap concurrency; the first limit you hit is the provider's rate limit.
• A rate-limit retry is the same attempt; other failures go back once, then to a handler.
• Parallel cuts time, not cost per claim.

• 用普通代码调度，并先用替身智能体测试。
• 记住状态，看得出谁在等、在跑、已完成或已失败。
• 给并行设上限；最先撞上的是供应商的速率限制。
• 速率限制后的重试是同一次尝试；其他失败退回一次，再不行交给理赔员。
• 并行缩短时间，不改变每份理赔的成本。
