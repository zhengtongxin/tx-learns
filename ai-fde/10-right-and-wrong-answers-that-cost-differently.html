Measuring an agent · Lesson 1衡量智能体 · 第 1 课

Right and wrong answers that cost differently对与错，代价各不相同

Two agents can agree with the handlers equally often and still cost very different amounts: learn to name each kind of mistake and price it · ~25 min · concept with one runnable idea两个智能体和理赔员一致的次数可以一样多，花费却天差地别：学会给每一种错误起名字、标价格 · 约 25 分钟 · 概念课，附一个可动手的做法

Where we left off上回讲到

Last time the pilot learned to work the queue by itself. Today two versions both agree with the handlers on 19 of 25 claims, and Mr Goh asks what the other six cost. We fix it by telling the mistakes apart and putting a price on each.

上回试点学会了自己处理队列。今天有两个版本都和理赔员在 25 份里有 19 份一致，Goh 先生问另外六份让公司花了多少。我们的办法是把错误分开，并给每一种定个价。

The story故事

Mei Ling has two versions of the claims agent, A and B. Both agree with the handlers on 19 of 25 claims, which is 76%. “Pick either,” she says. Mr Goh puts down his pen. “Agree on which 19? And the other six, what did they do to us?” He is right: a wrong answer is not one thing. Paying a claim that should have been refused is not the same as sending a plain claim to a handler. So she builds a scoreboard that tells the mistakes apart and puts a price on each.

Mei Ling 手上有两个版本的理赔智能体，A 和 B。两个都在 25 份理赔里和理赔员一致了 19 份，也就是 76%。“随便挑一个吧。”她说。Goh 先生放下笔：“一致的是哪 19 份？另外那六份，它们给我们惹了什么麻烦？”他说得对：错误不是一种东西。把该拒的理赔赔了出去，和把一份很普通的理赔转给理赔员，完全是两回事。所以她做了一块计分板：把错误分开，并给每一种标上价格。

Step 1 · The mistake table第 1 步 · 错误对照表

Learn先学

A single percentage hides which answers were wrong. So lay the results out in a grid, called a confusion matrix. Each row is what the handler decided. Each column is what the agent decided. The diagonal, where row and column match, holds the agreements. Everything off the diagonal is a mistake, and its position tells you what kind. Like a marking sheet that shows not just your score but which questions you missed. Save the code in a file called scoring.py. The next lessons use it again. Here “agree” only means the same action: approve, decline or refer. Payout amounts come later.

一个百分比会藏起“哪些答案错了”。所以把结果摆进一张格子里，叫混淆矩阵。每一行是理赔员的决定，每一列是智能体的决定。行和列相同的那条对角线是一致的地方，不在对角线上的都是错误，而且它的位置就告诉你是哪一种错。就像一张批改单：不只告诉你得了几分，还告诉你错了哪几题。把代码存进一个叫 scoring.py 的文件，后面几课还会用。这里的“一致”只指动作相同：批准、拒绝或转交。赔付金额留到后面。

# scoring.py from collections import Counter ACTIONS = ["approve", "decline", "refer"] def matrix(pairs): """pairs: one (handler's decision, agent's decision) per claim.""" counts = Counter(pairs) return [[counts[(h, a)] for a in ACTIONS] for h in ACTIONS] # rows: handler, columns: agent # practice data typed as counts: rows = handler, columns = agent (approve, decline, refer) GRID_A = [[12, 0, 2], [3, 3, 0], [1, 0, 4]] GRID_B = [[10, 2, 2], [0, 5, 1], [0, 1, 4]] def accuracy(grid): total = sum(map(sum, grid)) return sum(grid[i][i] for i in range(3)) / total

Step 2 · Name the mistakes第 2 步 · 给错误起名字

Learn先学

Mei Ling and Aisha name three kinds of mistake, by what the agent did. A wrongful payment: the agent approves, but the handler would not have. Money is out of the door. A wrongful decline: the agent says no, but the handler would not have. A customer is let down. A needless referral: the agent hands over a claim a handler would have decided at once. Only handler time is wasted. Counting an approve against a claim a handler would have referred as a wrongful payment is on purpose: money moved before a human looked.

Mei Ling 和 Aisha 按智能体做了什么，给错误起了三个名字。错付：智能体批准了，但理赔员不会批准，钱已经出了门。错拒：智能体说不，但理赔员不会拒，客户被辜负了。白转交：智能体把一份理赔员本可以当场决定的理赔转了过来，浪费的只是理赔员的时间。如果理赔员本来会转交、智能体却直接批准，也算错付，这是有意的：钱在人看过之前就动了。

# scoring.py, continued # (handler's decision, agent's decision) -> what kind of mistake KIND = {("decline", "approve"): "wrongful payment", ("refer", "approve"): "wrongful payment", ("approve", "decline"): "wrongful decline", ("refer", "decline"): "wrongful decline", ("approve", "refer"): "needless referral", ("decline", "refer"): "needless referral"} def mistakes(grid): found = Counter() for i, handler in enumerate(ACTIONS): for j, agent in enumerate(ACTIONS): if i != j: found[KIND[(handler, agent)]] += grid[i][j] return dict(found)

Step 3 · Precision and recall for approvals第 3 步 · 批准的精确率与召回率

Learn先学

Two questions about approvals. Precision: when the agent says approve, how often is it right? Recall: of the claims the handlers approved, how many did the agent also approve? Think of a lifeguard. High precision means whenever they blow the whistle, someone really is in trouble. High recall means they catch every swimmer who is in trouble. One agent can be strong on one and weak on the other.

关于批准，有两个问题。精确率：智能体说批准的时候，有多少次是对的？召回率：理赔员批准的那些理赔里，智能体也批准了多少？想想救生员。精确率高，意思是只要他吹哨，就一定真有人遇险；召回率高，意思是每一个遇险的游泳者他都能发现。一个智能体可能这个强、那个弱。

# scoring.py, continued def approval_precision_recall(grid): said_approve = sum(row[0] for row in grid) # the agent's approve column should_approve = sum(grid[0]) # the handler's approve row right = grid[0][0] return right / said_approve, right / should_approve

Step 4 · Kappa: agreement beyond luck第 4 步 · Kappa：扣掉运气之后的一致

Learn先学

Handlers approve 14 of the 25 claims, which is 56%. An agent that approves everything already scores 56%, without reading a word. Kappa takes that luck away. It asks: how much better than chance is the agreement? Zero means no better than chance, and 1 means perfect. The chance part is worked out from how often each side says each answer: multiply the two sides’ shares for each answer and add them up.

理赔员批准了 25 份里的 14 份，也就是 56%。一个什么都批准的智能体，一个字都没读，就已经拿到 56%。Kappa 把这份运气扣掉，它问的是：一致的程度比碰运气好多少？0 表示不比碰运气好，1 表示完美。“运气”那部分，用双方各自说每个答案的比例来算：每个答案把两边的比例相乘，再全部加起来。

# scoring.py, continued def kappa(grid): total = sum(map(sum, grid)) seen = accuracy(grid) by_handler = [sum(row) for row in grid] # row totals by_agent = [sum(row[j] for row in grid) for j in range(3)] # column totals by_chance = sum(h * a for h, a in zip(by_handler, by_agent)) / total ** 2 return (seen - by_chance) / (1 - by_chance)

Step 5 · Straight-through rate第 5 步 · 直通率

Learn先学

An agent that refers every claim never pays a wrong claim. It also saves nobody any time. The straight-through rate is the share of claims the agent decides itself, without a referral. Report it beside accuracy, so a cautious agent cannot hide behind a clean-looking record. It is the same thing as 1 minus the referral share.

一个把每份理赔都转交的智能体，永远不会错付，但也没替任何人省时间。直通率是智能体自己做决定、不用转交的理赔所占的比例。把它和准确率放在一起汇报，谨慎的智能体就不能躲在一份干净的记录后面。它等于 1 减去转交的比例。

# scoring.py, continued def straight_through(grid): total = sum(map(sum, grid)) referred = sum(row[2] for row in grid) # the agent's refer column return 1 - referred / total

Step 6 · Price each mistake第 6 步 · 给每种错误标价

Learn先学

Now the scoreboard Mr Goh asked for. Sit with him and Aisha and agree what each kind of mistake costs the company, in S$. The prices below are invented: yours come from them. A wrongful payment is the money plus the effort to get it back. A wrongful decline is a complaint and a lost customer. A needless referral is a few minutes of a handler’s time. Then multiply and add. The agent with the lower total is the better one for this desk.

现在轮到 Goh 先生要的那块计分板。和他、Aisha 坐下来，谈好每一种错误让公司花多少钱，用新元算。下面的价格是编的，你的价格要从他们那里来。错付是那笔钱，加上追回它的力气。错拒是一次投诉，加一个流失的客户。白转交是理赔员几分钟的时间。然后相乘再相加。总数更低的那个智能体，才是适合这个理赔台的。

# scoring.py, continued PRICE = {"wrongful payment": 400, "wrongful decline": 150, "needless referral": 15} # S$, invented def mistake_cost(grid, price=PRICE): return sum(price[kind] * n for kind, n in mistakes(grid).items()) for name, grid in [("A", GRID_A), ("B", GRID_B)]: print(name, f"{accuracy(grid):.0%}", f"kappa {kappa(grid):.2f}", f"straight-through {straight_through(grid):.0%}", "cost S$", mistake_cost(grid))

Expected output (an example: your numbers and wording will differ)

预期输出 （示例：你的数字和措辞会不同）

A 76% kappa 0.58 straight-through 76% cost S$ 1630 B 76% kappa 0.63 straight-through 72% cost S$ 495

Which agent would you give Mr Goh? Sort the numbers that matter.

你会把哪个智能体交给 Goh 先生？把重要的数字分一分。

What I got wrong我当时想错了I trusted accuracy first. A and B tied at 76%, and A had the better straight-through rate, so I leaned towards A. Then wrongful payments got a price, and A was the expensive one: four payments that should not have happened. The “best” agent changed the moment each mistake had a price.我一开始只信准确率。A 和 B 都是 76%，A 的直通率还更高，所以我偏向 A。后来错付有了价格，A 就成了贵的那个：四笔本不该发生的赔付。每种错误一标上价格，“最好”的智能体就换人了。

The next problem is that its payouts are often a few dollars off, and Mei Ling cannot see why.现在试点按错误的代价来评分：Goh 先生把图章落在智能体 B 上，因为它的三次错拒他还能打电话补救，而智能体 A 的四笔错付再也追不回来。下一个问题是它的赔付常常差几块钱，而 Mei Ling 看不出原因。

Common errors常见错误

ZeroDivisionError: division by zero
Cause: a grid row or column adds up to 0, for example nobody was told "approve". Fix: return 0 when the total is 0, and say so on the page.

ZeroDivisionError: division by zero
原因：表格的某一行或列合计为 0，比如从没有“批准”的结果。解决：合计为 0 时返回 0，并在页面上说明。

KeyError: 'wrongful payment'
Cause: the price table and the names that mistakes() returns do not match. Fix: use the same three names in both places.

KeyError: 'wrongful payment'
原因：价格表里的名字和 mistakes() 返回的名字对不上。解决：两处用同样的三个名字。

IndexError: list index out of range
Cause: the grid is not 3 by 3, so grid[i][i] runs off the end. Fix: build the grid with all three actions as rows and columns, even when a count is 0.

IndexError: list index out of range
原因：表格不是 3 乘 3，grid[i][i] 越界了。解决：行列都放上三种动作，即使某个数是 0。

Recap小结

• Accuracy alone hides how much each mistake costs.
• Count the mistake types, give each a price, and compare the totals.
• A model with lower accuracy can still be cheaper to run if its mistakes are the cheap kind.

• 只看准确率，会掩盖每种错误的代价。
• 把错误按类型数出来，给每种标上价格，再比较总额。
• 准确率较低的模型，只要错的多是便宜的那种，总体仍可能更省钱。

Takeaways要点回顾

• Accuracy flatters: it counts every mistake the same.
• A confusion matrix shows handler decisions in rows and agent decisions in columns; the off-diagonal cells are the mistakes.
• Name the kinds of mistake: wrongful payment, wrongful decline and needless referral.
• Precision asks “when it says yes, is it right?”; recall asks “did it catch the yeses?”.
• Kappa takes away the agreement you would get by luck: an agent that approves everything scores near zero.
• Report the straight-through rate beside accuracy, so an agent that refers everything cannot look safe.
• Put a price on each kind of mistake and total it: the ranking can change.

• 准确率会讨好人：它把每个错误都算成一样。
• 混淆矩阵的行是理赔员的决定，列是智能体的决定；不在对角线上的格子就是错误。
• 给错误起名字：错付、错拒和白转交。
• 精确率问“说是的时候对不对”；召回率问“是的那些都抓到了吗”。
• Kappa 扣掉碰运气也会有的一致：什么都批准的智能体，得分接近零。
• 把直通率和准确率放在一起汇报，什么都转交的智能体就不会显得安全。
• 给每种错误标上价格再加总：排名可能就变了。
