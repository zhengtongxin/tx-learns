Open models and token cost开源模型与成本

Cut the prompt, try models you can host or run yourself, and judge them on accuracy, cost and speed together · ~20 min · concept with one runnable idea把提示词剪短，试试能托管或自己运行的模型，并把准确率、成本和速度放在一起评判 · 约 20 分钟 · 概念课，附一个可动手的做法

Step 1 · Send fewer tokens第 1 步 · 少发 token

Learn先学
  • Models bill and slow down by tokens (about four letters of English). The full prompt pastes the whole wording into every call, and most of it is irrelevant to one claim.
  • Give each claim type only its own sections, and write the JSON compactly. Then check accuracy: trimming can cut the one section a claim needed.
  • 模型按 token（英文约四个字母）收费，也按 token 变慢。完整提示词每次都把整份条款贴进去，而对一份理赔来说大部分用不上。
  • 只给每种理赔类型它自己的那几节，JSON 也写得紧凑些。然后检查准确率：剪得太狠可能把某份理赔需要的那一节剪掉。
# bench.py, continued (build_prompt, claims, POLICIES and key are from the last lesson) # two things to add first: # 1. in your claims file, give each claim a "type": "delay", "baggage" or "medical" # 2. a new file, data/wording_sections.json: the policy wording cut into named parts, one per claim type plus "limits" WORDING_PARTS = json.load(open("data/wording_sections.json")) # {"delays": "...", "baggage": "...", "medical": "...", "limits": "..."} SECTIONS = {"delay": ["delays", "limits"], "baggage": ["baggage", "limits"], "medical": ["medical", "limits"]} def compact(data): return json.dumps(data, separators=(",", ":")) # drops the spaces json.dumps adds def small_prompt(claim): wording = "\n".join(WORDING_PARTS[name] for name in SECTIONS[claim["type"]]) return f"""Travel claims desk. Relevant wording: {wording} Policy: {compact(POLICIES[claim["policy_id"]])} Claim: {compact(claim)} JSON only: {{"action": "approve" or "decline" or "refer", "payout": number in S$, "reason": two short sentences}}""" def rough_tokens(text): return len(text) // 4 # about four characters per token full = sum(rough_tokens(build_prompt(c)) for c in claims) / len(claims) small = sum(rough_tokens(small_prompt(c)) for c in claims) / len(claims) print(f"full {full:.0f} tokens, small {small:.0f} tokens, saved {1 - small / full:.0%}")

Step 2 · Open models: hosted or local第 2 步 · 开放模型：托管或本地

Learn先学
  • An open-weight model has published weights, so anyone can host or run it.
  • A hosting service runs it for you, per token, usually far cheaper than a frontier model. The gateway from the last lesson reaches it with the same code.
  • Ollama runs small open models on your own machine: nothing is billed and no claim leaves the building. The price is speed, disk and memory.
  • 开放权重模型公开了权重，谁都能托管或运行。
  • 托管服务替你运行，按 token 收费，通常比前沿模型便宜得多。上一课的网关用同样的代码就能连上。
  • Ollama 在你自己的机器上运行小型开放模型：不收费，理赔也不会离开这栋楼。代价是速度，以及磁盘和内存。
# bench.py, continued import time from openai import OpenAI # ask replaces last lesson's decide: same job, but it takes the client and times the call def ask(client, model, prompt): start = time.perf_counter() reply = client.chat.completions.create( model=model, messages=[{"role": "user", "content": prompt}]) seconds = time.perf_counter() - start text = reply.choices[0].message.content decision = json.loads(text[text.index("{"): text.rindex("}") + 1]) return decision, reply.usage.prompt_tokens, reply.usage.completion_tokens, seconds def run_all(client, model): return [(c["id"], *ask(client, model, small_prompt(c))) for c in claims] # hosted: the gateway from the last lesson (check exact names on its model list) OPEN_MODELS = ["meta-llama/llama-3.3-70b-instruct", "qwen/qwen-2.5-72b-instruct"] # local: run `ollama pull llama3.2` once, then point the client at this computer local = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama") # the key is ignored, but the library needs one results = run_all(local, "llama3.2") hosted = {m: run_all(gateway, m) for m in OPEN_MODELS} # gateway is the client bench.py already has

Step 3 · Accuracy, cost and speed side by side第 3 步 · 把准确率、成本和速度并排放

Learn先学
  • One number is never enough: print accuracy, cost and speed per model. Drop a model when another is as good or better on every measure.
  • Also print the baseline, the score of a lazy answer such as “approve everything”. Your model is only worth what it adds on top.
  • 只看一个数永远不够：每个模型都印出准确率、成本和速度。如果另一个模型每一项都不输，这个就可以淘汰。
  • 再印出基线，也就是偷懒答案（比如“全部批准”）的得分。模型的价值只看它在这之上多加了多少。
# matches() and key are the scoring helper and the answer key from the last lesson def summary(name, price, results): right = sum(matches(decision, key[cid]) for cid, decision, _, _, _ in results) cost = sum(tin * price[0] + tout * price[1] for _, _, tin, tout, _ in results) / 1_000_000 / len(results) * 1000 secs = sum(s for *_, s in results) / len(results) print(f"{name:34} {right}/{len(results)} right US${cost:.2f} per 1,000 {secs:.1f}s per claim") for m in OPEN_MODELS: # add each model's price to PRICE first: US$ per million tokens (in, out) summary(m, PRICE[m], hosted[m]) summary("llama3.2 (local)", (0, 0), results) # local models cost nothing per token approve_share = sum(1 for want in key.values() if want["action"] == "approve") / len(key) print(f"approving everything scores {approve_share:.0%}")

Takeaways要点回顾

• Shorter prompts are cheaper and faster; check accuracy after trimming.
• Open-weight models on a hosting service are cheaper; a local one costs nothing per token and keeps data home, but is slower.
• Judge models on accuracy, cost and speed together.
• Always compare with the trivial baseline.

• 更短的提示词更便宜更快；剪完要检查准确率。
• 托管服务上的开放权重模型更便宜；本地模型每个 token 不花钱、数据留在家里，但更慢。
• 把准确率、成本和速度放在一起评判模型。
• 永远要和最简单的基线比。
