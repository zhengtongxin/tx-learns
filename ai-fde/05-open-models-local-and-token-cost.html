Step 1 · Make a smaller prompt第 1 步 · 做一份更小的提示词

Learn先学

The full prompt pastes the whole policy wording into every call, and you pay for every word, every time. Most of it is irrelevant to any one claim. A baggage claim does not need the medical section. So give each claim type only its own sections, and write the JSON without spaces and line breaks. This assumes you tagged each claim with a type (delay, baggage or medical) and split the wording into a file of sections.

完整的提示词每次调用都把整份保单条款贴进去，每个字每次都要花钱。而对某一份理赔来说，大部分内容用不上。行李理赔不需要医疗那一节。所以只给每种理赔类型它自己的那几节，JSON 也不要空格和换行。这里假设你给每份理赔标了 type（delay、baggage 或 medical），并把条款拆成了一个分节文件。

# bench.py, continued (build_prompt, claims, POLICIES and key are from the last lesson) # each claim now has a type, e.g. {"id": "C007", "type": "baggage", "policy_id": "P003", ...} WORDING_PARTS = json.load(open("data/wording_sections.json")) # {"delays": "...", "baggage": "...", ...} SECTIONS = {"delay": ["delays", "limits"], "baggage": ["baggage", "limits"], "medical": ["medical", "limits"]} def compact(data): return json.dumps(data, separators=(",", ":")) # drops the spaces that json.dumps adds by default def small_prompt(claim): wording = "\n".join(WORDING_PARTS[name] for name in SECTIONS[claim["type"]]) policy = compact(POLICIES[claim["policy_id"]]) return f"""Travel claims desk. Relevant wording: {wording} Policy: {policy} Claim: {compact(claim)} JSON only: {{"action": "approve" or "decline" or "refer", "payout": number in S$, "reason": two short sentences}}"""

Step 2 · Measure what you saved第 2 步 · 量一量省了多少

Learn先学

A token is a small piece of text, about four letters in English. Models are billed and slowed down by tokens, so count them before and after. A quick estimate is the number of characters divided by four. The exact count comes back from the gateway in each reply. A smaller prompt helps every model, but it can also cut the one section a claim needed. Check accuracy after trimming, not only cost.

token 是一小段文字，英文里大约四个字母。模型按 token 收费，也按 token 变慢，所以前后各数一次。快速估算就是字符数除以四。精确的数每次回复里网关都会给你。更小的提示词对每个模型都有好处，但也可能把某份理赔恰好需要的那一节剪掉。剪完之后要看准确率，不能只看成本。

def rough_tokens(text): return len(text) // 4 # about four characters per token full = sum(rough_tokens(build_prompt(c)) for c in claims) / len(claims) small = sum(rough_tokens(small_prompt(c)) for c in claims) / len(claims) print(f"full {full:.0f} tokens, small {small:.0f} tokens, saved {1 - small / full:.0%}")

Expected output (an example: your numbers and wording will differ)

预期输出 （示例：你的数字和措辞会不同）

Step 3 · Open models on a hosting service第 3 步 · 托管服务上的开放模型

Learn先学

You do not need your own big computer to use an open model. A hosting service runs it for you and charges per token, usually much less than a frontier model. Several providers can serve the same open model at different prices and speeds. The gateway from the last lesson reaches them with the same code. This time ask replaces decide from the last lesson. It does the same job and also times each call. It takes the client and prompt as inputs, so Step 4 can reuse it.

用开放模型不需要自己有一台大电脑。托管服务替你运行，按 token 收费，通常比前沿模型便宜得多。同一个开放模型可以由好几家服务商提供，价格和速度各不相同。上一课的网关用同样的代码就能连上它们。这次 ask 替代上一课的 decide：做同样的事，还会给每次调用计时。它把客户端和提示词作为输入，这样第 4 步可以复用。

# bench.py, continued import time # check the exact names on your gateway's model list; you can add more OPEN_MODELS = ["meta-llama/llama-3.3-70b-instruct", "qwen/qwen-2.5-72b-instruct", "mistralai/mistral-small-3.2-24b-instruct"] def ask(client, model, prompt): start = time.perf_counter() reply = client.chat.completions.create( model=model, messages=[{"role": "user", "content": prompt}]) seconds = time.perf_counter() - start text = reply.choices[0].message.content decision = json.loads(text[text.index("{"): text.rindex("}") + 1]) return decision, reply.usage.prompt_tokens, reply.usage.completion_tokens, seconds # client is the gateway from Lesson 4: run_all(gateway, "openai/gpt-5.4-mini") def run_all(client, model): return [(c["id"], *ask(client, model, small_prompt(c))) for c in claims]

Step 4 · Models on your own computer第 4 步 · 在自己电脑上跑模型

Learn先学

Ollama is a free app that downloads small open models and runs them on your own machine. It speaks the same OpenAI-style language, so ask works unchanged: just point the client at your own computer. No tokens are billed and no claim leaves the building, which is what Kumar wanted. The price is speed, and disk and memory to hold the model.

Ollama 是个免费应用，能下载小型开放模型，在你自己的机器上运行。它说的也是 OpenAI 那一套话，所以 ask 原封不动就能用：只要把客户端指向你自己的电脑。不按 token 收费，理赔也不会离开这栋楼，这正是 Kumar 想要的。代价是速度，以及放模型所需的磁盘和内存。

ollama pull llama3.2 ollama pull qwen2.5:3b
local = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama") # localhost is this computer; the key is ignored, but the library needs one LOCAL_MODELS = ["llama3.2", "qwen2.5:3b"] results = run_all(local, LOCAL_MODELS[0]) # same function, now running on your own machine

Step 5 · Accuracy, cost and speed side by side第 5 步 · 把准确率、成本和速度并排放

Learn先学

One number is never enough. A model can be the most accurate and also slow and dear. Print one line per model with all three. Later you can plot accuracy against cost, accuracy against speed, then all three at once. A model is worth dropping when another one is as good or better on every measure.

只看一个数永远不够。一个模型可能最准，也最慢最贵。每个模型打印一行，三项都带上。之后可以画准确率对成本、准确率对速度的图，最后三项一起看。如果另一个模型在每一项上都不输，这个模型就可以淘汰了。

def summary(name, price, results): right = sum(matches(decision, key[cid]) for cid, decision, _, _, _ in results) cost = sum(tin * price[0] + tout * price[1] for _, _, tin, tout, _ in results) / 1_000_000 / len(results) * 1000 secs = sum(s for *_, s in results) / len(results) print(f"{name:42} {right}/{len(results)} right US${cost:.2f} per 1,000 {secs:.1f}s per claim") # local models cost nothing per token, so their price is (0, 0) summary("llama3.2 (local)", (0, 0), results)

Step 6 · Check the lazy baseline第 6 步 · 对照偷懒的基线

Learn先学

A baseline is the score of a trivial answer. If most claims are approvals, a “model” that approves everything already looks decent. Your real model is only worth something by how much it adds on top. Always print the baseline next to the scores.

基线就是一个偷懒答案的得分。如果大多数理赔都是批准，一个“全部批准”的模型看上去就已经不差。你的真模型值多少，只看它在这之上多加了多少。分数旁边永远要印出基线。

approve_share = sum(1 for want in key.values() if want["action"] == "approve") / len(key) print(f"approving everything scores {approve_share:.0%}")

预期输出 （示例：你的数字和措辞会不同）

approving everything scores 56%

Now the baseline is always the first line I print.我忘了“全部批准”这条基线。我们大约 60% 的理赔是批准的，所以一个偷懒的模型看起来还不错，直到我拿它和最简单的答案比。现在基线永远是我打印的第一行。

Common errors常见错误

openai.APIConnectionError: Connection error.
Cause: Ollama is not running, so nothing answers on port 11434. Fix: start the Ollama app (or run ollama serve) and try again.

openai.APIConnectionError: Connection error.
原因：Ollama 没在运行，11434 端口没人应答。解决：打开 Ollama 应用（或运行 ollama serve）再试。

openai.NotFoundError: model 'llama3.2' not found, try pulling it first
Cause: the model was never downloaded. Fix: run ollama pull llama3.2 once.

openai.NotFoundError: model 'llama3.2' not found, try pulling it first
原因：这个模型从来没下载过。解决：运行一次 ollama pull llama3.2。

json.decoder.JSONDecodeError: Expecting value
Cause: small local models often add chatter around the JSON. Fix: shorten the prompt, repeat "JSON only", and count a bad reply as a wrong answer instead of crashing.

json.decoder.JSONDecodeError: Expecting value
原因：小的本地模型常在 JSON 周围加闲话。解决：缩短提示、重复“只要 JSON”，并把坏的回复算作错误答案，而不是让程序崩溃。

Takeaways要点回顾

• Shorter prompts are cheaper and faster, but can hide a fact a claim needs. Check accuracy after trimming.
• Tokens are what you pay for. Count them before and after.
• Open-weight models on a hosting service are cheaper, and several providers can serve the same one.
• A local model costs nothing per token and keeps data at home, but it is slower and needs disk and memory.
• Open and local models can be close on easy claims and clearly worse on hard ones.
• Always compare with the trivial baseline.
• Judge models on accuracy, cost and speed together.

• 更短的提示词更便宜更快，但可能藏起某份理赔需要的事实。剪完要检查准确率。
• 你付钱买的是 token，前后都数一数。
• 托管服务上的开放权重模型更便宜，同一个模型还可以有好几家服务商。
• 本地模型每个 token 不花钱、数据留在家里，但更慢，也要磁盘和内存。
• 开放和本地模型在简单理赔上可以很接近，在难的理赔上明显更差。
• 永远要和最简单的基线比。
• 把准确率、成本和速度放在一起评判模型。
