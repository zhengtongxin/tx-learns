Mei Ling’s dispatcher works, but only from her laptop. Aisha and Mr Goh will never open a terminal. So she gives it a page on the dashboard: one box to choose how many agents run at once, one button to start, and a panel that shows every claim and where it stands. When the run ends, Aisha gets a short summary of what is waiting for her. This project reuses the dispatcher from the last lesson, saved as dispatcher.py, and your claims agent and claim list saved as desk.py. Its load_claims() returns the day’s claims and its decide(claim) returns the decision and what that call cost in US dollars.

Mei Ling 的调度器能用了，但只能在她的笔记本上跑。Aisha 和 Goh 先生永远不会打开终端。所以她在看板上给它做一个页面：一个输入框，用来选同时跑几个智能体，一个按钮开始，一个面板显示每份理赔和它停在哪。运行结束时，Aisha 会收到一份简短的总结，写着有什么在等她。这个项目沿用上一课的调度器（存为 dispatcher.py），以及你的理赔智能体和理赔列表（存为 desk.py）。其中 load_claims() 返回当天的理赔，decide(claim) 返回判定结果，以及这次调用花了多少美元。

Step 1 · A queue page with a start button第 1 步 · 带开始按钮的队列页

Learn先学

The service is a small web server. Its start endpoint checks the number first: a whole number from 1 to 25, with 3 as the default. Anything else is turned away before any agent starts. Then it launches the dispatch in the background and answers straight away with a run id, so the page does not hang for minutes. We use FastAPI; install it with pip install fastapi uvicorn and start the server with uvicorn service:app. asyncio.to_thread runs a call that just waits, like the model call, on a helper thread, so the server can answer other requests in the meantime.

这个服务是一个小小的网页服务器。它的开始接口先检查数字：1 到 25 的整数，默认 3。别的值在任何智能体启动之前就会被拒绝。然后它在后台启动调度，并立刻回一个运行编号，页面不会卡上好几分钟。我们用 FastAPI，用 pip install fastapi uvicorn 安装，用 uvicorn service:app 启动服务器。asyncio.to_thread 会把一个只是在等的调用（比如模型调用）放到辅助线程上跑，这样服务器在等的时候还能回应别的请求。

# service.py import asyncio, sqlite3, uuid from fastapi import FastAPI, HTTPException from fastapi.responses import HTMLResponse from pydantic import BaseModel, Field from dispatcher import dispatch from desk import load_claims, decide app = FastAPI() class Start(BaseModel): n: int = Field(default=3, ge=1, le=25) # 1 to 25 agents at once async def agent(claim): decision, cost = await asyncio.to_thread(decide, claim) # the model call blocks, so use a thread return decision async def run_dispatch(n): await dispatch(load_claims(), agent, lambda claim_id, status: None, n) @app.post("/dispatch") async def start(body: Start): asyncio.create_task(run_dispatch(body.n)) return {"run": uuid.uuid4().hex[:8]} PAGE = """<h1>Queue</h1> <label>Agents at once <input id="n" type="number" min="1" max="25" value="3"></label> <button id="go">Start dispatch</button> <p id="msg"></p> <script> go.onclick = async () => { const r = await fetch("/dispatch", {method: "POST", headers: {"Content-Type": "application/json"}, body: JSON.stringify({n: Number(n.value)})}); msg.textContent = r.ok ? "Started." : "Could not start."; }; </script>""" @app.get("/", response_class=HTMLResponse) def page(): return PAGE

Step 2 · Only one dispatch at a time第 2 步 · 一次只跑一个调度

Learn先学

Two dispatches at once would share the same rate limit and mix their results, so nobody could tell which run a number belongs to. Keep one variable, current, holding the run that is working. If it is set, a second start is refused with a clear message. Like a single-lane counter: the next customer waits until the stamp is free.

两个调度同时跑，会共用同一个速率限制，结果还会混在一起，没人分得清某个数字属于哪一次。用一个变量 current 记着正在干的那次运行。如果它有值，第二次开始就会被拒绝，并给出清楚的提示。就像只有一个窗口的柜台：下一位客人要等图章空出来。

current = None # the id of the run that is working, if any async def run_dispatch(run, n): global current try: await dispatch(load_claims(), agent, lambda claim_id, status: None, n) finally: current = None # free the lane, even if the run failed @app.post("/dispatch") async def start(body: Start): global current if current: # no await between this check and the next line, so no race raise HTTPException(409, "A dispatch is already running. Wait for it to finish.") current = uuid.uuid4().hex[:8] asyncio.create_task(run_dispatch(current, body.n)) return {"run": current}

Step 3 · A run panel from records第 3 步 · 来自记录的运行面板

Learn先学

The panel needs somewhere to read from, so every change is written to a small table, one row per claim per run. The panel asks for that table and draws it. Have the page keep the run id from the start reply and ask /runs/{run id} every couple of seconds; you add that small script yourself, the way Step 5 adds its check. Because the rows are the truth, a page reload or a second browser shows the same thing. SQLite is built into Python; use your hosted database if you have one.

面板得有地方可读，所以每次变化都写进一张小表，每次运行里每份理赔一行。面板读取这张表并画出来。让页面保存开始接口返回的运行编号，每隔几秒去请求 /runs/{运行编号}；这段小脚本要你自己加，做法和第 5 步加检查一样。因为这些行就是事实，刷新页面或换一个浏览器，看到的都一样。SQLite 是 Python 自带的；如果你有托管数据库，也可以用它。

db = sqlite3.connect("runs.db", check_same_thread=False) db.execute("""CREATE TABLE IF NOT EXISTS claim_runs ( run TEXT, claim TEXT, status TEXT, action TEXT, payout REAL, PRIMARY KEY (run, claim))""") def save(run, claim_id, **fields): # fields: status, action or payout, set by our own code db.execute("INSERT OR IGNORE INTO claim_runs (run, claim, status) VALUES (?, ?, 'waiting')", (run, claim_id)) for column, value in fields.items(): db.execute(f"UPDATE claim_runs SET {column} = ? WHERE run = ? AND claim = ?", (value, run, claim_id)) db.commit() async def run_dispatch(run, n): global current async def agent_for_run(claim): decision, cost = await asyncio.to_thread(decide, claim) save(run, claim["id"], action=decision["action"], payout=float(decision.get("payout") or 0)) return decision try: await dispatch(load_claims(), agent_for_run, lambda claim_id, status: save(run, claim_id, status=status), n) finally: current = None @app.get("/runs/{run}") def panel(run: str): rows = db.execute("SELECT claim, status, action, payout FROM claim_runs WHERE run = ?", (run,)) return [{"claim": c, "status": s, "action": a, "payout": p} for c, s, a, p in rows]

Step 4 · A finishing summary from records第 4 步 · 由记录得出的收尾总结

Learn先学

When the run ends, handlers want five numbers, not a trace: approved, declined, referred, payouts waiting for sign-off, and claims left for a handler. Count them with a query. “Referred” means the agent itself passed the claim on; “left for a handler” means it failed twice. A big approval, over the S$800 limit, is not “approved” yet: it waits for a signature.

运行结束时，理赔员要的是五个数字，而不是一堆追踪记录：批准、拒赔、转交、等着签字的赔付，以及留给理赔员的理赔。用一条查询把它们数出来。“转交”是智能体自己把理赔交了出去；“留给理赔员”是它失败了两次。超过 S$800 限额的大额批准还不算“已批准”：它在等人签字。

SIGNOFF_LIMIT = 800 def count(run, where, *args): return db.execute(f"SELECT COUNT(*) FROM claim_runs WHERE run = ? AND {where}", (run, *args)).fetchone()[0] @app.get("/runs/{run}/summary") def summary(run: str): return { "approved": count(run, "status = 'done' AND action = 'approve' AND payout <= ?", SIGNOFF_LIMIT), "waiting_signoff": count(run, "status = 'done' AND action = 'approve' AND payout > ?", SIGNOFF_LIMIT), "declined": count(run, "status = 'done' AND action = 'decline'"), "referred": count(run, "status = 'done' AND action = 'refer'"), "left_for_handler": count(run, "status = 'failed'"), }

Step 5 · Say so when the agent is not running第 5 步 · 智能体没在运行时要说出来

Learn先学

A button that does nothing is the worst button. When the page opens it asks the service if it is alive. The page itself comes from this same service, so the check matters most when Aisha opens a saved copy of it. If there is no answer, the button is switched off and the page says why, in words Auntie Siew could read to Kumar over the phone. Add the small /health endpoint and change the page’s script to use it.

什么都不做的按钮是最糟的按钮。页面打开时，会先问服务还活着没有。页面本身也来自同一个服务，所以这个检查最有用的情况，是 Aisha 打开的是一份保存下来的副本。没有回应，就把按钮关掉，并用 Siew 阿姨可以在电话里读给 Kumar 听的话说明原因。加一个小小的 /health 接口，并让页面的脚本用上它。

@app.get("/health") def health(): return {"ok": True, "busy": current is not None} # in PAGE's script, before the go.onclick line: fetch("/health").then(r => r.json()).catch(() => null).then(h => { if (!h) { go.disabled = true; msg.textContent = "The agent service is not running. Ask Kumar to start it."; } else if (h.busy) { msg.textContent = "A dispatch is already running."; } });

Step 6 · Record cost and time for every claim第 6 步 · 为每份理赔记下成本和用时

Learn先学

To compare three caps on the same queue, you need what each claim cost and how long it took, against the run it happened in. Add four columns: cost, seconds, and when the claim started and finished. Fill them when the claim finishes. Then a run’s total cost, its slowest claim and its own run time are one query away. The total run time is the span from the first start to the last finish, because claims overlap.

要拿同一个队列比较三种上限，你需要知道每份理赔花了多少钱、用了多久，而且记在它所属的那次运行下面。加四列：成本、秒数，以及理赔开始和结束的时间，理赔完成时填进去。这样一次运行的总成本、最慢的那份理赔和整次运行的用时，一条查询就能得到。整次运行的总用时是从第一个开始到最后一个结束的跨度，因为各份理赔是重叠进行的。

for column in ("cost_usd REAL", "secs REAL", "started REAL", "finished REAL"): try: db.execute(f"ALTER TABLE claim_runs ADD COLUMN {column}") except sqlite3.OperationalError: pass # the column is already there import time # in run_dispatch, replace agent_for_run with this: async def agent_for_run(claim): started = time.time() decision, cost = await asyncio.to_thread(decide, claim) save(run, claim["id"], action=decision["action"], payout=float(decision.get("payout") or 0), cost_usd=cost, started=started, finished=time.time(), secs=time.time() - started) return decision # one run's totals, including its own run time: # SELECT SUM(cost_usd), MAX(secs), MAX(finished) - MIN(started) FROM claim_runs WHERE run = ?

Building the summary from the records fixed that, and it is faster and free.我的第一版总结是让模型写的，偶尔和记录对不上：它说批准了 11 份，表里只有 10 份。改成由记录生成总结之后问题就没了，而且更快、不花钱。

Takeaways要点回顾

• A cap is a safety feature: validate it (1 to 25) before any agent starts.
• One dispatch at a time keeps the results clean; refuse a second start with a clear message.
• Write every status change to a table so the panel, a reload and a second browser all agree.
• Build the summary from records, not from a model.
• If the agent service is down, the button says so instead of doing nothing.
• Record cost and time per claim against its run, so caps can be compared fairly.
• Handlers read the summary, not the traces.

• 上限是一道安全措施：任何智能体启动前先校验它（1 到 25）。
• 一次只跑一个调度，结果才干净；第二次开始要用清楚的提示拒绝。
• 把每次状态变化写进一张表，面板、刷新页面和另一个浏览器看到的就一致。
• 总结由记录生成，不由模型来写。
• 智能体服务没开时，按钮要说明，而不是什么都不做。
• 按所属运行记下每份理赔的成本和用时，这样才能公平比较不同的上限。
• 理赔员读的是总结，不是追踪记录。
