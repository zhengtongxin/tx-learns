Step 1 · A start button that validates and locks第 1 步 · 会校验、会上锁的开始按钮

Learn先学
  • This reuses the dispatcher from the last lesson (dispatcher.py) and your claims agent (desk.py, with load_claims() and decide(claim)).
  • A small FastAPI service wraps it: pip install fastapi uvicorn, run with uvicorn service:app.
  • The start endpoint validates the cap first (a whole number 1 to 25, default 3), launches the dispatch in the background and answers at once with a run id.
  • Only one dispatch at a time: a second start gets a clear 409, so runs never share a rate limit or mix results.
  • 这里沿用上一课的调度器（dispatcher.py）和你的理赔智能体（desk.py，含 load_claims() 和 decide(claim)）。
  • 用一个小小的 FastAPI 服务把它包起来：pip install fastapi uvicorn，用 uvicorn service:app 运行。
  • 开始接口先校验上限（1 到 25 的整数，默认 3），在后台启动调度，并立刻返回一个运行编号。
  • 一次只跑一个调度：第二次开始会得到清楚的 409，这样各次运行不会共用速率限制，结果也不会混在一起。
# service.py import asyncio, sqlite3, uuid from fastapi import FastAPI, HTTPException from fastapi.responses import HTMLResponse from pydantic import BaseModel, Field from dispatcher import dispatch from desk import load_claims, decide app = FastAPI() current = None # the id of the run that is working, if any class Start(BaseModel): n: int = Field(default=3, ge=1, le=25) # 1 to 25 agents at once async def agent(claim): decision, cost = await asyncio.to_thread(decide, claim) # the model call blocks, so use a thread return decision async def run_dispatch(run, n): global current try: await dispatch(load_claims(), agent, lambda claim_id, status: None, n) finally: current = None # free the lane, even if the run failed @app.post("/dispatch") async def start(body: Start): global current if current: # no await between this check and the next line, so no race raise HTTPException(409, "A dispatch is already running. Wait for it to finish.") current = uuid.uuid4().hex[:8] asyncio.create_task(run_dispatch(current, body.n)) return {"run": current} PAGE = """<h1>Queue</h1> <label>Agents at once <input id="n" type="number" min="1" max="25" value="3"></label> <button id="go">Start dispatch</button> <p id="msg"></p> <script> go.onclick = async () => { const r = await fetch("/dispatch", {method: "POST", headers: {"Content-Type": "application/json"}, body: JSON.stringify({n: Number(n.value)})}); msg.textContent = r.ok ? "Started." : "Could not start."; }; </script>""" @app.get("/", response_class=HTMLResponse) def page(): return PAGE

Step 2 · A panel and summary from records第 2 步 · 来自记录的面板和总结

Learn先学
  • Write every status change to a table, one row per claim per run. The panel reads the table, so a reload or a second browser shows the same thing.
  • The finishing summary is a count over that table, never a model's words, so it cannot disagree with what happened.
  • A payout over the S$800 limit is not “approved” yet: it waits for a signature.
  • 把每次状态变化写进一张表，每次运行里每份理赔一行。面板读这张表，所以刷新页面或换个浏览器，看到的都一样。
  • 收尾总结是对这张表的计数，不是模型写的话，所以不会和实际发生的事对不上。
  • 超过 S$800 限额的赔付还不算“已批准”：它在等人签字。
db = sqlite3.connect("runs.db", check_same_thread=False) db.execute("""CREATE TABLE IF NOT EXISTS claim_runs ( run TEXT, claim TEXT, status TEXT, action TEXT, payout REAL, PRIMARY KEY (run, claim))""") def save(run, claim_id, **fields): # fields: status, action or payout, set by our own code db.execute("INSERT OR IGNORE INTO claim_runs (run, claim, status) VALUES (?, ?, 'waiting')", (run, claim_id)) for column, value in fields.items(): db.execute(f"UPDATE claim_runs SET {column} = ? WHERE run = ? AND claim = ?", (value, run, claim_id)) db.commit() async def run_dispatch(run, n): global current async def agent_for_run(claim): decision, cost = await asyncio.to_thread(decide, claim) save(run, claim["id"], action=decision["action"], payout=float(decision.get("payout") or 0)) return decision try: await dispatch(load_claims(), agent_for_run, lambda claim_id, status: save(run, claim_id, status=status), n) finally: current = None SIGNOFF_LIMIT = 800 def count(run, where, *args): return db.execute(f"SELECT COUNT(*) FROM claim_runs WHERE run = ? AND {where}", (run, *args)).fetchone()[0] @app.get("/runs/{run}/summary") def summary(run: str): return { "approved": count(run, "status = 'done' AND action = 'approve' AND payout <= ?", SIGNOFF_LIMIT), "waiting_signoff": count(run, "status = 'done' AND action = 'approve' AND payout > ?", SIGNOFF_LIMIT), "declined": count(run, "status = 'done' AND action = 'decline'"), "referred": count(run, "status = 'done' AND action = 'refer'"), "left_for_handler": count(run, "status = 'failed'"), }

Step 3 · Say so when the service is down第 3 步 · 服务没开时要说出来

Learn先学

A button that does nothing is the worst button. On load the page asks /health; with no answer it switches the button off and says why in plain words.

什么都不做的按钮是最糟的按钮。页面加载时先问 /health；没有回应，就把按钮关掉，并用大白话说明原因。

Common errors常见错误

ERROR: [Errno 48] Address already in use
Fix: stop the other copy, or start with --port 8001.

sqlite3.ProgrammingError: SQLite objects created in a thread can only be used in that same thread
Fix: open the connection with check_same_thread=False and keep writes short.

Takeaways要点回顾

• A cap is a safety feature: validate it (1 to 25) before any agent starts.
• One dispatch at a time; refuse a second start with a clear message.
• Write every status change to a table so panel, reload and second browser agree.
• Build the summary from records, not from a model.
• If the service is down, the button says so.

• 上限是一道安全措施：任何智能体启动前先校验它（1 到 25）。
• 一次只跑一个调度；第二次开始用清楚的提示拒绝。
• 把每次状态变化写进一张表，面板、刷新页面和另一个浏览器就一致。
• 总结由记录生成，不由模型来写。
• 服务没开时，按钮要说明。
