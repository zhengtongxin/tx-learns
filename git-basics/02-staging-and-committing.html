Staging and committing暂存与提交

Read git status, stage exactly the changes you want and write messages that help later · ~10 min · reading and practice读懂 git status，只暂存你想要的改动，并写出以后有用的提交信息 · 约 10 分钟 · 阅读加练习

Step 1 · Ask Git what changed第 1 步 · 问 Git 改了什么

Learn先学

git status tells you what state each file is in. Its short form, git status --short, uses two columns: the left column is the staging area and the right column is the working folder. So M a.txt means “modified and staged”, and M a.txt means “modified but not staged”. ?? new.txt is a file Git has never seen.

git status 告诉你每个文件处于什么状态。它的简短形式 git status --short 用两列：左列代表暂存区，右列代表工作目录。所以 M a.txt 的意思是“已修改且已暂存”， M a.txt 是“已修改但未暂存”。?? new.txt 是 Git 从没见过的文件。

git diff shows the exact lines you changed and have not staged yet.

git diff 显示你改了、但还没暂存的具体行。

$ git status --short M prices.txt <- edited, not staged M menu.txt <- edited and staged ?? notes.txt <- new, Git has never seen it

Step 2 · Stage on purpose第 2 步 · 有选择地暂存

Learn先学

The staging area lets you build a commit deliberately. Add only the files that belong to one idea: git add prices.txt. Avoid git add . until you have checked git status, because it stages everything, including files you did not mean to share.

暂存区让你有意识地拼出一次提交。只把属于同一个想法的文件 add 进来：git add prices.txt。在看过 git status 之前，别急着用 git add .，它会把所有东西都暂存，包括你不想分享的文件。

Small commits that each do one thing are easier to read, review and undo.

每次只做一件事的小提交，更容易阅读、审阅和撤销。

Decide what to stage for each situation.

判断每种情况下该暂存什么。

Sort each one.

给每一项分类。

Step 3 · Write a useful message第 3 步 · 写有用的信息

Learn先学

A good message is short, starts with a verb, and says what the commit does: “Fix rounding in the bill total”. It should still make sense in a year. Messages like “update”, “fix” or “asdf” tell the future you nothing.

好的信息简短、以动词开头，说明这次提交做了什么：“修正账单总额的舍入”。一年以后读起来仍然看得懂。像“update”“fix”“asdf”这样的信息，对未来的你毫无帮助。

If you need “and” in the message, the commit probably does two things and should be two commits.

如果信息里需要用“和”，这次提交多半做了两件事，应该拆成两次提交。

Now make it yours现在把它变成你的

Takeaways要点回顾

• git status --short: left column staged, right column not.
• git diff shows unstaged changes line by line.
• Stage on purpose; one idea per commit.
• Write what the commit does, not “update”.

• git status --short：左列是已暂存，右列是未暂存。
• git diff 逐行显示未暂存的改动。
• 有选择地暂存；一次提交一个想法。
• 写这次提交做了什么，别写“update”。
