Looking back and undoing回看与撤销

Read the history, throw away a change you have not committed and undo a commit safely · ~10 min · reading and practice读懂历史，丢掉还没提交的改动，并安全地撤销一次提交 · 约 10 分钟 · 阅读加练习

Step 1 · Read the history第 1 步 · 读历史

Learn先学

git log lists commits, newest first. git log --oneline gives one short line each. git show displays one commit’s message and changes. Each commit has an id (a short code such as 3f2a9c1) that you can use to point at it.

git log 从新到旧列出提交。git log --oneline 每次提交一行。git show 显示某次提交的信息和改动。每次提交都有一个编号（一小串代码，如 3f2a9c1），可以用它来指向这次提交。

Reading the history is safe: none of these commands changes anything.

读历史是安全的：这些命令都不会改变任何东西。

Step 2 · Throw away uncommitted work第 2 步 · 丢弃未提交的改动

Learn先学

If you changed a file and want it back as in the last commit, run git restore filename. It overwrites your edit with the committed version. This cannot be undone, because Git never saw those edits, so use it only when you are sure.

如果你改了某个文件，想让它回到上一次提交时的样子，运行 git restore 文件名。它会用已提交的版本覆盖你的改动。这一步无法撤回，因为 Git 从没记录过那些改动，所以只在确定时才用。

To unstage a file without losing the edit, use git restore --staged filename.

想取消暂存、又不丢改动，用 git restore --staged 文件名。

echo "tea 99" > prices.txt # a mistake git restore prices.txt cat prices.txt

Step 3 · Undo a commit safely第 3 步 · 安全地撤销一次提交

Learn先学

To undo a commit that is already in the history, use git revert. It adds a new commit that does the opposite, so the history stays honest and anyone who already has the old commit is not confused. Avoid commands that rewrite history, such as git reset --hard, until you know exactly what they do.

要撤销已经进了历史的提交，用 git revert。它会新增一次做相反改动的提交，历史保持真实，已经拿到旧提交的人也不会被搞糊涂。在完全清楚后果之前，不要用会改写历史的命令，比如 git reset --hard。

Takeaways要点回顾

• git log and git show only read the history.
• git restore discards uncommitted edits for good.
• git revert undoes a commit by adding a new one.
• Avoid rewriting shared history.

• git log 和 git show 只读历史。
• git restore 会永久丢弃未提交的改动。
• git revert 通过新增一次提交来撤销。
• 不要改写已共享的历史。
