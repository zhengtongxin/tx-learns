Why version control为什么要版本管理

See why copies like final_v2 break down, and how a commit saves a snapshot you can return to · ~10 min · reading and practice看清为什么 final_v2 这类副本靠不住，以及提交怎样保存一个可以回到的快照 · 约 10 分钟 · 阅读加练习

Step 1 · Copies do not scale第 1 步 · 靠复制副本行不通

Learn先学

Most people start with file names like report_final_v2_REAL.docx. It works for a day and then you cannot tell which copy is newest, what changed, or why. With code it is worse, because many files must change together and a mistake in one can hide for weeks.

大多数人一开始用 report_final_v2_REAL.docx 这样的文件名。管一天还行，之后你就说不清哪份最新、改了什么、为什么改。写代码更糟，因为很多文件要一起改，其中一处的错误可能藏好几周。

Version control replaces the copies with one folder plus a history. The tool Git is the standard.

版本管理用“一个文件夹加一份历史”取代那些副本。事实上的标准工具是 Git。

Step 2 · Three places, one commit第 2 步 · 三个地方，一次提交

Learn先学

A folder tracked by Git is a repository. A change passes through three places. You edit files in the working folder. You choose which edits to include by adding them to the staging area. A commit then saves everything staged as one snapshot in the history, with a message saying why.

被 Git 管理的文件夹叫仓库。一个改动要经过三个地方。你在工作目录里修改文件；通过把改动加入暂存区，选出要包含的那几处；然后提交把暂存的全部内容作为一个快照存进历史，并附上说明原因的信息。

Put each place in order.

把每个地方按顺序放好。

Sort each one.

给每一项分类。

Step 3 · Your first commit第 3 步 · 你的第一次提交

Learn先学

Three commands make a first snapshot: git init turns the current folder into a repository, git add stages a file and git commit -m "message" saves it. git log lists the history, newest first.

三条命令就能做出第一个快照：git init 把当前文件夹变成仓库，git add 暂存文件，git commit -m "信息" 保存。git log 列出历史，最新的在最前。

A commit is a safe point. You can always come back to it, however much you change later.

提交是一个安全点。不管你之后改了多少，总能回到它。

mkdir shop && cd shop git init echo "tea 3" > prices.txt git add prices.txt git commit -m "Add first price" git log --oneline

Takeaways要点回顾

• Version control replaces file copies with one folder and a history.
• A change goes working folder, staging area, history.
• A commit is a snapshot with a message saying why.
• Only staged changes get committed.

• 版本管理用一个文件夹加一份历史取代文件副本。
• 一个改动依次经过工作目录、暂存区、历史。
• 提交是一个快照，附有说明原因的信息。
• 只有暂存的改动才会被提交。
