GitHub and pull requestsGitHub 与拉取请求

Step 1 · A remote is a shared copy第 1 步 · 远程是一份共享的副本

Learn先学

Your repository lives on your computer. A remote is a copy of it on a server, such as GitHub, that others can reach. git clone URL copies a remote repository to your computer. git push sends your new commits up to the remote, and git pull brings others’ new commits down.

你的仓库在你的电脑上。远程是它在服务器（比如 GitHub）上的一份副本，别人也能访问。git clone 网址 把一个远程仓库复制到你的电脑。git push 把你的新提交送上去，git pull 把别人的新提交拉下来。

GitHub is a website built around Git. It adds people, reviews and automation on top, but the history itself is plain Git.

GitHub 是围绕 Git 搭建的网站。它在上面加了人员、审阅和自动化，但历史本身就是普通的 Git。

git clone https://github.com/you/shop.git cd shop git switch -c sale # edit, add, commit git push -u origin sale

Step 2 · The pull request flow第 2 步 · 拉取请求的流程

Learn先学

A pull request (PR) is a request on GitHub to merge your branch into another one, usually main. The flow: make a branch, commit, push it, open a PR, let others review and automatic checks run, fix what they find by pushing more commits, then merge. The PR is where the team talks about the change before it lands.

拉取请求（PR）是在 GitHub 上申请把你的分支合并进另一个分支，通常是 main。流程是：建分支、提交、推送、开 PR、让别人审阅并让自动检查运行、把发现的问题用更多提交推上去修好，最后合并。PR 是团队在改动落地之前讨论它的地方。

Put the steps of the flow in order.

把流程的各个步骤按顺序排好。

Sort each one.

给每一项分类。

Step 3 · Fork when it is not yours第 3 步 · 不是你的仓库就 fork

Learn先学

If you cannot push to a project, fork it: GitHub makes your own copy under your account. You push your branch to the fork and open a PR from there back to the original. The owner then decides whether to merge it.

如果你没有权限向某个项目推送，就 fork 它：GitHub 会在你的账号下做一份你自己的副本。你把分支推送到 fork，再从那里向原仓库开 PR。是否合并由原仓库的主人决定。

This is how most open source projects take contributions from strangers.

大多数开源项目就是这样接收陌生人的贡献的。

More practice再练一练

Now make it yours现在把它变成你的

Takeaways要点回顾

• A remote is a shared copy; clone, push and pull move commits.
• A pull request asks to merge a branch and invites review.
• The flow: branch, commit, push, PR, review, merge.
• No access? Fork, then PR from the fork.

• 远程是一份共享的副本；clone、push、pull 搬运提交。
• 拉取请求申请合并一个分支，并邀请审阅。
• 流程：分支、提交、推送、PR、审阅、合并。
• 没有权限？先 fork，再从 fork 发 PR。
