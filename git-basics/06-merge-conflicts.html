Merge conflicts合并冲突

Read the conflict markers, choose what the file should say and finish the merge · ~10 min · reading and practice读懂冲突标记，决定文件该写什么，并完成合并 · 约 10 分钟 · 阅读加练习

Step 1 · When a conflict happens第 1 步 · 什么时候会冲突

Learn先学

Git merges changes line by line. When two branches changed different lines, or different files, Git combines them without asking. A conflict happens only when both branches changed the same lines in different ways, because Git cannot know which one you want. It stops the merge and marks the file.

Git 一行一行地合并改动。两个分支改的是不同的行或不同的文件时，Git 会自己合并。只有两个分支以不同方式改了同样的几行，才会产生冲突，因为 Git 无法知道你想要哪一个。它会停下合并并把文件标出来。

A conflict is normal in team work. It is not a sign that you did something wrong.

团队协作里冲突很正常，不代表你做错了什么。

Step 2 · Read the markers第 2 步 · 读懂标记

Learn先学

Git writes both versions into the file between three kinds of lines. Everything between <<<<<<< and ======= is the version from your current branch. Everything between ======= and >>>>>>> is the version from the branch you are merging in. git status shows the file as UU, unmerged on both sides.

Git 把两个版本都写进文件里，用三种线隔开。<<<<<<< 与 ======= 之间是你当前分支的版本，======= 与 >>>>>>> 之间是你正在合并进来的分支的版本。git status 把该文件显示为 UU，表示两边都未合并。

The markers are only there to help you. They must not stay in the final file.

这些标记只是帮你看的，最后的文件里不能留着它们。

<<<<<<< HEAD tea 4 ======= tea 2 >>>>>>> sale

Step 3 · Resolve and finish第 3 步 · 解决并完成

Learn先学

To resolve it, open the file, decide what it should say (one version, the other, or a mix), and delete all three marker lines. Then git add the file to say it is resolved and git commit to finish the merge. If you are lost, git merge --abort takes you back to before the merge.

要解决冲突，打开文件，决定它该写什么（其中一个版本、另一个版本，或者两者混合），并删掉三种标记行。然后 git add 该文件，表示已解决，再 git commit 完成合并。如果搞乱了，git merge --abort 会带你回到合并之前。

Put the steps in order.

把步骤按顺序排好。

Sort each one.

给每一项分类。

More practice再练一练

Now make it yours现在把它变成你的

Takeaways要点回顾

• A conflict happens only when both sides changed the same lines.
• Markers show both versions; you choose the result and delete them.
• git add, then git commit finishes the merge.
• git merge --abort takes you back to before the merge.

• 只有两边改了同样的行才会冲突。
• 标记显示两个版本；结果由你决定，并要删掉它们。
• git add，再 git commit，完成合并。
• git merge --abort 带你回到合并之前。
