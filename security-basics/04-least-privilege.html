Limiting the damage · Lesson 1限制损失 · 第 1 课

Least privilege最小权限

Give every person, program and key only the access it needs, so a mistake stays small · ~10 min · reading and practice只给每个人、程序和密钥它需要的权限，让失误的影响保持很小 · 约 10 分钟 · 阅读加练习

Step 1 · Small doors, small damage第 1 步 · 门越小，损失越小

Learn先学

The rule of least privilege says each person, program and key gets only the access its job needs and nothing more. It does not stop mistakes or break-ins. It limits how far they go. A key that can only read one folder, stolen, exposes one folder. An all-powerful key, stolen, exposes everything.

最小权限原则是：每个人、程序和密钥只拿到完成工作所需的权限，不多给。它不能阻止失误或入侵，但能限制影响范围。只能读一个文件夹的密钥被偷，只暴露一个文件夹；万能密钥被偷，一切都暴露。

Step 2 · Check before you act第 2 步 · 行动前先检查

Learn先学

Two checks are easy to confuse. Authentication asks who you are. Authorization asks what you are allowed to do. Passing the first does not give you the second, so every action that matters checks permission on the server, every time, never only by hiding a button in the page.

有两种检查容易混淆。认证问你是谁；授权问你被允许做什么。通过前者不代表拥有后者，所以每个重要操作都要在服务器端每次检查权限，而不是只靠在页面上隐藏按钮。

ROLES = {"viewer": {"read"}, "editor": {"read", "write"}} def allowed(role, action): return action in ROLES.get(role, set()) print(allowed("viewer", "write")) print(allowed("editor", "write")) print(allowed("guest", "read"))

Step 3 · Split by role第 3 步 · 按角色拆分

Learn先学

Create separate keys and accounts for separate jobs: one for reading, one for writing, one per service, one for each environment. When a person leaves or a key leaks, you remove one door without rebuilding the house. Unknown roles get nothing by default: the safe answer to “not sure” is “no”. Sort each grant.

为不同的工作创建不同的密钥和账号：一个读，一个写，每个服务一个，每个环境一个。有人离开或密钥泄露时，只需关掉一扇门，不用重建整座房子。未知角色默认什么都没有：对“不确定”的安全回答是“不行”。给每个授权分类。

Takeaways要点回顾

• Give each person, program and key only what its job needs.
• Authentication is who you are; authorization is what you may do.
• When unsure, the default answer is no.

• 每个人、程序和密钥只拿到工作需要的权限。
• 认证是你是谁；授权是你能做什么。
• 不确定时，默认答案是“不行”。
