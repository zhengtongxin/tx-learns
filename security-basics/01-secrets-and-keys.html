Secrets and keys密钥与凭证

Know what counts as a secret, keep it out of code and act fast when one leaks · ~10 min · reading and practice知道什么算密钥，不把它写进代码，泄露时迅速处理 · 约 10 分钟 · 阅读加练习

Step 1 · What counts as a secret第 1 步 · 什么算密钥

Learn先学

A secret is any value that gives access to something: an API key, a password, a database address with the password inside it, a signing token. If a stranger could use it to act as you or read your data, it is a secret. Anything that only describes your app, such as a colour or a page title, is not.

密钥是任何能让人获得访问权的值：API 密钥、密码、带密码的数据库地址、签名令牌。如果陌生人拿到它就能冒充你或读取你的数据，它就是密钥。只是描述应用的东西，比如颜色或页面标题，则不是。

Secrets leak in boring ways: pasted into code, committed to a public repository, printed in a log, shared in a screenshot or a chat message. Bots scan public code hosting all day, so a key pushed by mistake can be found within minutes.

密钥通常以平淡的方式泄露：粘贴进代码、提交到公开仓库、打印进日志、出现在截图或聊天里。机器人整天在扫描公开的代码托管，误推送的密钥几分钟内就可能被找到。

Step 2 · Keep it out of code and logs第 2 步 · 不让它进代码和日志

Learn先学

Read secrets from the environment at run time, never write them in a file you commit. Keep a file with the real values (such as .env) out of git, and commit only an example file with fake values. When you must show a secret in a log, show only the first few characters.

在运行时从环境读取密钥，绝不写进要提交的文件。存放真实值的文件（如 .env）不进 git，只提交带假值的示例文件。必须在日志里提到密钥时，只显示前几个字符。

import os os.environ["API_KEY"] = "abc123xyz" key = os.environ.get("API_KEY", "") print(key[:3] + "***")

Step 3 · When one leaks第 3 步 · 泄露时怎么办

Learn先学

Deleting the line from the code does not help, because the old version stays in history and may already be copied. The order is: revoke the key at its provider so it stops working, create a new one, put the new one where the app reads it, then look at the provider’s usage log for anything you did not do. Cleaning up the history comes last, and matters least.

把那行代码删掉没有用，因为旧版本还留在历史里，可能已经被复制。顺序是：先在服务商那里吊销旧密钥，让它失效；创建新的；放到应用读取的地方；再看服务商的使用记录有没有你没做过的操作。清理历史放在最后，也最不重要。

Takeaways要点回顾

• A secret is any value that gives access.
• Read secrets from the environment and keep the real file out of git.
• When one leaks, revoke first, then replace, then check usage.

• 密钥是任何能给人访问权的值。
• 从环境读取密钥，真实文件不进 git。
• 泄露时先吊销，再替换，再查使用记录。
