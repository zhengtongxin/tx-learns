Passwords and hashing密码与哈希

Store passwords so a stolen database does not reveal them · ~10 min · reading and practice用不会在数据库被盗后暴露的方式保存密码 · 约 10 分钟 · 阅读加练习

Step 1 · Never store the password itself第 1 步 · 绝不保存密码本身

Learn先学

If your database holds passwords as written, one leak gives an attacker every account, and people reuse passwords on other sites, so the damage spreads. Even you, the owner, should not be able to read them. The answer is to store something that lets you check a password without being able to read it back.

如果数据库里存的是明文密码，一次泄露就让攻击者拿到所有账号，而人们常在别的网站重复使用密码，损失会扩散。连你这个所有者也不应该能读到它们。办法是保存一个只能用来核对密码、却无法还原密码的东西。

Step 2 · A hash is a one-way fingerprint第 2 步 · 哈希是单向指纹

Learn先学

A hash function turns any input into a fixed-length scramble. The same input always gives the same result, a tiny change gives a completely different one, and there is no way back from the result to the input. To check a login, hash what the user typed and compare it with the stored hash.

哈希函数把任意输入变成固定长度的乱码。相同输入总是得到相同结果，输入稍有变化结果就完全不同，而且无法从结果倒推回输入。校验登录时，把用户输入的内容做哈希，与保存的哈希比较。

import hashlib def h(text): return hashlib.sha256(text.encode()).hexdigest() print(h("abc")[:8]) print(len(h("abc")))

Step 3 · Add salt, use a slow hash第 3 步 · 加盐，用慢哈希

Learn先学

Two users with the same password would get the same hash, and attackers keep tables of hashes of common passwords. A salt is a random value added to each password before hashing, stored next to the hash, so every user’s hash is different. A fast hash such as the one above is also too easy to guess against, so real systems use a deliberately slow, purpose-built password hash from a trusted library instead of writing their own.

两个用户密码相同，哈希就相同，而攻击者手里有常见密码的哈希表。盐是哈希前加到每个密码上的随机值，与哈希放在一起保存，让每个用户的哈希都不同。上面这种快速哈希也太容易被暴力猜测，所以真实系统用专门设计的、故意很慢的密码哈希，来自可信的库，而不是自己写。

Takeaways要点回顾

• Store a hash, never the password.
• A hash goes one way; check by hashing the input again.
• Add a salt and use a slow hash from a trusted library.

• 保存哈希，绝不保存密码本身。
• 哈希是单向的；校验时对输入再做一次哈希。
• 加盐，并使用可信库里的慢哈希。
