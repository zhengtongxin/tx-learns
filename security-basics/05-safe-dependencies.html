Safe dependencies安全的依赖

Trust the packages you install only as far as you have checked them, and keep them current · ~10 min · reading and practice只在核对过的范围内信任你安装的包，并让它们保持更新 · 约 10 分钟 · 阅读加练习

Step 1 · Packages are other people’s code第 1 步 · 包是别人的代码

Learn先学

Every package you install runs with the same access as your own code, and it brings its own dependencies too. Most are fine, but two things go wrong: a package may have a known flaw that is fixed in a later version, or a bad one may pretend to be a good one with a nearly identical name. A typo in an install command can fetch the wrong thing.

你安装的每个包都以与你自己的代码相同的权限运行，它还会带来自己的依赖。绝大多数没问题，但有两种情况会出事：包可能有已知漏洞，在后来的版本里才修复；或者坏包用几乎一样的名字冒充好包。安装命令里的一个拼写错误就可能装来错误的东西。

Step 2 · Pin the versions第 2 步 · 固定版本

Learn先学

A pinned version such as requests==2.31.0 says exactly which release you tested. Without pins, a fresh install tomorrow may bring a different release than the one that worked today. Keep the list in a requirements file in your project so everyone, and your server, installs the same set.

固定的版本，如 requests==2.31.0，说明了你测试过的确切版本。不固定的话，明天重新安装可能拿到与今天能用的不同的版本。把清单放在项目的 requirements 文件里，让所有人和你的服务器装的都是同一套。

line = "requests==2.31.0" name, version = line.split("==") print(name) print(version.split(".")[0])

Step 3 · Update on purpose第 3 步 · 有计划地更新

Learn先学

Pinned does not mean frozen. Check for security fixes regularly with the tool your language provides, update one package at a time, run your tests, then commit the new pin. Before adding a new package, ask four quick questions: do I need it, is it widely used, is it still maintained, and is the name spelled exactly right? A small function you can write yourself is better than a new dependency.

固定不等于冻结。用你所用语言提供的工具定期检查安全修复，一次更新一个包，跑测试，再提交新的版本号。添加新包之前，快速问四个问题：我真的需要它吗，用的人多吗，还有人维护吗，名字拼写完全正确吗？自己能写的小函数，比新增一个依赖更好。

Takeaways要点回顾

• A package runs with your code’s access.
• Pin versions so installs are repeatable.
• Add a package only when needed, and update on purpose.

• 包以和你的代码相同的权限运行。
• 固定版本，让安装可重复。
• 只在需要时添加包，并有计划地更新。
